# 直播观众行为结构：一个可审计的度量模型

## 0. 本文的性质与读法

**这是一份独立的模型论述**，写给任何愿意审阅它的人：不需要读过本项目、不需要看到代码，也能判断
它的定义是否合理、推导是否成立、结论能走多远。实现细节一律后置到**附录 C**。

模型的动机很朴素：对一个长时间开播的主播，"观众"不是同质集合。有人几乎每场都到、有人只在特定
内容出现、有人从不说话但一直在、有人话不多但出手很重。把群体的这些差异**测量**出来、并用可比较
的方式呈现，是本文的目标。

需要先说清**它不做什么**：不做"观众价值"排序，不做"忠诚度"判定，也不预测任何人会做什么。它只
产出若干**行为强度**的度量，并明确标出这些度量的适用边界（§10）。

> **阅读约定**：`约定`（convention）指人为选定的规则，换规则结论会变；`发现`（finding）指数据
> 本身呈现、换规则也不消失的性质。全文严格区分二者 —— 混淆这两类是这类模型最常见的错误。

**数值口径**：文中所有小数保留三位（四舍五入），模型输出同样如此 —— 对外展示与复算以同一串数字为准。

## 1. 观测对象：从直播事件到可分析的表格

### 1.1 上游事件

直播平台的弹幕接口逐条吐出**事件**。一条事件至少含：事件类型、发送者标识、时间戳；部分类型还带金额。

| 代号 | 事件 | 含义 | 是否带金额 |
|---|---|---|---|
| 0 | 弹幕 | 一条公开文字发言 | 否 |
| 1 | 礼物 | 送出可计价礼物 | 是 |
| 2 | 舰长 | 购买或续费大航海（月度订阅制） | 是 |
| 3 | 醒目留言（SC） | 付费留言，展示位置显眼 | 是 |
| 4 | 入场 | 用户进入直播间 | 否 |

**关键事实**：`入场` 是独立事件，因此**"只进场、从不发言"的观众在数据里是存在的**。实测样本
（5 场、62,427 个「人×场」对）：**90.1% 的对没有任何弹幕**，其中 **90.0% 仅有入场事件**。
绝大多数"到场"并不伴随发言 —— 这决定了"出席"与"互动"必须分开度量。

另有 **1.35%** 的「人×场」对有其他事件却**没有入场事件**（采集开始时人已在房间）；这些行都有实际
行为，不是空记录。

### 1.2 两级聚合

原始事件流太大（一个窗口可达数百万条），不能直接参与统计。加工分两步，每步只保留统计量、丢弃原文。

**第一级：场次内 × 用户**（每场产出"人 → 聚合值"的映射）

| 字段 | 含义 |
|---|---|
| `m`, `mt` | 该场弹幕条数；每条弹幕的时间戳数组 |
| `e`, `et` | 该场入场事件数；时间戳数组 |
| `p`, `pe`, `pt` | 该场付费总额；付费事件数；时间戳数组 |
| `sc`, `sc_cnt` | 醒目留言金额与条数 |
| `g`, `gd` | 礼物金额（两种计价口径） |
| `guard_cnt`, `guard_top` | 舰长数量与最高等级 |
| `mh` | 每条弹幕文本的**64 位哈希**（与 `mt` 一一对齐；空文本占位 0） |
| `uniq` | **去重后的不同文本条数**（归一化 = 去首尾空白、内部空白压一格） |
| `maxrep` | 单条文本的**最大重复次数** |

> **`mh` 的用意**：哈希在采集时一次算好，**原文不落盘**。它用确定性哈希（blake2b/64 位），
> 跨进程可复现 —— 因此**将来无论把去重规则改成什么样，都能在这串哈希上离线重算**，
> 不必重新采集。归一化只做空白压平，大小写、标点与 emoji 仍然被区分。

每场同时产出**场次级汇总**：总事件数、去重用户数、各类型总量、开始与结束时刻、事件类型直方图，
以及全场口径的重复率 `dup_rate`。这些汇总是 §1.7 自洽校验的对账基准。

**第二级：窗口内 × 用户**（把多场聚合值累加成整窗事实）

- `att_n(u)` —— **出席场次数**：窗口内 $u$ 至少产生过一次任意事件的场次数。"任意事件"是关键：
  只入场未发言者计入，只发言未入场者也计入。
- `m(u)` —— 弹幕总条数（不含 SC，SC 单列）。
- `pay(u)` —— 付费总额（礼物、舰长与 SC 的计价部分）。
- `uniq(u)`, `maxrep(u)` —— 文本指纹的窗口累计。
- `lag` —— 每场首次出场时滞（§2.1）。

$$\mathrm{att}_n(u)=\#\{\,s:\ u\text{ 在 } s \text{ 中至少出现一次}\,\},\qquad
m(u)=\sum_s m_{u,s},\qquad \mathrm{pay}(u)=\sum_s p_{u,s},\qquad
\mathrm{uniq}(u)=\sum_s \mathrm{uniq}_{u,s}$$

> **`m` 与 `uniq` 的关系**：两者都保留。`m` 用于"发言总量"口径，`uniq` 用于"有效发言"口径，
> **不是替代关系**。旧数据没有 `uniq` / `maxrep`（当时不读文本），读取时标记为"未跟踪"，
> **不能当成 0**。判定（是否刷屏）与采集分离，见附录 C。

### 1.2.1 文本去重与独轮车

**去重口径**：把文本按三步归一化 —— 全角空格转半角、连续空白压成一个、去首尾空白 ——
再取 **blake2b 64 位哈希**。同一场、同一用户、同一归一化文本只计一次。于是每条记录带三个量：

| 字段 | 含义 |
|---|---|
| `m` | 原始条数（**永不删减**） |
| `uniq` | 去重后的不同文本数 |
| `maxrep` | 单条文本的最大重复次数 |

归一化**不改大小写、不删标点、不做相似度**，因此"草"与"草！"仍算两条。原文不落盘，
只存哈希与时间戳一一对齐的序列 —— 将来换更复杂的规则可以在哈希序列上离线重算，不必重新采集。

**独轮车判定：只看文本多样性。** 判据只有一条 —— **不同文本率（`uniq/m`）≤ 20%**，
且该用户累计 ≥200 条。等价于"重复率 ≥80%"。

这条线不是拍脑袋定的。判据最初写成"单条文本重复 ≥50 次且横跨 ≥1 小时"，被真实样本推翻：

| 用户 | 消息 | 不同文本率 | 内容 | 是否独轮车 |
|---|---|---|---|---|
| `178727502` | 2,008 | **1.7%** | `火队加油` 刷 1,871 次 | ✅ 是 |
| `29951465` | 1,783 | **6.1%** | 只有 24 种文本 | ✅ 是 |
| `494629966` | 3,533 | **9.1%** | `🍆奶绿🥖` 刷 2,987 次 | ✅ 是 |
| `403044621` | 1,049 | **15.5%** | `啥意思` 刷 388 次 | ✅ 是 |
| `1049834725` | 5,702 | 40.6% | `好好好` 刷 1,557 次，但也在正常聊天 | ❌ 不是 |
| `8159881` | 7,371 | 28.7% | `prpr` 刷 793 次 | ❌ 不是 |
| `431410658` | 69,614 | **78.2%** | 说 3,961 次"哈哈哈"，5 万余条互不相同 | ❌ 不是 |

**边界极其清晰**：真独轮车 1.7%–15.5%，口头禅型话痨 28.7%–78.2%。
所以判据必须是"**他会不会说别的**"，而不是"他重复了几次那一条"—— 后者会把话痨误判。

两条被否掉的规则（都试过，都撤回）：

- **次数阈值**（单条 ≥50 次、跨 ≥1 小时）：绝对次数不区分"重复"与"高频"，
  6.9 万条里说 3,961 次"哈哈哈"一样满足；
- **单场低多样性**（某场多样性 ≤20%）：有人某一小时刷几句口号、平时正常说话，
  全场多样性 59.7%，按单场判会误伤。

判定结果**只标记、不剔除**，接口带 `spam` 字段。影响量级：命中率 0.15%–0.22% 的活跃用户，
整体指标几乎不动（强度排序 ρ≈1.0、类型分布变化 <0.5%），但**头部名单会被污染**
—— 弥月前 100 名里曾有 17 人命中。

### 1.2.2 池子怎么划：按平均同接（ACV）

入选门槛不是固定百分比，而是**平均同接的倍数**：

- 先用出席率 ≥10% 筛出**大盘**，再在大盘内按**核心度 S** 取前 **3×ACV** 人作为分析名单；
- **核心层** = 0.75 × ACV、**次核心层** = 1.25 × ACV、**外层** = 1.0 × ACV（2×~3×）；
- ACV 从上游的同接时间线取**去掉头尾各 10%** 之后的均值 —— 开播爬坡与下播回落会显著拉低均值
  （实测头部 10% 只有整体的 55%–65%，不裁会把 ACV 压低 2%–8%）；
- 达不到池子门槛的人**不进分析**，但会在报告里写明"分流走多少人"。

为什么不用固定百分比：同一套比例落到三个 V 上，隐含的出席率门槛相差 16 个百分点
（59%–75%）—— 固定百分比无法同时匹配。ACV 是**观众规模**的度量，用它定人数才是同一把尺子。

缺 ACV（该场没有同接数据）时回退到"出席率 ≥10%"的老口径，并在报告里标注。

### 1.3 场次身份：一行记录 ≠ 一场直播

同一场直播常被多个采集通道各记一行（实时通道、轮询通道、手工补录），各行标题与开始时间相同但
标识符形态不同。若按行计数，一场会被算成两三场。

合并规则：**每场指定一条主记录**，以"采集侧 UUID + 平台内部 ID"的组合作为主键；一切统计落在主记录上。

**实测**：同一份数据按行计数 **1,168 行**，按主记录 **942 场** —— 差 **226 行** 是重复记录。
按行统计会让场次数**系统性高估约 24%**。凡"场次数"口径的指标（月度活跃、窗口大小、采集预估）
都必须先落到主记录。

### 1.4 时间与时区

- 事件时间戳与场次起止均以 **UTC** 存储；展示层按本地时区呈现（同一场库中 `10:59`、界面 `18:59`）。
- **已修的口径问题**：采集侧曾用**本地时间**写入场次起止，而库与展示层是 UTC —— 东八区机器上
  新采数据整体偏 **+8 小时**（dev 库 227 场中 **76 场**如此）。现已统一写 UTC，历史文件已回填。
- **分天口径（已修）**：全文的分天 / 分月 / 分年一律按**东八区（UTC+8）**，实现上由单一函数
  `sql_day()` 生成 `date(col, '+8 hours')`，Python 侧用 `cn_day()`，二者共用同一套时区常量。
  修复前按 UTC 日切分，当地 00:00–08:00 开播的场次会落到前一天且**在图上不可见**；
  实测 dev 库中 **520 场**的"UTC 日"与"东八区日"不同 —— 这不是理论风险，是已经发生过的偏移。

### 1.5 窗口构造与质量过滤

"窗口" = 一段连续场次的集合。构造顺序固定：

| 步 | 动作 | 为什么必须这样 |
|---|---|---|
| 1 | 收集候选场次（含主记录判定） | 见 §1.3 |
| 2 | 按起止日期**闭区间**筛 | 用户的"时间范围"即此 |
| 3 | 按开始时刻升序 | 时间序是后续一切的前提 |
| 4 | 显式场次清单优先；否则取**最后 N 场** | 避免"区间末 N 场"与界面切片不一致 |
| 5 | **质量过滤**（三项） | 会减少实际场次 |
| 6 | 聚合 | 分位参照总体 = 第 5 步之后剩下的场次里的入选者（§2.4） |

**三项质量过滤**（任一不过即整场剔除）：

1. **事件数不足**（阈值 50）—— 样本太小，任何率都不稳；
2. **该场没有入场事件** —— 无法区分"没来"与"没记录"，出席率会被系统性压低；
3. **缺原始明细** —— 该场进了分母却记不上出席，同样压低出席率。

**后果**：请求 75 场 ≠ 分析 75 场。实测为 **72 场**（3 场被剔除）。这个差必须对使用者可见，
否则任何占比都缺一个分母说明。

### 1.6 场次跨度：优先用平台时间，其次弹幕跨度

**首选：平台记录的开播 / 下播时间。** 上游为每场提供 `startDate` 与 `stopDate`，
覆盖率 **99.7%–99.9%**。这是权威值 —— 与"从事件推"相比中位只差 6 分钟，
但尾部能差 8 小时（弹幕没覆盖全场，或延伸到下播之后）。当前 227 场**全部**使用该口径
（`duration_source = platform`）。

**回退：从事件时间戳推。** 平台缺 `stopDate` 时，取该场**弹幕时间戳的最小与最大值**；
连弹幕都没有时才回退到全部事件。之所以优先用弹幕而不是全部事件：入场事件可能是迟到的
（实测有场次的入场散落到 6 天后，把 11 小时的直播拉成 102 小时）。

无论用哪种来源，都会再经过下面的**离群裁剪**（仅回退路径需要）。

**再补一道：弹幕率骤降 ⇒ 提前结束。** 平台 `stopDate` 也会偏长 —— 实测有一场报 12.9 小时，
实际 2 点就没人说话了。规则（只让场次变短）：

1. 按 **5 分钟**分桶；
2. 基线 = 前 5 小时桶量的 **p75**（用中位数会被前段已存在的安静期拉低，反而裁不出来）；
3. 阈值 = 基线 **10%**；从第 5 小时起，找最后一个高于阈值的桶；
4. 结束时间 = 该桶末尾 + **30 分钟宽限**（保住下播前的告别语）。

阈值 5% 太松（9.6 小时的场次裁不动），20% 太紧（会切进真实活动）。10% 在实测中把
9.6 小时的一场裁到 6.1 小时，同时没有动三场"整段都有人说话"的长场次。个别散落记录（例如开播三天后的
2 条弹幕）会把跨度拉成几昼夜：实测有场次从约 6 小时被拉成 **5 天**。这类失真会传导到一切
"按场次时长归一"的量（在场覆盖、密度分桶、留存窗口）。

**现行规则**（保守，宁可少切）：

1. 找相邻事件里**最大**的间隔；不超过 **3 小时** 就停；
2. 只切掉**少数一侧**，且该侧必须 < 全部事件的 **5%**；
3. 重复直至无可切。

真实中场休息（两侧都很大）不会被误切。实测 227 场中 **19 场**触发裁剪，最长一场从 5 天回到 33 小时。

### 1.6.1 数据质量修复：后段回放

上游偶尔会把一场直播的**前段弹幕重新记到末尾** —— 时间戳变了、内容相同。实测 **9/227 场**
如此，最多一场重复 **9,857 条**。危害有两层：场次看起来长得多；重复内容抬高该场所有人的互动量。

**为什么不能用"多久没弹幕就下播"来判断**：重复块在末尾**密度并不低**（有的每小时上千条，
比正常时段还热闹），任何基于时间或活跃度的判据都会把它当成正常内容。必须比对**内容**。

**判据**（依赖 §1.2 的 `mh`）：

1. 按小时分桶，统计每小时 `(用户, 文本哈希)` 的多重集合；
2. 若某小时 **≥80%** 的记录在此前的全部记录里都出现过，且该小时 ≥50 条 ⇒ 判为回放；
3. 从**第一个回放小时**起，丢弃之后的所有弹幕，重算 `m` / `uniq` / `maxrep` 与场次计数；
4. 结束时间取「裁后最后一条弹幕」与「原结束时间」中**较早**者 —— 裁剪只会让场次变短。

只丢弹幕，不动入场与付费事件（它们没有逐条金额，无法按时间精确回退，且尾部量很小）。
实测最大一场从 **11.53h 裁到 6.87h**。

### 1.7 完整性判据：什么样的场次有权进入统计

| # | 判据 | 比较对象 | 不过时的处置 |
|---|---|---|---|
| **C1** | 聚合恒等式 | 场次汇总 vs 由明细现算 | **整场弃用**（唯一弃用理由） |
| C2 | 汇总与明细一致 | 平台给出的弹幕计数 vs 现算条数（容差 15%） | 仅降级 |
| C3 | 外部覆盖比 $\gamma$ | 外部源时间跨度 ÷ 本模型时间跨度（门槛 0.90） | 标记**未核验** |
| C4 | 逐分钟一致性 $\rho$ | 外部源与本模型的逐分钟条数相关（下限 0.80） | 仅降级 |

**区分理由**：只有 C1 是**内部自洽**（同一份数据自己与自己核对），不过就说明加工错了，必须弃用。
C2–C4 依赖**外部源**，而外部源本身可能不全 —— 不过只说明"无法核实"，不能说明"我们错了"。

**反例**：实测存在 $\gamma=0.120$ 的场次（外部源只覆盖 12% 的时间跨度）。若用"取最近一条"对账，
会得出 **+622%** 的伪偏离，把一场完全可用的数据判成异常。共同点：**把"外部没收录"当成"我们算错了"**。

**未核验 $\ne$ 有问题，也 $\ne$ 已核验。** 报告统计量时应说明窗口里有多少场处于未核验状态；
样本曾出现 100% 未核验（无外部源可用），此时这是一个**纯内部自洽**的模型。

### 1.8 复算（第 1 章）

主记录数由"按行计数 vs 按主键去重"对比得到；窗口实际场次由逐场跑质量过滤得到；无弹幕出席占比由
逐场统计"弹幕为 0 的「人×场」对"得到。具体命令见附录 C.1。

## 2. 三条轴

### 2.1 出席轴：先比来了几场，再比谁到得早

记窗口内在册场次为 $N$，用户 $u$ 的出席场次 $\mathrm{att}_n(u)$，其逐场首次出场时滞 $\ell_{u,s}$：

$$\overline{\ell}(u)=\frac{1}{\mathrm{att}_n(u)}\sum_{s}\bigl(t^{(1)}_{u,s}-\tau_s\bigr),\qquad
A(u)=\frac{\mathrm{att}_n(u)+\pi_E^{(k)}(u)}{N+1},\qquad k=\mathrm{att}_n(u)$$

- $t^{(1)}_{u,s}$ —— 用户 $u$ 在场次 $s$ 中**最早一个事件**（入场、弹幕或付费）的时刻；
- $\tau_s$ —— 该场**最早一个事件的时刻**（不是平台报的开播时间：实测两者中位只差 **0.6 分钟**，
  秩相关 $1.000$，用事件基准可少依赖一个数据源）；
- $k$ —— **出席场次本身即为档位**，共 $N+1$ 档，不做人为分档；
- $\pi_E^{(k)}$ —— **同档内** $(-\overline{\ell})$ 的经验分位（越早越高）；无时滞数据者取 $0.500$。

**为什么不用"出席率"**：$\mathrm{att}_n/N$ 只能取 $N+1$ 个离散值。72 场窗口里顶部有大量用户
**同为满勤**，这一段**排不出序** —— 而"排不出序"不等于"这些人一样"。

**为什么不用相乘**：形如 $A\times\pi_E$ 的接法会把轴降级 —— $\pi_E$ 在档内按构造均匀分布于 $[0,1]$，
相乘等于给每人乘一个随机系数。样本外实验（前 6 场算分 → 后 6 场检验）：

| 方案 | $\rho$(分, 后段出席) | $\rho$(分, 后段弹幕) |
|---|---|---|
| $\mathrm{att}_n/N$ | 0.597 | 0.376 |
| $A\times\pi_E$ | **0.381** | 0.310 |
| **字典序（本文采用）** | **0.602** | **0.392** |

**档数**也验证过：3 档会跨档错位（"来 4/6 次但很早"能压过"来 6/6 次但晚到"），$\rho$ 降到 0.536；
5 档与 10 档持平在 0.602，而 10 档在 6 场样本里正好退化成"每场一档"。故直接**每场一档，不调参**。

**档内区分效果**（前 6 场出席率 ≥ 0.800 的 2,527 人，看后 6 场）：

| 档内分组 | 后段出席率 | 后段发言占比 |
|---|---|---|
| 档内早到 | **0.940** | **73%** |
| 档内晚到 | 0.810 | 41% |

跨 V 复现（星瞳 42% vs 14%，弥月 42% vs 15%）。

> **表述纪律**："早到/晚到"是**行为模式**，不是"真人/挂机"的判定。数据能证明"早到者更常来、
> 更常发言、更常反复进出"，不能证明他们是否真的在看。

### 2.1.1 时机的真实收益：区分并列，而不是提高准确率

这一点必须写明，否则很容易被误读成"加了时机所以模型更准"。

#### ① 对总体预测力：**基本没有提升**

半窗 12 场、看后 12 场的出席率（三个 V 一致）：

| V | 仅出席 | 加时机（现行） | 差 |
|---|---|---|---|
| 明前奶绿 | **0.751** | 0.748 | $-0.003$ |
| 星瞳 | **0.710** | 0.705 | $-0.005$ |
| 弥月 | 0.687 | 0.688 | $+0.001$ |

半窗 6 场时方向还相反（0.597 → 0.602）。**差异都落在 $\pm0.005$ 内，符号随切分变化** ——
结论只能有一个：**时机不提高总体预测力。**

#### ② 真正的收益：在**同出席档内部**区分

只看满勤用户（出席次数完全相同，唯一差别就是时机），用时机分位预测后段出席：

| V | 满勤人数 | $
ho(\pi_E,$ 后段出席$)$ |
|---|---|---|
| 明前奶绿 | 244 | **0.373** |
| 星瞳 | 452 | **0.415** |
| 弥月 | 993 | **0.471** |

同档内所有人的出席次数一样，所以这个相关**不可能来自出席**。$\Rightarrow$ **时机把"并列"拆开了，
而且拆得有预测意义。**

#### ③ 一旦让档位取代场次，这个收益立刻消失

把分数从 $(\mathrm{att}+\pi_E)$ 换成 $(	ext{档号}+\pi_E)$，并在半窗 12 场下加宽档位：

| 档宽（每档几场） | 明前奶绿      | 星瞳        | 弥月        | 跨档逆序人数       |
| -------- | --------- | --------- | --------- | ------------ |
| 1（= 现行）  | 0.748     | 0.705     | 0.688     | 0            |
| 2        | 0.721     | 0.666     | 0.668     | 6,000–15,000 |
| 3        | 0.712     | 0.673     | 0.664     | 5,800–14,000 |
| 6        | **0.619** | **0.547** | **0.583** | 9,000–23,000 |

而**场次式在所有档宽下 $ho$ 完全不变、逆序恒为 0** —— 因为分数的整数部分就是出席场次，
时机的最大贡献 $(\pi_E<1)$ 永远跨不过一场。

$\Rightarrow$ **让档位取代场次，等于允许"少来几场"被"早到几次"抵消**，实测既掉准确率、又制造大规模错位。

#### ④ 取值依据：$\delta$ 应取 1

把时机折算成"等价于几场出席"（回归得交换率）：

| 样本 | $\hat\delta$（三 V 范围） |
|---|---|
| 全部用户 | 0.83 – 1.34 |
| 高出席档 | 1.42 – 2.30（受**天花板效应**影响：高档内出席方差消失，$b_1$ 被压低） |

按交换率做的"分档动态 $\delta$"实测**一次都没赢过** $\delta=1$（差 $\le 0.001$）。原因还是结构性的：
**同一档内 $(\mathrm{att}+\delta\pi_E)$ 的排序与 $\delta$ 无关**（档内出席相等），
而跨档数据又支持 $\deltapprox1$。两头都不需要调。

#### 一句话结论

> **出席决定"谁在前"，时机决定"同分的人怎么排"。**
> 时机的价值是**分辨率**，不是**准确率** —— 引用任何"引入时机后更好"的说法都不成立，
> 正确的是"引入时机后，**并列处可区分了**"。

### 2.2 互动轴

$$I(u)=\frac{m(u)+\mathrm{sc}(u)}{\mathrm{att}_n(u)}$$

**分母是出席场次而非 $N$**：$I$ 要回答"来了以后说得多不多"。若用 $N$ 作分母，"来得少但每次活跃"
的人会被稀释成低互动 —— 那样测的其实是"总产出"，与出席轴高度重叠。

**已知未接入的改进**：采集已产出 `uniq`（去重后条数）与 `maxrep`，但**当前轴仍用原始条数**。
现有去重口径只是**轻归一 + 精确匹配**（去首尾空白、内部空白压一格、全角空格视同空格），
它足以挡"加空格/大小写"的变体，但**挡不住近义改写**；是否据此判定刷屏、以及判定后是剔除还是
在分子里折价，**都尚未定**。
把分子换成 `uniq` 会让刷屏自动折价（发 500 条同一句等价于 1 条），且无需剔除任何人；
代价是旧数据无法回补（当时不读文本），新旧口径不可混算。**接入前必须先决定切换点。**

### 2.3 付费轴

$$P(u)=\ln\bigl(1+\mathrm{pay}(u)\bigr)$$

**取对数的理由**：付费额极度右偏（实测中位数 $0.000$、p99 $5.352$）。不取对数时少数大额打赏会
独占全部方差，$P$ 退化成"是否打过大钱"的 0/1 指示。

**不分母的理由**：它是**存量**（一共花了多少），不是**率**。改成"场均付费"会与互动轴的分母口径冲突，
且对小额高频者不公。

### 2.4 入选门槛与参照总体

**入选门槛 $\theta_{in}=0.100$**：出席率低于 10% 者不进入分位参照总体。理由：偶发路过者会把分位
曲线压在低端，使"常看的人"在任何轴上都显得偏高。

**实测**：观测用户 **170,470** → 入池 **34,180**（20.0%）。**凡"占池比例"的陈述，分母都是后者。**

### 2.5 经验分位变换

三轴量纲不同、分布极右偏，不能直接相加。做法是把每条轴换成**在本池内的经验分位**：

$$\pi(x)=\frac{1}{n}\Bigl(\#\{x_i<x\}+\tfrac12\#\{x_i=x\}\Bigr)$$

三个性质：

1. **参照总体必须显式指定**。$\pi$ 回答"相对于**谁**的分位"；传错总体会让全部分数错位，
   而错位看不出来（分数仍落在 $[0,1]$、仍然右偏）。
2. 分位化把三轴拉到同一尺度，这是"等权相加"的前提；代价是**丢掉间距信息**。
3. 分位是**相对于本窗口本池子**的，跨窗口、跨人比较绝对分位**不合法**（§2.8）。

### 2.6 参与强度

$$S(u)=\tfrac13\bigl(\pi_A(u)+\pi_I(u)+\pi_P(u)\bigr)$$

**判定：等权是「约定」，不是「发现」。** 没有数据能证明三轴应等权；选等权是为了**不在测量层引入
价值判断** —— 把付费权重调高，$S$ 就变成"消费力"而非"参与强度"。

**为什么等权不至于退化成单轴**：三轴分位的两两秩相关实测 **$A\sim I$ 0.412 · $A\sim P$ 0.290 ·
$I\sim P$ 0.423**。正相关但不共线，说明三者不是同一个东西。这只是**不共线的证据**，不是"等权最优"
的证明；真正决定权重的是外部效标（§4）。

**均值恒为 0.500 是构造结果**：$\pi$ 在 $[0,1]$ 上均匀，三者平均的期望即 0.500。实测
mean $0.500$、median $0.465$ —— **$S$ 的绝对值没有信息量，只有相对位置有。**

**这里的相关系数用秩相关**：先把每条轴的取值换成**平均秩**（并列取秩的算术平均），再对秩向量
求 Pearson 相关：

$$\rho_{XY}=\frac{\sum_i (r_X^{(i)}-\bar r_X)(r_Y^{(i)}-\bar r_Y)}
{\sqrt{\sum_i (r_X^{(i)}-\bar r_X)^2}\,\sqrt{\sum_i (r_Y^{(i)}-\bar r_Y)^2}}$$

选秩相关而非原始 Pearson，是因为 §2.2 已说明的极右偏：$I$ 的 p99 是中位数的无穷倍，原始值上的
Pearson 会被少数极端值完全主导。计算作用在入池的 **34,180** 人、72 场窗口上。

### 2.7 实测分布（样本：某主播，72 场）

> 本节数字来自 2026-10-20 的**全量重采**数据（已补上文本指纹、统一 UTC）。
> 与上一版相比只有千分位级别变化，结论不变。

| 量 | 值 |
|---|---|
| 出席 $A$ 中位数 / p99 | $0.255$ / $0.967$ |
| 互动 $I$ 中位数 / p99 | $0.000$ / $20.648$ |
| 付费 $P$ 中位数 / p99 | $0.000$ / $5.352$ |
| 强度 $S$ mean / median / p90 | $0.500$ / $0.465$ / $0.766$ |
| 三轴分位相关 | $A\sim I$ 0.412 · $A\sim P$ 0.290 · $I\sim P$ 0.423 |

**$I$ 与 $P$ 的中位数都是 0**：过半入池用户在这 72 场里一句话没说、一分钱没花（机制见 §1.1）。
这正是必须分位化、也是不能直接做线性回归的原因。

### 2.8 边界

1. **分位参照随窗口滑动**：换窗口 ⇒ 池子变 ⇒ 同一人分位可升可降，**跨窗口比较绝对分位不合法**；
2. 质量过滤改变 $N$，出席轴的分母随之变 —— **重采历史会改变历史分位**，历史结论不可原样复用；
3. $S$ 只测"行为强度"，不含"喜欢"或"支付能力"；当忠诚度、价值、意愿读都会过头。

## 3. 类型标注与展示标签

### 3.1 类型 = 主导轴 + 纯度门槛（**约定**）

取三轴分位中最大的两个 $\pi_{(1)}\ge\pi_{(2)}$：

- 若 $\pi_{(1)}-\pi_{(2)}\ge 0.150$ ⇒ 标为该主导轴对应类型（出席型 / 互动型 / 付费型）；
- 否则 ⇒ **综合型**。

**门槛 $0.150$ 没有最优性证明**，作用只是把"明显偏科"与"均衡"分开；换门槛，各类型占比整体平移。
**引用类型分布时必须同时给出门槛值。**

**实测（池 34,180）**：

| 类型 | 人数 | 占池 |
|---|---|---|
| 综合型 | 22,228 | **65.03%** |
| 出席型 | 6,620 | 19.37% |
| 互动型 | 4,240 | 12.40% |
| 付费型 | 1,092 | **3.19%** |

**判定：常见读法「表述过强」。** 把"综合型 65.03%"读成"多数观众三方面都均衡"，是把**门槛的后果**
当成数据结论。真实原因是 $0.150$ 在分位尺度上偏宽：多数人的三轴分位差距达不到这个值。

### 3.2 展示标签：只用于展示，不参与任何计算

标签是一组人可读的定性描述（"常驻""新面孔""仅入场""大额付费"等），共十余个。三条硬约束：

1. **不参与** $S$、类型或任何排序 —— 计算链路里不存在标签这一环；
2. 分母是**全部观测用户**（170,470），**不是入池用户**（34,180）；混用会得出相差五倍的"比例"；
3. 标签名多带价值色彩（"大额付费"），只能出现在**展示层**。

**这是产品约束而非统计约束**：标签一旦进入排序，等价于用"花得多"给观众排名，与 §2.6
"单分数会被读成价值判断"同源。

## 4. 效标加权：让权重由数据说话

**构造**：把窗口对半切，**前半窗**定池与分位，**后半窗**出结果。这样"预测"永远面向未来 ——
若用后半窗定分位再预测后半窗，$R^2$ 会被自身信息抬高。

两种效标，均取对数以压缩右偏：

- **收入**：后半窗付费额 $\ln(1+\cdot)$；
- **留存**：后半窗是否出现（出现 1 / 未出现 0）。

**拟合**：以后半窗结果为因变量、前半窗三轴分位为自变量做带非负约束的最小二乘，权重归一化到和为 1。

**实测**：

| 效标 | 权重 $[A, I, P]$ | 斜率 $[A, I, P]$ | $R^2$ |
|---|---|---|---|
| **收入** | $[0.078,\ 0.148,\ 0.774]$ | $0.192\ /\ 0.365\ /\ 1.910$ | **0.187** |
| **留存** | $[1.000,\ 0.000,\ 0.000]$ | $0.264\ /\ -0.041\ /\ -0.020$ | **0.073** |

**两条读法**：

1. 预测收入时**付费轴占 77.4%**，但模型只解释 **18.7%** 的方差 —— 知道一个人说了多少、付了多少，
   仍猜不准他未来会付多少；
2. 预测留存时**出席轴拿走全部权重**，互动与付费的斜率甚至是**负**的 —— "话多/舍得花钱"不预示会留下。

**判定：$R^2$ 这么低，权重只能当排序参考，不能当因果。** 它回答的是"在这批数据里哪个轴更能区分
结果"，不是"哪个轴导致了结果"。

## 5. 跨 V 对照

**做法**：对两个 V 各自的入池名单，用**超几何零模型**衡量重叠 —— 给定两边池子大小与总体规模，
算出"随机重叠人数"的期望，再看实际重叠与期望之比（lift）与下尾概率。

**实测（本 V 池 34,180）**：

| 对照 | 对方池 | 交集 | 随机预期 | lift | 下尾 $p$ |
|---|---|---|---|---|---|
| 弥月 | 14,767 | 3,168 | 11,025.6 | **0.287** | $0.000$ |
| 星瞳 | 33,050 | 5,288 | 18,237.4 | **0.290** | $0.000$ |

**读法**：两个对照都是**显著贫化** —— 重叠只有随机预期的 29%。这说明受众在**分化**，而不是同一批人
在多个直播间流转。

**限制**：贫化可以有多种机制（推荐算法、开播时段、内容定位、语言），模型**没有对任何一种建模**。
因此"显著"只说明"不是随机"，不说明"为什么"。

## 6. 时间动态

**做法**：把窗口切成多个大小固定、步长固定的滑动窗口（实测 25 场 / 步长 10 场，共 5 个窗口），
每个窗口独立建表与分层，再观察同一批人在相邻窗口间的流动与留存。

- **分层**：按 $S$ 分位切成"核心 / 次核心 / 外层"三档（实测第 1 窗：6,932 / 10,400 / 17,332）；
- **对角保留**：第 $k$ 窗的第 $t$ 层的人，在第 $k+1$ 窗仍处于同层的比例；
- **生存曲线**：以首次出现为起点，看此后每窗仍出现的比例；
- **半衰期与平台值**：对生存曲线做指数拟合得到半衰期；观测跨度不足时，半衰期只能作为**下界**。

**限制**：窗口数少（5 个）时，任何趋势都可能是单次事件的产物；且每次重算都会因为分位参照变化
而轻微移动分层边界 —— 跨窗口比较必须用**相对层位**，不能用绝对分数。

## 7. 直播类型推断

**类型体系**：9 类，来自业务约定（与界面徽章、统计胶囊的颜色体系一致），不是从数据里聚类出来的。

**多信号融合次序**（前面的信号优先级更高）：

1. **人工校正**（用户改过的类型不回退）；
2. **系列 / 栏目**（连载型标题）；
3. **标题评分**（关键词加权）；
4. **弹幕词库**（该场高频词与类型词典的匹配）；
5. **分区**（平台给的分区）；
6. **纪念日 / 特殊日期**。

**一致性**：类型在**写时定稿**（落库那一刻确定），另提供惰性回填以补齐历史。两者用同一套信号，
但回填不会覆盖人工校正。

**限制**：准确率没有独立标注集，只能靠抽样人工核对；误差主要是"混合型直播"（一半唱歌一半聊天）
被强行归入单一类别。

## 8. 弹幕词频与词云

**做法**：对窗口内的弹幕文本分词、去停用词与噪声词、统计词频，再按频次渲染词云。

**三条限制**：

1. **频次 ≠ 重要**：高频词往往是口头禅与弹幕梗，不代表内容主题；
2. 分词词典对网络新词覆盖有限，未登录词会被切碎；
3. 词云与行为结构指标**相互独立**：不共享权重、不互相校正。放在一起看时，读者需自行承担
   "把两套口径混读"的风险。

## 9. 测量学检验

### 9.1 信度：分半相关 + Spearman-Brown 校正

把场次按奇偶分成两半，各自建表，再对**共同用户**（实测 30,155 人）算同一轴在两半上的秩相关 $\rho$，
用 Spearman-Brown 公式校正到全长：

$$R=\frac{2\rho}{1+\rho}$$

| 轴 | $\rho$（两半） | $R$（校正后） |
|---|---|---|
| 出席 | 0.882 | **0.937** |
| 互动 | 0.739 | **0.850** |
| 付费 | 0.595 | **0.746** |

**读法**：出席轴最稳（0.937），因为它同时用了"来了几场"和"到得多早"两个信息；付费轴最不稳
（0.746），因为大额打赏是**稀疏事件**，半窗切分很容易把同一个人分到"有"和"无"两侧。

**没有任何一轴达到 0.950** —— 单人的分数应视为**带较宽置信区间的估计**。

### 9.2 效度：证到哪一步

| 类型 | 证据 | 结论 |
|---|---|---|
| 收敛 | 三轴两两正相关但不共线（0.290–0.423） | 测的是相关但不同的东西 |
| 判别 | 类型分布与标签分布不重合（标签不进计算） | 两套口径没有互相污染 |
| 效标关联 | 收入 $R^2=0.187$、留存 $R^2=0.073$ | **弱**，只能作排序参考 |
| 预测（样本外） | 出席轴对后段出席 $\rho=0.602$ | 中等偏强 |

### 9.3 误差来源清单

| 来源 | 说明 | 现状 |
|---|---|---|
| 抽样 | 只看"产生过事件的人"，纯围观者不可见 | 结构性，不可修 |
| 测量 | 出席靠入场事件；入场不等于观看 | 只能用行为痕迹近似 |
| 口径 | 按天聚合曾用 UTC 日期 | **已修**（统一东八区，520 场受影响） |
| 口径 | 场次跨度：曾用全部事件 min/max | **已修**（改用平台 `stopDate`，回退弹幕跨度） |
| 口径 | 采集曾写本地时间导致 +8 小时 | **已修**（§1.4） |
| 实现 | 互动轴仍用原始条数，未接入去重条数 | 已知，待切换 |

### 9.4 已知的、必然影响结论的实现问题

1. **互动轴未去重**（§2.2）：刷屏者仍会显著抬高互动分；
2. **未核验不等于有错**（§1.7）：没有任何外部源可用时，整个模型是纯内部自洽的。

## 10. 局限与适用边界

1. **只覆盖"产生过事件的人"**（含仅入场者），完全没有行为记录的观众不可见。任何"粉丝总量"的
   陈述都必须说明这一点。
2. **窗口有限**：72 场约覆盖数月，季节性与内容周期都可能混入。
3. **平台不可比**：不同平台的事件模型不同（是否有入场事件、是否有舰队），跨平台比较不成立。
4. **重采会改变历史**：分位参照随窗口滑动，重新采集后历史分位会变 —— 历史结论不可原样复用。
5. **能外推的**：群体层面的相对结构（谁更活跃、类型如何分布、受众是否分化）；
   **不能外推的**：任何个体层面的价值判断、任何因果解释、任何"他没来"的结论。
