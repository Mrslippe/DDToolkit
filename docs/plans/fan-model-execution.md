## 2. 阶段

### P0 · 数据层固化

**目标**：把"读 JSON 事实表 + 逐人聚合"从探针收成一个**有测试**的模块。

**交付物**

| 文件 | 职责 |
|---|---|
| `loader.py` | 数据根解析（可配）、V 注册表、`load_window(v, n)` → `{uid: Fact}` |
| `loader.py` | **只读**；对缺失文件/坏 JSON 给出**结构化错误**而不是崩 |

**关键设计：数据根可配。** 探针用 `datasets/fan-structure/`，正式模块用
`<DATA_DIR>/fan-structure/`，两者由同一个常量切换（`FAN_DATA_DIR`），
并提供 `export_probes_to_data_dir()` 做一次性搬运。**不做双向同步** —— 事实表是快照。

**验收判据**

| # | 判据 | 通过线 |
|---|---|---|
| P0-1 | 三 V × 75 场的 `load_window` 与 `_probe` 版逐人逐字段一致 | 差异 **0 条** |
| P0-2 | 坏 JSON / 缺文件 / 空目录 三种输入返回结构化错误 | 不抛未捕获异常 |
| P0-3 | 单次全量加载耗时 | ≤ **60 秒**（三 V 220 场） |

**风险**：`raw/*.json` 是**非 schema 化**的自由格式（探针演进过 3 版）。
⇒ 加载器必须**逐字段容错**（`a.get("sc_cnt") or 0`），并对缺失字段记一条 warning。

---

### P1 · 计算服务

**目标**：三轴 → 分位 → 三个输出，可对**任意 V、任意窗口**跑。

**交付物**

| 文件 | 职责 | 对应规格 |
|---|---|---|
| `axes.py` | `attendance()` / `interaction()` / `payment()` + `empirical_percentile()` | spec §3.2–3.5 |
| `compose.py` | `participation_strength()` / `type_label()` / `criterion_weights()` / `order_key()` | spec §4.1–4.4 |

**关键设计：三个输出必须分开调用**，不提供 `score()` 这种一揽子函数。
理由：`plans/fan-model-spec.md` §4.1 已论证"单分数会被误读成价值判断" ——
API 层面也**不给**被误用的机会。

**验收判据**

| # | 判据 | 通过线 |
|---|---|---|
| P1-1 | 与 `_probe/fan_output_model.py` 的三个输出逐人一致 | 差异 **0 条** |
| P1-2 | 经验分位变换的四条性质（尺度自由 / 抗异常 / 并列 / 样本内）各一条用例 | 4/4 通过 |
| P1-3 | 次序键的确定性：同一输入跑两次，名单逐行相同 | **相同** |
| P1-4 | 效标加权**只用前半窗口的预测子**（防退化） | 有专门用例守住 |

**风险**：分位变换依赖**参照总体**（入选者）。若调用方传了不同的池子，
分位会变。⇒ `empirical_percentile()` 必须**显式接收参照总体**，不允许默认取全体。

---

### P2 · 校验常驻

**目标**：把 C1–C4 做成**每次计算都跑**的闸门，而不是事后抽查。

**交付物**

| 文件 | 职责 | 对应规格 |
|---|---|---|
| `checks.py` | `check_identity()` / `check_summary()` / `check_coverage()` / `check_minute()` | spec §2.3 C1–C4 |
| `checks.py` | `verdict(session) → {ok / degraded / dropped, reasons[]}` | spec §2.4 |

**关键设计：判据分两类，处置不同。**

```
C1 内部恒等式  → 不过则 dropped（唯一弃用理由）
C2~C4 外部一致 → 不过则 degraded（只降级，绝不弃用）
```

这条**必须在代码里体现为分支**，不能靠注释提醒。理由：`devlog/508` 记录的第一次事故
就是把 C3 当成了弃用理由，20 场可用数据被判死。

**验收判据**

| # | 判据 | 通过线 |
|---|---|---|
| P2-1 | 225 场上"弃 1 保 224"复现 | **完全一致** |
| P2-2 | 人为构造 C1 破坏（删一条记录）→ 必判 dropped | 有反向用例 |
| P2-3 | 人为构造 C3 低覆盖（只给 10% 时间跨度）→ 判 degraded 而非 dropped | 有反向用例 |
| P2-4 | 无入场事件的场次 → 从出勤分母剔除而非记缺席 | 有专门用例 |

**风险**：C3 需要访问外部源（vtb.cat）。若网络不可用，**不能**因此判 dropped ——
必须降级为 `unverified` 并继续。这条要有用例。

### P3 · 名单与标签

**目标**：产出可查询的名单，带标签与次序键。

**交付物**

| 文件 | 职责 |
|---|---|
| `tags.py` | 13 条标签规则（阈值具名常量，见 `_probe/fan_tags.py`） |
| `routers/fan.py` | `GET /fan/{vtuber}/ranked?window=75&by=strength\|retention\|income` |
| `routers/fan.py` | `GET /fan/{vtuber}/tags`（列出标签及占比，用于界面说明） |

**关键设计：`by` 参数是**必填**，没有默认值。** 逼调用方显式选择效标
（spec §4.3 的要求）。界面上表现为"必须选一个排序口径"。

**验收判据**

| # | 判据 | 通过线 |
|---|---|---|
| P3-1 | 三个 `by` 各自的 Top-100 与探针产物一致 | 差异 0 条 |
| P3-2 | 缺失 `by` 时返回 400 | 有用例 |
| P3-3 | 标签占比与探针一致（`大额打米`/`话痨` 各约 1.00%） | 差 < 0.1 个百分点 |
| P3-4 | 名单在极端并列处的次序稳定 | 两次请求逐行相同 |

### P4 · 跨 V 对照（第一版必须做）

**目标**：回答"某人是 A 的核心、在 B 只是外层"这类问题，**且带上零模型**。

**交付物**

| 文件 | 职责 |
|---|---|
| `cross_v.py` | `overlap(a, b)` → 实际 / 超几何期望 / lift / 双向不对称比例 |
| `cross_v.py` | `tier_shift(uid)` → 该 uid 在各 V 上的**层级**（不是分数）与迁移方向 |
| `routers/fan.py` | `GET /fan/cross?vtubers=a,b&window=75` |

**关键设计：只比层级，不比分数。** spec §5.5 已否证测量不变性
（三轴 75 分位最多差 4.2 倍，交叉套用 39% 超标）。API 层**不返回**跨 V 的分数比较，
只返回层级 {"核心"/"次核心"/"外层"} 与迁移方向。

**零模型是必选**：单纯报"A∩B = 300 人"不可解释 —— 两个主播的受众本就有天然交集。
必须同时给出**超几何期望**与 **lift**，并**分方向**给 `|A∩B|/|A|` 与 `|A∩B|/|B|`。

**池子的选择**（超几何的 N）必须**写死一个并说明**：默认取两 V 入选者的并集，
因为"全库所有 uid"会随库增长而漂移、使 lift 不可比。

**验收判据**

| # | 判据 | 通过线 |
|---|---|---|
| P4-1 | 两 V 交集 = 各自名单求交 | 完全一致 |
| P4-2 | 超几何期望在"两 V 完全相同"的构造数据上等于实际重叠 | 有构造用例 |
| P4-3 | lift 与双向比例的分母符合口径 | 有专门用例 |
| P4-4 | 跨 V 接口**不返回**分数比较 | 有反向用例（字段不存在） |

**风险**：**同企划 / 常联动的 V 之间重叠天然更高**，那不是粉丝结构的发现。
⇒ 接口必须把两 V 的联动关系作为**已知协变量**暴露给调用方（哪怕只是提示），不能让其被读成因果。

## 3. 测试义务

每个阶段**必须**留下的用例（不是"建议"）：

| 阶段 | 用例数（下限） | 必须覆盖 |
|---|---|---|
| P0 | 6 | 正常加载 / 缺文件 / 坏 JSON / 空目录 / 字段缺失容错 / 与探针一致性 |
| P1 | 10 | 四性质 + 三输出一致性 + 次序键确定性 + 效标只用前半窗口（2 条） |
| P2 | 8 | 四判据各 1 + **反向用例 3**（C1 破坏、C3 低覆盖、外部源不可用） |
| P3 | 6 | 三口径一致 + 缺 `by` 400 + 标签占比 + 并列稳定 |
| P4 | 7 | 交集 / 超几何构造 / lift / 双向比例 / 不返分数 / 池子口径 |

**四条铁律**（全阶段适用）

1. **不许碰真实数据目录**：用例用 `tmp_path` 造微型事实表。
2. **反向用例与正向用例同权**：一条判据若不能变红，它就保护不了任何东西。
3. **参数改动必须同步用例**：阈值是具名常量，改常量就要看用例是否还成立。
4. **不许用 `_probe/` 的脚本做被测对象** —— 那是要被替代的。

## 4. 施工期间必须守住的不变量

| # | 不变量 | 后果 |
|---|---|---|
| I1 | **`raw/` 只读** —— 任何代码路径都不得覆盖事实表 | 覆盖 = 销毁证据（上游会漂移） |
| I2 | **C1 是唯一弃用判据** | 把 C2~C4 当弃用理由会误杀可用数据（已犯过一次） |
| I3 | **缺失 ≠ 零** —— 分子分母用同一组场次 | 会把所有人的出席率统一压低 |
| I4 | **`model_version` 冻结** —— 换算法不得原地重算历史 | 与不变量 40 同源；改了不会有东西变红 |
| I5 | **`by` 必填** —— 不提供默认排序口径 | 默认等于默许误读 |
