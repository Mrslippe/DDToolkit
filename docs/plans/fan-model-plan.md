# 粉丝结构分析 · 模型方案（统一版）

## 0. 口径定案（不可再议）

| 事项 | 定案 |
|---|---|
| **真源** | **danmakus 是主来源**；其它源（vtb.cat / zeroroku）只当**校验器** |
| 弃用规则 | **只有内部不自洽（C1）才弃用**；外部不一致一律不弃用 |
| 时间 | 存储 UTC；分天/分月按**东八区**；场次时长**优先平台 start/stop** |
| 场次身份 | `session_key IS NOT NULL` = 一场（一行 ≠ 一场，会重复约 24%） |
| 单位 | 一条弹幕 = 一个观测；一次「出席」= 该场出现任意事件 |
| 窗口 | 请求 N 场 ≠ 分析 N 场（质量过滤会减少） |

## 1. 数据层处理链（L0）

采集 → 落盘的每一步都可能静默失败，因此链路固定为：

```
枚举场次（channel API，含 startDate/stopDate/danmakusCount/totalIncome）
  → 区间筛选
  → 逐场：分页取全（先不带 pageNum 取大页；不够再 5000/页，≤60 页）
  → 聚合（类型直方图 / 按用户 m,mt,mh,e,et,p,sc,gift,guard / uniq / maxrep）
  → 回放裁剪（按小时比 (uid, 文本哈希) 多重集合，≥80% 且 ≥50 条 → 丢弃该小时起的弹幕）
  → 率降裁尾（5 分钟桶 / p75 基线 / 10% 阈值 / 5 小时后 / +30min 宽限 / 只变短）
  → 质量闸（L1/L2/L3，见 §3）
  → 原子写（先 raw 后 stats）
```

**已知的上游不稳定性**（都必须在质量闸里兜住，不能靠"应该没事"）：

- 大 `pageSize` 会被截断且谎报 `hasMore=false`；`total` 也可能被谎报成 100,000；
- 部分场次**带 `pageNum` 就返回 0**；
- 并发时偶发空页；
- 同一场不同时间的查询结果会变（镜像在持续补索引）；
- `stopDate` 会偏长（有一场报 12.9h，实际 6h）。

## 2. 测量层（L1–L7）

| 层 | 内容 | 关键规则 |
|---|---|---|
| 三轴 | 出席 / 互动 / 付费 | 出席 = (att_n + 档内时机分位)/(N+1)，**每场一档**；互动分母是出席场次；付费取 log1p |
| 分位 | 经验分位 | 参照总体**必须显式传入**；池 = 出席率 ≥ **0.10** |
| 强度 | $S=\frac13(\pi_A+\pi_I+\pi_P)$ | **等权是约定**；均值恒 0.5 是构造结果 |
| 类型 | 主导轴 + 纯度门槛 **0.15** | **约定**，不是发现；引用必须带门槛值 |
| 标签 | 十余个，只展示 | 不参与排序；分母是全部观测用户 |
| 效标 | 前半窗 → 后半窗 | 收入 $R^2=0.187$、留存 $R^2=0.073$：**只能当排序参考** |
| 跨 V | 超几何 + lift | lift 0.287 / 0.290 ⇒ 受众分化；不解释"为什么" |
| L6 | 滑动窗口 / 对角保留 / 半衰期 | 观测不足时半衰期只能当下界 |

## 3. 质量闸（三层，只标记不丢弃）

| 层 | 对账 | 判定 |
|---|---|---|
| **L1** | `type_hist` 求和 vs `records` | 不等 → `inconsistent` |
| **L2** | 平台 `danmakusCount` / `totalIncome` | 我们 < 90% → `low_coverage` / `low_income` |
| **L3** | vtb.cat `/live/list` 的 `Message` / `Money` | 我们 < 90% **且对方收得够多** → 同上 |

**匹配规则**：vtb 的 `StartAt` = 我们的 UTC epoch **+8 小时**（它的坑）；容差 1 小时；
`Message < 100` 视为"对方没索引"，不参与判定。

**状态**：`ok / no_external / low_coverage / low_income / inconsistent`，写进 `stats["quality"]`。

**独轮车**：单一判据（不同文本率 ≤20%），结果以 `spam` 字段随排行返回；
只标记不剔除（实测只污染头部名单，不改整体结构）。
分析层按需过滤，**默认照用**（外部少收录是常态，danmakus 是超集）。

## 4. 参数表

| 参数 | 值 | 依据 |
|---|---|---|
| **入选门槛** | **池 = 2×ACV**（核心 0.75×ACV、次核心 1.25×ACV） | 2026-10-23 用户定案；ACV = 去头尾 10% 的平均同接，缺数据时回退出席率 10% |
| 纯度门槛 | 0.15 | 类型判定 |
| 出席轴档位 | 每场一档 | 3 档会跨档错位（实测 ρ 0.536 vs 0.602） |
| 率降基线 | 前 5 小时 p75 | 中位数会被安静期拉低 |
| 率降阈值/宽限 | 10% / 30min | 5% 裁不动、15% 过切 |
| 回放阈值 | 80% / ≥50 条 | 内容哈希比对 |
| 分页 | 5000/页 × 60 页 | 大页会被截断 |
| 覆盖门限 | 0.90 | 低于此才标记 |
| ACV 裁剪 | 头尾各 10%（按点数） | 实测头 10% 只有整体的 55–65%，不裁会把 ACV 压低 2%–8% |
| 独轮车 | **不同文本率 ≤ 20%** 且累计 ≥200 条（等价重复率 ≥80%） | 判据经 13 个真实样本校验：真独轮车 1.7%–15.5%，话痨 28.7%–78.2% |

## 5. 验证结论（2026-10-21 · 323 场新基线）

| 项 | 结果 |
|---|---|
| 分半信度（Spearman-Brown） | 出席 **0.901 / 0.937 / 0.906** · 互动 0.844 / 0.850 / 0.833 · 付费 0.741 / 0.745 / 0.675 |
| 出席轴样本外 | 出席轴 ρ 0.820 / 0.878 / 0.817 vs **纯出席率 0.822 / 0.877 / 0.820** —— 时机几乎不带来增量 |
| 效标 · 收入（**log1p**） | R² **0.227 / 0.200 / 0.142**；权重 0.057 / 0.139 / **0.804**（付费主导） |
| 效标 · 留存（**跌幅 ≥50%**） | R² 0.068 / 0.074 / 0.056；流失率 16.1% / 11.1% / 11.2% |
| 跨 V lift | 0.289（弥月×明前奶绿）· **0.173**（弥月×星瞳）· 0.292（明前奶绿×星瞳） |
| 七海 96 场 | 覆盖率中位 1.000；回放 1 场；率降 0 场（长场次是真的） |

**效标口径（2026-10-21 定案，别再改回去）**：

- 收入必须用 **log1p**：90.6% 的人零付费、前 1% 贡献 89.5% 的收入，
  原始金额的 R² 只有 0.022（被鲸鱼淹没），log 尺度是 **0.200**；
- 留存必须用**相对跌幅 ≥50%**，不能用"后半有没有来"：池子已经筛过出席率 ≥10%，
  后半留存率高达 98.4%，二值方差仅 0.0157，R² 注定只有 0.03。

两组数字与 10-17 的旧记录（**0.187 / 0.073**）在误差内一致 —— 旧记录用的就是这套口径，
之前的 0.022 是因为我误用了原始金额。

**与 10-17 旧记录的一致性**：分半信度 0.937 / 0.850 / 0.746 与效标 0.187 / 0.073 全部复现。
结论不变：**收入只能解释约 20% 的 log 方差、留存约 7%，排序只能当参考，不能当预测。**
