# 开发循环（DEV-LOOP）

## 0. 唯一判据

**一个流程动作值不值，只看它有没有缩短「改错 → 发现」的时间。**

判据/探针 → 缩短 ✅ ；反向验证 → 缩短 ✅ ；**开工前通读规范、写叙述性长文 → 不缩短 ❌**。

### 0.1 每批的预算

| 允许 | 不许 |
|---|---|
| **会红的判据**（探针 / 测试）—— 必需 | 叙述性长文（那是 devlog 的体裁） |
| **活文档**：改了才同步，**1–2 行 + 指针** | **复述真源**（改一次要同步 N 处，见 §0.3） |
| **devlog：每需求 1 篇、≤40 行**；字母级微调并进现有篇 | 同一需求的每个字母各开一篇 |
| **机器判据优先**（能写成断言就别写成散文） | **流程新规默认不加** |

### 0.2 新规矩的准入门槛

**同类事故 ≥2 次**才升级成"规矩"（进本文件 / 进 skill）；**只发生一次的写进 devlog 即可**。
判据一句话：**这条经验三个月后还成立吗？** 成立 → 提炼；只对本批次成立 → 留 devlog。

### 0.3 复述 = 负债（能引用就别复述）

实测同一条规则的复述面可达 **数十处 / 十几份文件**，而单条搜索词的覆盖率**最高一半** ——
原因不是搜得不用心，是**复述的本质就是换词**，而搜索的前提是措辞相似。
已出过真事故：skill 里写「`MIGRATION_HEAD` 当前值 `f004`（17 个版本）」，真值是 `f007` / 20，
**门禁一直报"数字一致 ✓"，一份错误事实挂在"开工前必读"里没人发现。**

⇒ **规范只有两个合法落点：真源（代码 / 测试 / 脚本）与指针。** 改规则时多词搜一遍（汉字数字 /
阿拉伯数字 / 换一种分解方式），并**承认会漏**。

⚠️ **搬运 ≠ 复制**（2026-09-30 加）：把一段内容从 A 文档搬到 B 文档之前，**先查 B 里有没有同一批事实**。
实测把 `ARCHITECTURE.md` 的抓取小节搬进 `backend/FETCH-PIPELINE.md` 时，
**12/12 个关键词在目标文档里都已存在** —— 那不是搬运，是在造第二份。查法：取该段的关键标识符，
数它们在目标文档**原有部分**的出现次数；全命中就该整段丢掉，只留指针。

**数字三分法**：测量值**不写死**（指向脚本或 `gen_doc_numbers.py --list`）；定义值照写（它就是规格）；
带日期的快照必须标日期。

### 0.4 文档与判据都要能退役

- **前提消失**的规矩 → 删；**从立起来就没红过**的判据 → 每几批审一次，删；
- **能从真源重建**的段落 → 压成指针；
- `plans/` 里的批次方案 —— **落地后必须删除或并入模块文档**。

### 0.5 成本纪律

```
花费 ≈ 步数 × 每步上下文 × 缓存单价 ＋ 输出 × 输出单价
```

实测一个"改 1 行 CSS"的批次：**101 步 × 148k 上下文 ≈ 15M token**，其中 99% 以上是缓存命中读入。
四条推论：① **成本与需求大小几乎无关** ⇒ 小需求也按批收尾，别攒着；② 别把 `totalTokens`
当"新输入"看；③ 触发收尾的信号是**上下文体量**（>200k 就该收），不是轮次；
④ 该丢的是**工作台**（一次性读进来的原文、长门禁输出），不该丢的是**需求知识** ——
后者压成稳定档案（稳定 = 缓存命中 = 几乎免费）。

## 1. 需求分级 → **只读这几份**

**本表是全仓唯一的这张表。** 判据是**文件**，不是"看起来像不像 UI"。

| 级 | 判据（碰了哪些文件） | 必读（**只读这些**） | 门禁 | 收尾 |
|---|---|---|---|---|
| **L0** 样式值 / 文案 | 单个 CSS 值、文案串 | `frontend/UI-MAP.md` 对应节 | C | commit |
| **L1** 单组件 / 探针 | 1 个组件文件；`scripts/ui_probe.py` | UI-MAP 对应节 ＋ `frontend/PROBE.md`（改探针时） | C | commit |
| **L2** 前端特性 / 跨层 | 多组件 · `hooks/` · `api/` · `styles/tokens.css` | `frontend/ARCHITECTURE.md` ＋ UI-MAP | B | devlog 一段 |
| **L3** 后端模块内 | 1 个 `app/services/**` 文件 | **该模块文档** ＋ `backend/ARCHITECTURE.md` 的跨模块不变量 | A | devlog 一篇 |
| **L4** 数据 / 契约 | `app/models/` · `alembic/` · 路由契约（路径 / 状态码 / 请求体） | `backend/DATA-MODEL.md` ＋ `backend/HTTP-CONTRACT.md` ＋ 跨模块不变量 | A ＋ 迁移检查 | devlog ＋ 活文档 |
| **L5** 复杂 / 跨模块 | 多模块 · 新平台 · 新宿主 · 碰 `src-tauri/` | `OVERVIEW.md` ＋ 相关模块 ×N ＋ **`plans/` 里一份批次计划** | A / full | 分批，每批一 devlog |

**拿不准就往上一级靠。** 级数只决定"读哪几份"和"跑哪档"，不决定工作量。

## 2. 各级操作卡

### L0 / L1 · 前端表现

```powershell
python scripts/gate.py                                 # 自动判档；C 档约 46s
python scripts/ui_probe.py --vtuber 15 --seed-accounts 8   # 布局不变量（三档）
```

- ⚠️ **`--vtuber 15` 必须显式给**：不传时探针自动探测，探测失败会让路由落到 `/`、
  **所有布局断言静默空转**，而脚本照旧打印 `[ok]` 退出 0。
- ⚠️ 探针需要**真浏览器 + Vite + 后端副本**，在受限沙箱里会失败；失败时保留 `_ui_probe_tmp/`。
- 改探针判据时先读 `frontend/PROBE.md`（虚拟时间的三条硬事实 → 判据本身会错的三种形态）。

### L2 · 前端特性

```powershell
python scripts/gate.py          # B 档：C 档 ＋ vitest
```

跨组件、动 hooks / api 时读 `frontend/ARCHITECTURE.md` §4（场景机与原子提交）——
**切 V 全程不能出现"中间加载"帧**是这一层的硬要求。

### L3 · 后端模块内

```powershell
python scripts/gate.py                     # A 档：＋ pytest ＋ cargo
python -m pytest -q tests/test_services.py # 定位时单跑
```

先读**那个模块的文档**（它的 `verify` 字段就是该模块的验收命令）。

### L4 · 数据 / 契约

在 L3 基础上多三条：

1. 新增迁移 → 同步 `app/main.py` 的 `MIGRATION_HEAD`（测试断言与 alembic head 一致）；
2. 新增挂 `accounts` / `vtubers` 外键的表 → **同步 `app/services/purge.py`**（漏一处，删 V 会被
   `foreign_keys=ON` 整次回滚）；
3. 路由契约变了 → 同步 `backend/HTTP-CONTRACT.md` 与 `docs/GLOSSARY.md`。

### L5 · 复杂 / 跨模块

**先写 `docs/plans/<主题>.md` 的批次计划**，内容四件事：改哪里 · 先补哪条会失败的用例 ·
怎么反向验证 · **什么时候必须停**。然后一批一个会话、一批一次收尾。
批次全部落地后，把仍然成立的知识并进模块文档，**把计划删掉**。

## 3. 门禁分档

```powershell
python scripts/gate.py            # 自动判档并执行
python scripts/gate.py --plan     # 只说要跑什么（会打印"哪条路径把档位顶上去的"）
python scripts/gate.py --tier full  # 发版前 / 拿不准时兜一次
```

| 档 | 触发（命中即此档） | 跑什么 |
|---|---|---|
| **C** 局部/表现 | 其余一切（样式值、探针、文档、devlog） | tsc · eslint · doc_check · docs_gate · syntax · 探针三档 |
| **B** 跨层/特性 | `frontend/src/**`（除 `styles/`·`dev/`）· `package.json` · `UI-MAP.md` | C ＋ vitest |
| **A** 数据/契约 | `app/` · `alembic/` · `tests/` · `backend_main.py` · `frontend/src-tauri/**` · `pyproject.toml` / `uv.lock` · 有 pytest 护栏的脚本 | B ＋ pytest ＋ cargo |
| **full** | 发版前 / 拿不准 | 改用 `dev_check.py` 一把梭（含 pytest 与后端冒烟） |

⚠️ **档位映射漏一格 = 那个文件从此没人守，而且不会自己响**（已抓到三次：`doc_check.py`、
`frontend/src-tauri/**`、`docs_gate.py`）。**新增门禁脚本时必须同时**：加进 `A_FILES`、
加进 `steps()`、写用例。

⚠️ **只查一半的检查 = 假证明**（2026-09-30 加）：上一条之所以能漏半个月，是因为那条
"映射路径必须存在"的用例**只遍历 `A_FILES`、不查 `B_FILES`** —— 文档搬家把 `docs/frontend/UI-MAP.md`
改成了 `docs/frontend/UI-MAP.md`，而 `B_FILES` 里的死映射没人管。**写"这类东西都不许出错"
的检查时，遍历面必须是全集**；只覆盖一半的守卫比没有更危险，因为它会让人以为已经守住了。
⚠️ **探针永远跑满三档**（实测单档 28.3s / 三档 26.6s —— 成本全在启动）；
**cargo 只在 A 档跑**（编译成本真实存在，与探针不同性质）。
⚠️ **读门禁结果别把 stderr 灌进管道**：判据是脚本自己那行 `=== 汇总 ===`，**不是 shell 退出码**。
⚠️ **计时从命令自己那一侧取**：早先 tsc / lint 的"29–40s"是后台作业的**等待时长**（含排队），直跑是 6s / 4s。

**CI**：真源是 `.github/workflows/`（两条腿）。`src-tauri` 编译不了非 Windows，所以 Rust 腿固定在
Windows，Linux 腿只做与平台无关的。**注释里的命令会让文本型断言假绿** —— CI 断言只认 `run:` 里
真会执行的命令。

## 5. 反向验证：判据必须能变红

**绿 ≠ 断言有效。** 写完判据要做一次"破坏性改动"，确认它**精确报红**；红不了就说明那条断言是装饰，
删掉或改写。

- **改不动就用更极端的手段**（显式尺寸 / 负偏移 / 直接改被测元素），直到它红。
- ⚠️ **变异必须保证能终止**：把"循环推进"本身改掉时被测代码会**不推进**，反向验证脚本自己挂死。
  两条防线：给 `subprocess` 加 `timeout=`（超时当"红"但要打印出来），
  以及给测试替身加硬闸（"同一游标最多服务 N 次"）。
- ⚠️ **"没发生 X"这类断言必须配正对照**：先断言一次"没熔断时确实会打一发" ——
  它同时锁住"补丁打对了函数"和"这条路径真的会走到那儿"。
  ⚠️ **反面判据还要写清"症状"**（2026-10-04 加，`devlog/333`）：抖音"删签名"预期 403、实测 **200 + 0 字节空体**（只看状态码会判成通过）；**免签通道**会让对照失效 ⇒ **"缺参数"与"参数写错"必须分开测**。
  ⚠️⚠️ **结构判据的锚点必须是"语法位置"，不是子串**（2026-10-07 加，`devlog/414`/`416` 两天内犯两次）：
  `includes('x')` 会被**注释里**的同一句话满足；`indexOf('.x.dragging')` 会命中注释里提到的选择器名
  ⇒ 都是"判据全绿地量错东西"。用**行首锚定正则**，且**改完必须再变异一次**（唯一能发现它的办法）。
- ⚠️ **别用"症状"当跳过断言的前提**；**临时脚本"写回原文件"必须逐字节**（换行会被翻译）。
  ⚠️ **又踩一次（2026-09-30）**：把仓库行尾统一成 LF 的批量脚本，**二进制扩展名白名单里漏了
  `.icns`** ⇒ 它被当文本读、里面恰好是 `0D0A` 的 13 处字节被换成 `0A`，**图标静默损坏**
  （git 当二进制存、不会报错 —— 只有逐字节比对才发现）。⇒ 改行尾/编码前按 `.gitattributes` 的
  binary 表对齐排除清单，改完逐字节比对。

## 6. 开发纪律（与本项目强相关的几条）

- **用例不许碰真实数据目录**：测试库必须是**每进程独立目录**（同类事故 2 次后升级成规矩）。
- ⚠️ **动了测试文件就必须真跑一次 pytest**（2026-09-30 加）：那一批里两处翻车都不是逻辑错，
  而是"没跑过就以为对了"——① 新写的门禁用例断言了**旧的上限值**（改上限时忘了同步测试）；
  ② 用正则按函数名删死用例时，**把挂在被删函数尾部的模块级常量一起删了**，
  连带打断 9 个仍在用的用例。**静态看结构看不出来，跑一次两秒钟就露。**
- **加了门禁之后，把所有"打自己后端"的调用方过一遍**：症状会伪装成"布局坏了 / 网络不可达 /
  上游挂了"（S1 加会话 token 时的实际教训）。
- **本地门禁跑的是 3.14**：注解里"名字没导入"这类错**本地永远看不见**（CI 的 3.12 腿才会红）。
- ⚠️ **"应用里没效果"先看它跑在哪个解释器上**（2026-10-02 加，`devlog/276`）：dev 壳起后端时打印的
  `[ddtoolkit] dev 模式：<python> backend_main.py` 就是答案（`Get-CimInstance Win32_Process` 的
  `ExecutablePath` 可对账）；只装进 `.venv` 的可选依赖在系统解释器下静默缺失。报"抓不到数据"先看**我们发没发请求**（`devlog/338`）。
- ⚠️ **界面的"说法"必须跟着补救动作走**（2026-10-05 加，devlog/338）：同一个"受限"背后可能是
  "去登录"或"去设置打开开关"，写成同一句话（当时统一写「需要登录」）⇒ 用户拿着有效凭据
  反复重粘，而问题不在那儿。**换个补救动作 = 换个状态值 + 换个说法**（能力矩阵四态就是这么加的），
  并且**光有正确文案不够**：探针要按状态属性把"状态 → 说法"逐条量出来校验，截图看不出来。
- ⚠️ **替身注入 ≠ 接线正确**（2026-10-02 加，devlog/277）：只在测试里被注入的协作对象
  （签名器 / 时钟 / HTTP 客户端…），必须有一条判据打在**生产真正用的那个实例**上
  （注册表单例、模块级 `fetcher`）。小红书就是这么"全绿上线"的：测试里人人传 `FakeSigner()`，
  生产那个单例攥着 `NullSigner` ⇒ 请求**未签名**发出、上游一律 **406**，而所有用例都过。
  **自查生产行为时也别手搓一个对象**（`XhsSigner()` 单测能 200，注册表那条路才是真相）。
- **成功路径也要有判据**（2026-10-02 加，devlog/277）：接平台时"成功一次"必须是一条用例，
  且回包形状要照**真机抓下来的**写、别照文档猜 —— 小红书的账号信息字段映射错了
  （昵称/头像/粉丝数全空），而那个文件里 `fetch_user_info` **只有失败用例**，所以一路绿着。
- ⚠️ **"点了没反应"先看是不是权限被拒**（2026-10-02 加，devlog/278）：WebView 里裸
  `<a target="_blank">` 会走壳的 `shell:allow-open`，而本仓**刻意删掉了那条权限**
  （改用带主机白名单的 `open_external`）⇒ 链接打不开 + 一条内部报错。外链一律走
  `utils/externalLinkGuard.ts`（全局捕获，平台富文本里的链接也覆盖）。
- **「挂死」不是「变红」**：先抓栈，别猜；**「单跑绿」不算数**（并发/顺序相关的问题单跑必绿）。
- **一次只开一个会话改代码**（本仓**不采用**并行）：`git worktree` 建立成本不高但**协调成本更高**
  —— 枢纽文件太集中（`ui_probe.py` / `tokens.css` / 共享文档）。想并行就在一个会话里分批次做。
  ⚠️ **别拿 `git stash -u` 回答只读问题**：它是**全仓**操作，曾 stash 到另一个进程正在改的 6 个文件。
- **全新检出开箱不能构建 Rust 壳**：`binaries/backend/` 被 gitignore，而 `tauri.conf.json` 的
  `bundle.resources` 指向它 ⇒ 先跑 `scripts/build_backend.py`。看到那个 glob 报错别怀疑编译器。
- ⚠️ **"反复修不好"时，先存档再清空重来，成本通常低于继续打补丁**（2026-10-01 加，`devlog/270`）：
  小窗那条线连做四版，最后一版真机评价仍是"不丝滑 + 左右闪 + 位置乱跑"。**准入判据**：当"修一次冒一个

- ⚠️ **"能过门" ≠ "不带头也能过"**（2026-10-03 加，devlog/292）：`tests/conftest.py` 会给**每个**
