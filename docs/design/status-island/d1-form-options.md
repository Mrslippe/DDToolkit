⚠️ **而且 200 这个数在代码里有"两个源"，要一起改**（我核对了探针量的是哪个）：

## 2. 四条路线的代码级差异

### A. 折叠宽 = 面板宽（折叠 280×40，展开 280×40+6+H）

**改什么**：
1. `WIDGET_SIZE` / `WIDGET_COLLAPSED` 的 `w: 200 → 280`；`status-island.css:162` 同步
2. `lib.rs:785` `const W: f64 = 200.0 → 280.0`（**探针验不到这处**，见 §1）
3. 三处探针断言（§1 那三条）

**展开逻辑**：`w = Math.max(cur.w, WIDGET_PANEL_W)` = `max(280,280)` = **280 恒定** ⇒
`anchorX - w/2` 与 `cur.x` 的关系变成"恒等"，锚定计算**退化为不动**。
`widgetExpandGeom` 的横向部分从此没有实际作用（但**代码可以原样留着** —— 它仍要处理夹取）。

**代价**：静息态从 5:1 变 7:1（200→280 宽），更像一条"带子"。

### B. 三档（200×40 →只变宽→ 280×40 →只变高→ 280×40+6+H）

**改什么**：在 A 的基础上**新增一个中间态**：
- 新状态（如 `preview`）与它的几何函数
- `StatusWidgetWindow.tsx` 的 `sync()` 要从"二值（展开/收起）"改成**三值状态机**；
  现在 `expanded.current` 是个 `bool`（`:304`），要变成枚举 + 变迁表
- **悬停两段式的触发源**：现在悬停只有一个 `setOpen`（`StatusIsland.tsx` 的 `hoverIn`），
  要拆成 stage1/stage2 两档（需要新的 120ms/再延时 或位移判定）
- 探针要新增一条状态机断言（三段各自的尺寸 + 中间态不被跳过）

**代价（读完代码后我认为比 review 时估计的重）**：不是"多一档"这么简单 ——
**它把"展开/收起"从二值改成了状态机，并且要动悬停判定这个已经被 3 条判据钉住的地方**
（`ui_probe.py:3257-3266`：掠过不弹 / 悬停必弹 / 移入保持 / 离开必收）。
R38 批 5d/5f/5g 三轮真机修复都在这条链上。

### C. 不动

保持现状。锚定逻辑继续背着 —— 但它**已经在工作且有三轮真机验证**（devlog/183/187/188）。

### D. 恒定宽透明舞台（FocuSD 路线）

**改什么**：窗口固定成 `280 ×（最大可能高）` 不动，形变全在 CSS 层。
**代价**：那个透明区域会**盖住桌面且吃掉点击**，除非补鼠标穿透。我们现在**有**穿透开关
（`set_widget_click_through`）但**默认关**，且是"整窗穿透"—— 走 D 需要的是
**"按胶囊矩形选择性穿透"**（FocuSD 用 12ms 轮询 + 圆角命中 + 用实测窗宽反推 DPI，`lib.rs:1278-1329`）。
**这是新增一个常驻轮询线程 + 一套命中测试。**

## 3. 我的建议：**A**（改变了 review 里的 B）

读完代码后，三条理由让我从 B 转向 A：

1. **A 让锚定问题真正消失，B 只是让它分两步发生。**
   A 之下 `max(280,280)` = 280 恒定 ⇒ 窗口**永不横向变化** ⇒
   锚定、`preloadPos` 防漂移（`widgetWindow.ts:218-227`）这些复杂度**失去存在理由**（可保留但不再被触发）。
   B 之下第 1 步仍然横向变化、仍然要锚定 —— **我们保留了复杂度，只换来个"分两步"的观感**。

2. **B 的成本被我低估了**：它要动**悬停判定那条链**，而那条链上有 4 条判据 + 三轮真机修复史。
   为一个"悬停时多显示几个字"的中间态去动它，**风险收益比不划算**。

3. **A 的代价（静息更宽）可以被"吸附位"抵消掉**：
   静息 280 宽如果落在**屏幕顶部居中**（用户在 §1.4 原话里提过的落点），
   它就是一条居中的状态条 —— 观感上接近 LuckyIsland 的 compact（720×80），
   **并不比"右下角一块 200×40 的方块"更打扰**。这也是我建议 A 与 D2 一起定的原因。

### A 的窗口尺寸建议

| | 现在 | A 之后 |
|---|---|---|
| 折叠 | 200×40 | **280×40** |
| 展开 | `max(cur.w,280)` × `40+6+H` | **280 × `40+6+H`**（宽恒定） |
| 横向位移 | 有（-40px 再居中） | **0** |

⚠️ **一个要一起定的细节**：80px 的增量（200→280）会让**右下角默认落点**（`defaultWidgetPos`，
`y = 屏高−40−72`）的横向位置变化 —— 需要重新核一次"右下角 + 280 宽"在 1280 档下是否仍留够
`WIDGET_MIN_VISIBLE`。这有单测覆盖（`widgetWindow.test.ts:82-95`），改常量后会跟着跑。

### ⚠️ D1-a2：A 会让两条既有判据**前提消失**（我实际算过）

A 之下 `cur.w` 恒为 280，而 `w = Math.max(cur.w, WIDGET_PANEL_W) = 280` ⇒

```
anchorX = cur.x + 140
raw.x   = anchorX − 140 = cur.x      ← 恒等，锚定计算不再产生任何位移
```

**后果**：`widgetWindow.test.ts:113` 那条
「下面装得下 ⇒ 向下展开，**顶边中心不动**（200→280 胶囊不跳）」**仍然会绿** ——
但它喂进去的 `MID = {x:1000, y:300, w:200, h:40}`（`:105`）**在生产里再也不会出现**。
它会变成一条**描述旧世界的、空转的**判据。

按 `DEV-LOOP.md` §0.3「**判据的前提消失后，判据本身要退役**」，这一批要做的**不是删**，而是**改写**：

| 现在 | A 之后应该改成 |
|---|---|
| 断言"200→280 时中心不动" | 断言"**展开前后 x 完全不变**"（因为宽恒定）—— 这条更强，且**能变红**（改错宽度就会红） |
| `MID` 用字面量 `w:200` | 改成 `WIDGET_COLLAPSED.w`，让它**跟着常量走**，不再手写会漂的数 |
| `:216` `expect(g.x).toBeGreaterThanOrEqual(WIDGET_MIN_VISIBLE - WIDGET_PANEL_W)` | 这条是夹取下界，**仍然有效**（夹取路径不变），保留 |

**顺带一条"一个事实两个源"**：A 之下 `WIDGET_COLLAPSED.w === WIDGET_PANEL_W === 280`。
两个常量表达同一个数 ⇒ 要么在注释里写明"**它们是同一个数，改一个必须改另一个**"，
要么让 `WIDGET_PANEL_W = WIDGET_COLLAPSED.w` 单向派生。**我倾向前者** ——
它们语义不同（折叠尺寸 vs 面板尺寸），将来若 D2 让静息落点变成"贴顶条"，
两者仍可能再分开；派生会把这条路堵死。

### ⚠️ D1-a 的门禁档位：**必须让 `widgetWindow.ts` 进同一个提交**

我核对了 `gate.py:62-115` 的档位映射，有个**要绕开的坑**：

| 文件 | 档位归属 |
|---|---|
| `frontend/src/utils/widgetWindow.ts` | **B**（`frontend/src/utils/` 前缀）⇒ 会跑 vitest |
| `frontend/src/styles/status-island.css` | **不在任何列表** ⇒ 不抬档 |
| `frontend/src-tauri/src/lib.rs` | **不在任何列表** ⇒ 不抬档 |
| `scripts/ui_probe.py` | **不在任何列表** ⇒ 不抬档 |

⇒ **只要 `widgetWindow.ts` 在改动里，档位就是 B（vitest 会跑）** —— 这对 D1-a 成立。
但**如果把 D1-a 拆成两个提交**（先改 CSS + Rust 的常量、再改 TS），
第一个提交会判成 **C 档、跳过 vitest** —— 而那正是最需要跑 `widgetWindow.test.ts` 的时刻。

**结论：D1-a 的常量改动必须放在同一个提交里。**（这也是一条可提炼的档位漏洞：
`styles/*.css` 与 `src-tauri/**` 改动本身不抬档 —— 记在 §6，本方案不顺手修它。）

### ⚠️ 一条我建议**不要**做的

**不要删锚定与 `preExpandPos` 防漂移逻辑**，即使 A 之下它们不再被触发。
理由：它们**同时也是夹取路径的一部分**（贴边/多显示器/极小屏），
而且 `widgetCollapseGeom` 的 `restore` 参数还有"退化路径"在用（`widgetWindow.ts:236-246`）。
**只有当"宽度恒定"被证明在所有路径成立时才谈删除** —— 那至少要先有 D1-b 的吸附位落地。

### ⚠️ 顺带发现（已核对，不在本方案范围）：**CSS 宽与 TS 常量之间没有交叉判据**

我最初以为"只改 CSS 会被判 C 档、跳过探针"，**核对后这是错的** ——
`gate.py` 的 **C 档本来就跑 `ui_probe` 三档**（`:126-128`，C = tsc + eslint + 探针 + doc_check）。
真正的缺口更窄、也更危险：

| | 值 | 谁在守它 |
|---|---|---|
| CSS 胶囊宽 | `status-island.css:162` `width: 200px` | 探针 `ui_probe.py:3950` —— 但它比的是**字面量 `[200, 40]`** |
| TS 折叠尺寸 | `widgetWindow.ts:102` `WIDGET_COLLAPSED.w` | `widgetWindow.test.ts` —— 但它比的是**自己那个常量** |
| Rust 建窗宽 | `lib.rs:785` `const W` | **无人守**（探针拿不到真窗口） |

⇒ **三个源、三套判据，互不交叉。** 具体后果：若把 CSS 改成 280 **并把探针字面量也改成 280**，
但**漏改 `WIDGET_COLLAPSED.w`** ⇒ `widgetCollapseGeom` 仍返回 `{w:200}`（`:235`）
⇒ 收起时把窗口 resize 成 200 宽，而 CSS 画的是 280 ⇒ **胶囊被窗口裁掉 80px**。
**这个错误在 vitest 里绿（它测的是自洽的常量）、在探针里也绿（字面量已改）** ⇒ 只有真机能看见。

**本方案的对策**（写进 D1-a）：探针断言**不再比字面量，改比"CSS 量出来的宽 == TS 常量"** ——
但这要求探针能读到 TS 常量，而它在浏览器里。
**务实做法**：D1-a 把三处一起改，并在 `ui_probe.py:3950` 的注释里记下
"这个字面量必须与 `WIDGET_COLLAPSED.w` 同值"，**再加一条真机验收项**（§1.3 那批）。

> 另一处**文档漂移**（同样仅记录）：`gate.py:36` 的表写「B = `frontend/src/**`（除 `styles/`·`dev/`）」，
> 而代码 `B_PREFIXES` **含 `frontend/src/dev/`**（`:79`）⇒ 改 `probe.ts` 实际会抬到 B 档。
> 哪个对不影响本方案（抬档更安全），但**文档与代码不一致**这件事本身值得记。
