# 03 · 展示标签、独轮车与行为画像

## 0. 本文管什么

这一层全部是**描述与展示**，不改变三轴、强度或类型：

- 10 条人可读标签（谁常来、谁不说话、谁花钱多……）；
- 独轮车三档（不是 / 疑似 / 确定），以及它为什么只看文本多样性；
- 采集时预计算的破坏性行为画像 `stats.bp`；
- 为将来模糊匹配留的 64 位 simhash `msh`。

**硬约束**：标签与独轮车**不进入** `S`、类型或任何排序。计算链路里不存在这一环。
标签的分母还有两种（观测用户 vs 入选池），引用比例时必须写明用的是哪一个。

## 1. 展示标签

### 1.1 总则

- 共 **10 条**，定义在 `tags.RULES`（9 条规则）+ `spam`（独轮车）；
- 只描述「这个人做过什么」的极端单一事实，不描述「有多核心」；
- 分位类阈值（黑听/互动/老头）一律相对**池内分位**，不是绝对金额/次数；
  结构类（舰队 / SC / 全勤 / 新人）按等级或场次。这样同一个标签在不同主播之间仍可比；
- 一个用户可同时命中多条（除舰长/提督/总督由 `guard_top` 天然互斥）；
- 顺序固定：先规则顺序，最后追加「独轮车」。

### 1.2 10 条标签的判据

| 标签 | 判据 | 代码常量 |
|---|---|---|
| 舰长 | `guard_top == "舰长"`（不含提督/总督） | — |
| 提督 | `guard_top == "提督"` | — |
| 总督 | `guard_top == "总督"` | — |
| 黑听民 | 出席 ≥10 场，且**场均弹幕**在本池最低 5% | `MIN_SESSIONS_FOR_TAGS=10`、`P05=0.05` |
| 互动民 | 场均弹幕进本池前 1%（且 p99 > 0） | `P99=0.99` |
| 老头 | 累计付费进本池前 1%（且 p99 > 0） | `P99=0.99` |
| sc民 | 在 ≥10 个**不同场次**打过 SC | `SC_SESSIONS=10` |
| 全勤 | `att_n >= 窗口场次数`（注意是 ≥ 不是 ==） | — |
| 新人 | 首次出现落在窗口**最后 25%** | `NEWCOMER_FIRST_POS=0.75` |
| 独轮车 | 被独轮车判定为 **confirmed**（`win.spam` 非空） | 见 §2 |

「场均弹幕」= `m / max(1, att_n)`（`tags._pm`），分母是**出席场次**，不是窗口 N。

**分位实现**：`_q(xs, p) = xs[min(len-1, int(len(xs) * p))]`（升序、不插值）。
这是「第 ⌊n·p⌋ 个」而不是统计软件默认的线性插值分位；池子很小时边界会跳动，
引用「前 1%」时要意识到它可能只是头部几个人。

### 1.3 两种分母（最容易混的地方）

| 出口 | 分母 | 代码 |
|---|---|---|
| `GET /fan/{v}/tags` 的 `prevalence` | **本窗口观测到的全部用户** | `tags.prevalence(tag_all(...))` |
| `GET /fan/{v}/ranked` 的 `tag_prev` | **入选池** | `routers/fan.py::_compute` |
| 标签规则里的「本池前 1% / 最低 5%」 | **入选池** | `tags.tag_context(win, table)` |

同一标签在两个出口会得到不同比例（池内占比通常高得多），接口响应里两个分母都给了。
**不要拿 `/tags` 的比例去解释名单里的构成。**

### 1.4 当前快照（2026-10-27，明前奶绿）

窗口 72 场（请求 75）、观测用户 193,217、池 5,305：

| 标签 | 池内人数 | 池内占比 | 全体观测占比 |
|---|---|---|---|
| 舰长 | 783 | 14.76% | 0.529% |
| 提督 | 33 | 0.62% | 0.018% |
| 总督 | 1 | 0.02% | 0.001% |
| 黑听民 | 266 | 5.01% | 9.293% |
| 互动民 | 54 | 1.02% | 0.035% |
| 老头 | 54 | 1.02% | 0.030% |
| sc民 | 124 | 2.34% | 0.064% |

**读法**：「舰长」在池内占 14.76%、在全体观测里只占 0.53% —— 不是标签变了，
是分母从「所有看过的人」换成了「按核心度选出的 5,305 人」。这正是 §1.3 要防的混读。

### 1.5 旧 13 条已退役（2026-10-24）

旧标签（新面孔 / 几乎不言 / 纯黑听 / 常驻 / 话痨 / 大额打米 / SC 常客 / 满勤 / 千元户 /
大额 SC / 提督+ / 每场 SC 等）有三个问题：

1. 无标签用户占 53%；

## 2. 独轮车三档

### 2.1 为什么单独一个模块

聚合阶段（`collector.aggregate`）只负责产出原料：`m`（原始条数）、`uniq`（去重后条数）、
`maxrep`（单条文本最大重复）。**判定放在 `spam.py`**：

1. 判定口径将来一定会改（阈值、是否结合入场模式、是否用文本相似度），改动不该碰采集器；
2. 判定影响指标（互动轴），必须能被**单独审计** —— 报告里要说清用的是哪一版。

版本号 `SPAM_ALGO_VERSION = 4`。改判定逻辑必须 +1，并在报告里写明版本。

### 2.2 核心判据：他会不会说别的

**重复率 = `1 − uniq/m`**；**不同文本率 = `uniq/m`**。判据是「不同文本率低」，
不是「某一条重复了很多次」—— 后者会把口头禅型话痨误判。

真实样本（2026-10-21 人工审原文后定线）：

| 用户 | 消息 | 不同文本率 | 内容 | 是否独轮车 |
|---|---|---|---|---|
| `178727502` | 2,008 | **1.7%** | `火队加油` 刷 1,871 次 | 是 |
| `29951465` | 1,783 | **6.1%** | 只有 24 种文本 | 是 |
| `494629966` | 3,533 | **9.1%** | `🍆奶绿🥖` 刷 2,987 次 | 是 |
| `403044621` | 1,049 | **15.5%** | `啥意思` 刷 388 次 | 是 |
| `1049834725` | 5,702 | 40.6% | `好好好` 刷 1,557 次，但也在正常聊天 | 不是 |
| `8159881` | 7,371 | 28.7% | `prpr` 刷 793 次 | 不是 |
| `431410658` | 69,614 | **78.2%** | 说 3,961 次「哈哈哈」，5 万余条互不相同 | 不是 |

边界很清晰：真独轮车 1.7%–15.5%，口头禅型话痨 28.7%–78.2%。
所以判据必须是「**他会不会说别的**」。

两条被否掉的规则（都试过、都撤回）：

- **次数阈值**（单条 ≥50 次、跨 ≥1 小时）：绝对次数不区分「重复」与「高频」，
  6.9 万条里说 3,961 次「哈哈哈」一样满足；
- **单场低多样性**（某场 ≤20%）：有人某一小时刷几句口号、平时正常说话，全场多样性 59.7%，
  按单场判会误伤。

### 2.3 v1：整体重复率（仍作为原料判据）

`spam.is_spam(uniq, maxrep, m)`：

| 条件 | 结果 |
|---|---|
| `m < 200` | `None`（**未知 ≠ 清白**） |
| `1 − uniq/m ≥ 0.80` | `True` |
| `maxrep/m ≥ 0.30` | `True` |
| 其余 | `False` |

注意是**或**关系（2026-10-21 修正）：整体重复率高，**或者**单条文本反复刷，都算。
`spam_score` 取两者较大值，只用于诊断。

### 2.4 v2：逐场序列 + 场次证据

`spam2.Trace.feed` 把每场的 `mt`/`mh` 喂进来，累计：

- `messages` / `uniq` / `maxrep`；
- `low_variety_sessions`：该场 ≥200 条且 `uniq/len(mt) ≤ 0.20`；
- `cross_sessions`：同一条文本在 ≥3 条的场次里出现过的场次数；
- `variety = uniq/messages`。

`verdict` **复用 `is_spam` 的同一判据**（整体重复率 ≥80% 或 maxrep 占比 ≥30%），
返回 `(True, "low_variety")` / `(False, "ok")` / `(None, "unknown")`。
它比 v1 多的不是阈值，而是**逐场证据**，供报告解释「是在哪几场刷」。

### 2.5 v3：跨场持续性

只看窗口累计 `uniq/m` 会把「场景行为」误判成人格。实例（2026-10-25）：

> 用户 `483347460` 在明前奶绿窗口共 538 条、整体不同文本率 13.9%，被判独轮车；
> 拆开看是**一场歌回的 404 条打 call（0%）**把整体拉低，其余 23 场几乎正常
> （71.8% / 100% / 66.7%）。打 call 是场景行为，不是刷屏人格。

规则（`is_spam_across_sessions`）：单场 ≥20 条才算证据；单场不同文本率 ≤20% 记为低多样性；
**低多样性场 ≥2 场且占证据场 ≥50%** 才算独轮车。当前 loader 不再直接调用这个函数，
它的思想已并入 v4 的 `share` 条件。

### 2.6 v4：三档（现行）

`spam.level_for(m, uniq, sessions, speaking_sessions)`：

先算：`variety = uniq/m`；`evidence` = 单场 ≥20 条的那些场；
`low` = 单场 `uniq/m ≤ 0.20` 的场；`share = len(low)/len(evidence)`。

| 档 | 条件 |
|---|---|
| `none` | `m < 200`，或下面两档都不满足 |
| `confirmed` | `variety ≤ 0.20` **且** `speaking_sessions ≥ 5` **且** `len(low) ≥ 2` **且** `share ≥ 0.60` |
| `suspected` | `variety ≤ 0.25`，**或**（`share ≥ 0.50` 且有低多样性场） |

- **场次不足 5 的，无论多像，最多判疑似**（2026-10-25 用户定）；「连续两场高强度刷屏」是确定档的
  最低场次证据；
- 确定档比疑似档更严：整体 ≤20%、低多样性占比 ≥60%；
- 疑似档整体放宽到 ≤25%。

**loader 的并集逻辑**（`loader.load_window` 末尾）：

1. 有文本指纹且 `m ≥ 20`：跑 `level_for`，非 none 写 `spam_levels`；confirmed 写 `spam[uid]="repeat"`；
2. 有逐场序列的：跑 v2 `verdict`；为真时要求至少 2 场证据且 `msg_sess ≥ 5` 才升 confirmed，
   否则 suspected；confirmed 时 `spam[uid]` 记为 `"low_variety"`；
3. `spam` 只放**确定**档（标签「独轮车」据此判定）；`spam_levels` 放三档全量（详情页展示）。

接口 `ranked` 同时返回 `spam`（规则名或 `None`）与 `spam_level`（默认 `"none"`）。
不要用 `spam` 为空推断「清白」—— 可能只是样本不足（`m < 200`）。

### 2.7 影响量级（2026-10-19 快照）

- 命中率约 **0.15%–0.22%** 的活跃用户；
- 整体指标几乎不动：强度排序 ρ≈1.0、类型分布变化 <0.5%；
- 但**头部名单会被污染** —— 弥月前 100 名里曾有 17 人命中。

所以策略是**只标记、不剔除**：分析层按需过滤，标签只做展示，默认照用。
「剔除」与「降权」是将来接入互动轴时才能决定的事，且必须把剔除人数写进报告。

## 3. 破坏性行为画像 `stats.bp`

### 3.1 是什么

采集时在 `aggregate` 之后扫一遍记录，预计算「跟着别人发」的画像（2026-10-27，`BP_VERSION=1`）：

```jsonc
"bp": {
  "version": 1, "window_ms": 5000,
  "copy_msgs": 2, "copy_ratio": 0.667, "users": 2,
  "top": [{ "uid": "...", "copied": 1, "msgs": 2, "ratio": 0.5,
            "targets": 1, "lag_med": 1500, "interval_cv": 0.0 }]
}
```

| 字段 | 含义 |
|---|---|
| `version` | 判定版本；判据一变就 +1，旧 stats 可据此判断是否过期 |
| `window_ms` | 复制判定的时间窗（**5,000 ms**） |
| `copy_msgs` / `copy_ratio` | 被判为「跟着别人发」的条数 / 占全部有效弹幕的比例 |
| `users` | 受影响用户数 |
| `top` | 按 `copied` 降序的前 20 名 |
| `top[].uid` / `copied` / `msgs` / `ratio` | 用户、复制条数、总条数、复制占比 |
| `top[].targets` | 复制了多少个**不同**的人 |
| `top[].lag_med` | 源消息 → 复制消息的延迟中位数（毫秒）；脚本通常很稳定 |
| `top[].interval_cv` | 该用户发车间隔的变异系数（越小越「规律」） |

### 3.2 判据与限制

- 只做**精确复制**：同一归一化文本哈希在 ±5 秒内被**另一个 uid** 也发过，
  当前这条就算「跟着发」；
- 按 `(type=0, uid, 时间戳, 归一化文本)` 事件流扫；每条最多记一次（先看前邻、再看后邻）；
- `interval_cv`：该用户消息时间戳的正间隔，`std/mean`；少于 3 个时间戳记 0；
- 体积约 **2–5 KB/场**；**当前不参与三轴、类型或标签**，只供展示与后续审计；
- 局限：只认完全相等（空白压平后）；加 emoji / 改写 / 插入字符的变体判不出来 ——
  那是 `msh` 的活（§4）；交替改写、低频复制也可能逃逸。

## 4. `msh`：为模糊匹配留的 simhash

`mh` 只能判「完全相等」；「自动融入」这类脚本常做变体（加 emoji、空格、改写），
`mh` 判不出来。因此每条弹幕额外存一个 **64 位 simhash** `msh`，与 `mt`/`mh` 一一对齐：

- 字符 **3-gram**（长度 <3 时用整串）；用 `zlib.crc32` 两个种子拼成 64 位（C 实现、跨进程稳定）；
- 对每个 3-gram 做**加权位投票**：该位为 1 加 1、为 0 减 1，最后取正号；
- 空文本返回 0（与 `mh` 对齐，真实值不可能为 0）；
- 每条 8 字节，压缩后代价约 **+10%**；
- **汉明距离**近似文本相似度，将来可在 `msh` 上做模糊查重（当前**没有调用方**）。

因此采集侧同时保留三套东西：`mh`（精确去重/回放裁剪）、`msh`（未来模糊匹配）、
`m`/`uniq`/`maxrep`（判定原料）。删除 `mh` 只省压缩后约 10%，却会永久失去「事后重算」
能力，所以不能删。

## 5. 维护规则

| 改动 | 必须做 |
|---|---|
| 改独轮车阈值/规则 | `SPAM_ALGO_VERSION += 1`；更新本节与测试；报告写明版本 |
| 改 `bp` 判据 | `BP_VERSION += 1`；旧 stats 里的 `bp` 标过期 |
| 改标签集合/阈值 | 同步 `tags.py`、`routers/fan.py` 的说明、本节；旧口径数字不得混引 |
| 想让标签参与排序 | **不要**。这等于用「花得多/说得少」给人排名，与模型的中立性约束冲突 |
