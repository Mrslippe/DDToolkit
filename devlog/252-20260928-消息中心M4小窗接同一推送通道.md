# 252-20260928-消息中心 M4：小窗接同一推送通道

M4 的目标一句话：**小窗不再依赖主窗口**。改前它的条目**全部**来自 `TopBar` 的
`widget:notices` 广播（R38 批 5b 的设计：主窗口轮询、小窗纯显示）⇒ **主窗口一关，小窗永远是空的**。

## 一、改了什么

| | 改前 | 改后 |
|---|---|---|
| 小窗的条目 | 只吃 `widget:notices`（主窗口广播） | **两路**：自己订阅 `GET /messages/stream` 算推送类 + 保留广播（轮询类） |
| 推送类通知（开播 / 任务受理 / 操作完成） | 靠主窗口转达 | **小窗自己算**（`utils/noticeStream.ts`） |
| `widget:action`（小窗 → 主窗口的动作） | — | **不变** |

**合并规则**（`mergeWidgetNotices`，纯函数 + 11 条单测）：主窗口的轮询进度一到，自己那份**让位**；
瞬时消息两边都有时用主窗口那份（同一句话不显示两遍）；按 id 去重（开播告警两边同 id）。
⇒ **主窗口开着时两边看到的完全一样**，不开时小窗仍能收到推送类 —— 这是"并存"的全部内容。

⚠️ **`widget:notices` 本轮不删**：轮询类的事实（登录失效 / 风控冷却 / 完成报告 / 抓取进度 i/N）
还住在 `TopBar` 的轮询里。方案 §3 的原话就是"**先并存、后退役**"，退役点落在 **M5**
（后端接管汇总）。把没搬家的那半边删掉 = 小窗少显示四类通知，那是**功能倒退**。

## 二、两个真问题（都是被这条判据逼出来的）

### ① 拆入口漏东西的**第五次**：小窗在开发态每个请求都 401

`main.tsx` 在非 Tauri 环境里按 `DEV_API_TOKEN` 决定"开闸"还是"清空 token"
（2026-09-25 踩过一次，注释写得很清楚）；而独立入口 `widgetMain.tsx` 原来**无条件**
`markNoTokenRequired()` —— 那个函数会把 `apiToken` 清成**空串**。
于是小窗自己起流时：`backend.log` 里刷满
`拒绝未授权请求：GET /messages/stream（missing）`，而页面表现只是"连不上 / 偏好没读回来"，
**一个错都不报**。修法：抽 `openApiGate()`，口径与 `main.tsx` 逐字一致。

> `DEV-LOOP` §6.1 那条"拆前端入口 / 抽共用样式时的坑"此前已记四次（Tailwind preflight ·
> `layout.css` 的 `.os-*` · `main.tsx` 的 `setApiBase` · `main.tsx` 的探针挂载），这是第五次。
> **新入口必须自己走一遍启动副作用的清单**，且"走一遍"要**有判据**：
> 这次是 `ui_probe --status-widget` 的推送段把它钉住的。

### ② 探针的"自己/别人"写死了宿主

`probeMessages()` 里那两条 originator 判据硬编码 `originator: 'main'`（自己）与 `'widget'`（别人）
—— 那等于假设"跑探针的页面就是主窗口"。小窗那一轮语义正好反过来 ⇒ 两条判据**同时**红
（自己点的弹了、别人点的不弹），看着像实现坏了。改成按 `myHost()` 推导
（`me` / `other`）—— 判据跟着语义走，而不是跟着某一扇窗走。

## 三、虚拟时间下的等待：等**网络**不能用 `sleep`

小窗入口的**第一件事**就是起流，而主窗口那边流早连上了（它前面跑过十几秒真实 I/O）。
`probeMessages` 原来等 `state === 'open'` 用"8000ms"，但虚拟时间下 `sleep(100)` 几乎立即返回
—— **8000ms 不是 8 秒真实时间** ⇒ 小窗永远判在 `connecting`。
修法：等待循环里每轮补一发**本地请求**（`/healthz`），用真实 I/O 换真实时间。
（`DEV-LOOP` §6.16 记的是"别用等待去等 rAF 产物"；这条是它在**网络**上的同族。）

## 四、判据与反向验证

| 层 | 判据 |
|---|---|
| 纯逻辑 | `utils/noticeStream.test.ts` 11 条：合并三条规则（进度让位 / 消息让位 / 同 id 去重）· TTL **从到达时刻**起算（不是渲染时刻 —— 否则条目永不过期）· `PILL_MS`/`PUSHED_PROGRESS_MS` **只有一处定义**（结构扫描 TopBar） |
| 端到端 | `ui_probe --status-widget` 新增第三段：`widget.html?probe=messages` —— **整页只有小窗**（没有主窗口、没有广播），把 `_assert_messages` 跑一遍（`host="widget"` ⇒ 账号快照/帖子/V 本体那三条**打印跳过理由**，它们要求页面上有消费者） |
| 实跑结果 | `state='open'` · 总线 `0 → 1` · 发布 `200` · 抵达 ✓ · 岛上已显示 ✓ |

**反向验证 3/3 全红**：① 去掉 `startMessageBus()`（小窗不起流）；② 把闸门改回无条件
`markNoTokenRequired()`（token 被抹）；③ 小窗不用自己那路（只画广播）。

## 五、真机待确认（只有你能做）
