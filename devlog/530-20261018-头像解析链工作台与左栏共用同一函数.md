# 530-20261018-头像解析链：工作台与左栏共用同一个函数

用户问："头像在第一次添加的时候难道没有落库吗？我记得头像保存逻辑里是要把历史头像全部固定的"
**记忆是对的，是我判断错了。**
## 一、头像落库是完整的（dev 库实测）
| 层 | dev 库里的值 |
|---|---|
| `accounts` | `avatar_url = i0.hdslb.com/bfs/face/d3eac4f9…`<br>`avatar_path = static/assets/avatar/bilibili_2132180406_8c43aa3c.jpg` |
| `vtuber_avatar_history`（账本） | **1 行**，带 `first_seen_at` / `last_seen_at` |
| `local_assets` | 44 行里有 **1 条 `kind='avatar'`**，`key` = 去掉签名参数的 URL |
写账本的是 `scheduler.py:871` 的 `record_avatar_version(...)` —— "历史头像全部固定"**在正常工作**。

## 二、`vtubers.avatar` 本来就该是空的
它是**用户覆盖字段** —— 只有"在档案设置里点选某个账号的头像"才写。
`current_avatar_url()` 的口径：`vtubers.avatar` → B 站账号 `avatar_url` → 首个账号 `avatar_url`。

## 三、根因：档案卡少传了 `accounts`

左栏调 `resolveAvatarSources(vtuber, vtuber.accounts)`（①覆盖 → ②账号本地缓存 → ④⑤账号 URL）；
档案卡只读了 `src={v.avatar}` —— **只命中第 ① 级**。而 `local_avatar_map()` 以
`vtubers.avatar` 非空为前提（`if not wanted: return {}`），所以 dev 里 `avatar_local` 也是 null。
⇒ 同一份数据，**左栏有头像、工作台只有首字兜底**。

> `avatarSource.ts` 注释原文："这类'两处各写一遍、慢慢漂开'的错不会报错，
> 只会让人以为'设置没生效'。" —— 这次照着重犯了一遍。

## 四、修法（方案 A）

不造第二个派生字段（那等于第二份"该显示哪张脸"的口径），让前端**字面上调同一个函数**：
后端 `/fan/{v}/profile` 增加 `accounts`；档案卡改 `resolveAvatarSources(v, data.accounts)`。
dev 库验证：端点返回 `accounts[0] = bilibili/2132180406`（`avatar_url` + `avatar_path` 都在），第 ②④ 级命中。

## 五、上一轮的错误已回滚

曾把 release 的 `vtubers.avatar` 拷进 dev 想"补头像" —— 那会把**账号头像变成用户覆盖**，
档案设置里会显示成"自定义头像"。已还原成 `NULL`（备份 `vtuber.db.bak-20261018` 仍在）。
