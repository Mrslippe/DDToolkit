# 153-20260919-R39-B设置关于页排版重排

> 用户 2026-09-19 四条前端改动里的第 ② 条：
> 「这是设置界面的关于分项，整理一下这个子页面中的各小项，现在**按钮、信息、小字样有点混在一起**了，
> 重新排版让它们更整齐」。拍板：**按提案完整重排**（不是只归位按钮）。

---

## 一、问题（从代码里逐条核出来的）

| # | 现象 | 根因 |
|---|---|---|
| 1 | 「版本」出现**两次** | 运行信息里一行 + 「应用更新」小节又写「当前版本 1.0.2」 |
| 2 | 按钮夹在信息里 | 「删除旧目录」原来是一个**塞在注释小字里的 `FloatPill`** |
| 3 | 小字夹在数字与按钮之间 | 「另有手工备份…」排在存储数字与动作行**中间** |
| 4 | 数值列不对齐 | 「（上限 300 MB）」直接跟在数字后面 ⇒ 三行数字右缘参差 |
| 5 | 合计与磁盘剩余混在占用里 | 一个是"占了多少"、一个是"还剩多少"，却在同一个 dl 里当第四、五项 |
| 6 | 只读项没有小节头 | `<ul class="aps-readonly-list">` 裸挂在最后，看着像"关于页没结束又来了几行" |

## 二、改法：四段同构

每段都是 **小节标题 → 信息/数字 → 动作行 → 注释小字**：

```
运行信息            ← 新增小节头（原来裸着一个 dl）
  版本 / 数据目录 / 数据库 / 后端端口 / 迁移版本 / 日志 / 进程
存储占用
  数据库 / 图片缓存（上限自成右列）/ 日志
  ────────────────  ← 通栏发丝线（.aps-info--sep）
  合计（加粗）/ 磁盘剩余
  [清理图片缓存] [整理数据库] [迁移到其他盘…] [删除旧目录]   ← 动作统一收在这一行、右对齐
  注：另有手工备份… / 注：数据目录来源… / 注：旧目录仍保留…
应用更新
  状态句（不再重复版本号）
  [检查更新] [打开发布页]
这些项不开放修改    ← 新增小节头
  · 只读项逐条（标签 + 为什么 + 键名）
```

**数值列的两端对齐**（`.aps-info--nums dd` 用 `display:flex; justify-content:space-between`）：
数值都在同一 x 起排、自然成列；「上限 300 MB」「空间偏紧」这类后缀贴右缘自成第二列。
比"整列右对齐"更整齐 —— 单位长度不一（MB/GB）时右对齐反而参差。

## 三、护栏（全部可量，先红后绿）

这一批是**纯排版** —— 正是"看着乱、但很难举证"的那类，所以每条都变成数字：

| 判据 | 为什么这么写 |
|---|---|
| 版本号在关于页**只出现 1 次** | 用 `/\b\d+\.\d+\.\d+\b/` 数"版本形状"的数，**不依赖任何属性** ⇒ 实现还没加钩子时判据也有牙（量到 2 就是重复） |
| 信息行/注释里**不许有按钮** | `dlg.querySelectorAll('.aps-info button, .aps-note button').length === 0` |
| 小节标题 ≥ 3 | 运行信息 / 存储占用 / 应用更新（实际 4 个） |
| 存储小节子元素顺序 = `[head, info, info, actions]` 开头 | 标题 → 占用数字 → 分隔后的合计/余量 → 动作行 |
| 注释小字**不排在动作行之前** | 判**顺序关系**而不是"最后一项必须是 note" —— 有没有注释取决于数据（手工备份/便携版），断言"最后一项"会随数据漂 |
| 数值列 `display:flex` + `space-between` + `tabular-nums` | 两端对齐与等宽数字 |
| 「合计」前有分隔线（`border-top > 0`） | `.aps-info--sep` |

**反向验证：7 条红 → 0**（版本 2 次 / 只有 2 个小节头 / 存储顺序 / 小字位置 / 数值列 / 等宽数字 / 无分隔线）。
