# 243-20260927-消息中心 M1：开播边沿的出口 + "读到流"的见证

M1（方案 `docs/design/notices/message-hub-execution.md` §M1）。**不是新造检测，是给它一个出口**：
T0 早就分出了开播方向（`edge` / `started`），但唯一消费者是 `note_dynamics_activity()`
（把动态流恢复满速）⇒ 用户什么都看不到。

## 一、后端：开播边沿 → 一条 `domain.live.edge`

`scheduler.py` 的 T0 循环里，`db.commit()` **之后**多一次
`message_hub.HUB.publish("domain.live.edge", {...})`。payload 用 **snake_case**
（= API/表字段口径）：`vtuber_id / account_id / platform / platform_uid / name / live_title / live_url`。

⚠️ **顺序是这一批唯一的硬约束**（方案 §2.2）：消息发出去收不回，而事务可能回滚 ——
放在 commit 之前，订阅者就会收到一条"从未发生过"的开播，而库里 `live_status` 还是 0。
判据 `test_no_message_when_the_transaction_rolls_back`，反向验证第 1 刀就是把它挪回 commit 前。

判据 6 条（`tests/test_live_edge_notice.py`）：① 0→1 恰好一条 + payload 逐字段；
② 非边沿（连着两轮 1）不再发；③ 1→0 不播成开播；④ 回滚时零消息；⑤
`note_dynamics_activity` 既有行为不变（回归）；⑥ 一轮里两个账号开播 ⇒ 两条（T0 是批量接口）。

## 二、前端：领域事件 → 顶栏 **alert**

`messageBus` 把 `domain.live.edge` 解成结构化 payload（`parseLiveEdge`：**缺字段就什么都不发**，
不发半个对象）→ `ddtoolkit:live-edge` → TopBar 的 `liveEdge` 状态 → `liveNotice()`
（`notificationHub`）：`kind:'alert'`、源「开播」、文案「XXX 开播了」、detail = 场次标题。

⚠️ **alert 必须带 TTL，不能常驻**：alert(4) 优先级高于 progress(3)，常驻就等于
"开播过的那次一直压住任务进度"。取 2 分钟（`LIVE_NOTICE_MS`），有单测钉住
（`sticky` 不许出现 + 到期后 `pickPrimary` 让位给 progress）。
⚠️ **补发的开播边沿不播**：重连不该把"几小时前就开播了"再提示一遍（复用 M0b 的 `replay` 语义）。

## 三、补上方案缺的一环：**"读到流"的见证**（`POST /messages/ack`）

方案的 M0 停止条件是"真机（Tauri **WebView2**）里 `ReadableStream` 读得出流吗"，
**但它没有任何可获得的见证**：M0/M0b 阶段**没有真实发布方**（没人开播就没有消息），
而"连接建起来"不等于"客户端读得到字节"（缓冲区不吐数据时，服务端一切正常、日志干净）。

⇒ 本批补上：前端在**收到第一块字节**时（`eventStream.onFirstChunk`，每条连接一次）发一次
`POST /messages/ack`，后端记一行

```
推送通道：客户端已确认读到流（seq=…，订阅者 1）
```

于是真机验收在日志里**一句话可查**（`%APPDATA%\com.ddtoolkit.app-dev\logs\app.log`），
不必等一次真开播。它同时是 **M5「目睹才报」订阅者注册表的雏形**（那一项需要后端知道"有没有人在看"）。

## 五、探针踩到的坑：**别采样过渡中的文案**

第一版探针断言"顶栏文案变成『XXX 开播了』"—— **红**，而被测行为是对的：
`.si-text` 是**两段式**（淡出旧的 → 换新的），虚拟时间下 CSS 过渡不推进（`DEV-LOOP` §二·五），
采到的永远是**上一相位**（实测读到的是更早那条瞬时消息）。**加长等待救不了**（等待不产生帧）。

⇒ 改成看**面板**（`.si-panel` 的 `.si-item[data-kind="alert"] .si-item-text`）：一次渲染直接列出、
不经过任何动画相位。教训提炼进 `DEV-LOOP.md` §6.19（"判某样东西进没进界面要看结构"）。
**判据换了之后，同一刀变异（TopBar 不把告警放进列表）才咬得住** —— 反向验证第 10 刀。
