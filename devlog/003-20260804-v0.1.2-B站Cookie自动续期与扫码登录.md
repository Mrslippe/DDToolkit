# 003-20260804-v0.1.2-B站Cookie自动续期与扫码登录.md

## 概述

实现 B站 Cookie 三阶段自动维护机制：**心跳保活 → refresh_token 续期 → 二维码扫码兜底**，彻底告别手动更新 `.env`。

## 架构

```
Auth 维护循环 (每 30 分钟)
    │
    ├─ 阶段 1: check_session()
    │   调 /x/web-interface/nav → isLogin == true → 跳过续期
    │   └─ 顺便更新 refresh_token（调用 /cookie/info）
    │
    ├─ 阶段 2: try_refresh()
    │   Session 过期 → 拿 refresh_token 换新 SESSDATA
    │   └─ 调 POST /x/passport-login/web/cookie/refresh
    │
    └─ 阶段 3: qr_login()
        refresh_token 也失效 → 终端展示二维码
        └─ 用户扫码 → 提取 Cookie + refresh_token → 写入 .env
```

## 新增文件

### [app/services/auth.py](app/services/auth.py)

`BilibiliAuth` 单例，负责全部认证逻辑：

| 方法 | 作用 |
|------|------|
| `build_headers()` | 每次动态构建请求头（Cookie 永远是最新值） |
| `check_session()` | 调 nav 接口验证登录态有效性 |
| `try_refresh()` | 用 refresh_token 换取新 SESSDATA/bili_jct |
| `qr_login()` | 终端二维码 + 轮询 + 提取 Cookie |
| `run_maintenance()` | 后台异步循环，每 30 分钟执行一次 |
| `_save_to_env()` | 将当前 Cookie 持久化写入 `.env` |

Cookie 更新后自动写回 `.env`，下次重启无需重新登录。

### 二维码展示

- 使用 `qrcode` 库在终端打印 ASCII 二维码
- 同时打印原始链接（二维码渲染异常时手动打开）
- 轮询超时 3 分钟，支持过期检测

## 工作流程

### 正常情况（Session 有效）

```
启动 → load_dotenv(.env) → check_session() ✓
  → 每 30 分钟: check_session() ✓
  → 同时更新已存储的 refresh_token
```
- `/x/web-interface/nav` 每 30 分钟被调一次 → Session 维持活跃

### Session 过期但 refresh_token 有效

```
check_session() ✗ → try_refresh()
  → POST cookie/refresh → Set-Cookie 返回新 SESSDATA
  → 自动写入 .env → 下次 nav 验证通过
```

### 全部失效（冷启动 / 过期太久）

```
check_session() ✗ → try_refresh() ✗ → qr_login()
  → 终端打印二维码 → 用户扫码确认
  → 提取 SESSDATA / bili_jct / DedeUserID / refresh_token
  → 写入 .env → 回到正常循环
```
