# 696-20261027-CI 第四处：`check_date_range.mjs` 在 Node ESM 下解析失败

## 现象

前端 job 里 tsc / eslint / vitest 全过（135 个测试文件、1584 条），
但最后一步 `node scripts/check_date_range.mjs` 报：

```
ERR_MODULE_NOT_FOUND: Cannot find module '.../src/utils/cndate'
imported from '.../src/utils/dateRange.ts'
```

## 原因

`dateRange.ts` 里写的是 `from './cndate'` —— **省略扩展名**。
Vite/tsc 能补全，但**Node 的 ESM 解析不做补全**；这个脚本又靠 Node 的类型擦除直接 import `.ts`，
于是链条断在这里。

## 修法

`dateRange.ts` 的导入改成 `'./cndate.ts'`（tsconfig 已开 `allowImportingTsExtensions: true`，
Vite 与 tsc 都接受这种写法），并在注释里写明**为什么必须带后缀**。

验证：`node scripts/check_date_range.mjs` → 全部通过；`tsc --noEmit` 干净；`src/utils` 下 724 条测试全过。

## 教训

**"本地能跑"的脚本若依赖 Node 直接 import TS，任何省略扩展名的相对导入都会在 CI 炸**。
凡是给 Node 直接消费的 `.ts`，相对导入一律带 `.ts` 后缀。
