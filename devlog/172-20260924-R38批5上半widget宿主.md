## 一、改前必查：§8 的"宿主无关"其实早就满足

§8 说「状态机与动画都不得依赖顶栏……面板锚定一律相对胶囊自身」。查下来
**`place()` 读的一直是 `anchorRef` 自己的 rect** —— 面板锚定本来就是相对胶囊自身的。
所以换宿主**只是换一层材质与尺寸**，不是重构。§8 里那个 `useStatusIsland()` 抽取
**没做**：它只有在真的有第二个消费者时才有价值，现在抽是过早抽象。

## 二、交付

`<StatusIsland density="bar" | "widget">` + `data-density` 属性（**用属性选择器而不是加类**，
状态与样式不容易漂）。

| | `bar` | `widget` |
|---|---|---|
| 定位 | `absolute` + `translateX(-50%)` 居中 | **`relative`**（它自己就是窗口）|
| 折叠 | 高 25 / 内容自适应 | **200 × 40** |
| 面板宽 | 340 | **280** |
| 底 | 透明 → `.on` 变粉 | **`rgba(18,18,22,.72)` + `blur(20px) saturate(1.4)`** + 1px 高光内边 |
| 事件态 | 整块变粉 | 深底**不变** + 一圈粉环 |

## 三、两条实测教训

**① 深底的不透明度是算出来的，不是调出来的。**
桌面控件要浮在**任意壁纸**上，而 `backdrop-filter` 后面的东西**不可知** ⇒ 只能按 α 复算
**最亮（纯白）与最暗（纯黑）**两个极端壁纸的有效底色。α = 0.72 时白字实测
**7.51:1** 与 **19.41:1** —— 两端都过；中间壁纸必然落在区间内（**混色是线性的**）。
**改这个值要重算。**

**② ⚠️ 量面板宽要用布局宽，不是 rect。**
首次实现量到 **276**（期望 280）—— 原因是面板入场动画的 `scale(.985)` 在**虚拟时间下被冻在
起始帧**（`DEV-LOOP.md` 记过这条），rect 量到的是 280 × 0.985 ≈ 275.8。
改用 `getComputedStyle().width` 立刻对。**这是同一个坑第三次绊人**（前两次是 R37-P4c 的
`settleTransforms` 与 `--motion-cards` 的 identity 矩阵）。

## 四、判据：`ui_probe --status-widget`

新增 flag + dev-only 的 `?density=widget` 开关 —— widget 宿主本来只该出现在独立小窗里，
但探针要能在**同一个页面**上量它，否则"不透明度够不够"只能靠肉眼估。

断言：density / 折叠尺寸 `[200,40]` / 面板宽 280 / `backdrop-filter` 含 `blur(20px) saturate(1.4)` /
`box-shadow` 含 `inset` / **不是 `absolute`** / **两极端壁纸对比度 ≥ 4.5:1**（脚本侧按 α 复算）。

**反向验证过**（α 调到 0.3 + 去掉尺寸与模糊 ⇒ 四条同时报）：

```
- 折叠尺寸是 [326, 40]，应为 [200, 40]（§7）
- backdrop-filter 是 'none'，应含 blur(20px) 与 saturate(1.4)（§7）
- box-shadow 里没有 inset —— §7 要求 1px 高光内边
- 最差壁纸下文字对比度只有 1.98:1 （底色 α=0.3）—— 亮/暗壁纸都 ≥ 4.5:1
```

对比度那条**正确取了最差的一端**：白壁纸 1.98:1（红）、黑壁纸 20.32:1（绿）✓

## 五、⚠️ 一次"假回归"，值得记

我先跑默认三档（后台），同时跑了 `--status-island` —— 默认三档报了 **10 处不变量破坏**
（`缺少量测段 list-video` / `数据视图里没有牌堆` / `档案视图里没有卡片画布`），
看起来像大回归。**单独重跑全过。**

真因：`--status-island` 那次直接崩在 `shutil.copy2` 上 ——
`OSError: [WinError 1224] 请求的操作无法在使用用户映射区域打开的文件上执行`。
**两个 `ui_probe` 不能并发**（共享工作库副本 + 各自起后端/Vite）。
并发污染会伪装成回归 —— 见到大面积失败先确认是不是只有一个探针在跑。

## 七、批 5 下半（5b）为什么停在这里

§7 的窗口那一格只写了「无边框 + 置顶 + 可拖动 + 位置持久化（`utils/shellState` 同款做法）」，
**没写"怎么开"**：是设置里一个开关？托盘菜单？还是常驻？以及**它和顶栏胶囊是并存还是互斥**。

这些是**产品决策**，不是实现细节 —— 规格没给，不该我替用户定。所以 5a 落地、5b 挂起待拍板。

**技术侧已核实的可行性**（供拍板参考）：`tauri.conf.json` 目前只有 `main` 一个窗口
（`decorations: false` + `transparent: true` + `visible: false`，已有 `rebuild_main_window`）；
`utils/shellState` 是 localStorage + sanitize + TTL 的那套做法，位置持久化可以照搬。
