# 133-20260916-R31切换手感：退场只播一次 + EXIT_MS 150

> 接 devlog/132（用户报"不同视图之间、或不同 V 之间快速切换会有比较明显的卡顿，这是正常的吗"，
> 先量后定）。量出来的结论是：**"卡"不是渲染慢** —— 时间几乎全在 `EXIT_MS=200` 的**刻意退场**上
> （挂载 ~10ms、长任务 0 条），而**连点 270ms ≈ 60ms 间隔 + 210ms**，
> 说明第二次点击**又等了一整轮退场**。
> 于是给了三个选项与代价（A 缩短 EXIT_MS / B 连点跳过退场 / C 交叉淡化），
> 用户选 **"B + 轻微 A"**：连点直接落地 + 退场时长 200ms → 150ms。

## 一、护栏先行（两条，其中一条当场抓到了我自己的 bug）

| 护栏 | 位置 | 钉住什么 |
|---|---|---|
| 纯函数单测 **11 条** | `frontend/src/utils/sceneStep.ts` + `.test.ts` | 场景机的"下一步动作"穷举：idle / 退场 / 等预取 / **连点直接提交**；外加一条**布局契约**（`.scene-exit` 动画必须**短于** `EXIT_MS` —— 挡"改了常量忘了 CSS"或反之） |
| 探针硬判据 | `probe.ts` 的 `switch-perf` 出 `exitReplayed` + `ui_probe.py --switch-perf` 判失败 | **退场只该播一次**：连点总耗时必须**比单次更快**（`burstMin < singleMedian`），否则第二次点击重播了退场 |

**为什么要抽纯函数**：`hooks/useSceneTransition` 要 React 渲染环境才跑得起来，
而本仓 vitest 跑在 **node 环境**（无 jsdom / 无 testing-library）——
"连点不重播"这条规则必须有单测钉住，所以把**判断**（纯函数，可穷举）与**执行**（setState/定时器）拆开。

**判据的反向验证**（改之前，先让新判据跑在旧代码上）：

```
$ python scripts/ui_probe.py --switch-perf --vtuber 15 --width 1280
  · 视图切换 210ms ×4       · V 切换 225/230/230ms
  · 连点（60ms 间隔）：[270, 270] ms
  - @1280 switch-perf: 连点 270ms ≥ 单次中位 210ms ⇒ 第二次点击重播了退场（应直接提交）
[exit 1]
```

⇒ 判据真的会红，而且红的是**真现象**（270 = 60 + 210）。

## 二、第一版写错了：把"退场态"当成了"连点"（探针 20 秒抓到）

第一版的规则是"`exiting === true` 且来了新目标 ⇒ 立刻提交"。听起来对，实际踩了一个**自递归**：

```
点击 → planStep 决定 exit → setScene(exiting: true)
     → 而 exiting 是 effect 的依赖 ⇒ **effect 自己再跑一遍**
     → 这一遍：目标没变、exiting 却是刚置上的 ⇒ 被判成"连点" ⇒ 当场提交
     → 退场动画一帧都没播
```

实测数字一眼看穿（**同一把尺子**）：

```
  · 视图切换 20/15/15/15ms（中位 15ms）   ← 退场被整个跳过（原来 210ms）
  · 连点 [80, 80] ms                      ← 于是"连点比单次慢"再次判失败
```

**修法**：退场要记住**它是为哪个目标播的**（hook 里 `exitForRef`），
规划器新增入参 `exitingIsForTarget` —— 只有"为**别的**目标播的退场"才算连点可跳；
为自己播的那轮必须**继续等它自己的定时器**（否则定时器被 cleanup 清掉，会**卡在退场态**）。
这条坑与对应测试都写进了 `utils/sceneStep.ts` 的模块说明（"`exitingIsForTarget` 为什么必须单独传"）。

## 三、改动

| 层 | 改动 |
|---|---|
| `utils/sceneStep.ts`（新） | `planSceneStep({accChanged, viewChanged, exiting, exitingIsForTarget, ready, exitMs})` → `idle` / `commit` / `wait-prefetch` / `exit`（顺序即优先级，见模块说明） |
| `hooks/useSceneTransition.ts` | `EXIT_MS` **200 → 150**；effect 改成"规划 + 执行"；新增 `exitForRef`（退场属于谁）；提交/回退时清它 |
| `styles/layout.css` | `.scene-exit` 动画 `0.18s → 0.13s`（**恒比 EXIT_MS 短 20ms**：动画必在类移除前结束，杜绝竞态闪帧） |
| `dev/probe.ts` + `scripts/ui_probe.py` | `switch-perf` 出 `singleMedian`/`burstMin`/`exitReplayed`，连点重播即判失败；help 与注释同步 |

**没有动**的：预取机制（同目标复用 / 不 abort / 失败兜底 / 原子提交）、
详情抽屉与图片查看器各自的 200ms 退场（那是弹窗，不是场景机）。

| 指标 | 改前（devlog/132 基线） | 改后 | 变化 |
|---|---|---|---|
| 视图切换（点击 → 目标可见） | 210ms ×4 | 170/165/165/165ms（中位 **165**） | **−45ms** |
| V 切换（含预取 + 提交） | 225–230ms | 170/165/170ms（中位 **170**） | **−60ms** |
| 连点（60ms 间隔点两次） | 270 · 270ms | **75 · 75ms** | **−195ms** |
| 主线程长任务 | 0 条 | 0 条 | 挂载与渲染依旧不是瓶颈 |

```
$ python scripts/ui_probe.py --switch-perf --vtuber 15 --width 1280
    → 单次中位 165ms，连点最快 75ms：没有明显积压（≈ 单次 + 60ms 间隔）
    → 比单次快 90ms ⇒ 没重播退场（退场只播一次）
  [ok] 切换全部落地                                              [exit 0]
```

⚠️ 口径：这是 **Vite dev + React 开发模式**（StrictMode 双挂载、未压缩）的数字，
打包版会更快；它的价值是**相对信号**（改动前后同一把尺子）与"退场只播一次"这条不变量。

**场景机原护栏 `--scene` 复跑通过**：提交耗时 250 → **200ms**、末态 hero/路由/侧栏一致、
`view-body` 的 class 序列正常、中途失败 **0**。
