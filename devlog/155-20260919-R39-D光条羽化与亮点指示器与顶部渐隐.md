## 一、诊断（为什么"裁切"这件事看着不对）

问题不在裁切本身（任何滚动容器都会裁），而在**这一刀没有视觉解释**：光条是
`linear-gradient(90deg, 透明 → rgba(255,255,255,.68) → 透明)` 的**软光带**，本身是透的 ——
卡片从它下面经过时，眼睛读到的是"卡片坏了"，而不是"卡片钻到工具栏下面去了"。

## 二、三件事

### 1. 顶部渐隐（方案 A）

滚动体**滚下去之后**才挂 `mask-image: linear-gradient(to bottom, transparent 0, #000 28px)` ——
内容接近光条时逐渐淡出，而不是被切一刀；**静止时零干扰**（不滚就没有渐隐，不白白牺牲可读性）。

开关的**单一事实来源**是 `OverlayScroll` 下发的 `data-scrolled`（`scrollTop > 0`）——
它本来就随 scroll / RO / 400ms 轮询在跑，零额外监听；视图侧只写 CSS（四个视图各一行选择器）。

### 2. 光条 2D 羽化

`linear-gradient(90deg,…)` 的左右两端是渐隐的，但**上下缘是硬边**（59px 的一条带子横在顶栏上，
边界一眼可见）。改成 **2D 径向**：`radial-gradient(120% 100% at 50% 50%, rgba(255,255,255,.68) 0%,
rgba(255,255,255,.30) 46%, rgba(255,255,255,0) 100%)` —— 四个方向同时收口，才是"光"的样子。
圆角/描边/阴影一律不加（那本身就是分界线）。

### 3. 亮点指示器

- **位置量的是激活钮自己的 `offsetLeft/offsetWidth`**（不是按 50+10 的间距算）：
  以后改按钮尺寸/间距，亮点自动跟得上，不用同步改两处数字；
- 在 `useLayoutEffect([view])` 里量 ⇒ "按钮换高亮"与"亮点滑过去"在同一次布局里落定，不会闪；
- `transition: transform/width 220ms var(--ease-standard)`（复用 R37-P4b 落的动效令牌）；
  reduced-motion 下 `0.01ms`（瞬移到位，渐隐是静态遮罩不受影响）；
- **`pointer-events: none` 是硬要求** —— 亮点盖在按钮上，不关掉就会吃掉点击
  （"看着能用、其实点不着"的典型）。

## 三、护栏（先红后绿，全部量化）

| 判据 | 拦的是什么 |
|---|---|
| 光条背景含 `radial-gradient` | 线性渐变 ⇒ 上下缘硬边（用户要的"边缘羽化"没做到） |
| 光条**无**圆角/描边/阴影 | 那三者本身就是"分界线" |
| 亮点中心 == 激活钮中心（≤1.5px） | 亮点要"追随当前切换的按钮" |
| 亮点 `pointer-events: none` | 否则挡住视图钮的点击 |
| 亮点过渡里含 `transform` | 否则切换时不滑动（硬跳） |
| 滚动体下发 `data-scrolled` | 渐隐开关的单一事实来源 |
| 未滚动 ⇒ **不许**有 mask；滚动后 ⇒ **必须**有 mask | 两个方向都要判（只判一半 = "看着有、其实没接上"） |

**反向验证**：实现前 **3 红/视图**（线性渐变 / 无亮点 / 无 `data-scrolled`）→ 全绿。

**⚠️ 尺子又踩一次（第三次同类）**：亮点带过渡，而**虚拟时间下过渡不推进** ⇒
`getBoundingClientRect()` 报的是**过渡起点** —— 实测只有 `cards` 那一档量到"亮点没跟上"
（其实是尺子读的旧值；提交值一直是对的）。修法照旧：**量之前先注入
`.glow-spot{transition:none !important}` + 强制重排**（本仓 `--settings` 与 chevron 两处已有先例），
同时把**内联 transform（提交值）**一起记下来 —— 这样"状态没跟上"与"尺子读不到"能一眼分开。
