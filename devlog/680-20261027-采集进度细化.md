# 680-20261027-采集进度细化：阶段 / 翻页 / 吞吐 / ETA / 逐场状态

P2：让"正在采集"不再只有一个 `3/25 场`。

## 后端 `CollectProgress` 新增

| 字段 | 含义 |
|---|---|
| `phase` | `enumerate / fetch / aggregate / write / verify` |
| `page` / `pages` | 当前场次翻页进度（`fetch` 阶段） |
| `records` | 本次任务累计拉到的记录数 |
| `throughput` | `{records_per_s, sessions_per_min}`（属性，实时算） |
| `eta_s` | 按"已处理场次均耗时 × 剩余场次"估算 |
| `sessions_detail[]` | 逐场状态 `{live_id, start_at, state, records, reason}` |

采集循环里在四个位置埋点：开始拉取、拉到记录、聚合、落盘完成；
失败/跳过也写进 `sessions_detail`（`_mark()` 保证同一场只留一条）。

## 前端

`wb-busy` 区域新增两行：

1. **阶段行**：`阶段：拉取 · 第 3/12 页 · 已拉 41,203 条 · 5,200 条/秒 · 预计剩余 96 秒`
2. **逐场列表**（最近 8 条）：绿点=完成、黄点=进行中、红点=失败，带记录数与失败原因

样式沿用现有 tokens；列表只保留最近 8 条，避免长任务把面板撑长。
