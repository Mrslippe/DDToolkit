## 二、三个反直觉的点（都花了时间才发现）

1. **debug 构建不能用来计时**：同一段动画 debug 下帧间隔 40–56 ms（超采样光栅没优化），release 下
   16.2 ms、光栅 3.39 ms。**"波形难看"先怀疑构建档，别先改算法。**
2. **测试用的是"另一个进程的窗口"而不是记事本**：垫一块覆盖**整个虚拟桌面**的白色计数窗口
   （`GetSystemMetrics(SM_XVIRTUALSCREEN..)`）—— 只垫主屏会让副屏那次测量变成量壁纸，
   第一次就栽在这（副屏点击计数为 0，看着像"穿透失败"，其实是底幕没铺到那儿）。
3. **A/B 测内存别只看总数**：同一配置两次读数是 612 / 616 MB，而刚启动未预热时低到 384 MB
   （主窗页面还在加载）⇒ 只能取**同状态对照**或**逐进程归属**（按 `--type=` 分类后，
   两个渲染器 163 / 85 MB 一目了然）。

## 三、提炼（不随本批次变的）

- **不变量/坑** → 方案 §11：`WS_EX_NOREDIRECTIONBITMAP` 与 `UpdateLayeredWindow` **不能共存**
  （TrafficMonitor 源码注释：noredir 会让 ULW 失败）；`SetLayeredWindowAttributes` 与 ULW 互斥；
  ULW 会失败时"清掉再重设 `WS_EX_LAYERED` 位后重试"；置顶要用 `SetWinEventHook` 事件钩子而不是每秒轮询。
- **验证手法** → `docs/DEV-LOOP.md` §6 那条"垫底幕采样"这次扩了两点：**底幕要铺满整个虚拟桌面**、
  **穿透必须用别的进程的窗口验**（自己的窗口证明不了跨进程）。
- 探针本身是**抛弃件**，但它的结构（`win.rs` / `draw.rs` / `cli.rs` / `anim.rs`）就是将来 `widget` crate
  的骨架；`--shot` 出来的 PNG 就是 §6 那条"金标图"链的原型。
