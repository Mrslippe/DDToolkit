## 一、为什么必须"打进产物"

浏览器只接受两种扩展来源：**商店**，或**本地目录 + 开发人员模式**（双击 `.crx` 从 Chrome 75 / Edge 起
就被禁了）。v1.1.0 之前 `extension/` 只活在仓库里 ⇒ 只下载 Release 的新用户**根本装不上**
（而界面文案还写着"选本仓库的 `extension/` 目录"——只有开发者做得到）。把那份目录随包发出去之后，
新用户要做的只剩"在应用里看到路径 → 浏览器里选它"。

## 二、四处接线（每一处都有机器判据，缺一处都不报错、只是"装不上"）

| 环节 | 落点 | 判据 |
|---|---|---|
| 暂存 | `scripts/stage_extension.py`：仓库根 `extension/` 的**白名单**条目 → `frontend/src-tauri/extension/`（已 gitignore）；`tauri:build` 里先跑它 | `extension/test/logic.test.mjs` 的结构判据（`tauri:build` 必须含 `stage:extension`、`resources` 必须含 `extension/**/*`、白名单不含 `test`） |
| 直装版 | `bundle.resources` 加 `extension/**/*`（**数组形式**；map + glob 会把目录摊平，devlog/036） | 新增 `release.py::classify_nsis_extension`：**只认目标路径** `/oname=extension\`（源路径里也有这个词，按源判会误命中）+ 一条拿真实 `installer.nsi` 量的用例。实测 **8 行** |
| 便携版 | `collect_release.py::_portable` 把暂存目录拷成 `DDtoolkit\extension\` | `verify` 断言 zip 里有 `DDtoolkit/extension/manifest.json`。实测 **881 条目**（原 873）· `扩展=True` |
| 指路 | 壳 `extension_dir` / `open_extension_dir` → 设置 → 登录 → 浏览器扩展 那一栏（路径 + 「打开目录」+ 装法三步） | `cargo test`（候选顺序 / **空目录不算扩展** / 暂存那份是 MV3 + 四档图标齐）· vitest 12 条 · 探针 `--first-run` 判那一行在不在 |

## 三、口径与踩到的坑

- **两条命令的路径由壳解析、前端传不了路径**（与 `open_data_dir` 同一口径，写进 `SHELL.md` 不变量 30c）——
  否则等于把"打开任意目录"交给页面；两条都进了 `COMMAND_ACL`。⚠️ 第一次只加了表没加
  `generate_handler!`，注册表↔准入表对账用例**当场红**（这条判据值回票价）。
- **`test/` 不进产物**：白名单只认 `manifest.json` / `src` / `icons` / `README.md` ——
  扩展开源目录里的用例（`node --test`）不该被打进安装包。
- 「像不像一份扩展」的判据是 **`manifest.json` 在不在**，不是"目录存不存在"：dev 下 `resource_dir()`
  指向 `target/debug`，那里可能留着同名空目录 ⇒ 用户照着填进浏览器却加载不了。
- 浏览器/探针里 `extensionDir()` 返回 `null` ⇒ 那一行只显示说明、**不渲染按钮**
  （"点了没反应"比没有入口更糟）；探针里 `data-ext-dir="unknown"` 是合法形态。
- 顺带修 README 里已漂的测量值：版本表还是 1.0.2 / 58 MB / 72 MB，实测 1.1.0 是 **45.4 / 52.6 MB**。
