# 558-20261019-缩放时另一端跟着动、中央把手越界

用户两条，都是滑杆的交互缺陷。

## ① 拖缩放条一端，另一端跟着动并闪

**原因：锚点记的是「轨宽百分比」**。而缩放恰恰在改轨宽 ⇒ 同一个百分比在缩放前后对应**不同像素**，
于是被"固定住"的那一端其实在动；再叠上 `requestAnimationFrame` 里改 `scrollLeft` 触发的
`clamp()` 反向推挤，就成了闪动。

**改法：锚点改成「场次序号」。**

- 拖右端 ⇒ 固定**左端序号**：`scrollLeft = leftIdx * step2`
- 拖左端 ⇒ 固定**右端序号**：`scrollLeft = rightIdx * step2 - clientWidth`
- 按下瞬间把 `step0 / scroll0 / clientW` 存进 ref，**每次移动都从按下瞬间算**，不累积
- 新增 `suppress` 标志：程序化改 `scrollLeft` 时跳过 `clamp()`，避免自己推自己

## ② 拖中央把手，窗口一半跑到视野外

**原因：只夹到整条轨道** `[0, total - size]`，没夹到**可视区**。轨道比视口宽，
所以把手能一路推到看不见的地方。

**改法**：drag 时按当前 `scrollLeft / clientWidth` 现算可视区
`[firstVisible, lastVisible - size + 1]` 再夹。若可视区装不下窗口，取下界（保证左端可见）。

## 说明

这两条都是**交互行为**，静态截图看不出来。已跑通 `tsc` / lint / 1565 用例，
但"拖起来手感对不对"只能真机验证 —— 请你在 `tauri:dev` 里试：
① 拖缩放条左右两端，看对面端是否稳住；② 把窗口拖到最左/最右，看是否还越界。
