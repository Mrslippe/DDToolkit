# 187-20260925-R38 批 5f：面板还是被挤压 —— 自指循环的第三件外衣

> **一句话**：批 5e 我把 `60vh` 换成了 `innerHeight - 120` —— 那**是同一个自指循环换了件外衣**。
> `innerHeight` 就是**小窗自己的高度**，而小窗高度**由面板高度决定**。
> 实测收敛在 **120px 的下限**上，面板被永久压住（用户："现在小窗还是被挤压了"）。

---

## 一、根因：换了个参照系，循环还在

面板高度 → 决定窗口高度（窗口 = 40 + 6 + 面板高）→ 而我把**面板上限**又按**窗口**高算了。
同一个循环换过三件外衣，**每一件看着都很合理**：

| 写法 | 循环怎么闭合的 | 实测后果 |
|---|---|---|
| `60vh` | `vh` = 窗口高的 1% | 折叠态窗口 40px ⇒ `60vh=24px` ⇒ 面板压成一条（用户第一次截图） |
| `innerHeight - 120` | **`innerHeight` 就是小窗自己的高** | 收敛在 120px 下限，**永远长不开**（用户第二次截图） |
| `screen.availHeight - 120` | 屏幕高**与窗口无关** ⇒ 不闭合 | ✅ |

**实测那个收敛过程**（写进单测的判据）：

```
第1轮: innerHeight= 40 -> cap=max(120, -80)=120 -> 面板=120 -> 窗口=166
第2轮: innerHeight=166 -> cap=max(120,  46)=120 -> 面板=120 -> 窗口=166
第3轮: innerHeight=166 -> cap=120 ...            ← 卡死，永远 120
```

修完（`screen.availHeight=1040`）：`cap=920` ⇒ 面板按**内容**长到 137px，只有超过屏幕才封顶。

### 可提炼的判据（已进 DEV-LOOP §6.7）

**给小窗里任何"按高度算"的值选参照系时，先问一句：
「这个值会不会因为我算出来的结果而变？」—— 会，就不能用。**

这条比"别用 vh"更本质：`vh` 只是这个循环最显眼的一件外衣，
换成 `innerHeight` / `documentElement.clientHeight` / `getBoundingClientRect().height`
**全都一样会闭合**。要的是"外部参照系"（屏幕、显示器、任务栏），不是"换一个词"。

## 二、连带修掉的第二处：`place()` 也在自判翻转

`StatusIsland.place()` 原来自己按 `window.innerHeight` 判"下方放不下就翻上去"。
在**顶栏宿主**里这是对的（`innerHeight` 就是应用窗口高，稳定）；但在**小窗宿主**里
它是同一个循环 —— 展开前后 `innerHeight` 从 40 跳到面板高，判据跟着乱跳：

```
折叠态窗口 40px ⇒ below(166) > 40-4 ⇒ 判"翻上去"
             ⇒ top = 0 - 6 - 120 = -126 ⇒ 面板跑到窗口上方去了
```

**修法**：小窗宿主下**跟随窗口那边写下的 `data-flip`**（那是屏幕级几何的唯一事实源，
`widgetExpandGeom` 用 `currentMonitor()` 算的）。顶栏宿主仍走原来的算法。
§8「宿主无关」没被破坏 —— 它只是读一个**可选**的外部信号，读不到就退回原算法。

⚠️ 配套：`data-flip` 是窗口那边 resize **之后**才写的，而那时 `place()` 已经跑过 ——
所以用 `MutationObserver` 盯这个属性变化重排。**不让窗口去调组件**（组件不该知道窗口存在）。

## 三、用户说的"日志里一堆报错"

19 条清一色是：

```
小窗 @5000ms URL 读不到：runtime error: failed to receive message from webview
```

那是我 2026-09-24 第四轮加的**诊断探针**（用来查明"页面到底有没有执行"）。
它在**窗口刚建好、WebView 还没就绪**时读 `url()` 必然失败 ——
**那是正常时序，不是故障**，但它在日志里长得跟真错误一模一样。

探针的使命在 devlog/180 就完成了（结论：真凶是同步命令卡死主线程）。
**留着它每次开窗都跑，只是持续生产噪音。** 收敛成：

- 只在**第一次**创建窗口时探一次（`WIDGET_PROBED` 一次性开关）；
- 失败降级成明确的"**时序说明**"（不再刷 `读不到` 这种像报错的措辞）；
- 页面侧那条 `[widget] 页面自检` 照旧每次都发 —— 那才是现在有用的那半条。

> **可提炼**：诊断仪器的寿命 = 它回答的那个问题被回答为止。
> 问题答完之后还不撤，它就从"提供事实"变成"制造噪音"——
> 而噪音的代价是**真错误会淹没在里面**（这次用户就以为小窗又坏了）。

## 五、这批留下的教训（一句话）

**同一个 bug 修两次不算什么，可怕的是第二次修的时候以为自己换了个思路 ——
其实只是给它换了件外衣。** 判据不是"我这次用的不是 `vh` 了"，
而是"**这个量的参照系，会不会被我算出来的结果反过来决定**"。
