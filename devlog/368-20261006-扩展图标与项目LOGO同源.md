> 用户（2026-10-06）：「浏览器拓展的图标换成项目图标，**你也可以根据小工具的特征加点元素**」。

## 一、同一份源，同一次生成

`scripts/make_icons.py` 本来就负责桌面图标（窗口 / 任务栏 / 安装包 / 商店），这次让它
**顺带产出 `extension/icons/{16,32,48,128}.png`** —— 图标只有一份真源（`docs/design/svg/LOGO.svg`），
改图标 = 改那份 SVG 再重跑脚本，**别手改 PNG**。manifest 里 `icons` 与 `action.default_icon`
都写全（浏览器四档各有各的用处：工具栏 16/32、扩展管理页 48、商店 128）。

## 二、两套画法（小尺寸的物理限制）

| 档 | 画法 | 为什么 |
|---|---|---|
| **16 / 32** | **实心白猫头**（主稿第 1 条子路径填白 + 两点粉眼） | 线稿在 16px 下描边不足 1px、胡须只有 2px ⇒ 糊成一团灰雾；实心块面保住"有耳朵的猫"这个识别特征（与各平台"小图追求识别"的规范同一条） |
| **48 / 128** | 线稿猫（缩到 84%、往左上让位）+ 右下角**白色 ⇄** | 这一档像素够，把"这个扩展干的是**同步/搬运**"画出来（用户点名"加点元素"）|

⚠️ **⇄ 是试错两版之后的选择**（都记进脚本注释，免得下次再走）：
先是「深粉圆底 + 白 ↻」——128px 下圆弧 + 箭头糊成一个**锁孔**，而且多一个圆盘像**第二个图标**；
把弧调细、箭头改成切向之后**还是**像钥匙孔（圆弧天生像环）。换成**四笔直线的 ⇄**（上左下右）
之后，18px 下也认得出，语义也正好是"浏览器 → 应用"这一次搬运。

## 三、判据

`extension/test/logic.test.mjs` 新增一条：**manifest 声明的四档都要真的在盘上**
（`icons` 与 `action.default_icon` 逐档存在、两处路径一致、文件 `existsSync`）。
为什么要有它：manifest 里写错图标路径**浏览器不报错**，只画一个空白格 —— 典型的静默故障；
而这条判据跑在 `extension logic` 步里（三档门禁都跑），顺带守住"改了图标忘了提交 PNG"。

## 四、踩到的两件小事（都写进注释/文档）

1. **`pillow` 不在 `uv.lock` 里**（脚本一直依赖它，但没人把它登记成依赖）——
   本机用 `uv pip install pillow` 装上（Pillow 11.3.0），并在这篇与脚本头里写明
   "只是开发机生成图标的工具依赖，运行时不需要"。
2. **脚本一次重写全部产物**：换机器 / 换 Pillow 版本时，`icon.icns` 与
   `Square142x142Logo.png` 会重算出字节不同的结果（实测就这两个变了）。本批**已把它们
   `git restore` 掉**（本批不该动桌面图标），并在脚本头加了"跑完看 `git status`，只提交你要动的"。
