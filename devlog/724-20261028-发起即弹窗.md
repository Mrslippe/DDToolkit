# 724-20261028-点采集/分析后直接弹窗（修订第 2 条）

## 口径变更

2026-10-28 早些时候用户先定"**不自动弹**，总进度在顶栏、点顶栏才开窗"；
当晚看完真机后修订为：**点击采集后应该直接弹出弹窗**。分析按同一口径（用户确认"是"）。

所以 `devlog/718` 里"不自动弹"那条被**覆盖**了 —— 顶栏胶囊仍然保留（关掉弹窗后靠它找回），
但"发起 → 弹窗"是默认行为。

## 改动

`hooks/useFanTask.ts` 两处，各一行：

```ts
// startCollect() / startAnalyze() 成功发起之后
emit({ openWindow: true })
notifyTopBar()      // ← 第 3 条改进的钩子，见下
```

## 顺带铺好了"顶栏延迟"的地基

新增 `FAN_TASK_EVENT = 'ddtoolkit:fan-task-changed'`：任务一发起 / 一结束就
`window.dispatchEvent`。顶栏的进度胶囊来自**后端** notices，而后端那条要等下一拍轮询
才回到前端 —— 这就是"点了采集，顶栏隔 1~3 秒才出现"的原因。有了这个事件，顶栏可以在
收到时**立刻**拉一次通知（一次请求、几十毫秒），而不是等定时拍。

⚠️ 用 DOM 事件而不是 import 耦合：`TopBar` 在渲染树上层，反向依赖 store 内部函数没必要。
⚠️ **这一步只搭了钩子，顶栏还没接**（见下"未完成"）。
