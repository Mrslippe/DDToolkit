## 顺带铺好了"顶栏延迟"的地基

新增 `FAN_TASK_EVENT = 'ddtoolkit:fan-task-changed'`：任务一发起 / 一结束就
`window.dispatchEvent`。顶栏的进度胶囊来自**后端** notices，而后端那条要等下一拍轮询
才回到前端 —— 这就是"点了采集，顶栏隔 1~3 秒才出现"的原因。有了这个事件，顶栏可以在
收到时**立刻**拉一次通知（一次请求、几十毫秒），而不是等定时拍。

⚠️ 用 DOM 事件而不是 import 耦合：`TopBar` 在渲染树上层，反向依赖 store 内部函数没必要。
⚠️ **这一步只搭了钩子，顶栏还没接**（见下"未完成"）。

## 第 3 条收尾：顶栏接了事件（同一提交的后续）

`TopBar` 新增一条独立监听（`[]` 依赖的 effect）：

```ts
window.addEventListener(FAN_TASK_EVENT, () => {
  void api.getNotices().then((nb) => { setServerNotices(nb.notices); noticesBusy.current = nb.manual_running })
})
```

- 任务**发起/结束/收起**（`startCollect`、`startAnalyze`、`tick`/`analyzeTick` 的收尾、
  `dismissTask`）都会广播一次 ⇒ 胶囊**立刻**出现、立刻撤掉，不等下一拍；
- ⚠️ 只刷"通知"这一份，**不动** `getFetchStatus` 与那条轮询链的并发保护（`inFlight`）：
  一次性请求、不排程、不续链，失败了下次轮询自会补上；
- 没有走"本地伪造条目"那条路 —— 本地条目 id 必须 `local-` 开头（`mergeNotices` 规则），
  会和服务端那条 `progress-fan` **同时出现两条重复胶囊**。触发刷新更简单且无重复。
