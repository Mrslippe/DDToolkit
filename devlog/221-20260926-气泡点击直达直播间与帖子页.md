# 221-20260926-气泡点击直达直播间 / 帖子页（R12 续）

> 用户：「增加点气泡直接开直播间/帖子页」
>
> 这是 R12（devlog/220）的第二步：220 让气泡**能弹出来**，这轮让它**点得动**。

---

## 一、难点：通知区域气泡的点击不在"我们这边"

托盘气泡没有按钮、没有 URL 字段。用户点它时，shell 会往**图标所属窗口**投一条
我们指定的回调消息（`NIF_MESSAGE` + `uCallbackMessage`），`lParam` 才是"用户点了"
这个事实（`NIN_BALLOONUSERCLICK = 0x405`）。要收到它，三件事缺一不可：

1. `NIF_MESSAGE` + `uCallbackMessage` 挂在图标上（220 已经有了 —— 当时只是没接管）；
2. 窗口过程要**认这条消息**（`_on_message` 里判断 `msg == CALLBACK_MSG and lParam == 0x405`）；
3. **调用方在泵消息**。这条最容易漏：220 的投递线程是"睡 0.5s → 取队列"，
   消息只是堆在线程队列里没人派发 —— 用户看到的就是**点了没反应**，
   而日志里一个字都没有（安静地失败，本仓的老毛病）。

于是这轮把投递线程的空转改成"泵消息 + 取队列"，并给气泡显示期与间隔期都换成
`_Balloon.wait()`（泵消息版的 sleep）。

## 二、做了什么

### 2.1 链接进 `Notification`（`notifier.py`）

`Notification` 多一个 `url` 字段（点不开就 None），两个合成函数各自定优先级：

| 通知 | 点击目标（从高到低） |
|---|---|
| 开播 | 直播间 `live_url` → `https://live.bilibili.com/{room_id}`（自己拼）→ 该 V 的账号主页 |
| 更新动态 | **第一条新内容的 `permalink`** → 该账号主页（`account_home_url()`）→ 不可点 |

- 主页兜底口径**照抄前端** `utils/postTypes.ts::accountHomeUrl`（B 站 `space.bilibili.com/{uid}`、
  微博 `weibo.com/u/{uid}`）—— 实测 B 站 `accounts.url` 常为空（devlog/048），
  没有兜底就等于"通知有、点不动"；
- 有链接时正文尾巴挂 `｜点击打开`（气泡没有按钮，不提示就没人会点），
  预算里**先扣掉提示的长度**再做截断，免得提示被截掉；
- 链接一律收窄到 **http/https** 才交给 `os.startfile`（`_http_url()`）——
  数据来自上游，但"点一下变成执行本机路径"这种事故不该有入口。

### 2.2 点击 → 打开浏览器

`_Balloon` 新增：

- `click_url`：当前这条气泡的点击目标（每次 `show()` 前由投递线程写入）；
- `pump()`：`PeekMessageW` + `TranslateMessage` + `DispatchMessageW` 把本线程消息派发掉；
- `wait(seconds)`：泵消息版的 sleep（气泡显示期、两条气泡的间隔期都用它）；
- `_on_message()`：认 `NIN_BALLOONUSERCLICK` → `_open_url()`（**就地打开**：`os.startfile`
  只是把 URL 交给 shell，几十毫秒；起线程反而让"点了会怎样"不可断言）。

`_on_message` 是 **ctypes 回调**（跑在 C 栈上），异常穿出去只会换来一行
`Exception ignored` + 一个垃圾返回值，所以整段包 try，失败只记日志。

### 2.3 探针也能验点击（`scripts/notify_probe.py`）

`show_now()` 增加 `url` 参数，探针的示例链接指向 `example.com`，并在输出里明写
「气泡显示期间**点它一下**：应该用默认浏览器打开上面的链接」——点击这件事没法自动断言
（要人去点），但可以让它**可操作、可观察**。

## 三、口径与已知边界

- **点击窗口 = 图标存活期**（`NOTIFY_BALLOON_LINGER_SECONDS`，默认 8s）：
  气泡显示结束后我们 `NIM_DELETE` 摘图标，之后（比如从操作中心里翻出来再点）多半收不到回调；
- **多条内容只开一条**：气泡没有列表可选，开"最新那条"是最不意外的选择；
- **不做"点了自动跳转后关掉浏览器以外的动作"**（比如直接唤起应用内视图）——超出气泡能力范围；
- 气泡文案与可点性一致：**不可点的气泡不会挂「点击打开」**（避免"提示能点、点了没反应"的反向坑）。
