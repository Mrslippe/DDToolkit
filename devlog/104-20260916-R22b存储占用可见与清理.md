## 一、为什么"显示占用"本身就是一个功能

A/D 两批已经把**涨得最快的缓存**管住、并让**删数据真的还盘**，但用户看不到任何数字 ——
他只知道"装在 C 盘"，不知道"现在占多少、谁在长、还剩多少"。R22 的起因（"会不会挤爆 C 盘"）
本质上是**信息缺失**，所以这一批把三件事补齐：

| 补什么 | 在哪 |
|---|---|
| 三块占用 + 合计 + 磁盘剩余 + 遗留备份提示 | 「关于」页新增「存储占用」面板 |
| 两个能**当场动手**的动作 | 「清理图片缓存」（全清）·「整理数据库」（回收 WAL + 还盘） |
| 空间偏紧时主动说一次 | 状态岛瞬时消息（复用现成通道，不新造通知类型） |

## 二、后端（`app/routers/settings.py`）

| 端点 | 干什么 |
|---|---|
| `GET /settings/storage` | `dir_stats()` + `cache_stats()` + `low_space` 判定（**阈值由后端算好下发，界面不抄一份**） |
| `POST /settings/storage/prune-cache` | `img_proxy.clear_cache()`（全清；顺带扫掉"只有元数据没有图"的孤立 `.json`） |
| `POST /settings/storage/maintenance` | `checkpoint_wal()` + `incremental_vacuum()`，返回省了多少 |

两个动作的返回里都**带上最新占用**，省掉界面为了刷新数字再打一次接口。
`LOW_SPACE_THRESHOLD_BYTES = 5GB` 是模块常量（用户口径：不做成设置项）。
`clear_cache()` 与 `prune_cache()` 的关系写清了：前者是"用户主动全清"，后者是"到点/超限自动清"。

## 三、前端

- **关于页存储面板**（`AppSettingsDialog` → 关于）：复用 `.aps-info` 的 dt/dd 栅格，
  显示 数据库 / 图片缓存（**带上限**）/ 日志 / 合计 / 磁盘剩余；余量偏低时挂一枚「空间偏紧」徽章；
  有手工 `.bak` 时单独提示一句"不是程序生成的，确认没用可以删"；右下角两个浮片按钮（R21 批 3 的元件）。
- **`formatBytes()`**（`utils/format.ts`，纯函数 + 2 条用例）：二进制单位、>100 不带小数；
  `null/NaN` 当 0 —— 界面不该因为一个空值崩掉。
- **`useLowSpaceNotice()`**（新 hook，挂在 `TopBar`）：等第一轮 `fetch-status` 回来再查
  （既保证后端就绪，也保证 `pill-message` 监听已挂上），`low_space` 时发一条状态岛瞬时消息；
  **同一台机器 3 天内只提一次** —— 磁盘满是持续状态，每次启动都喊一遍只会让人讨厌；
  拿不到数据就静默。
