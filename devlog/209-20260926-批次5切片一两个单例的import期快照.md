批次 5（R2 `FetchStatusStore` 并发一致性）的**第一刀**：计划 §2.9 那两个"改了设置不生效"的
真 bug。整批的锁/类改造还没做（见 §三）。

## 一、bug 本体（用户能感觉到的那句话："我改了抓取节奏，它吃不吃？"）

```python
_dynamics_budget = _PlatformBudget(settings.DYNAMICS_BUDGET_RPM)        # ← import 期快照
_dynamics_pacer  = _PlatformPacer(settings.STARTUP_DYNAMICS_INTERVAL_MIN,
                                  settings.STARTUP_DYNAMICS_INTERVAL_MAX)
```

`app/core/runtime_settings.py` 的承诺是"**每一轮读一次**"（`config.py` 的 `__getattribute__`
拦截 + `SPECS`）。这两个单例在**模块导入时**把值取成固定的 ⇒ **用户在设置里改
`DYNAMICS_BUDGET_RPM` / 起跑间隔，实际不生效**（改完重启才生效，而设置页没说这件事）。

## 二、修法：**显式传值 = 固定，不传 = 每次现读**

```python
_PlatformBudget(rpm=None)      # None ⇒ @property rpm 每次现读 settings（生产单例走这条）
_PlatformBudget(12)            # 显式值 ⇒ 固定（用例与别的调用方要能钉死一个值）
_PlatformPacer(gap_min=None, gap_max=None)   # 同理
```

- 单例改成 `_PlatformBudget()` / `_PlatformPacer()`（**不传参数**，注释里写明为什么）；
- 属性带 setter：`tests/test_services.py:1361` 那两处 `monkeypatch.setattr(pacer, "gap_min", …)`
  照旧能用（既有用例一条没改）；
- ⚠️ `_PlatformBudget(0)` 必须仍然是"不启用"（0 不是 None，别被当成"没传"）—— 有用例钉着。

## 三、判据与反向验证

- `test_production_budget_reads_the_hot_setting` / `test_production_pacer_reads_the_hot_setting`：
  **打真单例**（`sch._dynamics_budget` / `sch._dynamics_pacer`）改 settings ⇒ 值立刻跟着变。
  ⚠️ 这俩必须打真单例：新建一个 `_PlatformBudget()` 的话，就算有人把 import 期快照写回去，
  用例照样绿 —— 那正是要防的回归。
- `test_explicit_budget_stays_fixed`：显式值不受影响 + `0` 的语义。
- **反向验证**：把两个单例改回 `_PlatformBudget(settings.X)` / `_PlatformPacer(settings.X, …)`
  ⇒ 上面两条**都红** ✓（实测：`2 failed`）。
