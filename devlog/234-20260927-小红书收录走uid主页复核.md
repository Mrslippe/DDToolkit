也能收录小红书账号。这是"能给人试"的**功能阻断点** —— 没有它，库里进不了一个小红书账号，

## 一、为什么走"uid → 主页"而不是搜索

调研 `docs/platforms-xhs-douyin-research.md` §2.4/§2.2：小红书**搜索接口要 `xsec_token`**，
而 token 不能自行构造、只能从列表/搜索响应里拿 —— 收录这一步**拿不到**它。
⇒ 改走「拿 uid 直接问主页信息」（`fetch_user_info`，devlog/230 已经实现）：
既复核了"这个人真的存在"，又拿到规范名，**与 B 站那条"池外必须服务端复核"的纪律一致**
（前端传什么名字都不作数）。

## 二、改动

`app/routers/vtuber.py::adopt_vtuber` 的池外分支多一条：

| 分支 | 判据 |
|---|---|
| `source="xiaohongshu"` 且 `platform="xiaohongshu"` | 用适配器复核 uid ⇒ 建库；名字取**服务端**结果 |
| 平台对不上（如 `platform="weibo"`） | **400**（别静默换平台） |
| 适配器 `last_error.kind == "cookie_invalid"` | **503** + "先在登录里粘贴（至少 a1 与 web_session）" |
| `kind == "risk_control"` | **503** + "风控冷却中，稍后再试" |
| 上游确实没这个人 | **404** |

⚠️ **503 与 404 的分界是刻意的**（B 站那条踩过：把"你没登录"报成"B 站没这个 UID"是误导）：
"我们没问到"和"确实没有"必须给不同的状态码与文案。`app/routers/vtuber.py` 里那条注释与
`tests/test_xhs_adopt.py` 的用例都盯着这一点。

## 三、判据（`tests/test_xhs_adopt.py`，4 条）

① 收录成功：**用 uid 复核** + 名字只认服务端 + 落库 `platform=xiaohongshu`；
② 没 cookie ⇒ 503（**不是** 404）且不建库；③ 上游说没有 ⇒ 404；
④ `source` 与 `platform` 不一致 ⇒ 400。

⚠️ 这四条**不起真 app**：`TestClient(app)` 会带起 lifespan，实测与别的用例互相干扰
（单跑绿、全量 `RuntimeError` —— devlog/233 §二 同一个坑）⇒ 直接调端点函数，
`background` 用替身（收录响应本就不该等抓取）。
