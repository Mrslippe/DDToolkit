## 一、选中态：用户要的三件事，在"顶栏粉"那一档**数学上不能同时成立**

用户先要的是**顶栏粉 `#ffa2b4` + 白图标**。把白图标 ≥3:1 这个约束解出来：

```
白图标 ≥3:1  ⇔  填充相对亮度 L ≤ 0.30          （3.0 = 1.05/(L+0.05)）
顶栏粉 #ffa2b4 的 L = 0.504 —— 比门槛高 68%
```

**⇒ 不存在"还叫顶栏粉、又能承载白图标"的一档。** 要按顶栏粉的色相压到刚好过线，
得压到 `#c77e8c`（V=0.78）—— 那时粉已经灰掉了，用户要的那个"粉"就没了。

**这条边界还顺带说明另一件事**：同一个不等式也管"填充对白条面 ≥3:1"（条面就是白）
⇒ **一个数同时管形状与对比度**，所以"去描边之后填充要多深"没有第二个自由度。

### 用户第 1 条要求（滑块内白 / 滑块外灰 / 途中也成立）——**能做到，但代价不成比例**

本质是几何判定（图标在不在块内），JS 算得出来。但：

- 把 18px 图标在 42px 行程里**整枚**切换颜色 ⇒ 跨界那一瞬整枚跳变，而那一刻它正好
  半灰半白最难看。要真平滑得**逐像素按覆盖率混合**，CSS 做不到（要 `mix-blend-mode` 或 SVG mask）
- 更要紧的是：**它不解决根因**。用户看到的问题是"图标变白了、块还没到位"——
  而那个状态之所以存在，是因为**图标换了颜色**。图标不换色，窗口根本不存在

⇒ 所以最后没有做 JS 逐像素，而是**换填充色**：把窗口从"缩小"变成"消失"。

### 实测出来的那个数（真动画台，不是估算）

在预览页的真动画台上量：块要滑满 **42px** 才能完全盖住新图标，而滑到它左缘只要 **5px**
⇒ **行程中段被瞄准的图标有 42% 露在白条上**。

| 填充 | 那 42% 的对比 | 结果 |
|---|---|---|
| `#ffa2b4` 顶栏粉（用户想要的） | 白压白 ≈ **1.0:1** | 图标**断成两截** |
| **`#ec407a`**（方案 E，实交） | **3.76:1** | 同样的暴露**仍读得出**，只是"碎" |
| `#c9406f` 深玫瑰（方案 A） | 4.72:1 | 更碎（块与白条反差更大） |

**⇒ 定方案 E：`#ec407a`**，亮粉里**能承载白图标的最亮一档**（Material Pink 400，
H=340° S=73% V=93%），余量 25%。备选一起量过：`#f06292` 最亮但余量只剩 2%
（3.06:1，低亮度环境会掉线）且偏"芭比粉"；`#f489b0`/`#f472b6` 之类 2.6 档全部不过。

### 落地的四步（每一步都是被迫的）

| 步 | 结论 | 数 |
|---|---|---|
| ① 去描边 | 形状只能由**填充**扛 | — |
| ② 浅粉扛不住 | `--sel-bg` 对**自己这个白条面** = **1.10:1** | ❌ 比它当年在近白页上的 1.07 还差 |
| ③ 压深后深图标读不出 | `#4b5a6b` on `#c9406f` = **1.50:1** | ⇒ 图标只能转白 |
| ④ 白图标要够亮 | 填充亮度 ≤0.30 ⇒ `#ec407a` | **3.76:1** ✅ |

`tokens.css` 新增 **`--sel-strong: #ec407a`**，注释里写明它与 `--sel-bg` 的**约束相反**
（`--sel-bg` = 浅粉底配深字、越浅越好；`--sel-strong` = 承载白图标、越浅越糟）。

### ⚠️ `.float-pill.on` **不动**（用户已确认范围）

查了它影响谁 —— 一共 4 处，而且**这 4 处的约束与工具条相反**：

| # | 元素 | 内容 | 需要 |
|---|---|---|---|
| 1 | `.bg-set` 档案设置钮 | 纯图标 | ≥3:1（图标标准） |
| 2 | 列表页筛选触发器 | 文字 `筛选 · N` | ≥3:1 |
| 3 | 侧栏筛选钮 | 文字 | ≥3:1 |
| 4 | 能力说明窗「去登录」 | 文字（主操作） | **≥4.5:1**（12–13px 小字正文） |

用户说「这里是图标不需要小文字那么高的辨识度」—— **这句对第 1 处成立，对 2/3/4 反了**：
它们是**白字压粉**，要的是**更高**的标准。工具条为了保住亮粉 ⇒ 只能白图标 + 深一档底；
小字浮片要白字达标 ⇒ 只能把底压深。**两者方向相反，强行统一才是错的。**

（留档：`.float-pill.on` 现役 `白 on #fb77a1` = **2.54:1**，对 2/3/4 三处**都不达标**。
R45-A 没有扩大范围去修它 —— 那需要逐处看观感，属另一批。）

## 二、版式：用户的顾虑成立，而且比预想的更严重

### 2.1 card 视图**放弃垂直居中**（用户反驳有效）

我先提的是"对称内距 + `margin-block:auto`"。用户指出：「如果后面用户添加了很多平台
账号让容器往下拓展了很多，hero 还是会被挤到很上面」。

**查了数据，他说得对，而且更糟**：平台药丸按**每 3 枚一行**排（`chunkBy(accounts, 3)`）：

| 账号数 | 药丸行数 | hero 高度 |
|---|---|---|
| 1–3 | 1 行 | ~340 |
| 4–6 | 2 行 | ~400 |
| 7–9 | 3 行 | ~460 |
| 12 | 4 行 | ~520 |

- **居中只在"内容比容器矮"时成立**。账号加到 9 个左右 hero 就撑满，`margin-block:auto`
  自动归零、退化成顶部对齐 —— 跟没做一样
- 更糟的是**每次加账号 hero 都会往上跳一截**（居中基准在变）
- 边界也放不下：窗口最小高 600，工具条带 52 + hero 最小 ~340 = 392，本来就没有居中余量

⇒ **容器居中不适合高度由用户数据驱动的内容。** 这个否决理由比"60px 平衡"实在得多。

### 2.2 改成：**list / archive 加左对齐标题**，让内容静态让开

新增 `.page-title`（`posts.css`）：

```css
.page-title {
  padding: calc(var(--toolbar-band) + 8px) 16px 8px;   /* 让开工具条覆盖带 */
  font-size: 16.5px; font-weight: 600; line-height: 1.3;
  color: var(--c-text-main);
  overflow: hidden; white-space: nowrap; text-overflow: ellipsis;
}
```

⚠️ **它与工具条的关系是"让位"不是"参与"**：标题**不随工具条显隐**（它是内容、不是 chrome）。
工具条隐着的时候标题照常在那儿 —— 这正是"占掉一部分顶部间距"的实现方式：
**静态地让开**，而不是等工具条出现再挤。

**顺带补了单一真源**：`top:6px` / `height:46px` 原来是散在 `.glow-bar` 里的两个字面量，
现在提成令牌 **`--toolbar-top` / `--toolbar-h` / `--toolbar-band`**（= 52px），
标题按它让位 ⇒ 改条高不会漏改一处。

### 文案来源（用户口径：「直接从前端拿」）

| 视图 | 文案 | 数据源 | 新代码 |
|---|---|---|---|
| **list** | **选中账号的昵称** | 现成 `selectedAccount.display_name \|\| platform_uid` | 零 |
| **archive** | **当前卡片的标题** | `DataDeck` 新抛 `onIndexChange` + `PostsPage` 传 `labels` | `DataDeck` 加 2 个 prop |
| **profile** | —— | 用户："这轮不做 profile" | — |
| cards | 无 | hero 本身就是主体，加标题反而挡头像 | — |

**`DataDeck` 的两个改动**：加 `labels: string[]`（与 `keys` 同序）+ `onIndexChange?: (i) => void`。
回抛用**普通 effect**（挂 `index`）而不是在 `step` 里调 —— 因为 `index` 也会被
"按 V 恢复上次那张"的初始化改动，只挂 `step` 会漏掉那条路径。

### ⚠️ 两份真源的坑，以及怎么堵

卡片标题**硬编码在卡片 JSX 里**（`LiveCalendar.tsx` 的 `直播日历`、`FanTrendChart.tsx`
的 `粉丝趋势`），而导航标题要由 `PostsPage` 给 ⇒ **同一个字符串存了两份**。

本仓的惯用手法是**写两份 + 机器对账**，所以加了判据：
**archive 下「导航标题」必须等于「当前卡片内部渲染出来的标题」** —— 改了 `DECK_LABELS`
忘了改卡片 JSX 就红，不会静默漂移。
（探针取 `.lc-title` / `.fc-title` 的 **`childNodes[0]`**：那元素后面还跟着
`<span class="card-src-note">` 数据来源说明，不剥掉会把说明也读进来。）

### list 标题的位置（用户选的）

放在**账号切换器上方单独一行**。理由：切换器在左上角（`padding-left:16`），
标题若同行会被它挤（切换器宽度随账号数/名称长度变，1100 档最宽 ~200px）。

## 三、门禁：换口径 + 加三组

### 3.1 选中态（`_assert_glow` 的 ④ 组）

| 旧 | 新 |
|---|---|
| 底色 alpha 必须 =1 且**不得是渐变** | **保留**（防退回"白光点"） |
| —— | **激活图标对填充 ≥3:1**（按**渲染值**算，不写死 `#ec407a`） |
| —— | **不得有 `inset` 描边 / `border`**（拦 R39-D4 那版回流） |

新增探针字段：`onColor` / `spotBg` / `spotShadow` / `spotBorder`。

### 3.2 页面标题（新增 ⑤ 组）

1. **list / archive 必须有标题**（cards / profile 必须有**空**标题）
2. **标题下缘 ≥ `--toolbar-band`** —— 拦"象征性挪一点"；这是用户口径的机器化
3. **标题不与工具条 rect 相交**
4. **archive：导航标题 == 卡片内渲染的标题**（两份真源对账）

新增探针字段：`pageTitle{text,rect}` / `cardTitle` / `toolbarBand`。

## 四、验证

### 4.1 探针首跑：**34 处红**，而且几乎全是"探针自己的问题"

拿到完整权限后第一次真跑，红了 34 处。**逐条查根因，没有一条是产品代码错了** ——
这一节值得全文留着，因为它是"判据写得比被测对象更容易错"的密集样本。

| # | 症状 | 真根因 |
|---|---|---|
| 1 | `算不出 --toolbar-band（'calc(6px + 46px)'）` | 自定义属性的值**在使用处**才求值 ⇒ `getPropertyValue` 只回字符串。分量读出来自己加 |
| 2 | archive 帧上 `.on` 读到深色、`.off` 读到**白色且 opacity=1** | **自相矛盾的读数**（`.off` 不可能 opacity=1）⇒ 尺子读在过渡中途。R45-A 给 `.view-btn` 加了 `color/opacity` 过渡，而探针只杀了 `.glow-spot` 的 ⇒ **必须一起杀** |
| 3 | `18 处"没有页面标题"` | 页面 `Failed to fetch` —— 见下 §4.2，**这条是真 bug** |
| 4 | `页面标题与工具条相交` ×18 | **两个坐标系混用**：`pageTitle.rect` 是视口坐标（y=40 = 顶栏高），`--toolbar-band` 是面板内坐标（52）。拿 129 与 52 比 ⇒ 一条恒真、一条假红 |
| 5 | `该页不该有页面标题（拿到 '七海Nana7mi'）` ×12 | 判定写成 `tag in ("list","archive")`，而 `list` 还有 6 个扩展帧（`list-scrolled` / `list-filter-*` / `list-video`）—— 它们**都是列表页**。改成判"视图族" |
| 6 | `筛选弹窗越出右栏` ×6 | **我的 `.page-title` 把它挤出去的**：`.post-filter-pop` 的 `max-height: calc(100vh - 252px)` 是"筛选行之上有多少固定高度"的**手算值**，加了 89px 标题后不再成立。改成 `calc(100vh - 252px - var(--toolbar-band) - 38px)`，跟同一个来源走 |

**两次"编辑事故"也留档**：改 §5 段时多缩进了一层，我用脚本机械左移，
结果**把 `if tag == "archive":` 的 body 多减了一格**（15 应为 16）——
`ast.parse` 只报"某行 SyntaxError"，不报"层级错了"。**这类自动改缩进必须逐行复核**。

### 4.2 一个真 bug：`_seed_accounts` 造的数据不合后端契约

```
pydantic_core._pydantic_core.ValidationError: 6 validation errors for VTuberOut
accounts.2.live_status  Input should be a valid integer [input_value=None]
```

`live_status` 可空，所以 INSERT **不报错**；但 `VTuberOut` 把它声明成 `int`
⇒ `/vtuber/{id}` 500 ⇒ 前端 `Failed to fetch` ⇒ **页面连 V 都加载不出来**，
于是所有视图级判据（页面标题 / 牌堆 / 画布）**一起报"缺失"**。
⇒ 教训：**"可空但下游当非空用"的列，种数据时必须照抄基准行的值。**

（另一条同族的：`accounts` 没有 `created_at/updated_at` —— 我照 `posts` 表的习惯多写了两列，
直接报错。**两处都写进了 `_seed_accounts` 的 docstring**。）

并**补一条判据** `heroTop.topInPanel ≥ --toolbar-band`（量 `glow.heroTop`）。
**新判据当场在 3 档上各红了 1 处** —— 证明它真的在拦东西。

**② `+2` 溢出钮长得不像药丸**：白底方块，比旁边药丸**矮一截**，看着像错位。
⇒ 修：几何完全继承 `.stat-pill`（191×37 / 2px 圆角 / **同一条 box-shadow**），
底色由白改成 `--sel-bg` 淡粉（既与平台图像底区分得开，又还在同一族）。

**③ 列表页另发现一处（判据也测不到）**：标题与账号切换器之间**没有留白**
（标题 y≈143、切换器 y≈190），视觉上标题像被切换器压着。

⇒ 记为遗留（见 §五）。

**这条元教训值得单独记**：`ui_probe` 的三档 × 10 帧、几十条判据，
拦住了"结构错"，但**拦不住"看着不对"** —— 而 R45-A/B/C 三批改的**全是"看着对不对"的东西**。
判据绿 + 截图看，两者缺一不可。

## 五、遗留

1. **`profile` 视图没做标题**（用户："这轮不做"）。⚠️ 但它是三个视图里**最严重**的：
   首行卡片**通宽**（`.board-view .os-scroll { padding: 12px 18px 18px }`），
   工具条会盖住**中间列的首行卡片**。
2. **`.float-pill.on` 的白字对比仍是 2.54:1**，对其中 3 处小字**不达标**。
   本轮按用户口径不动，但它是真账。
3. **off 图标压在"正被滑过的块"上只有 2.43:1** —— 行程过渡态，**没设为判据**
   （那枚图标本来就在被替换的过程中，两侧的 on/off 都达标）。
4. **标题与账号切换器之间没有留白**（§4.4 ③）—— 判据测不到"两个元素挨太近"。
   要补的话得判"标题下缘与切换器上缘的间距 ≥ 某个值"，但那属于**排版审美**，
   判据化要谨慎（容易变成"写死一个数字"）。
5. **`--shot-toolbar` 只截最宽档**：窄档（1100）才是布局最紧的一档，
   视觉评审其实更该看它。留着按需再扩。
6. **预览页 `_tmp_A预览.html` 的慢放倍率写反了**（`DEMO_MS * 0.25` = 加快 4 倍，
   不是慢放）—— 用户发现的。**仓里那份 `MotionLab.tsx` 是对的**（设 `--motion-scale`，
   令牌是 `calc(N × scale)`），只有我的临时预览页写反，且它不影响结论
   （用户是在 1× 真实速度下得出"图标不会被分割"的判断）。
