# 570-20261020-时间口径：一个真源，三层规则

接着 569 查出的"76/227 场偏 8 小时"，把**整条链路**的口径收成一条规则。

## 三层规则

| 层 | 口径 | 谁负责 |
|---|---|---|
| 存储 | **UTC**（naive 字符串） | `timecn.utc_iso()` |
| 分天/分月/分年 | **东八区** | SQL 用 `timecn.sql_day()`；Python 用 `timecn.cn_day()` |
| 展示 | 浏览器本地时区 | 前端 |

新增 `app/core/timecn.py` 作为唯一真源：`utc_iso` / `parse_utc` / `cn_day` / `sql_day` /
`day_bounds_utc`，常量 `CN_TZ` 与 `SQL_SHIFT`。

## 改到的读侧

| 位置 | 之前 | 之后 |
|---|---|---|
| `/fan/{v}/activity` 按天聚合 | `date(s.start_at)`（UTC 日） | `sql_day('s.start_at')` |
| 同一接口的区间过滤 | 同上 | 同上 |
| 逐场明细的日期键 | 同上 | 同上 |
| 首末场次日期 | 同上 | 同上 |
| `load_window` 的 `since`/`until` | `start_at[:10]`（UTC 日） | `cn_day(start_at)` |

**为什么要改**：当地 00:00–08:00 开播的场次，UTC 日期比本地早一天 —— 用户"选 10-20 却少一场"，
而且这种偏移在热力图上看不出来（只是整体左移一格）。

## 测试

`tests/test_timecn.py`：
- `utc_iso` 不随机器时区漂移；
- `cn_day` 的跨日边界：`15:59:59Z → 23:59 本地`（当天）、`16:00:00Z → 00:00 本地`（次日）；
- **`sql_day` 与 `cn_day` 在边界上逐条一致**（用内存 SQLite 跑真实表达式）；
- `day_bounds_utc` 的边界值；
- `parse_utc` 显式带时区，解析失败返回 None。
