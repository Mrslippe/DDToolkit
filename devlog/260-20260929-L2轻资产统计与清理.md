# 260-20260929-L2 轻资产统计与清理（dry-run）+ 设置页读数

轻资产模块第三批（执行方案 §3 的 L2）。**B 档**：不改表、不改既有契约，
只是把 L1 已经写好、但**用户看不见也动不了**的那半边（`stats` / `prune` / `pin`）接到界面上。

## 一、三个端点（都挂在 `/settings` 下）

| 端点 | 语义 |
|---|---|
| `GET /settings/assets` | 读数：按 kind 的文件数 / 字节 / 已固定数 / **索引有盘上没有的条数** / 最旧一份 + 合计 + 图片缓存那一份 |
| `POST /settings/assets/prune` | 淘汰未 pin 且未被引用的；**`dry_run` 默认真**；报告里顺带带最新读数 |
| `POST /settings/assets/pin` | 打/撤长留标记；索引里没有它 ⇒ **404**（不凭空报成功） |

⚠️ **为什么放 `/settings` 而不是另开 `/assets` 一组**：消费者只有设置页那一块（它已经在打
`/settings/storage`），而多一组路由就多一套鉴权面与前端 client（`ARCHITECTURE` §6 第 26 条
那条"往白名单/路由表里加东西要当改安全边界"的纪律）。执行方案里写的 `/assets/*` 是这个意思。

## 二、界面上多了什么

「关于 → 存储占用」多一行 **轻资产副本**（与「图片缓存」并排 —— 规格 §2.5 那两套东西的边界
就摆在用户眼前），动作行多一枚 **「清理未使用的轻资产」**：点它先打一次
`prune --dry-run`，**把"将删除 N 份 / 释放 X"摆出来让人确认**，确认了才带 `dry_run:false`
再来一次。没有可清理的就说一句"没有可清理的轻资产（被引用的和已固定的都不动）"。

## 三、判据与反向验证

`tests/test_assets_api.py` **6 条**（读数字段与合计 / dry-run 缺省且不删 / dry-run 与实际逐条相等 /
pin 与引用在**端点这一层**也删不掉 / pin 往返与 404 / 未知 kind 422）。

**反向验证 3/3 全红**（锚点唯一、字节级还原 + sha256 核对）：端点忽略 `dry_run` /
端点不 `commit` / pin 不校验存在性。
⚠️ 第二条最初**没红** —— 因为判据只在**同一个会话**里数行数，而 `flush` 已经让删除对本会话
可见、文件也 unlink 了 ⇒ "忘了 commit"照样全绿。补了一条**另开会话**再数一次的断言之后才真红。
**这就是反向验证的价值：它证明的是"判据有牙"，不是"实现正确"。**
