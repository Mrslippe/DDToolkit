# 599-20261023-池子改按 ACV 划（B 方案）：核心 0.75×、次核心 1.25×、外层取消

用户定案：选 B（抬高门槛），外层不要，只在图上标明"分流走多少人"。

## 一、ACV 从哪来

danmakus 的 `/api/v2/live?includeExtra=true` 里 `live.extra.onlineRank` 是**逐秒级**同接时间线
（一场 2,859–18,503 个点），比 vtb.cat 的逐分钟更细。交叉验证：两源 ACV 中位偏差 **−1.2% ~ −0.0%**。

**裁剪**：ACV = 去掉头尾各 10% 的点后的均值。实测头部 10% 只有整体的 55%–65%、尾部 85%–90%，
不裁会低 2%–8%；裁 10% 与裁 15% 只差 <1%。

## 二、落地

1. 采集时 `fetch_records(..., with_extra=True)`：**同一次请求**顺带拿 `onlineRank`，
   落 `stats.acv / acv_points / peak_online`，不增加请求数；
2. 回填脚本 `scripts/backfill_acv.py`：323 场补了 **319 场**，缺 4 场（上游没有该场 extra）；
3. 分析层：`build_axis_table(..., pool_size=2×ACV)` —— 按出席场次降序取前 N 人；
4. 分层：核心 = 0.75×ACV、次核心 = 剩余；**取消外层**，其余人记 `excluded`（分流走）。
