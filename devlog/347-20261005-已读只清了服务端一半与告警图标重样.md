# 347-20261005 已读只清了服务端那一半 / 告警图标四条一模一样

> 用户截图反馈两件事：
> ①「面板中全部已读按钮点击后没有响应是正常的吗，并且需要处理这一栏下面的通知即使我点进详情中
> 处理了但还是一直存在，这是只在调测中出现还是实际使用中出现」
> ②「开播通知、登陆失效、功能受限、上游风控全都用的一个警告图标，我希望开播通知用其他图标区别一下」。

## 一、①的答案：**不是正常的，而且实际使用中也会出现**（真 bug）

原来两条已读路径都只做了一半：

```ts
setServerNotices(prev => prev.filter(x => !r.acked.includes(x.id)))   // ← 只清了服务端那份
```

而**本地条目**（客户端自己的事实 / dev 注入 / 能力受限 / 通知调测页造的那些）**不在
`serverNotices` 里** ⇒ 点了等于没点。更糟的是它们**常驻**（`cap-limits` 与 `report-*` 都是
`sticky`）⇒ **永远删不掉**。所以：

| 场景 | 实际使用 | 只在调测 |
|---|---|---|
| 「全部已读」看着没反应 | ✅ **会**（能力受限那条本地条目永远在） | 更明显（注入的报告也是本地的） |
| 点进详情处理了它还在 | ✅ **会**：报告对话框的「知道了」原来只 `setDoneReport(null)`，**没 ack** | 同上 |

修法：抽一个 `ackIds(ids)`，**两边一起清**：

- 本地那份：`setLocalNotices(filter(...))` 就地删；
- 服务端那份：**只把真的来自服务端的 id** 发 `POST /vtuber/notices/ack`
  （本地 id 发过去会把客户端自己的名字写进服务端已读集合 —— 污染 + 白占 `READ_LIMIT` 上限）；
- 单条（`dismiss`）、整组（`ack-all`）、报告对话框的「知道了」**三条路都走它**。

判据：组件级那条改成"载荷必须是 `todoIds` 算出来的 id（`report-1`）"，另加**源码级结构判据**
（存在 `ackIds`、本地被过滤、两条入口都走它、服务端仍发请求）—— 要渲染级复现得把整个
`TopBar`（路由+api+capabilities+轮询链）搭起来，收益不抵成本。

## 二、②：图标现在按**来源**分，认不出来才退回 `kind`

`kind` 只有四种，而开播 / 登录失效 / 能力受限 / 风控冷却**全是 `alert`** ⇒ 面板里四条
不同的东西顶着同一个 ⚠。用户的判断很准：**开播是好事，用警示三角是在说错话**。

口径：`source`（后端给的字符串，`services/notices.py` 里的 `"开播"` / `"登录态"` / …）
→ 图标的一张表，**不动契约**；认不出来退回 `KIND_ICON[kind]`（不会出现空白图标）。

| 来源 | 图标 | 为什么 |
|---|---|---|
| 开播 | `Radio`（广播信号） | **好消息**，不是警告 —— 用户点名的那一条 |
| 登录态 | `KeyRound`（钥匙） | 凭据问题，与顶栏那个"钥匙"登录入口同语义 |
| 能力矩阵 | `Gauge`（仪表盘） | 说的是"打了折 / 有范围限制"，比锁少一点责备感 |
| 风控冷却 | `Hourglass`（沙漏） | 它等的就是时间，正好配右侧那个每秒刷新的倒计时 |

判据（组件级）：四条**两两不同**（相同就等于没区分）+ 开播**不许**是 `triangle-alert`
+ 认不出的来源退回 `kind` 那套。
