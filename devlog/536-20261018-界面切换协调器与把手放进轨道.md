# 536-20261018-界面切换协调器 + 把手真的放进轨道内

## ① 协调器：导航推迟到幕布合上之后
用户要的顺序：**界面不动 → 闭幕 → 加载中（这时候才换界面）→ 揭幕 → 完成**。
之前的实现里，点击瞬间就 `navigate` 了 —— 新界面在幕布**还没合上**时就渲染出来，成了"先换再遮"。
光调 CSS 时序改不了这件事，必须**推迟导航**。

新增 `utils/viewTransition.ts`：

- `setViewTransitionDriver(fn)` —— 壳层注册 driver；
- `requestViewChange(next)` —— 工具栏调它，把"真正的导航"作为回调交出去；
  没有 driver 时（单测/壳层没挂）直接执行，保证导航不会卡死。
`App` 里的 driver 按四段驱动，并在**加载段**才调用 `next()`：
```
0ms      闭幕开始（180ms）
180ms    图标渐显（140ms）
320ms    进入加载段 + **调用 next() 换界面**
520ms    揭幕开始（260ms）
780ms    结束
```

`IconRail` 的两个入口（帖子浏览、模块）都改成 `requestViewChange(() => navigate(...))`。

⚠️ 同一界面内换 V（`/vtubers/16 → /vtubers/17`）**不走协调器**，也不播揭幕 ——
那条路径是左栏自己的 `navigate`，本来就该是瞬时的。

## ② 把手依旧越界 —— 这次改对了地方

前两版都在挪把手位置（`-6px` / `0`），治不了根：**只要把手跨在窗口边缘，窗口贴到轨道两端时
它必然有一半在轨道外**。

这次改结构：
- `.wb-win` **不再自己画左右边框**，边界交给把手表达；
- 把手贴在窗口**内缘 1px**（`left/right: 1px`），宽 6px、圆角、带描边、22px 高；
- 因为把手在窗口内部，而窗口被夹在 `[0, total-size]` 内 ⇒ **把手必然在轨道内**，
  无论是拖两端还是拖中央把手。
