## 一、先量：未登录到底能用什么（这是本批的事实基础）

冷进程（空数据目录 + 显式清空凭据）+ 匿名 WBI 签名，**一个进程只发一条请求**逐项量
（混在一个进程里量是错的：前一条的失败会波及后面，第一版就量错过）。矩阵结果：

| 功能 | 未登录 | 已登录 | 证据（2026-09-15） |
|---|---|---|---|
| 名称模糊搜 `wbi/search/type` | ✅ | ✅ | 匿名 `code=0`，20 条 |
| 账号信息 `space/wbi/acc/info` | ⚠️ 间歇 | ✅ | 一次 `code=0`，另一次 `-352 风控校验失败` |
| 粉丝数 `relation/stat` | ✅ | ✅ | 匿名 `code=0` |
| 直播状态（live 批量） | ✅ | ✅ | 匿名 `code=0` |
| **投稿列表** `arc/search` | ❌ | ✅ | 匿名 `-352` → 重复后 **HTTP 412 `request was banned`** |
| **动态流** `polymer/.../feed/space` | ❌ | ✅ | 匿名**直接** `HTTP 412 request was banned` |
| 第三方 danmakus（场次/弹幕/词云） | ✅ | ✅ | 公开接口（既有 `--upstream` 冒烟） |
| 微博 `ajax/statuses/mymblog` | ❌ | ✅（微博登录） | 匿名 `302 passport.weibo.com/visitor` |
| 本地归档（浏览/搜索/筛选/归档/日历/趋势） | ✅ | ✅ | 纯本地，零上游 |

两条关键细节：**`-412` 是 IP 级、会持续**（换新进程、隔 40 秒再打仍 412）；
**它不连累登录态**（同一时刻登录态 `arc/search` 返回 `200 / code=0 / 5 条`，已实测）。

**结论**：目标要分两半 —— "未登录用全部功能"做不到（内容抓取是平台策略，不是我们的实现），
但"本地全功能 + 轻量在线信息 + 检索"这一大块能拿到，而且**不该让用户去撞 412**。

## 二、P0：把测量变成常驻护栏

### 2.1 `scripts/capability_matrix.py`（新）

两态（`anon` / `login`）× 逐接口测量：

```powershell
python scripts/capability_matrix.py                      # 两态 × 轻量接口，打印矩阵
python scripts/capability_matrix.py --include-content    # 额外量投稿/动态（有代价，别勤跑）
python scripts/capability_matrix.py --write              # 写 tests/fixtures/capability_matrix.json
```

纪律写在脚本头里：**一个进程只发一条请求**（`--probe <name>` 子进程模式）、
冷态**显式清空凭据**、默认不量内容接口（会触发 IP 级 412）、不重试、条间 `--gap`。

### 2.2 `tests/fixtures/capability_matrix.json`（新）

真机测量快照（含 `captured_at`、每条 HTTP/code/message/条数/耗时）。它是**测量**，
`capabilities.py` 是**策略**，两者由用例双向约束（见 §三.3）。

## 三、P1：后端

### 3.1 `wbi`：匿名签名（使能件）

```python
await wbi.get_wbi_keys(allow_anonymous=True)   # nav 回 -101 但带 data.wbi_img 时照常取键
await wbi.sign_params(params, allow_anonymous=True)
wbi.wbi_status()          # {"cached": bool, "anonymous": bool|None} —— 能力矩阵/诊断用
```

匿名取到键时记一行日志；`allow_anonymous=False`（默认）**行为逐字不变** ——
抓取路径靠它继续"未登录就快速明确地失败"。启动预热改为匿名允许（未登录也能搜）。

### 3.2 `app/services/capabilities.py`（新）：能力表 + 闸门

- `FEATURES`：每条 = `id / label / platform / anon_state / anon_note / login_note / evidence`，
  三态 `full` / `degraded`（能用但完整性或稳定性打折）/ `requires_login`；
- `snapshot(bili_logged_in, weibo_logged_in)` → `GET /capabilities` 的返回：
  `features` + `limited`（前端只读这个就能渲染提示）+ `wbi` 状态 + `measured_at`；
- `content_fetch_allowed()` → `(bool, 原因)`：**内容抓取闸门**（未登录返回 False + 一句人话）；
- `weibo_available()`：沿用 devlog/079 的"微博未登录整条名单跳过"口径。

### 3.3 策略 vs 实测的**双向契约**（`tests/test_capabilities.py`）

- **R1**：实测匿名可用 ⇒ 策略**不得** `requires_login`（不许白白限制用户）；
- **R2**：全部探测被**硬拒**（HTTP 412 封禁，非 -352 软风控）⇒ 策略**必须** `requires_login`。

这样平台哪天放宽/收紧，用例会先红，逼我们重测后再改承诺，而不是让承诺悄悄失真。

### 3.4 闸门落地（未登录**不发请求**，而不是"试了失败"）

| 位置 | 行为 |
|---|---|
| `scheduler.async_fetch_posts` / `async_fetch_first_screen` | 未登录**入口即返回** `PostFetchResult(stop_reason="login_required")` |
| `scheduler._lane_skip_reason("bilibili")` | 动态流名单整条跳过（与微博名单同一套模式） |
| 5 个内容端点（`fetch-posts` / `fetch-all-posts` / `update-posts` / `batch/*`） | **403** + 原因（不再打了才知道） |
| 账号信息类端点（`/vtuber/fetch`、`/{id}/fetch`、建账号） | **不挡**（实测匿名可用） |
| `bili_search.search_users` / `exact_user` | 放行匿名签名；`exact_user` 把 tenacity 的 `RetryError` 归类为 `upstream_degraded`（"平台拒绝了本次查询"），**不再冒充签名故障** |
