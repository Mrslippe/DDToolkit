# 171-20260924-R38 批 4：文案切换可打断（keyframes 重放 → transition 重定向）

> 规格这一批只给了一句话，**时序值在 §3 规则 2 里有**（"离场比入场快 80–100ms"）——
> 所以不用发明值，但**状态机要自己设计**（规格没给）。

## 一、它解决什么

`.si-text` 原来挂 **`key={text}`** ⇒ 文案一变 React 就**重挂载**那个 span ⇒ CSS
`@keyframes pill-fade-in` **从头重放**（先 `opacity:0` 停 `--motion-lag` 60ms，再淡入 140ms）。

**连续换字时每次都会闪一下** —— 因为每次都是"从 0 重新开始"。

改成：元素**保持挂载**、用 **transition** 驱动。
**transition 的固有性质是"可重定向"**（从当前值继续），而 keyframes 只会重启 ——
这就是规格那句话的全部意思。

## 二、规格补充：三条本批实测得出的结论（原文没有）

**① 两相就够，不需要单独的 `in` 相。**
CSS 过渡取的是**变化后**那一边的 `transition-duration`：
- 进 `.is-out`（撤）⇒ 用 `out` 的 `--motion-instant`(90ms)
- 回 `idle`（入）⇒ 用基态的 `--motion-fast`(140ms) + `--motion-lag`(60ms)

所以 §3 规则 2「**离场比入场快 80–100ms**」是**免费**的，不需要为"入"单独建相。

**② "入"的时长不需要新令牌。** §3 规则 2 给的 80–100ms 正好落在 `--motion-instant`(90ms) 上。

**③ 决策抽成纯函数** `utils/statusIslandText.ts`（`reduceText` + **9 条 vitest**）。
理由与 `utils/sceneStep.ts` 同：本仓 vitest 跑 **node 环境**（无 jsdom），**hook 测不了** ——
而"连续换字**不重放、不排队**"必须有单测。

## 三、⚠️ hook 侧的反直觉点（最容易写错的地方）

那条驱动状态机的 effect **故意不返回 cleanup**：

```tsx
useEffect(() => {
  const step = reduceText(textRef.current, text, false)
  if (step.state !== textRef.current) setTextState(step.state)
  if (step.scheduleMs == null) return
  // ⚠️ 故意不返回 cleanup —— 见下
  textTimer.current = window.setTimeout(() => { ... }, step.scheduleMs)
}, [text])
```

**为什么**：定时器属于"**撤**"这个**阶段**，不属于某一次 `text` 变化。
若返回 cleanup，"打断"（text 又变 ⇒ effect 重跑 ⇒ cleanup 执行）会**把定时器清掉**
⇒ 文案**永远换不过去** —— 而"打断不重排"正是本批要保住的性质。

卸载时的清理由**另一条** effect 负责（`useEffect(() => () => clear(), [])`）。

## 四、护栏：批 1 那条判据**抓到了这次改动**

批 1 断言「文案**动画**时长 == `--motion-fast`」（读 `animationDuration`）。
本批改成 transition 后它读到 **0ms 并报红**：

```
- @1100 status-island: 胶囊文案淡入时长是 0ms，应等于 --motion-fast（140ms）
```

**这是护栏在正确地工作** —— 它逼我把判据一起换掉，而不是让"文案没动画了"悄悄过去。

判据换成三条：① `animation-name` 必须是 `none`（还挂 keyframes 就红）；
② `transition-duration` == `--motion-fast`；③ `transition-property` 含 `opacity`。
**反向验证过**（写回 `pill-fade-in 0.5s` ⇒ 两条同时报）。
