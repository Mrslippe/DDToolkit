# 432-20261007-单推唤出改成事件委托 + 状态

同一天的后续：用户看了真机截图报三条。

> 1. 顶栏和左侧工具栏的 hover 触发宽度都加宽到它们自身的宽度
> 2. 如图，**左侧工具栏没有唤出**
> 3. 我希望界面元素透明度**降到 0**，鼠标 hover 到触发区域的时候才恢复

## 第 2 条是真 bug：`:hover` 兄弟选择器方案在真机上不成立

`devlog/430` 那版是**纯 CSS**：贴边窄带 `~` 被唤出的元素。它在纸面上说得通，实际上
**鼠标一从窄带移到唤出来的工具栏上，就掉出 hover** —— 因为唤出来的工具栏是**另一个元素**、
而且压在窄带**上面**，指针此刻既不在窄带上、也不在（`~` 关系里的）同一个 hover 目标里。
症状正是"左侧唤不出来"。而且 jsdom 没有 hover ⇒ **这条路径在单测里根本不可见**，
当初只有"规则在不在"的字符串判据 ⇒ 假绿。

**改法**：窄带**与它唤出的元素**算**同一个区**，用一个状态表示：
- `utils/soloMode.ts` 新增纯函数 `peekZone(el)`：`.topbar`/`.solo-hover-top` ⇒ `top`，
  `.icon-rail`/`.solo-hover-left` ⇒ `left`，其余 `none`；
- `App.tsx` 在 `.app-shell` 上做**事件委托**（`onPointerOver` / `onPointerOut` 用 `relatedTarget`
  重算），把结果挂成 `data-peek`；
- CSS 只认 `[data-peek='top'|'left']` ⇒ 位移归零、`transition-delay` 也归零。
⇒ **能单测**（dispatch 指针事件即可）、也能照着推理；退出单推顺手清掉唤出态。

## 另两条（用户口径）

- **触发区加宽到元素自身**：`.solo-hover-top { height: var(--topbar-height) }`、
  `.solo-hover-left { width: var(--rail-width) }` —— 悬在"那一整片区域"就唤出。
  ⚠️ 副作用：单推时内容区顶部那一条 / 左侧那一竖条成了死区 —— 但此时内容本来就被淡到 0
  （见下），点它没有意义，可以接受。
  ⚠️ 唤出期间窄带必须 `pointer-events: none` **让位**，否则顶栏那些按钮（账号切换器、通知、
  窗口控制）全被窄带挡住点不着。
- **透明度降到 0**：`--solo-dim: 0 → 0.12`（用户口径"降到 0，hover 到触发区域才恢复"）。

## 判据（净 +3）

`peekZone` **2 条**（★窄带与被唤出的元素**算同一个区** —— 含"元素里面的子节点也算"；
其余地方一律 `none`，别因为划过内容就把顶栏叫出来）+
CSS 契约 **5 → 6**（★淡到 **0**、窄带尺寸 = `var(--topbar-height)`/`var(--rail-width)`、
唤出**走 `data-peek`**、且**明令不许退回 `:hover` 兄弟选择器**、唤出期间窄带让位）。

**反向验证**（三组，各自确认"改到了"）：顶栏不算唤出区 ⇒ `peekZone` 那条红；
透明度退回 0.12 ⇒ 那条红；触发区退回 10px ⇒ 那条红。
