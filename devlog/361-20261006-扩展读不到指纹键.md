# 361-20261006-扩展读不到指纹键（小红书缺 a1 / 抖音缺 s_v_web_id）

> 用户（附扩展 popup 截图）：小红书 4 个键「缺 a1」、抖音 24 个键「缺 s_v_web_id」，
> 两行的「同步」都是灰的，而**这两个平台在浏览器里明明登录着**。

## 一、真因：**一个 URL 读不全**

E4 的 `logic.js` 每个平台只配了**一个** `url`，popup 用 `chrome.cookies.getAll({url})` 读。
而 `getAll({url})` 只返回"浏览器**会发给那一个 URL** 的那些 cookie" ——
指纹键常常不在那一条上：

- 小红书：`a1` 是**签名强制输入**（缺了直接 `Missing 'a1' in cookies`），
  而主力业务网关是 `edith.xiaohongshu.com`（`docs/design/xhs-douyin-research.md` §2.1）——
  只读 `www.xiaohongshu.com/explore` 就漏了；
- 抖音：`s_v_web_id` 要同时充当 `verifyFp`/`fp`，页面 JS 在别的 host/path 上铸它，
  `/` 这一条读不到。

⇒ 这不是"用户没登录"，是**我的 URL 表拍窄了**（E4 里那张表是按"最像请求头"选的，
没有实测过；方案里也没把这一条列成"P1 第一件实测"）。

## 二、修法：三趟取并集

`readCookie()` 现在按顺序读三趟，`mergeCookies()` 按 `name + path + domain` 去重（**先到的赢**）：

1. **一组 URL**：每平台 2–3 条（主站 + API 网关 + 首页）。小红书加了
   `edith.xiaohongshu.com/`，抖音加了 `/discover` 与 `/user/self`；
2. **域扫描** `getAll({domain})`：覆盖子域与别的 path（这是"抄整条 Cookie"的近似）；
3. **分区 cookie 兜底**：只在"还缺必需键"时才跑 —— Chrome 默认**不返回 CHIPS 分区 cookie**，
   而第三方嵌入的指纹 cookie 正好可能是分区的。`partitionKey.topLevelSite` 要的是**站点**
   （scheme + 可注册域，API 主机的 origin 不是站点）⇒ 两种写法都试；不认识这个字段的 Chrome
   会抛，`try/catch` 跳过。

顺带修一处**判据分叉**：扩展原来按**原样大小写**比键名，而后端 `douyin_auth.cookie_keys()`
是 `lower()` 之后比的（`REQUIRED_ANY` 里写的还是小写 `uifid_temp`）⇒ 会出现
"扩展说缺、后端其实认"的**假灰按钮**。现在扩展也统一小写比（显示仍用扩展侧规范拼写）。

## 三、诊断（这次真正解决问题的东西）

popup 的「设置」里新增 **「诊断：这次读到了哪些 cookie」**：每个平台逐条列出
`name @ domain path` + 标志（`HttpOnly`/`会话`/`分区`）——**只有键名与出处，没有任何值**
（`describeCookie()`，有用例钉着"不许带值"）。另有「**重新读一次 cookie**」按钮
（在别处刚登录完不用重开 popup）。

判据：`extension/test/logic.test.mjs` 18 条（新增：多趟读的并集与去重、**每平台至少两个 URL
且 URL 必须落在自己的 `domain` 下**、小红书必须含 `edith`、大小写不敏感、诊断行不带值）。
其中"只读一个 URL 会漏指纹键"那条**就是这次用户现场的形状**，改回单 URL 即红。
