# 426-20261007-V1d1视频取景与图片取景分开（数据与契约）

用户口径（2026-10-07）：「**视频的取景和图片的取景分开**，用一个按钮进行切换，预览用视频首帧」。
本批只做**数据与契约**那一半（前端切换按钮与首帧预览是 V1d-2）。

## 为什么另开一列（而不是塞进同一个 JSON）

`background_focus` 现在是 `{"x","y","scale"}`。把它改成嵌套的 `{"image":…,"video":…}` 看起来更省事，
但**已经存下来的那批值会突然换个读法** —— 新代码得靠"顶层有没有 `x`"来猜它是谁的，猜错就是
**静默换构图**（用户看到的是"背景自己挪了"，没有任何报错）。而且"一个东西一列"在本表已先例：
`background_path` / `background_video_path`（`f011`）。⇒ **`f012` 加一列 `background_video_focus`**，
形状与语义与图片那份**逐字相同**，契约与文档都不用写兼容分支。

## 改了什么

- 迁移 `f012`：`vtubers.background_video_focus` TEXT NULL（`MIGRATION_HEAD` → `f012`）。
- `models/vtuber.py`、`schemas/vtuber.py`（`VTuberOut.background_video_focus`，同样是 **JSON 原文**）。
- 路由 `PUT/DELETE /vtuber/{id}/background-video-focus`：请求体**复用** `BackgroundFocusIn`
  （同一个模型 ⇒ 同样的 0..1 / 1..3 与 422，不各写一套边界）。
- 命名沿用既有不对称：`/background` = 图、`/background-video` = 视频 ⇒
  `/background-focus` = 图的取景、`/background-video-focus` = 视频的取景。
- 头部连锁：`app/main.py` 的 `MIGRATION_HEAD`、`tests/test_runtime_settings.py` 的硬编码、
  `README.md`（版本数）、`docs/GLOSSARY.md`、`.dsh/.../change-recipes.md`（两处"当前 head"）。

## 判据（3 条，`tests/test_background_upload.py`）

★**两份互不相干**（存一份不动另一份、清一份不动另一份 —— ⚠️ 四条"没碰它"断言**每条都配正对照**：
两边都先真的存上值，否则"没碰"与"顺手清成 None"分不出来，`devlog/417` 的同一个坑）·
与图片那条**同一个模型**（同样的 422 / 404；边界值 0/1 与 1/3 合法）·
传新视频**不重置**取景（与"换图不丢取景"同口径；要清是「重置取景」的事）。

**反向验证**（三组，都确认替换真的生效）：清视频取景顺手清图片取景 ⇒ 独立性那条红；
视频取景写进图片那一列 ⇒ 2 条红；换视频顺手清取景 ⇒ reupload 那条红。

## 顺手记一个自己的错

新用例的辅助函数写成 `f"/vtuber/{vid}/background-{suffix}-focus"` 而调用方传 `"background"`
⇒ 拼出 `/background-background-focus`，**全程 404** —— 报错长得像"路由没接上"，
其实是拼串错了。改成传 `image` / `video` 两个词，并在 docstring 里写明这个坑。
