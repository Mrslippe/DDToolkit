# 346-20261005 dev 壳没给后端 dev token：应用窗口里那几条推送类别 404

> 用户实测：「开播告警注入项点击之后没有反应，log 显示发布失败，HTTP 404」。
> 查清了，**不是通知功能的问题，也不是调测页的问题** —— 是 `npm run tauri:dev` 起的
> **dev 壳从来没给后端那个环境变量**，于是 dev-only 的合成钩子**根本没挂进路由表**。

## 一、根因：dev-only 钩子按 `DEV_API_TOKEN` 把关，而壳没设它

`POST /messages/_debug/publish` 只在 `routers/messages.include_debug_routes()` 里挂载，
而那道门是 `dev_mode()`：

```python
def dev_mode() -> bool:
    """只有 `DEV_API_TOKEN` 非空才算。"""
    return bool((getattr(settings, "DEV_API_TOKEN", "") or "").strip())
```

三个起后端的调用方里，**两个给了、一个没给**：

| 谁起后端 | 给 `DDTOOLKIT_DEV_API_TOKEN` 吗 |
|---|---|
| `scripts/ui_probe.py`（探针） | ✅ `be_env` 里显式给（`PROBE_DEV_TOKEN`） |
| `dev_check.py` / 其他脚本 | ✅ `**dev_token.backend_env()` |
| **`frontend/src-tauri/src/lib.rs`（dev 壳）** | ❌ **只给了 `DDTOOLKIT_API_TOKEN`** |

⇒ 症状的分工非常阴：**探针里那条路永远绿**（它自己设了变量），**只有人的应用窗口里坏** ——
而"应用窗口里那几条走推送的类别"正好是 ④⑤⑥⑪（进度/开播/回执）。

这与 `scripts/dev_token.py` 开头那条教训是**同一类第四次**：
> S1 给后端加了门禁之后，**开发态打自己后端的调用方逐个失效**，而它们失效的样子非常不像"门禁问题"。

## 二、真机验证（两个方向都做了，不是推理）

写了个临时脚本，起一个后端（临时数据目录、随机端口），**照 dev 壳的形态注入 `DDTOOLKIT_API_TOKEN`**
（所以那一发会过鉴权、落到路由表上），只改 `DDTOOLKIT_DEV_API_TOKEN` 一位：

```
MODE=without  status=404  body={"detail":"Not Found"}
MODE=with     status=200  body={"status":"published","seq":1}
```

⚠️ 第一版验证脚本没注入 `API_TOKEN`，得到的是 **401**（缺少访问令牌）——那是**另一种**形态，
不能拿它当"复现了 404"。（用户的机器上壳一定注入了 API_TOKEN，所以是 404。）
**"复现"必须复现到同一个症状**，这一点值得单独记：401 与 404 在"这条钩子没挂"这件事上
指向完全不同的原因（前者是鉴权、后者是路由）。

## 三、修法与判据

`lib.rs` 的 debug 分支补一行（并与前端那份**同值**）：

```rust
.env("DDTOOLKIT_DEV_API_TOKEN", DEV_API_TOKEN)   // const = "dsh-ui-probe-dev-token"
```

- 只在 `#[cfg(debug_assertions)]` 那一块（本块就是 dev 分支）⇒ 发布版**没有这一段**，
  生产依旧不挂那条钩子（`tests/test_messages.py` 的 `include_debug_routes(prod) is False` 照旧）；
- 值同源：`const DEV_API_TOKEN` 与 `scripts/dev_token.py::DEV_TOKEN`、`vite.config.ts` 的
  define 默认值、`api.ts` 的 fallback **四处同值**。

**补了判据**（`tests/test_dev_token.py::test_desktop_dev_shell_passes_the_dev_token_too`）：
壳里必须真的出现 `.env("<ENV>", …)`，且那个常量的值 == `dev_token.DEV_TOKEN`。
反向验证：删掉 `lib.rs` 里那一行 ⇒ 红。
> 这条判据欠了很久：本文件原来的扫描面只有 `scripts/*.py`，**壳不在里面** ——
> 而"谁起后端"这个问题，壳是第四个答案。加了门禁就要把**所有**调用方过一遍（第四次了）。

## 四、⚠️ 顺带：`VITE_NOTICE_LAB` 那个开关会**漏进探针**（同一批修掉）

补完上面那条之后跑 A 档，`ui_probe` 在三档宽度上报了一整片
`原创容器 DIV.nl-panel nativeBar=12x0` —— 因为**用户在 `frontend/.env.local` 里开着
`VITE_NOTICE_LAB=1`**（我上一轮让他这么做的），而探针跑的是**同一个 Vite**
⇒ 调测页的面板出现在了**每一个**探针模式里，而它按设计是个可滚面板（`overflow-y:auto`）。

修法与 `#problem-report` **完全同款**：探针的滚动容器清单把 `#notice-lab-host` 也排除掉 ——
口径一致：**诊断/调测工具不是被测界面**。（.env.local 是本地文件，探针读不到"它存不存在"，
所以从"排除"这一侧修才是稳的。）

> ⚠️ 这又是一次"**判据抓到了我自己的改动**"：本批两处红（`nl-panel` 溢出、以及前面
> `pillGroup` 那次）都不是产品坏了。区别在于这次**真的是 bug**（工具污染了被测面），
> 而修法要落在"谁能进判据面"上，不是放宽阈值。
