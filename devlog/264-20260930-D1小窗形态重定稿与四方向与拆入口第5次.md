## 一、判据先行：先在小窗**自己的坐标系**里量一次，红 11 条

动手前先给 `ui_probe --status-widget` 加判据（这一批的新判据全在**第二段** = `widget.html` 本身），
在**未改代码**的现场跑一遍 —— 红 11 条，其中 5 条是**从没被人量过**的：

```
解剖：display='block' 圆角=0 字号=16 max-width='none'
      变量：--widget-cap-min-w='' --widget-cap-max-w='' --widget-radius='' --widget-panel-w=''
点=[0, 24] 底色='rgba(0, 0, 0, 0)' ｜ 字形=None 活数据=None 计数=None chevron=[24, 24]
```

**这就是「拆入口顺带生效的东西」的第 5 次**（`DEV-LOOP.md` §6.1，前四次：Tailwind preflight 的
`box-sizing` · `layout.css` 的 `.os-*` · `main.tsx` 的 `setApiBase` · dev token）：
胶囊的**解剖**（`display:flex` / `gap` / `border-radius` / 字号）和**点的 7×7** 只写在
`layout.css` 的 `.topbar-status*` 里，而 `widgetMain.tsx` **只加载 `tokens.css` + `status-island.css`**
⇒ 真窗口里胶囊是**方角 + 非 flex 行**、字号 16、**点 0×0（紧迫度这个通道整个看不见）**。

**为什么五次探针全绿**（这次的教训与前面四次不同）：`--status-widget` 有两段，第一段跑
`index.html?density=widget` —— 那是**主窗口**，它加载 `layout.css` ⇒ 解剖在那里当然是对的。
**判据的坐标系错了**（§6.5）。⇒ **"漏了东西"和"漏了坐标系"会互相掩护**：只要有一条判据在
错的地方量，前者永远不会红。

**修法**：两个宿主都要的声明**搬家**（不是抄）到共用文件 —— `.topbar-status` 的解剖
→ `.si-island`，`.topbar-status-dot*` → `.si-dot*`，`status-pulse` 与 reduce 段一起搬。
`layout.css` 里只留**顶栏宿主特有**的四条（绝对定位 / 水平居中 / `max-width: 46%` / 顶栏胶囊高）。

## 二、宽度：方案 A 的正确实现是**让 CSS 自己量**，不是 JS 逐帧算

09-27 的口径是"胶囊宽 = 实测文字宽，夹在 200–400，**超 400 才省略号**"。
我没有用"JS 量文字宽 + 逐个槽位加余量"（样例页是那么写的：`CAP_PAD*2 + 点 + 字形 + 活数据 + 计数 + chevron + 6`）——
那套**必须与 CSS 的 padding/gap 逐项对齐**，任何一边改了就会"读数 300、渲染 360"（样例页自己记过这个不自洽）。
改成 CSS 侧一次说清：

```css
.si-island[data-density='widget'] {
  width: calc-size(max-content, size);          /* 内容宽 + 可过渡 */
  min-width: var(--widget-cap-min-w, 200px);
  max-width: var(--widget-cap-max-w, 400px);    /* 只有超上限才 ellipsis */
}
```

`.si-text` 已有 `min-width:0; overflow:hidden; text-overflow:ellipsis` ⇒ 上限之内**不省**、超了才省，
与样例页的行为一致，而"量宽"这件事**只有一个实现**（浏览器）。
JS 只负责**读** `offsetWidth` 去调窗口大小（`ResizeObserver`，保持胶囊中心）。

⚠️ **它不自指**：`max-content` 的宽**与容器宽无关** ⇒ "改窗口 → 胶囊变宽 → 又改窗口"这条回路不存在。
`widgetPanelMaxHeight` 那条注释记过三次"按窗口算"的循环（`vh` → `innerHeight` → …），
这是**躲开它的办法**：让被量的东西不受结果影响。

## 三、数字的单一真源：TS 常量 → CSS 变量 → 探针量"两个值相等"

`d1-form-options.md` §6 早就点过名：宽度同时写在 `status-island.css`、`widgetWindow.ts`、
`lib.rs const W/H` 三处 ⇒ 只改一两处时**单测和探针都会绿**，而真机上窗口正在裁胶囊。
这一批把它收成一个来源：

| 层 | 角色 |
|---|---|
| `utils/widgetWindow.ts` | **唯一的数字来源**（200 / 400 / 40 / 20 / 6 / 8） |
| `applyWidgetCssVars()` | 写进 `--widget-cap-min-w` / `-max-w` / `--widget-radius` / `--widget-panel-w` / `--widget-cap-h` |
| CSS | 只 `var(…, 兜底同值)` |
| 探针 | 断言**解析值 == 变量值**（不只是"== 400"）—— 后者在两处各写一遍、值凑巧相同时也绿 |

Rust 侧那 200×40 保留为**首帧下限**（内容要等页面渲染完才知道），由前端的 `ResizeObserver` 纠正；
`resize_widget_window` 的调用改成**只递四个数**（几何对象现在带 `dir`/`align`/`capOffset` 给 CSS 与探针用，
整包转发就变成"靠 serde 忽略未知字段"工作）。

## 四、四方向：方向与"胶囊在窗口里的偏移"必须**一起**由几何给

规格上四方向是"朝屏幕里侧长"，实现上它落到三条不变量（都在 `widgetExpandGeom` 里，67 条单测）：

1. **近边恒等**：窗口贴住胶囊的那条边展开前后**同一个值**（向下 ⇒ 顶边、向上 ⇒ 底边）。
   样例页 CDP 实测过反例（卡片整体离开屏边 `jumpY = +46 = 40 + 6`），用户报的"和边缘拉开"就是它。
2. **判据是"装不装得下"，不是"在哪一半"**：按中线劈半会把**正中央**判成"向上 + 向左"
   （`0.5 < 0.5` 为 false），用户截图正是"胶囊在屏幕正中、面板却往左上长"。
   水平侧的"只在边缘才反向"由**夹取**天然给出：先试居中、居中出屏才贴边
   （可证：居中是"贴左"与"贴右"两个候选的**区间中点** ⇒ 两侧都放得下时居中必然也放得下，
   所以这个顺序不必来回比较）。
3. **锚点 = 胶囊所在的角**：方向定了，胶囊在窗口里贴哪一边也就定了 ⇒
   `capOffsetX` / `capOffsetY` 由几何算出来写进 CSS 变量。**这是批 5g 那条教训的横向版**：
   一旦"胶囊在窗口里的位置"有两个主人，就会出现"面板在一处、胶囊在另一处"。
   实际改掉的旧写法是 `.widget-shell` 的 `justify-content: center`（面板向左长时它把胶囊按回中间）
   ⇒ 换成 `flex-start` + `margin-left: var(--widget-capsule-x)`，两条轴都是单一来源。

`StatusIsland.place()` 也跟着收敛：小窗真窗口宿主下面板**铺满窗口**（`left=0`，宽 = `WIDGET_PANEL_W`），
方向只读几何写下的 `data-dir`（原 `data-flip` 只有上/下两态）。
⚠️ 宽取**常量**而不是 `window.innerWidth`：resize 还没落地的那一帧会量到更窄的视口 ⇒ 内容重排版
⇒ 面板高变 ⇒ 窗口高度按错的高算完就再也不改了（`place()` 不会因为窗口 resize 再跑）。

## 五、内容契约：字形是**修缺陷**，不是装饰

`report` 与 `message` 的点色在产品里判定**相同**（`progress→busy / alert→warn / 其余→ok`），
而胶囊原先**根本不渲染图标**（`KIND_ICON` 只在面板用）⇒ "全量抓取完成"与"已复制诊断信息"
在胶囊上**长得一模一样**。现在：**点色 = 紧迫度**、**字形 = 类型**（`KIND_GLYPH`，单测钉"两两不同"），
外加活数据槽（`Notice.value` 单独一格 ⇒ 倒计时每秒刷新不再重写整句）。

⚠️ **字形用文本字符而不是 lucide 图标**：小窗不加载 Tailwind，`size-[12px]` 这类类名在那里**无效**
—— 探针在小窗坐标系里实测到 `chevron=[24,24]`（比半个胶囊还高）、面板条目图标也是 24×24。
所以这两处改成在 `status-island.css` 里写死尺寸（同属"共用文件必须自包含"）。

⚠️ **小窗宿主的点色不能照抄顶栏的白点**：顶栏 `.si-dot.ok` 是白色，那是"深玫瑰底上的成功色"；
小窗是浮在壁纸上的深色卡片，白色在那里没有语义 ⇒ 小窗里 `ok` 改回绿（判据：探针量小窗里的点色）。

## 六、默认落点：角落到"顶部居中 + 80px"不只是审美

旧落点是**右下角**（1080p 上 `y=968`），向下展开需要 `968+40+6+面板高` ⇒ **任何面板高度都放不下**
⇒ 小窗一起手就**只能向上翻**。一个"默认就在角落"的落点会让四方向逻辑的第一印象永远是特例。
改成顶部居中 + 80px 之后，默认就是真的向下（单测钉住这条）。

## 七、顺带修掉的一条：探针找不到"现场"了
第一次跑探针直接 `[FAIL] 未找到开发数据目录 …\com.ddtoolkit.app-dev（先跑一次 dev 应用）`，
而**用户明明跑过** —— 他用应用内的「迁移数据目录」把 dev 数据搬到了 `E:\test\DDToolkit-data`
（指针文件 `%APPDATA%\DDToolkit\data-dir.txt`，机制见 `datadir.rs`），而 `ui_probe.py` 里那个路径是**写死的**。
⇒ 解析口径改成与壳逐条一致：**环境变量 > 迁移指针 > 默认目录**（指针坏了回退并打印原因），
并在报告里打一行"这一轮量的是谁的现场"。
**判据的现场比判据本身更容易陈腐** —— 这条上一批（devlog/263 §三）刚写过一次，这次换了个形态又来一遍。

## 七之二、同一个坑的第 6 次：字体族（收尾时用户问"形态定下来了吗"才发现的）

收尾时用户问了一句「小窗的基础形态已经完全定下来了吗」。**去查而不是去答**，当场发现同一类问题还漏了一处：
全站的 `font-family: var(--font-family)` 写在 **`layout.css` 的 `body`** 上，而小窗的独立入口不加载那个文件
⇒ 真窗口里胶囊与面板用的是 **WebView2 的默认字体**（探针在小窗坐标系里实测 `"Noto Sans SC"`，
而顶栏宿主是 `"Alimama FangYuanTi VF", …`）。顺带暴露一处浪费：`@font-face` 在 `tokens.css` 里，
小窗**下载了字体却没人用**。

**为什么之前 11 条解剖判据没抓到**：那些判据量的是 `display` / `border-radius` / `font-size` / 点的盒子 ——
**字号对完全推不出字体对**。这正是"判据只覆盖它写下来的那些量"的老实话。

**修法**：在共用文件里给两处材质自己声明字体 —— `.si-island`（胶囊）与 `.si-panel`
（⚠️ 面板是 **portal 到 `body`** 的，既不继承胶囊、也不在 `.widget-shell` 里，所以两处都要写）。
**判据成对写**：顶栏宿主那条是**正对照**（它在 `body` 的继承链上，必然成立）⇒ 小窗那条红了就只能是入口差异，
不必再论证"胶囊本来就该用全站字体"。

  **report ≠ message** 就是那个缺陷的判据）；
- `frontend/src-tauri/src/lib.rs`：注释与日志更新（首帧尺寸 = 下限），命令集不变（ACL 用例不动）；
- 探针 `--status-widget`：第二段新增 **12** 条（解剖 / **字体族** / 变量同源 / 点 / 字形 / 活数据 / chevron /
  面板图标 / 面板宽 / `data-dir` 默认值），第一段的尺寸断言从 `== [200,40]` 改成**区间 + 上限**，
  新增圆角/变量三条；`--status-island` 新增两条（**字形**、**字体族正对照**）；
  窄视口那一段的视口宽 200 → 400（D1 起真窗口宽 ≥ 400）。
- 反向验证（**做过、逐条记下真实报错**，还原后 sha256 逐字节相同）：
  1. `applyWidgetCssVars` 把 `--widget-cap-max-w` 写成 `300px` ⇒ 报「`--widget-cap-max-w` 是
     '300px'，应为 400px（TS 常量写进变量）」，**且探针量到的解析值 `max-width` 也真的变成 300px**
     —— 后半句才是关键：它证明 **CSS 读的确实是那个变量**（不是自己另写了一份）；
     ⚠️ 如实记：「胶囊宽越过 400 上限」那条**没报**（300 宽的胶囊仍落在 200–400 区间里）——
     它守的是"上限失效"，与"变量不同源"是两条不同的判据。
  2. `.widget-shell` 的 `justify-content` 改回 `center` ⇒ 报「胶囊左缘离窗口左缘 **438px**，应为 0」；
  3. 方向判定改成"按中线劈半"（用户 2026-09-27 报的那个错法）⇒ `widgetWindow.test.ts` 当场红：
     「expected 'up' to be 'down'」，且**只红那一条**（正中那个用例）；
  4. 去掉胶囊的字形渲染 ⇒ `--status-island` 报「亮起后胶囊上没有类型字形（量到 None，
     瞬时消息是 message ⇒ 应为 '✦'）」。⚠️ 这条**只在小窗坐标系之外又验了一次**（顶栏宿主）：
     小窗那一条测的是同一个 JSX 分支与同一个探针字段，但**它的红是在本条之后才补的** ——
     如实标注：小窗侧的"字形缺席"是靠顶栏这条同源推导的，不是单独变异出来的。
  5. 字体族那两条判据**没有单独做变异**：`status-island.css` 里那句 `font-family` 的"红"是
     **修复前实测到的**（`"Noto Sans SC"`），修复后变 Alimama —— 一次真实的红→绿就是它的牙齿。
