# 487-20261014 滑杆改成浅灰底无描边 + 滑杆下方给图文混排示例

> 用户口径（接着 `devlog/486` 那根滑杆）：「滑杆样式改为浅灰底无描边，和项目风格对齐，
> 同时在下方给出图文混排的示例方便用户观察」。
>
> 起因是他截图里那根滑杆**还是原生的深灰轨 + 描边** —— 那是浏览器默认外观，跟这套浅色界面不搭。

## 一、滑杆自绘（浅灰底、无描边、主色圆钮）

`accent-color` 只能染原生的那张脸，救不了"深灰轨 + 描边"。改成**自绘**，
与播放器音量滑杆（`.vp-vol`）同一套路数（`appearance:none` + 轨道/钮分开画），
配色换成浅色界面的令牌：

| 部件 | 取值 | 为什么 |
|---|---|---|
| 轨道 | `var(--pill-bg-hover)`（#eef1f5）· 6px · 圆角 999px · **`border:0`** | "浅灰底无描边"；用**已有令牌**而不是新写色值 |
| 圆钮 | `var(--c-primary)`（#ffa2b4）· 16px · 实心 · `box-shadow: 0 1px 3px rgba(0,0,0,.18)` | 与**同一页**的 `.aps-radio.on` 同一个粉、同一族的软投影 |
| 焦点 | `:focus-visible` 自绘 2px 主色环 | 上面把原生 `outline` 关了，键盘走到这儿必须看得见（不然就是一个无障碍窟窿） |

⚠️ webkit 与 moz 两套伪元素都写了（`::-webkit-slider-runnable-track/-thumb` +
`::-moz-range-track/-thumb`）；`margin-top: -5px` 是给钮在 18px 高的控件里跟 6px 轨道垂直居中用的。

## 二、示例：滑杆下方直接看图文混排

新增 `GET /emoji/sample`：从**已经热好的第一源索引**里挑**一大一小**两枚真表情
（纯内存、不出网、不扫库）。三条口径：

1. **必须是真表情**：尺寸不一样、图本身也不一样（官方小脸 vs 贴纸）—— 拿占位图调出来的手感是假的；
2. **确定性**（名字排序后取第一枚）：每次打开设置看到同一对，用户才能"上次调到 40 是这个效果"地复现；
3. 索引没热上/取不到 ⇒ 给 `null` ⇒ 界面**不显示**示例（宁可不显示，也不画一个空框）。

前端拿到之后**先塞进表情缓存**（`PostText.tsx` 新增 `seedEmojiCache()`）再渲染：
这样示例与正文走**同一条渲染路** —— ProxyImage 的 https 化/no-referrer/兜底、`size` 分档、
chip 兜底全都一致，示例才代表真实效果；顺带省掉一次 `/emoji/resolve`
（`fetchNames` 本来就会跳过已在缓存里的名字，用例钉住了这一点）。

## 三、判据

- pytest **+2 → 1471**：★`/emoji/sample` 两类各挑一枚 + **跳过没地址的** + 确定性；
  ★索引冷 ⇒ 两个字段都 `null`（界面据此不显示示例）。
- vitest **+4 → 1465**：★示例用真表情画出来且**分档正确**（`size=2` 那枚带 `--big`）+
  走了 `no-referrer`（与正文同一条渲染路）；★**预置过缓存就不再发 resolve 请求**；
  ★后端给 `null` ⇒ 不显示示例；★取示例失败 ⇒ 不显示示例但**滑杆照旧可用**。
- 真样式表 + 真浏览器量过（顺带给用户看截图）：`input` 的 `border-width=0px`、
  `appearance=none`；示例里小表情 15px / 大表情 40px（滑到 64 时 64px）。

## 四、留给下次

- 示例文案是固定的那句（「今天的直播…谢谢大家…下次见啦…」）—— 只为让两枚表情落在**一句话中间**，
  便于看行距；换成真实帖子文本没有额外价值（真帖子在详情页就能看）。
- `/emoji/sample` 只从**第一源**挑（离线那级）。第二源（上游整表）里也有表情，但它是按需拉的 ——
  为了一个示例去出网不划算，将来真要再说。
