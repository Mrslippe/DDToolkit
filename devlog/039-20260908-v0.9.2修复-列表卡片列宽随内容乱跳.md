# 039-20260908-v0.9.2 修复-列表卡片列宽随内容乱跳（OverlayScroll 插层）

> 用户 2026-09-08 截图反馈：右栏帖子「宽度不对，就投稿这个分类有问题，有的宽有的窄」。
> 两张截图同一版本同一窗口宽度：七海投稿页卡片被撑到窗口外（封面只剩一条竖边、
> 日期看不见），菜菜子投稿页卡片却缩窄居中留大片空白。

## 一、结论先说：列宽退化成「内容宽度」

`.list-scroll > .list-inner` 这条规则**自 2026-09-07 滚动条迁移起就静默失效**：
`OverlayScroll` 会在 `.list-scroll`（`.os-root`）内部再插一层 `.os-scroll`，
`.list-inner` 不再是直系子元素，于是

```css
.list-scroll > .list-inner { width:100%; max-width:900px; align-items:stretch }
```

整条不生效。`.list-inner` 退化为 `.os-scroll`（`display:flex; align-items:center`）
的普通 flex 项目，宽度变成 **fit-content = min(max-content, max(min-content, 可用宽))**，
也就是「这页内容有多宽，列表就多宽」：

| 页面内容 | 列宽 | 观感 |
|---|---|---|
| 短标题、无长串（菜菜子投稿首页） | 566px | 缩窄 + 居中，左右各留 ~188px 空白 |
| 含长不可断行串（七海投稿页） | 1350px | 居中溢出，封面被左缘裁成一条、日期推出窗口 |
| 摘要很长（图文/全部） | 900~940（被可用宽夹住） | 「看起来正常」——这就是为什么只有投稿页露馅 |

## 二、长串从哪来（真机定位）

用真实数据（开发数据目录副本）+ 无头 Edge CDP 复跑，逐卡片量「固有最小宽度」
（克隆到 `width:min-content` 容器里量）：

- 七海投稿第 12 张卡：标题 `汪啊！！！！！！！！…`（约 30 个全角感叹号）——
  CSS 断行规则不允许在连续 `！` 之间断行，`titleMin = 1106px` → `cardMin = 1350px`；
- 同页多条帖子的摘要是 150 字符的 `https://www.bilibili.com/h5/mall/...` 长链接
  （B 站投稿简介常见），同样撑出上千像素；
- `.post-grid` 是 column flex + `align-items:stretch`，**一张卡宽 → 整列同宽**，
  所以「一条帖子有病，整页卡片全歪」。

修复前的实测：`.list-inner` `[337..1687]`（窗口才 1482 宽）、`maxW=none`、`align=normal`、
20 张卡全部 1350px、封面起点 x=337（右栏左缘在 542）。

## 三、修复（四处，都在 `frontend/src/styles/posts.css`）

1. **列宽契约**（根因）：`.list-scroll > .list-inner` → `.list-scroll .list-inner`。
   注释里写明「必须是后代选择器 + OverlayScroll 会插层」，防止再犯。
2. **`.post-card-body { min-width: 0 }`**：解除 flex 项目「自动最小尺寸 = min-content」
   下限，长串再也挤不掉右侧日期。
3. **`.post-card-title/.summary/.paper-title { overflow-wrap: anywhere }`**：
   连续 `！`、长链接这类不可断行串允许任意处折行，再交给 2 行截断——
   比「横向裁掉半个字」好看，也让 min-content 回到单字符级。
4. **同类遗留**：`.archive-section-scroll > .archive-empty` 同样因插层失效
   （档案卡空态没垂直居中），一并改后代选择器。

修复后实测（同一真机复现脚本）：

| | 修复前 | 修复后 |
|---|---|---|
| `.list-inner` | `[337..1687]` w=1350 `maxW=none` | `[562..1462]` w=900 `maxW=900px` `align=stretch` |
| 卡片宽度 | 全部 1350 | 全部 900 |
| 封面 | 起点 x=337（被裁） | x=562 完整 220px |
| 固有最小宽度 >900 的卡 | 1 张（1350） | 0 张 |
| 菜菜子投稿页 | 566px 居中缩窄 | 900px 铺满 |

## 四、防回归：列宽契约进探针

这类问题肉眼只在打包版偶发、又跟数据相关，靠手测抓不住，所以固化成机器断言：

- `frontend/src/dev/probe.ts`：每个视图多测一段 `cards`（列宽/卡片宽/封面宽/被裁张数），
  并在列表视图**额外点一次「投稿」筛选**再测一遍（`list-video` 段）；
- `scripts/ui_probe.py`：新增第五组不变量——`.list-inner ≤ 900`、卡片铺满该列且宽度一致、
  封面恒 220 且不被左缘裁切；
- `docs/DEV-LOOP.md` 不变量表、`docs/UI-MAP.md`（`.list-inner` / 卡片行）同步改述。

## 六、经验

- **给 OverlayScroll 包过的容器写 CSS，选择器一律用后代**（`>` 会踩插层），
  或者干脆让子元素自己 `width:100%`。本次两个 `>` 选择器同时阵亡，说明这是系统性坑。
- 判断「宽度不对」时先量 `.list-inner` 的 `max-width` 计算值：如果是 `none`，
  说明列宽契约根本没生效，先修选择器再看内容。
- 量「固有宽度」用克隆 + `width:min-content` 最快，能直接指出是哪张卡、哪个元素在撑。
