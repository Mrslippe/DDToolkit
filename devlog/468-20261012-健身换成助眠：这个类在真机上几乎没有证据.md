# 468-20261012-健身换成助眠：这个类在真机上几乎没有证据

T3（批次 `docs/plans/live-type-persistence-execution.md` 的第三批）：用户口径
「沿用现有的 10 类，但**健身删掉，换成助眠**」。规划与实测依据见
`docs/plans/live-type-sleep-terms.md`（词表草稿 + 真机命中量 + 9 处引用点清单）。

## 一、先说结论：助眠**在真机上一次都命不中**

换完跑真机库副本（8,515 条有标题的场次）：

```
助眠词表 ['助眠', '哄睡', '白噪音', 'asmr', '音声', '伴睡', '耳骚', '冥想']
标题命中 0 条 · 分区命中 0 条
```

这几个词**语义上毫无争议**（谁也不会把「哄睡」判成别的），但用户这批 V 从来不用它们
写标题。所以这一档今天的实际产出是 **0 场** —— 它是"给以后留着的"。

⚠️ **这一条必须让用户知道**：他要的是"把没用的健身换掉"，而换来的助眠**同样是空的**。
差别在于：助眠是"没有证据"，健身是"有一个错的证据"（真机 58 条健身类内容里，
20 条是「健身鹮」「健身环」这类，其中 `健身环` 其实是 Switch 游戏 —— 被旧词条抢走了）。

## 二、刻意**不收**的词（都有实测依据）

| 词 | 命中 | 为什么不收 |
|---|---|---|
| **工作音** | 24–28 条 | 实测那批是 `【工作音】学歌（1-5）` 这种**陪伴学歌**直播 —— 收了只会与 `song`（学歌回/歌回）抢票，并不会真把它们判成助眠 |
| 晚安 | 6 | `晚安提问箱喵`（提问箱=杂谈）、下播告别那几条，都不是助眠内容。**留在 `radio`** |
| 早睡 / 睡 | 7 / 75 | 绝大多数是"聊到睡"的杂谈（`聊一会会儿睡！`、`通宵没睡低气压碎碎念中……`），收了会把一批**本来判对的**场次改错 |
| 放松 / 治愈 | 16 | 两词都太泛：「打游戏治愈狂躁症」会被误伤 |

⇒ 三个词（工作音 / 晚安 / 睡）都是**用户过目项**，改 `TITLE_TERMS[SLEEP]` 一处即可。

## 三、施工中真正抓到的问题：**词表分离**

助眠词原来**同时挂在 `RADIO`** 下（`asmr`/`伴睡`/`哄睡`/`助眠`）。两边都留的后果不是
"看谁先命中"，而是**平分导致判不出自信**：

```
score_title("助眠") → {sleep: 3.0, radio: 3.0}
_confident 要求「最佳 ≥2.5 且领先 ≥1.0」⇒ False
⇒ 「助眠」这种最该判对的标题，反而落回中性兜底
```

所以 `radio` 那条收窄成**节目感**那一组（电台 / 陪聊 / 谈心 / 朗读 / 轻音乐 / 晚安），
四个助眠词整体搬走。判据 `test_category_sleep_words_are_confident` +
`test_category_radio_keeps_only_the_programme_words`（后者是反向的：那四个词不许被电台抢走）。

按**当前规则**重判（真机副本，标题或分区命中旧健身词的 58 条）：

| 去向 | 条数 | 解释 |
|---|---|---|

| `watch`（title） | 1 | `一起看纪录片《肥宠瘦身》` → 观影，判对了（旧规则也是它） |

## 五、改动清单（9 处引用点一次改完）

按 `docs/plans/live-type-sleep-terms.md` §四 的清单执行；两处**结构**改动：

1. `TITLE_CATEGORY_PRIORITY` 里的 `FITNESS` → `SLEEP`（并列同分的兜底顺序）；
2. `AREA_RULES`：**删掉健身那一行**（真机没有健身类分区；"运动"这个宽匹配会把一批
   直播拉进一个已删除的类目），并把 `助眠`/`asmr` 从 `RADIO` 那行**挪到新的 `SLEEP` 行**
   ——分区里出现这两个词时语义就是助眠，挂在电台下等于永远判错。

色调：`.lc-stat-pill--sleep` 与 `.lc-tone-sleep`（三条）**新值用冷靛蓝**（`#cbd5f5` /
`#4f5fc4`）—— 助眠用原来的暖橙（`#ffd5b8`）语义上反了。⚠️ **旧类名必须删掉而不是留着**：
色调是按 key 拼出来的，留一个没人用的旧类不会有害，但会让
`liveCalendarFmt.test.ts::missingTypeTones`（从 `posts.css` 正则取类名）**变成恒真**。

## 六、判据

- `test_category_sleep_replaces_fitness`：旧词条失效（`健身鹮`/`来运动！` 不再判 fitness）；
- `test_category_sleep_words_are_confident`：明确的助眠标题**判得出来**（施工前全部落回兜底）；
- `test_category_radio_keeps_only_the_programme_words`：**反向**判据，四个助眠词不许被电台抢走；
- `test_frontend_type_keys_match_backend_taxonomy`（上一轮加的）：前后端两份表必须同集
  —— 换体系正是会同时碰两边的改动，这条让它"改一边"当场红；
- `missingTypeTones` 的正对照补上 `lc-tone-sleep` / `lc-stat-pill--sleep`。

⚠️ 顺带修好一条**自己过期**的反向验证：`missingTypeTones` 那三条用例里，"不存在的类型"
原来用的是 `'sleep'`；T3 真加了助眠、真给它配了色调类之后，那条从"证明判据会红"
变成了"证明判据恒真"。改成 `'nosuchtype'` —— **反向验证的素材要挑不会随产品演进变成真值的值**。

用例基线：pytest 1417 → **1420**（+3）；vitest **1366 / 114 文件**（条数不变：换体系只改了
既有判据的素材）。`python scripts/gate.py --tier a` 见下一节。

## 七、留给用户的两个开放项（都是一行字的改动）

1. `TITLE_TERMS[SLEEP]` 要不要收「工作音 / 晚安 / 早睡」——收了会让这个类在真机上有产出
   （28/6/7 条），代价是其中相当一部分语义不对（学歌陪伴、"聊到睡"的杂谈）；
2. 助眠这个类如果长期是空的，是否值得保留 —— 或者下次体系调整时并进 `radio`。
