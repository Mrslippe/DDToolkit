# 074-20260913-签名来源与覆盖（A3）+ 字段锁定退役 + 曾用名·曾用签名

> 用户在看到"点别的平台签名 → 主账号签名被覆盖"之后选了 **A3**，并追加两条口径：
> **签名/昵称锁定不需要了**（账号信息有快照）、**只需在 V 上标注曾用名/曾用签名**。
> 本批含**迁移 f004**（3 项 schema 变更）。

---

## 一、先纠正一个前提：快照表**不含**昵称与签名

用户说"当前账号信息会存快照"，实测 `account_stat_snapshots` 只有
`followers_count / live_status / live_title / captured_at / source` ——
**没有 `display_name`、没有 `sign`**。所以"退役锁定 + 让抓取自由覆盖"如果不记账，
旧值就是**永久丢失**（不是"反正有快照"）。

于是口径落地为：**允许覆盖 + 显式记账**。这也正是用户要的"标注曾用名/曾用签名"。

## 二、schema（迁移 `f004`）

| 变更 | 说明 |
|---|---|
| `vtubers.sign_override TEXT NULL` | 手改的签名（覆盖）。**不写 `accounts.sign`** |
| `vtubers.sign_source_account_id INTEGER NULL` | 卡片签名跟随哪个账号（null = 主账号） |
| `vtuber_field_history`（新表） | `vtuber_id / account_id / field / value / changed_at` + 索引 `(vtuber_id, field)` |
| `accounts.locked_fields`（**删除**） | 锁定退役；`scheduler._field_locked` 留恒 False 垫片 |

卡片签名解析（前端 `utils/signSource.ts`，7 条断言）：
`sign_override` → `sign_source_account_id` 指向的账号 → 主账号（B 站优先）→ 空。
**来源账号被删/指向不存在的 id 时回落主账号**（不是显示空）。

## 三、行为口径

| 动作 | 结果 |
|---|---|
| 下拉里点某个平台 | 写 `sign_source_account_id` + **清掉 `sign_override`**；**所有 `accounts.sign` 一动不动** |
| 输入框打字 | 写 `sign_override`（自定义覆盖）；平台签名不受影响 |
| 输入框清空 | `sign_override = null` → 回到"跟随来源账号"（这就是撤销覆盖的入口） |
| 抓取到新昵称/签名 | 覆盖平台值，**覆盖前把旧值记进历史**（相同值不重记，A→B→A 只留 A、B） |
| 手改账号昵称/签名（`PUT /account`） | 同上：先记旧值再写新值 |

> 为什么"选来源要清覆盖"：有覆盖在时选来源不会有任何可见变化（覆盖优先），
> 那才是真的"点了没反应"。

**展示**：签名区下方一行「曾用签名：xxx（B站）· yyy（微博）」；
已订阅账号每行下面「曾用名：…」（只在该账号确实改过名时出现）。
数据来自新端点 `GET /vtuber/{id}/former-values`（各最多 5 条、最近优先、按值去重）——
单独一个端点而不是塞进 `VTuberOut`：`/vtuber/list` 返回全部 V，塞进去就是 N+1。

## 五、收尾时发现并修掉的一个真问题：新表漏进 `purge.py`

新表 `vtuber_field_history` **同时挂两个外键**（`vtuber_id` 非空、`account_id` 可空），
而 `services/purge.py` 的清理清单是按"accounts 之下 4 张子表"写的 —— **没加它**。

后果与 v0.9.3 那次事故**一模一样**：只要某个账号有过改名/改签名，解除订阅或删该账号就会
被 `foreign_keys=ON` 挡下 → 整次事务回滚 → 接口 409/500、V 删不掉。
改签名/改名恰恰是本批新增的日常操作，所以这是"上线即踩"的形态，不是理论风险。

修法与验证：

- 新增 `VtuberFieldHistoryRepo.delete_by_account / delete_by_vtuber`（只删除、不提交）；
- `purge_account` 加一条按 `account_id`；`purge_vtuber` 额外按 `vtuber_id` 再清一遍
  —— **必须两条**：`account_id` 可空，来源账号被删后留下的行按 account 清不到；
- 回归用例 `test_delete_vtuber_cleans_account_children` / `test_delete_account_cleans_children`
  各塞一行曾用值（前者还特意塞一行 `account_id=None` 的）；
- **反向验证过护栏真的会红**：把 purge 里那两行临时去掉重跑，两个用例立刻失败
  （`IntegrityError` → 删除回滚），加回去恢复绿 —— 不是"写完就绿"的假护栏。

## 六、遗留

- **`sign_source_account_id` 没有外键**：账号被删时不做级联，解析端按"指向不存在 → 回落主账号"
  处理（更宽松：删账号不该连带改 V 的设置）。历史行仍有 `account_id`，前端对"已移除账号"
  显示成「（已移除账号）」。
- **历史只记 `display_name` / `sign`** 两个字段（`FIELD_*` 常量）：要加"曾用头像"等，
  在 `vtuber_history.FIELDS` 登记 + 调用点加一行即可。
- 头像仍然是"选账号的远端 URL"（未纳入来源/覆盖模型）—— 与签名不同，
  头像没有"平台事实 vs 展示偏好"的强区分需求，暂不动。
