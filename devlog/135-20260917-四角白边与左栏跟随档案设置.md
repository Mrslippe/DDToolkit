## 一、四角白边：白色来自 **WebView 自己的背景**，不是 DWM

### 取证（这一步花了力气，但没它就只能猜）

`.app-shell` 只有 4px 圆角（`--radius-window: 4px`）且**没有任何 border/box-shadow**，
所以"白边"只可能是圆角抗锯齿像素**背后那一层**的颜色。做法：把窗口挪到**第二块显示器**
（第一块被 DSH Desktop 自己的窗口压着，截出来的是别人的窗口 —— 第一版"证据"就是这么作废的），
置顶后按屏幕坐标逐像素读四角：

| | 角上那 1~2 个像素 | 说明 |
|---|---|---|
| **修前**（rail 底色 `#4B5A6F`） | `#657183` / `#727B8A` | 比底色**更亮**，且**偏冷（蓝灰）** |
| **修前**（顶栏粉 `#FFA2B4`） | `#FDB3C1`（G 179 vs 粉 162） | 粉里**混进了白** |
| **修后** | 与桌面同温的暗色（`#675250` 这类） | 只是正常的抗锯齿 |

两处都能用"**底色按 ~85% alpha 压在白底上**"精确复现
（`#FFA2B4`→`#FFB2C1`≈实测 `#FDB3C1`；`#4B5A6F`→`#667384`≈实测 `#657183`）
⇒ 圆角抗锯齿像素背后是**一层白**。

**先把 DWM 排掉**：Win11 会给窗口画圆角与 1px 描边，本是头号嫌疑。
用 `DwmSetWindowAttribute`（`CORNER_PREFERENCE=DONOTROUND` + `BORDER_COLOR=NONE`，
并补 `SWP_FRAMECHANGED` 强制生效）改完**逐像素数值一字不变** ⇒ 与 DWM 无关。
（顺带确认：窗口左缘**中段**是纯底色、没有亮线 —— 亮线只出现在 4px 圆角那一段。）

### 修法

`transparent(true)` 只让**窗口**透明，**WebView 自己的背景仍是白色**（Tauri 2.11 的默认行为）。
所以两处补上"连 WebView 一起透明"：

| 位置 | 改动 |
|---|---|
| `lib.rs::setup()` | `w.set_background_color(Some(tauri::window::Color(0, 0, 0, 0)))` —— 该 API **同时**设窗口与 WebView 两层 |
| `lib.rs::rebuild_main_window()` | builder 加 `.background_color(Color(0, 0, 0, 0))`（深休眠唤醒重建窗口那条路，必须与配置等价） |

⚠️ 设这一步的时机安全：窗口 `visible: false`，等前端 `present_window` 才显示 ⇒ 看不到闪烁。
⚠️ 验证方法留档：`scripts/` 之外我用的是一次性脚本（置顶 + 第二屏 + 逐像素）——
**没进仓库**（它不是不变量，只是一次取证）；复现命令写在 `DEV-LOOP.md` 的注里。

## 二、左栏跟随档案设置：两处各写了一遍取值链

**根因**：卡片（`HeroCardsView`）用的是 `resolveSign`（`sign_override` → 来源账号 → 主账号）
与 `vtubers.avatar`；而左栏 `VtuberSidebar` 自己拼了一条
`bili.avatar_path ?? bili.avatar_url` + `bili.sign`（**只看平台字段**）——
于是"档案设置里换过头像/签名"在卡片上生效、在左栏上看着像没生效。

**修法**：把头像口径抽成 `utils/avatarSource.ts::resolveAvatar`（与 `signSource.ts` 对称），
**卡片与左栏都调它**；左栏签名改用 `resolveSign(...).text`。口径链：

```
vtubers.avatar（档案设置点选的那枚头像 URL，原样用）
  → B 站账号的本地缓存 avatar_path → 任一账号的本地缓存
  → B 站账号的 avatar_url → 任一账号的 avatar_url → undefined（回落到名字首字）
```

## 三、这条 UI 行为怎么"看见"（新探针 `--profile-sync`）

我看不到界面（DSH 自己的窗口压在上面），所以**只有探针能当眼睛**。
新增第 16 个探针模式：CLI 先往**副本 DB** 种 `sign_override` + `avatar`（绝不碰开发库），
再断言**左栏那一行实际渲染出来的**签名文本与头像 URL，并与卡片交叉对账；
另设一个**没有 override 的 V 当对照组**（防"永远渲染自定义值"的假绿）。

**踩到两个"尺子"的坑（都留档）**：

1. **虚拟时间下图片永远加载不完** ⇒ Radix `AvatarImage` 只在加载成功后挂 `<img>` ⇒
   左栏头像量成 `None`，看着像"没接线"其实是尺子量不到。
   修法：给左栏 `Avatar` 与 hero 容器各挂一个 **`data-src` / `data-avatar-src`**
   （**为可测性存在**，同 `.stat-sets[data-hover]` 的先例，别当冗余删掉）。
2. **种的头像必须有区分度**：第一版种的是 B 站账号自己的缓存，
   而**旧代码恰好也取那一枚** ⇒ 头像半条断言永远绿（假绿）。改成种**非 B 站账号**的头像。

**反向验证**（把左栏改回旧写法再跑）：

```

- 左栏头像是 '…/static/avatars/434334701.jpg'，不是自定义头像 '…/weibo_7198559139.jpg'
[exit 1]
```
改回修复版 ⇒ `[ok] 左栏与卡片同源：自定义签名/头像都到位，对照组未被污染`（exit 0）。
