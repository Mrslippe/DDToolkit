## 三个刻意做窄的决定

1. **取景存归一化值**（`x/y` 是 0..1 的比例、`scale` 是 1..3 的倍数），不是像素：
   窗口尺寸/DPR 变了取景不该跟着跑。
2. **越界 ⇒ 422**（Pydantic 边界）：越界值存进去只会让前端算出**一张跑出视野的图** ——
   那是"看起来坏了"而不是"报错了"，所以要在入口挡住。⚠️ 判据里同时钉了**边界值本身合法**
   （`x=0`/`y=1`/`scale=3` 都在定义域上）—— 别把"越界"写成"靠边就拒"。
3. **`background_focus` 给 JSON 原文**（同 `profile_cards.config_json` 的口径，这一层不做二次建模）。
   代价是前端要自己解析 ⇒ `VTuberOut` 的注释里写死"坏 JSON 必须退回原样铺满，不许白屏"。

## ⚠️ 判据第三次假绿 —— 这次是**正对照缺失**

第一版是这样写的：

```python
before = client.get(...)["background_path"]        # 这张 V 还没有背景 ⇒ None
...
assert after["background_path"] == before          # 拿 None 和 None 比
```

反向验证（把 `clear_background_focus` 改成**顺手清掉 `background_path`**）时，**用例照样全绿** ——
因为两边都是 `None`，"没碰它"与"把它清成 None"在断言上**分不出来**。

修法：**先真的传一张背景上去**（走真实那条 upload 路）再清取景，然后断言它**还在**。改完再变异，红。

⇒ 这条**不是新规矩**：`DEV-LOOP` §5「**"没发生 X"这类断言必须配正对照**」说的就是它 ——
我这次是**知道那条规矩但仍然写漏了**。三次假绿（`414` 的 `toContain` 撞注释、
`416` 的 `indexOf` 撞注释、这次缺正对照）里，前两次是**锚点**问题（已进 `DEV-LOOP`），
这一次是**对照**问题（规矩早就在）。⇒ **唯一可靠的防线还是那句话：写完就去做那次破坏性改动。**
