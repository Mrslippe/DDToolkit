# 541-20261019-采集改按「窗口场次清单」

用户："采集本身仍按日期区间 —— 也就是那个 78 场的区间。" 要求窗口与采集对象同一批人。

## 改法

前端把**窗口切片**的场次清单随请求发过去，后端不再按日期区间重新枚举：

```json
POST /fan/{v}/collect
{ "since": "…", "until": "…",
  "sessions": [{"live_id": "…", "start_at": "…"}, …] }
```

- `CollectRequest.sessions` 给了就据此建 `SessionPlan`，**跳过** `_resolve_sessions`；
  没给则退回原路径（日期枚举），保持向后兼容。
- `/activity` 的 `recent` 每条补上 `live_id`，前端才知道要采哪几场。

## 途中踩的两个坑（都是同一类）

1. **缩进猜错**：`fanCollect` 用 2 空格缩进，我按 4 空格写锚点 ⇒ 静默不匹配、
   `patched 0`。这次靠脚本里的 `assert` 立刻暴露，改前先用 `repr()` 打出真实字符。
2. **顺序错**：`slice` 定义在 `startCollect` 之后，`useCallback` 里用到 ⇒
   `Block-scoped variable used before its declaration`（10 条用例全红）。
   把 slice 挪到 `loadRanked` 之前解决。
3. `slice` 是每次渲染新建的数组，放进依赖数组会让 `useCallback` 每次都变 ⇒
   包 `useMemo`（lint 本来就是因为这条警告失败的）。
