# 151-20260919-档案视图边缘自动滚动：内容坐标位移与滚动跑道

> 用户 2026-09-19 口径：「我抓着卡片**接近底部**的时候网格**自动向下拓展**，同时**自动向下翻页**，
> 反之光标在顶部也一样；这个逻辑在**拖动右下角改变大小**的时候同样适用 —— 即按住时光标靠近底部，
> 网格自动拓展，界面也向下滚动，**与此同时不要发生闪动和错位**」。
> 并要求**先给实现方案**（方案落在规格 §5.7，三个口径过用户拍板：64px/900px/s · 编辑态常驻 240px 跑道 ·
> 连续滚动而不是整屏跳页）。

---

## 一、一句话原则：滚动与跟手必须是同一套坐标

设 `P` = 指针位移（视口坐标），`S` = 滚动量（`scrollTop − scrollTop₀`，向下为正），
定义**内容坐标位移**：

```
D = P + S        ← 唯一真值；模型格位与跟手补偿都只喂它
```

把 `D` 同时喂给"模型目标格位"与"补偿"两处，卡片的视口位置 = 内容位置 − `scrollTop` + 补偿，
`S` 在代入时**正好抵消** ⇒ **卡片视口位置 ≡ 起点 + 指针位移**（与滚了多少无关）。

⇒ "不错位"是**数学结论**，不是调参结果；探针量的也正是这条恒等式（同步误差，实测 **0px**）。

## 二、驱动方式：滚动是主量，下探是它的结果

每周期：`speed = ramp(指针纵坐标)`（纯函数）→ `scrollTop += speed×dt` → `S` 变 → `D` 变 →
模型下探 → 网格长高 → `scrollHeight` 变大 → 能滚更多（**正反馈自洽**，不用另写"拓展"逻辑）。

**为什么不能反过来**（先让模型下探、再把视图滚过去）：网格按 **96px 整行**长高、滚动是连续的 ⇒
模型一动一整行、滚动只走几像素，卡片会在"手指底下"与"差一行"之间来回跳 —— 正是要避免的闪。
**让连续的量当主时钟，离散的量（格位）只是它的函数。**

## 三、"鸡生蛋"与滚动跑道

内容短时 `scrollHeight == clientHeight` ⇒ 滚不动 ⇒ `S` 不涨 ⇒ 模型不动 ⇒ 网格不长 ⇒ 永远动不了。

解法：**编辑态在滚动体底部留 240px 跑道**（≈2.5 行）。数学上净消耗 = `d(网格高)/dt − d(scrollTop)/dt`，
而网格平均长高速度 ≡ 下探速度 ≡ 滚动速度 ⇒ **平均净消耗 0**；网格按整行跳、瞬时最多吃掉一行 ⇒
跑道 ≥2 行就不会见底。跑道是滚动体的 `padding-bottom`（在网格之后）⇒ **不影响网格上缘**
（"进编辑态不推动画布"那条不变量继续成立）。

## 四、四个实测坑（都写进了规格与 DEV-LOOP）

1. **虚拟时间下 rAF 几乎不被服务**：实测 400ms 里只被叫 **0–1 次**。第一版只用 rAF 驱动 ⇒
   探针里 `scrollTop` 恒为 0（功能"看不见"= 没护栏）。改成 **rAF + 定时器双驱动**
   （真机靠 rAF 跟帧率、探针靠定时器可观测），两者共用一个 **8ms 闸门**防止滚成两倍速。
2. **滚动与补偿必须同帧落下**：滚动是同步生效的，补偿要等 React 渲染 ⇒ 中间那一帧卡片多偏
   "这一跳的滚动量"（实测 **15px** = 24ms × 620px/s，且**时有时无**）。改成：循环只把目标
   `scrollTop` 记进 ref + 更新手势状态，由 `useLayoutEffect`（DOM 改完、绘制之前）把两者一起落下去
   ⇒ 任何一帧画出来的都自洽（实测 0px）。
3. **合成 `pointermove` 必须派发在网格上**（监听挂在 `.board-grid`）：派发到祖先（滚动体）
   不会向下冒泡 ⇒ 事件根本到不了 handler（探针第一版就这么假红）。
4. **两段手势之间要等保存落地**：`busy` 期间 `beginDrag` 直接返回、不接新手势 ⇒ 第二段"按住"
   按不下去，相位是 `idle`，看着像"跟手失效"。

## 五、护栏（先红后绿）

- **纯函数**：`autoScroll.ts` 的 `autoScrollSpeed`（中点 0 / 下区 ramp / 贴边与出界满速 / 上区为负 /
  容器未量到不滚）+ `nextScrollTop`（按速度×时间前进、夹在 `[0, maxScrollTop]`）—— **10 条单测**；
  `motion.ts` 的 `liftOffset` 加滚动项 + 新增 `contentDelta`（含一条"补偿 = D − 格子位移 ⇒
  视口位移回到 P"的自洽用例）—— **+5 条**。
- **探针** `--motion-scroll`（新）：**先红**（底部停住只滚 0px、同步误差 436px、模型行 -1、网格没长…）
  → 实现后全绿：

```
容器 106–621（高 515）· 可滚范围 366px · 400ms 内 rAF 被服务 0 次
底部停住：scrollTop 0 → 832（832px）· 模型行 0 → 13 · 网格高 564 → 1524 · 同步误差 0px
顶部停住：scrollTop 852 → 59（-793px）· 同步误差 0px
抬手后：59 → 59（停表）· 缩放手柄：滚 442px、高 3 → 10
```

- **旧断言按新语义重写**：`--motion-cards` 的缩放段原来判"拖不到半格模型尺寸不许变"，而手柄若
  落在触发区里，自动滚动会让**内容**多走一截、模型因此吸附（这是 P4d 的正常行为）。改成用
  **内容坐标位移**判：`|内容 dy| < 半行 ⇒ 模型不许变`、`≥ 半行 ⇒ 必须吸附`（宽度没有横向滚动，照旧严格判）。

## 七、口径记录（规格 §5.7 表）

触发区 **上下各 64px** · 最大速度 **900px/s**（按深度线性 ramp，不设停留延时）·
指针移出容器按该方向**满速**继续 · **不做横向**（12 列恒等于容器宽，没有横向可滚的东西）·
reduced-motion **照常自动滚动**（这是功能不是动画）· 缩放手柄**同一套** ·
松手立刻停表（跑道保留）· **"翻页"= 连续滚动**，不做整屏跳页（跳页会丢参照物）。
