## 一、为什么是 1.0.0

自 v0.9.9（08-13 发布）以来共 **22 个批次（devlog 060–081）**，主题是"**档案可信**"：

| 维度 | 这一版收了什么 |
|---|---|
| 抓取正确性 | 弹幕超时误报（12s→30s×3 + 两段式取数 + 单飞）、动态流每轮 ERROR（loop-bound 锁）、动态名单口径（每 V 主账号 → 全部账号按平台分组） |
| 设计纠偏 | "字段锁定"退役 → **平台签名只读 + 曾用值记账**（A3 来源/覆盖模型） |
| 可观测 | 日志按天轮转（此前 5.2MB / 33963 行跨数月）、上游取数入口日志、名单/间隔逐轮打印 |
| 验证基建 | 探针 4 条（新增档案设置可点性 29 项、场景切换机）；后端 307→315、前端 119→131 条用例；三条"测试量错了轴"的教训写进文档 |

**1.0 的含义不是功能变多，而是数据链路与验证基建都收敛了** —— 这也是把它定为 1.0 的理由。

## 二、本批动作

1. **版本号 5 处同步**（`docs/RELEASE.md` §2）：`app/core/config.py`、`tauri.conf.json`、
   `Cargo.toml`、`Cargo.lock`（只改 `ddtoolkit` 块）、`package.json`，外加 README 徽章；
   `Cargo.lock` 用**块定位**替换而非全文替换（0.9.9 也可能出现在依赖里）。
2. **发布说明** `docs/releases/v1.0.0.md`（`upload_release_assets.py` 直接读它当 Release notes）。
3. **门禁**：pytest / tsc / eslint / vitest / 探针（四条）/ `dev_check.py`。
4. **构建**：`npm run release`（PyInstaller onedir → Tauri release → NSIS → 聚合 `dist-release/`），
   并按 §3 校验安装脚本**没有把后端目录打平**（`_internal` 层级，devlog/036 的事故形态）。
5. **发布**：commit → `git tag -a v1.0.0` → 推代码与 tag → `scripts/upload_release_assets.py v1.0.0`
   （token 走环境变量，不落盘）。
6. **升级说明**（写进 release notes）：首次启动自动迁移到 **f004**；
   "字段锁定"入口消失是预期；微博未登录时其名单整条跳过、重新扫码自动恢复。
