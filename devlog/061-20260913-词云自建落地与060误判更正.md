## 〇、更正：不存在"上游断供"（推翻了 devlog/060 的核心结论）

### 事实

`/api/v2/live` **仍然返回 100 个热词**。用**正确的嵌套层级**复核 12 个近期场次：
**12/12 全部有词云**。

### 误判是怎么发生的

该接口的响应是**双层信封**：

```jsonc
{ "code": 200,
  "data": {                 // ← 信封
    "total": 39316, "pageNum": 0, "pageSize": 1, "hasMore": true,
    "data": {               // ← 真正的载荷（**多这一层**）
      "live": { "extra": { "wordCloud": { … 100 个词 … } } }
    } } }
```

我在 devlog/060 的探查脚本里读的是 `d["data"]["live"]["extra"]` —— 信封层没有 `live`，
于是 `extra` 恒为 `None`，我就把它当成了"字段整个消失"。

**后端代码从头到尾是对的**：`_parse_live_summary` 写的是
`inner = payload.get("data")` → `live = inner.get("live")`，正好跳过了信封。

### 我当时为什么没怀疑自己

三条"证据"互相印证，让我跳过了复核：

1. 24 个场次**全部**报缺失 —— 我把"一致"当成了"确凿"，
   而**一致的错误正是读错层级的典型症状**（bug 通常不会 24/24 全中）；
2. devlog/052 记录该场次曾有 40 热词，而现在"没有" —— 时间线看起来像上游变更；
3. 前端当时确实显示"暂无热词数据" —— 有一个**独立的现象**与结论吻合。

第 3 条最误导：那个现象其实另有原因（见 §三），但我把它当成了同一件事的佐证。

### 教训（写给下一次）

- **"100% 复现的缺失"要先怀疑读取路径，而不是对方下线**：对方真的改接口时，
  更常见的是返回错误码、空对象、或只对部分场次缺失。
- **写探查脚本时先 dump 一次原始结构**（`print(list(d.keys()))` 三行代码的事）。
  本批最后就是靠 `data 键: ['total','pageNum','pageSize','hasMore','data']` 一眼看破的。
- **别让"吻合的旁证"代替"直接的证据"**：前端现象吻合不代表因果相同。

> devlog/060 里**仍然有效**的部分：§一.2 的 v3 原始弹幕端点实测、
> §一.3 的 **`rawText` vs `text` 字段名差异**（普通弹幕在 `rawText`，SC/系统提示在 `text`）——
> 本批的自建实现正是基于它。060 已加上作废标注。

## 三、本批踩到的四个"自己写错"的点（比功能本身更值得记）

1. **重复计数（两次）**：我加了一个"非 CJK token 再跑一遍 `_ASCII_WORD.findall`"的补捞分支。
   结果 ① `["Sweety","sweety","SWEETY"]` 得到 **6** 而不是 3（jieba 已把 ASCII 整串吐出，又被补捞一次）；
   ② regex 引擎把混合串 `"Sweety 好耶"` 整块返回时同理翻倍。
   实测**两个引擎都已经把 ASCII 词切好**（jieba `'Only Apple Can Do'` → 4 个词），
   补捞纯属多余 —— **删掉即正确**。教训：加"保险"逻辑前先确认它是不是在做重复劳动。
2. **大小写未归一会让同一个词分成两条**：实测 `Sweety` 与 `sweety` 各 60 次、白占两个词位。
   新增 `normalize_token()`（ASCII 转小写、中文原样）。
3. **派生量与来源字段自相矛盾**：详情端点曾写 `wc_status=summary.get("status") or "upstream_absent"`，
   当 summary 没带 `status` 时就会报出 `source='upstream'` + `wc_status='upstream_absent'`。
   被既有用例当场抓出 → 改为**以实际拿到的词条为准**（派生量就地从同一份数据推导）。
4. **`--archive` 探针的 `词云格 0` 不是数据问题**（见下）。
   顺手新增 `--archive-day <N>`：`--archive` 固定点"最近一场"，遇到刚下播/未收录就量到 0，
   看起来通过却什么都没验。

> 关于 058 记的"`词云格: 0`"：*archive 的弹幕区是**异步**填充的（实测 /api/v2/live 首包
> 0.4–1.1s，且大场次数 MB），探针 3s 采样窗口可能落在填充完成之前 —— 那是**探针时序**问题，
> 不是词云坏了。本批未修改该等待时长。
