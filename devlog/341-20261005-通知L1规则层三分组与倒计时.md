# 341-20261005 通知 L1 规则层：三形态分组、相对时间、倒计时与一键已读

> 接 `devlog/340`（设计案）。用户拍板了样式四选（都取推荐项）之后落地 **L1 规则层**：
> 形态三分 + 面板三组 + 同级合并 + 相对时间 + 倒计时可视化 + 一键已读 + 自动已读滑出。
> 其中两处是**改代码时才发现的真问题**（下面 §二、§三），不是样式活。

## 一、后端契约加两个字段（`Notice`）

- **`form`**（`state`/`notice`/`action`）：与 `kind` **正交** —— `kind` 管长相（字形/点色），
  `form` 管行为（活多久、怎么消失）。⚠️ 刻意不用 `kind` 推 `form`：两者今天恰好一一对应是巧合
  （报告曾是 alert、进度也曾经要和报告抢胶囊），混着用会在下次改口径时静默出错。
- **`createdAt`**（服务端毫秒）：面板要显示"3 分钟前"，而 `expiresAt` 只能表达"什么时候没了"。
  **来源按形态各不相同**（状态=开始时刻 / 告知=记录时刻 / 处置=收尾时刻）——
  这正是最容易漏的字段，所以补了一条"**每条**都要有 `createdAt`"的判据（漏了的症状是
  面板上那一行安静地没有时间）。
- 状态类的"开始时刻"落在调度器：`_status[*]["started_at"]`，在 `running = True` 的**每一处**写入
  （10 处，脚本插入 + 复核），`external` 那块还要一个 `auto`（见下）。

## 二、⚠️ 真问题一：「自动节拍不占顶栏」漏在第三方同步那条路上

`_progress_notices` 对 `post`/`account` 查了 `auto`，而 `status["external"]` **根本没有这个字段**
⇒ 收录回填 / 每日批次 / 启动补抓都会产生一条**没有终局的**常驻进度，把胶囊一直占着。
漏的原因不是疏忽：判据**无从写起**（字段不存在）。修法：`external_task_started(..., auto=True)`
默认**保守**（忘了说 → 表现是"安静"，不是"永久占位"），只有"用户刚点按钮、必须立刻看到反馈"
才显式 `auto=False`。判据打在"自动档不出条目 / 手动档照样出"这一对反差上
（只测前者会让函数退化成 `return []` 也算过）。

## 三、⚠️ 真问题二：TTL 到期**没人重渲染**（探针抓到的）

`ui_probe --status-island` 报"瞬时消息过了 ttl 还亮着"。查下去不是过滤器坏了，是**没人重算**：
过期判定读的是 `now`，而 `now` 只在**宿主重渲染**时更新 —— 宿主闲时轮询 **10s** 一次，
于是"6 秒后自动已读"实际是"最多 10 秒后才消失"（面板里那句"3 分钟前"同样会停住）。
修法：`StatusIsland` 自带一个 1s 秒表，只在**有会自动过期的条目**或**面板开着**时走
（空闲态本来就有自己的轮播时钟，两个定时器不同时开）。

> ⚠️ 这条正好说明"探针等的秒数要跟着常量走"：原来写死 `sleep(4600)`，TTL 提到 6s 后
> 它会变成"还没过期就断言" —— 红的是探针而不是产品。已改成跟着 `EVENT_TTL_MS` 的量级并注明。

## 四、前端规则层（`utils/noticeBoard.ts`，24 条单测）

三形态 → 三组（正在进行 / 需要处理 / 最近）· 组内按「过期会不会丢信息 / 要不要动手」排 ·
**同级合并**（两个任务同时跑 → `帖子·账号 抓取中 - 3/11`；两场开播 → `2 场开播 · A、B`）·
相对时间（`刚刚 / N 秒前 / N 分钟前 / N 小时前 / N 天前 / 日期`，**缺 `createdAt` 就不显示**，
不许糊一个"刚刚"）· 倒计时比例（**只给会自动消失的条目**，进度/报告不许有 —— 那会误导成
"任务会自己消失"）。

## 五、⚠️ 真问题三：让位那一下会**闪出空窗**（探针连读三次都撞上）

`mergeNotices` 的让位是"本地撤 + 服务端上"两件事，而服务端那条的**到达节奏**与本地无关
⇒ 存在"本地已撤、服务端还没进列表"的空窗。修法：进让位那一刻记一个时刻，**3 秒内不撤本地**
（`HANDOVER_GRACE_MS`）—— 两条并存时文案同源（`compose_task_text`），读起来是同一句话。
⚠️ 记时刻必须用 `??=`：每拍都刷新会让宽限窗口**永远不会到点**（第一版就是这么写的，
判据当场红）。

## 六、⚠️ 两个"看起来像纯数据变换"的渲染坑（都靠组件用例抓出来）

写 `StatusIsland.test.tsx`（12 条）时踩到两个，它们的共同点是**纯逻辑测试永远看不见**：

1. **transition 的 `map` 少写一个 `return`** ⇒ 未过期的条目全变成 `undefined`、被整批丢掉
   （症状是"面板里只剩一条"）；
2. **体检 effect 每拍返回新数组** ⇒ `setRows` 每次都触发重渲染、effect 互相点火，
   **退场动画一帧都播不出来**（症状是"滑出动画没生效"，而 `is-out` 类名确实加上了）。
   修法：没有真变化时 `return prev`（React 的"同一个引用就不重渲染"）。
   ⚠️ 后面这条特别值得记：它长得像纯粹的数据变换，实际是"`useEffect` 里 setState 要防抖"
   的同一类坑。
