# 397-20261007-B2第十五轮 诊断行"发出去了"不等于"落进日志"

## 现场：三次复现，6 个窗只有 3 个摘要

用户跑三次（① 小窗→全屏 = 不卡 ② 直接全屏 = 卡，左 seek 后流畅 ③ 直接全屏 = 流畅），
探针这次**抓到了翻面那一拍**：

```
01:46:41 [video] 转折 →坏 位置=2.8s 缓冲=22.2s 全屏=是 元素=4/停/播 窗=start第3秒 丢=2/s 帧=30/s
```

**数据侧全清白**：全屏、播放中、没在 seek、`readyState=4`、前方缓冲 **22.2 秒**、播放点 2.8 秒 ——
而它紧跟在 `01:46:39 全屏表面=不透明`（进全屏）之后 **2 秒**。三次的开关也对得上日志：
`01:46:21` 进全屏 → 15 秒零丢帧（①）；`01:46:39` 进全屏 → 3 秒后翻坏（②）；
`01:47:17` 进全屏 → 零丢帧（③）。

**但六个窗只留下三行摘要。** 查下来不是探针没发，是**后端把整行丢了**。

## 根因：`max_length=400` ⇒ 422 ⇒ `.catch()` 咽掉

- 后端 `ClientLogIn.line` 是 `max_length=400`；超一个字就是 **422**，`logger.info` 根本不执行。
- `api.clientLog` 那头 `.catch(() => {})` —— 于是**从日志上看不出任何异常**，
  只表现为"这一窗没有摘要行"（曲线那行短、照常落地，所以现象是"只有曲线没有摘要"）。
- 为什么以前没暴露：唯一那条判据叫"最坏情况 ≤400"，而它的"最坏情况"**没带 `动画名=`** ——
  它是全行**唯一长度不封顶**的字段（CSS 类名可以任意长，最多 3 个 `name@选择器`）。
  真机最长的一行本来就 397 字，再补上这一轮新加的 `位置=` ⇒ **直接越界**。

## 修法（生产端保证，不靠调用方自觉）

`summarize` 自己兜底：超 400 就按 `DROPPABLE` 顺序丢**可选项**（`动画名=` 最前），
丢掉的数量写进行尾 `截=N`；兜底再截断，**绝不整行丢**。

为什么丢字段而不是截断：截断从行尾切，切掉的正好是 `位置=`/`末缓冲=` 这些主判据；
而 `动画名=` 丢了几乎不影响读日志。⚠️ **静默丢字段比行长更坏** —— 这一行的用途就是事后读。

判据：补一条"**类名长得离谱**"的用例（3×200 字），断言 ≤400、**含 `截=`**、
且 `丢帧=`/`位置=`/`全屏=` 一个都不许丢。**反向验证过**（`MAX_LINE` 调大 ⇒ 只这条红）。

## 提炼出去的一条

**"发到日志"的诊断量，要有判据盯住它真的到得了**（→ `docs/frontend/PROBE.md` §6.23 末尾）。
残缺的证据看不出来是残缺的 —— 这次差一点就拿着"少了三窗"的日志去下结论。
