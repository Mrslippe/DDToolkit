# 291-20261003 微博视频映射：数字 11 也是视频

> 批 3（目标里的"顺手把微博视频地址映射补上"）。现场来自用户之前的报障：
> 微博视频帖的 `body.video` 恒为 `{mp4: null, cover: null}` —— 打开详情没有可播的东西。

## 一、真机取证

拿库里带媒体地址的那条微博帖（mid `5334672825653617`）走仓内既有的
`weibo.com/ajax/statuses/show?id=` 取**新鲜**回包（库里存的是**已过期**地址，实测全 403，
不能拿来判策略 —— 这点先踩过）：

```
page_info.type   = 11            ← ⚠️ **数字 11**，不是字符串 "video"
media_info 键     = [… duration, h265_mp4_hd, mp4_720p_mp4, mp4_hd_url, mp4_sd_url, stream_url, …]
mp4_720p_mp4     = http://f.video.weibocdn.com/o0/q54c…mp4?label=mp4_720p&template=960x720…
duration         = 256
```

**微博视频 CDN 的防盗链实测**（同一支新鲜地址）：

| 请求 | 结果 |
|---|---|
| 裸请求（无 UA 无 Range） | **200**（18MB 全量） |
| UA + Range（**无 Referer**） | **403** |
| UA + Range + `Referer: https://weibo.com/` | **206** ✓ |

⇒ 与 B站 同款：**必须带平台 Referer**，走 `/video-proxy`。

## 二、改了什么

| 处 | 内容 |
|---|---|
| `weibo._page_type` / 判定处 | 认 **数字 `11`** 也是视频（旧注释写"仅接受字符串 video"，正是根因）；注释改成实测口径 |
| `weibo._video_of()`（新） | 按实测优先序取地址：`mp4_720p_mp4` → `stream_url_hd` → `mp4_hd_url` → `stream_url` → `mp4_sd_url` → **`h265_mp4_hd`（最后，HEVC 在 WebView2 不一定能解）**；顺带认 `page_info.urls` 字典形态；产出与小红书**同款形状** `{url, fallbacks[], duration_s, cover}` ⇒ 前端一个播放器通吃，不用加分支 |
| `body_json.video` | 从 `{mp4, cover}`（空壳）换成上面那套 |
| `/video-proxy` | 白名单加 `weibocdn.com` / `sinaimg.cn`；`HOST_POLICY` 给这两个域配 `Referer: https://weibo.com/` + UA |

## 三、判据

`tests/test_weibo_video.py` 4 条：**数字 11 认成视频且带出地址**（事故复现）、720P 优先与
fallback 链（H.265 只能在最后）、没有媒体字段就不写 `video` 键、微博两域的策略都必须带 weibo Referer。
