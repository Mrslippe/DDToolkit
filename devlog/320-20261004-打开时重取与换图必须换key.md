# 320-20261004 打开时重取：本地没有副本时的备选路径（批次 3）

> 用户口径（`devlog/319` 同一句的后半段）：「把**打开时重取**作为一个备选项，如果本地没有缓存就回退到重取」。
> 方案：`docs/plans/media-pinning-execution.md` 批次 3。

## 一、这一批做了什么

**后端**：`POST /posts/{post_id}/refresh-media`

- 走**平台自己的详情补全**（`BasePlatform.enrich`：小红书 `feed`、微博详情）——签名头、风控、
  节流都在平台层，这里不另造一套；库里的行先**还原成抓取时的 item 形状**再交给它（`raw_json`
  里有平台要的令牌，小红书 `xsec_token` 就是这么来的）；
- 失败**如实分级**：404 帖不存在 / 403 未登录（内容接口能力闸门，与抓取同一条）/
  **409 平台没有详情补全**（B 站视频帖的封面与播放地址是播放时另取流，别假装重取了）/
  **429 同帖 30s 内再来**（图床地址是限时的，重取只能拿"当下这一份"）/ 502 上游失败；
- 写回**只动媒体相关的列**（`cover_url`/`body_json`/`raw_json`/`stats_json`）：标题与发布时间是
  另一件事，顺手改会让"列表顺序忽然变了"这类现象更难解释；
- 拿到新地址**立刻固化一次**（`media_pin.pin_post_media`）——不然几小时后又过期，用户下次打开还是灰的。

**前端**：`ProxyImage` 四级全失败时回调 `onAllFailed`（**只在真正落到 failed 那一级**，中间级不算）⇒
详情页收到后**一帖只调一次** `refreshMedia`，用回来的**整帖就地替换**渲染（不动父级列表）。

## 二、踩到的坑：拿到新地址 ≠ 画得出来

`ProxyImage` 的四级状态（`stage`）是**组件内**的。重取回来只换了 `src`，React 沿用同一个实例 ⇒
那个实例已经停在 `failed` 上，连 `<img>` 都不再渲染（这一级渲染的是占位块）⇒ **新地址永远进不来**。
"换图要换 `key`"本来就是本组件的约定（见其文件头），只是"重取"是第一条真会换图的路径。

修法：图片项的 `key` 带上 `url + local`（重取的常见结果恰恰是"URL 没变、顺手固化的副本到位了"），
封面 `key` 带上 `cover_url`。反向验证：把 `key` 改回 `${url}-${i}` ⇒
`PostDetailDrawer.media.test.tsx`「本地副本新到位也要重画」立刻红（`副本到位后没有重画`）。

## 三、判据

后端 3 条（`tests/test_vtuber_api.py`）：新地址写回库 + 顺手固化 + **二次调用 429**；
能力闸门/无详情平台/**帖不存在**如实 404/403/409。`tests/test_media_pin.py` 补
`pin_post_media` 只固化这一帖、且已固化时**零请求**。

前端 9 条：抽屉 5 条（重取一次 + 换上**新签发**地址 / N 张坏图**只发一个请求** / URL 没变但副本到位
也要重画 / 失败**不打扰用户**只留一行诊断 / **换了帖就丢掉**重取回来的那份）+
`ProxyImage` 4 条（中间级不回调、四级走完只回调一次、有本地副本时不算全失败、可选回调不炸）。
