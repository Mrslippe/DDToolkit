# 201-20260925-S1会话token：后端门禁与壳生成（含一次伪装成"布局坏了"的排查）

用户口径：「开始吧」（按修正后的顺序做批次 1 / S1）。

## 一、这一批在防什么（具体，不是"最佳实践"）

后端监听 `127.0.0.1:<随机端口>`，而**端口可以扫**（65536 个，几秒）。在此之前：
本机任何进程、以及任何网页（那时 `CORS_ORIGINS` 默认 `"*"`）都能读到全部归档、改数据、
触发抓取；而 `DATA_DIR/.env` 里是**活的登录凭据**（B 站 SESSDATA + refresh token、微博 cookie）。

## 二、改了什么

- 新建 `app/core/api_auth.py`：`X-DDToolkit-Token` + `hmac.compare_digest` + 路由分级。
  **公开白名单只有三处**：`/healthz`、`/static/*`、`GET /img-proxy`
  （前两者是 `<img>` 直连与桌面端就绪探活；`/img-proxy` 另有主机白名单）。
- `app/main.py` 挂中间件；`app/core/config.py` 读 `DDTOOLKIT_API_TOKEN` / `DDTOOLKIT_DEV_API_TOKEN`。
- Rust：**每次启动生成** 32 字节 CSPRNG token（只存内存、不落盘、不进 argv），
  注入 sidecar 的两个 spawn 分支；新增 `get_api_token` 命令，
  **自己校验调用方窗口 label**（`build.rs` 无 app manifest ⇒ 自定义命令默认不查 ACL，
  只拆 capability 等于没做 —— 见执行方案 §2.2）。

## 三、修掉一颗早就标出来的地雷：托盘退出会静默掐掉一轮抓取

`backend_manual_running` 用**手写裸 TCP** 打 `/vtuber/fetch-status`（为了一处判定不值得引
HTTP 客户端）。加 token 之后它必然吃 401，而原代码把"非 200"一律当成**问不到** ⇒
`tray_quit_impl` 走"直接退出"分支 ⇒ **手动抓取中用户点托盘退出，不弹确认就把这一轮掐了**
（正是 R20 / devlog/095、097、129 花大力气修好的行为）。

修法：把正文判定抽成纯函数 `manual_running_from_response`，**三态**：
- `Ok(Some(..))` 真问到了；
- `Ok(None)` 问不到（非 200/401/403）⇒ 当"没在跑"（**用户点的是退出，不该退不出去**）；
- `Err(401)` ⇒ **保守当成"在跑"**（那是"这个壳与这个后端对不上"，很可能真有任务）。

## 四、一次伪装成"布局坏了"的排查（本批最费时的一段，值得单独记）

门禁里 `ui_probe` 红了，60 条失败，读起来全是**内容/布局**问题：
"缺投稿 chip"、"缺 `list-video` 帧"、"所有视图 `.page-title` 为空"、"没有 `.data-deck`"。

排查路径（**每一步都排除了一个看似合理的假设**）：
1. 先怀疑产品：`git stash` 掉本批改动 ⇒ **探针全绿** ⇒ 是本批引入的。
2. 再怀疑 token：后端日志里**一条 401 都没有**（中间件拒绝会打 WARNING）⇒ 门没挡。
3. 再怀疑数据：查探针副本的库 ⇒ 8 个 V、uid 434334701 有 60 条 video 帖 ⇒ 内容够。
4. 再怀疑 CORS：进程内 `TestClient` 实测四种配置 ⇒ 确认"没有 `allow-origin` 时浏览器
   不让页面读响应"；但**只有 `"*"` 会发通配头**，而探测脚本里的正则**没生效**。
5. 量真后端：`curl -H "Origin: ..." ` ⇒ 只回 `access-control-allow-credentials`
   —— 而进程内同一正则**是生效的**。
6. ⇒ 定到 `app/main.py`：它把 `CORS_ORIGINS` 拆成列表**只喂 `allow_origins`**，
   于是探针传进去的正则被当成**一个字面 origin**、永远匹配不上。

**为什么极难查**：请求到了、后端也回了 200、日志里一条错都没有；
唯一的现象是"页面数据全空"，于是**布局断言集体报红**。判据只有"stash 掉就绿"。

修法：`main.py` 识别正则（含元字符即按正则处理，喂 `allow_origin_regex`），
并**把 `"*"` 排除在正则判定外** —— 第一版没排除，`"*"` 被当正则 ⇒
`re.PatternError: nothing to repeat` ⇒ **应用直接起不来**（3 条用例当场报错）。

## 五、口径修正：**CORS 不是主防线，token 才是**

我一度把 `CORS_ORIGINS` 默认从 `"*"` 改成空，想顺便关掉"任意网页可读"。**已改回 `"*"`**：
- 它会打断浏览器形态的开发态（探针、`npm run dev` 都是跨源）；
- 收益接近零：拿不到 token 的网页即使能读到响应，读到的也只是 401。
⇒ 要收紧就收紧 token 的**分发**（S3-A 的命令级权限），别动 CORS。
这条写进了 `ARCHITECTURE.md` §6.26 与 `tests/test_api_auth.py` 的一条用例（有意钉住它）。

## 六、先补的失败用例（`tests/test_api_auth.py`，13 条）

无 token 逐端点 401（**真应用的路由表**）/ 对 token 放行 / 错 token 401 /
公开白名单只认那三处 / 401 不回显 token / token 不进 OpenAPI /
"没配 token"必须可被查询到 / 常量时间比较的**源码级**判据 / CORS 正则与默认值。

其中一条是**路由表对账**：直接读 `app.routes`，新加的路由若既不在白名单、
又没被要求 token，**直接红** —— 不依赖写测试的人记得往清单里补一行。

⚠️ 不写"错 token 与对 token 耗时相同"那种断言：单测测不出等时性，写了就是装饰性断言
（`DEV-LOOP` §0.7）。
