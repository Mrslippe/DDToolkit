## 一、事实核对（三条硬证据）

| 证据 | 结果 |
|---|---|
| 开发日志里的登录态探测 | 21:52 / 21:54 / 21:55 / 21:57 / 21:58 / 22:35 / 22:36 **全部 `有效`**；而 `ok=-100` 只出现在 **10:06 与 12:29**，12:33 那次 `v2 登录失败` 是扫码前的失败尝试 |
| 现场只读复核（刚跑） | `cookie` 存在（271 字符）· `needs_login=False` · `check_valid()=True` · 七海 weibo 取到 **24 条**、明前奶绿 **20 条** |

还和自己的实测输出（weibo 2 个请求、0 问题）矛盾却没察觉。

## 二、顺手改掉我自己引入的两处问题

### ① 每分钟一次多余的登录态探测（去掉了）

R10 版本在每轮开抓前调 `check_valid()` 复探登录态 —— 而**探测本身就是一次上游请求**
（`weibo.com/ajax/profile/info`）。动态流每 60~70s 一轮 ⇒ **每分钟白打一个请求**，
纯粹为了"万一 cookie 中途失效"。

改成**让既成的失败来标记**（零额外请求）：

```python
# platforms/weibo.py：ok=-100 的两条路径（mymblog 列表 / profile 信息）
weibo_auth_manager.mark_invalid(f"mymblog ok=-100 uid={uid}")
```

- `WeiboAuth.mark_invalid(reason)`：把 `_valid` 置 False（已在 False 时不重复刷日志）；
- 下一轮 `_lane_skip_reason()` 命中 `needs_login` ⇒ **整条 weibo 名单跳过**；
- 代价：**本轮**那条名单白打（2 个账号 ≈ 2 个请求），而不是此后每分钟都白打；
- 重新扫码走 `apply_cookie()`（置回有效）⇒ 自动恢复，不会卡死。

### ② `check_valid()` 的并发双探测（顺手修）

日志里出现过 **同一秒两次探测**（22:35:55.969 / 22:35:56.086）：两个调用方在第一次探测
返回之前都判断"缓存过期"→ 各打一次上游。修法：**先记账再探测**（`_checked_at = now` 提到
`await` 之前），并发调用者在本轮探测期间直接用旧结论。

> ⚠️ 不能在这里用 `asyncio.Lock` 去串行化：认证单例是**模块级**对象，而动态流每轮一个
> `asyncio.run()` —— 那正是 devlog/076 的事故形态（`is bound to a different event loop`）。
> 用"先记账"这种**同步**手段才是安全的。

## 三、一次真实的副作用事故（我自己踩的，已恢复）

新加的测试 `test_weibo_login_required_marks_auth_invalid` 里调了 `apply_cookie()` 验证
"重新扫码后恢复"——而 `apply_cookie()` 会 `save_env_keys()` **落盘到 `DATA_DIR/.env`**。
测试环境的 `DATA_DIR` = **项目根** ⇒ 仓库根 `.env` 的三个 WEIBO 键被写成了假值
（`SUB=new / 1 / x`，实测 `LastWriteTime` 正好是跑测试那一刻）。

- **恢复**：根 `.env` 与开发数据目录 `.env` 的键集合完全一致、其余值逐字节相同 ⇒
  从开发目录（权威凭据）把 `WEIBO_COOKIE/UID/NAME` 三行写回根文件，其余行原样保留；
  复核现场登录态仍有效（见 §一）。**注意**：文件 mtime 无法恢复（内容已复原）。
- **防复发**：测试改成 monkeypatch `save_env_keys`（项目里既有测试都是这么挡的，
  `test_auth.py:182` 还写了注释"不落盘"——我漏了这个惯例）；并加了"跑完测试根 `.env`
  哈希不变"的核对。
- 顺带排查：全仓测试里其余 `apply_cookie`/`save_env_keys` 调用点**都已**做了不落盘处理，
  只有我这一处漏了。

## 五、遗留

- `mark_invalid()` 目前只由 weibo 的**抓取路径**调用；`check_valid()` 仍由 TopBar 的

  在 `_lane_skip_reason()` 里加分支即可（同步判据，预算估算共用同一口径）。
