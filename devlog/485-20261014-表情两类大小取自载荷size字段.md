# 485-20261014 表情的两类大小：B站 的载荷里本来就有这个字段

> 用户给两张截图：「表情分成两类，一类是图文共同大小的表情（图二），一类是大于文字的表情（图一），
> 原 json 中有说明表情大小的字段吗，如果有就直接取那个，如果没有就我们自己定」。
>
> **有** —— 就是 emoji 节点的 `size`。这批没自己定口径，直接取它。

## 一、先回答"有没有"（实测，不是猜）

扫真机库 5,060 条载荷的 **5,999 个 emoji 节点**：**每一个都带 `size`**（int，只有 `1` / `2` 两个值）。

| `size` | 是什么 | 实测 | 地址形态 |
|---|---|---|---|
| `1` | **小表情**（图文同大小） | 425 个节点 / 84 种 token | **全部**在 `/bfs/emote/`，`package_id` 是官方表情包（1 / 2 / 0） |
| `2` | **大表情**（贴纸） | 5,574 个节点 / 409 种 token | garb 4,724 + **emote 812** + 其他 38 |

**⚠️ 两个反直觉的点（都是实测踩出来的）：**

1. **判别不能按"官方 vs 自定义"，也不能按 `garb` vs `emote`**：`/bfs/emote/` 那条"看着像官方小表情"
   的路径里有 **812 个 `size=2`** —— `[明前奶绿_灰头土脸]`、`[菜菜子_开心]`、`[罗小黑_来了]`、
   `[热词系列_吹爆]` 这些装扮/收藏集。只有 `size` 分得开。
2. **也不能按形状判**：`size=1` 里也有 27/85 种带包名（`[doge_金箍]`，官方包里本来就带下划线）。

**用户的两张截图正好一样一个**（都在他自己库里，按原文找出来的）：

| 截图 | 帖子 | 表情 | `size` |
|---|---|---|---|
| 图一（大的） | id=5575「为什么我读博这么眉笔啊！！！！」 | 梨安收藏集表情包 `气鼓鼓`×2 / `得意` / `爱心发射` | **全是 2** |
| 图二（同文字大小） | id=5563「实在抱歉！！又在紧急抢修网络中…」 | `[委屈]`×6 | **全是 1** |

**第二源也带这个字段**：上游整表（`x/emote/package`）每张脸在 `meta.size` 里给同一件事 ⇒
两级解析都能给出大小，不存在"只有第一源才有"的窟窿。

**量级**（`scripts/check_emoji_coverage.py` 现数）：命中的表情里 **大表情占 83% 的出现次数**
（4,983 / 5,979）—— 也就是说"一律 18px"等于把绝大多数表情都画小了（用户提这条的由来）。

## 二、实现：一路带到前端（`size` 以前是被丢掉的）

| 位置 | 改动 |
|---|---|
| `bili_emote.collect_emotes` | 索引值从 `(url, package_id)` 变 **`(url, package_id, size)`**；`_norm_size()` 收 int 与 str（上游在 `type` 上实测过"有时 int 有时 str"），认不出给 `None` |
| `bili_emote.build_index`（第二源） | 同样的三元组，size 取自脸的 **`meta.size`** |
| `bili_emote.resolve` | 返回 `{token: (url, size)}`（原来是 `{token: url}`） |
| `app_meta` 里的索引 | 格式带版本号 **`{"v": 2, "items": …}`**；读到旧格式（没有 `v`）**全量重扫一次**（0.71s，一次性）。⚠️ 不做这一步的话，升级后索引里**永远没有 size**，前端就永远按小表情画 —— 而且一声不响 |
| `GET /emoji/resolve` | `items` 的值从 URL 串变**对象** `{"url": …, "size": 1|2|null}` |
| `GET /emoji/packages` | 诊断里加了 `payload_small` / `payload_large` / `payload_size_unknown` |
| `PostText.tsx` | 按 `size` 选类名：`2` ⇒ `.post-emoji--big`，`1`/`null` ⇒ `.post-emoji` |
| `posts.css` | 两档尺寸与对齐只写在这儿：小 `15px` / 大 `32px`，对齐 **`-(尺寸/2 - 5)`** |

**对齐用同一条规则**：`vertical-align = -(尺寸/2 - 5)` —— 让两档表情的**中心**都落在基线往上 5px
（14px 正文的文字中心约在基线往上 3.5px）。不这么做的话，大表情会吊在半空或沉到底下。

**尺寸怎么定的**（我定的两个数，用户可在对照页里调）：小 `15px`（1.07×，**不撑行高**）、
大 `32px`（2.29×，**会把行撑到 32px** —— 贴纸本来就该占地方，B站 也一样）。实测：

| 档 | 尺寸 | 比例 | 实测行高（正文行高 20px） |
|---|---|---|---|
| 小（size=1） | 15px | 1.07× | **20px**（不撑） |
| 大（size=2） | 32px | 2.29× | **32px**（撑高 12px） |

## 三、判据

- pytest **+3 → 28 条**（`tests/test_emoji.py` 25 → 28）：★`build_index` 读 `meta.size`（含字符串、
  含认不出的怪值 ⇒ `None`）× 2 条（第二源 / 第一源各一）；★**旧格式索引触发全量重扫**
  （不做这条，升级后 size 永远缺席）；另有既有用例按新形状改（`items` 变成对象、索引三元组）。
- vitest **+1 → 1449**：★`size=2` ⇒ 大档、`size=1`/`null` ⇒ 小档（**并钉住"不按官方/自定义判"**：
  用例里 `size=2` 的那枚就是官方路径的）；`PostDetailDrawer` 那条加了接线断言（`size=2` 真带 `--big`）。
- 真机覆盖探针：多了"两类大小各多少"一行（现数：小 996 次 / 大 4,983 次）。

## 四、给用户看的实现（`_tmp_emoji_size.html`）

一份**自带字体与图片**的对照页（离线可开），内容：

1. 他截图里那两条帖子 —— 左列"旧：一律 18px"、右列"新：按 size 分档"，**真表情内嵌**；
2. 两个滑块（小 / 大）实时调，并报**实测行高**（哪一档开始撑行高）；
3. 两行"尺"（保证单行）用来量行高 —— ⚠️ 这里踩了一次自己的坑：第一版按"段高 ÷ 行数"算，
   而真实那段会折行（量出 40px）⇒ 改成专门放两行单行的尺子。

## 五、口径记一笔

`size` 是 **B站 的字段**，不是我定的口味 —— 所以我们**不猜**：`null`（上游没给）按小表情画，
而不是按"名字里有没有下划线"或"地址像不像官方"去推。这条写进了服务与端点的文档串。

## 六、顺手修掉一条**假绿**判据（A 档 pytest 就红在它）

这批跑 A 档时 `pytest` 随机红在 `test_sqlite_concurrency.py::test_data_survives_checkpoint_and_reopen`
（`assert after == 0` 得到 4152），**单独跑必绿**。查下去是两个问题叠在一起：

1. **`checkpoint_wal(engine)` 量错了文件**：它报的字节数取自 `_database_path()`
   （= `DATABASE_URL` 那个**应用主库**），**不是传进来的引擎**。所以换库/测试场景下，
   日志里的"WAL 已回收 X MB"和这条判据量的都是另一个文件。
2. 于是那条判据**单独跑时空过**（主库 WAL 恰好空 ⇒ `before == after == 0` 直接满足），
   整仓一起跑时主库 WAL 里有几千帧、别的连接还开着 ⇒ 截不掉 ⇒ 红。**判据量错文件**就是这么隐蔽。

**修**：`checkpoint_wal` 改成按**传进来的引擎**算 WAL 路径（`_wal_path_for()`，内存库退回原路径）；
用例补一条 `assert got["before"] > 0` —— 先证明"真有东西可截"，`after == 0` 才不是空过。
**反向验证**：把 `wal_checkpoint(TRUNCATE)` 改成 `PASSIVE`（不截断）⇒ 该用例**当场红**；
还原 ⇒ 绿。
