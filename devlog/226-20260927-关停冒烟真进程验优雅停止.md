# 226-20260927-关停冒烟真进程验优雅停止

批次 6 的补充（TODO §1.1「真机"关停"冒烟」）：**把"优雅停止"那一半从"只能真机"变成机器判据**，
并顺带查清一个更根本的问题 —— 打包版**根本不会**走到那条路径。

## 一、它原来为什么只能真机

- `tests/test_scheduler_lifecycle.py` 那条是**拿替身直接驱动 `app.main.lifespan`**（不起真进程）；
- `scripts/dev_check.py` 的后端冒烟收尾是 `proc.terminate()` —— Windows 上那是
  **TerminateProcess（硬杀）**，lifespan 不跑 ⇒ 优雅停止一条判据都没有。

## 二、⚠️ 查清的第一件事：**打包版永远不会优雅停止**

把退出路径逐条读了一遍（`lib.rs` + `backend_main.py`）：

| 退出方式 | 实际动作 | lifespan 跑吗 |
|---|---|---|
| 关窗/托盘退出（R20 两种现场） | `RunEvent::Exit` → Job Object 关句柄 或 `taskkill /PID /T /F` | ❌ 硬杀 |
| 壳进程被杀 | 后端看门狗 `_watch_parent` → `os._exit(0)` | ❌ 硬杀 |
| 迁移数据目录 | `stop_backend()` → `child.kill()` | ❌ 硬杀 |

⇒ **批次 6 做的"调度运行时优雅停止"在打包版里是死代码**：那行日志永远不会出现在真机上。
要让它在真机出现，得先给壳加一条**礼貌通道**（见 §五，待拍板）。

## 三、能自动化的那一半：`scripts/shutdown_smoke.py`

Windows 上没有可投递的软 SIGTERM（`os.kill(pid, SIGTERM)` 也是硬杀），父进程唯一的礼貌通道是
**控制台 CTRL_BREAK**（子进程收到 `SIGBREAK`），而 uvicorn 默认只处理 SIGINT/SIGTERM ⇒
`backend_main.py` 里补了 **6 行**：把 `SIGBREAK` 接到同一条优雅路径（`server.should_exit = True`
→ 主循环退出 → lifespan shutdown → 调度运行时停止 + 线程 join）。

冒烟脚本起**真进程**（`python backend_main.py`，独立进程组 + 真数据目录），四条判据：

1. **前提**：`logs/app.log` 里有「调度运行时已启动」—— 没起来过就谈不上"优雅停止"
   （空转不是通过）；
2. 发完 CTRL_BREAK 后进程 **≤15s 内退出**；
3. **退出码 = 0**（见下面那条教训）；
4. `logs/app.log` 出现「调度运行时已停止（N 个线程已退出…）」。

⚠️ **没有控制台时发不出 CTRL_BREAK** ⇒ 打印 SKIP 并**按失败计**：这条冒烟的要点就是那份"优雅"，
发不出信号等于什么都没验。

**实测**：`/healthz` 就绪 1.6s → 发信号 → **0.36s 退出、码 0**、日志命中
「调度运行时已停止（3 个线程已退出，取消在飞轮次 0 个）」。

## 四、反向验证三刀（都精确报红）+ 一条教训

| 刀 | 改法 | 结果 |
|---|---|---|
| A | 拆掉 SIGBREAK 处理器 | **退出码 3** ⇒ 判据 3 变红 |
| B | 调度运行时的停止日志改词 | 判据 4 变红（进程码仍 0 —— 说明两条判据各管一件事） |
| C | 根本不启动调度运行时 | **前提**判据拦下（不必看后面） |

⚠️ **刀 A 的教训值得记**：拆掉处理器后，进程**居然还是**打了「调度运行时已停止」——
CTRL_BREAK 在没有 Python 处理器时变成 `KeyboardInterrupt`，`asyncio.run` 在收摊时照样跑了
lifespan shutdown，只是 `backend_main` 的 `except BaseException` 把它记成异常退出（码 3）。
⇒ **只靠"日志命中"会漏掉这种"半优雅"的收场，退出码那条判据不是多余的。**

## 五、剩下的那一半（待拍板，不是这次能做掉的）

让**打包版**也优雅停止，需要给壳加一条礼貌通道，两条路：

- **A. 后端加 `POST /shutdown`（token 守卫）**：`RunEvent::Exit` 里先 POST（≤3s），
  进程没退再 `taskkill /F` 兜底。优点：与进程组/控制台无关，确定性强；
  代价：后端多一个端点（路由数与文档要同步），退出路径多一个超时分支。
- **B. 壳发 CTRL_BREAK 给 sidecar 进程组**：不用动后端，但依赖 Tauri shell 插件给的进程
  **是不是独立进程组**（今天不确定）⇒ 得先验。

⚠️ **别顺手做**：退出路径改错的后果是"关不干净 / 卡住不退出"（R20 为此专门验过两种现场），
而且现在这条路径上**没有自动化判据**。已记进 `TODO.md` §1.1（含这次的证据）。

## 七、⚠️ 本脚本第一版被门禁拦下（§6.13 的又一次实证）

第一版 `shutdown_smoke.py` **没注入开发态 token** ⇒ `tests/test_dev_token.py::
test_every_script_that_starts_a_backend_passes_the_dev_token` 直接判红：

> 这些脚本起了后端但没把 token 并进它的 env：['shutdown_smoke.py'] —— S1 起它们打自己的后端
> 会逐条 401，而症状看起来像网络/上游坏了

正是 `DEV-LOOP.md` §6.13 那条规矩（"加了门禁之后，把所有'打自己后端'的调用方过一遍"）的
自动化版本：**新写一个起后端的脚本，就得同时把 token 带上**。修法是加两行
（`sys.path.insert` + `from dev_token import backend_env`）并在 env 里 `**backend_env()`；
修完那条用例 4 passed，冒烟照旧通过。
