**卡片为什么自己取数**：档案视图每张卡的数据源不同（本地字段 / 帖子接口 / 以后的大事记 / 时间线），
让页面上层统一取数就意味着页面要认识"卡片需要什么"—— 注册表的意义正是让视图**不认识**任何具体卡片。

**窄窗阈值 560 是量出来的**：探针三档窗口下网格容器实宽 **1100→498 · 1280→678 · 1440→838**
（面板要减掉图标栏 50 与左栏）。默认布局是 5+7 两张卡，窄的那张占 5/12 ≈ 0.42×W，
留住 ~220px 可读宽度需要 W ≥ ~530 ⇒ 取 560。第一版我按窗口宽猜了 900 ⇒ **三档全是单列**
（多列分支根本没被走到），改成 560 后 1100 单列、1280/1440 十二列，**两个分支都真的验到**。
阈值本身经 `data-board-narrow` 下发给探针（跨语言契约，免得 TS 与 Python 各写一份数字漂掉）。

## 四、护栏（反向验证 5/5 全红）

默认探针（三档宽度 × 四视图）新增 `_assert_board`，判据五条：

1. 档案视图里**必须有**画布，且卡片 = 注册的两种内置卡（纪念日 / 优质投稿）；
2. 每张卡的**实渲染高 = 模型算的像素高**（`ROW_H×h + GAP×(h-1)`）—— 高度不被网格算死时相邻行会被压住；
3. 卡片**不重叠、不出网格**（只读布局的硬不变量，P2 的拖拽复用同一套几何）；
4. **窄窗单列**：容器宽 < 阈值 ⇒ `cols==1`，否则必须 12 列；阈值本身还要落在 **400–1200** 的合理区间
   （判据自洽看不出阈值定得对不对：定成 100 卡片会挤成一条、定成 3000 则永远单列 —— 都是"断言全绿但用户看着不对"）；
5. 卡片**内容非空**：纪念日必须有两行（标签 `生日`/`出道`）+ 底部提示；优质投稿必须"要么有榜单行、
   要么有一句明说的空态"（**空态文案也算内容**，但必须是明说的那种）—— 防"卡片挂上了但里面什么都没渲染"。

**反向验证**（把实现逐条改回坏行为，5 项全红）：

```
卡片高度不由网格算死（grid-auto-rows: auto） → RED（实渲染 125px vs 模型 276px）
窄窗阈值定成 100                            → RED（超出合理区间 400–1200，三档都报）
两张卡摆在同一格                            → RED（1280/1440 重叠；1100 单列天然不重叠）
纪念日卡什么都不渲染                         → RED（渲染了 0 行，应为 2）
优质投稿卡什么都不渲染（连空态都没有）        → RED（既没有榜单行也没有空态文案）
```

**实跑输出（三档）**：

```
@1100  画布：2 张卡 · 容器 498px · 单列   · 高度与模型一致、无重叠无越界
@1280  画布：2 张卡 · 容器 678px · 12 列  · 高度与模型一致、无重叠无越界
@1440  画布：2 张卡 · 容器 838px · 12 列  · 高度与模型一致、无重叠越界
```

## 五、本批踩到/留档

1. **`parseAnniversary` 第一版拿 `m.length` 判"有没有年份"**：正则的可选组缺席时 `m[1]` 是
   `undefined`，`Number(undefined)` 静默变成 `NaN` ⇒ 单测当场抓住（"前后空格不影响"那条）。
   教训：**可选捕获组要用 `== null` 判**，别用 `length`。
2. **阈值必须实测**（见 §三）：凭窗口宽猜阈值 = 多列分支静默不生效。
3. **改名要连带改探针的选择器前缀**（见 §二）。
4. `topPosts` 的"点赞兜底"必须**如实标 metric**（卡片上写"播放"还是"点赞"）——
   不然一个微博号看起来像"播放量只有 30"。
