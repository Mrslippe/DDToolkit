# 412-20261007 进出全屏加一段过渡（View Transitions）

用户口径：「**现在全屏回到小窗有点生硬**」。问下来是**硬切**那一类 —— 没有动画缓冲，
满屏一下就缩回卡片（不是闪、也不是布局跳）。

## 为什么会硬切

**HTML 全屏本身就是一帧内完成的**：`requestFullscreen()`/`exitFullscreen()` 做的是把元素
放进/移出 **top layer**，尺寸**不参与过渡**。所以这不是这轮还原弄坏的，是浏览器一直的默认行为
——只是 B2 那阵子全屏里外差别更大（图层被撤掉/底色被切），硬切反而不那么显眼。

## 修法：`document.startViewTransition()`

它正好是为这件事设计的：给元素一个 `view-transition-name`，浏览器就把"切换前的快照"和
"切换后的快照"**morph + 交叉淡入**。

| 文件 | 改动 |
|---|---|
| `VideoPlayer.tsx::toggleFs` | 用 `startViewTransition` 包住那一对 `request/exitFullscreen()`；**API 不存在就直接切**（纯装饰，缺了不许影响功能） |
| `posts.css` | `.vp { view-transition-name: vp-player }` + `::view-transition-old/new(vp-player) { animation-duration: .22s }` + `prefers-reduced-motion` 下归零 |

## 落笔时咬住的一个细节（也是判据咬的那一条）

⚠️ **回调必须把 `requestFullscreen()/exitFullscreen()` 的 Promise 交出去。**
这个 API 是"跑回调 → 等它的 Promise 落定 → 才截新状态快照"；回调里空转的话，
会在窗口**还没变尺寸**时截到一张和旧状态一样的快照 ⇒ **过渡跑了但画面什么都没变**
（而且看起来像卡了一下）—— 那比原来的硬切更糟。

⇒ 判据 `keys.test.tsx`：有 API 时必须调用它**一次**，并且**手动跑一次回调**、断言回调里
真的去了 `requestFullscreen`。**反向验证过**（把 API 分支短路 ⇒ 只这条红）。
前端判据 1119 → **1120**。

## 没做的事（免得下次有人以为漏了）

- **没动 `UI-MAP.md`**：那份文档里根本没有"播放器全屏"这一行（`vp:fullscreen` / `requestFullscreen`
  都搜不到），所以没有"现状描述"需要跟着改。这条是**刻意跳过**的，不是忘了。
- **没做"缩回卡片"的自绘动画**（把元素从满屏 tween 回卡片）：那要自己在退出全屏后接管几何，
  与 top layer 的进出会打架；View Transitions 是同一效果的**原生**版本，先用它。

## ⚠️ 要真机确认

`.22s` 是个起点值：**太长**会显得拖沓（尤其来回快速切），**太短**等于没变。
真机上试几次，觉得不合适我调 `posts.css` 里那个数就行（一处）。
另外要看一眼：过渡期间画面是**快照**（相当于冻 0.22 秒）—— 这是该 API 的正常行为，
但如果你觉得"画面顿一下"比"硬切"更难受，那就该退到更轻的方案（只淡入不 morph）。
