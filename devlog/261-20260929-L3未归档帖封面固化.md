## 二、⚠️ S-5：实测收益与前提不符 —— 封面**不是**"轻"资产

执行方案 §L3 的停止条件写着：「**实测收益与预期不符**（例如图片请求数没降）⇒ 停下报告，
别把'省了'写进文档」。实测下来，**机制是对的，但前提错了**：

**真机实测（本机 dev 库，全部账号一轮）**

| 量 | 实测值 |
|---|---|
| 未归档且有封面的帖 | **214 条 / 212 个稳定键** |
| 第 1 轮固化（每账号限 20 张） | 121 张 / **121 次请求** / **133 MB** / **188.6s** |
| 第 2 轮（同一批已固化） | 71 张（上限之外的剩余）/ **已固化的那张 0 请求** ✓ |
| 全部固化后占用 | **194 份 / 220 MB**（平均 **≈ 1.1 MB/张**，最坏单张 **4.7 MB**） |
| 覆盖率 | 194/212 = **92%** 的未归档封面已有本地副本 |

⇒ 两条结论：
1. **"小、不变、反复要"里的"小"对封面不成立**：原图平均 1.1 MB，固化 212 张要 ~330 次请求 /
   ~330 MB / 好几分钟。规格 §6.1 的 1GB 默认上限按这个体积算**只够 ~900 张**。
2. **确定性收益成立**：已固化的那些，列表首屏读盘、**零远端请求**；重复滚动/重开不再回源。

**因此本批做了两件收敛**（不改 fidelity、只收紧节奏）：
- 加**字节上限** `COVER_PIN_MAX_BYTES_PER_ROUND = 24MB`（只按张数封顶时，一轮最坏能下 90+ MB）；
- 设置项的说明写清"每轮最多 20 张 / 24MB"，不再暗示这是"顺手做的小事"。

**没有做、需要你拍板的一件事（会改 fidelity）**：B 站的封面支持缩略变体 ——
同 8 张样本实测 **原图 14.00 MB vs `@672w_378h_1c.webp` 2.22 MB（16%）**。
代价两条（都实测到了）：① 只对 `hdslb` 域名有效（另一个图床的样本加了后缀返回空体）；
② 动图（gif）会变成**单帧** webp（实测 360×360）。⇒ 换不换是你的产品决定，
本批**不擅自改**已存/将存的图片规格。

## 四、踩到的两个坑（都是"本仓已经记过一次"的那类，值得再记）

1. **`app.dependency_overrides.pop(get_db)` 会摘掉别人装的全局**：
   新写的 `test_route_exposes_cover_local` 里 `pop` 掉 override 之后，后续 **46 条**
   `test_vtuber_api` 用例的 TestClient 转去读**真实数据目录**的库 ——
   症状是 `/vtuber/list` 返回 173 条真数据、以及 `no such table: vtuber_avatar_history`
   （那个文件在**模块导入时**就把自己的 override 装进 `app.dependency_overrides`）。
   ⇒ 凡是要动全局 override 的用例，**必须"保存 + 还原"**（照 `tests/test_vtuber_avatars.py` 的写法），
   不能 `pop`。这与"测试碰真实数据目录而它不会红"是同一族：**跨用例的全局状态**。
2. **加一个热更键 = 改四处，缺一处就红**：`runtime_settings.SPECS`（面板元数据）、
   `config.Settings` 的类属性（默认值的落脚点，缺它报"默认值没有落脚点"）、
   `test_runtime_settings` 的**可见/高级白名单**（有意决定，防"数量对了但项不对"）、
   以及**默认值对账表**。四条判据各红一次，一条都没漏过 —— 这正是那套白名单想达到的效果。
   （另：`docs/GLOSSARY.md` §7 配置项速查是人肉同步的那一处。）
