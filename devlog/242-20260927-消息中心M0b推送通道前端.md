# 242-20260927-消息中心 M0b：推送通道的前端半边

M0 的**前端半边**（`docs/design/notices/message-hub-execution.md` §M0b）。M0 只做了后端"能推"，
这一步让它"真的到界面"，并把"通道通了"变成可机器判定的判据。

## 二、三条定稿语义（都有判据）

1. **`replay: true` 不弹提示**（方案 §8.5 D）：重连补发的是历史，弹出来就是"每次断线重连
   重播一串旧 toast"。判据在 `messageBus.test.ts`。
2. **每条消息都发 `ddtoolkit:message`**：以后加消费者（M1 开播、M2 手动动作、M4 小窗）
   不用动本模块。
3. **类型字符串是跨语言契约**：`messageBus.test.ts` 直接**读后端源码**
   （`app/services/messages.py`）解析 `KNOWN_TYPES` 对账 —— 后端拼错会当场 `ValueError`，
   前端拼错只会**静默没人理**。

## 三、V5（token 不进 URL）落在四处，两处是行为判据

方案 §2.1 要求"锚定 `apiToken`，别写成搜 `token=`"（本仓 `xsec_token=` 会假红）：

- **行为**（最硬）：`eventStream.test.ts` 桩掉 `fetch`，断言实参里 URL = `/api/messages/stream`
  （**无 token、无 query**），而 `X-DDToolkit-Token` 在**请求头**里；
- **结构**：`messageBus.test.ts` 扫 `frontend/src/**`，`${apiToken}` / `${TOKEN_HEADER}`
  这类**插值**一处都不许有；且除 `api/api.ts` 外没有文件读 `apiToken`；
- 端点路径常量本身不含 `?` / `token`；
- 后端那侧：端点**不在**公开白名单（M0 的判据）。

## 四、判据与反向验证

`eventStream.test.ts` 14 条 + `messageBus.test.ts` 9 条（含跨语言契约与 V5 结构判据）
+ 探针 `--messages` 一条端到端（主流程三档顺带跑）。**反向验证 15/15 全红**
（13 条 vitest 变异 + 2 条探针变异：应用不起流 / 桥不弹提示）。

⚠️ **第一遍有两条变异是绿的 —— 判据没牙，已修**：

- "半个帧不交回调用方"没被抓到：原用例的切点落在**第一帧之前的半行**里，走的是"一行都没
  收全"那条早退分支，`rest` 的交回逻辑根本没被执行。改成"切在第二帧中间"才咬得住；
- "HTTP 401 也当成连上了"没被抓到：原用例的假响应是 `{ok:false, body:null}`，**`!res.body`
  那一半也能拦下它** ⇒ "必须看 `res.ok`"这条没人验。改成 401 带一个**真的流**。

## 五、顺手修掉一处既有缺口（S1 之后探针里的三处裸 `urlopen`）

做 `--messages` 时手动裸跑探针，路由落到了 `/`（`no-view-btn`）——看着像"数据目录里没有 V"，
实际是 **`_first_vtuber` 用裸 `urlopen` 打 `/vtuber/list`，S1 起恒定 401 ⇒ 静默返回 None**。
顺着查还有两处同款（`--board-cards` 与 `--board` 的 `profile-cards` 落库对账），
**实测** `--board-cards` 报 `读不回卡片布局（HTTP Error 401）`。三处都修了（改走
`urllib.request.Request(url, headers=DEV_HEADERS)`，值钉 `dev_token` 的常量）。

这类漏在本仓是**第三次**（`dev_check.py` / `smoke_upstream.py` 那次已经在 `DEV-LOOP.md`
§6.13 立过规矩）：⇒ 补了**结构判据** `tests/test_dev_token.py::test_probe_backend_calls_send_the_token`
（从 Python 侧打后端业务路径的每一发都要有 `headers=`，公开三处豁免），
并把 `ui_probe.py` 加进"必须接 dev_token"的名单。
