# 440-20261007-纱罩跟着界面元素一起渐隐渐显

用户：「现在背景遮罩又不会渐隐渐显了，改好，并且和界面元素的入退场匹配」。

## 原因：**是我上一批把它删掉的**

`devlog/438` 里我把两条"让位时纱罩渐隐 / 回来时渐显"的规则当成**死规则**删了 ——
当时刚经历过"纱罩整体撤掉"（`437`）又"改回 12%"（`438`），我以为那两条随纱罩一起作废了 ✗。
实际它们在 `438` 之后**仍然是活的**：纱罩回来了，就该跟着 `data-idle` 一起动。

⇒ 用户侧的现象正是"界面元素让位了、纱罩还压在背景图上"（背景图没有真正"完全显现"）。

## 改法（并按要求"匹配"）

两条规则重新加回，键在**同一个 `data-idle`** 上，用**同一套时长与曲线**：

```css
.app-shell[data-solo='1'][data-idle] … .hero-backdrop::after { opacity: 0; transition: opacity var(--solo-hide-ms) var(--solo-ease, ease) }
.app-shell[data-solo='1']          … .hero-backdrop::after { opacity: 1; transition: opacity var(--solo-hide-ms) var(--solo-ease, ease) }
```

- **匹配** = 同一个 `data-idle` 键 + 同一套 `--solo-hide-ms` / `--solo-ease`（界面元素那条用的也是它们）；
- 纱罩**没有"位移"那一半** —— 它是一层颜色，滑不动，只有透明度；
- ⚠️ 这两条**不加 `!important`**：`::after` 上没有别的动画在写 `opacity`
  （`backdrop-out` 动的是**图层**的 `opacity`，父层透明度与子伪元素相乘，互不干扰）。

## 判据（+1）

★「纱罩跟着界面元素一起渐隐/渐显，且同一套时长与曲线」：断言两条规则分别在 `opacity: 0/1`
**且都引用 `--solo-hide-ms` 与 `--solo-ease`**，并**配正对照**（界面元素那条也是同一套，
否则"匹配"无从谈起）。**反向验证过**：删掉"让位时纱罩渐隐"那条 ⇒ 当场红（这正是用户报的回归）。

⚠️ 顺手又踩到一次"同名规则两份"：那条断言原来用 `indexOf('.hero-backdrop::after {')`，
会**先命中 solo 那条**（它也含这个子串）⇒ 改成行首锚定（`\n.hero-backdrop::after {`）。
与 `devlog/439` 的教训是同一条：**先确认自己看的是哪一份规则**。
