# 506-20261015 录播号按 V 独立 + 小窗条目化与拖动排序

## 用户报的与拍板的

> 不同主播的第三方录播号是独立的，现在**所有主播都复用了我自己输入的录播号**。
> 修改为每个主播的录播号都是独立的，并且可以支持在弹窗内：
> ① 输入录播号后保存为固定条目，展示为 `| 昵称 mid 投稿数 |`；
> ② 拖动条目的上下位置进行排序，越上面的优先级越高。
> （先出 HTML 方案稿 → 拍板：新号进**末尾** · 昵称查不到**允许保存** · 显示**最近投稿** · **上限 5 条**）

方案稿：`_probe/mockups/vod-account-dialog.html`（可拖动、四态可切），定稿后按它落地。

## 一、串号的根因在前端（服务端从头就是对的）

`vtubers.vod_account_uid` 是**每个 V 一列**，没问题。问题在 `PostsPage`：

```tsx
const [vodUidOverride, setVodUidOverride] = useState<string | null>(null)   // ← 整页共用一份
vodAccountUid={vodUidOverride ?? vtuber.vod_account_uid ?? null}
```

那个"存完立刻回显"的覆盖值没有跟 V 绑定，而 `??` 左边一旦有值就**永远赢** ——
给明前奶绿存过一次 `94009831` 之后，切到哪个主播显示的都是它；
更糟的是在别人那儿点保存会把那个号**写进别人的字段**。

⇒ 改成 `{vtuberId, mids}`：只有**同一个 V** 才用覆盖值，其余回落到服务端那份。

## 二、小窗：从"一个逗号文本框"改成"条目 + 拖动"

| | 旧 | 新 |
|---|---|---|
| 展示 | 一串逗号分隔的 mid | `\| 头像 昵称 · mid · 1093 条投稿 · 最近 2026.10.11 \|` |
| 排序 | 手工剪切粘贴，靠记得谁在左边 | 拖 `⠿`（手柄是可聚焦按钮，`↑/↓` 也能换位） |
| 新增 | 直接往串里打字 | 输入 mid 或主页链接 → **查询** → 预览 → 添加到**末尾** |
| 查不到 | —— | 标黄 + 「昵称未取到」，**仍然能加** |
| 上限 | 无 | **5 条**；满了禁用输入与查询；⚠️ **已有的超过 5 条不静默丢**（照旧能保存） |

**存出去的东西没变**：仍然是那个逗号串（左 = 高优先）⇒ 服务端与扫描逻辑一个字都没改。

## 三、数据从哪来（新端点）

`GET /vtuber/vod-accounts/resolve?mids=1,2,3` → 一次把一屏的资料查回来（并发）。

- **昵称/头像**：`x/web-interface/card`（**匿名可用**，实测 `94009831 → 虚拟JK`）；
  ⚠️ 别用 `x/space/wbi/acc/info` —— 那个匿名是 `-352 风控校验失败`（同一天实测）。
- **投稿数 / 最近投稿**：复用登录态的 `arc/search`（`ps=2`，只要 `page.count` 与最新一条的时间）。
- **两半各自独立失败**（`name_error` / `uploads_error`）：这就是"昵称查不到仍允许保存"的落点；
  `uploads` 取不到是 `None` **不是 0**（0 会被界面显示成"0 条投稿"）。
- 超过 12 个 mid 截断（每个 mid 两次上游，不限量就是放大器）。

⚠️ **路径踩了两次坑**：`/vtuber/vod-accounts`（一段式）被先注册的 `/vtuber/{vtuber_id}` 抢走；
改两段的 `/vtuber/vod/accounts` 又被 `/vtuber/{vtuber_id}/accounts` 抢走 ——
两次的症状都是 **422 `int_parsing`**（`vtuber_id` 解析不了 `vod`），而路由根本没进来，
看起来像"参数写错了"。最后落在 `/vtuber/vod-accounts/resolve`（没有任何 `{vtuber_id}`
路由的第二段叫 `resolve`），并把"顺手断言 200"写进用例 —— 只断言"服务层被调用"会漏掉这一整类。

## 四、顺手收口：同一个字段的第二个写入口

「添加录播」小窗里那个"记住这个号"（找录播时顺手存）写的是**同一列**。
两个入口规则不一致就会互相拆台（一个能存 6 个、一个归一去重）⇒
`VodDialog` 改成从 `VodAccountDialog` import `parseMids` / `VOD_ACCOUNT_MAX`：
归一形态一致、超上限时按钮禁用并给出"去哪改"的提示。
