# 428-20261007-V1d3取景解耦与默认调视频

用户报的两条（2026-10-07）：

> 「现在同时有图片和视频的时候调整图片位置会影响视频位置」
> 「并且如果有视频的话默认取景框是视频取景」

## 一、图与视频互相影响 —— 真 bug，`transform` 会带走整棵子树

**根因**：取景的三件套是**挂在 `.hero-backdrop` 那一层**上的，而视频是该层的**子元素**
（`devlog/424` 把它做成"盖在同层图上面"）。`background-position` 只动背景图、**不影响子元素**，
但 `transform: scale()` 会 —— 于是**调图的缩放等于把视频一起放大**（用户看到的"调整图片位置
会影响视频位置"，其实是缩放那一下在带走视频）。当初只想到"位置不吃子元素"，漏了缩放。

**改法**：图挪进**内层** `.hero-backdrop-img`（取景挂它），视频留作**兄弟节点** ⇒
两者**结构上**再也不可能互相影响。这与设置页预览的结构一致（`devlog/427` 那版预览本来就是
"图一层 + 视频一层"），是把真机结构对齐到已验证的预览结构。

⚠️ 外层**不再带** `background-size/position`（图不在它身上了）—— 留着会让人以为图还在外层。

## 二、有视频 ⇒ 默认调视频

`target` 的初值从"写死 image"改成 `videoSrc ? 'video' : 'image'`：**视频是盖在图上、观众看得见
的那一层**，进来先调看得见的那层；图的取景点左上角切过去。
另加一条：**弹窗开着时后传视频** ⇒ 自动切到视频（那一刻的意图就是"调这段视频"）。

## 判据（净 +2：crossfade 1 条 + CSS 1 条，另有 3 条被改写成新口径）

- ★ **取景变换不许挂在外层**（`expect(layer.style.transform).toBe('')`）—— 就是这次这个 bug 的机器判据；
  同时断言图那层**有** `background-position` + `scale(2)`（正对照：否则"外层没有"什么都证明不了）。
- ★ **图在**内层 `.hero-backdrop-img`（CSS 契约：`position:absolute` + `inset:0` + `background-size:cover`，
  且**外层不许再有** `background-size`）。
- ★ **有视频 ⇒ 默认调视频**（切换钮文案 + 预览已经是视频首帧）· 只有图 ⇒ 没有可切的钮。
- ★ **重置取景打当前那一份**改成**双向**判：默认（视频）⇒ 清视频；切到图片 ⇒ 清图片，且视频那个端点
  总共只被叫过一次（顺带钉住"两边不互相触发"）。

**反向验证**（四组）：把取景**挂回外层** ⇒ 分离那条红（就是用户报的回归）；默认目标改回 `image`
⇒ 默认那条与首帧那条红；内层去掉 `position:absolute` ⇒ CSS 契约红；取景整个从内层拿掉 ⇒ 3 条红。

## 又一次"观测方法"的坑

突变脚本第一版用**双引号** PowerShell 串去匹配 JSX —— 里面全是反引号（模板字符串），
而反引号在 PS 双引号串里是**转义符** ⇒ 匹配字符串当场变形、`Replace` 什么也没换，
输出"生效：False"。同一类问题这个批次已经出现三次（`422`/`425`/`427`）。
⇒ 结论固化成一句：**改文件的脚本，第一件事是断言"我真的改到了"**，而且**含反引号的 JSX 一律用单引号串**。
