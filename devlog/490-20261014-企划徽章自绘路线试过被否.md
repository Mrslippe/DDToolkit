## 一、做到哪一步

- 从 14 张参考里归纳出绘制语言 8 条（一色为主 / 零渐变 / 两种笔法各自等宽 / 硬边 / 满幅靠负空间留白 /
  容器是几何体 / 允许反白 / 文字极少），并如实划出**做不到的 3 张**（骷髅玫瑰、羱羊剪影、毛笔书法）。
- 按这套语言出了 **4 枚试水稿**（VirtuaReal / 四禧丸子 / EOE组合 / 个人势）。
  验收手段 = 「先按 20×20 **真实栅格化**、再最近邻放大 12 倍」的像素图，走**无头 Edge 截图**
  （与 `ui_probe` 同一条链路，不需要 Pillow 或任何图像库）。

## 二、为什么自绘这条路不成立（**这三条是留档的重点**）

| 现象 | 数 |
|---|---|
| 简笔「个」在 128px 下完全正常，**20px 下读成向上箭头** | 竖笔出头 + 宽人字 |
| 「四」的方框 + 儿在 20px 下读成「」し」 | 方框内两笔太密 |
| `E●E` 三个字形糊成一团 | 笔画 1.7px + 间隙 1.2px；换成单个粗 `E` 才成立 |
| 有底色稿的可用字形只剩画布的 58% | 扣掉容器后就没多少地方了 |

⇒ 20px 这个槽位（`.vtuber-emblem-icon` 固定 20×20）**只容得下 1–2 个字形**，
而企划名多数是 3 个字以上 ⇒ **要么牺牲可读性、要么牺牲"像不像"** —— 用户选了两者都不要。

## 三、最终口径（用户 2026-10-14 拍板）

1. **素材保持空缺**：徽章维持**文字胶囊**，这就是当前终态（已记 `docs/TODO.md` §5 已搁置）。
2. **用户给的那 3 张原图也不加进来**（未处理 + 第三方美术）。
3. 三条来源路**全部不要**：现成库（没有）/ 运行时抓官方账号头像（实测可行，但属未获许可的复制）/ 自绘（效果差）。
4. `frontend/src/assets/groups/` 的**手工投递通道照旧留着** —— 哪天有处理好的图，丢进去即生效、不改代码。
