# 317-20261004 播放器四处改进：hover 延时、会员徽标、跳转先暂停、播完重新播放

> 用户（附参考图）四条：
> ① 「控件 hover 触发的时间拉长一点，以防鼠标扫过就呼出上拉栏」
> ② 「需要大会员的图标改为如图类似的圆圈中一个大字的 svg」
> ③ 「点击进度条跳转的时候先暂停视频，直到跳转完成后再开始播放，现在的情况是点击跳转后
> 依旧会接着播放原先的内容直到跳转完成后再开始播放跳转之后的内容」
> ④ 「视频播放完后冻结在尾帧，显示重新播放的图标，点击后从头开始播放」

## 一、hover 延时（①）

`useHoverMenu()` 拆成两个时间常数：**呼出延时 `HOVER_OPEN_MS=240`**（扫过不弹）、
**收起宽限 `HOVER_GRACE_MS` 140→180**（穿缝不断）。已经开着的浮层被再次 hover **不再等延时**。
判据里专门有一条"**扫过不弹**"：hover 80ms 就走 ⇒ 菜单一次都不许出现。

## 二、会员徽标（②）

`Crown`（lucide 王冠）换成自绘 `VipBadge`：**圆圈 + 「大」三笔**（一 + 丿 + 捺），
`viewBox 0 0 16 16`、`stroke=currentColor`（跟着档位名一起变淡）。类名 `.vp-crown` → `.vp-vip`
（名字与画的东西对齐）。为什么不放文字：12px 的徽标用字形会受字体/基线影响，自绘笔画不看这些。
判据：圆圈 + 3 条 path，`aria-hidden`（无障碍名仍走档位的 `title`/`aria-label`）。

## 三、跳转先暂停（③）

`pauseForSeek()`：提交一次跳转（点击 / 拖拽松手 / 方向键）**先 `pause()`**，等目标段落地再接着放。
两条必须一起做的口径：

- 这一下暂停要记成"**我们按的**"（`holdRef.selfAt`），否则 `onPause` 会把它当成用户暂停
  ⇒ `wantPlay` 翻掉 ⇒ **跳完再也不放**（`devlog/302` 的同一个坑）；
- 和解那一拍要把"跳转中"也算成**语义上仍在播**（`mseTargetRef != null || seekRef.settling`），
  否则每 250ms 一次的和解把界面按回暂停（底栏图标翻 ▶）。
- 恢复点：MSE 走 `onSeekApplied`，渐进式走 `seeked`（`settleAudio` 的 `apply` 里补了
  "视频轨自己也要接回去" —— 顺带修好了**没有独立音轨的单文件档**（小红书/微博）以前的空档）。

## 四、播完冻结 + 重新播放（④）

- 判定有**两条来源**：元素的 `ended` 事件，以及 `timeupdate` 里"位置到尾 + 停着 +
  不是我们按住的 + 没在等跳转"（MSE 侧没有 `endOfStream()`，`ended` 不保证发 —— `devlog/314`）；
- 中央那颗"重新播放"（`.vp-bigplay.vp-replay`：图标 + 一行小字）与普通大播放键**互斥**渲染
  （两颗都在正中会叠在一起）；
- 点击 ⇒ `kernel.seekTo(0)`（MSE：播到末尾时开头可能已被淘汰，得让内核去取第 0 段）
  或直接写 `currentTime=0`（渐进式），然后 `startPlayback()`。
