# 013-20260817-v0.3.2-修复建议落地

## 概述

根据架构分析报告（docs/项目架构分析报告.html §16/§17）的修复建议，逐项落地 bug 修复，并新增单元测试验证。

## 修复清单

### P1 · 日志文件恒为空（已实证修复）

**根因**：`app/services/scheduler.py` 在模块导入时先调用了 `logging.basicConfig()`，
使 `app/main.py` 中的 `basicConfig(handlers=[FileHandler, StreamHandler])` 被静默忽略——
`logs/app.log` 始终 0 字节。

**修复**：删除 scheduler.py 中的 basicConfig 调用，根日志配置统一由 main.py 完成。

**验证**：启动服务后 `logs/app.log` 正常写入（启动/导入/调度/认证日志共 13+ 行）。

### P2 · 风控状态全局变量并发污染

**根因**：`fetcher.py` 的 `_rate_limited` 是模块级全局变量，账号抓取与帖子抓取
并发运行时可能互相误读风控状态。

**修复**：改为 `contextvars.ContextVar`，风控状态按任务上下文隔离；
`scheduler.py` 在每次抓取任务开始时调用 `clear_rate_limit()` 重置为干净初值。

**验证**：`tests/test_services.py::test_rate_limit_isolated_between_tasks` ——
并行任务中触发风控不影响观察任务。

### P3 · 配置版本号未同步

`app/core/config.py` 的 `VERSION` 由 `0.1.0` 更新为 `0.3.1`，与 devlog 保持一致。

### P4 · 动态类型映射缺项 + 存量数据修复

- `_map_dynamic_type` 补充 `DYNAMIC_TYPE_MUSIC → "music"`，并增加 major.type
  含 `MUSIC` 时的反推兜底；
- `app/models/vtuber.py` 的 Post.type 注释同步补充 music 类型；
- 新增 `scripts/repair_post_types.py`：一次性将存量 7 条
  `type='dynamic_type_music'` 修复为 `music`（幂等，已执行，剩余 0 条）。

### P5 · 其余小项

| 项 | 修复 |
|----|------|
| 头像扩展名判定 | `_avatar_ext()` 从 URL 路径推导扩展名（jpg/jpeg/png/gif/webp），未知回退 .jpg；原 ".jpg in url" 判定会把 gif/webp 存成 png |
| alembic/env.py 耦合 | `from app.main import Base` → `from app.core.database import Base` + 显式 `import app.models.vtuber`，迁移上下文不再加载整个 FastAPI 应用 |
| CORS 规范 | 来源列表可配置（`CORS_ORIGINS`，默认 `*`）；通配符来源时 `allow_credentials=False`（浏览器 CORS 规范要求），仅显式来源列表时允许凭据；`.env.example` 增加示例 |
| httpx 连接复用 | fetcher 各接口函数新增可选 `client` 参数；scheduler 的账号抓取/帖子抓取任务各复用一个 `AsyncClient`（含重试与风控冷却期间），结束统一 `aclose()` |
| importer 可测性 | `import_from_file` 新增可选 `db` 注入参数；顺带修复列表文件不存在时未关闭自建会话的小泄漏 |
