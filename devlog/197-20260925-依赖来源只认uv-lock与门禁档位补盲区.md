# 197-20260925-依赖来源只认 uv.lock + 门禁档位补两处盲区

用户口径：「那就 uv 吧」。本批只做一件事——**让"发出去的版本"可复现**；顺带被锁文件咬出两个真 bug。

## 一、为什么必须做（不是"最佳实践"，是两个具体缺口）

1. `requirements.txt` 只有 `>=`，**没有锁文件**（前端有 `package-lock.json`、Rust 有 `Cargo.lock`，
   **只有 Python 侧不可复现**）。而 `scripts/build_backend.py` 是直接拿"当前解释器里装了什么"
   去冻结 exe 的 ⇒ **发布产物装的是"跑构建那天的版本"**。
2. 因此 `requirements.txt` 里还躺着 `pytest` —— PyInstaller 把它一起打进了用户的包。

**先补的失败用例**：`tests/test_gate.py`（`gate.py` 此前**一条测试都没有**）。7 条断言里
3 条在实现前必然是红的（Rust 档位、依赖来源档位、A 档的 cargo 步骤）。

## 二、改了什么

- 新增 `pyproject.toml` + `uv.lock`（**唯一真源**）；`requirements.txt` 降级为
  `uv export --frozen --no-dev` 的**只读导出产物**（531 行 / 494 个 hash / 零个 `>=`）。
- 依赖分组：运行依赖 = `dependencies`；`pytest` → `dev` 组；`PyInstaller` → `build` 组。
  **这是"用户拿到的包"与"开发机装的包"第一次真正分开。**
- `scripts/build_backend.py` 加环境守卫：**拒绝在非 `.venv` 里构建**，构建前用
  `uv sync --frozen --dry-run` 复核"环境 = 锁文件"，并**自动补装 `build` 组**（`uv sync`
  默认只装 `dev`，不让人去记 `--group build`）。
- `scripts/gate.py` 补两处**会静默失去守护**的档位盲区：
  `frontend/src-tauri/**`（原先落 C 档 ⇒ 改**删除数据目录**那条 Rust 命令时 `cargo test` 一次都不跑）
  与 `pyproject.toml` / `uv.lock`；另加 A 档的 `cargo test` 步骤、`scripts/gate.py` 自身入 A 档。

## 三、被锁文件咬出来的两个真 bug（本批真正的收益）

1. **`python-multipart` 从来没被声明过。** 它是 `UploadFile` / `Form(...)` 路由的硬依赖，
   缺失时**注册路由即抛 `RuntimeError`**（4 个测试文件直接收集失败）。它此前能跑，只是因为
   系统 Python 里**别的包顺带装了它**——典型的"没锁文件就不知道自己在依赖什么"。已显式声明。
2. **`tests/test_services.py:127` 把整个 `_test_tmp` 根目录 `rmtree` 掉了。** 而
   `test_vtuber_api.py` / `test_profile_cards.py` 用 `tempfile.mkdtemp()` 在工作区临时目录下建库
   ⇒ 它们的 `test_engine` 指向的目录被连根删除。症状极具误导性：**单跑那两个文件全绿，
   整套跑时 `test_vtuber_api.py` 61 个用例集体 `sqlite3.OperationalError: unable to open database file`**
   ——看起来像 SQLAlchemy 或锁文件升坏了。**同环境用系统 Python 同样复现 ⇒ 与依赖无关，是既存的测试卫生问题。**
   修法：每个用例只动自己那一格（`_test_tmp/first_run`）。

## 四、验证（实测数字）

- 锁出来的环境：**615 passed / 1 skipped / 0 failed**（修 bug 前是 64 errors + 4 failed）。
- **门禁 A 档 7 步全过 / 245s**（`tsc` · `eslint` · `doc_check` · **`cargo`** · `ui_probe` · `vitest` · `pytest`）
  —— 其中 `cargo test` 是**本仓第一次由门禁自动跑**。
- 冻结产物：**71.7 MB**（旧记录 118.8MB），`_internal` 里只剩 7 个真运行依赖
  （`werkzeug` / `email_validator` / `numpy` 这些误打进去的包消失）。
- 冻结 exe 冒烟：alembic 全链 `a001→f007`、APScheduler、auth 循环、`app.log` 落盘、`/healthz` 全绿，无残留进程。
- **反向验证**：删掉 `frontend/src-tauri/` 那条前缀 ⇒ `test_rust_shell_files_must_not_fall_into_tier_c` 精确报红
  （`frontend/src-tauri/src/lib.rs 应落 A 档，实际 C`）；用系统 Python 跑 `build_backend.py` ⇒ 守卫拒绝并打印修复命令。

## 四点五、顺带修的第三处（同类：用错解释器）

`gate.py` / `dev_check.py` 原先用 `sys.executable` 跑子步骤。依赖真源变成 `uv.lock` 之后，
用户用系统 Python 调它们就会**拿另一套版本跑测试**（实测缺 `python-multipart` 时 4 个文件收集失败）。
两个脚本各加一条 `project_python()`：**有 `.venv` 就用它**，没有才退回 `sys.executable`。

## 五、环境导致的未验证项

- 依赖版本有一次整体上抬（`uvicorn` 0.46→0.54、`starlette` 0.4x→**1.7.0**、`fastapi` 0.136→0.141）。
  615 条用例 + 探针三档全绿，但 `starlette` 跳大版本会**只在运行期暴露**的差异（中间件顺序、
  `TestClient` 行为）本轮**只在测试与冻结冒烟里验过**，**真机（Tauri 主窗/小窗）未验**。
- `starlette.testclient` 已提示改用 `httpx2`（deprecation，未处理）。
- `.venv` 是新建的：**在它成为唯一环境之前，系统 Python 那套仍能跑**（两份并存）。
  建议下一次发版时用 `.venv` 走一遍 `release.py`，再删掉系统 Python 里的项目依赖。
