# 319-20261004 帖子媒体固化 + 归档自动清理（批次 1/2）

> 用户口径（承 `devlog/318` 的"为什么过期"）：「把抓取时固化作为轻资产固化的一部分，
> 不论什么平台，未归档的帖子都可以作为轻资产固定下来，已归档的部分就自动移除，
> 然后再设置中给出可以调整固定选项（是否固定资产、未归档时长、是否自动清理归档资产、
> 视频资源是否固定（默认否）等），然后把打开时重取作为一个备选项，如果本地没有缓存就回退到重取」。
> 方案：`docs/plans/media-pinning-execution.md`（分批 + 停止条件）。

## 一、这一批做了什么（批次 1 + 批次 2 的"本地优先"）

**后端**

- `assets.py`：新增两个 kind `post_image` / `post_video`；`_referenced_keys` 给它们加了
  **"只保护未归档帖引用的媒体"**这条规则；`_media_urls(body_json, video=)` 是纯函数，
  图片取 `images[].url`，视频取 `video.url` + 镜像链。
- `services/media_pin.py`（新）：`pin_account_media()`（未归档 + 时间窗 + 每轮张数/字节上限 +
  每份落盘即提交 + 命中零请求；视频按镜像链**只存第一条成功的**、单文件 > 200MB 跳过）
  与 `clean_archived()`（= 对媒体 kind 跑 `prune(max_bytes=0)`，受开关管）。
- 设置新分组「**媒体固化**」（后端 specs 驱动 ⇒ 设置窗口**自动多一项**，前端一行没改）：
  `MEDIA_PIN_ENABLED`(开) / `MEDIA_PIN_MAX_AGE_DAYS`(30 天, 0=不限) / `MEDIA_PIN_VIDEO`(**关**) /
  `MEDIA_PIN_CLEAN_ARCHIVED`(开) + 高级两项（每轮 20 份 / 24MB）。
- 挂点：账号抓取轮里、封面固化之后跑媒体固化，再跑一次归档清理（都只记日志，不拖垮抓取）。
- 契约：`PostOut.images_local`（与 `body_json.images` **同序同长**）/ `video_local`，
  在 `_post_outs` 里**一次批量查**（页大小翻倍而查询数不变）。

**前端**

- 详情页：封面、正文图缩略图、灯箱大图都把本地副本当 `ProxyImage.fallbackSrc`
  （远端优先、本地兜底 —— 图床签名过期时画出盘上那份，而不是灰块）。
  ⚠️ 本地副本要在 `dedupeImages` **之前**按索引挂上去（去重会重排/丢项）。

## 二、为什么"归档就清"不用新写清理器

`prune(kind, max_bytes=0)` 的语义是"**清空未 pin 且未被引用的**"，而媒体类的"被引用"
只算**未归档帖**——两条一合就是用户要的："帖子一归档 ⇒ 失去保护 ⇒ 下次清理删掉它"。
少一个清理器 = 少一处会和 `prune` 漂移的重复实现（`docs/DEV-LOOP.md` §0.3 那条纪律）。

## 三、判据（12 条，`tests/test_media_pin.py`）

未归档帖的图固化；**第二轮零请求**（配正对照）；只固化时间窗内的（窗 = 0 ⇒ 不限）；
总开关关掉**一个请求都不发**（正对照）；**视频默认不固化**、开了只存镜像链第一条、
超大跳过；**归档后删行 + 删文件**（开关关掉一条不删）；dry-run 不删；
单张失败只跳过；`images_local` 同序同长（空串 = 没有副本）；派生**不 N+1**。
前端 3 条（`PostDetailDrawer.media.test.tsx`）：两跳失败落本地副本、没有副本时照旧占位、
`images_local` 按**索引**对齐。后端 1086 → 1099、前端 899 → 902。
