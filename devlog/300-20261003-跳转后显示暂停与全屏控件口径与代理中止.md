## 一、"界面显示暂停、还没声音"：一箭三雕的 `el.pause()`

真机现场还原（用户描述与日志对得上）：点进度条跳到**还没缓存**的位置时，音轨元素那一刻
正在 seek，`audio.play()` 会被浏览器立刻以 **`AbortError`** 打断。而我们的
`startAudio()` 当时是这么写的：

```ts
void audio.play().catch(() => el.pause())     // ← 任何失败都把视频轨停住
```

那条 catch 是为"自动播放策略拒绝"写的（没手势 ⇒ 别留静音画面），但**瞬时失败**（`AbortError`、
`NotSupportedError`）被它一起吞了 ⇒ **视频轨被暂停**。于是：

- 界面显示暂停（`pause` 事件把 `playing` 置回 false，大播放键冒出来）；
- 没有声音（音轨本来就没起来，而它只在视频轨 `playing` 时才被拉起）；
- 用户看到"视频正常播放"是因为画面已经缓冲出那一帧、并没有立刻冻住观感。

**三处一起修**：

1. **失败分类**：只有 `NotAllowedError`（真的没手势）才停视频轨；瞬时失败**什么都不做**，
   交给和解逻辑下一拍重试；
2. **`timeupdate` 当和解心跳**：`playing` 这个 React 状态改从**元素本身**推
   （`setPlaying(prev => prev === !el.paused ? prev : !el.paused)`），并且
   `if (!el.paused) startAudio()` —— 播放时每秒 4 次心跳，最多 250ms 自愈。
   这条是"事件时序只要错一次就永久错下去"的通用解法：**别只信事件，要有从状态反推的路径**；
3. `AbortError` 之后音轨仍会被 `startAudio()` 拉起（幂等：已在放且偏差 < 0.2s 就不动）。

## 二、全屏控件的隐藏口径

用户要的是标准行为：**停手就收，指针压在底栏上永不收**。原来只有两个触发点 ——
"移动就显示" + "**指针离开整个播放器**才隐藏"，既没有停手计时，也不认"指针正压在底栏上"。

现在：`mousemove` → 显示并重置 **3 秒**计时；计时到点且指针不在底栏 ⇒ 收起；
指针 `mouseover` 底栏 ⇒ 立刻显示并**取消计时**；离开底栏 ⇒ 重新开始计时；
指针离开整个播放器 ⇒ 立刻收起（用户就是想让它让开）；**暂停时永远不收**。
`hoverBar` 用 ref（只参与判断、不参与渲染），否则鼠标每次划过底栏都要重渲染一遍。

## 三、那串 `ConnectionResetError` 是什么，以及为什么现在不会再有

```
ERROR asyncio: Exception in callback _ProactorBasePipeTransport._call_connection_lost
ConnectionResetError: [WinError 10054] 远程主机强迫关闭了一个现有的连接
```

**它不是崩溃**：浏览器掐掉在飞的媒体请求（拖进度条、切清晰度、小窗接管都会）是**常态**，
uvicorn 的 proactor transport 把它记成 ERROR 级 traceback。真问题会被它淹掉，所以两边都收口：

| 处 | 改动 |
|---|---|
| 代理的流式生成器 | 客户端中止（`httpx.HTTPError` / `ConnectionResetError` / `OSError`）**当正常收尾**，只记 debug（默认级别下不落盘），真错误才 warning |
| 共享客户端 | 以前**每个请求新建 `AsyncClient`** ⇒ 每次 Range 请求都重做 TCP+TLS 握手（拖一次进度条要发好几条）。改成与 `/img-proxy` 同款的**模块级共享客户端**，并在 `lifespan` 关闭时释放；块大小 64KB → **256KB**（少几百次事件循环切换） |

判据：`test_client_abort_is_not_an_error`（用会抛 `ConnectionResetError` 的假上游，
断言日志里**没有任何 ≥WARNING** 的记录）+ 一个 autouse 夹具每个用例复位共享客户端
（不复位的话，上一个用例塞进去的假客户端会被下一个捡到 —— 单跑绿、整跑红那种）。

| 用例 | 钉什么 |
