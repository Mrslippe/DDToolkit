# 299-20261003 小窗（画中画）三则：暂停不带音轨 / 静音点不动 / 缓冲没有转圈

> 用户三条（2026-10-03 23:3x）：① 点悬浮小窗看视频后**暂停**，原音轨不停，而是"一小段一小段重复"，
> 关掉小窗也一样；② 小窗的**静音按钮**点了不静音；③ 点进度条跳转后**加载时要转圈**，
> 否则用户以为"点了跳转结果暂停了"。
> 三条都出在同一个根源：**DASH 是双元素，而小窗/系统那套控制只认 `<video>` 那一个元素**。

## 一、为什么"一小段一小段重复"（最刺眼的那条）

小窗的暂停按钮、系统媒体键、`mediaSession` —— **都不经过我们的 `toggle()`**，它们直接
`video.pause()`。而声音在**另一个元素**（`<audio>`）上，没人告诉它 ⇒ 音轨继续放。

于是每秒一次的漂移纠正登场：它看到"音轨超前 0.6s 以上"就 `a.currentTime = v.currentTime` ——
把音轨**拽回冻结的画面时间**。音轨再往前跑 0.6s、再被拽回……**同一小段被反复重放**，
听起来就是"一小段一小段重复"。关掉小窗时视频轨仍是暂停态 ⇒ 循环继续。

**两处一起修**：

1. **任何来源的暂停都带走音轨**：给视频元素加 `pause` 监听 → `audio.pause()`
   （我们自己的 `toggle()` 也走这条路，不再各写一份）；
2. **视频轨暂停时漂移纠正直接停手**（`if (v.paused) return`）——
   纠正的前提是"两条都在放"，画面冻住时任何"纠正"都是错的。

对称的一侧也补上：视频轨 `playing`（小窗里点继续播、缓冲结束）⇒ 音轨对齐并起播
（`startAudio()` 幂等：已经同步就不动，避免每次重新缓冲都把音轨拽一下）。

## 二、小窗静音按钮为什么点了没用，以及怎么修

小窗那个按钮切的是 **`<video>` 元素的 `muted`**。而我们的实现里，DASH 档**恒定**
`video.muted = true`（当初的理由是"防止两份声音"）⇒ 那个按钮无论怎么点都不影响声音
（声音在音轨上），用户看到的是"点了没反应"。

**修**：视频轨的 `muted` 改成**跟随全局偏好**（`prefs.muted`），并加一条 `volumechange` 监听：

```
小窗按钮 → video.muted 变 → volumechange → setPlayerPrefs({muted}) → 音轨跟着静/不静
```

前提说明白：**B站 DASH 的视频轨本身不含音轨**（音频是分开的那条流），所以"视频轨不静音"
不会出现两份声音；真要哪天含了，那一份也受同一个 `prefs.muted` 管。

## 三、缓冲要有转圈（不是"看起来暂停了"）

`waiting` → `buffering = true`；`playing` / `canplay` → 收起。转圈与"取流中"共用
`.vp-spin`，并且**与大播放键互斥**：缓冲时若摆着播放键，用户会以为"跳转把它暂停了"
（这正是用户描述的那个误判）。

顺带一个已有的好效果：进页面点播放时视频轨第一帧要等 **1.26 秒**（`devlog/298` 量的），
现在那 1.26 秒也有转圈了，而不是冻着第一帧。

## 四、判据（`VideoPlayer.dash.test.tsx` 新增 4 条）

| 用例 | 钉什么 |
|---|---|
| 暂停带走音轨 | 视频轨 `pause` ⇒ 音轨 `pause()` 被调；播放键露出来 |
| 暂停时纠正停手 | 视频轨 paused 且音轨超前 0.8s ⇒ 跑 3 秒纠正，`a.currentTime` **纹丝不动**、`playbackRate` 也没被改（这条就是"重复"的封口） |
| 小窗静音回写 | `video.muted = true` + `volumechange` ⇒ 音轨静音；再取消 ⇒ 音轨恢复 |
| 缓冲转圈 | `waiting` ⇒ `.vp-spin`（`aria-label="正在缓冲"`）出现且**播放键消失**；`canplay` ⇒ 收起 |
