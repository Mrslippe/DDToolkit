# 343-20261005 通知 L3 渠道收敛：客户端的事实也进面板

> 接 `devlog/342`（L2）。L3 = **渠道收敛**：把"事后该知道"的信息从"胶囊上闪一下"改成
> "进通知面板、能回看"，并给"哪条消息该走哪条渠道"一条**可执行的定义**。

## 一、判据一句话：它是不是某个用户动作的即时回执？

设计案（`docs/design/notices/channel-and-layering.md` §2.1）给 toast/胶囊一条定义：

> **`pillMessage` = 命令结果**：用户刚点了一下，我告诉他成没成（读完即弃）。
> 不是回执、但"事后该知道"的**事实** ⇒ 走新事件 **`noticeAlert`**（进通知面板的「最近」分组，
> 有相对时间、能回看）。

按这条口径迁了两个：

| 原 | 今 | 为什么 |
|---|---|---|
| `useUpdateCheck` 发 `pillMessage` | 发 `noticeAlert`（`id='local-update'`，源「更新」）| "发现新版本"不是回执 —— 用户可能几分钟后才回来看。关于页照旧有手动检查入口 |
| `useLowSpaceNotice` 发 `pillMessage` | 发 `noticeAlert`（`id='local-low-space'`，源「磁盘」）| 同上。⚠️ 它过期≠查不到：**关于页那条常驻红字**（`aps-storage` 的「空间偏紧」）还在 |

`pillMessage` 本身**不退役**（11 个调用点仍是"命令回执"，语义正好），只是**定位收窄**：
名字没变、判据写进了 `appEvents.ts` 的注释与用例。

## 二、⚠️ 迁过去才发现的一个缺口：客户端的事实会被服务端顶掉

`mergeNotices` 有一条"服务端也有 message ⇒ 本地让位"（同一句话不显示两遍）。
而客户端自己的事实（磁盘/更新）与服务端那条 message **毫无关系** ——
按 kind 让位会把它们一起顶掉。原先它们走 `pillMessage`（**根本不进这份列表**），所以没暴露。

修法：**按 id 前缀放行**（`local-` 开头的条目不让位）。为什么用前缀而不是再加一个 kind：
`kind` 是**视觉**分类（字形/点色），"谁说的"是**来源**分类 —— 混进 kind 会让
`noticeBoard` 的分组与长相跟着变形。判据是 `noticeStream.test.ts` 里那条
"local 前缀不让位"（两 local + 一条服务端 message 三条都在）。

## 三、顺带修掉两个"共有状态"的坑

1. **`extraLocal` 有两个来源**（dev 注入的报告 + 客户端事实），而 `setState` 是整表覆盖 ——
   谁后写谁把对方清掉。改成**两边都按 id 合并**（dev 注入只删自己那批 `report-*`）。
2. **本地条目没有轮询兜底**：服务端那份过期由轮询自然带走，本地这份不会 ——
   补一个 1s 的清理（只在有条目时开；没有变化时返回同一引用，别每拍触发重渲染）。

## 四、判据与门禁

- `mergeNotices`：local 前缀不让位（新增）；原有 16 条全绿（含"让位配对"与"宽限窗口"）；
- 事件表：`APP_EVENT_NAMES` 十条 + `pillMessage !== noticeAlert`（两个名字**都要在**，
  删一个会让别的调用点静默失效）；
- 探针：`--status-island` 与两个默认模式全绿（这次**没改**它的判据 ——
  迁的是"发哪个事件"，面板呈现那一层 L1 已经钉住了）。
