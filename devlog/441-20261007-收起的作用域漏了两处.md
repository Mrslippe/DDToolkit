# 441-20261007-收起的作用域漏了两处（正常模式）

用户：「正常模式收起左栏时左工具栏也被收起了，并且明显的感觉到收起和展开有延迟」。

两条都是**同一批改动漏了作用域** —— 我按"单推模式"写规则时把两样东西写进了**基础规则**里：

## 第 1 条：左工具栏被"收起" = 被左栏的白底盖住

和 `devlog/435` 那次**同型**：左栏"收起来"用的是**负外边距** ⇒ 它的盒子仍然横跨
`[-sidebar-width + rail-width, rail-width]`（右缘正好落在 x=50），而它在 DOM 里**靠后**
⇒ **白底盖住工具栏的 `[0,50]`**。

`435` 我给工具栏加的 `position: relative; z-index: 2` **只写在 `.app-shell[data-solo='1']` 里**
⇒ 单推好了、**正常模式照样被盖** ✗。现在提到**基础 `.icon-rail` 规则**（无条件），
单推那条里就不必重复了。

## 第 2 条：收起/展开的延迟 = 基础规则里排了"退出单推"的次序

```css
.topbar { transition-delay: 0ms }
.icon-rail { transition-delay: var(--solo-step) }
.sidebar-shell { transition-delay: calc(2 * var(--solo-step)) }   /* ← 520ms，正常模式也生效 ✗ */
```
那三段是**退出单推**的倒序播放，但我写成了基础规则 ⇒ 正常模式手动收起左栏**先干等 520ms**
（用户实测"明显感觉到有延迟"）。左栏**进场**的延时本来就是 0 ⇒ **直接删掉它那条基础延时**，
两边都不吃亏：单推进场照样是它先动，正常模式收起立刻响应。

## 判据（净 +1，另有 1 条改写）

★「左栏**不许**带基础 `transition-delay`」—— 用**行首锚定**的跨行正则
（`/^\.sidebar-shell \{[^}]*transition-delay/m`）断言基础规则里没有它，并**配正对照**
（单推里那条 `0ms` 进场延时确实在，否则"不含"什么都证明不了）；
「退出倒着来」那条改写为"顶栏 0 → 工具栏 1 段，**左栏没有基础延时**"；
`z-index` 那条改用"含 `z-index` 的那条 `.icon-rail` 规则"定位
（第一条 `.icon-rail` 是入场动画那条 —— 又一次"同名规则两份"）。

**反向验证**（两组）：把 `z-index` 挪回单推作用域 ⇒ 那条红；给左栏加回基础延时 ⇒ 两条红。

## 教训

**写"只在某模式下生效"的规则时，先问一句：这条选择器有没有模式前缀？**
漏一次，症状会跑到"另一个模式"里去 —— 而且看起来像新 bug（用户就是在正常模式下发现的）。
本批连着三次栽在"作用域/真源"上（`439` 的同名规则两份、`441` 的两条漏前缀）——
**CSS 改动收尾时扫一遍：我加的选择器有没有都带上该带的前缀。**
