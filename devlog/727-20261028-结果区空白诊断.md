# 727-20261028-分析完成后结果区空白：诊断与两处修复

用户图二的现象：卡片框和标题都在、里面**全空**；名单卡写着「已加载 20 / 全池 3,920 人」却一行都没有。
按用户要求：**先做完整诊断，确认根因再修**。

## 诊断一：JS 路径是通的（新增回归用例证明）

新写一条端到端用例复现整条链路：
点「分析」→ `fanAnalyzeStart` → 轮询 `fanAnalyzeStatus` 到 `done` → `finishedAt` 边沿 →
`loadRanked` → **断言 DOM 里真的有 `<tbody><tr>`**（不是只断言接口被调用）。

结果：**通过**。说明"任务结束 → 取结果 → 渲染"这段逻辑没错，空白的成因在别处。

（顺带暴露一个真 bug：`WorkbenchPage.test` 的 api 桩原先**没有** `fanAnalyzeStart`，
点分析会抛错→任务直接 failed→`finishedAt` 照样触发 `loadRanked`，所以旧用例一直是
"歪打正着"地绿。这次把桩补全了。）

## 诊断二：`EChart` 在 0 宽容器上 `init` ⇒ 画布永远是空的（**已修**）

原实现：

```ts
if (!host.offsetWidth && tries < 20) { tries += 1; raf = requestAnimationFrame(boot); return }
api.current = echarts.init(host)          // ← 20 帧（约 330ms）后仍为 0 宽就走到这里
```

后果：在**隐藏或 0 宽**的时刻挂载（窗口最小化、路由切换动画中、结果区还在 0 宽容器里），
ECharts 会用一个 0×0 的容器 init —— 画布建立成功但**永远是空的**，并且之后
**没有任何 resize 逻辑**会救它回来。症状与用户截图完全一致：**卡片框和标题在、里面全空。**

修法：

- 宽度为 0 时**绝不 init**，改用 `ResizeObserver` + 帧重试（兜底 600 帧 ≈ 10s）等它第一次有宽度；
- init 之后挂一个 `ResizeObserver` 调 `chart.resize()` —— 原来容器尺寸变化时图会被拉伸/裁掉。

## 诊断三：任务判死太急 + 计数不重置（**已修**）

- `emptyProbes`（"后端没有这个任务条目"的连续计数）是模块级变量，但 `resetFanTask()` 没清它
  ⇒ 测试里跨用例累积、第二次就直接判任务结束；线上表现为"刚点完就变完成"。
- 原逻辑**一次空响应**就收摊。任务刚发起时后端可能还没登记，单次空就结束会让界面闪一下"完成"。

修法：连续**两拍**都空才收摊；`resetFanTask` 一并清计数；`startCollect`/`startAnalyze`
成功后**立刻探一次**（首个进度不用等 1 秒）。

## 还剩下的疑点（需要用户给一个动作来区分）

截图里「已加载 20」却一行都没有 —— 按代码，`rows.length === 20` 就必然渲染 20 行；
若 `rows` 为空，表头应该显示「已加载 **0**」并出现「这一页没有数据」。所以只剩两种可能：

| 可能 | 判据 |
|---|---|
| **A. 瞬时态**：截图正好卡在 `loadRanked` 返回前后（`ranked` 是新的、`rows` 还是旧的/空的） | **切一下「出席」页签**能恢复 ⇒ 是 A |
| **B. 渲染/样式**：行确实在 DOM 里但看不见（`wb-row-enter` 的 `both` 填充 + 动画未启动） | 切页签仍空、且 Console 无报错 ⇒ 是 B |

请下次复现时告我一句：**切页签能不能恢复**。能恢复我按 A 收（加"结果未到"的骨架/占位），
不能恢复我按 B 收（把行动画的填充模式改成 `backwards` 并加 `animation-fill-mode` 兜底）。
