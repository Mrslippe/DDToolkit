# 703-20261028-评论抓取失败的真因：用错了接口 + 全程没日志

## ① 为什么"抓取失败"且终端没日志

用户报：帖子抓取失败，终端也没有 log。查下来是**两个独立问题叠在一起**。

### a) 用了已废弃的旧接口

`GET /x/v2/reply?type=1&oid=…`（老接口）现在对未登录请求返回 **`code: 0` 且 `replies: []`** ——
不是报错，是"空成功"。所以任务状态是 `done`、抓取 0 条、用户名单为空，
看起来像失败，日志里也什么都没有（因为确实没报错）。

实测对照：

| 接口 | 返回 |
|---|---|
| `/x/v2/reply` | code=0，`replies: 0` 条 |
| `/x/v2/reply/main` | code=0，`replies: 20` 条，`cursor.all_count=89497` |

**改用 `/x/v2/reply/main` + `cursor.next` 游标分页**。

### b) 整条链路一行日志都没有

`bili_replies.py` 里既没有 `logger` 也没有任何 info/warning；`_get` 把 HTTP 状态、上游 `code`、
`message` 全吞掉返回 `None`。于是"为什么 0 条"完全无从判断。

现在补上：

- `_get`：非 200 打 warning 带 URL 末段与参数；JSON 里 `code != 0` 打 warning 带 code/message；
- `fetch_users`：每页 info `评论第 N 页：20 条（all_count=… is_end=…）`；
  首页为空时 warning「可能被风控或接口变了」；
- `run_scan`：开始 info（input/with_sub/scan_id）、解析成功 info（kind/oid/title/expected）、
  失败 warning（原因 + scan_id）、结束 info（state/fetched/expected/users/耗时）；
- 路由 `fan_compare`：起任务时 info（input/with_sub/max_pages）。

日志走 `logging_setup` 里已有的 `StreamHandler` ⇒ **终端能看到**，同时也进 `logs/app.log`。

## ② 顺手把规模封住

8.9 万条的帖子按 1.2s/页要跑一个多小时。改为：

| 参数 | 值 |
|---|---|
| `MAX_PAGES` | 150（=3000 条主楼） |
| `GAP_S` | 0.6s |
| 超限行为 | `partial=true` + `error` 说明「只抓到前 150 页（3000/89497 条）」 |

接口新增 `max_pages`（1–1000），前端暂用默认。

## 验收

- 实测 3 页：`2.8s / 60 条 / 56 用户`，日志逐页可见，`partial=true` 且带原因；
- `tests/test_bili_replies.py` 4 条改为喂 `cursor` 形状，全过；
- fan api / cross_v 一并回归通过。
