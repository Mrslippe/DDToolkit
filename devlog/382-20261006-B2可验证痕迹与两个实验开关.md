## 二、本批做了什么

### 0）把"第二刀是否生效"变成可验证的（**这是前提**）

`set_surface_opaque` 是后加的命令，**跑在改动前启动的旧壳上会直接失败** —— 而第一版把它包在
`catch {}` 里静默吞掉，于是"还是卡"根本分不清是"生效了但不够"还是"压根没生效"。

- `shellBridge`：`setSurfaceOpaque` 返回布尔、并把状态记进模块变量（`opaque/transparent/failed`），
  `surfaceState()` 供诊断用；**播放器进全屏时往客户端日志写一行**「全屏表面=不透明/失败（旧壳…）」；
- 播放诊断行加一格 **`表面=`** —— 每一条窗口记录都自带"当时那一刀在不在"。

### 1）全屏时"只留视频"（实验开关，本批起默认生效）

`posts.css`：`html[data-video-fs]` 下用 **`:has()`** 把**页面里除播放器祖先链之外的东西整个
`display:none`**（`.app-shell` / `.app-body` / `.posts-panel` 三层各滤一遍）—— 保留的只有
`.vp` 那条链。以前的"全屏"只是被黑底**挡住**，图层**仍在合成树里**；成熟播放器全屏时屏幕上
**只有视频**（YouTube 连控件都整块撤）。

### 2）永久不透明的实验开关（默认关）

`lib.rs` 的 `setup`：`DDTOOLKIT_OPAQUE_WINDOW=1` ⇒ 窗口与 WebView 表面**从一开始就不透明**
（等价于"永久去掉 alpha 合成"那一刀）。用法：

```powershell
$env:DDTOOLKIT_OPAQUE_WINDOW = "1"; npm run tauri:dev   # 下次启动生效；四角/圆角观感会变
```

默认保持透明（壳的既定视觉：四角白边 / DWM 圆角，见 `setup` 里的原注释）。

## 三、判据与两个"尺子"教训

- `VideoPlayer.keys.test.tsx`：进全屏 ⇒ `setSurfaceOpaque(true)` + `data-video-fs=1` +
  **客户端日志里出现「全屏表面=不透明」**（`api.clientLog` 用真模块 + 只换这一个方法，免得
  播放器别的调用撞上 undefined）；退出与**卸载**都必须还原。
- `playbackProbe.test.ts`：诊断行必须含 `表面=\S+`。
- ⚠️ **两个写死锚点又被改动作打断**（都当场红了，是对的）：
  ① `setup_actually_uses_the_candidate_ports` 原先拿 `set_background_color(...)` 整行当起点，
  改了参数就找不到 —— 而那个词在 setup 的**注释里也有**，换成"词"当锚点同样不行；
  最终改成 **「setup 开头 → 取 token 那一行」**（语义稳定的两端）。
  ② `VideoPlayer.holdRate.test.tsx` 的结束锚点在函数改名后 `slice` 到文件末尾（上一批已修）。
  **结论照旧：判据的锚点要选语义稳定的那一段，"整行文本"和"固定长度窗口"都是会骗过自己的尺子。**

## 四、下一步（按证据走，不再猜）

1. 先跑一次默认配置（本批的"只留视频"已生效）⇒ 看 `表面=opaque` 是否出现 + 丢帧是否下降；
2. 再跑 `DDTOOLKIT_OPAQUE_WINDOW=1` ⇒ 若这一步才顺，说明根因就是 alpha 合成（那就该讨论
