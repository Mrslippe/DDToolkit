# 279-20261002 「启动诊断」红框改造成面向用户的报错出口

> 用户口径（2026-10-02，附图）：「点击查看原文窗口右上角会出现红色的报错 log 框，
> 我觉得可以把这个报错 log **改造成面向用户的报错日志展示**，当出现类似的报错就出现，
> **让普通用户更容易提交 bug**」。

## 一、原来的东西是什么

`frontend/src/bootDiag.ts`：捕获未捕获异常 / Promise 拒绝 / `console.error` / 资源加载失败，
渲染一块**常驻右上角**的红色面板（标题「启动诊断 N 条」、560px 宽、`<pre>` 堆原始行、可复制）。
它是**开发者视角**的：内容形如 `[promise] Promise shell:allow-open not allowed…`，
没有版本、没有环境、没有提交入口 —— 用户能做的只有截图（2026-10-02 的报障正是这样来的）。

## 二、改造后的分工

| 层 | 模块 | 职责 |
|---|---|---|
| 捕获 | `bootDiag.ts` | 四类陷阱照旧（含"资源抖动只记账、≥3 次才算真故障"那条既有分级） |
| 判定→去重→脱敏→成文 | `utils/problemReport.ts` | 纯逻辑，**可单测**；快照引用稳定，直接喂 `useSyncExternalStore` |
| 呈现 | `components/ProblemPanel.tsx` | **右下角**、默认一条细条（不遮挡）；展开才是报告 |

要点：

- **只有真错误才露面**（`reportable`）；同一错误**去重计数**（`×N`），不刷屏；
- 展开后：每条错误（在哪、几次、细节）+「我当时在做什么」输入框 + 可选「附诊断包」；
- 动作：**复制报告**（markdown，可直接粘 issue）/ **提 issue**（预填标题正文）/
  **忽略**（清空）；
- 报告自动带：发生时间、应用版本（`/healthz` 的运行时真源）、当前路由与视图、WebView/系统、
  `[perf]` 启动时间线（`window.__bootTrail`）；诊断包**复用既有入口** `GET /settings/diagnostics`
  （既有"一键导出"没有作废，面板只是它的前门）；
- **脱敏**是硬要求（报告会贴到公开 issue）：cookie/token/session/签名头 + 长 base64url 串一律打码；
  ⚠️ 但 Windows 路径**不打**（那是排查要用的东西）—— 这条有专门用例钉着。

## 三、判据

`problemReport.test.ts`（9 条）：脱敏（凭据消失、路径保留）、去重计数、资源类不惊动用户、
Promise 拒绝会惊动用户、订阅通知、报告含版本/界面/用户描述且不含明文凭据、issue 链接预填与截断、标题取首条。
