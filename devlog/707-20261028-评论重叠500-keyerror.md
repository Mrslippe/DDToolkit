# 707-20261028-「依旧报错」的真因：`payload["items"]` KeyError

## 日志里查不到

`logs/app.log` 尾部只有 scheduler 与 `fan: 已计算 …` 的 INFO，**没有 ERROR** ——
因为这次不是"异常没落文件"，而是我上一段代码里的一个**必然触发的 KeyError**，
只有真正请求到那条端点时才会炸；用户点到它时前端拿到 500，界面显示"加载失败"。

## 从快照反查

`_compare/scans/7f1049878846.json`（02:14:03）：

```
state=done phase=write fetched=53 expected=54 users=53 kind=dynamic
```

**抓取其实是成功的**。所以问题在下一步：`/fan/compare/comment-overlap`。

## 真因

```python
order = sorted(payload["items"], key=lambda r: -(r.get("strength") or 0))
#                    ^^^^^^^ KeyError: 'items'
```

`_compute()` 返回的是 `{window, pool, sessions, charts, …}`，
**`items` 是 `/ranked` 端点自己追加的** —— 对比端点复用 `_compute` 时拿不到它。

## 修法

直接用画像里的强度表（本来就为对比准备着）：

```python
order = sorted(prof.strength.items(), key=lambda kv: -kv[1])
for i, (uid, _s) in enumerate(order[:1000], 1):
    if uid in comment: hit += 1
```

实测（明前奶绿 20 场 × 动态 413547951）：

```
200 · 共享 5 · Jaccard 0.082% · lift 0.095 · 下尾 p≈9e-115（显著贫化）· 覆盖 7 个点 · 交集 5 人
```

## 回归

`tests/test_fan_api.py` 增加一条：`overlap_stats` 不依赖 `items`（喂没有 `items` 的输入仍能算出交集）。
