## 一、密钥（一次性，必须保管好）

```
E:\work\Project\ddtoolkit-updater.key        ← 私钥（**仓库外**，348 字节，密码留空）
E:\work\Project\ddtoolkit-updater.key.pub    ← 公钥（152 字节）
```

- **公钥**写进 `tauri.conf.json` 的 `plugins.updater.pubkey`（入库）；
- **私钥**只在本机、仓库外，构建时通过 `TAURI_SIGNING_PRIVATE_KEY_PATH` 提供（无密码 ⇒ 不用密码变量）；
- ⚠️ **私钥丢了就再也发不了更新**（已装的客户端只认这一对密钥）—— 请备份到安全的地方；
- ⚠️ 密码留空意味着"拿到文件就能签"：别把它拷进仓库、别放进同步盘/聊天窗口。

生成命令（记下来，将来换机器要用）：
```
npx tauri signer generate -w <仓库外路径> --password=
```
> PowerShell 会把 `-p ""` 的空字符串吞掉，得走 `cmd /c` 或 `--password=`。

  该 zip 确实存在 ⇒ 把"签名缺失/字段写错"这类**静默失效**挡在发版之前。

**`upload_release_assets.py`**：资产列表加 `*.nsis.zip` 与 `latest.json`
（**必须一起传**：只传 zip 没人知道有新版本，只传 json 下载会 404；签名不单独传，它写在 json 里）。

## 四、契约里最容易写错的四点（用例钉住）

| 点 | 写错的后果 |
|---|---|
| `platforms` 键必须是 **`windows-x86_64`** | 所有 Windows 客户端都收不到更新（静默） |
| `signature` 非空 | 空签名 ⇒ updater 拒绝安装，用户只看到"更新失败" |
| `url` 走 **`releases/download/v<版本>/`**，不是 `latest/download` | 用户下到"最新版"的包却配旧签名 ⇒ 校验必失败，**且只在发下一个版本时才暴露** |
| `pub_date` 是 ISO8601 UTC（`Z` 结尾） | 解析失败 = 更新器直接报错 |

`tests/test_release_updater.py` 六条用例逐项覆盖（含"长说明要截断并附指引"、"空签名必须 raise"）。
