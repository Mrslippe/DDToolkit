## 一、`RELEASE.md` 新增 §3.1「应用内更新：签名密钥与更新产物」

| 写进去的事实 | 为什么值得写 |
|---|---|
| **更新载体 = NSIS 安装包本身 + `.exe.sig`**（**没有 `*.nsis.zip`**） | 这是本次最耗时的一个错误假设：按 zip 写导致 `latest.json` **一直生成不出来**（脚本在找一个不存在的文件），排错时先看这条 |
| `latest.json` 的 `url` 必须**版本化**（`download/v<版本>/…`） | 用 `latest/download` 会让旧版本客户端下到新包却配旧签名，**且只在下次发版才暴露** |
| 签名嵌在 `latest.json` 的 `signature` 字段里 | 所以资产只需传 安装包 + 便携包 + `latest.json`（签名不用单独传） |
| 密钥三件套在仓库外（私钥 / 密码 / 公钥），公钥已进 `tauri.conf.json` | 丢了就再也发不了更新；换密钥必须同步改 `pubkey` 并重打产物 |
| ⚠️ **密码不能为空** | 空密码时 CLI **直接从终端读密码**（绕过 stdin），脚本/CI 里表现为**无输出地挂住**（实测 180s 无返回）；PowerShell 的 `$env:X = ''` 其实是**删除**变量，同样会被当成没提供 |
| 私钥用**内容**而不是路径（`TAURI_SIGNING_PRIVATE_KEY`） | CLI 这版不认 `_PATH`（实测报 "no private key"） |
| `verify` 已内置的四条清单校验 | 把"签名缺失 / 字段写错"这类**静默失效**挡在发版前 |

`§3` 的构建命令也同步改成"先设签名环境变量再 `npm run release`"，产物清单从两个变成三个
（安装包 / 便携包 / `latest.json`），实测数字更新为 v1.0.2 的 57.5MB / 71.9MB。

## 三、这次定版收口暴露的三个坑（都已修，此处留档）

1. **NSIS 更新载体不是 zip**（见上表）+ `_collect_updater` 写了却**没在 `main()` 里调用**
   —— 两个错叠加，表现为"清单静默不生成"；
2. **空密码私钥在非交互构建里走不通** ⇒ 重新生成带密码的密钥对（旧密钥作废；
   当时还没有任何发布的版本，换掉零成本）；
3. **release 构建独有的警告**：`let mut default_dir` 在 release 下那段 `cfg(debug_assertions)`
   代码不参与编译 ⇒ "不需要的可变"警告。改成 `cfg` 分支表达式（debug/release 各一个值）。
