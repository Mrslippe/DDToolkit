# 216-20260926-Q1的便宜那一半ApiError与运行时校验

批次 13 = 计划 §Q1，按 2026-09-25 的修正**只做便宜的那一半**：
`ApiError` + `JSON.parse` 的 try/catch + 关键响应的运行时校验。
**OpenAPI 离线生成 + CI「重新生成无 diff」暂缓** —— 那是新增一条会漂的管道，
而第二个消费方（社区脚本 / MCP / 插件）今天并不存在。

## 一、改前是什么样（三个毛病，都能在代码里指出来）

| # | 毛病 | 用户/排查看到的 |
|---|---|---|
| ① | `throw new Error(detail)`（`api.ts:225`） | HTTP 状态、后端 detail、出错的路径**全丢** ⇒ 界面只能统一说"加载失败"，409/422 这类**可判别**的失败分不出来 |
| ② | `JSON.parse(text)` 无 try/catch | 后端 2xx 但响应不是 JSON ⇒ 抛**裸 `SyntaxError`**，而调用方按 `e.name === 'AbortError'` 分流 ⇒ 被当成**业务错误**弹 toast |
| ③ | `JSON.parse(...) as T` 是**纯断言** | 后端改字段名/改嵌套 ⇒ 界面拿到 `undefined` 继续渲染（空白 / `NaN` / "还有更多"永远为假），**一路静默** |

## 二、改成什么

- 新增 `api/errors.ts`：**`ApiError`**（`status` / `detail` / `path` + `isAuth` /
  `isClientRejection`）与 **`ApiShapeError`**（形状不对 / 不是 JSON，带**截断过的**实际值）。
  `request()` 两处抛出点换掉。
- 新增 `api/validate.ts`：三个关键响应的**最小**校验 —— `/vtuber/list`、
  `/vtuber/{id}`、`/vtuber/fetch-status`、`/posts/…/paginated`。
- `request()` 多了第三个可选参数 `parse`（只有挂了校验的走它）。

**关于 zod / valibot**：计划里那句是**工具建议**，这里**手写**了几十行、零新依赖 ——
引运行时校验库会连带 `package-lock.json` 变更与冻结产物里的新包，换来的只是同样的几十行。
真长到十几个 schema 再换库，替换面就是 `validate.ts` 一个文件。

## 三、兼容性：改前逐条审过调用方（这是本批最容易翻车的地方）

全仓 grep `catch` / `.message` 命中 **121 处**，形态几乎都是 `(e as Error).message`，
另有 4 处判 `e.name === 'AbortError'`。所以三条硬约束，全部有判据：

1. 两个错误类都 **extends Error**，`message` **文案与改前逐字一致**
   （401 那句"应用若刚重启，请重开窗口"照旧，只是改成只进 `message`，`detail` 保留后端原文）；
2. **取消仍是 `AbortError`**（`fetch` 直接 reject，不经过 `request()`）—— 用例断言
   `e.name === 'AbortError'` 且 `not.toBeInstanceOf(ApiError)`；
3. `as T` 的**成功**路径行为不变（含"空响应体 → `null`"，204 删除类端点靠它）。

**计划点名的 6 处 `r.status === 'skipped'` 也审了**：它们读的是**成功响应体**里的
`status:'skipped'`（后端对"已有抓取任务在跑"返回 **200 + status**，见
`routers/vtuber.py:907/927/972/…`），**不是**错误码 ⇒ ApiError 不影响它们。
真正受影响的是 `catch` 分支，而它们只读 `.message`。

## 四、判据（`frontend/src/api/apiContract.test.ts`，16 条）

- **分类稳定**：401/403/409/422 各自的 `status`/`detail`/`path`/`message`；
  401 带排查提示且 `isAuth`；409/422 是 `isClientRejection`，404 不是；
  错误体不是 JSON ⇒ 退回 `"<status> <statusText>"`；
  取消 ⇒ `AbortError`（不是 ApiError）。
- **非 JSON 的 2xx** ⇒ `ApiShapeError`（`path` / `received` 都在，含 `oops` 那段实际内容）；
  空响应体 ⇒ `null`。
- **形状校验**：正常通过 · `id` 改名成 `vtuber_id` ⇒ 报错并**点名字段 + 第几个元素** ·
  数组里混 `null` ⇒ 报错 · **多余字段放过**（后端加字段是兼容变更）·
  缺 `manual_running` ⇒ 报错 · 分页 `total: null` ⇒ 报错。

**反向验证 4/4 真红**：失败退回裸 `Error` · `JSON.parse` 去掉 try/catch ·
列表不挂校验 · fetch-status 不挂校验。

⚠️ 顺带修了**两条既有用例**：它们拿 `okJson({})` 当 `/vtuber/list` 的假响应
（只为测请求头），现在会被形状校验挡下 ⇒ 改成 `okJson([])`——
这正是"校验真的生效"的证据（判据咬到了自己的测试脚手架上）。

## 五、没做（按修正）

- **OpenAPI 离线生成 + CI 无 diff**：暂缓（理由见开头）。所以本批**没有**"生成器"那一层，
  字段漂移的防线是 `validate.ts`（运行时）+ `types.ts`（编译期手写 DTO）。
- **不给所有端点加校验**：只挂"界面真的读、读错会静默出错"的那几个。
  其余保持 `as T`（多一层校验就多一处要跟着后端改的地方）。
- `pages/useVtuberActions.ts` 的 6 处 `status === 'skipped'` **不改**：它们本来就是对的分流方式
  （后端用 200+status 表达"跳过"），改成读 `ApiError.status` 反而会漏掉这条路径。
