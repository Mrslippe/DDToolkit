# 480-20261013 录播的第二条播放路径：无边框播放器窗 + 一个偏好开关

> 用户 3.2 的后半句：「设置里加『默认用应用内**无边框播放器窗口**播放』选项」。
> 上一批（`devlog/479`）已经能在应用里播了，但播放面是**主窗里的浮层** ——
> 这一批补上"另一扇窗"，并把它做成用户可选。

## 一、壳侧：第二个窗口（本仓第二次做这件事）

| label | 谁开 | 页面 | 关掉它 = |
|---|---|---|---|
| `main` | 启动建 / 深休眠唤醒重建 | `index.html` | **隐藏到托盘**（`CloseRequested` 被拦下） |
| `player` | 主窗调 `open_player_window` | `player.html?bvid=…&p=…` | **真的关掉** |

三条硬约束（都是历史踩出来的，写进 `SHELL.md` 了）：

1. ⚠️ **`CloseRequested` 必须按 label 分流** —— 不分流的话点播放器的 ✕ 会**把主窗藏进托盘**、
   播放器还杵在那儿（`lib.rs` 的 `.on_window_event` 现在第一句就判 `PLAYER_LABEL`）。
2. ⚠️ **命令必须是 `async fn`** —— 同步命令跑在主线程，"在已有 webview 的进程里同步建第二个"
   实测卡死（历史小窗那次，`devlog/175`-`179`）；另有 `CREATING_PLAYER` 重入闸门
   （`React.StrictMode` 下 effect 跑两次）。
3. ⚠️ **建窗参数逐项照抄主窗**（无边框 / 透明 / 全透明底色 / `VP_BROWSER_ARGS`）：
   少一项的症状是"两扇窗不是一套"或"视频在播放器窗里丢帧"（硬件解码只认后者，`devlog/404`）。

权限面（`SHELL.md` 29 号不变量）：`PLAYER_LABEL` 只进 **`PLAYER_COMMAND_ACL` 三条**
（`get_backend_port` / `get_api_token` / `close_player_window`），而 `CALLER_LABELS_ALLOWED`
也必须放进它 —— 播放器窗要自己发取流/段表请求，读不到 token 就是"窗口开了、播不了"。
`cargo test` 两条新判据：**只拿到那三条** + 反向（`migrate_data_dir`/`quit_app`/`open_external`/
`open_player_window` 它都调不了）。

## 二、前端：第二个入口

`player.html` → `src/playerMain.tsx`（`vite.config.ts` 多入口）。它只做四件事：取 URL 上的
`bvid`/`p`、**注入后端地址与 token**、渲染 `BiliVideo`、画一条可拖拽的窄条（无边框窗没有
系统标题栏）与一枚 ✕。

⚠️ **不能靠 `index.html?player=1` 运行时分流** —— 静态 import 拦不住，整个应用会被拉进那扇窗的
renderer（历史小窗实测 132MB，`devlog/274`）。CSS 侧确实引了整份 `posts.css`（`.vp*` 住在那里，
拆出去要动主窗的层叠顺序），但省下的正是 **JS** 那棵树。

## 三、偏好开关

`vod_player_window`（`prefs` 家族，`group: 外观` 的「视频播放」小节，**默认 `off`**）。

- 默认关的理由：独立窗口只有桌面端有 —— 默认打开等于让新装用户先撞上一个"开了没反应"的开关。
  关着时走主窗内的播放浮层（`VodPlayerDialog`），浏览器/探针里**永远**走这条。
- 消费点：`LiveCalendar.playVod` —— 点那一刻**现读**偏好（与顶栏点 ✕ 读 `close_action` 同一套），
  `on` 且 `openPlayerWindow()` 真的返回 true 才开窗，否则回落浮层。
- ⚠️ `usePrefs` 的兜底默认值有**两处**（初值 + `load()` 里那份），加键时两处都要补 ——
  漏一处会读到 `undefined`，症状是"开关显示成关着、其实后端是开"。
