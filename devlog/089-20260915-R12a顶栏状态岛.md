## 一、改造前：顶栏是**三套并存**，而且风控看不见

| 来源 | 实现 | 问题 |
|---|---|---|
| 任务进度 | `TopBar` 轮询 `fetch-status` 算 `busy`，内联拼文案 | 判定散在组件里，无法单测 |
| 瞬时消息 | `ddtoolkit:pill-message` 事件覆写文案（4s） | 与进度的优先级是散落的一行 `showOverride = pillMsg !== null && !busy` |
| 完成报告 | 全量抓取完成 → **自动弹 AlertDialog** | 与上面两套各说各话 |
| **风控冷却** | **只在服务端日志里** | 用户只感到"任务变慢/没结果"，界面上完全看不到 |

## 二、R12a：一个控件 + 一份判定

```
utils/notificationHub.ts      ← 判定（纯函数，12 条单测）
  Notice{id,kind,text,detail,source,sticky,expiresAt,action}
  优先级 alert(4) > progress(3) > report(2) > message(1)
  progressNotice / rateLimitNotice / loginNotice / reportNotice / messageNotice
  pickPrimary / liveNotices / isLive / composeTaskText
components/StatusIsland.tsx   ← 渲染（四态 + portal 面板）
TopBar.tsx                    ← 把六类信息源汇成 notices，动作映射回业务
```

**六类信息源全接**：任务进度 · 第三方同步 · 完成报告 · 登录失效 · **风控冷却** · 瞬时消息。

### 三条关键决策

1. **「自动节拍不占顶栏」从"副作用"升级为"具名规则 + 反向用例"**（2026-09-10 用户口径）：
   改造前它靠 `TopBar` 里 `isQuietTask` 的散落判断成立；现在 `progressNotice({auto:true})`
   直接返回 `null`，并有单测 `auto=true（动态流/自动账号流）直接不产生条目`。
   真实后端上仍由既有探针断言兜底（`_assert_topbar`）。
2. **完成报告不再自动弹窗**：改成状态岛里一条**常驻**条目 + 「查看详情」打开原来的对话框
   （内容一字未改：存储/跳过/视频可能缺/中断账号清单）。这是方案里批准的形态变化，
   报告仍然是 sticky 的，不点「知道了」不会消失。
3. **能力受限（P2 的 `.topbar-limits`）保持独立入口**：**工具 vs 通知**的分工 ——
   前者是"随时可点的入口"，后者是"有事发生才出现的信息"。`NoticeActionKind` 里保留
   `open-limits` 给后续批次合并用（避免这一批同时改动 P2 的探针契约）。

### 后端：把风控从日志搬到界面

- `get_fetch_status()` 新增 `rate_limit: {active, reason, seconds_left}`；
- 9 处风控冷却点原本各自 `await asyncio.sleep(RATE_LIMIT_COOLDOWN)`，现在统一走
  `_cooldown_for_rate_limit()`（**先记账再睡**）—— 逐处手改必漏，所以用一个入口收口；
- 冷却窗口过去后 `active` 自动变 false，前端不需要额外清理（用 `expiresAt` 表达）。

## 三、护栏：新探针 `ui_probe --status-island`

现场用**真实事件源**驱动（派发 `ddtoolkit:pill-message`，不直接改 React state）：

```
空闲：文案='数据服务运行中' 亮起=False 计数=False 右栏宽=670
瞬时消息：文案='探针消息：账号信息抓取完成 · 成功 3 · 失败 0' 亮起=True chevron=True
面板：打开=True 条目=1 种类=['message'] 来源='提示 · 操作结果'
可命中：面板=True 首条=True 在视口内=True ｜ 展开后右栏宽=670 Esc 收起=True
ttl 到期后：文案='数据服务运行中' 亮起=False
```

它盯的是四态与两条不变量：**空闲无容器**（用户口径）、**展开不挤动右栏**（面板必须
portal + fixed —— 顶栏容器 `overflow: hidden` 会裁掉内联面板）。

**反向验证与一次"诚实修正"**：我先用"把瞬时消息改成永不过期"去反向验证探针，
结果探针**照样绿** —— 查下去发现那一条量的其实是 `TopBar` 自己的清态定时器（消息消失是它做的），
不是 hub 的 `expiresAt`。于是：
- 探针那条改成**如实标注**（"量的是端到端结果，背后有两个机制，探针分不清是哪一个"）；
- hub 的过期规则由**单测**钉住，并确认它会红：改坏 → `notificationHub.test.ts` 失败
  （`瞬时消息带 ttl 过期时刻`），恢复后绿。
