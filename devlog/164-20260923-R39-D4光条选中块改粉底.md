## 二、改了什么

### 2.1 选中块：白光 → 粉底圆角块（`posts.css`）

```css
.glow-spot {
  border-radius: 12px;                                  /* 档案卡族圆角口径 */
  background: var(--sel-bg);                            /* 不透明浅粉：选中语义与全仓一致 */
  box-shadow: inset 0 0 0 1px var(--c-primary-deep);    /* 主色粉边 = --sel-bar 同一个 token */
}
```

- `--glow-spot`：**64 → 56px**（柔光要够大才读得出来；填充块只要比按钮大一圈：四周各 3px）；
- `.view-btn.on`：`.8 → 1`（选中块已经给出"在哪"，图标不再靠半透明兼任选中信号）；
- **描边走了两步**：先 `rgba(251,119,161,.35)`（≈1.44:1，太弱且是字面量）→ 换成
  **token 本体 `--c-primary-deep`**（描边对填充 ≈2.3:1、对页面 ≈2.5:1）。
  浅粉底与近白页面的亮度差只有 **1.07**，形状完全靠这条边承担 —— 这也解释了为什么不能更淡。

### 2.2 顺带修掉一个**被暴露出来的旧缺陷**：选中块盖住了激活图标

`.glow-spot` 是**绝对定位**元素 ⇒ 按 CSS 绘制顺序（定位后代画在 in-flow 内容之后）**画在按钮之上**。
R39-D 的柔光版表现为"把激活图标**洗淡**"（白 .90 盖住），换成不透明填充后就变成
**"块里什么都没有"** —— 截图上一眼可见（第一次截的放大图就是一块空白粉底）。

修法：`.view-btn { position: relative; z-index: 1 }`。
**这不是新引入的问题，而是旧问题被不透明填充暴露**：之前没人能一眼看出"图标被洗掉了"。

### 2.3 护栏：探针从 5 条加到 8 条

| 新判据 | 拦的是什么 |
|---|---|
| 选中块背景**不得是渐变/图片** | 退回"白光点"那套（在近白背景上看不见 —— 本次要修的病） |
| 选中块底色 **alpha 必须 =1** | 半透明填充在浅背景上糊掉 |
| **不得盖住激活图标**（`coversIcon`） | 绘制顺序回归。⚠️ **常规命中测试看不出**（块平时 `pointer-events:none`，`elementFromPoint` 会绕过它）⇒ 探针**临时把它的 `pointer-events` 打开**再命中测试，才问得出真实绘制顺序 |
| 激活钮必须参与定位层（`position`/`z-index`） | 同上，给结构性兜底 |

旧 5 条（中心 ≤1.5px / 宽度 ≥56 / `pointer-events:none` / 过渡含 transform / 光条四条毛玻璃口径）全部保留，
**没有一条被放宽** —— 因为 56px 正好是"比按钮大一圈"的尺寸，原判据天然兼容。

## 三、验证（每步都看了真实像素，不靠算式）

| 步骤 | 结果 |
|---|---|
| 探针 `--shot --width 1440`（改前） | 全绿，但放大图显示**粉底块是空的**（图标被盖） ⇒ 发现 2.2 |
| 加 `position/z-index` 后重跑 + 放大 | 图标回到块内（`≡` 深色实心），相邻两枚仍是 `.4` 浅灰 |
| 描边换 token 后重跑 + 放大 + 采样 | 顶边 `#FB77A1`（=`--c-primary-deep`）、填充 `#FFF0F3`（=`--sel-bg`）、页面 `#FFFBFB`；观感为"浅粉底 + 1px 主色粉边 + 实色图标" |
| 默认三档宽度探针 | **问题=0**（8 段视图契约 + 三档宽度全绿） |
| `tsc` / `eslint --max-warnings 0` | **0 错** |

判据的机器化程度：**绘制顺序**这条是本次最有价值的护栏 —— 它拦的错法（"看得见却看不见内容"）
在几何断言与常规命中测试下**都是绿的**，只有"临时打开 pointer-events 再问一次"能问出来。

## 五、遗留（本次刻意没动，留给下一轮）

1. **光条的 footprint 与新选中块不匹配**（量出来的数）：
   - 纵向：条高 59、块 56 ⇒ 上下各只剩 **1.5px**，贴着顶栏显得挤；
   - 横向：条宽 354、内容 230（四枚 50 + 3×10）⇒ 两端各 **62px** 空白 —— 那是当年给
     "柔光在盒子内归零"留的收口空间，现在块是紧凑 chip，这 62px 就没有理由了。
   两条路：把条高提到 ~64-66，或把条宽收到贴住按钮（230 + 2×8）。**改的是 footprint**，
   牵动 UI-MAP 的 354px 规格与按 `barRect` 取剖面的像素分析，所以单独一轮做。
