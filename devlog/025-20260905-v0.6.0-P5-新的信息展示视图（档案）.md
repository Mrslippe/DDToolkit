# 025-20260905-v0.6.0-P5-新的信息展示视图（档案）

## 概述

P5 落地：第三个与 cards/list 同级的「档案」视图（占用原「日历视图·开发中」
占位钮）。数据层早已就绪（P4 回填的 7433 行粉丝历史 + 3010 行礼物日聚合 +
9141 条企划索引），本次以**服务端降采样 + shadcn Chart** 把档案能力兑现：
粉丝趋势双线图 → 返回 2019-07-03 起的完整历史（七海 8453 → 111 万粉）；
直播日历；企划/阵营/设定集档案卡。

## 后端（3 新端点，读取只算）

- `GET /account/{id}/fan-trend`：服务端按天分桶——self 取**每日最后一条**
  （5min 高频直采不抖动）、zeroroku 日粒度全量保留（补历史空洞）；
  实测 1947 点（含 self 2 点 + zeroroku 1945 点），图表直用。原始 7433
  行不上行的关键：数据本地不足 100KB，但 JSON 解析/传输/渲染都按点计；
- `GET /account/{id}/live-sessions`：由 self 快照 `live_status` 转移点推导
  场次（0→1 开场 / 1→0 收场，5min 粒度近似；进行中 end_at=None）；
- `GET /externals/vtubers/by-uid`：企划精确查询（档案卡 group_name 来源）。

## 前端（组件封装 + 视图接线）

- **shadcn Chart**（`components/ui/chart.tsx`，recharts **2.15.4**）：
  用户定引用库（美观/生态）；主题映射 `--chart-1..5`（粉系 token）；
  recharts 3.x 与 registry 版 chart.tsx 类型不兼容 → **降级 2.15.4**
  与 registry 声明依赖一致（首次安装 3.10 即踩到，降级后零改动通过 tsc）；
- `<FanTrendChart>`：薄封装（双 Line + CartesianGrid + X/Y 轴 + Tooltip/
  Legend）；props 只收数据点，内部实现可替换；
- `<LiveCalendar>`：手写月网格（可翻月）；绿点=当日直播证据、满格=礼物日，
  悬浮显示礼物/大航海/SC 原始字符串（保精度）；
- `<ProfileCard>`：阵营 Select 编辑（选项自动建议第三方 `group_name`，
  「采纳」一键写 `faction`，乐观更新失败回退）、企划·公会（只读+来源）、
  生日/出道/房间号、设定集折叠；
- `<ArchiveView>`：按账号维度独立拉取（fan-trend/sessions/gift-days/
  by-uid 并行），scene 容器复用（key=acc|view 转场无缝），
  header-actions 操作钮行对 list/archive 共用；
- glow-bar：日历占位 → 档案钮（BarChart3）。

## 已知限制（记录不掩盖）

- live-sessions 依赖本机运行时长：应用没开的时间窗无快照，可能把跨越停运
  窗口的场次连成「进行中」（冒烟即出现一例）——日历以「当日是否有直播
  证据」为展示语义，不做精确时长断言；
- self 曲线仅在应用运行时采样（当前 dev 库仅 2 个 self 点），zeroroku 线
  是曲线主体——两条图例如实呈现「本工具直采 vs 第三方回填」的互补关系；
- 图表未做缩放/刷选交互（recharts Brush 留待数据更厚时启用）。

   （默认账号=页面层选中或 B站优先；切 V 时保留同 id 选中）。
