# 731-20261028-结果包：每个 V 一个分析结果，写盘（后端部分）

## 用户需求

> 1. 分析结果应该作为一个包存在于缓存中，每个 V 存各自的结果，当切换到这个 V 的时候
>    默认展示这个结果，时间区间也默认跳到这个结果对应的区间；
> 2. 当用户重新选取时间段分析时，就用新的分析结果覆盖原结果；
> 3. 分析结果中的分页就直接读取结果包，对比分页中对比的基本单位就是缓存中的这些结果包。

四条决定（用户 2026-10-28 确认）：**写盘**；切 V 时**滑杆窗口与日期区间都跳**；
对比允许求交但**相对量标注不可比**；覆盖**要二次确认**。

## 这一批做了什么（后端）

新增 `app/services/fan/packages.py`：

```
数据根/_packages/{subdir}.json.gz
{ version, vtuber, subdir, window, since, until, live_ids[], sessions, computed_at,
  overview: { pool, tiers{}, uid_tier{uid: tier}, uids[] },   ← 对比页的基本单位
  payload }                                                    ← 完整结果（分页直接切）
```

| 设计点 | 理由 |
|---|---|
| **每个 V 一个包位**，`save()` 整包覆盖 | 用户第 2 条：重新分析就覆盖；所以前端要二次确认 |
| `payload` 存**名单全量行** | 用户第 3 条：结果分页直接读包，只有全量才能本地切页 |
| `overview.uid_tier`（uid→层级） | 对比页的「层级迁移」需要知道同一 uid 在**各自包里**属于哪一层；只存计数不够 |
| 写盘用 **tmp + 原子替换** | 半途挂掉不会留下半个包；`load()` 坏包/版本不符一律返回 None（回退现算） |
| `matches()` **六格比对** | 窗口 / 区间 / 场次清单，少比一格就是拿错数据（`devlog/730` 的教训） |

`app/routers/fan.py` 的接线：

1. `_compute`：内存 `_CACHE` 未命中时 → **先查包**（`matches` 命中就直接返回 payload，
   **不再读盘**）；算完之后 → **写包**（写失败只记日志，不影响这次分析）；
2. 新增 `GET /fan/packages`（所有包摘要，不含 payload）与
   `GET /fan/{v}/package?with_payload=1`（404 = 还没包）；
3. `purge` 真删数据时**连带删包** —— 否则切回来会看到"基于已删数据"的结果。
