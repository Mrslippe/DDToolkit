# 595-20261021-独轮车误判：v2 必须带「占比」门槛

用户拿 `431410658` 的实际弹幕截图反馈：他的弹幕是正常发言 + 零星的"哈哈哈"，
不该被判成独轮车。查证属实，v2 有三处问题。

## 一、用户实际情况

| 指标 | 值 |
|---|---|
| 消息总数 | 69,604 |
| 不同文本 | **50,066（72% 不重复）** |
| 最高频文本 | 3,961 次，占 **5.69%** |
| v1 判定 | **不是**（整体重复率 28% < 60%） |
| v2 判定 | **是**（window：窗口重复率 0.94） |

**v1 是对的，v2 错了** —— 因为 v2 只看"单条次数/窗口重复率"，完全不管这条文本占他全部消息的比例。

## 二、修了什么

1. **加占比门槛**：`sustained` 要求该文本占其全部消息 **≥20%**；`window` 要求 **≥10%**；
   `cross_session` 从 5% 提到 **25%**（5% 会被口头禅误伤）。
2. **两个计数 bug**：
   - `sum(counts.get(top_h, []))` 把**时间戳**求和了（算出 9.7e14 这种数），改成 `len(...)`；
   - `cross_session` 的占比分子用的是"出现场次数"而不是"累计条数"，已改为后者。
   —— 前者正是这次误判的直接原因：`window` 的占比被算成一个天文数字，恒 ≥10%。

## 三、修后结果（明前奶绿）

| 指标 | 修前 | 修后 |
|---|---|---|
| v2 判定 | 186 人 | **155 人** |
| `431410658` | 判为独轮车 | **正常**（最高频占比 0.78%） |
| 规则分布 | window 114 / cross 35 / sustained 37 | window 39 / cross 79 / sustained 37 |

新抓到的典型：`317676427`（10,457 条，单条重复 1,066 次，窗口重复率 0.97）——
这种才是真独轮车。
