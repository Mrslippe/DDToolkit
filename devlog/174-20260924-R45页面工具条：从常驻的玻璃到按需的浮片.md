# 174-20260924-R45 页面工具条：从「常驻的玻璃」到「按需的浮片」

> 用户（2026-09-24，前端评审第 2 问）：「右栏顶部的光条……它现在的模糊液态玻璃背景真的
> 和我们当前项目适配吗」→ 我给了三条结构性证据（不是"好不好看"）。用户随即说出真正想要的：
> 「既能够指示当前处于哪个界面，又**不要太突兀去抢占用户的视线**，另一方面我希望在
> **没有需要用到它的时候可以自动隐藏**起来」。
> —— 这三条把问题从"表面材质"改成了"**行为**"，而**第 3 条顺手解掉了第 2 条**。

## 一、先回答"适配吗"：三层证据，都不在"好不好看"上

| 层 | 结论 | 证据 |
|---|---|---|
| **美学** | 项目最深层的隐喻是**纸**，玻璃是它的反面 | ① 浮片＝斜切白卡；④ 档案卡族＝注释原话「**贴纸卡**…圆角阴影稍微浮起」。贴纸说"面是不透明的、盖在上面的"，玻璃说"面由背后的东西定义" —— 两套互斥的表面理论。同一列里另两个浮动控件（`.bg-tools` 的 FloatPill、`.back-to-top`）**都是"不透明白 + 阴影"**，只有光条是玻璃 |
| **功能** | 默认态下它**精确为 0**，不是"淡" | 默认背景合成 ≈ `#fffbfb`（头像只 0.18，再被 `::after` 两层纱罩压到 <1% 贡献）：白 `.10` 叠上去 254.1 vs 254（差 0.1/255）、白 `.22` 内描边同理、`blur` 作用在**平滑纱罩**上等于没作用。**这条 devlog/164 §一 第 3 条已经量到过**（「白 0.10 的玻璃…叠上去等于没有」）—— 但当时只修了柔光那一半，**玻璃这半没进 §五遗留，掉了** |
| **制度** | 它被自己的门禁锁死，三条出路全封 | `_assert_glow` 当时写着：`alpha > 0.2 → FAIL`（不许靠填充变可见）· 非 none 必须含 `inset`（不许靠高度变可见）· 不许有 border（不许靠边线变可见）· **`blur` 必须存在**。⇒ **唯一被强制保留的手段，恰好是默认态下唯一无效的手段**。门禁是上一轮为"防退回旧状态"写的，它做到了，但顺手把所有出口也封了 |

**一条技术上不成立的推理**（留档）：R39-D3 的理由是「blur 让背景**变糊**而不是**变白**
⇒ 没有"细节消失的边界"可读」。但**"变糊"就是"细节消失"最字面的形式** —— blur 抹掉的正是
中高频，而人眼对比敏感度的峰值就在中高频。公平地说：用户之后确实没再抱怨边界
（devlog/164 的问法是"美学不统一"）⇒ 玻璃**解决了它被派去解决的那个抱怨**，
但它换来的是**另一种**纹理边界（冲淡型 → 失焦型），不是"边界消失"。

## 二、真正的重构：**常驻**才是"突兀"的根源

> 玻璃这套语言的含义是「**浮在内容之上、用完就退**的控件」（iOS 导航栏滚动时收缩、
> Liquid Glass 的全部用法）。把一块玻璃**永久钉在 hero 图顶部中央**，是手段与语义的矛盾。

变成"按需出现"之后，**"不透明浮片"的代价从"永久"降到"仅交互的那几秒"** ⇒
它从最贵变成最便宜。**这就是第 3 条要求解掉第 2 条要求的地方。**

比这更重要的是：**原来的"隐藏"是假的** —— 隐藏后 66px 还在占位，那不是隐藏、只是看不见。
改成 `position:absolute; height:0` 之后隐藏才真的把空间还给内容。

## 三、R1 与 R3 的直接冲突（分权）

「指示当前在哪个界面」与「不需要时自动隐藏」**不能同时字面成立**。分权：

| 角色 | 承担者 |
|---|---|
| 主指示器 | **内容本身** —— 卡片/列表/牌堆/画布形态差异极大，不需要控件告诉你 |
| 按需指示器 | 工具条可见时的选中块（`.glow-spot`）—— 控件只在"你正在找切换入口"那一刻回答"我在哪" |
| 反馈 | 冷启动首挂 + 深休眠唤醒时**闪现 1.2s** |

## 四、几何：**50px 是元凶**

| 顶部这一行的元素 | 高 |
|---|---|
| `.acc-switch-btn` 账号切换器 | 30 |
| `.type-chip` 分类胶囊 / `.search-float` | 25–30 |
| `.bg-set` 配置浮片 | 30 |
| **`.view-btn` 视图钮** | **50** ← |

只有它是 50 ⇒ 它得占 59px 的条、撑出 66px 的带子。**这是"突兀"的尺寸来源**，
也是 overlay 在窄档撞车的根因。缩到 **34** 之后条变 **176×46**：

```
y=6 .. 52    工具条（条底 52）
y=12 .. 42   账号切换器（30 高）—— x 上分离，y 重叠无害
y=52 ..      分类胶囊 / 搜索筛选（.type-chips 有 6px padding 出血，实体从 52 起）
```

⇒ **条底 52 与胶囊顶 52 严丝合缝**，零视觉重叠（原方案条高 59 + `top:0` 是压着胶囊的）。

面板宽 = 窗口 − 542（rail 50 + sidebar 492）⇒ 1100 档只有 **558px**，是全案约束档。
`posts.css` 的 `@media (max-width:1200px) { .acc-switch-name { max-width:72px } }` 就是为它加的：
条 176 居中 ⇒ x=191..367；名称 120 时切换器右缘 ~214（**压 23px**），收到 72 ⇒ ~166（**余 25px**）。
**让"数据相关的那个"（账号数 × 名称长度）让步，而不是让布局模型变形。**

## 五、⚠️ 一处偏离批准方案：5 个动作钮**没有**搬进工具条

用户批准的是「五个全搬」，**我没搬**，理由是量出来的：

> 1100 档右上组可用宽度 = 546 − 367 − 8 = **171px**。
> 5 枚文字胶囊（`FloatPill --md`，4 个汉字 ≈ 88px）= 4×88 + 3×8 = **472px**。
> ⇒ 差 300px。**搬过去会撞上 1100 档的宽度墙。**

而且**搬不搬都不省空间**：`.header-actions` 是**内容**、不是工具条，它本来就占那 42px。
搬过去唯一的好处是腾出右上角给"页面配置钮"—— 而那枚钮目前只存在于卡片页
（`.bg-tools`，`scene.view === 'cards'`），与列表页的动作钮**不会同时出现**。

⇒ 结论：**本批不动它**。真要搬，得先把它做成**溢出菜单**（`[操作 ▾]` 64px + `[设置]` 32px
+ gap = 104px，能塞进 171px），那是一个新组件（仓里没有 Radix dropdown，
`PostFilterPop` 是自绘的），单独一批做。已记进 `docs/TODO.md`。

## 六、探针抓到的两个**真 bug**

### 6.1 StrictMode 下闪现定时器被清掉，`barShown` 永久停在 true

`ui_probe.py --toolbar` 第一次跑就红：`rest: shown=1 opacity=1`，而 `afterLeave` 正常。

根因链：`React.StrictMode`（`main.tsx:237` 确实开着）下 effect 走
**setup → cleanup → setup**：

1. 第一次 setup：`showBar()` + 装 1200ms 闪现定时器
2. StrictMode cleanup：**把定时器清掉**
3. 第二次 setup：`toolbarFlashedThisSession` 已是 true 且非唤醒 ⇒ **早退** ⇒ 定时器再没人装
4. ⇒ `barShown` 永久 `true`

修法：**"要不要闪"在渲染期决定一次（`wantFlashRef`），effect 只负责装定时器**（可重复执行）。
⚠️ 这是**真 bug 不是探针假阳性** —— 开发模式下工具条会一直挂着不下来。
**探针钉的是机制而不是现象**，才问得出这个：`afterLeave` 是绿的（那条路径自己装了定时器），
只看"能不能收回去"会以为没问题。

### 6.2 旧的 `coversIcon` 判据在"条按需出现"之后变成假阳性

那条判据（R39-D4）问的是**绘制顺序**：临时把 `.glow-spot` 的 `pointer-events` 打开，
再 `elementFromPoint` —— 命中的若是块本身，就说明块画在按钮之上。

**它隐含假设"工具条永远可命中"。** R45 之后 rest 态整条是 `pointer-events:none`
⇒ 只打开块的话，命中的**必然是块本身** ⇒ 假阳性「块盖住了图标」。
（实测：默认三档里只有 `archive` 报红 —— 因为那一点上恰好没有别的可命中元素"接住"这次命中。）

修法：**临时把整条 `.glow-bar` 打开**，让两者都可命中，绘制顺序才观测得到。
⇒ 又一次印证同一条：**判据会悄悄依赖一个没写下来的前提。**

## 七、门禁：整套换口径（**不是放宽**）

R39-D3 那四条（必须含 `blur` / alpha ≤0.2 / 非 none 必须含 inset / 圆角 ≥8）**整套替换**。
理由：**它们写的是上一轮的结论（"必须是毛玻璃"），不是那一轮要保护的性质。**

新的分四组：

| 组 | 判据 |
|---|---|
| ① **overlay 成立** | `toolbarH == 0` · `bodyH == panelH` · 整条 `pointer-events:none` |
| ② **不与内容控件相交** | 条/右上组的 rect 与 `.acc-switch-btn`/`.type-chip`/`.search-float` 的 rect 不相交（列表视图必须有这些控件，缺了判失败 —— 否则判据静默空转） |
| ③ **可见性与对比度** | rest 态 `opacity ≤ 0.02` + 不吃指针 · **不许有 `backdrop-filter`** · 底色 **alpha 必须 =1** · **必须有外阴影** · 圆角 ≥8 · **off 态非文本对比 ≥3:1**（按渲染值算，不写死数字） |
| ④ **选中块** | R39-D4 的六条**一条没放宽**；只把「宽 ≥56」改成**相对关系**「宽 ≥ 按钮+6」—— 原写法把上一轮的尺寸当成了性质 |

**② 是本次最有价值的产出**：它把用户的"手感"要求（账号切换/分类切换/搜索筛选必须
最直接可触及）变成了**机器判据**。

**③ 里的"必须有外阴影"是旧判据的反转**，它第一次真正断言了老门禁一直想保护、
却从没断言过的东西：**默认态下这个面看得见**。

新交互档 `ui_probe.py --toolbar`（`?probe=toolbar`）钉状态机五态：
`rest` 全隐 / 进热区 + dwell 呼出 / 移出 + grace 收回 / **Tab 聚焦由 `:focus-within` 显形**
（拦"聚焦到看不见的控件"）/ 呼出前后内容区高不变。
探针里**先杀过渡**（本仓老招）：虚拟时间下过渡不推进，`getComputedStyle().opacity` 会一直
报过渡起点 ⇒ 那样"呼出来了没有"就变成尺子问题。`data-shown`（机制）与 `opacity`（效果）
**两条一起判**，才分得清"机制没生效"和"尺子读不到"。

**顺带补一层单测**（`utils/toolbarZone.ts` + **10 条**）：热区判定抽成纯函数
`inHotZone(x, y, rects, pad)`。理由是**探针只走得到"命中 / 不命中"两个点**，
而这段逻辑真正容易错的是**边界与多矩形并集**：

- 多矩形取并集（条够不到的地方，右上组自己也能触发）；
- 两个矩形**之间**的空隙**不算**命中 —— 热区不是"从条左缘到右上组右缘"的一整条；
- `null` 与**零宽**项跳过（零宽 = 未布局；当成一个点会造出一块**看不见却能触发**的热区）；
- 纵向下沿 `52 + 8 = 60`，`61` 就不命中 ⇒ **悬停分类胶囊（y=52 起）不会把工具条叫出来**。

## 九、遗留

1. **命名债（这次没还）**：`glow-bar` / `glow-spot` / `--glow-spot` 已名不副实（不再是"光"）。
   我原以为"这次本来就要动三处引用，搭车免费"—— 但开工时 `ui_probe.py` 与 `UI-MAP.md`
   **正被另一个会话改着**，改名的合并风险大于收益 ⇒ 推迟。已记进 `docs/TODO.md`。
2. **"向下滚动立即隐藏"没做**：不是正确性所需（指针离开 900ms 后自然会收），
   且要给 `OverlayScroll` 加**方向**信号（共享组件，风险外溢）。单独一批。
3. **列表页动作组展开时可能与条重叠**：`.actions-extra` 展开到 `max-width:480px`，
   在 1100 档会伸到条的下方（x=62..542 vs 条 191..367）。**当前不触发**——
   要展开得先点右侧的展开钮（x≈406，在热区 375 之外），条已经收回；但 900ms grace
   窗口内理论上能撞上。探针的"不相交"判据**只覆盖 `.acc-switch-btn`/`.type-chip`/
   `.search-float`**（用户点名要保的三个），没覆盖动作钮 —— 因为用户已同意它们可以搬走。
4. **`saturate(1.08)` 已删**（8% 在感知阈值以下，纯多一遍滤镜），但它**在旧探针里没有判据**，
   所以是"删了但拦不住别人加回来"。已并入第 ③ 组的"不许有 `backdrop-filter`"。
