# 420-20261007-V1b3取景口径换成图片锚点

需求 7 第四批。用户看完对比示例稿（`docs/design/background-fit/resize-drift.html`）**选了 C**：
保持铺满（`cover` 不动），把取景的**口径**从"溢出百分比"换成"**图片锚点**"。

## 为什么要换（量出来的，不是感觉）

面板高度不变、宽度从 716 拉到 1336（就是用户那两张截图）时，同一组存储值：

| | 缩放 | 锚点实际落在 |
|---|---|---|
| 旧口径 | 1.65× → 3.09×（+87%） | 35% → **13.5%** |
| 新口径（C） | 1.27× → 2.38×（+87%） | 35% → **35%** ✓ |

旧口径存的是"**溢出量的百分之几**"，而溢出量本身随宽高比变 ⇒ 同一组数字换宽度就落到别处。
**归一化救不了这一层**（归一化只管 DPR/像素无关，管不了 `cover` 改变裁切）。选 C 就是承认
"缩放随宽度变"是 `cover` 的几何必然，只把**对齐**钉死。

## 改了什么

- `utils/backgroundFocus.ts`：`focusTransform`（translate + scale）→ **`focusStyle`**（三件套）。
  位置 `background-position: x% y%`、缩放 `transform: scale(s)`、**支点 `transform-origin` 与位置同源**。
  ⇒ `x`/`y` 与 CSS `object-position` 完全同向，浏览器自己算宽高比，**不用量容器、不用图片原始尺寸**
  （只有拖拽要，那是 `panDelta` 的事）。
- `panDelta(dPx, boxPx, imgPx, scale)`：拖拽换算，分母是**负的溢出量**。
  ⚠️ 没余量的那条轴返回 0 —— 竖图铺在宽面板里**横着拖不动是正确结果**。
- `BackgroundFocusEditor.tsx`：拖拽改用它；**删掉"拖动自动抬到 120%"**（那是旧口径下
  "`scale=1` 时平移无处可去"的权宜之计，新口径下 `scale=1` 纵向照样能挪）；
  预览框的**比例从真 `.hero-backdrop` 量**（`align-self:flex-start` + `width:auto` + `aspect-ratio`，
  用真引擎验过 1.78/0.95/2.6 三档）。
- `BackdropCrossfade.tsx`：改挂三件套。
- 后端只存不算 ⇒ 只有注释/文档跟着改（形状没变：`0..1` / `1..3`，**老值被重新解释**，
  本仓此时无真实用户数据）。

## 判据（+6，见 `docs/ops/PERF.md` 那一行）

★**锚点守恒**（多条宽度×缩放×比例的组合，锚点必须落在同一比例位置；含"支点写成中心就会漂"的反面对照）·
★**永不露边**（`x,y∈[0,1]` + `scale≥1` ⇒ 图始终盖满框）· ★**拖拽 1:1**（挪完之后图上那个点真的挪了那么多像素）·
★**三件套一起挂且支点同源** · ★**没余量的轴一动不动**（不许除出个巨大跳变）。

## 顺手抓到的两个真 bug

1. **V1b-1 的**：`BackdropCrossfade` 的首层 `focus` 写死 `null` ⇒ "页面加载后**第一次**换 V"时，
   正在淡出的那层退回居中、图跳一下。新判据（旧层跟自己的取景）当场把它照出来。
2. **V1b-2 的**：内联样式里拖一下就是 `28.57142857142857%` ⇒ `focusStyle` 收敛到两位小数
   （**库里那份不收敛**，否则每次拖拽都会把取景改一点点）。

## 教训

**判据要判"外面的世界"，不要判自己的表达式。** 旧口径下那批用例（`devlog/418`）断言的是
`translate` 的数值与范围 —— 全绿，却拦不住"锚点换个宽度就漂"，因为它们只跟自己的公式对齐。
这次的②③④都写成 **CSS 语义的模型**（`cover` + `background-position` + 绕锚点的 `scale`），
所以"支点写错""符号反了"当场红。
