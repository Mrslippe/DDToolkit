## 一、为什么把它单独成模块

`frontend/src-tauri/src/migrate.rs`，只依赖 `std` + Windows 的磁盘余量 API。三条判定写成了
可测的纯逻辑 —— 因为**这是 R22 里唯一可能让用户丢数据的地方**：

| 函数 | 判定 |
|---|---|
| `plan_migration()` | 目标必须是**存在的绝对路径目录**；不能等于 / 包含 / 被包含于当前目录（否则复制自我递归）；目标盘可用空间 ≥ 待复制体积 × **1.15**；新数据目录 = `所选目录\DDToolkit-data`（用户口径：自动建子目录） |
| `copy_tree()` | 递归复制，**跳过 `logs/` 与 `static/img-cache/`**（用户口径：诊断与可再生）；**符号链接一律不跟随**（可能成环，也可能把外部数据抄进来） |
| `verify_copy()` | **逐文件比对相对路径与字节数**，缺文件/大小不符/多出文件都算失败，报错列前 5 条明细 |

> 为什么"复制完还要逐文件校验"：复制之后马上写指针、之后就切到新目录了，
> **用户没有任何补救机会**。少一个 `.env` 就是"登录信息没了"，
> 少一个 `vtuber.db-wal` 可能就是"最近几小时的帖子没了"。

## 二、两条纪律的落点

1. **旧目录全程不动**：`copy_tree` 只读源、只写目标；`verify_copy` 只读两边。
   所以最坏情况是"新目录里有半份数据被丢掉"——用户的原始数据始终在原处。
   （这也是为什么"删旧目录"必须是**事后单独一步 + 用户确认**。）
2. **探活成功才算成功**（下一步接线时执行）：写完指针后用新目录拉起 sidecar，
   探活失败就回滚指针、用旧目录重启 —— 而不是"指针写了就算迁好了"。

## 三、用例（+7，`cargo test` 19 passed / exit 0）

| 用例 | 钉什么 |
|---|---|
| `plan_skips_logs_and_image_cache` | 跳过项的**字节数真的不算进去**（4096+512+env+csv+64，日志 9999 与缓存 7777 不参与） |
| `copy_then_verify_is_clean_and_skips_stay_behind` | 复制后校验通过 · `.env`/库真过去了 · 日志与图片缓存**没**过去 · **源目录一个文件都没少** |
| `verify_catches_a_missing_file` | 少一个 `.env` 必须报"缺文件"并点名 |
| `verify_catches_a_size_mismatch` | 大小不符必须报（见下面的教训） |
| `rejects_same_nested_and_containing_targets` | 同一个目录 / 目标在源里 / **源在目标里**（选了 C:\Users 这种）三种都拦下 |
| `rejects_missing_or_relative_target` | 目标不存在、相对路径两种都拦下 |
| `free_space_is_reported_for_an_existing_dir` | Windows 上真能问到磁盘余量（拿不到时返回 `None`，**不据此拒绝迁移**） |

> ⚠️ **一个值得记的教训**：`verify_catches_a_size_mismatch` 第一版**通过了** ——
> 因为我把 `vtubers.csv`（`"name,uid\n"`）覆盖成了 `"truncated"`，两者**都是 9 字节**。
> 用例自己"绿"了但什么都没测（这正是本仓库反复强调的"测试量错了轴"）。
> 修法是把覆盖内容改成明确的长度差（1 字节），并把这个坑写进用例注释。
