# 131-20260916-探针脚本语法事故与门禁补齐

> 用户报"不同视图 / 不同 V 之间快速切换有明显卡顿"，我为了取真实数字去跑
> `python scripts/ui_probe.py --scene` —— 命令直接抛 **SyntaxError**。
> 一查：**是我上一批（R29）改坏的**，而且**推上去之后没有任何门禁发现**。
> 本批先修事故、再补门禁，最后才回答用户的性能问题。

## 一、事故本身

R29 那批我在 `ui_probe.py` 的 `--tray-suspend` help 文案里加了一句说明，
其中用了**直引号**：

```python
             "看不到它 —— 所以"隐藏后零请求"只在这个窗口内成立，不是永久承诺。",
                                        ^^^^^^^^^^ Python 字符串提前闭合 ⇒ SyntaxError
```

`ast`/Python 层面等价于把一个字符串拆成三段，编译器当场不干。
**修法**：直引号改成「」（本仓中文文案本来就用「」，既是风格也是安全）。

## 二、为什么没被发现（这才是重点）

| 门禁 | 会编译 `scripts/` 吗 |
|---|---|
| `pytest` | 不会（只 import `app/` 与 `tests/`） |
| `tsc` / `eslint` / `vitest` | 不会（前端） |
| `cargo test` | 不会（Rust） |
| `doc_check` | 不会（只读 Markdown） |
| `release.py` 的 gates | 同 pytest/tsc/eslint/vitest |

⇒ **一个纯开发工具的语法错误可以完全绕过全部门禁**，直到下次真要跑它才暴露。
这正是本仓最忌讳的那类**静默失败**：工具坏了，但没有任何红灯。

**影响面**：`ca286d8`（R29）之后到本次修复之间，`ui_probe.py` 整体不可用（14 个探针模式全挂）。
⚠️ 但 R29 的证据**仍然有效** —— 那次 `--tray-suspend` 实跑发生在这行 help 改动**之前**，
探针当时是好的（本次也重新跑通了 `--scene`，见 §四）。

## 四、顺带：本次为回答"切换卡顿"取的实测数字

`python scripts/ui_probe.py --scene --vtuber 15 --width 1280`（真后端 + 真浏览器）：

```
候选 V=8 目标='泽音Melody' 点击前 hero='七海Nana7mi'
提交耗时=250ms 末态 hero='泽音Melody' 路由='/vtubers/14'
在途请求=0
  · done 10ms /vtuber/14
```

**切 V 的总耗时 250ms，其中后端只花 10ms** ⇒ 瓶颈不是网络/后端，
而是"**200ms 刻意退场动画 + 新视图挂载**"（`EXIT_MS=200` 见 `hooks/useSceneTransition`）。
这组数字是回答用户问题的依据，详细分析见对话记录与 devlog/132（若后续做优化）。

## 五、教训

1. **改字符串字面量先看引号**：中文文案一律用「」，别用直引号 —— 这次是自找的；
2. **"没被门禁覆盖的代码"等于没有护栏**：加这个 0.2 秒的语法步比事后查半天便宜得多；
3. 遇到"工具本身坏了"时**先修工具再干活** —— 否则你会把工具的错误当成事实（本次差点
   把 SyntaxError 当成"探针不可用"而放弃取数）。
