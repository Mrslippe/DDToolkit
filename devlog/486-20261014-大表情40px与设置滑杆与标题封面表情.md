# 486-20261014 大表情默认 40px + 设置里的滑杆 + 标题与纯文字封面也画表情

> 用户口径（接 `devlog/485` 那批两类大小）：
> 「大表情的大小默认为 40px，然后在设置中给一个滑杆供用户调节；
> 同时在标题和仅有文字的封面也渲染表情包」。

## 一、大表情默认 32 → **40px**

CSS 里那一档改成读**变量**（`--post-emoji-big`，兜底 40px），于是"用户调多大"与"在哪画的"
解耦：`.post-emoji--big { --post-emoji-size: var(--post-emoji-big, 40px) }`。

⚠️ **对齐跟着尺寸走**：`vertical-align` 从写死的 `-11px` 改成
`calc(var(--post-emoji-size) / -2 + 5px)` —— 不这么改，用户把 40 调到 64 之后表情会**吊在半空**
（尺寸变了、对齐没变）。这条规则仍然只有一条：中心落在基线往上 5px。

## 二、设置里的滑杆（「外观 → 大表情大小」）

这是**第二种控件形态**，所以顺手把偏好系统扩了一格：

| 层 | 改了什么 |
|---|---|
| `app/routers/settings.py` | `PREFS["post_emoji_big"] = ("40", *range(24,65,2))` —— 值仍是**字符串**（这套偏好一律字符串），**白名单就是滑杆的 21 个档位** ⇒ 越界/怪值照旧走既有的 400 分支，不用新写校验 |
| 同上（spec） | 新增 `kind: "range"` + `min/max/step/unit`。⚠️ 刻意**不给 `options`**：21 档写成选项列表只会把响应撑胖；界面按 min/max/step 画 |
| `frontend/src/utils/emojiSize.ts`（新） | 一个模块级 store：`clampEmojiBig()`（夹档 + 空值回默认）、`applyEmojiBigSize()`（写根元素的 CSS 变量）、`useEmojiBigSize()`（启动读一次）。**为什么是一个文件**：这个尺寸要在**所有**渲染正文的地方一致（详情页/标题/封面/以后别处），挂在某个组件上必然漂 |
| `App.tsx` | 挂 `useEmojiBigSize()`（壳层，不挂在设置窗 —— 否则"没打开过设置就没生效"） |
| `AppSettingsDialog` | 滑杆行（`data-setting="post_emoji_big"`）、`pickEmojiBig()`：**乐观生效 + 落库**；失败把尺寸退回**控件显示的那个值**并回显错误 |
| `posts.css` | `.aps-range-ctl` / `.aps-range-out`（⚠️ 不叫 `aps-range` —— 那个名字早被"范围提示文字"占了） |

**为什么小表情那一档不做成偏好**：它必须与正文同高（一变大就撑行高，`devlog/484` 量过 18px 是上限）。
用户只要求调大的那个，这个决定写进了后端 spec 的 note 里（界面照实显示）。

## 三、标题与纯文字封面也画表情

**做法：把"一段文字里的表情"抽成行内组件**，而不是在两处各写一遍 ——
`PostText.tsx` 里新增 `PostTextInline`（没有外层标签，四种形态：图 / 大图 / chip / 原样），
`PostText` 自己变成"`<p class="post-text">` + 它"。三个**已经有自己标签**的位置改走它：

| 位置 | 之前 | 现在 |
|---|---|---|
| 列表卡片标题 `.post-card-title`（14px） | 一串 `[梨安收藏集表情包_气鼓鼓]` | `<h4><PostTextInline/></h4>`（`title` 属性仍留**原文**，那是 hover 提示） |
| **纯文字封面** `.paper-title`（20px，无封面图时） | 同上 | `<span class="paper-title"><PostTextInline/></span>` |
| 详情窗标题 `.pd-head`（16px） | 同上 | 同上 |

⚠️ **这两处的尺寸不能沿用正文那两档**：40px 的大表情会把 14px 的两行标题撑爆、把居中的封面文字
挤出去（"贴纸该占地方"的前提是正文有整行空间）。所以给这三个位置一组 CSS 覆盖，
让表情**跟着该处的字号走**：小 `1.15em` / 大 `1.5em`（`.post-card-title .post-emoji` 那一组）。
⇒ 效果是"标题里的表情和标题一样大"，而不是"标题里插了一张 40px 的图"。

## 五、随手验的（真样式表 + 真浏览器）

`jsdom` 量不了 CSS（`var()`/`calc()`/`em` 全靠浏览器解析），所以另起一页把
**整份 `posts.css`** 搬进去、用真机库里那两枚表情（内嵌 data URL）量实际像素：

| 位置 | 小表情（size=1） | 大表情（size=2） | 对齐 |
|---|---|---|---|
| 正文 `.post-text`（14px） | 15px | **40px** | `-2.5px` / **`-15px`**（= -(尺寸/2 - 5)） |
| 卡片标题 `.post-card-title`（14px） | 16.09px | 21px | `-3.05px` / `-5.5px` |
| 纯文字封面 `.paper-title`（20px） | 23px | 30px | `-6.5px` / `-10px` |

行高：正文那一行 40px（大表情撑的，设计如此）、标题 22px、封面 32px —— 都没有炸开。

## 六、留给下次

- 滑杆的档位（24–64 步 2）是我定的：**下限 24** 保证"仍然明显大于文字"（小表情 15px），
  上限 64 是"再大就该考虑换行了"。改区间要**同时**改三处：`PREFS` 白名单、
  `emojiSize.ts` 的三个常量、用例里的断言（跨语言契约那条会盯着前两处）。
- `useEmojiBigSize()` 读失败**不重试**：CSS 里已经有默认值（40px），退化成默认是安全的。
