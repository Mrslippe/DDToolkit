## 一、为什么放弃：不是"做不出来"，是"不值"

原生重建那条路**技术上完全可行**，N0 当天已经实测到（release 构建、真机）：

| 判据 | 实测 | 对照：现在的 WebView2 小窗 |
|---|---|---|
| 形状外有没有系统阴影 | **一个像素都没有**（10 个采样点全 255） | 靠"挂宿主子窗口"绕开，代价是坐标/拖动/区域全按子窗口重写 |
| 卡片之外鼠标穿透 | **按 alpha 白送**，跨进程实测生效 | `SetWindowRgn` + 外扩 2px + 相位边界维护 |
| 动画帧率 | p95 **16.59 ms**（光栅 3.39 + 呈现 0.21） | CSS 过渡（够用） |
| 动画期间 CPU | **19.5% 单核** | — |
| 空闲 | **0 帧、6 秒 CPU = 0.000 s** | WebView2 常驻 |
| 工作集 | **8.4 MB**（冷启动到首帧 53–100 ms） | 小窗那份渲染器 **85 MB**（A/B 整树 616 → 508 MB） |

**卡在哪**：它不是"把窗口换个实现"，而是**要把整套渲染与文字重写一遍** —— 手写圆角光栅、
DirectWrite 排版与变体字轴、省略号截断、图标、三拍动画、再加上**一条全新的验证链**
（现有无头探针看不见原生像素，得自己造"离屏出图 + 与浏览器渲染逐像素对照"的金标图）。
按方案估算是 **2–3 周**，而它换来的只是"一个桌面小胶囊"。用户判断**成本远超收益** ⇒ 停。

## 二、删了什么

  → `src/widgetMain.tsx`、`vite.config.ts` 的第二个入口。
- **壳侧为小窗加的全部东西**：`WIDGET_CALLER` / `WIDGET_COMMANDS`（三条命令 + 准入表第二档）、
  `SetWindowRgn` 区域穿透与外框自愈、**宿主窗口**（`ensure_widget_host` / `SetParent` / 区域镜像 /
  `apply_widget_move`）、`setup()` 里的挂载、以及对应的测试。
- **声明面**：`tauri.conf.json` 的 `widget` 窗口、capability 里为它加的 6 条 window 权限、
  `Cargo.toml` 里为区域穿透加的 2 个 windows-sys feature。
- **探针 crate**：`frontend/src-tauri/widget-native/`（N0 用的 ULW 探针，抛弃件）。
- **文档**：`docs/plans/widget-native-rust.md`（原生方案）、`docs/plans/widget-rebuild-execution.md`
  （WebView2 路线方案）、`docs/frontend/specs/widget-window.md`（形态规格）；`TODO.md` §4 清空。
