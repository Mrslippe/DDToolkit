# 195-20260925-R49批4 账号行溢出：修一个只能靠截图发现的 bug，并补上那个判据盲区

> 用户口径（本批决策）：「**直接按照你推荐的决策**」—— 我推荐的是**换行**（不是横向滚动）+ 补判据。

## 一、这个 bug 为什么能"全绿"存在

`.account-switch` 是 `HeaderActions` 里的 flex item：账号一多就被**收缩到比内容窄**，
而它自己**不换行** ⇒ 内部药丸溢出 `.posts-panel` 的 `overflow:hidden`，**被静默裁掉**
（`--seed-accounts 8` 时右缘那枚只剩半截）。

**它是用户截图目视发现的**（R45-E），而当时**所有判据全绿**。原因在探针里：

```ts
// probe.ts —— `overflowing` 判据
const cross = r.right > d.clientWidth + 1 || r.left < -1
return cross && !clippedByAncestor(n)      // ← 被祖先裁掉的**主动放行**
```

`clippedByAncestor()` 存在的理由是对的：折叠组 `max-width:0 + overflow:hidden`
属于**有意为之**。但这条放行**同时盖住了一整类真 bug** —— "被面板裁掉"恰恰是
`overflow:hidden` 最常见的坏法。

## 二、修法（两个动作，第二个比第一个重要）

### 2.1 换行

```css
.account-switch { flex-wrap: wrap; row-gap: 6px; }
```

⚠️ **旧的顾虑已经不成立**：TODO 曾担心"行高变高会让筛选弹窗算错高度" ——
而 R45-E 已经把那个高度改成**实测 + ResizeObserver**，能自动跟上。
（这正是"先把量测改成实测"的回报：它解锁了这一处的修法。）

### 2.2 补判据 —— **写具体，而不是放宽**

**没有**去动 `overflowing` 的放行条件（那会把折叠组那类**有意**的裁掉全部报红）。
新增一条**只盯账号行这一个契约**的判据：

> `clippedOverflow`：`.account-switch` 的子元素**不许越过它自己的矩形**。

这是本仓判据设计的一条通用取舍：**当一个放行条件同时保护"有意为之"和"真 bug"时，
不要放宽/收紧那个条件，而是为目标单独写一条更具体的判据。**

### 2.3 判据里顺带带出的证据

`clippedOverflow` 同时报 `rowH`（行高）与每个子元素的高 —— 换行生效时行高会从
30 → 66（两行 + 6 gap），这也让"真的换行了"可被机器确认，而不是只看 CSS 里有没有那一行。

## 三、反向验证（判据有没有牙的唯一证据）

把 `.account-switch` 改回 `nowrap` ⇒ **7 处红**，精确点名：

```
@1100 list: 账号切换行里有 5 枚药丸**越过本行矩形**（行高 30px）
⇒ 会被 `.posts-panel` 的 `overflow:hidden` 裁掉：
BUTTON.acc-switch-btn [964,108 → 1091,138]；…
```

**这正是改动前那个"全绿"的 bug。** 恢复 `wrap` ⇒ 三档 问题=0。
