# 150-20260918-档案视图拖动闪动修复：跟手补偿取错格位 + 拾起推动画布

> 用户 2026-09-18 报障原话：「按住并移动卡片的时候有**明显的闪动和位移**，
> 像是鼠标**每一点移动**都让这个卡片在**吸附不同的网格**，检查是什么原因」。
>
> 这是一次**报障 → 量 → 修 → 变成断言**的完整闭环。没有靠猜：新加了一条轨迹诊断，
> 一跑就把两个叠加的原因分开了。

---

## 一、先造尺子：轨迹诊断 `ui_probe.py --motion-trace`

原来的 `--motion-cards` 只抽两点量跟手（同格内 +30 / 跨一格），两点**恰好都对**，
所以它是绿的 —— 而真鼠标的每一步都在错。新诊断模拟真鼠标：

- 小步连续移动 **26 次**（每次 8px），每一步量「卡片中心实际位置 vs 期望位置（本段起点 + 指针位移）」；
- 同时记下模型格位、内联 transform、`data-flip`、卡片上的动画实例数、**DOM 顺序**。

第一次跑就给出结论（`最大误差 212.5px，超差步数 18/26`）：

```
 步  误差(x,y)        列  行  相位     内联 transform
  4  (   0.0,   0.0)   1   1  lifted   translate3d(32px, 12px, 0px)     ← 跨格前：正确
  5  (  -0.2,   0.0)   2   1  lifted   translate3d(-31px, 15px, 0px)    ← 跨格那一帧：补偿正确
  6  (  70.8,   0.0)   2   1  lifted   translate3d(48px, 18px, 0px)     ← **下一帧：少补一整格**
 ...                                                                     （一直错到下次跨格）
 14  (  -0.3,   0.0)   3   1  lifted   translate3d(-30px, 42px, 0px)    ← 又对了
 15  ( 141.7,   0.0)   3   1  lifted   translate3d(120px, 45px, 0px)    ← 又错
```

误差在 `0` 与 `±一格`（70.8 / 141.7 / 212.5）之间来回跳 = **一帧对一帧错** = 用户看到的"闪"。

## 二、原因①：`cellDelta` 的"当前格位"取错了来源

跟手算式是 `视觉位移 = 指针位移 − 格子位移`。第一版里"格子位移"是这样取的：

```ts
let next = d.base                       // d.base = **手势开始那一刻**的布局快照
if (live.x !== tx || live.y !== ty) {   // 跨格了才重算布局
  next = moveCard(d.base, d.id, tx, ty)
  applyLayout(next)
}
const cur = next.find(c => c.id === d.id)   // ← 没跨格时，next 还是 d.base
```

`d.base` 里这张卡还在**起点那一格**。于是"没跨格"的那些帧算出 `cellDelta = 0`，
补偿凭空少一整格 —— 而卡片此刻明明渲染在**新格**里，于是它比手指多走一格。
跨格那一帧用的是新布局（对），下一帧又回到 `d.base`（错）⇒ 来回闪。

**修法**：当前格位只有两个合法来源 ——
**这一帧改过布局 ⇒ 用新布局**；**没改 ⇒ 用正在渲染的那一版**（`cardsRef.current`）：

```ts
const cur = changed ? (next.find(c => c.id === d.id) ?? d.origin) : live
```

## 三、原因②：长按拾起会把整块画布推下去 28px

修完①之后误差变成**恒定 28px（纵向）**—— 不是"跳"，是"整体偏了"。28 = 提示行高 16 + gap 12：
编辑态会多出一行操作提示（「拖动卡片可换位置…」），而它原来在**画布上方**；
长按拾起会顺手进编辑态 ⇒ 拾起那一瞬间网格被推下去 28px，卡片与所有邻居一起跳。

**修法**：提示移到**画布下方**（`board-grid` 之后）⇒ 进编辑态不再改变网格上方任何东西的尺寸。

## 四、两条断言（把这次的教训钉住）

| 断言 | 判据 | 为什么这么写 |
|---|---|---|
| **连续小步跟手** | 12 步 × (8,3)px，**每一步**误差 ≤2px | 抽两点采样是**假绿**的温床：第一版那两点恰好一个不跨格（用 `d.base` 也对）、一个跨格（用新布局也对）⇒ 全绿，而真实输入每一步都在错 |
| **进编辑态不推动画布** | 长按拾起前后画布上缘位移 ≤1px | 这类"整块画布被推动"的位移，单看卡片几何是发现不了的 |

顺带修掉诊断脚本自己的一个假信号：`orderChanged` 原来比的是**数组引用**（永远为真），
改成比内容。

## 六、留给下一批的经验

1. **手感类断言必须按真实输入节奏连续采样**，并且把误差写成**数字**（这次是 212.5 vs 0.3）；
   两点采样看起来省事，实际是把"每一步都错"漏成"全绿"。
2. **任何"进编辑态/切视图"引起的画布位移都要量**：提示行、按钮行、状态条都可能是"整块跳"的来源。
3. `--motion-trace` 保留成常驻诊断工具（它只打印数字、不做断言），下次再有人说"手感不对"，
   先跑它，别先猜。
