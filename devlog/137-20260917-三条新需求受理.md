## 二、核实结论（决定方案成本的关键三件事）

### R35：后端**已经识别置顶，但只用于"别把新帖漏掉"**

- `app/services/fetcher.py`：B 站按 `modules.module_tag.text == "置顶"` 产出 `pinned_ids`
  （连"置顶帖时间顺序被打乱"这个坑都写在注释里）；微博走 `isTop` ✓
- `app/services/scheduler.py` L1600–1620 / L1837–1848：增量停止**已豁免置顶** ✓
- **缺口三处**（都不是"没做"，而是"做了前半截"）：
  1. **没落库** —— `posts` 表没有置顶列 ⇒ 周表按它的 `published_at`（比如 8 月）**沉到 8 月去了**；
  2. **已入库的置顶帖不刷新** —— 增量路径对"已入库"直接 `skipped++ / continue`
     ⇒ 置顶被换成新周表时**内容不会更新**（正是用户那句"保证修改及时被捕捉到"）；
  3. **前端没有置顶位** —— `vtuber_repo.list_posts` 是 `ORDER BY published_at DESC`（L815/863），
     `PostCard` 只有删除徽章与药丸行，没有置顶徽章。
- ⇒ 成本集中在**迁移 `f005`（加 `posts.is_pinned`）+ 刷新/撤销两条路径 + 排序与徽章**，不算大。

### R36：缺的正是这个项目一贯反对的那种"加载中…"

- `frontend/src/components/live/LiveSessionDialog.tsx`（`.lc-dlg`）：左列 `.lc-dlg-cover` 是封面 + 状态徽章，
  右列 `.lc-dlg-sec` 是「直播信息」；上游（danmakus 的词云 / 场次指标 / 直播动态）没回来时，
  区块里是 `.lc-dlg-ph` 的**「加载中…」「暂无动态数据」文案**，而**左列封面下方是空的**（截图红圈处）；
  数据一到 DOM 长高 ⇒ **弹窗高度跳变**。
- ⇒ 与项目"**全程没有『正在加载』闪帧**"的既有口径（`useSceneTransition` 那套）是同一条线，
  属于这条线上最后一个明显缺口。

### R37：数据素材其实**都现成**，缺的是"画布 + 卡片注册表"

| 卡片 | 数据在哪 | 状态 |
|---|---|---|
| 纪念日 | `vtubers.birthday` / `debut_date` | ✅ 已有 |
| 优质投稿 | `posts` 的播放/点赞/转发/评论（`postStats` 已有排序） | ✅ 已有 |
| 大事记 | **`vtuber_events` 表**（P7 就建了，一直没被用） | ✅ 表在，没界面 |
| 时间线 | `posts` 按天聚合 + `account_stat_snapshots` | ✅ 已有 |
| 自定义 | 标题 / 正文 / 外链 | ❌ 要新表或 JSON |

- 命名落点：`PostsPage.tsx` 的光条 title 与视图枚举注释、`UI-MAP.md` / `GLOSSARY.md` / README 功能表
  （探针按**索引**点视图按钮，对文案免疫 ✓ 但注释与文档要同步）。

## 三、方案要点（已写进 `docs/TODO.md` §0 的对应块）

三条的"现状 → 缺口 → 改法 → 护栏 → 待拍板"都落在 TODO 里，这里只记**为什么建议这么排**：

- **R35 先做**：成本最小（一个迁移 + 两条路径 + 排序/徽章），而收益是"周表/舰礼"这种**用户天天要看**的东西。
- **R36 次之**：纯前端、与既有设计口径同源，护栏也好写（连采两格比高度）。
- **R37 分三批**：命名 + 网格骨架 + 2 种卡片（只读）→ 拖拽缩放 + 落库 → 扩展点 + 自定义卡片。
  理由：它是**本仓最大的一次前端结构改动**（新视图 + 网格引擎 + 持久化 + 扩展点），
  一次做完护栏会写不细；而且它还要**给视图枚举加第五个视图**，主探针的视图列表与部分基线要跟着扩。

**R37 有四个必须先拍板的点**（写进 TODO §1.2 了）：
① 网格引擎自研 vs `react-grid-layout`（我倾向自研：几何完全可控、探针可断言，而"用户排布"本来就有一堆布局不变量要守）；
② 存储用新表 `profile_cards`（我倾向）还是挂在 `vtubers` 上的布局 JSON；
③ 扩展点形态（照 `registerIdleProvider` 的先例）；
④ 交互细节：碰撞"推开"还是"拒绝"、编辑态与阅读态是否分离、窄窗降级。
