## 一、根因（`devlog/378` 当初只记了现象，这版把它钉死）

`drawnGroups` 要把**四拨人**拼起来重排：活着的（`live`）、排队中、滑出中、已让位的（后三拨都在
`exiting`）。写法是 `[...live, ...mine].sort(compareInGroup)`，而 **`Array.prototype.sort` 是稳定的** ——
于是两条排序键**打平**时（同 tier 且 `createdAt` 相同或缺失），后拼进来的**退场那条排到活着的后面**
⇒ 屏幕上**两行交换位置**，还都走 FLIP 缓动，看得清清楚楚。

**为什么长期没被发现**：生产里 `createdAt` 各不相同 ⇒ 主键几乎从不打平；能撞出来的是
**fixtures 与老后端**。更早还被另一件事挡住：老口径下退场那条"当拍就浮起来"、跳过 FLIP，
所以那个换位**看不见**（`StatusIsland.test.tsx` 里那条老用例的注释记着这个坑，
它一直靠"把两条的 `createdAt` 错开"绕过去 —— 现在不必绕了）。

## 二、修法：打平时拿**上一拍的布局位置**当第二排序键

```ts
function orderedInGroup(rows, prev) {          // 组内排序的**唯一**实现
  return rows.slice().sort((a, b) => compareInGroup(a, b) || tieByPrevTop(a, b, prev))
}
```

- `tieByPrevTop` 读 `geomRef`（**上一拍提交结束时**的布局快照，FLIP 一直在维护它）里的 `relTop`：
  打平的两条就按"它们在屏幕上的先后"排 —— 位置一个都不动。
- 量不到（首帧 / 面板没开过）⇒ 返回 0（保持原序）：**宁可不排，也不凭空造一个顺序**。
- ⚠️ 同时把 `queueOrder`（退场队列的放行顺序）也换成 `orderedInGroup`：它的注释早就写着
  "必须与 `drawnGroups` 同一把尺子"，否则"第二条滑出去的"可能是屏幕上第三条。现在**只有一处**
  组内排序实现，改一处即两处。
