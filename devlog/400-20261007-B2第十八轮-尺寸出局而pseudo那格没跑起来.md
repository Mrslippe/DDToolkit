# 400-20261007-B2第十八轮 尺寸出局；而 pseudo 那一格根本没跑起来

用户把两格各跑了一遍（① `size` → 卡，② `pseudo` → 流畅）。日志读下来：

## ① `size`：**显示尺寸出局**

```
02:11:43  [video] 全屏诊断模式=size（真全屏，只把画面钉回 678x381 ⇒ 只动"显示尺寸"）
02:11:44  [video] 全屏表面=不透明
02:11:48  转折 →坏 位置=3.9s 缓冲=21.1s 全屏=是 元素=4/停/播 窗=start第5秒 丢=4/s
02:12:13  start 全屏=29/30秒 **尺寸=1920x1080→678x381** 丢帧=67/872(**7.7%**)
```

**真全屏、画面只有 `678x381`（跟窗口态一模一样大）——照样翻坏。**
⇒ 变量 ②（"画面铺到 1:1"）**出局**。

## ② `pseudo`：⚠️ **这一格没跑起来，不作数**

```
02:13:08  [video] 全屏诊断模式=pseudo（不走全屏 API；…）
02:13:10  [video] 全屏表面=不透明
02:13:38  start 全屏=0/30秒 **尺寸=1920x1080→718x392** 丢帧=0/873(**0.0%**)
```

**`718x392`** —— 画面**从头到尾只有窗口那么大**，一次都没被放大过。它的 CSS 没生效
（`position: fixed` 被 `.vp` 祖先链里的 transform/contain 困住）。所以这一格量到的
**只是又一次窗口态播放**，而窗口态本来就是 0.0%（`devlog/398` 那个 30 秒对照就是它）。

⇒ **"`pseudo` 流畅"这句话是假的**：它流畅是因为它压根没进假全屏。
**这一格的教训比结果值钱**：跑完一格，**先看"那个变量到底改掉没有"（`尺寸=` 就是自检），再看卡不卡** ——
否则会把"变量没改"读成"这条不是病因"（同 `PROBE.md` §6.22 的可见性验证）。

## 所以这一轮真正推进的是：**② 出局，嫌疑收窄到 ① 与 ③**

| 变量 | 状态 |
|---|---|
| ② 显示尺寸 `678x381` ↔ `1920x1080` | **出局**（`size` 格：小画面全屏照样 7.7%） |
| ① 全屏 API / 全屏窗口 | 待判 |
| ③ WebView 底色 `transparent` ↔ `不透明` | 待判 |

## 补了一格：`surface`（真全屏 + 铺满，但**保留透明底色**）

只动 ③，**不需要任何 CSS**（就是在切表面的那个分支上加个短路）：
流畅 ⇒ 元凶是"窗口底色"（那就有一条极便宜的正式修法：全屏时不切不透明）；
照旧卡 ⇒ ③ 也出局，**只剩全屏 API / 全屏窗口**（那就得走"假全屏"那条路，也就必须先把
`pseudo` 的祖先链问题查清）。

判据：`VideoPlayer.keys.test.tsx` 加一条（`surface` 下**不许**调 `setSurfaceOpaque(true)`、
但布局照全屏做、并留痕 `全屏表面=保持透明`）；**反向验证过**（把那个分支短路 ⇒ 只这条红）。
诊断模式的口径也写进了那一行日志（`全屏诊断模式=…` 带一句"只动哪个变量"）。
