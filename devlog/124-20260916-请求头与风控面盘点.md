## 一、Q1：头信息硬编码的现状与真实风险

**是硬编码的**，逐处：`auth.py::BASE_HEADERS`（B 站：Edge 150 UA + Referer/Origin/Accept/
Accept-Language/Connection）· `platforms/weibo.py` 的 `_PC_UA`/`_MOBILE_UA`（各配各的 Referer）·
`bili_search.py`（搜索页专用 Referer，**不带就 `-1200 被降级过滤`**）·
`danmakus.py::BROWSER_HEADERS`（**缺 Origin/Referer 直接被 RST**）· `img_proxy._UA`（**按主机带
Referer**，不带微博图床全 403）· `runner.py`（自报家门的机器人 UA）。

**结论：共用同一个 UA 本身不是风控主因。** 平台按 Cookie（账号）+ IP + 设备号 + 行为速率归因；
同版本浏览器的 UA 本就一模一样。我们**已经为"头"踩过三次坑并都修对了**（搜索 / danmakus / 图床）。

真正的三处 tell（可被当作"工具签名"匹配）：

| # | 现状 | 为什么是 tell |
|---|---|---|
| 1 | **完全没有** `sec-ch-ua` / `Sec-Fetch-*`；还多发一个浏览器不会显式发的 `Connection: keep-alive`；未开 HTTP/2 | 真 Edge 会发 client hints 与 Sec-Fetch；这几条合起来是**跨用户完全一致**的脚本指纹 |
| 2 | **设备号 cookie 名写错** | `auth.py` 只发 `bvuid3=`（全仓仅此 2 处），而 B 站 web API 读 `buvid3`。匿名实测 `x/frontend/finger/spi` → `code=0, data={b_3: 46 字符, b_4: 116 字符}`，与本机 `.env` 里 `BILI_BUVID_3` 的值**同形（46）** ⇒ 值是对的、**名字发错了，疑似等于没带设备指纹** |
| 3 | UA 永久冻结在 Edge 150 | 真实浏览器会自动升级；"永远 Edge 150 + 24/7 调 API"时间越久越显眼 |

⚠️ **修第 2 条时的硬约束**：设备号**必须按安装生成并持久化**（照浏览器那样调一次 `spi` 取 `b_3`，
或本地生成同构随机串）。**把一份值写进代码 = 全网用户共享设备身份**，比现状更糟 —— 现状至少
没有跨用户设备关联。

## 二、Q2：托盘 ≠ 更多请求，主力也不是 60s 直播轮询

**托盘不改变请求节奏**：`ARCHITECTURE.md` §3.10 第 4 条写明"隐藏只影响前端渲染与前端轮询"，
R24b 的"隐藏后降频"被明确取消。所以风险不是"托盘导致"，而是"**24/7 常态节拍**"。

| 节拍 | 实测/配置 | 量级 |
|---|---|---|
| T0 直播 | `60±15s`，批量 ≤100 uid/请求 | **1 请求/分钟 ≈ 1440/天**（便宜） |
| **动态流（真主力）** | 预算 12 rpm/平台；实测一轮 8 请求 / 周期 60–70s | **≈ 1.1 万/天**（7 V/10 账号口径） |
| 账号流 | 24h/账号，间隔 3–5s 随机 | 轻 |
| 第三方 | 每日 3:00 / 每周一 3:30；词云按需 | 轻 |

**已经做得好的**：预算滑窗 · **抖动到处都是**（T0 ±15s / 轮间 ±15s / 名单内 2–5s / 手动 3–5s /
启动随机）· 名单内间隔写明了"再快就谈不上拟人" · 风控码 `{412,-412,-509,-799}` + 冷却 · 手动优先。

**四个真实缺口**（→ R27/R28/R29）：

1. **冷却不落库**：`scheduler._rate_limit_until` 是模块级变量 ⇒ **重启（含应用内更新后的自动重启）
   即遗忘、立刻恢复满速** —— 这是最该先修的一条；
2. 冷却**固定 10 分钟、不升级**（连续撞 412 也不拉开），解禁后也没有恢复期；
3. **动态流没有空闲退避**：预算允许多快就多快，库里几天没新帖也照跑满 —— 而它占约 90% 请求量；
   另 `_PlatformBudget._rpm_for()` 会把预算抬到"至少装得下一轮" ⇒ **稳态速率随账号数线性上抬**
   （30 个 B 站账号 ≈ 30 req/min ≈ 4.3 万/天）；
4. **托盘模式下风控不可见**：R12a 做进了顶栏状态岛，但收进托盘后没人看界面、也没有系统通知。

> ⚠️ 一条要写进设计约束的取舍：**开播检测走 T0（不受 R28 影响）**，所以"动态流空闲退避"
> **不损害 R25 的推送时效** —— 别用"推送要快"把 R28 整条否掉。
