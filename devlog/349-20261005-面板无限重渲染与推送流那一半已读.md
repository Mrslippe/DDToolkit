# 349-20261005 面板白屏（无限重渲染）+ 已读漏了「推送流」那一半

> 用户 2026-10-05（接着 348 那批的实机验收）：
> 「首先我打开的时候在调测窗口点击全部注入就出现了这个报错（附图 `Maximum update depth exceeded`），
> 然后点击已读功能并没有实现，鼠标 hover 的时候通知条目还会上下跳动，通知快速进入的时候条目一直重复堆叠，
> 出现大片空白」。

四条症状，实测是**两个**根因：一个自激的 effect 链（占三条：白屏 / 跳动 / 堆叠+空白），
一个"已读只盖了两份来源、漏了第三份"。两条都先复现、再修、再拿探针回证据。

## 一、白屏：`Maximum update depth exceeded`（348 那套"浮起来"的坐标）

348 让退场条目浮起来，坐标放在**共享 state**（`floatPos` + `lockH`），由一条**无依赖**的
`useLayoutEffect` 每拍重算并 `setState`。它会自激，链条是：

```
E332（依赖 [now]）每拍 `??=` 一次快照 ⇒ flipRef 非空
  ⇒ E211（无依赖）看到 .is-out 那行 ⇒ setFloatPos(**新对象**) ⇒ 重渲染
    ⇒ `now` 又变了（`Math.max(nowProp, Date.now())`）⇒ E332 再跑 ⇒ 回到第一步
```

React 数到 50 层嵌套更新就抛 `Maximum update depth exceeded`，整棵树被卸载 ⇒ **白屏**。

⚠️ **为什么单测 18 条全绿而实机必炸**：`vi.setSystemTime(NOW)` 把 `Date.now()` **钉死**了，
每拍算出来的 `now` 完全一样 ⇒ 那条依赖 `[now]` 的 effect 根本不会重复跑。
实机 `Date.now()` 每毫秒都在走。**这是"单测绿、实机白屏"的那道缝**，所以新用例
（`StatusIsland.test.tsx`）**故意让每次 `Date.now()` 往前跳 1 秒**去点火。
已验证它**真能抓住旧代码**：`git checkout HEAD -- StatusIsland.tsx` 后跑这条用例，
报的就是用户那句 `Maximum update depth exceeded`。

同一条链还解释了另外三条症状：`lockH` 把列表高度锁在一个**过期值**上（`overflow:hidden`）
⇒ 新来的条目被裁掉、看起来"重复堆叠"、"大片空白"；`floatPos` 记的是编排变化前的错位坐标
⇒ 鼠标 hover（触发重渲染）时条目上下跳。

**修法：几何跟着行走，链子从结构上不可能存在。**

- `Row` 多两个字段 `exitTop` / `exitH`：**判退场的那一拍量一次就冻住**（`freezeExit`）；
- 删掉 `floatPos` / `lockH` 两个 state 与那条"每拍重算"的 effect；
- FLIP 的快照改成**一份、transform-free**（`geomOf`：把上一拍自己挂上去的反向 `translateY`
  从 `getBoundingClientRect` 里减掉，位移量另存 `data-flip-y`）。不减就会把"上一步的位移"
  当成布局差再补一次 ⇒ 快速连续进入时**越补越偏**（"重复堆叠"的另一半）；
- FLIP 与退场坐标都改用**容器内坐标**（`.si-list` 内的 `relTop`）而不是视口坐标：
  面板自己也会动（`place()` 量到真实高度后翻到上方、窗口缩放），视口坐标会把整块内容
  也拖着"缓动"过去（hover 跳动的来源之一）；
- 退场那条的坐标只能从**上一次提交的布局快照**里取 —— TTL 到点与服务端撤条目这两条路径
  **当下都已经量不到它了**（`sectionNotices` 过滤的是 `isLive`，那一拍 DOM 里已经没有它）。
- 只剩退场条目的那一组：补成"**同一组、同一个 `<ul>`**"（`drawnGroups`），不再另挂
  `data-orphan-leaving` 兜底容器 —— 退场坐标是相对它原来那个 `<ul>` 量的，换容器就整体错位。

## 二、"点击已读没实现"：条目有**三个**来源，348 只盖了两个

`TopBar.ackIds` 清的是"本地那份 + 服务端那份"。但面板里的条目还有**第三份：推送流**
（`useNotices` 里的 `liveEdge` / `message`：`live-<account_id>` / `msg-<ms>`）——
那份没人清，于是"刚推来的开播告警点一下纹丝不动"。

⚠️ 探针 `--notice-lab` 此前**是绿的**，两处原因，都已修：

1. 探针从**已经卸载的**面板节点上读 `hasAckAll`（「清注入」会把面板连带收起，之后它一直是关的）
   ⇒ 读到的是旧快照，看着像在断言、其实什么都没看。现在一律读**活的** `.si-panel`，
   逐条验之前先把面板开回来（`perRow` 的条数因此从全 0 变成 6→11 递增，真的在看内容了）；
2. 探针只点「批量全部」发消息，**从不点已读**。现在补两条行为判据：
   ⑥ 点一条 ⇒ 它当拍进 `.is-out` 且"活着的"少一条；⑦ 「全部已读」按 **id 逐个**对
   （按条数会被 TTL 混淆），并要求「正在进行」**一条都不许动**。
   另外给这一页加了**页面报错捕获**（`pageErrors`）：`window.onerror` + `console.error`，
   致命项在脚本侧判 —— 第一节那个白屏，旧探针是"全绿"的，它只数 DOM，数不到"树已经炸了"。

修法（**两半都要**，只修一半的样子是"闪一下又回来"）：

- **本机**：`TopBar` 多一张 `ackedIds` 表，`notices` 是过滤后的那份。寿命由
  `noticeBoard.pruneAcked` 定：**该 id 在活着的列表里真的没了之后才忘** ——
  忘早了它又冒出来；忘晚了（或不忘）**稳定 id** 的同类事件会被历史已读一起吞掉
  （开播告警 `live-<account_id>` **按账号稳定**，用户点过一次之后那个账号下次开播就再也不显示了）；
- **服务端**：`notices.drop_ring()` —— 环里的两类（`msg-*` / `live-*`）走**真的删掉**
  而不是写进已读集合：① `live-<account>` 稳定，落库会吞掉下次开播；② 6 秒寿命的瞬时 id
  白占 `READ_LIMIT` 的格子，把真正要持久化的处置类挤出去。`ack` 两个口回给前端的
  `acked` 现在 = **落库的 + 从环里删掉的**（少算了"删掉的"那一半，前端就不跟手）。
