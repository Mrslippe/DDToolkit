# 183-20260924-R38 批 5d：小窗面板从来没显示出来过 + 三项增强

> **一句话**：小窗（200×40）里那个通知面板**用户从来没看见过** —— 它 `top = 46`，
> 而窗口只有 40px 高。这个 bug 活了整整一批没被发现，因为探针一直在**主窗口的大视口**里
> 量那套样式。本批修掉它（加 resize 通路 + 向上翻），并补上三项增强。

---

## 一、真 bug：面板落在窗口外

### 怎么发现的

做「两段式 hover」时，我先算了一遍几何，发现对不上：

```
窗口 200×40，面板宽 280
  面板 top = 胶囊底(40) + 6 = 46   ← 窗口只有 40px 高
  面板 left = 8，右缘 288          ← 窗口只有 200px 宽
```

**面板整个落在窗口外**。实测确认（`ui_probe --status-island --width 200 --height 90`）：

```
可命中=False 在视口内=False
  - 面板命中测试失败（点不着）
  - 面板里的条目不可命中
  - 面板越出视口（会被裁）
```

**规格 §3 早就写了**小窗展开是「**280 × 面板高**」，但 Rust 侧窗口尺寸
**写死 `W = 200.0` / `H = 40.0`，没有 resize 通路**（`TODO.md` §1.2 已记为缺口）。
规格与实现之间的这道缝，正好是一个"面板能不能用"的完整 bug。

### 为什么它活了这么久没被发现

**探针的坐标系错了。**

`--status-island` 一直在**主窗口的视口**（1100×800）里量状态岛那套样式 ——
在 1100 宽的视口里，280 宽的面板当然"在视口内、可命中"，于是**一路绿**。

它量的是「这套样式在一个大视口里对不对」，而**不是**「在小窗里能不能用」。
`--status-widget` 那一段虽然跑了 `widget.html`，但量的是"分流生效没 / 胶囊尺寸 / 窗口底透明"，
**没有一条判据碰过面板**。

> **可提炼的教训（已进 DEV-LOOP §6.5）**：
> **同一个组件被塞进不同尺寸的容器时，"在大容器里绿"完全不能推出"在小容器里能用"。**
> 判据必须**跑在实际会被使用的坐标系里** —— 或者至少显式声明它量的是哪个坐标系。

### 修法

1. **Rust 加 `resize_widget_window`**（`w/h/x/y` 一起下发）：光改尺寸会以**左上角**为锚
   向外长 ⇒ 胶囊横向跳一下。所以调用方把新位置也算好，**顶边中心不动**。
   顺序是**先 `set_size` 再 `set_position`**（反过来会有一帧"错位的、更大的窗口"）。
2. **`widgetExpandGeom` / `widgetCollapseGeom`**（纯函数，29 条单测）算那个矩形。
3. **面板 `max-height` 不能再用 `60vh`**：小窗高度**跟着面板长** ⇒ `vh` 与面板高度
   **互为因果**（40px 窗口 ⇒ `60vh = 24px` ⇒ 面板被压到 24px ⇒ 窗口只长到 70px ⇒ 仍然很小
   ⇒ **死锁在一块 24px 的板子上**）。改成 JS 按**屏幕高度**算好写进 `--widget-panel-max-h`。

## 二、单测逼出来的第二个问题：右下角根本放不下

写完"展开就把窗口长够"之后，单测**当场红了**：

```
× **右下角默认落点 ⇒ 必须向上翻**（否则夹取会把胶囊挪走）
  → expected 1756 to be 1796
```

`defaultWidgetPos` 把小窗放在**右下角**（1080p 上 `y = 968`），向下展开需要
`968 + 40 + 6 + 面板高` —— **任何面板高度都放不下**（≥1214 > 1080）。
硬要向下长就只能夹取，而**夹取会把胶囊从用户摆的位置挪走**（实测 968 → 710）。

**所以真机上只有一条路：贴着屏幕下沿时向上翻**（面板长在胶囊上方）。
这是所有浮层控件（菜单 / 下拉 / 气泡）的标准解法。

### 连带的两处必须同步改

- **胶囊在窗口里的位置**：向上翻之后窗口是"面板在上、胶囊在下"，
  所以 `.widget-shell[data-flip='up']` 要用 `flex-direction: column` + `justify-content: flex-end`
  把胶囊压到窗口**底边**。光改窗口坐标不管这个，会得到"面板在上面、胶囊也还在上面"的错位。
- **`place()` 也要会翻**：面板在窗口里的落点同样要按 `flipUp` 决定
  （下方 `r.bottom + 6` / 上方 `r.top − 6 − 面板高`）。两处必须一致。

## 三、第三个问题：反复展开会漂走

又一条单测红了：

```
× **展开再收起回到原处** → expected 710 to be 800
```

贴屏幕边的窗口展开时**必须被夹**（200→280 宽要收回来，否则面板出屏），
于是"展开矩形的中心"**已经不是原来那个中心了** —— 反推回去就少掉那几十像素。
一次展开/收起看不出来，但**每次悬停都漂一点**，久了小窗就爬走了。

**修法**：展开**之前**把胶囊矩形记下来，收起时**直接回到那个矩形**（不是反推）。
加了一条 10 轮循环的单测守它。

## 四、三项增强（本批的正题）

| 项 | 做法 | 关键取舍 |
|---|---|---|
| **鼠标穿透** | `set_widget_click_through`（Rust）→ `set_ignore_cursor_events` | 走**自定义命令**而不是前端 `setIgnoreCursorEvents()`：`core:window:allow-set-ignore-cursor-events` **不在 `core:window:default` 里**（已核 `tauri-2.11.5` 的 permission reference），而**自定义命令不走 ACL** ⇒ 少一个会漂的配置点 |
| **全屏时隐藏** | `SHQueryUserNotificationState`（shell32） | **不能用"我自己是不是全屏"** —— 小窗永远 200×40，`is_fullscreen()` 恒 false，问了等于没问。要躲的是**别人的**全屏。取不到状态时**默认不隐藏**（宁可偶尔多露，也不要因为探测失败让它永不出现） |
| **两段式 hover** | 面板放不下时向上翻 | 就是本批那个 bug 的产物 |

两项都进了「设置 → 外观」，都**只 `show`/`hide` 不销毁**（全屏结束要能立刻回来）。

### 反向验证（本仓纪律）

- **探针**：新判据要求先注入一条条目（探针里小窗收不到 Tauri 事件 ⇒ 永远空闲 ⇒

  那个死锁**只在真机 40px 窗口里存在**。所以它由单测+代码注释守，**真机确认是必需的**
  （已进 TODO §1.3）。

### ⚠️ 还有一处必须真机确认

**探针证明不了"真机上窗口会跟着长大"** —— 探针的视口是浏览器视口（1076×621），
不是 Tauri 那个 200×40。resize 通路（`resize_widget_window` + `set_size`/`set_position`）
**只能真机验**。

## 六、一个流程事故（记下来）

为了判断一个 tsc 报错是不是我引入的，我用了 `git stash push -u` —— 结果**stash 到了
另一个进程正在改的 6 个文件**（`DataDeck.tsx` / `PostsPage.tsx` / `posts.css` / `tokens.css` /
`FanTrendChart.tsx` / `LiveCalendar.tsx`）。两次 stash 都完整 pop 回来了（已核对
`git stash list` 为空、diff 规模未变），**没有丢东西**。

**教训**：`git stash -u` 是**全仓**操作，而本仓可能有并发编辑（另一个 agent / 另一个窗口）。
判断"某个报错是不是我引入的"应当用**只读**办法：
`git stash` 之前先 `git diff --stat` 记下范围，或者只对我自己的文件做检查
（本次最后用的就是后者：`npx tsc --noEmit | Select-String <我的文件名>`）。
**别用会动工作区的命令去回答一个只读问题。**
