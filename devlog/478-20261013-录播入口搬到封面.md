> 用户 3.1：「录播文字行可以不需要，尽量保证左右两栏高度一致，如果以后要加功能的话也不要
> 直接加进左边或者右边」；3.2：「把记录录播功能的前端按钮集成到场次详情页**左上方的封面上**，
> 做成鼠标 hover 显示、鼠标离开隐藏的悬浮图标……没有录播记录时显示为**添加（加号）**，

## 一、做了什么

- **删掉右列那条「录播」行**（连同它下面那一大块候补列表）：地址 / 未填写 / 找录播 / 手动填
  原本全挤在这一行里，既让右列高低不定，也让"给这一场补录播"散成三个入口。
- **新增「添加录播」小窗** `components/live/VodDialog.tsx`：录播的**唯一入口**收在封面上，
  三件事收在一个窗里（填地址 / 找录播 / 记住录播号）。写路径仍是 B2 那条 PATCH（只传 `vod_url`）。
- **封面左上角加悬浮钮** `.lc-dlg-vodbtn`：无录播 `＋`（开小窗）、有录播 `▶`（播放）。
  ⚠️ 静止 `opacity: 0`、`.lc-dlg-cover:hover` **或自身 `:focus-visible`** 才显形 ——
  只做 hover 等于把键盘用户关在门外（CSS 契约有用例钉住）。
- 小窗由 `LiveCalendar` 渲染（不是详情弹窗内部）：Radix 的 portal 按 DOM 顺序叠，
  后渲染的才在上面 —— 与 `ManualSessionDialog` 同一个做法。

## 三、⚠️ `▶` 这一批**还没有**应用内播放器

老老实实记一笔：`▶` 目前交给系统浏览器（`openExternal`）—— 那正是**被删掉的那条链接原本
的行为**，所以这一步没有回退，但**不等于**用户要的"打开播放器"。

差的是一条"按 BV 取流"的路：现有 `/bili/play/{post_id}` 是**按帖子 id** 的，而录播不是帖子
（侦察结论：`bili_play.play_info()` 本来就吃 bvid，端点那一层只是查库把 post_id 翻成 bvid）。
下一批要动的四处（`devlog/479` 接手）：

1. 后端 `GET /bili/play-by-bvid?bvid=&qn=&fallback=&cid=`（纯加法：`bvid_of()` 抠号 → `play_info`），
   同步 `docs/backend/HTTP-CONTRACT.md`（**注意那里有一处端点计数**）；
2. 前端 `api.biliPlayByBvid` + `BiliVideo` 加"流来源"二选一（`postId` / `bvid`）—— 其余 190 行
   播放逻辑（清晰度菜单 / durl 回落 / 分 P / 镜像链 / MSE）全是现成的；
3. 播放面：先做主窗内的浮层；**无边框独立窗**（+ 设置里那个"默认应用内播放"开关）是再下一批，
   它要动 Rust（`async` 建窗 + `COMMAND_ACL`/`CALLER_LABELS_ALLOWED` + `CloseRequested` 按 label 分流
   + `player.html` 独立入口），并且会碰 `lib.rs:2610` 那条 `assert_eq!`；
4. 设置项本身是纯加法（prefs 家族，`group: 外观` 的「视频播放」小节；**不要新开分组** ——
   探针逐字断言导航 5 项）。
