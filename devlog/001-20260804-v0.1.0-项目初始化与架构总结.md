# 001-20260804-v0.1.0-项目初始化与架构总结

## 项目概述

**Better DD Toolkit** — VTuber 数据监控与管理平台，支持从 Bilibili API 自动抓取主播信息（昵称、粉丝数、直播状态等），并提供 REST API 和桌面前端界面。

## 技术栈

| 层级 | 技术 |
|------|------|
| Web 框架 | FastAPI (Python) |
| ORM | SQLAlchemy |
| 数据库 | SQLite (vtuber.db) |
| 数据库迁移 | Alembic |
| 定时任务 | APScheduler (BackgroundScheduler) |
| HTTP 客户端 | httpx (异步) + tenacity (重试) |
| 桌面前端 | Flet |
| 环境变量管理 | python-dotenv |
| B站 API 认证 | WBI 签名算法 (自实现) |

## 核心功能

### 1. REST API（FastAPI）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/vtuber/list` | 获取全部主播列表 |
| GET | `/vtuber/{id}` | 按 ID 获取单个主播 |
| POST | `/vtuber` | 新增主播 |
| PUT | `/vtuber/{id}` | 更新主播信息 |
| DELETE | `/vtuber/{id}` | 删除主播 |

### 2. 定时数据抓取（APScheduler）

- **频率**：每 5 ± 0.5 分钟执行一次
- **抓取内容**：
  - `fetch_bilibili_user_info(mid)` → 用户昵称、签名、性别、头像
  - `fetch_bilibili_user_stat(mid)` → 粉丝数、关注数、获赞数
- **容错机制**：tenacity 自动重试（最多 3 次，指数退避），单个主播失败不影响其他
- **反爬策略**：请求间随机间隔 1~3 秒

### 3. B站 WBI 签名（wbi.py）

- 从 B站导航接口获取 `img_key` 和 `sub_key`（带缓存）
- 根据固定置换表生成 32 位混合密钥
- 对请求参数排序拼接后计算 MD5 签名（w_rid + wts）
- 使用 `.env` 中的 Cookie 凭证发起请求

### 4. Flet 桌面前端（app_frontend.py）

- 深色主题，卡片式布局展示主播列表
- 显示主播名称、粉丝数、直播状态（🔴 直播中 / ⚫ 离线）
- 刷新按钮手动重新拉取数据
- 连接错误、HTTP 错误等异常状态提示

## 数据库模型

```
vtubers 表
├── id           INTEGER  PK
├── bilibili_uid TEXT     UNIQUE   (B站 UID)
├── name         TEXT              (主播名称)
├── platform     TEXT              (平台，默认 "Bilibili")
├── fans_count   INTEGER           (粉丝数)
├── is_live      BOOLEAN           (是否直播中)
└── birthday     TEXT              (生日，格式 MM-DD)
```
