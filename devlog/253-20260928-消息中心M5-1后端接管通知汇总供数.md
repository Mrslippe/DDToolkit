# 253-20260928-消息中心 M5-1：后端接管通知汇总（供数半边）

M5 是方案里**最后也最重**的一批（目标架构 S2：后端接管供数 + 已读持久化 + 退役广播 + 删 `kickPoll`）。
本批**只做它的后半边**，理由写在最前面：M5 的完整形态会**改用户可见的通知行为**
（报告何时弹、进度由谁供、广播退役）——那需要重做探针（`--status-island` / `--messages` 现在
断言的是"推来的消息 200ms 内进岛"，换成 3–10s 轮询取回后这些等待全不对）、
真机验收与 `kickPoll` 的前置两件事（devlog/245）。把"供数"与"切换"混在一批，
出问题时分不清是哪边 —— 所以切成 **M5-1（本批，供数）→ M5-2（切换）**。

## 一、本批交付什么

| 项 | 内容 |
|---|---|
| `app/services/notices.py`（新） | 事实 → `Notice[]`：五类来源的文案模板 / 优先级 / ttl；**已读**落 `app_meta` |
| `GET /vtuber/notices` | `{now, notices[]}`，**已按优先级排序**（目标架构 §2.1 的契约） |
| `POST /vtuber/notices/ack` | 记 `{id}` 已读，**幂等**，落 `app_meta` 的 `notices.acked`（上限 50） |
| 契约对齐 | `Notice` 新增 `value`（活数据槽：倒计时/进度自己刷新而不重排文案）；前端类型同步 |
| 接线 | `_set_post_last_result` / `_set_account_last_result` 记"有没有人在看"；`_note_manual_done` 记瞬时消息 |

⚠️ **这个端点目前没有消费者**（前端仍用自己那份 `useMemo` + 推送通道）。这是**有意**的：
先让"契约 + 判据"落地，M5-2 再切换。方案 §3 的分工也支持这一点 ——
`services/notices.py` 只做事实→文案/优先级/ttl，路由只做暴露。

## 二、「目睹才报」怎么落地的（§8.5 拍板 C：保留，用订阅者注册表）

旧口径住在主窗口四个 `useRef` 里：**轮询看见过这次运行**且它已结束，才弹完成报告
（"用户没看见过程就别打扰"）。后端版本把"谁在看"表达成**推送通道有没有订阅者**
（`HUB.subscriber_count > 0`），在**任务收尾那一刻**采样，随 `(kind, seq)` 记在进程内。

三处差异都写进代码注释了，最要紧的一条：**主窗口收进托盘时行为会变**
（旧：轮询停了 ⇒ 不报；新：SSE 还连着 ⇒ 报，且报告**已读持久化**）。这正是 M1 立的规矩
（"收进托盘后该知道的仍要知道"），但要**在 M5-2 的真机验收里专门看一眼**。

## 三、两个把判据自己坑了的地方（本批最值钱的记录）

### ① 路径注册顺序：`/vtuber/notices` 被 `/vtuber/{vtuber_id}` 吃掉

第一版把两个端点放在文件下面（挨着别的 vtuber 子路径），`GET /vtuber/notices` 恒定 **422** ——
FastAPI 按**注册顺序**匹配，`{vtuber_id}: int` 解析 "notices" 失败 ⇒ 422。
`/vtuber/fetch-status` 那边早有一条同样的注释（"必须注册在 `/vtuber/{vtuber_id}` 之前"），
我照着新加路径却没照做 ⇒ 判据（`test_route_serves_notices`）当场抓住。
**已写进 `docs/backend-repositories-and-routers.md` §3 的口径说明**。

### ② 替身的**形状**必须与真身一致（否则真 bug 在替身那边全绿）

`MessageHub.subscriber_count` 是 **property**。我在 scheduler 里写成了 `subscriber_count()`，
而 `tests/test_notices.py` 的**替身写成了方法** ⇒ 替身那边 13 条全绿，而全套
`test_services`（15 条）一起 `TypeError: 'int' object is not callable`。
修法两条：生产代码改成 property 调用；**替身也改成 property** ——
并补了一条反向验证（把生产代码改回 `subscriber_count()` ⇒ `test_notices.py` 必须红），
证明这条判据现在真的盯着形状。

## 四、判据与反向验证

| 层 | 判据 |
|---|---|
| 契约 | `tests/test_notices.py` 13 条：**键集合**（少一个键前端就画不出）· 顶层 `{now, notices}` · 报告带 `action`/`sticky` |
| 语义 | 优先级排序 · `now` = 服务端毫秒且 `expiresAt` 以它为基准（风控倒计时进 `value` 槽）· **自动节拍不产生条目** · **目睹才报**（没人看 ⇒ 不报）· 已读 ⇒ 不再出 · **ack 幂等** · 空 id 422 |
| 时间 | 瞬时消息 TTL 从**记录时刻**起算（拉多少次都不后漂 —— 否则永不过期）· 开播边沿 → alert + 2 分钟 TTL |
| 接线 | `_set_*_last_result` 用**当时的订阅者数**记"谁在看"（替身形状照抄真身） |

**反向验证 7/7 全红**：① 报告去掉 `action`；② 不看目睹标记；③ ack 不落库；④ 自动节拍也产生条目；
⑤ TTL 从渲染时刻起算；⑥ 排序不生效；⑦（形状）生产代码改回 `subscriber_count()`。
