# 181-20260924-R38 批 5c：小窗拆独立入口（124MB → 85MB）

> **一句话**：小窗原来把**整站**的 JS/CSS 都加载了一遍，只为画一个 200×40 的胶囊。
> 拆成独立入口后，它加载的 JS 从 **1214KB → 188KB**、CSS 从 **153KB → 6KB**，
> 渲染进程内存从 **124MB → 85MB**。

---

## 一、为什么这不是"优化"，是路线问题

R38 批 5b 让小窗跑起来了（devlog/180），但它走的是 `index.html?widget=1` ——
靠 `main.tsx` 里的**运行时**判断分流。也就是说：**小窗和主窗口加载同一份 bundle**。

写的时候没觉得有问题（"反正能跑"），真机上量了一下才发现代价：

| 指标 | 拆之前 | 拆之后 |
|---|---|---|
| 小窗渲染进程内存 | 124 MB | **85 MB** |
| 小窗加载的 JS | 1214 KB | **188 KB** |
| 小窗加载的 CSS | 153 KB | **6 KB** |

**判据不在"省了多少"，在"这钱怎么算"**：小窗是**常驻**的（用户就把它摆在桌面上），
它的成本要按"一整天挂着"算，而不是按"点开看一眼"。主窗口可以偶尔重一点，
小窗不行 —— 这是两种不同的东西，不该共用一份 bundle。

> 顺带印证了本项目的一条老经验：**"能跑"与"该这么做"是两个判据**。
> 运行时分流在功能上完全正确，五轮真机反馈里没有一轮提到性能 ——
> 它不制造 bug，只制造**每天都在付的成本**，而这类成本没有任何测试会红。

## 二、做了什么

- **独立 HTML 入口**：`widget.html` → `src/widgetMain.tsx`，走 Vite 多入口
  （`build.rollupOptions.input`）。
  小窗**不再 import `index.css`**（Tailwind 全量 153KB），只 import 它真正要的
  `tokens.css` + `status-island.css`。
- **状态岛样式抽成共用文件**：`layout.css` 1494 → 1166 行，状态岛那 341 行搬到
  `src/styles/status-island.css`。两个入口共用一份（主窗口由 `App.tsx` import）——
  **不是复制两份**，否则下次改胶囊就得改两处，一定会漂。
- **`main.tsx` 瘦身** 360 → 251 行：删掉 `isWidgetWindow` 运行时分流与
  `WidgetErrorBoundary`，它只渲染 `<Root />` 了。
- **自检仪器跟着走**：devlog/178 那套仪表（`window.onerror` / `unhandledrejection` /
  React 错误边界 / `invoke('widget_diag')`）**必须在新入口里重新挂一遍** ——
  独立入口不会继承 `main.tsx` 的任何东西。探针同理（`import.meta.env.DEV && has('probe')`）。

## 三、踩到的两个坑

### 坑 1：独立入口丢了 Tailwind preflight 的 `box-sizing`

拆完之后探针量到胶囊宽 **224px**，而不是规格里的 **200px**。

**根因**：`box-sizing: border-box` 在本项目里**不是自己写的**，是 Tailwind preflight
（`index.css`）全局设的。小窗作为独立入口不再加载 `index.css` ⇒ 退回浏览器默认的
`content-box` ⇒ 宽高各多出 padding + border。

**修法**：在 `status-island.css` 顶部补**显式** reset（`.si-island` / `.si-panel` /
`.widget-shell` 及其后代），并加注释说明**为什么这两个入口不能只靠 Tailwind**。

> **可提炼的教训（已进 DEV-LOOP）**：拆入口时**"顺带生效的全局样式"是最容易漏的一类依赖** ——
> 它不在 import 图里，靠 preflight/base 层兜着。拆完要专门核一遍"哪些样式是**别人**给的"。

### 坑 2：抽文件时"两个入口都要的那几行"只留了一份

抽 `status-island.css` 时开头那几行 reset 是**两个入口都需要**的，
一度只留在主入口那份里 —— 表现出来就是"主窗口正常、小窗错位"。
判据：**共用文件必须自包含**，不能假设调用方已经设好了什么。

## 四、顺带修掉的探针假失败（真机环境前提）

`--status-island` 的"空闲语义"断言在真机上**必然误报**（这次实测 5 条红）。

**根因**：探针自己起的后端会跑 `app/main.py` 的启动外部补抓
（`start_external_catchup`：`STARTUP_CHAIN_DELAY=4.0` 秒后同步 N 个主账号的第三方数据）。
于是探针跑到"空闲态"那一段时：
- 胶囊**亮着**（有真任务）⇒ `data-idle-pool` / `data-idle-size` **根本不挂**
  （`StatusIsland.tsx` 的 `lit ? undefined : …`）；
- 屏幕文案是同步进度 ⇒ 每条"空闲文案应为「数据服务运行中」"全红。

看起来像产品崩了，其实是**探针的环境假设塌了**。

### ⚠️ 修的时候刻意避开的陷阱：别用症状当自己的前提

第一版我写成"**胶囊亮着** ⇒ 判定为环境问题 ⇒ 跳过"。这是**循环论证**：
"因为亮着所以有任务"会把**"空闲却常亮"这个真 bug** 一起当环境问题放过 ——
而"空闲不占顶栏"正是这段断言要守的东西（用户 2026-09-10 口径）。**跳过等于把断言删了。**

**改成取后端凭据**：页面侧读 `/vtuber/fetch-status` 的 `external.running`
（`idleBackend` 带回），脚本按三种情况分支：

| 情况 | 处理 |
|---|---|
| 真·空闲（胶囊不亮） | 照常跑全部空闲语义断言 |
| 亮着 + 后端**确认有任务** | 跳过（前提不成立，**打印**真实 label 说明原因） |
| 亮着 + 后端**确认没任务** | **报红** —— 这正是要抓的回归 |
| 亮着 + 凭据取不到 | 跳过（环境判不了，但绝不伪造成"失败"） |

这条纪律在 `_assert_topbar_quiet`（devlog/083）里已经有先例，这次是把同一套办法
用到状态岛段。

### 反向验证（本仓纪律：新断言必须能红）

光看到绿色**不能**证明断言有效 —— 它可能被跳过了。所以伪造"后端说没任务"
（`_backend_ok = True; _busy = []`）再跑一次：

```
 - @1100 status-island: 空闲态就亮着容器（文案='正在同步8 个主账号的第三方数据'）
   而**后端说没有任何任务在跑**（external/account/post 全 false）—— 频繁轮询不占顶栏，空闲只有绿点
退出码: 1
```

**确实红了** ⇒ 断言有牙齿，恢复代码后绿。这一步不能省。

## 七、附：一个 git 提交的坑

用 `$msg | Out-File -Encoding utf8` 写 commit message 会**带 BOM**（`\xef\xbb\xbf`），
于是 `git log --oneline` 的标题前面多一个不可见字符。改用 `$msg | git commit -F -`
（stdin）即可。**判据**：`git log -1 --format=%s` 的首字节是不是 `\xef`。
