# 455-20261010-B站登录为什么失效 + 登录浮窗文字顶出窗口

用户 2026-10-08 两件事：「登录详情页面文字宽度超出了窗口」+「我的 B 站登录失效了」。

## 一、B 站登录失效：不是应用弄丢的，是**续期从来没武装上**

先摆证据（`DATA_DIR/logs/app.log`，真机）：

| 时刻 | 日志 | 含义 |
|---|---|---|
| 10-06 16:24 | `.env` 最后写入 | 用户最后一次粘/扫码；此后**没被重写过**（凭据没丢、也没被清） |
| 10-08 21:53:38 | `Session 有效 (mid=1062902765)` + `cookie/info 返回中无 refresh_token (code=0)` | 那时还能用；但平台**拒绝下发续期令牌** |
| 10-08 22:34:47 | `Session 已过期: code=-101` → `refresh_token 续期失败: code=-101` | 会话被平台判死，唯一的自愈手段也被同样的 -101 挡回 |
| 同分钟 | 14 × `❌ B站错误码 -352 风控校验失败` | **失效之后**匿名抓取撞上的风控（不是失效的原因） |
| 同分钟 | 小红书 `cookie 已失效：活了 2.3 天` | 两条 cookie 都是 10-06 16:24 配的 ⇒ 两个平台同批到期/被吊销 |

**根因（可修的那一半）**：B 站 web 端的 cookie 鉴权是**四件套** ——
`SESSDATA` + `bili_jct` + `DedeUserID` + **`DedeUserID__ckMd5`**
（[bilibili-API-collect · API 认证与鉴权](https://lxb007981.github.io/bilibili-API-collect/other/API_auth.html#cookie%E6%96%B9%E5%BC%8F-web%E7%AB%AF)），
而本仓库的 `_ATTR_MAP` **没有第四件** ⇒ 用户粘整条 cookie 时它被**静默丢掉**，
缺它的后果正是上面那条 `cookie/info 无 refresh_token` ⇒ `refresh_token` 永远拿不到 ⇒
SESSDATA 一到期就只能重新登录。这一条从项目第一天就在，只是从没人问过"为什么续期没生效"。

**修法**（用户拍板"补全套"）：① 认下第四件（`_ATTR_MAP` + `cookie_str()` + `.env` 键
`BILI_DEDE_USER_ID_CKMD5`）；② 记「这套登录从什么时候开始用」（`BILI_COOKIE_SET_AT`，
**只在扫码成功/导入验过时盖章，内部续期不盖**）；③ 状态接口与日志失效时说「（这条活了 N 天）」；
④ `notices` 在 ≥25/30 天时给一条可 ack 的 warn「可能随时过期」，**已失效时只出 alert**。
⚠️ **不拒收**缺第四件的 cookie：它照样能抓（`nav` 通过），只是到期续不上 ——
拒收等于把可用凭据挡在门外，而"什么都不说"才是那次失效没人反应过来的原因（回执里如实写一句）。

## 二、登录浮窗文字顶出窗口：缺 `overflow-wrap`

`probe.ts::measureDialogs` 量「面板 `scrollWidth` + 最深一层肇事元素」两件事。
在探针里**量不到溢出** —— ⚠️ 更正（2026-10-08 当天自查）：探针的 `--capabilities` 档按设计
**删掉了 `.env`**（它要的就是"有数据但未登录"那个现场），所以那次量的是**未配置态**的四个 Tab，
已登录/已失效那几屏的文案没被覆盖到（用户随后给的截图正是那一屏）。
**注入法仍然成立**：`overflow-wrap` 是**根上继承的 CSS 性质**，与具体文案、登录态无关；
用户那一屏的具体文案我复现不出来，所以改用注入把这条性质钉死：

- 注入一条 300 字**不可断**串 ⇒ 改前：512px 的面板被撑到 **2512px**，连标题「账号登录」
  都顶出 **1999px**、四个平台 Tab 顶出 129px（与"文字宽度超出窗口"逐字同型）；
- 修法：`DialogContent` 加 `[overflow-wrap:anywhere]`（**不是 `break-word`**：只有 `anywhere`
  会同时压缩 min-content 宽度，让 auto 宽度的容器真的缩得下来）⇒ 注入后仍是 512px、**0 溢出**。
- 判据进了**门禁**：`--first-run`（A 档）与 `--capabilities` 都先量真实几何、再注入长串量第二遍。

顺带记两条探针经验（都不止这一次有用）：
① **故意的裁切要排除**才能定阈值 —— `.sr-only`（1×1 + hidden）与 `float-pill` 里中文的
2–3px 亚像素削边，不排除的话判据一出生就红、然后没人看它；阈值 4px 与"真正的超窗"
（几十上百 px）差一个数量级，且做过注入验证；
② **量命中前先 `scrollIntoView`** —— `--app-settings` 的主题卡片判据此前一直假红（切页不重置
`.aps-pane-scroll`，卡片被裁在视口外，`getBoundingClientRect` 照样给坐标而 `elementFromPoint`
命中不到），修法与同文件 ③d 步进条那条相同。
