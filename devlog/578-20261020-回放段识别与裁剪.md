## 三、实现

新增 `app/services/fan/quality.py`：

- `find_replay_from(raw)`：按小时比对 `(uid, mh)` 多重集合，某小时 ≥80% 内容此前出现过且 ≥50 条
  ⇒ 判为回放；
- `apply_replay_cut(raw, stats)`：从该小时起丢弃**弹幕**，重算 `m` / `uniq` / `maxrep` 与
  `records` / `type0` / `uniq_total` / `dup_rate`，结束时间取「裁后最后一条弹幕」与原结束的**较早**者。

接入两处：采集链路（aggregate 之后立即执行）、`scripts/cut_replay.py`（回填已有数据，留 `.bak-replay`）。

**只丢弹幕**：入场/付费没有逐条金额，无法按时间精确回退，尾部量也小。这一点写在 `duration_note` 里。

## 四、效果

- 数据侧：9 场、合计 **29,878 条**被裁；
- 最大一场 `d720e4f9` 从 **11.53h → 6.87h**（19:05 → 02:57），与用户肉眼判断一致；
- 其余 8 场平台结束时间本就早于回放起点，时长不变，但重复内容不再污染 `m` / `uniq`。
