# 290-20261003 B站视频播放批 2：内核换型（双元素 DASH）+ 清晰度菜单

> 计划原写的是 "`dash.js` + MSE"。**实测后改了选型**，理由在第一节 —— 这一段是本篇最该记的东西。

## 一、为什么不用 dash.js（实测推翻原计划）

扒了 B站 DASH 流的容器结构（取前 8KB 解析 box）：

```
视频流 id=80 1920x1080 codecs=avc1.640033  →  ftyp(32) moov(886) sidx(136) moof(1904) mdat(685704)
音频流 id=30280      codecs=mp4a.40.2      →  ftyp(32) moov(805) sidx(136) moof(1040) mdat(88903)
```

两条都是**顺序 fMP4**（moov 在前、带 sidx 索引）⇒ **浏览器能直接播**；而 dash.js 要的是 **MPD
manifest**，B站**根本不提供** —— 用它就得自己合成 MPD 或写 MSE 拼接。于是：

**选型改为「双元素」**：视频轨静音播 + 独立音轨播，两条都经 `/video-proxy`（CDN 不带 Referer 就 403）。
好处：**零新依赖**、原生 `buffered/seekable/currentTime` 全保住（自绘控件一行没改）、1080P 照样拿。

## 二、做了什么

| 处 | 内容 |
|---|---|
| `VideoPlayer` 新增 `dash` 模式 | `dash={{video, audio}}` ⇒ 视频元素 `muted` + 隐藏 `<audio>`；两条**只走代理**（不走直连，B站直连必 403）；`seek/play/pause` 同时驱动两条；**每 2s 纠偏**（`|音-视| > 0.3s` 就拉回）；音量/静音/倍速**作用在音轨**上（全局偏好那套照旧） |
| 清晰度菜单（新增 props） | `qualities/qualityId/onPickQuality`：默认显示**实际拿到**的档；`accept` 里的大会员档（112/116/120/125/126/127）**禁用并标注「需大会员」** |
| `components/BiliVideo.tsx`（新） | **点播放才取流**（`playurl` 地址短时效+绑 IP，不预取）：封面 + 大播放键 → `api.biliPlay(postId)` → 渲染 `VideoPlayer`；失败**原样显示后端分类的原因**（不存在/无权限/风控）；DASH 播不动 ⇒ `onFallback` 重新取 `durl`（单 mp4、720P） |
| `PostDetailDrawer` | B站视频帖从**官方 iframe** 换成 `BiliVideo`（控件才统一）；`api.biliPlay` + `BiliPlayInfo` 类型进 api/types |

## 三、判据

`VideoPlayer.dash.test.tsx` 3 条：视频轨 `muted` 为真 + 音轨存在 + **两条都走代理**；
seek 时音轨跟着跳（不同步就是"画面跳了声音没跳"）；清晰度菜单默认显示实际档、
大会员档禁用且 `title=需大会员`、选可用档回调。
`BiliVideo.test.tsx` 2 条：**挂载不取流**、点播放才取一次（+ 拿到后双元素成立）；
失败如实显示原因。

⚠️ 踩点：React 把 `muted` 当 **property** 设，DOM attribute 上不一定有 ⇒ 断言要读 `el.muted`。
