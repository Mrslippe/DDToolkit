# 403-20261007-B2第二十一轮 Chromium flag 把 10.8% 打到 0.1%

用户跑了 flag 之后说"肉眼已经有点难分辨是否还在丢帧"。**探针答得毫不含糊：不是"好一点"，是基本清零。**

## 两次会话（同一支视频，只差在启动时的 flag）

| 会话 | `硬解=` | `尺寸=` | `全屏=` | 丢帧 |
|---|---|---|---|---|
| 02:20:46（改 flag 前） | **有** | `→1920x1080` | `28/30秒` | **94/872 = 10.8%**（`呈现=25.8fps`） |
| 02:25:15（改 flag 后） | **无** | `→1920x1080` | `28/30秒` | **1/873 = 0.1%**（`呈现=28.9fps`） |
| 同上 `续` | 无 | `→1920x1080` | `20/21秒` | `0/594 = 0.0%` |
| 同上第二个 `start` | 无 | `→1920x1080` | `29/30秒` | **`0/895 = 0.0%`**（`呈现=29.7fps`） |
| 同上 `续` | 无 | `→1920x1080` | `17/18秒` | `2/558 = 0.4%` |

**全屏、铺满、透明底、时长 ~85 秒 ⇒ 一共丢了 3 帧。**
对照：改之前同一个配置是 **10.8%**（每秒 ~4 帧）。

⇒ **用户"肉眼难分辨"的直觉是对的，而且探针把它钉成了数字**（这正是探针存在的理由：
`devlog/396` 那次"用户说卡、日志说 0.0%"的反向误差，这次方向相反但同样靠它才说得清）。

## 唯一的变量：`硬解` 从 `有` 变成 `无`

两次之间只改了启动环境变量，而日志里**唯一系统性变化的字段是 `硬解=`**
（`MediaCapabilities.decodingInfo().powerEfficient`，`devlog/384` 的口径：它是**能力查询**，
不是"刚才真走了硬解"）。⇒ **嫌疑落到"硬件解码 / GPU 呈现那条路"上。**

三条独立的旁证把它串起来：

1. `devlog/387`：同一台机器上 **Edge 播同一支视频是流畅的，而 Edge 那轮 `硬解=无`**；
2. 这一轮：**关掉那条路 ⇒ 我们也不卡了**；
3. 五格对照（`devlog/402`）里"画面多大 / 底色透不透明 / 合成表面多大"全都无关 ——
   而这三样**都不改变解码路径**，只有"进 OS 全屏"会（Chromium 会按元素的呈现状态挑解码/呈现路径）。

⚠️ 还差一步才算定死。**已确认用户跑的就是第一条**：

```
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--disable-direct-composition
  --disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection
  --autoplay-policy=no-user-gesture-required
```

⚠️⚠️ **而 `硬解=有→无` 很可能是"关掉 DC"的副作用，不一定是"解码器换了"**：
Chromium 的 `powerEfficient` 判定要求**解码与呈现都在 GPU 上**（这正是 "power efficient" 的定义）——
关掉 DC 让呈现退回非 GPU 路径，它自然就报"无"。所以这一格**不能**拿来当"元凶是硬件解码器"的证据。

⇒ 下一步只有一刀能分清楚：

```powershell
# 只关"硬件视频解码"，**不动** DirectComposition
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS='--disable-accelerated-video-decode --disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection --autoplay-policy=no-user-gesture-required'
npm run tauri:dev
```

- 这样也流畅 ⇒ **元凶是硬件解码器**（`硬解=` 那一格的读数也才有意义）；
- 照样卡 ⇒ **元凶是 DirectComposition 这条呈现路径本身**（那么 `硬解=无` 就只是它的副产品）。

## 修法在哪里落地

不管定到哪一条，**都不需要用户再设环境变量**：wry 的 WebView 构造参数就在我们手里
（`frontend/src-tauri/src/lib.rs`）——把 flag 加进 `additional_browser_args`（连 wry 的三条默认值
一起显式写上，免得像环境变量那样"整串替换"出意外），全屏卡顿就是壳的一行配置。
⚠️ 落地前要量一下**代价**：软件解码 1080p 的 CPU 占用，以及关掉 DC 对整页合成的观感。
