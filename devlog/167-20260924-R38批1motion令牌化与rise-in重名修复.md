## 一、改前必查：规格与代码有四处不一致（**本批最值钱的部分**）

| # | 规格说 | 实际 |
|---|---|---|
| 1 | §2「现状是**三处**零散时长（220 / 180 / 0.35s rise-in）」 | 状态岛实际有 **5 处**硬编码（220 / 180 / 180 / 300 / 200），而且 **`rise-in` 根本不在状态岛里**（它是 `.topbar` 等的**应用揭幕**动画） |
| 2 | §2「`--ease-standard` …… **已在用**（`.si-panel` 入场曲线）」 | **错**。`.si-panel` 用的是 `cubic-bezier(0.22, 0.61, 0.36, 1)` —— 全站**唯一的异类曲线**（标准是 `0.22, 1, 0.36, 1`） |
| 3 | §12 批 1「收进令牌（**零行为变化**，纯整理）」，风险"极低" | 与 §2 的令牌值**矛盾**：`--motion-fast` 是 **140ms**，而现状徽章 180ms、文案 300ms。且现有值 **180/300/200 都不在令牌集**（只有 140/220/320）⇒ **"保持值"与"收进令牌"不可兼得** |
| 4 | — | **真 bug**：`layout.css` 里**两个同名 `@keyframes rise-in`**（揭幕组 8px / 条目组 14px）。CSS 同名 keyframes **后者赢** ⇒ 揭幕那组写的 `translateY(8px)` **从未生效**，实际跑的是条目组的 14px |

第 3、4 条**用户拍板**：按 §2 对齐值（接受行为变化）+ 本批一并修重名 bug。

## 二、做了什么

**① 令牌化（7 处）**

| 位置 | 旧 | 新 |
|---|---|---|
| `.si-panel` 面板入场 | `0.22s` + `cubic-bezier(.22,.61,.36,1)` | `var(--motion-base)` + `var(--ease-standard)` |
| `.si-count` 计数徽章 | `0.18s ease` | `var(--motion-fast) ease` |
| `.si-panel` reduced-motion | `0.18s ease` | `var(--motion-fast) ease` |
| `.pill-text-fade` 文案淡入 | `0.3s ease` | `var(--motion-fast) ease` |
| `.si-chevron` 展开翻转 | `0.2s ease` | `var(--motion-base) ease` |
| `rise-in-page` 揭幕组 | `0.35s ease` | `var(--motion-slow) ease` |
| `rise-in-item` 条目组 | `0.32s cubic-bezier(.22,1,.36,1)` | `var(--motion-slow) var(--ease-standard)` ← **真零变化**（值全同） |

顺带获得：所有时长走 `calc(N × var(--motion-scale))` ⇒ 动效调测页的**慢放**对它们也生效了。

**② `rise-in` 重名修复**：拆成 `rise-in-page`（揭幕，8px）与 `rise-in-item`（条目，14px）。
揭幕那组的 8px 位移**首次真正生效**。

## 三、护栏：把"令牌真的被用上"变成机器判据

原来 `--status-island` 只判面板时长 `> 0`、chevron 硬编码 `== 200` —— **判不出"令牌被写回硬编码"**。

改成：**元素上量到的时长必须等于令牌的解析值**。

- `probe.ts` 用**临时元素**把令牌解析成毫秒（`getPropertyValue('--motion-base')` 拿回来的是
  `calc(220ms * var(--motion-scale))` **原文**，不是时间 —— 所以注入一个 `animation-duration: var(--x)`
  的隐藏元素，读它计算后的 `animationDuration`）
- 断言：面板 / chevron == `--motion-base`；文案淡入 / 计数徽章 == `--motion-fast`
- **反向验证过**：把面板临时写死 `0.3s` ⇒ 报
  `面板入场时长是 300ms，应等于 --motion-base（220ms）—— 令牌没被用上（写回硬编码了？）`，退出码 1；还原后绿

> `.si-count` 是条件渲染（`lit && notices.length > 1`），本模式只派一条消息 ⇒ 量不到时不判
> （它和文案共用 `--motion-fast`）。**这是有意的**，打印里会显示 `计数徽章=None` 而不是静默跳过。

## 五、⚠️ 如实标注

1. **这不是"零行为变化"**（规格 §12 的说法不准确）。值确实变了：徽章 180 → **140ms**、
   文案 300 → **140ms**、chevron 200 → **220ms**、面板曲线换了。方向是"更快、更克制"
   （合 §0「借它的语法，不借它的存在感」），且**曲线那处是修正全站唯一异类**。
2. **`.si-count` 没有独立判据**（条件渲染量不到）。它和文案共用令牌，所以令牌值本身是被验的；
   但"将来有人把 `.si-count` 写回硬编码"探针抓不到。
3. **揭幕有一处 20ms 的名义越界**：`.app-main` 最晚 `0.45s 延迟 + 0.32s 时长 = 0.77s`，
   而 `main.tsx::ENVELOPE_MS = 750ms` 就挂 `shell-settled`。**实测感知不存在** ——
   t=750ms 时该元素动画进度 93.75%，`ease` 输出 ≈ **0.995 不透明度**。
   本批把差距从 50ms **缩到** 20ms（原来 0.35s 时长 ⇒ 0.80s）。**没有为它加判据**（`ENVELOPE_MS`
   与 CSS 时长是跨语言耦合，要另设机制）。**没有测试断言这条耦合**，只有注释 —— 这是个已知缺口。
