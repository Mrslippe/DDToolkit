## 一、那行日志

```
[2026-09-24 17:08:13] show_widget_window 被调用 x=None y=None
```

| 我上一轮的推断 | 实际 |
|---|---|
| 「命令**没被调用**」（因为控制台里没有那行）| **被调用了** |
| 「小窗可能压根没创建」 | 创建流程**至少进到了这一步** |

**为什么我会推错**：那行当时还是 `println!` —— **只进控制台、会滚**，
用户只截了一屏（到 `RunEvent::Ready +34ms` 为止），而我的探针在 **+1500ms** 才打印。
**我拿一个不完整的日志当成了完整证据。**

⇒ 这轮把**所有**小窗诊断改走 `shell_log`（写进数据目录的 `shell.log`）：
用户能整份发过来、不会丢帧、也不依赖他截得准不准。

## 二、现在钉死的证据链

1. **命令链通** —— `show_widget_window 被调用 x=None`（shell.log）
2. **JS 模块真的执行了** —— 第二轮的"粉色启动幕消失"就是证据：`boot-splash.remove()`
   在 `main.tsx` 的**模块作用域**，它跑到了
3. **但 React 没画出来** —— 那行自检条（`position:fixed` + 不透明白底黑字）用户确认"没有"

⇒ **模块执行了，但 React 渲染阶段抛错了。**

## 三、为什么前几轮加的监听一个都抓不到

`window.onerror` **抓不到 React 渲染阶段的异常** —— React 自己捕获后走 error boundary 链路，
**不冒泡到 window**。所以前几轮那些监听**在结构上就不可能捕获它**。

这轮加了 **class 组件的 ErrorBoundary**（React 的硬要求：**只有 class 能当**），
`componentDidCatch` 里把 `name / message / componentStack / stack` 全部写进 `shell.log`，
同时画在窗口里（9px，塞得下多少算多少）。

## 四、顺带修掉的静默失败

`shellBridge` 那三个函数原来是空的 `catch { return false }` ——
**"命令没被调用"和"命令报错了"在日志里长得一模一样**（都是什么都没有）。
改成 `console.error`；`AppSettingsDialog` 里每一步 `console.info` 打点
（切换值 / `isTauri` / 两个调用结果）。

> 这个毛病和本仓 `doc_check` 那条纪律是同一个：**沉默的失败等于没有失败**。
