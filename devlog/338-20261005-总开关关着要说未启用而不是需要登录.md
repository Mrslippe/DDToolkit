# 338-20261005 总开关关着要说「未启用」而不是「需要登录」

> 用户真机反馈（原文两条）：
> ① 「粘贴 cookie 登陆之后还是依旧在登陆按钮左侧显示一项**受限胶囊**，并且点开的详情页显示
>    抖音未登陆，我希望的效果是粘贴完成后自动清除这个警告」；
> ② 「抖音账号信息没获取到、首次添加账号帖子抓取流程也没抓取到数据」。

## 一、先把②查清：**没坏，是总开关从来没开过**

在真实开发库（`E:\test\DDToolkit-data`）上验：

| 查什么 | 结果 |
|---|---|
| `.env` 的 `DOUYIN_COOKIE` | 有（6356 B）+ `DOUYIN_UA`（125 B）+ `DOUYIN_COOKIE_SET_AT` ⇒ **粘贴那一步成功了** |
| `app_meta` 里的 `settings.DOUYIN_ENABLED` | **没有这一条** ⇒ 用的是默认值 `False` |
| 后端日志 | `抖音总开关关着，本次不发请求（设置 → 抓取设置 → 平台抓取）`（01:44:00 首屏跳过 account#27、01:44:15、01:44:20、01:46:37） |
| 账号 #27（douyin `MS4wLjABAAAA…`） | `display_name=None`、0 条帖子 ⇒ **一个请求都没发出去**，所以当然是空的 |

⇒ ② 的答案是**开关**（`DOUYIN_ENABLED` 默认关，`devlog/335` 定的合规闸门，不是 bug）。
但这句话不能只写在回帖里 —— 用户是**看着界面**得出"没生效"的结论的，所以本批改的是界面。

## 二、①的根因：角标把"我们自己关了"说成"需要登录"

`/capabilities` 里抖音那条以前是 `state = requires_login` + 总开关的说明文案。界面于是渲染
「**需要登录**」——而用户刚粘完 Cookie（后端明明报 `已配置`）⇒ 他的结论必然是"我的 Cookie 没生效"，
于是**反复重粘**。真正该做的是「设置 → 抓取设置 → 平台抓取 → 启用抖音抓取」，他照着角标做一万次也不会生效。

> ⚠️ 这是一类**通用**错误，不是抖音专属：**说法要跟着"补救动作"分家**。
> `devlog/239` 给失败文案立过同一条规矩（"分工不同就别用同一句话"），这次轮到能力矩阵的状态。

修法分三层：

1. **后端加第四态 `disabled`**（`app/services/capabilities.py`）：`STATES` 三态 → 四态，
   新增 `_disabled_reason(platform)`（今天只有抖音有总开关，将来加一家就在这里加一条），
   `snapshot()` 命中时 `state = DISABLED` 且 `ready` 强制 `False`。
   ⚠️ `DOUYIN_DISABLED_REASON` 的文案**从 `devlog/335` 起就已经指向设置**（那时它挂在
   `requires_login` 上，是"对的文案配错的状态"）—— 所以本批只动状态，不动那句话。
2. **前端按状态说三种话**（`utils/capabilities.ts::limitBadge()`，纯逻辑 + 单测）：
   `requires_login` →「需要登录」· `disabled` →「**未启用**」· 认不出 →「部分受限」（宁少说，不误导）。
3. **说明窗不再通篇"未登录"口径**：标题/正文按有没有 `disabled` 项分岔；页脚**全是开关关着时不给
   「去登录」按钮**，换成一句「这些项与登录无关：去『设置 → 抓取设置 → 平台抓取』打开对应开关」
   —— 点进去也没有用的话，给按钮比不给更费时间。

## 三、为什么**不**"粘贴后自动清除警告"（用户字面要的那个效果）

用户要的效果是"粘完就自动清掉"。本批**没有**让粘 Cookie 顺手打开总开关，理由：

- 那道闸门是**合规**闸门（抖音用户协议禁止自动化采集，风险落在用户账号上，`devlog/335`），
  它的语义就是"用户本人确认知情后才开"。凭据粘对了**不等于**同意一直抓 ⇒ 自动开＝替用户签字；
- 而且它真的**会**消失：开关打开后 `/capabilities` 里抖音那条变 `full`，角标那条就没了 ——
  用户要的"自动清除"在**开关那一步**之后是成立的，只是触发点不该是粘 Cookie。

真正的问题从来不是"警告没消失"，而是**它说了假话**（说登录、其实是开关）。所以批里做的是让警告诚实。

## 四、顺带修掉一个**真会咬人**的刷新缺口

两条保存路径原先都不重取能力矩阵：粘完 Cookie（`LoginDialog.saveCookie`）、改完设置
（`AppSettingsDialog.save` / `resetAll`）—— 而后一条正好住着总开关。
⇒ 用户把开关打开后，顶栏那个「N 项受限」**还是旧值**，得重启才更新（与 `devlog/086` 扫码那条路
同一个理由，当时只给扫码补了）。两处都加 `refreshCapabilities()`，并补**源码级**断言钉住
（渲染级测试要 Mock 掉整个 api 层，收益不抵成本）。

## 五、⚠️ 改说明窗文案时撞出的第三个洞：**页脚会被推出视口**

给说明窗换成分岔文案后，`ui_probe --capabilities` 立刻红了一条：`说明窗页脚浮片点不着`。
量下去发现**不是新 bug，是旧账**：

- `DialogContent`（`components/ui/dialog.tsx`）是 `fixed top-[50%] translate-y-[-50%]` 垂直居中，
  **没有 `max-height`**，而 `.cap-limits-dialog` 只有 `max-width`；
- 内容一长（4 条受限 + 每条两三行 note + 能用清单）整窗高过视口 ⇒ 页脚被推到视口外
  ⇒ 探针量的 `elementFromPoint` 落在视口外返回 null（"点不着"），
  **用户侧是"看不到补救入口"**（这次只是文案多了一行才越线）。

修法是三段式：`.cap-limits-dialog` 加 `max-height: calc(100vh - 120px)` +
`grid-template-rows: auto minmax(0, 1fr) auto`，正文包一层 `.cap-limits-body`
（`min-height: 0` + `overflow-y: auto`）⇒ 页头与页脚常驻，只有清单滚。
⚠️ `min-height: 0` 不能省：grid 子项默认 `min-height: auto`，会撑破父级（等于没限高）。

> ⚠️ 教训：**"探针点不着"经常是布局真问题，不是探针挑剔**。这次如果不查就把它当"探针又抽风"，
> 用户那边就是"说明窗底下的按钮消失了" —— 而且只在内容长到越线时出现（最难复现的那种）。

## 六、判据（都在门禁里）

- 后端：同一条用例里断言"配了凭据 + 开关关着 ⇒ `state == DISABLED` 且 `!= REQUIRES_LOGIN`"，
  且 `note` 指向设置、开关打开后同一份凭据立刻放行（`tests/test_capabilities.py`）；
- 前端：`limitBadge` 三态文案 + `disabled` 与 `requires_login` 互斥 + 开关与登录态是**两个独立字段**
  + 两条保存路径都调 `refreshCapabilities()`（5 + 2 条）；
- **UI 探针**（能让真机自己说）：受限项角标带 `data-limit-state`，探针把"状态 → 说法"逐条量出来
  并按表校验（`requires_login=需要登录` / `disabled=未启用`）；"全是未启用"时不许有「去登录」按钮、
  且必须有"去设置"那句提示。⚠️ 只看截图是量不出这个的（字都长得差不多）。
- 布局契约（源码级 3 条）：正文在 `.cap-limits-body` 里、CSS 有 `max-height` + 三行网格 +
  `min-height: 0`、两条页脚分支都在。
