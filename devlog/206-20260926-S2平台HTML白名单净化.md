# 206-20260926-S2平台HTML白名单净化

批次 3（S2）。全仓**只有一处**平台 HTML 进 React DOM 的点，本批把它关进白名单。

## 一、威胁模型：**别只盯 XSS**（计划 §2.1 的口径）

真机 CSP 已经是 `script-src 'self'`（无 `unsafe-inline`/`unsafe-eval`）⇒ 注入的
`<script>` / `onerror=` / `javascript:` **本来就执行不了**。本批真正挡的是：

1. **`style-src 'self' 'unsafe-inline'` ⇒ 注入的 `<style>` 与 `style=` 会生效** ——
   把危险操作伪装成"显眼的下一步"（UI 伪装 / 点击劫持）。**CSP 永远管不了这一层。**
2. ⚠️ **我们的 Tailwind 工具类是全局的** ⇒ 平台 HTML 里一条
   `class="fixed inset-0 z-50"` 就能盖住整个界面 —— 所以 **`class` 必须剥掉**。
   这条是本次最容易漏、后果最直接的一层（`class` 看起来"无害又该保留"，它还真的在
   平台 HTML 里到处都是）。
3. 开发态浏览器（`npm run dev` 走 Vite，CSP 是否生效未在真机核实）＋**将来任何一次放宽 CSP**
   —— 那时净化就从纵深防御变成唯一防线。

## 二、核实结论（与计划的一处出入）

- 全仓 `dangerouslySetInnerHTML` **只有一处**：`PostDetailDrawer.tsx:297`，喂的是
  `body_json.content`（B 站专栏全文，`scheduler.py:1408` 写进去的
  `fetch_article_detail()["content"]`）。旧注释写着"本地工具场景直接渲染，如部署公网建议
  净化处理" —— **那个判断是错的**（理由见上），已随代码改掉。
- ⚠️ 计划说"`OriginCard`（`:311-314`）渲染同源数据，要一起过" —— **实测不需要**：
  它今天渲染的是 React **文本节点**（`{origin.title}` / `{origin.text}`），压根没有 HTML 通路。
  ⇒ 没有为它加净化，而是补了一条**扫源码的判据**：全仓只允许一处 `dangerouslySetInnerHTML`，
  且它必须消费 `sanitizePlatformHtml(...)`（防止哪天又长出第二处）。

## 三、改动面

- 新增 `frontend/src/utils/sanitizePlatformHtml.ts`：白名单（标签/属性）＋
  URI 只放行 `http(s)` 与协议相对 ＋ 外链统一 `rel="noopener noreferrer"` / `target="_blank"`
  （与仓里另外三处外链同款）。
- `PostDetailDrawer.tsx` 只消费净化结果。
- **依赖**：`dompurify`（运行时）＋ `jsdom`（**仅测试**：本仓 vitest 跑在 node 下，
  而 DOMPurify 要真 DOM ⇒ 新用例用 `// @vitest-environment jsdom` 单文件切环境）。
- **CSP 一个字都没改**：`git diff frontend/src-tauri/tauri.conf.json` 为空（判据之一）。

## 四、两个实测发现（都写进代码注释了）

1. ⚠️ **`ALLOWED_URI_REGEXP` 管不到 `<img>` 的 `data:`**：DOMPurify 对
   `audio/video/img/source/track` 另有一份 data-URI 白名单，命中就**跳过** URI 正则 ⇒
   `<img src="data:image/svg+xml,<svg onload=alert(1)>">` 原样活下来（实测）。
   虽然 `<img>` 里的 SVG 脚本不执行，但它能当**整屏伪装的图**用 —— 与 `class` 劫持同类。
   ⇒ 在 `afterSanitizeAttributes` 里把"只放行 http(s)/协议相对"**再钉一遍**。
2. **真实专栏 HTML 里就有** `style="width: 340px"`、`class="ql-bg-#ffa0d0"`、
   `contenteditable="false"` ⇒ 这些净化后会掉（**有意**）；而
   `<figure>` / `<img src="//i0.hdslb.com/…">` / `width` / `<br/>` 全部保留 ⇒ 排版不损坏。

## 五、判据（27 条）与反向验证

- 恶意 payload 矩阵 16 条（script / 事件属性含大小写变体 / `javascript:` / `data:text/html` /
  `data:` 图片 / SVG onload / iframe / form / object / 内联 style / class 劫持 / `<style>` /
  畸形嵌套 / 未闭合注释外逃），每条都断言"净化后再解析：没有禁用标签、没有 `on*`、
  没有 `style`/`class`、`href`/`src` 只能是 http(s) 或协议相对"。
- 白名单策略 3 条（禁用项不在表里；放行清单覆盖真实排版需要的标签；外链 rel/target）。
- **真实数据 4 条**：`tests/fixtures/bili_article_cv3000000.html`（老编辑器 84 段 + 18 组
  figure/img）与 `cv20000000.html`（新版 `ql-*` 类名 + h1）——
  **从 `api.bilibili.com/x/article/view` 真拉的**（来源/日期/形态写在文件头注释里；
  ⚠️ 正文文字已换成「文」，**标签/属性/空白/实体逐字保留**，见 §六）。
  断言：`p`/`img`/`figure`/`br`/`strong` 计数**一个不少**、图片仍带 `src`、文本量级不缩水、净化幂等。
- 接线 1 条（见 §二）。

**反向验证（两条，缺一条都说明判据没牙）**：

| 改法 | 结果 |
|---|---|
| 把 `class`/`style` 放回白名单（"顺手放宽"的典型） | **3 条红**（两条 payload + 策略用例）✓ |
| 把调用点改回 `dangerouslySetInnerHTML={{ __html: body.content }}` | 接线判据红并点名 `PostDetailDrawer.tsx:297` ✓ |

⚠️ **不要用"换个 payload"当反向验证** —— 那只说明 payload 挑得好，不说明净化接上了。

## 六、两条 fixture 的来路（为什么不是手写样本）

`ARCHITECTURE.md` §6 第 22 条要求"判据至少有一条用例吃真实数据"。所以 fixture 是从
上游真拉的专栏全文，而不是我编的：

```
https://api.bilibili.com/x/article/view?id=3000000   → 7397B 全 HTML（84 段 / 18 图）
https://api.bilibili.com/x/article/view?id=20000000  → 2601B 新版编辑器（ql-* 类 + h1）
```

⚠️ **正文文字替换成「文」**（不把第三方文章内容入库），**标签/属性/空白/`&xxx;` 实体逐字保留**
—— 替换脚本刻意只动"非空白可见字符"（`_tmp_make_fixture.py` 跑完即删）。
判据考的就是这些结构，所以这一步不影响判据的有效性。

## 七、未验证 / 风险

- ⚠️ **本机库里没有任何一条 `body_json.content`**（两条 article 一条是 Quill Delta、一条是纯文本，
  实测确认）⇒ **这条路径在当前数据上看不到**，真机上也就看不到差别。它是一条**存在但休眠的**
  通路（哪天专栏返回 HTML 就会走），本批是"在它被走到之前先把门装上"。
  ⇒ 停止条件（"净化后真实排版严重损坏"）在这台机器上**暂时观察不到**；判据落在真实 fixture 上。
- 外链**主机白名单**与 WebView2 的跳转行为**不在本批**：归批次 4ab（计划 §2.17）。
  本模块只保证"只放行 http(s)/协议相对"，别在这里顺手加主机白名单 —— 那会与 4ab 出现两份口径。
- 新增依赖 `dompurify` 进主包（`main` chunk 1,059.17 kB / gzip 360.14 kB）；
  `jsdom` 只在 devDependencies。
