# 316-20261004 播放器浮层统一成 hover 触发（音量浮窗的 `:focus-within` 是"点完不收"的根因）

> 用户（附截图）：
> ① 「鼠标点击音量调节滑杆后移开，滑杆并不会自动缩回去，而是需要点击空白处后才会自动回缩」；
> ② 「清晰度、倍速的按钮上拉栏并不是 hover 触发，而是点击触发，这会让控制逻辑不统一，
> 全部改为 hover 触发」。

## 一、症状 ①：`:focus-within` 把浮窗钉住了

CSS 里音量浮窗的显示规则是：

```css
.vp-volwrap:hover .vp-volpop, .vp-volwrap:focus-within .vp-volpop { opacity: 1; pointer-events: auto; }
```

`:hover` 那一路没问题；问题在 `:focus-within` —— **鼠标点一下滑杆，`<input type=range>` 就拿到了焦点**，
而它会一直保持到"点别处"为止 ⇒ 指针移开也照样显示（用户描述得完全准确：必须点空白处才收）。

修法：`focus-within` → **`:has(:focus-visible)`**。Chromium 的 `:focus-visible` 对"鼠标点击拿到的焦点"
**不成立**（range 这类不需要文字输入的元素），而键盘 Tab 过来成立 ⇒ 鼠标移开就收、键盘仍常开。

## 二、症状 ②：清晰度/倍速改成 hover（与音量同一套）

原来是 `useState` + `onClick` 开关。现在抽了一个 `useHoverMenu()`，三处浮层**同一套口径**：

| 输入方式 | 行为 |
|---|---|
| 鼠标 | **hover 开、移开关**（点击**不改变**状态 —— 否则会出现"点一下反而关掉"） |
| 键盘 / 触屏 | 点击（Enter/Space）**钉住**开合；`Esc` 收起；`aria-expanded` 如实上报 |

两条细节，都是踩过的：
- **宽限 140ms**：按钮与浮层之间有几像素的缝，指针穿过去时 `mouseleave` 先到 —— 没有宽限就会
  "刚移开就没了、够不着菜单"（音量浮窗当初靠 CSS 里一块看不见的"桥"绕开，菜单没有那块桥）；
- 每组浮层**各自一个 hover 区**（`[data-vp-menu]`）：挂在外面那个 `.vp-rate` 上的话，
  指针划过倍速会把清晰度菜单一起带出来。

判据 6 条（`VideoPlayer.menus.test.tsx`）：hover 开/移开收、两组互不串、缝里不闪断、
键盘点击钉住 + 再点收、选中一项后收起、音量浮窗的 CSS **不许**出现裸 `:focus-within`
（最后这条就是反向验证：改回旧写法立刻红）。

⚠️ 测试环境的两个硬事实（写进用例注释）：React 的 `onMouseEnter/onMouseLeave` 要用
`mouseover`/`mouseout` + `relatedTarget` 派发；收起有 140ms 宽限，断言"已收起"要真等一会儿。
