# 095-20260915-R18 关闭窗口 → 隐藏到系统托盘（后台照抓、前端不渲染）

> 用户需求（2026-09-15）：「我希望可以关闭前端界面隐藏到系统托盘，这个时候后台抓取照样进行，
> 但不用渲染前端」。两个待定项由用户当场拍板：
> **首次点 ✕ 问一次、之后按选择记住**；**P1（隐藏+停表）与 P2（深休眠省内存）一起做**。

---

## 一、改造前是什么行为（先把问题说准）

代码级核实：`tauri.conf.json` 里窗口 `visible:false`、**没有托盘**；`lib.rs` 对
`CloseRequested`/`Destroyed` **只打印日志、不拦截**；`RunEvent::Exit` 里会显式 kill
后端子进程，Windows 侧还有 Job Object（`KILL_ON_JOB_CLOSE`）兜底。

⇒ 点 ✕ = 销毁窗口 → Tauri 关掉最后一个窗口即退出 → **sidecar 连带被杀、抓取停止**。
所以"关闭 = 全退"不是错觉，而是这条链路。

## 二、方案（P1 + P2）

| 块 | 做法 |
|---|---|
| **托盘**（Rust） | `tauri` 开 `tray-icon` feature；菜单「显示主界面 / 后台运行中（禁用）/ 退出」；**左键单击 = 唤回**；tooltip 写明"后台运行中" |
| **关闭语义** | `on_window_event` 里拦 `CloseRequested` → `api.prevent_close()` + `hide()` + `set_skip_taskbar(true)` + `emit("shell:hidden")`；`RunEvent::ExitRequested` 在非主动退出时 **`api.prevent_exit()`**（否则"窗口没了"仍会把应用带走 —— 深休眠销毁 WebView 也会走到这里，这条是必须的） |
| **退出路径** | **唯一一条**：托盘「退出」→ 先唤回窗口 + `emit("shell:quit-requested")` → 前端确认（正在抓取时写明"退出会中断本轮"）→ `invoke("quit_app")` → 置 `QUITTING` 再 `app.exit(0)` → 走既有 `RunEvent::Exit` 清理 |
| **首次询问** | 前端 `CloseActionDialog`：两个选项**各自写清后果**（托盘：后台继续抓、界面停止刷新、10 分钟后释放内存；退出：结束进程/正在抓取会中断）+「记住我的选择」→ 写 `prefs.close_action` |
| **前端停表**（P1 的实质） | `utils/shellLifecycle` + `hooks/useShellHidden`：接 `shell:hidden/shown`（浏览器/探针退化为 `visibilitychange` + dev 钩子）。**停**：顶栏抓取轮询、60s 登录态轮询、状态岛 6s 空闲轮播；**复**：立刻补一轮再恢复定时器 |
| **深休眠**（P2） | 隐藏满 **10 分钟**（`DDTOOLKIT_TRAY_SLEEP_SECONDS` 可覆盖，仅供测试）→ **销毁 WebView** 释放内存；唤回时**重建窗口** + 加载 `index.html?restored=1` → 前端把路由/视图还原回离开时的位置 |
| **二次启动唤回** | `single-instance` 回调从"只 `set_focus()`"改成 `show + unminimize + set_focus`（隐藏/深休眠状态下原来的写法等于"点了没反应"） |

**为什么 P2 要真销毁而不是导航到 `about:blank`**：只有窗口销毁才会让 WebView2 的渲染进程
一起退出，内存才真的还回去；导航到空白页只丢 DOM，进程与大部分内存还在。

**为什么恢复要带 `?restored=1` 而不是直接开深链接**：SPA 的 `/vtubers/14` 在 Tauri 的
资源协议下会 404 —— 所以重建窗口一律加载 `index.html`，再由前端 `navigate()` 回到原处。

## 三、护栏：探针 `--tray-suspend`（这一批的关键产出）

托盘本身是 OS 级能力，无头浏览器测不到；但"隐藏之后该发生什么"完全可以断言。
探针分三段对照，**缺第一段这探针就是空转**（一个彻底卡死的应用也能"通过"隐藏断言）：

```
① 可见（基线）：一个空闲周期内轮询 1 次（在跑=True）
② 隐藏：一个周期内轮询 0 次（停住=True）· 轮播停住=True
③ 唤回：2.5s 内轮询 1 次（立刻补一轮=True）
轮询时刻（ms，隐藏发生在 15699）：[2841, 3376, 3386, 13396]
```

### 这个探针抓到了两个真 bug（都值得记）

第一版跑出来是 `② 隐藏：一个周期内轮询 **1** 次`。顺着"轮询时刻"看：

```
轮询时刻：[1499, 2033, 2043, 12053, 22063]，隐藏发生在 14349
```

**bug 1（竞态）**：停表判据原本读的是 React 同步过来的 ref —— 而状态要等下一次渲染才落地，
定时器可能恰好落在那道缝里。改成读**同步源** `isShellHidden()`。
**bug 2（更隐蔽）**：只拦住"排下一轮"是不够的 —— `22063` 那一发是在**还可见时**（12053 那次
轮询结束时）就排好的，隐藏之后它照样到点触发。所以 `poll()` **触发时还要再看一次**。

两条都写进了代码注释与 DEV-LOOP：**"停表"要在"排程"和"触发"两处都判，且判据必须读同步源。**

## 四、深休眠的取舍（诚实标注）

- **代价**：唤回要重建窗口 + 重载（慢约 1 秒，会看到既有的启动幕）；恢复位置靠
  `utils/shellState` 持久化的路由 + 视图（**校验过**才用：只认 `/` 与 `/vtubers/<数字>`，
  过期 12 小时或格式坏一律当没存过）。
- **没做的**：隐藏多深算"该省内存"不做成设置项（固定 10 分钟，文案写进首次询问框）；
  托盘菜单里的实时进度（"后台运行中"是静态文案）。
- **要人工验的**（打包版，探针覆盖不到）：✕ → 窗口消失 + 托盘图标在 → 等 10 分钟
  （或用 `DDTOOLKIT_TRAY_SLEEP_SECONDS=20` 起）→ 唤回，位置回来了、数据是新的 →
  托盘「退出」→ 任务管理器无 `ddtoolkit.exe` 与 backend 残留 → 再点 exe → 唤回而不是第二个实例。
