# 717-20261028-任务浮窗（C 批）

## 用户口径

- 形态：**应用内浮窗**（同「添加 Vtuber」那种 Dialog），**不是** Tauri 第二扇窗；
- **不自动弹出**：点采集后只出顶栏通知，**点通知**才打开浮窗；
- 右下角三个按钮：取消 / 完成 / 分析；**抓取中途「完成」「分析」都是灰的**；
- 关掉浮窗不影响任务（轮询在 store 里照跑），顶栏通知还在；
- 「完成」= 关窗 + 回工作台，**不自动分析**。

## 做法

| 文件 | 改动 |
|---|---|
| `hooks/useFanTask.ts` | 新增 `openWindow` / `analyzeRequest` 两个状态 + `openTaskWindow` / `closeTaskWindow` / `requestAnalyze` 三个动作 |
| `components/workbench/FanTaskDialog.tsx` | 新组件：标题（采集/分析 · 主播）、区间、进度条、阶段/翻页/吞吐/ETA、逐场列表、失败明细、三个按钮 |
| `App.tsx` | 挂在**应用级**（`ErrorBoundary` 内、`Routes` 旁）：用户切走了页面，浮窗也得能开 |
| `pages/WorkbenchPage.tsx` | 响应 `analyzeRequest`（走与页面「分析」按钮同一条路）+ 忙碌面板加「查看进度」入口 |
| `api/types.ts` | `FanCollectSessionDetail` 补 `title?` / `ms?`（后端下一批开始提供） |
| `styles/workbench.css` | `.wb-task-dialog` / `.wb-task-body`（可滚）/ `.wb-task-foot`（右对齐） |

## 两个设计决定

1. **`analyzeRequest` 用自增计数，不用回调。**
   浮窗挂在 `App` 上，分析逻辑在工作台页里 —— 回调会变成"全局注册一个可能已卸载的函数"。
   计数则是单向信号：工作台监听变化，自己决定怎么分析（顺带天然幂等：值没变就不重跑）。
2. **「分析」只在 `state === 'done'` 时可用**，不是"不 running 就亮"：
   取消/失败之后点分析没有意义（那时采集数据不完整，用户该先重采）。
