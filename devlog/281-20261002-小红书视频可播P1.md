# 281-20261002 小红书视频：详情页里能播了（P1）

> 需求（2026-10-02）：「帖子详情页不止展示图片，视频也可以展示，评估一下技术可行性」→
> 评估后用户定「先 P1 看看效果」（P1 = 小红书视频解析 + 详情页 `<video>` + CSP `media-src`）。

## 一、可行性结论（评估阶段的实测，全部为真机数据）

| 事实 | 实测 |
|---|---|
| **数据早就在手里** | 3 条视频帖的 `raw_json.video` 里已有完整流信息（详情抓取时就带回来了，只是没解析） |
| **小红书不设防盗链** | `master_url` 无 Referer / 裸请求均 200，`accept-ranges: bytes`，`Range` → 206 |
| **唯一挡路的是 CSP** | `tauri.conf.json` 只有 `default-src 'self'`，**没有 `media-src`** ⇒ `<video src=CDN>` 会被拦 |
| B站（497 条视频帖） | 没有直链，要播需官方 iframe 或 playurl+WBI 签名 ⇒ 留给 P2 |
| 微博（1 条） | `body.video={mp4:null}`、`page_info.media_info` 为空 ⇒ 需补映射，样本极少 |

## 二、这一刀做了什么

1. **解析**（`xiaohongshu._video_of()`）：`video.media.stream` → 播放信息 + **fallback 链**。
   选流序：**EF5（H.264 档）里分辨率最高 → EF4 → 其余档 → 各条 `backup_urls`**。
   ⚠️ 踩点记录：`stream[].duration` 是**毫秒**（13281）、`media.video.duration` 是**秒**（14），
   两处单位不同；`drm_type=0`（无 DRM）才可能播。
2. **不动抓取链路**：`parse_note_detail()` 里挂上即可 —— 详情本来就在 `enrich()` 里抓
   （devlog/280），所以**新帖自动带视频**，无需额外请求。
3. **存量零请求修复**：`scripts/backfill_xhs_details.py --reparse-only`（**不联网**，只重解析
   已存的 `raw_json`）。本机跑过：
   ```
   3 条视频帖 → 1280x720 31s / 1080x1920 8s / 720x1280 14s，fallback 5~8 条
   ```
4. **前端**（`components/PostVideo.tsx` + 详情抽屉一行接线）：`<video controls preload="metadata"
   poster=封面>`，**不自动播放**；`onError` 沿 fallback 换源，链走完显示「这个视频在当前环境里
   播不了」+「在浏览器打开」（复用 `externalLinkFromHref`，走带白名单的 `open_external`）。
5. **CSP**：`media-src 'self' https://*.xhscdn.com http://*.xhscdn.com`（最小白名单；改壳要重启）。

## 三、判据

- 后端 `tests/test_platform_xiaohongshu.py` **+3**：⑭ 选流序与 fallback 链（真机形状，
  含两处 duration 单位）、⑭′ 图片笔记**不许**多出 `video` 键、⑭″ 有 `video` 段但流为空 → 当图片帖；
- 前端 `PostVideo.test.tsx` **4 条**：渲染（controls/poster/不 autoplay/preload）、换源两次、
  兜底按钮真的调外链桥、无 permalink 时不给死按钮；
- 真机：`--reparse-only` 输出见上；**播放本身需人工看一眼**（我只能验"元素/URL 正确 + CDN 206"）。

## 四、边界与下一步

- 本刀**不做**：下载/缓存、B站、统一 `/video-proxy`、自动播放、其它平台；
- 若某条流在 WebView2 解不了（如 HEVC 档），fallback 链会兜住；若**全部**解不了，
  兜底按钮仍能看 —— 但那说明该走 P3 的本地代理（顺带覆盖微博）。
