## 一、`load_window` 接受场次清单

新参数 `live_ids`：给了就**只算这几场**，且**不做 `[-n:]` 截断** —— 清单本身就是窗口。

```python
if live_ids is not None:
    wanted = {str(x) for x in live_ids}
    entries = [kv for kv in entries if str(kv[0]) in wanted]
    if missing: warnings.append(f"{len(missing)} 场在数据目录里找不到")
...
if live_ids is None and len(entries) > n:   # 只有老路径才截断
    entries = entries[-n:]
```

`_compute` 的缓存键补上清单指纹 `tuple(sorted(live_ids))` —— 否则同一区间不同切片会互相污染。

## 二、`/ranked` 接受 `ids`，并交代"窗口 vs 实际计入"

`GET /fan/{v}/ranked?ids=<逗号分隔 live_id>`；返回新增：

- `requested_sessions`：窗口请求的场次数（滑杆选的）
- `warnings`：`load_window` 跳过了哪些场、为什么

**这是本轮最有价值的一处**：以前"窗口 75 场"而分析只用 72 场，用户完全看不出来。

实测：

| 请求 | sessions | requested | warnings |
|---|---|---|---|
| 传 20 个 id | **18** | 20 | 2 条（`无入场事件，出勤不可测`） |
| 不传 id（旧路径） | 72 | 75 | — |
