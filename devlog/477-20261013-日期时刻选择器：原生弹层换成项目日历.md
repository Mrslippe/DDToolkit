# 477-20261013 日期+时刻选择器：原生弹层换成项目自己的日历（B 方案 · 滚轮列）

> 用户口径：「手动记录直播里打开的下拉日历样式参照 list 视图日期筛选的日历样式改一下，
> 以保证符合项目的整体美术风格」。原生 `<input type="datetime-local">` 的弹层是**浏览器
> 自己画的**（蓝灰、直角、与全站零关系），所以换成自己画的。

## 一、先出图，再动手（4 个候选 → 用户选 B）

时刻那一段没有现成参照（图二那颗日历只选**日期区间**），所以先做了一张**样式对照页**
（`_tmp_datetime_styles.html`，直接照抄仓库 CSS：`.lc-ms-*` + `.drp-*` 逐字复制，
只有「时:分」那一段是候选）让用户挑：A 两个下拉 / **B 滚轮列** / C 保持手打 / D 分钟档位。
用户选了 **B**（与原生那颗弹层的版式最像），并定了两件：**单月面板**、范围**只改手动记录窗
+ 预约窗**（仓里另有大事记/周年卡两处 `type="date"`，本批不动）。

## 二、做了什么

- **日历那一半一个新像素都没写**：`.drp-panel/.drp-head/.drp-nav/.drp-wd/.drp-grid/.drp-day`
  全是 list 视图那颗区间日历的同款类 —— "同一个美术风格"这条需求就是这么满足的；
- 新写的只有**字段**（`.dtp-field`，与 `.lc-ms-input` 同形的一枚按钮，值挂 `data-dtp-value`）
  与**时/分滚轮列**（`.dtp-col`：`scroll-snap` 吸附、中线色带、滚轮/触摸/键盘三条路都通）；
- **值只有一种格式**：`YYYY-MM-DDTHH:mm`（就是原来的 `datetime-local` 值）⇒ 服务端、
  `manualSessionForm.ts`、`buildManualPatch` **一个字都没改**；拆装走 `utils/dateRange.ts`
  的 `splitLocal`/`joinLocal`，由 `check_date_range.mjs` 钉住（+26 条，含往返恒等）；
- 预约窗用同一个控件的 `dateOnly`（只有日历、没有时刻列）；身份钩子 `data-rv-date`
  从那个 input 挪到**字段那一行**上（探针的查询口径不变）。

## 三、两个"只有量出来才知道"的错

1. **滚轮的可滚高度不够**（我自己写的 CSS）：给 `.dtp-col` 多写了一句
   `box-sizing: content-box` ⇒ `height` 变成内容高、可滚高度只剩 `(N−4) × 格`
   （实测 `maxScroll=440=20 格`）⇒ **小时 21/22/23 永远到不了中线**（滚上去弹回 20，
   用户根本选不到）。屏幕上完全看不出。改回 border-box + `--dtp-win: 110px`（5 格）后
   `maxScroll=506=23 格` ✓。判据：`滚到最底必须选到最后一档`。
2. **Esc 的归属**：Radix 把 `keydown` 挂在 `document` 的**捕获段**
   （`react-dismissable-layer`）⇒ 弹层里的 `onKeyDown` 拦不住，"按 Esc 想关日期弹层"
   会变成"整个弹窗没了"。正解是弹窗持有 `picker` 状态 + `DialogContent` 的
   `onEscapeKeyDown` 里 `preventDefault()`：第一下关弹层、第二下才关弹窗。

## 四、判据与反向验证

- 控件 19 条（jsdom）+ 手动记录窗 12 条（设值走**用户那条路**：点字段 → 翻月 → 点日 →
  点时刻列）+ 预约窗 4 条（此前它**一条 vitest 都没有**）；
- 探针 `--archive` 新增 9 条（弹层没被切 / 日历 42 格 / 两列 24·60 档 / 中线色带与选中项
  同一行 / 点日期不许改时刻 / 滚动真改值 / **滚到底 = 最后一档** / Esc 两条）；
- **反向验证**（把两处故意改坏再跑）：点日期丢时刻、摘掉 `onEscapeKeyDown` ⇒ 四条判据
  各自精确报红（其中"滚到底"那条是被真的几何错先咬出来的）。

## 五、顺手记下的三条"读数取错对象"（进 `PROBE.md` §6.28）
