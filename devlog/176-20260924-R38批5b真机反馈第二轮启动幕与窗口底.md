## 一、真凶：两层不透明背景盖住了小窗

**① `index.html` 的静态启动幕 `#boot-splash`**

```html
<div id="boot-splash" style="position:fixed;inset:0;z-index:150;background:#ffa2b4;...">
```

它是"HTML 解析即绘制、消除启动白闪"的刻意设计。而**唯一**摘掉它的地方是
`main.tsx` 里 **`Root` 的 effect**：

```tsx
{isWidgetWindow ? <StatusWidgetWindow /> : <Root />}
```

**小窗跑的是 `StatusWidgetWindow`，根本不走 `Root`** ⇒ 那层 `z-index:150` 的粉幕
**永远摘不掉**，把 200×40 的胶囊整个盖住。

> **一个 bug 解释了全部现象**：用户看到的"一块粉底"就是这层幕，
> 而"没有胶囊"是因为胶囊被它盖在下面 —— 胶囊其实**一直在正常渲染**
> （探针量到 `#root` 子元素 = 1、文本 = '数据服务运行中'）。
> 我第一轮加的"React 渲染抛错"判据其实**没被触发**，这也印证了这一点。

**② `index.html` 内联样式里的 `html{background:#ffa2b4}`**

同一段内联样式还有 `html { background: #ffa2b4 }`（"首绘即主色"）。
主窗口靠**揭幕完成后** `main.tsx` 把它切回透明；**小窗没有揭幕** ⇒ 它一直是粉的。
这层的 `border-radius: var(--radius-window)`（4px）正好解释了截图里那个方块的圆角。

## 二、修了什么

| # | 改动 |
|---|---|
| 1 | 小窗在 `main.tsx` 的**分流处**自己摘 `#boot-splash`（模块作用域，早于 React 一帧）|
| 2 | 分流处给 `<html>` 挂 `data-widget-window="1"` |
| 3 | `layout.css` 加 `html[data-widget-window]` + `body` + `#root` **全透明**（`!important`）|

**为什么不把摘除放进 `StatusWidgetWindow` 的 effect**：那是**静态 HTML 节点**、不等 React，
早一帧摘掉就少一帧"先粉后黑"的闪。
**为什么主窗口不受影响**：React 版 `<Splash>` 在 `Root` 首帧就位、与静态幕像素级一致，
所以只摘小窗的；主窗口仍走原来的"`Root` 挂载后再摘"，无白闪修复原样保留。
