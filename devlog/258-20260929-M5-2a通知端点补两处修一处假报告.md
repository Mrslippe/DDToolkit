# 258-20260929-M5-2a 通知端点补两处、修一处假报告

消息中心 M5 拆成两批（`docs/design/notices/message-hub-execution.md` §M5）：本批是**供数补全**，
下一批 M5-2b 才做前端切换（`TopBar` 的 `useMemo`、小窗广播、`kickPoll`、探针等待口径）。
拆开的理由：只读侦察发现"切过去"不是一次替换 —— 端点缺三类事实，而且有一条**潜伏 bug**
会在切换那一刻变成用户可见的假报告。

## 一、修：报告**只对全量轮**出（R4，潜伏 bug）

`_report_notices` 原先对**任何**"有人看着跑完"的帖子轮都出一条常驻报告，文案却写死
"**全量**帖子抓取完成"。而 `quick`（手动「抓取帖子」，`scheduler.py:2499`）与
`adopt`（收录首屏，:2577）**都**走 `_set_post_last_result`，`witnessed` 在主窗口开着时恒为真
（有 SSE 订阅者）⇒ 只要前端切过来，**每次手动抓帖都会留下一条假报告 + 一个「查看详情」**。

修法是加回前端旧口径（`TopBar` 只对 `full_all` / `full_vtuber` 开报告框）：
`REPORT_KINDS = ("full_all", "full_vtuber")`，其余轮次照旧只走瞬时消息
（`_note_manual_done` → `record_message`）。

⚠️ **为什么 M5-1 没发现**：那个端点当时**没有消费者**，判据只断"有个报告、id 是 `report-<seq>`"。
**"端点没人用"不等于"端点是对的"** —— 这也正是把切换拆成独立一批的价值。

## 二、补：`manual_running` 与通知同一趟给出（R1）

删 `kickPoll` 的前置（`devlog/245` §二①）：顶栏的按钮禁用判定需要一个"现在有没有手动任务"的
信号，否则点完按钮要等下一轮轮询（空闲最长 10s）才禁用，第二次点击会拿到 `skipped`。
新字段与 `fetch-status` 里那个**同源**（`scheduler.manual_task_running()`：**自动档持锁不算忙**），
判据里专门有一条反例盯着这点 —— 用 `account.running || post.running` 当忙，会把自动节拍
期间的按钮全禁掉。

顶层键因此从两个变三个：`{now, notices[], manual_running}`（前端契约用例同步）。

## 三、判据与反向验证

`tests/test_notices.py` **+3**（quick/adopt 不出报告、全量两态都出、`manual_running` 三态与
自动档反例），契约用例的顶层键集合同步为三键。
**反向验证 2/2 全红**：去掉 `REPORT_KINDS` 过滤 ⇒ quick 用例红；顶层不带 `manual_running`
⇒ 契约 + 忙标志两条都红。锚点唯一、字节级还原 + sha256 核对。

## 四、下一批（M5-2b）的侦察结论

十三条卡点（R1–R13）已写进执行方案 §M5，要点：端点**没有"任务已受理"**（本地覆盖不能删）、
`MSG_TTL_MS=4s` < 空闲轮询 `10s`（纯轮询必漏瞬时消息）、「查看详情」要的字段只在
`fetch-status` 里（那条轮询不能删）、`StatusIsland` **只渲染 `text` 不渲染 `value`**（风控倒计时会丢）、
探针靠 dev 注入造条目（改由服务端列表驱动会让 WCAG 判据**静默空转**）。
⇒ M5-2b 的口径定为：**服务端列表 + 本地覆盖（推送 + dev 注入）合并**，SSE 与 `fetch-status` 都保留。
