# 504-20261015 「全是投稿」的录播号被判成没来源 + 投稿时长从来没读到

## 用户报的

「这里显示账号 `94009831` 没找到，但实际上 `space.bilibili.com/94009831` 这个账号**全是投稿**，
检查一下 API 是否出错了」。

## 一、API 没错，是**我们没试投稿那条路**

`_probe/vod_mid_probe.py` 直接打上游：

```
[清单] HTTP 200 / code = 0 / message = OK
[清单] seasons_list: 0 条 []      ← 这个号真的没有合集
[清单] series_list:  0 条 []      ← 也没有系列
[fetch_uploads] p1: 50 条 [('BV1A8pp6hEjU', '【明前奶绿录播】玩点低能小游戏 2026.10.'), …]
[fetch_uploads] p2: 50 条 …
                total = 1093        ← 这号有 1093 条投稿，全是录播
```

投稿流**取得到、而且正是我们要的东西**。问题在自动挑来源那一步：

```python
cands = [s for s in sources if s["kind"] != "uploads" and (s.get("total") or 0) > 0]
return src.pick_source(cands)        # ← 系列/合集为空 ⇒ None ⇒ "没找到可扫的来源"
```

`list_sources` **永远**会在末尾附一条 `uploads`，而这里**恰好把它筛掉了** ——
于是"目录里没有合集"被当成了"这个号没东西可扫"，报错文案还写着"投稿也没取到"
（其实投稿**一次都没试**）。

**修**：系列/合集一个都没有 ⇒ **退回投稿流**（投稿本来就是三条路之一，
`default_fetch_items` 早就分派好了，这里只是把它接上）。
`GET /vod-sources` 的"自动挑中的来源"同步改，免得界面显示的与扫描用的不是一个。

## 二、顺带挖出来的第二处：**投稿的时长从来没读进来**

```python
dur = raw.get("duration")            # 系列/合集是顶层 int
if not isinstance(dur, int): dur = None
```

投稿流的时长在 **`body_json.duration`**（`"5:34:00"`）里，顶层没有 ⇒ 每一条投稿都是
"时长未知"。后果不是报错，而是 `classify` 里两条前处理**静默失效**：

- `<10 分钟直接丢`（切片/动态就是靠它滤掉的）；
- 兜底路径的 `≥30 分钟`（`MIN_FALLBACK_SECONDS`）。

实测（修前）：`94009831` 的 99 条投稿里 **99 条 `duration_seconds is None`**；
修后 **0 条**，且 tier 全是 `replay`。用例
`tests/test_vod_source.py::test_upload_duration_is_read_from_body_json` /
`::test_a_short_upload_is_dropped_now_that_duration_is_known`。

## 三、第三处：投稿只翻 3 页（150 条）

`fetch_uploads(max_pages=3)` 对"全是投稿"的号（1093 条）只覆盖 **14%**，而且**不报错**。
改成 `UPLOAD_MAX_PAGES=24`（1200 条，实测这个号 22 页取完），
取不满时把总条数写进日志。⚠️ 投稿走的是**登录态**接口（`arc/search`，要 WBI 签名），
比匿名的系列接口慢，所以仍要有上限。

## 四、真机效果（真库副本 + 真上游 + 真凭据）

```
两个号整轮扫描: 5.9s
配上 65 漏配 3 候选合计 1868
  号 94009831 : ok=True 来源='投稿'   候选=941 新配=65
  号 2132180406: ok=True 来源='直播回放' 候选=927 新配=0
配上按号分: {'94009831': 65}
```

用户库里当时只剩 68 场没配上（其余已被他写入），**投稿号一口气补上 65 场**——
而系列那条路对这 68 场本来就是 0（它们正是系列覆盖不到的缺口）。
优先级语义也如设计：投稿号先占，系列只补缺。

## 六、教训

- **"没有 A"不等于"没有 B"**：三个来源（系列/合集/投稿）里任何一个为空，
  都只说明**那一个**为空。自动挑来源时"筛掉某一类再挑"这种写法，
  必须回答"剩下的为空时回退到哪"。
- **两条取数路的字段名不同，转成同一种结构的那个函数就是唯一防线**：
  `_to_item` 的注释里**写着**"投稿流是 `body_json.duration`"，而代码没实现它 ——
  注释与实现对不上时，静默失效的是**下游的全部判据**（这里是"<10 分钟丢掉"）。
