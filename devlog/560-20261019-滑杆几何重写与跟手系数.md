# 560-20261019-滑杆几何重写：7px 的错位 + 两个系数

用户三条，前两条是"位置不准"，第三条是"手感"。

## 总根因：几何里写死了偏移，和真实布局对不上

真实布局有三段偏移，我的公式只算了一段：

| 层 | 实际值 |
|---|---|
| `.wb-zoom-scroll` 横向 padding | **7px**（早先为手柄让位加的） |
| `.wb-zoom-inner` border | 1px |
| `.wb-bars` padding | 2px |

而代码里写的是 `+4 / -2`。**那 7px 让 `scrollLeft` 与内容的对应关系整体偏了** ——
左端差一格、右端多出一截，都是它。修法：

1. **删掉滚动容器的横向 padding**（把手在带子内部，不需要让位）；
2. 轨道 `box-sizing: border-box`，宽度 = `total*step + 2*PAD`；
3. JS 里只留一个 `PAD = 2`，与 `.wb-bars` 的 padding 严格一致；
4. 选中区改成 `left = PAD + start*step`、`width = size*step` —— 两端与内距对称。

## ① 两端贴不准 / 超出

除了上面的 7px，还有**取整不对称**：起点 `round`、终点 `floor`，且 `clamp` 的
`hi` 再与 `total - size` 取小；`step` 用 `stepRef` 读最新值，避免闭包拿旧值。

## ② 拖缩放条：鼠标比带子快

**系数算错了。** 带子的行程是 `trackW - bandW`，对应可滚范围 `innerW - clientW`；
而 `bandW = trackW * clientW / innerW` ⇒ 化简后系数**正好是 `innerW / trackW`**。

早先用的是 `range / trackW`，小了一个数量级 ⇒ 带子跟不上鼠标。

## ③ 缩放是"段落式"

因为 `step` 用了 `Math.round((BAR+GAP) * scale)`。**取整会让每跨一场跳一下** ——
拖一段没反应、过一档猛跳。

改成**浮点 `step`**（CSS 接受小数像素），缩放就连续了。

## 说明

三条里 ① 能在静态截图看到对齐（已裁图确认左端齐平），②③ 是手感，只能真机验：
拖缩放条是否跟手、两端缩放是否连续、窗口能否贴到最右。
