# 237-20260927-身份级限速与四类响应（+影子比对）

第 4 阶段 ⑤：调研 `docs/platforms-xhs-douyin-research.md` §5.3.1 / §3.4.1 点名的那三件事，
一次做完 —— **四类响应**、**(身份, 端点) 令牌桶 + 端点熔断**、**签名影子比对**。
它们在调研里是"接平台时必须一起设计"的那一批，而小红书已经接完了，所以现在落地。

## 一、为什么现有机制不够

现有风控全是**按平台**的：`rate_limit.py` 的冷却窗口键是 `platform`，风控标志是
`fetcher.py` 里按平台置位的 ContextVar。B 站够用（一个号 = 一份身份），但：

| 机制 | 缺了它会怎样 |
|---|---|
| **四类响应** | "帖子被删"与"身份被风控"混成一个 ⇒ **遍历 id 的调用方白白冷却身份**（抖音对不存在的帖子返回 200 + `aweme_detail: null`，恰好长得像风控）；反过来 5xx 被记成业务失败 ⇒ "上游挂了"看起来像"这个帖子有问题" |
| **身份级令牌桶** | 粒度是平台 ⇒ 换个目标就满速重来，实际速率 = 目标数 × 单价，节流等于没有 |
| **端点级熔断** | 一个坏目标就能把整个端点关掉，别的目标跟着停 |

## 二、刻意的两个口径决定（写在模块头，别当照搬）

1. **身份 = 我们自己的会话**（`platform + cookie 指纹`），**不是被查的 uid**。
   调研的"身份四要素"（cookie jar / 指纹 / 代理 / 历史）说的是**采集方**；
   本项目一个平台只有一份 cookie ⇒ 现实身份数 = 1。`identity_key()` 把 cookie 哈希进去
   只是为了"将来支持用户提供自己的账号"时不用改结构（且**不落明文 cookie**）。
2. **熔断的第三个条件落到"不同目标"上**（≥3 个不同目标都被风控）。
   DTK v5 原文是"≥3 个不同身份"（它是多账号采集器）；照抄会让这条**永远不触发**（等于没有）。
   改成"不同目标"后，它照样是"端点坏了"与"某个目标坏了"的分界线
   （例：签名改版后**每个**目标都吃 403）。⚠️ 这是**适配**，不是照搬。

## 三、判据（`tests/test_identity_limit.py` 24 条 + 适配器净增 3 条 = 27 条）

| 判据 | 反向验证（都实测红） |
|---|---|
| 业务失败**不影响**身份健康度（连 `consecutive_fails` 都不动） | 把 `affects_health` 改 True ⇒ 红 |
| 业务失败/网络错**退还令牌** | 把 `refund_token` 改 False ⇒ 红 |
| 熔断三条件**同时**成立（每条单独验一次"不熔断"） | 删掉第三个条件 ⇒ 红 |
| 被节流时**一个字节都不发** + `identity_throttled` | 忽略 `_admit` 的结论 ⇒ 红 |
| 节流**不算上游故障**（`stop_reason="throttled"`） | 去掉那个分支 ⇒ 红 |
| 影子比对"比不出来"**绝不算失败** | 让 inconclusive 返回 mismatch ⇒ 红 |

另外几条容易被忽略的：`classify` **不猜 body 语义**（200 一律先算 ok，抖音那个坑由调用方
按结构给 `business_error`）；未知诊断 kind 兜底落 `risk_control`（宁可多冷却，也不让真风控
从统计里消失）；令牌桶**按身份**（换 cookie 才有新额度，换目标没有）；
影子比对的主侧**复用真正发出去的那组头**（抽样只多花一次签名）。

## 四、顺手修掉的一个旧口径

`classify_http` 以前把 **5xx 归成 `business_error`**（"上游挂了"被算成"这个帖子有问题"）。
接四类时这条立刻暴露 ⇒ 新增诊断类 `server_error` → 四类里的 `network_error`。
旧判据 `assert classify_http(500) == "business_error"` 随之改成 `server_error`
（那条断言当初是照实现写的，不是照语义）。

## 五、接线与隔离

- 小红书适配器：`_identity()` / `_admit()` / `_observe()` / `_outcome_of()` 四个小函数，
  两个请求方法各问一次、各记一次；台账可注入（`ledger=`），测试用自己的可控时钟。
- 调度循环：`data is None` 时先问 `identity_limit.throttled(pf)` ⇒ `stop_reason="throttled"`。
- **测试隔离**：`tests/conftest.py` 新增 autouse fixture 清空进程内台账 —— 不隔离的话
  "上一个用例花掉了额度"会让下一个用例静默少发一次请求（表现是在别处炸，极绕）。
- 影子比对接在 `XhsSigner.headers()`：每 600s 抽样一次，`last_comparison` 留痕；
  **判定不一致只告警，照常返回头**。
