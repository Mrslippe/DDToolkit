# 022-20260905-v0.5.1-删除检测（墓碑机制）

## 概述

TODO 路线图的「灵魂功能」落地：动态从平台消失后，库不再是静默滞留，
而是能被**证明**——区分「还在只是没翻到」和「已被删除」，并记录发现时刻。
争议取证时证据链不再断在最后一环。

## 问题与设计

**问题**：抓取是增量模式（`stop_on_existing=True`，遇第一条已入库帖即停，
`/vtuber/update-posts` 每 5 分钟跑的就是它）。直接把「库中未归档 ∖ 本轮所见」
当缺席集合会出大事：**比停止帖更早的帖子本轮根本没被翻页扫描**，
一律判成已删 = 全库误杀。

**定案「已验证窗口」**（TODO 实现注意之外的细化）：
- 窗口下界：有增量停止帖 → 用该帖 `published_at`（停止即覆盖边界）；
  自然走到流尾（has_more=false / 空页 / 归档边界）→ 用本轮所见最旧帖的
  `published_at`（整段流被连续翻过）。窗口无上界（流首即新帖位置，
  比本轮最新所见还新的缺席 = 已从流中消失）。
- **窗口外缺席永不判定**；`page_limit` / 网络失败 / 风控中断 → 窗口不可信，
  本轮跳过判定（仅推进 last_seen 刷新与扫描标记）。

**两击规则**：缺席帖 `last_seen_at` 严格早于上一轮扫描完成时间
（`accounts.posts_last_scan_at`）才算连续第二次缺席 → 写 `deleted_detected_at`。
单次缺席（分页边界/接口抖动/更新期间发布）→ 保持现状；下一轮被见即「愈合」。

## 实现

**数据层（迁移 `e002_post_tombstone`，MIGRATION_HEAD → e002）**：
- `posts.last_seen_at` / `posts.deleted_detected_at` + 索引
  `ix_posts_deleted_detected`；
- `accounts.posts_last_scan_at`（两击比较基准）；
- 回填：未归档帖 `last_seen_at = 迁移时刻`（已入库旧帖即时获得基线，
  真正已删的旧帖在迁移后两轮缺席中被标记——两击成立）。

**判定服务 `app/services/tombstone.py`**（新模块，纯函数式，
不依赖 scheduler 避免循环导入）：`apply_tombstone_scan` 单账号判定 +
last_seen 批量刷新 + 扫描标记推进，一次事务提交。

**接入点 `scheduler.py`**（各抓取流的共同必经点）：
- `PostFetchResult` 新增 `seen_pids` / `stop_existing_pid` / `natural_end`
  （双流 B 站核心按 `video_natural ∧ dyn_natural` 合成，单流直接置位）；
- 三个循环（B 站视频 / B 站动态 / 微博单流）记录所见与停止原因；
- `_fetch_posts_for_account` 结尾统一调用 `_run_tombstone_scan`
  （全量 / 按名 / 增量 / 快速单账号全部覆盖；快速单账号改走同一漏斗）；
- 增量轮 `exclude_types={"video"}`（视频流未扫描）；
- 判定失败只记日志 `db.rollback()`，不影响已完成的抓取结果。

**读取侧**：`PostRepo.paginated` 新增 `is_deleted` 过滤；`stats` 新增
`deleted` 计数；`PostOut`/`PostStats` 暴露新字段（naive-UTC 序列化补时区）。

**前端**：
- 列表页 chips-tools 新增「已删 N」独立 toggle（Ghost 图标，激活走
  float-pill.on 强调色；计数来自 stats.deleted）；
- 帖子卡片墓碑角标（右上「已删」+ 封面灰度弱化，TODO「灰化可选」→ 已做）；
- 详情抽屉：元信息行「已删除」flag + 墓碑时间线三行
  （发布时间 / 最后在线 / 删除发现）。

## 已知限制（记录不掩盖）

- 顶部删除（帖子被删后一直没有新帖顶上来）依赖「流首」论证，属于
  窗口无上界的设计假设；个人库量级 + 每 5 分钟增量轮，实际影响极小；
- 增量轮（快速单账号抓取带 page_limit 参数）不判定——检测靠
  定时更新轮（-1/-1），与 TODO「挂在 update-posts 尾部」一致。
