# 528-20261018-工作台截图暴露的三个问题

用户给了一张**实际应用**的截图，里面三处不对。逐条修完。

## ① `Failed to fetch` —— 后端把预估打到了已 502 的上游

`session_preview` 里写的是 `_resolve(vtuber)`，**少传 `db`**。不传时 `get_vtuber` 只能查
硬编码的 `LEGACY_VTUBERS`；一旦库里那条账号的 mid 与常量不一致，本地枚举就返回空，
于是落到**上游兜底**（`_resolve_sessions` 的第二条路，实测今天 502）⇒ 请求挂到超时
⇒ 浏览器只报 `Failed to fetch`（fetch 层的 TypeError，连 HTTP 状态都拿不到）。

修法：`_resolve(vtuber, db)`。这一行与 `profile` / `activity` 对齐 —— 它们本来就是对的。

## ② ★「待采 0 / 已全部采集」与滑杆的「待采 75」自相矛盾

`const toCollect = preview?.to_collect ?? 0` —— **把"还不知道"当成了"零"**。
`preview` 没回来（或取失败）时，按钮就显示「已全部采集」，而滑杆那边明明是 75 场待采。

修法：`toCollect` 允许为 `null`，界面区分三态 ——
`预估中…`（未知）/ `采集 N 场`（有待采）/ `已全部采集`（真的是 0）。
读数行的「待采」在未知时显示 `—` 而不是 `0`。

## ③ 错误文案对用户零信息量

`Failed to fetch` 直接摊在界面上。加了 `friendly()`：网络级错误翻成
「取不到区间预估：后端没有响应（通常是上游枚举超时）。可以稍后重试；已采过的数据仍能「查看名单」。」
