# 262-20260929-L4 历史行合并与强制回源校验

轻资产模块最后一批（执行方案 §L4，只做前两项）。两项都是**给人用的工具**，不是新机制：
`local_assets` 与账本的结构不动，多的是"把存量数据收拾干净"和"给取舍留个口子"。

## 一、历史行按 sha256 / 稳定键合并（`merge_duplicate_versions`）

**起因是真实形态**：R47 的账本按**完整 URL** 记账，而微博每轮抓取换签名 ⇒ 同一张脸会各留一行；
R47 之前本地文件名还是**固定**的，同一张图会先落 `{platform}_{uid}.jpg`、之后又落带摘要的
⇒ **两个文件名、同一张脸**（实测两个文件 sha256 逐字节相同，样本在 `tests/fixtures/light_assets.json`）。
选择器里因此可能出现两张一模一样的选项。

判同走**两条路**（命中任一即可）：① 稳定键（`assets.key_of`）；② 内容摘要
（`local_assets.sha256`，索引里没有就现读盘算）。三条纪律：
- **只并"行"，绝不删文件**（S-1）：被并掉的行指向的图就是同一张，文件留在盘上；
- **用户选中的那行必须活下来**（否则"当前用的是哪张"这个标记会丢）；
- **默认 dry-run**；幂等（并完再跑 `groups=0`）。
- 合并保留**时间窗的并集**（最早的 first_seen + 最近的 last_seen）。

工具：`scripts/merge_avatar_versions.py`（`--vtuber` 可只处理一个 V）。
**真机实测：8 个 V、0 组重复** —— 说明 L1 的"按稳定键归并"已经止住了新增，
这个脚本是给**老数据**用的修复工具（本机恰好没有需要修的）。

## 二、`--verify` 强制回源校验（`assets.verify`）

这是规格 §2.1 那条取舍的**逃生口**：`get()` 命中稳定键就不回源（"每轮抓取零图片请求"正是这么来的），
代价是"平台换了图却没换文件名时我们会一直用旧图"。三条纪律：
- **≥7 天节流**（以副本 `created_at` 为基准）：复核是额外请求，天天跑等于把收益还回去；
  要立刻全量就显式 `--min-age-days 0`；
- **默认只报告**（`--apply` 才用新字节覆盖 + 更新摘要）：图床抽风返回一张错误页时，
  默认行为不该是"把好副本换掉"；
- **`unreachable` ≠ `mismatch`**：图床挂了不等于我们的副本坏了。

工具：`scripts/verify_assets.py`。**真机实测：5 份副本回源核对，5/5 一致** ⇒
"URL 没换名就没换图"这条假设在这台机器的真实数据上**成立**（这是对取舍本身的抽样验证）。

## 三、判据与反向验证

- `tests/test_vtuber_avatars.py` +4（签名对并一行且保留选中那行 / 同内容两个文件名也算同一张 /
  时间窗并集 + 幂等 / **不同的脸不许被并掉**）；`tests/test_assets.py` +4（新的跳过老的要核对 /
  不一致只报告、`apply` 才修 / 取不到只记账 / `min_age_days=0` 立刻全量）；
- **反向验证 7/7 全红**（只按完整 URL 判同 / 不看内容摘要 / dry-run 也真删 / 保留行不看用户选择 /
  不看新旧全核对 / `apply=False` 也改文件 / 取不到算成不一致），锚点唯一、字节级还原 + sha256 核对。

## 四、没做的那一项

**其他 kind（企划徽标 / 平台药丸艺术）不做** —— 目前**没有消费者**；而加一个 kind 的成本
已经被 `local_assets.kind` 压得很低（表结构不用动），等真有需求再按同一个模块加，不必现在猜。
