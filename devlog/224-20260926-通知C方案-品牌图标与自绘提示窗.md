# 224-20260926-通知 C 方案：品牌图标（气泡）+ 自绘提示窗（配色）

> 用户：「弹窗颜色可以修改吗」→ 讲清"系统气泡改不了色"之后给了三条路线，
> 用户选 **C（A + B 并存）**：气泡负责留档，另加一个自己能配色的自绘窗。

---

## 一、先回答"能不能改颜色"

**不能。** 通知区域气泡是 Windows 自己渲染的，配色来自系统主题（浅/深色、对比度），
应用侧只有 `dwInfoFlags`（图标语气）、`hBalloonIcon`（图标）、声音、文案这几个抓手。
想要颜色就只有换实现 —— 于是有了本轮的 C 方案。

## 二、做了什么

### 2.1 A 部分：气泡换自家图标

- `scripts/build_backend.py` 增加 `--add-data .../icons/icon.ico;.`，
  图标随后端一起分发（实测落在 `<backend>/_internal/icon.ico`，与 `alembic/` 同级）；
- `notifier.brand_icon_path()` 按 **打包态 `_MEIPASS` → exe 同级 → 仓库回退** 三级找图标；
- `_Balloon` 用 `LoadImageW(..., 32, 32, LR_LOADFROMFILE)` 加载，气泡图标与托盘图标都换成它：
  `dwInfoFlags = NIIF_USER | NIIF_LARGE_ICON` + `hBalloonIcon`；加载失败自动退回系统信息图标。

### 2.2 B 部分：自绘提示窗（`app/services/desktop_popup.py`）

品牌配色的无边框置顶卡片，与气泡**同时**展示：

| 项 | 取值 |
|---|---|
| 底色 | `#ffa2b4`（`--c-primary`，与顶栏同源）；悬停提亮为 `#ffb3c2` |
| 左侧强调条 | `#fb77a1`（`--c-primary-deep`） |
| 文字 | 白色标题（对底色 4.72:1，达 AA）+ 略带底色正文 + 白色提示行 |
| 圆角 | 10px（`SetWindowRgn` + `CreateRoundRectRgn`，四角真透） |
| 位置 | **鼠标所在那块屏**的工作区右下角（多显示器不再错过） |
| 交互 | 整张卡片可点（悬停变亮 + 手型光标），点完立刻收起 |
| 时长 | `NOTIFY_POPUP_SECONDS`（默认 8s），到点自动收 |
| 行为 | `WS_EX_NOACTIVATE` 不抢焦点、`WS_EX_TOOLWINDOW` 不进任务栏 |
| 提示行 | 开播→「点击进入直播间 ›」、动态→「点击查看这条内容 ›」 |

### 2.3 双通道投递

`notifier._deliver(item, balloon, popup)` 同时送两条，**任一条成功即算送达**；
`last_delivery()` 现在分别记 `balloon` / `popup` 两个布尔 —— 排查时能一眼看出
"是气泡被系统吞了，还是两条都没出去"。新增开关 `DDTOOLKIT_NOTIFY_POPUP=0` 可只留气泡。

## 三、坑（都记在这里，免得下次再踩）

1. **`FillRect` 在 user32，不在 gdi32**（`DrawTextW` 也是）。第一版把绑定挂在 gdi32，
   `AttributeError: function 'FillRect' not found` —— 与 devlog/220 那条
   "`GetModuleHandleW` 在 kernel32" 是同一类想当然。
2. **`CreateFontW` 是 13 个整型 + 1 个字符串**（高/宽/字距/角度/字重/斜体/下划线/删除线/
   字符集/输出精度/裁剪精度/质量/字族 + 字体名）。argtypes 少写一个就
   `TypeError: this function takes 13 arguments (14 given)`。
3. **两条通道必须同线程**：窗口消息按线程排队，所以自绘窗由 notifier 的投递线程创建，
   直接复用它已有的 `pump()`；否则卡片画不出来、也点不动。
4. **`WS_EX_NOACTIVATE` 不是可选项**：否则弹一下就把用户正在打字的应用打断。
5. 另外把上一轮排除掉的"AUMID 未注册导致静默丢弃"记在这条链上：那条假设已被 G/H/I 实验否掉
   （devlog/223），**气泡看不到 ≠ 应用身份有问题**。

## 五、用户实测反馈两轮（同批次内改掉）

### 5.1 「图标分辨率有点低」

**根因**：我拿**一个尺寸**（32×32）同时当托盘图标和气泡图标。托盘图标由 shell 按
实际尺寸渲染（100% 是 16px、150% 是 24px），32 缩到 16 就是糊的来源。

**改法**：按**用途**分别取档，并且跟着 DPI 走：

| 用途 | 请求尺寸（100% / 150% / 200%） | 说明 |
|---|---|---|
| 托盘小图标 | 16 / 24 / 32 | `icon.ico` 里正好都有对应档，不需要缩放 |
| 气泡大图标 | 32 / 48 / 64 | `NIIF_LARGE_ICON` 走这一档 |
| 卡片内图标 | 30 / 45 / 60 | 左上角与标题同排，一眼认出是谁在提醒 |

`desktop_popup.load_icon_file(path, size)` 统一按尺寸 `LoadImageW`（`IMAGE_ICON` +
`LR_LOADFROMFILE`），`icon.ico` 的 11 档（16…256）让每次请求都能命中原生尺寸。

### 5.2 「弹窗颜色改成粉色半透」

给自绘窗加 `WS_EX_LAYERED` + `SetLayeredWindowAttributes(alpha)`，alpha 由
`NOTIFY_POPUP_ALPHA` 控制（默认 **232 ≈ 91%**，即"粉色半透"：透出桌面又不影响读字，
代码里有 80 的下限保护）。同时把**自家图标画进卡片**左上角（`DrawIconEx`，尺寸随 DPI），
标题与图标垂直居中对齐。

> 半透与圆角同时生效：`SetWindowRgn` 负责四角，`LWA_ALPHA` 负责整窗的透。
> 验证方式：`GetLayeredWindowAttributes()` 读回 alpha 断言（`c_byte` 有符号，
> 232 会读成 -24 —— 按无符号比较才是对的）。

### 5.3 「图标修改为主播的头像」

气泡与卡片上的图标都换成**主播本人的头像**（App 图标退居兜底）：

| 环节 | 做法 |
|---|---|
| 取文件 | `scheduler._account_avatar_file(acc)`：把 `accounts.avatar_path`（相对数据目录，如 `static/avatars/bilibili_1265680561.jpg`）还原成绝对路径并确认存在；缺失返回 None |
| 传给通知 | `Notification.icon_path`（`compose_live_start` / `compose_new_posts` 都新增该参数）；开播用**该账号**头像，动态用**发帖账号**头像 |
| 转图标 | 头像是 jpg/png 这类位图，`LoadImageW` 只认 `.ico/.bmp` → 走 **GDI+**：读原图 → 建 32bppARGB 目标位图（`GdipCreateHICONFromBitmap` 只吃这个格式）→ 高质量插值缩放 → `HICON` |
| 用图标 | 气泡 `hBalloonIcon`（`NIIF_USER`）与卡片左上角（`DrawIconEx`）共用同一个 HICON；尺寸按 DPI（32/48/64） |
| 圆角 | 卡片上的头像用"与底色同色的粗圆角描边"盖掉四个直角（比 GDI+ 裁剪省事），和卡片 10px 圆角同一套语言 |
| 兜底 | 文件缺失 / 格式不支持（GDI+ 不认 WebP）/ GDI+ 启动失败 → **退回 App 图标**，通知照常弹；`last_delivery().detail` 会记一句"头像不可用（xxx.jpg），退回 App 图标" |

**HICON 的生命周期**（容易踩）：shell 在气泡显示期间还会用它，提前 `DestroyIcon`
会把图标变成白块。做法是保留**最近两组**图标，第三组到来时再释放最早那组，
工作线程退出时全部释放。

> 验证：拉一张**真实头像**（B 站直播接口的 `face` 字段，无需登录）→ 本地渲染成 PNG 检查
> （`PrintWindow`，只截我们自己的窗口），确认头像清晰、四角圆润；`image_file_to_hicon`
> 另有单测（真图能转、缺文件返回 0）。

### 5.4 「暂时关闭 win 弹窗，只发单独弹窗」

两条通道各自一个开关，互不影响：

| 开关 | 关掉谁 | 留下的 |
|---|---|---|
| `DDTOOLKIT_NOTIFY_BALLOON=0` | 系统通知区域气泡（**不建气泡后端、不加托盘图标**） | 只发自绘卡片 |
| `DDTOOLKIT_NOTIFY_POPUP=0` | 自绘卡片 | 只发系统气泡 |
| `DDTOOLKIT_NOTIFY_ENABLED=0` | 两个都关 | 只在日志里留一行 |

`_make_balloon()` 在第一行就判这个开关（连窗口都不建），`show_now()` 也会跳过气泡那一段 ——
所以"关掉气泡"是真的什么都不做，不是"发了但不显示"。

> 用户的口径是"**暂时**关掉"，所以默认值仍是两条都发；他应用的 `.env` 里加了一行
> `DDTOOLKIT_NOTIFY_BALLOON=0`，想恢复时改成 `1`（或删掉这行）再重启即可。
> 实测判据：`{'ok': True, 'balloon': False, 'popup': True, 'icon': True}`。

### 5.5 「通知字号加大」

**系统气泡的字号改不了**（和颜色一样，由 Windows 画）；能改的只有自绘卡片。做法不是
单独调字号，而是加一个**整体缩放** `NOTIFY_POPUP_SCALE`（默认 **1.15**，可调到 2.0，
下限夹在 0.8）—— 字号/图标/宽度/内距/圆角**一起**按比例放大：

| | 1.0（旧） | 1.15（新默认） | 1.5（可调） |
|---|---|---|---|
| 标题字号 | 15 | **17** | 22 |
| 正文字号 | 12 | **14** | 18 |
| 卡片宽度 | 380 | **437** | 570 |
| 头像 | 30 | 35 | 45 |

只放大字号会让文字挤在一起、正文折行变多，整体缩放才保持版式。实测渲染：
正文在 437px 宽下正常折行成两行，标题白字、卡片圆角与半透都不受影响。
