## 一、用户口径拆成三步

> 「先按平台分类取抓取任务名单，然后并行根据名单进行抓取，一轮抓取时间如果小于一分钟
> 则休息至一分钟，如果大于则休息时间保证不触及上限」

| 口径 | 改前 | 改后 |
|---|---|---|
| ① 按平台分类取名单 | ✅ 已有（`groups = {platform: [账号…]}`） | 不变 |
| ② **并行**按名单抓 | 平台**之间**并行，平台**内**每轮只抓 1 个（逐个 + 每账号抓完睡 3~5s） | `per_platform=DYNAMICS_CONCURRENCY`（默认 **3**）：同一平台每轮并发抓 3 个；平台内请求间隔改由**平台级起跑闸门**保证（见 §三） |
| ③ 一轮 <1min → 休息至 1min | ❌ 旧写法是"轮**结束**后再等 `max(30s, 预算) ± 15s`" —— 实际周期 47~75s 且随抖动漂 | ✅ 新增 `DYNAMICS_MIN_CYCLE_SECONDS=60`，到期时刻 = `max(轮开始 + 60s, now + 预算等待)` |
| ④ 一轮 >1min → 按预算休息不触上限 | ✅ 已有（`_PlatformBudget` 滑窗 12 req/min） | 不变（下限自动失效，回到预算等待） |

## 二、真机实测（两轮都打真实 B 站，7 个主账号，库副本不碰真库）

| | 旧（`--old`：单并发 + 无下限） | R6（并发 3 + 60s 下限） |
|---|---|---|
| 一轮墙钟 | **30.2s** | **25.7s** |
| 实际请求数 | `{bilibili: 7}` | `{bilibili: 7}` |
| 风控/异常 | 0 | 0 |
| 下一轮（旧口径：轮结束算） | +27s | +21s |
| 下一轮（R6 口径：轮开始算） | — | **+60s** |
| **实际周期** | ≈ 47~75s（抖动漂） | **≈ 60s（稳定）** |

两组请求数完全一样（7 个账号各 1 次 feed 页，无新帖详情）——
**速率没变（7 req/min ≤ 预算 12），变的是节奏**：一轮更短（并发省下的抓取耗时），
周期从"抖动 47~75s"变成"稳定 60s"，也就是用户要的"抓完休息到一分钟"。

> ⚠️ 一个必须说清的事实：**并发不是这轮提速的主力** —— 平台内的**请求起跑间隔**
> （3~5s，沿用旧值）才是瓶颈，7 个账号无论怎么并发都得铺开 ~26s。
> 也就是说"并行"在这里的作用是**让抓取耗时与间隔重叠**，而不是把 26s 压成 5s。
> 想真正压成"齐射"，把 `STARTUP_DYNAMICS_INTERVAL_MIN/MAX` 调小即可 ——
> 但那是拿风控面换墙钟，**默认不动**（见 §三）。

## 三、实现要点

| 位置 | 改动 |
|---|---|
| `_run_platform_rounds(..., per_platform=1)` | 每轮每平台取 N 个一起 `gather`。**默认 1 = 逐字节等价旧行为** —— 账号流仍走这条，只有动态流传 3 |
| `_PlatformPacer(gap_min, gap_max)`（新） | 平台级**请求起跑闸门**：同平台两次请求起跑至少隔 `random.uniform(3,5)` 秒（每平台一把 `asyncio.Lock` + 上次起跑时刻）。并发下"每账号抓完再睡"不再能保证间隔（3 个账号会同时发出去），所以间隔上移到平台级；不同平台互不阻塞 |
| `run_latest_dynamics_sweep()` | 传 `per_platform=settings.DYNAMICS_CONCURRENCY`；并发模式（>1）下用 pacer 取代"抓完再睡"（并发时那段 sleep 只是 3 个 worker 一起白等） |
| `_dynamics_next_due(db, *, since=None)` | `since` = 本轮**开始**时刻；给了它就套周期下限。`_dynamics_due_or_retry` 同步透传（含失败兜底路径） |
| `_tier_loop` | 轮前记 `round_start`，轮末排期时传给 `_dynamics_due_or_retry`；异常路径把 `round_start` 置空（不给下限，避免异常后把下一轮推得更远） |
| `config.py` | `DYNAMICS_CONCURRENCY = 3`、`DYNAMICS_MIN_CYCLE_SECONDS = 60.0` |

**风控面**：请求数与旧版完全相同（7/轮），且平台内起跑间隔不变；风控冷却
（`RATE_LIMIT_COOLDOWN=600s`，按平台）与手动让位逻辑一行未动。

## 五、留给用户的调参口（都在 `config.py`，改完重启即可）

| 想要的效果 | 怎么调 |
|---|---|
| 一轮更快（更"齐射"） | 调小 `STARTUP_DYNAMICS_INTERVAL_MIN/MAX`（3/5 → 1/2）；**代价是风控面变大** |
| 一轮更慢/更保守 | `DYNAMICS_CONCURRENCY = 1`（回到逐个抓）或调大上面两个间隔 |
| 更新更频繁 | `DYNAMICS_BUDGET_RPM` 提高（12 → 20）或 `DYNAMICS_MIN_CYCLE_SECONDS` 调小；**两者都会更接近平台上限** |
| 完全回到旧节奏 | `DYNAMICS_CONCURRENCY=1` + `DYNAMICS_MIN_CYCLE_SECONDS=0`（= `--old` 那组实测） |
