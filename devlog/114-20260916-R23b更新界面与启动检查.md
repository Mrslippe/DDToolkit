## 一、关于页新增「应用更新」

`AppSettingsDialog` 关于页底部：

| 状态 | 显示 |
|---|---|
| 浏览器/探针 | 只显示「当前版本 x.y.z · **更新只在桌面端可用**」——**没有按钮**（那边根本没有这回事） |
| 空闲 | 「检查更新」+「打开发布页」 |
| 检查中 | 按钮变「检查中…」并禁用 |
| 已是最新 | 「已是最新版本」 |
| 发现新版本 | `发现新版本 vX.Y.Z（日期）` + **更新说明**（限高 160px 可滚，取自 `latest.json` 的 notes）+ 「下载并重启安装」（下载中显示百分比） |
| **便携版** | 同上但按钮是「**打开发布页下载**」，并写明"便携版不自动覆盖：请下载新版压缩包解压替换整个目录" |
| 失败 | **红字**：`检查更新失败：<原因>（连不上 github.com 时可以直接去发布页下载）` |

**待安装的更新留在模块作用域**（`shellBridge` 的 `pendingUpdate` / `pendingInfo`）：启动时静默检查发现的
版本，用户过一会儿才点安装时**不必重查**，也不会出现"两次检查结果不一致"。关于页打开时若已有待安装项，
直接显示（`pendingUpdateInfo()`，**不发网络请求**）。

## 二、启动静默检查（`hooks/useUpdateCheck.ts`）

挂在 `TopBar`，等第一轮 `fetch-status` 回来后再计时（保证后端就绪、且 `pill-message` 监听已挂上），
**延迟 15 秒**才查（启动那几秒留给后端就绪与首屏）。四条克制：

- **失败只写 `console.warn`**：国内连不上 github 是常态，为它弹提示只会让人烦；
  只有用户**主动**点「检查更新」时才把原因显示出来；
- 发现新版本时**只发一条状态岛瞬时消息**（复用现成通道，不新造通知类型）；
- **不自动下载/安装** —— 更新是"用户决定"的事；
- 便携版**照常查**（知道有新版本有用），只是不给自我更新入口。

## 三、打开发布页：用 Windows API，不引新依赖

`tauri-plugin-shell` 的 Rust `open()` **已标记废弃**（官方让换 `tauri-plugin-opener`），而为了
"打开一个固定网址"再引一个插件不值得 ⇒ 新增命令 `open_release_page()` 直接调 `ShellExecuteW`
（`windows-sys` 加 `Win32_UI_Shell` 特性）。URL 是**常量**（比"前端随便传 URL"安全），
返回值 ≤32 按 Win32 约定判为失败。

## 四、tsc 抓到的一个真 UI bug

我最初把"正在安装"塞进了 `updateState`（`'installing'`）。`tsc` 的类型收窄立刻报
`'"available"' 与 '"installing"' 没有重叠` —— 一查才发现：切到 `installing` 后
**"发现新版本"那个分支就不再渲染，按钮和进度条会当场消失**。
改成**独立标记** `installing`，状态机保持 `idle/checking/latest/available/error`。
（这类"状态机塞了不该塞的状态"的 bug，界面上很难第一眼看出来。）
