# 350-20261005 「滑出正常，但留下的空白不被自动顶上去」—— 补位量错了两次

> 用户 2026-10-05（附截图：面板「通知（2）／最近（2）」下面一条通知悬在底部，上方一大片空白）：
> 「点击已读之后虽然向左滑出是正常的，但留下的空白不会被自动顶上去，问题出在哪」。

先复现再动手：给探针 `--notice-lab` 加了**几何采样**（点一条已读之后，按分组读每条的
位置、内联位移、以及列表子节点的 `offsetTop`），一句话结论 —— **布局早就对了，
是"补位"这个动作把位置量错了两回**。

## 一、第一处：位移跨帧残留（349 那版的写法）

349 用的是经典的"下一帧再撤"（`requestAnimationFrame`）FLIP：挂反向位移 → 下一帧撤。
实测采样（`+680ms`）：

```
msg-…|flow|tf=translateY(69.75px)|fy=69.75|h=51|rel=76      ← 布局位置其实早已回到 rel=6
残留位移=[… 7 条 …]   空位=['rel=76/h=51', …]
```

**位移与 `transition:none` 一起永久留在了 DOM 上**。成因：点已读会在**几毫秒内连着两次提交**
（本地状态一拍、`ack` 回来的那一拍），第二拍触发 effect 的 cleanup ⇒ 那个 rAF 被
`cancelAnimationFrame` 掉 ⇒ 没人撤这份位移。那一行就停在旧位置，腾出的空位自然没人顶。
同一份采样还显示位移在**正负之间翻转**（`+80ms` 是 `+139.5px`、`+680ms` 变成 `-139.5px`）——
因为"量位置"会撞上这份位移，得靠 `data-flip-y` 记账去减，记账一旦对不上就越补越偏。

修法：**同步 FLIP** —— 挂位移 → **强制一次样式计算**（读 `offsetHeight`，这是过渡的起点）
→ 当场恢复过渡并撤掉位移。不留任何跨帧状态：既不会被后来的提交取消，也不会污染任何一次测量。
（留了源码级判据钉住这三步的顺序，并禁止这段里出现帧回调。）

## 二、第二处（**真根因**）：`getBoundingClientRect()` 量到的是"正在动的样子"

同步化之后位移不再残留（`残留位移=[]`），但空位还在。采样给出的矛盾数据是关键：

```
列表: padding=6px/6px pos=relative h=114 kids=[li…|offTop=6|offH=51 ; li…|offTop=57|offH=52]
采样: msg-…@76  lab-pushed-message-demo@127      ← 布局 6/57，视觉 76/127
```

差的正好是退场那条的高度（70px）—— **布局是对的，视觉位置是过渡的中间值**。
而每次重渲染（秒表每拍、轮询回来）都会拍一次快照，`getBoundingClientRect()` 把
"它还在下面 70px"记成布局 ⇒ 下一拍再补 70px ⇒ **过渡反复重启，那一条永远到不了位**。
（这也是"hover 时上下跳"的另一半来源。）

修法：`geomOf` 改读 **`offsetTop` / `offsetHeight`**（布局值，与 transform 无关）。
配套两件事：
- 判据也钉在源码这一层（`geomOf` 里不许出现 `getBoundingClientRect`）—— 这条错的形态
  在 jsdom 里复现不出来（它要"过渡正在跑"这个真实中间态），只能靠结构判据守；
- 探针自己的"空位"判据也改成 `offsetTop`：**同一个坑差点让探针恒定假红**（见下）。

## 三、探针这一轮学到的两件事

1. **无头环境不推进过渡**：自检元素（`200ms linear` 的 transform 过渡）在 +120ms 与 +420ms
   读到的都是 `matrix(1,0,0,1,0,0)` ⇒ "过渡没推进"。于是 `+80ms` 那次采样读到的 76/127
   是**过渡的起点**，不是产品没补位；而那条条目身上确实挂着 `transform:running@0ms`
   （过渡**建起来了**，只是这个环境不放它走）。这一条已固化成采样里的
   `motionSelfTest` 一行 —— 免得下一个人把探针的假象当成产品 bug（我自己就先怀疑了一轮）。
2. **判据一律用布局值**：空位判据原来用 rect，在有过渡中间值/不推进动画的环境里会**假红**
   ⇒ 改成 `offsetTop`。这与组件侧的修法是同一条教训，写进注释互相引用。

另外顺手补了 ⑨ `ackListDump`（列表的子节点 + 各自 `offsetTop/offH/position/transform`）：
这一轮就是靠它一眼看出"视觉 76 / 布局 6"，没有它还在猜。

## 四、结果

- 实机（`ui_probe --notice-lab --width 1440`）rc=0：
  `布局=空位 ['rel=6/h=51', 'rel=6/h=70', 'rel=6/h=51'] ｜残留位移=[]`，
  `+680ms` 采样 `recent[1]: msg@6 lab-pushed-message-demo@57`（都顶到列表顶部了），
  `doing` 组六条 6/57/145/196/248/299 依次相邻 ✓。
  也就是：**点一条已读 ⇒ 它滑出、下面的当场补上来、一次到位**。
- 单测 24 条（新增"补位的反向位移不留跨帧状态"1 条 + 两处源码级结构判据）：
  用**假布局**（`offsetTop`/`offsetHeight` 打桩，jsdom 不做排版）把这条路径逼出来，
  并反向验证过——去掉那三步里的任何一步（或改回 rect），用例就红。
- ⚠️ 动画本身（220ms 的缓动）**探针验不了**（环境不推进过渡），只能由那三步的顺序
  + "过渡确实被创建（`transform:running`）"来保证；观感仍要人眼确认。
