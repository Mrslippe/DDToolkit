# 026-20260905-v0.6.0-P6-界面外观和逻辑优化

## 概述

P6 三条全部落地：chips 切换滚动位置（真回顶）、详情抽屉 → 居中独立窗口、
二级窗口全面对设计 token 重绘（UI-MAP「二期待办」清零）。

## P6-1：筛选切换滚动位置

**根因**：筛选变化 → `setPage(1)` 整表替换，但滚动容器不重置 `scrollTop`——
内容高度变化后浏览器 clamp 把位置拽走，深内容处切类型表现为「直接到底/断层」。
此前 dcf05e9「按筛选指纹缓存+恢复」9285689 实测不达预期已 revert
（恢复位置对不上新内容）。

**定案（标准列表 UX）**：筛选切换 = 用户意图重置 → **立即滚回顶部**。
- 单一 effect 监听 `typeFilter/searchKw/dateFrom/dateTo/deletedOnly`
  （list 视图）→ `listScrollRef.scrollTo({ top: 0 })`；
- 触发即滚（不等重取完成）；追加加载（page>1 哨兵续载）不受影响；
- 不引入任何新的滚动位置记忆状态。

## P6-2：详情抽屉 → 居中独立窗口

- `PostDetailDrawer`：`Sheet(side=right)` → `Dialog`（居中，`sm:max-w-[720px]`，
  `max-h-[90vh]` 内容区滚动）；`lastPostRef` 末帧保留逻辑沿用；
- 动效**保留原规格无缝迁移**（UI-MAP「抽屉动效」专段）：进场 260ms
  淡入+**scale(0.97)**（替原右移 48px）、退场 200ms、遮罩同拍、
  radix animationend 卸载机制不动、reduced-motion 0.01ms；
  选择器 `[data-slot=sheet-content/overlay]` → `[data-slot=dialog-content/overlay]`。

## 追加修订 3（用户反馈，2026-09-05 同日）

**查看器层级与遮罩修正**：

- **根因**：查看器是普通 portal（非 radix 层），radix 详情窗的
  `pointerdownOutside`（document 级监听）把查看器内一切点击都判为
  「点在详情窗外」→ 点查看器按钮会先关掉详情窗。修复：查看器根层
  `onPointerDown` 阻断冒泡（React 监听到达早于 document），
  详情窗在查看器打开期间完全收不到指针事件；
- **去掉黑色遮罩**：`bg-black/85` 全屏纱罩移除——与详情窗自身遮罩叠加
  双重变暗不美观。改为图片直接浮于详情窗上方（空白区点击仍关查看器，
  且不会波及详情窗）；
- **控件改白玻璃浮钮**（发丝边 + `bg-white/85` + backdrop-blur，
  hover 实心）：原深色玻璃钮（白字）在去掉遮罩后落在浅色详情窗上不可读；
  点状序号适应浅底：当前点 `bg-primary` 粉、其余 `bg-border`；
- 入场动画从整屏容器移到图片主体 `.image-viewer-img`（切图重播）。

## 追加修订 4（用户反馈，2026-09-05 同日）

**点查看器按钮仍会先关详情窗——真正的根因（读 radix 源码定位）**：

- 上一版以为是 `pointerdownOutside` 未拦截，加 `onPointerDown` stopPropagation
  **无效**——因为事件根本打不到查看器：radix 详情窗为 modal，
  `disableOutsidePointerEvents` 会把 `document.body` 置为
  `pointer-events: none`（body 级纱罩，dialog 自身内容/overlay 各自显式
  auto 恢复）；查看器是 portal 到 body 的「窗外节点」，**继承了 none 变成
  点击穿透**——指针命中直接落到其下 z-50 的详情窗 overlay
  （DismissableLayer 自有的 dismissable surface，见 radix-ui issue #3346）
  → 点击 = 按详情窗遮罩 → 先关详情窗。
- 修复：查看器根层加 **`pointer-events-auto`** 显式恢复（[已继承值被
  body 纱罩覆盖的关键修复]），配合原有 `onPointerDown` stopPropagation
  （此时才真正生效，屏蔽 pointerdownOutside）——查看器现在确为浮于
  详情窗之上的可交互层。旧 SmartImage 内置灯箱此前"能用"是因为它嵌在
  dialog content 内部（content 自带 pointer-events:auto），
  P6-4 移出窗外后必须自持。

## 追加修订 5（用户反馈，2026-09-05 同日）

**查看器遮罩只盖详情窗 + 查看器退场动画 + 玻璃钮换黑 + 详情窗遮罩退场缺失**：

1. **遮罩只盖详情页**：去掉整屏黑纱的复活方案——按
   `[data-slot=dialog-content]` 实测矩形定位一块 `bg-black/40` 圆角遮罩
   （`image-viewer-veil`，打开时量 + window resize 复测），只压住详情窗口
   本身，图片/控件浮于其上；不与详情窗自身遮罩整屏叠加变黑。
2. **查看器退场动画**：组件 `closing` 态 + `image-viewer-closing` 类：
   图片 0.2s 微缩淡出（viewer-out）、遮罩同步渐隐，EXIT_MS(200ms) 后
   才真正卸载——与详情窗退场同拍；退场期间交互一律忽略。
3. **玻璃钮换黑色**：上一张/下一张/关闭钮 → 黑色玻璃圆钮
   （border-white/25 + bg-black/60 + backdrop-blur，hover bg-black/85），
   点状序号适配暗底（当前白点放大、其余 white/40）。
4. **详情窗遮罩退场缺失（根因，读 react-presence 源码）**：radix
   `usePresence` 判定退场的 `isAnimating` 时，`currentAnimationName` 和
   `prevAnimationNameRef` 都取自**挂载时缓存的 computed style**
   （ref 回调只跑一次 + animationstart 记录的同源样式），
   data-state 换名（drawer-veil-in → drawer-veil-out）根本不会被感知
   → 始终等于 → 直接 UNMOUNT，面板/遮罩**瞬消**。
   **修复：弃用换名动画，改为类驱动**——详情窗 `exiting` 态给 content 加
   `is-exiting` 类播 `drawer-out`，遮罩经
   `[data-slot=dialog-overlay]:has(+ [data-slot=dialog-content].is-exiting)`
   联动播 `drawer-veil-out`（同为 200ms）；EXIT_MS 到点才真正
   `onClose()`（radix 侧卸载时元素已 opacity 0，无瞬闪）。
   重开时复位 exiting（含计时器未到点重开的边界）。

## 追加修订 6（用户反馈，2026-09-05 同日）

**详情窗突然全宽**：修订 3 把 DialogContent className 改成模板字符串
`` `…sm:max-w-[720px]${exiting …}` ``——**Tailwind v4 类提取器会丢弃
「带方括号的类名紧邻 `${` 插值」的候选**：`sm:max-w-[720px]` 规则未被生成
（编译后 CSS 里没有 `.sm\:max-w-\[720px\]`，只有 ErrorBoundary 的裸
`max-w-[720px]` 且排在 `max-w-[calc(100%-2rem)]` 之前、被后者覆盖）
→ 详情窗只剩基类限宽 = 视口 - 2rem ≈ 全宽。
修复：静态类名字串与推导段分离（`'…sm:max-w-[720px]' + (exiting ? ‘ is-exiting' : '')`），
重建后验证 `.sm\:max-w-\[720px\]{max-width:720px}` 出现在 `@media (min-width:40rem)`
内。**护栏**：className 模板插值处，带方括号/变体的类名禁止紧邻 `${`；
全库同类写法已审计（其余均为自定义类或 `${` 前有空格，无风险）。

## 追加修订 9（用户反馈，2026-09-05 同日）
