## 一、⚠️ 为什么量在**前端**（第一版写在后端，跑了测试才发现不可行）

| | 后端算 | 前端算 |
|---|---|---|
| 需要什么 | 一个图片解码器 | 浏览器本来就要解码它（它就是背景）|
| 现实 | **这个项目没有 Pillow** —— 上传校验只认文件头 magic（`services/vtuber_background.py`），`tests/test_backdrop_tone.py` 第一次跑就 `ModuleNotFoundError: PIL` | canvas 顺手就量了；后端 CORS 是放开的（`main.py` 的 `CORS_ORIGINS`），`crossOrigin="anonymous"` 下画布不被污染 |

⇒ 为一个纯观感特性引 Pillow 不划算，改成前端量。**后端那版（服务 + 端点 + 测试）整个删掉了**
（没提交过），理由记在这里：不是"前端更好"，是"后端根本没有解码器"。

## 二、口径（`frontend/src/utils/backdropTone.ts`）

- **只对自定义背景量**：没上传背景时铺的是头像，而头像是 `.18` 透明叠在白底面板上
  ⇒ 那一带**几乎是白的**，固定深字一直读得清。拿头像原图去量会得出**相反**结论
  （深色头像 ⇒ 判"深底" ⇒ 换白字，而屏幕上其实是白底）⇒ 头像态一律 `null`（保持原样）。
- **采样"中间那条横带"**（纵向 35%–65%）：英雄区在竖直中间，整图平均会被上下暗角/亮天空带偏。
  ⚠️ 近似：背景是 `background-size: cover`（有裁切），两档粗判够用。
- **和纱罩一起算**：字压在"图 + 白纱罩"上，`L_eff = L·(1−a) + a`，`a = 0.35`
  （`posts.css` 的 `.hero-backdrop.custom::after` 中段；**与 CSS 是同一件事的两半**，
  改了那边记得回来改 `VEIL_ALPHA_MID`）。
- **量不到就不猜**：加载失败 / 画布被污染 / 没有 canvas ⇒ `null` ⇒ 界面保持现在的灰字。
- 判据：`L_eff < 0.55` ⇒ `tone="dark"`（这一带是深色的）⇒ 挂 `data-ink="dark"` ⇒ CSS 换浅字。

CSS 只加两条规则（`.hero[data-ink='dark'] .live-tag.off` / `.hero-sign`），浅字再补一层
暗投影兜底（与名字那条 `text-shadow` 同族）。**名字不参与**（用户明确只要这两处）。

## 三、验证（哪些验到了、哪些验不了）

| 事项 | 证据 |
|---|---|
| 判定逻辑（带子/纱罩/阈值/null） | `backdropTone.test.ts` **8 条**：深底→dark、浅底→light、亮度是**合成纱罩后**的、上下再极端也不影响（只看中间带）、量不到→null |
| canvas 接线（crossOrigin / 失败兜底 / 上下文缺失） | 同文件**打桩 Image/canvas** 的 3 条 |
| **CSS 真的换浅色** | 实机 `ui_probe`：`签名色 rgba(94,94,94,.76) → 挂 dark 后 rgba(255,255,255,.94)`，标签同 ✓ |
| ⚠️ **真图量一次** | **验不了**：探针跑在**虚拟时间**下，图片加载永远不完成（本仓老坑，`ProxyImage` 同理）⇒ canvas 量不到像素。探针里如实**打印**"量不到（环境限制）"而**不判红** —— 判红就是把环境限制记成产品坏了 |

⇒ 结论：**判定与 CSS 都有机器判据**；"这张图真的量得出亮度"这一步只有**你的眼睛**能终验
（挂一张深色背景，看「未开播」和签名有没有变成白字）。
