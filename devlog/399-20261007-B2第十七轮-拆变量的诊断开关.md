# 399-20261007-B2第十七轮 拆变量的诊断开关（size / pseudo）

第十六轮已经把规律钉到 4/4（`devlog/398`）：**进全屏 → 2~3 秒后每秒丢 4 帧；退出全屏 /
一次 seek → 立刻恢复**。但"进全屏"这个动作一次翻了**三件事**，不定下来就没法归因：

| 变量 | 窗口态 | 全屏态 |
|---|---|---|
| ① 全屏 API / 全屏窗口 | 无 | `requestFullscreen()` |
| ② 显示尺寸 | `678x381`（`.vp-video{max-height:60vh}`） | `1920x1080`（1:1） |
| ③ WebView 底色 | `transparent` | `不透明`（`set_surface_opaque`） |

这一轮不加功能，只做一个**每次只动其中一个变量**的开关。

## 加了什么

`frontend/src/utils/vpFsMode.ts`（新）+ `VideoPlayer` 里两处接线 + `posts.css` 两块（**默认 `off`
⇒ 生产行为一字不变，查完就删**）：

- **`size`**：走真全屏（①③ 与全屏态相同），只把 `<video>` 钉回 `678x381` 居中 ⇒ **只动 ②**；
- **`pseudo`**：**不走全屏 API**（① 变），但布局、尺寸、不透明表面都照全屏做 ⇒ **只动 ①**。

开法：`$env:VITE_VP_FS_MODE='size'; npm run tauri:dev`（或 `pseudo`），
与 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 同一套路（`PROBE.md` §6.22）；
也认 `localStorage.ddtoolkit.vpFsMode`。⚠️ `pseudo` 下 **Esc 退不出来**（没有真全屏可退），再按一次 `f`。

**两格合起来是完整的 2×2：**

| `size` | `pseudo` | 结论 |
|---|---|---|
| 流畅 | —— | 元凶是"**画面铺到 1:1**"（②） |
| 卡 | 卡 | 元凶是"**全屏 API / 全屏窗口**"本身（①） |
| 卡 | 流畅 | 元凶是"**窗口底色**"（③） |

## 三条做法上的规矩（都落成了判据）

1. **开关值必须进日志**：进全屏时写一行 `[video] 全屏诊断模式=…`。否则事后分不清这一轮跑的
   是哪个模式 —— **那比不量还坏**，会把"开关没生效"读成"这条不是病因"（同 §6.22 的可见性验证）。
2. **垃圾值一律当 `off`**：判据里列了 9 种垃圾值（`''`/`ON`/`SIZE`/` size`/`fullscreen`/数字/对象…）。
   开关被一个手滑的值卡住时，表现是"播放器行为莫名变了"，而排查的人不会想到去看环境变量。
3. **`pseudo` 也必须走同一套 `data-video-fs` / `setSurfaceOpaque` 路径**，否则它拆的就不止一个变量。

## 反向验证 + 一条被判据逮住的改名

- 反向验证：把开关改成**恒返回 `off`** ⇒ 4 条判据红（单测 2 条 + 组件 2 条），**只有这 4 条**。
- ⚠️ 改名的连带：门里的 `fs` → `fsOn`（真实全屏 ∨ 假全屏）**当场撞红**一条**源码结构判据**
  （`VideoPlayer.holdRate.test.tsx` ⑦ 靠字面量 `if (!hovering && !fs) return` 断言"不无条件挂
  document 监听"）。那条判据的作用正是这个 —— 更新时写清了"**约束没变、口径变宽一格**"，
  而不是无脑改字面量。
