## 一、平台徽章：可点、可拖、尾部可加（P8-3）

**点击开主页**：药丸原本是纯 `<div>`（无任何交互）。现在：

- `StatPill` 加 `onClick`/`onPointerDown`/`dragging`/`dataIndex`，成为可点元素
  （`role=button` + Enter/Space 键盘可达，`focus-visible` 主色描边）；
- 主页 URL 优先取库里的 `accounts.url`；**B 站实测 0/8 为空**（`fetch_bilibili_user_info`
  不返回 url），故前端兜底拼 `space.bilibili.com/{uid}`、微博拼 `weibo.com/u/{uid}`；
- 打开方式：桌面端直接 `invoke('plugin:shell|open', {path})` —— capability
  `shell:allow-open` 本就在，**不需要新增 npm 依赖**（省掉 `@tauri-apps/plugin-shell`）；
  失败或 Web 环境退化为 `window.open(..., '_blank')`。

**长按拖动重排**：全仓原先没有任何拖拽实现，也不打算引 dnd 库。

- 交互：`pointerdown` 起 350ms 计时 → 进入拖拽态（`.is-dragging` 抬起 + 半透明）；
  `pointermove` 用 `document.elementFromPoint` + `data-pill-index` 找落点并就地交换；
  `pointerup` 提交。**未达 350ms 或没有位移 → 视为点击**（`dragMoved` 标记，
  点击后立即复位，避免拖完误开浏览器）。
- 落库：新增 `accounts.sort_order`（迁移 f002）+ `PUT /vtuber/{id}/account-order`
  （body 为新顺序的 id 列表，未列出的账号排在其后）。`AccountRepo.by_vtuber`
  改 `order_by(sort_order, id)`。前端拖完本地先乐观渲染，接口失败则回退服务端顺序。

**尾部「+」**：`.pill-add` 半透明小方钮，默认 `opacity:0`，`.stat-sets:hover` 时浮现
（用户口径：hover 时出现半透明徽章按钮）。点击打开**抽出来的** `AddAccountDialog`。

## 二、档案设置窗口（P8-4）

原「更换图片」按钮（只触发 file input）扩展为独立窗口 `VtuberSettingsDialog`：

| 分区 | 内容 | 接口 |
|---|---|---|
| 背景 | 缩略预览 + 更换 + 清除 | `POST/DELETE /vtuber/{id}/background`（`clearBackground` 此前零调用） |
| 基本资料 | 名称 / 企划 / 生日 / 出道日 / 角色设定 | `PUT /vtuber/{id}`（**前端类型此前缺 `name`/`avatar`**，已补） |
| 头像 | 从账号候选里点选（写远端 `avatar_url`）或「用平台默认」 | `PUT /vtuber/{id}` |
| 签名 | 主账号签名 + **字段锁定开关** | `PUT /account/{id}` |
| 已订阅账号 | 列表（平台/昵称/粉丝）+ 删除（二次确认）+ 添加 | `DELETE /account/{id}`（新封装）、`POST /vtuber/{id}/accounts` |

- **字段锁定**（已定决策）：`accounts.locked_fields`（逗号分隔，迁移 f002）+
  `scheduler._field_locked()` —— 抓取时被锁的 `display_name`/`sign`/`avatar` 不覆盖。
  没有它，用户在窗口里改的昵称/签名会被下一次抓取冲掉
  （`info.get("name") or acc.display_name` 这类赋值天然覆盖）。
- 头像只能写**远端 URL**：`vtubers.avatar` 不走 `resolveAsset`，写本地相对路径会拼错前缀。
- 草稿 + 保存：改完点「保存」才提交（避免逐键打接口）；背景上传/清除即时生效
  （走 `onSaved` 立刻刷新背景层）。
- profile 视图（档案卡）此前已占位下线，其**企划编辑 / 设定 / 账号一览**在这里承接。

顺带：添加账号表单抽成 `components/AddAccountDialog.tsx`（原来内联在 `PostsPage`，
现在被 card 视图的「+」、`list` 视图的按钮与设置窗口三处共用，避免三份同样的表单）。

## 四、经验

- **前端零依赖实现拖拽**：`pointerdown` + 长按阈值 + `elementFromPoint` + data 索引
  足够覆盖「一排元素重排」这个场景；引 dnd 库反而要处理它的 key/排序模型。
- **「用户手改的字段」必须能上锁**：只要抓取是「平台值 or 现值」的写法，没有锁定语义
  就一定会覆盖用户输入；这类字段要在同一批里连数据、接口、抓取侧一起改。
- **capability 已在 ≠ 需要装 JS 包**：Tauri 插件命令可以直接 `invoke('plugin:shell|open')`，
  省掉一个 npm 依赖与一次版本对齐。
