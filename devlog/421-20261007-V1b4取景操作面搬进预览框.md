# 421-20261007-V1b4取景操作面搬进预览框

需求 7 第五批。用户口径（原话大意）：**「直接在详情页里把拖动取景集成到那个预览框，支持鼠标滚轮缩放，隐藏滑杆」**。

## 为什么要搬

V1b-2 的取景控件是**另起一行**的：一个大预览 + 一条滑杆 + 读数。于是「档案设置 → 背景」里
**同一个背景显示了两次**（小预览一次、大预览一次），滑杆还把那行撑得很高 —— 用户看到的就是
"两块一样的东西"。现在合成一块：**那个 132×74 的预览本身就是操作面**。

## 改了什么

- `BackgroundFocusEditor` 只渲染**预览框 + 一个「重置取景」图标钮**（都是 `.vd-bg-row` 的直接子元素，
  排在一起）；`.vd-focus-stage` / `.vd-focus-bar` / `.vd-focus-range` 整组删除。
- **滚轮缩放**：指数映射 `scale × e^(−deltaY·0.0015)`（鼠标一格 ≈ ±16%；触控板按 delta 连续，
  ⚠️ 不能"每个事件 ×1.1"—— 触控板一次滑动几十个事件，会瞬间顶到 3×）。
  近 1 吸回**正好 1×**（否则永远差一点点、变换也撤不掉）。
- **倍数读数**只在真放大时以右下角小标签露出（`.vd-focus-zoom`）—— 它不是滑杆。
- 拖动平移、方向键微调（Shift ×5）、松手/滚停才存 + 260ms 防抖 + 关窗兜底：**沿用**。
- 没背景图时退回静态的 `.vd-bg-preview`（"头像铺底"）——那时也没可取景的。

## 四个坑（都写进代码注释与 `UI-MAP` 了）

1. ★**滚轮必须挂原生非被动监听**：React 的 `onWheel` 是 **passive** 的，`preventDefault()` 无效
   ⇒ 弹窗内容体一边缩放一边跟着滚。用例直接断言 `event.defaultPrevented === true` —— 被动监听做不到这件事。
2. **取景三件套必须挂在内层** `.vd-bg-focus`：`transform: scale()` 会把边框与圆角一起放大，
   挂外层会让 1px 描边变成 2px、框长到邻居身上（真引擎截了三种状态对比确认描边没变）。
3. **拖动按溢出量换算**（`panDelta`）：竖图铺在宽框里横向本来就没有可露的部分 ⇒
   横着拖不动是**正确**结果（返回 0，不许除出巨大跳变），纵向照挪。
4. **行模式 delta**：Firefox 的 `deltaY` 是"行"（`deltaMode === 1`），按 `×33` 折成 px 当量，
   否则滚一格几乎不动。

## 判据（11 条，含上面 1、3、4）

1:1 跟手（132×176 的图、scale=2、往右拖 30px ⇒ x 恰好减 30/132）· `scale=1` 时纵向跟手、横向一动不动 ·
★滚轮上滚放大且 `defaultPrevented` 为真 · 下滚缩回**正好 1×** · 一路滚封顶 3× ·
★**渲染里不许有 `input[type=range]`**（"隐藏滑杆"这条直接钉住，免得以后有人手滑加回来）·
死区 · 松手才存 · 关窗兜底 · 坏 JSON · 重置钮（没取景时禁用）· 方向键。

**反向验证**：见 `docs/ops/PERF.md` 那一行（把非被动监听改回 `onWheel` ⇒ `defaultPrevented` 那条红）。
