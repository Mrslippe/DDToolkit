# 028-20260905-v0.6.1-抓取任务时效分层调度

## 概述

按**时效敏感度**对全部周期抓取任务分层（用户 2026-09-05 提出，方案已确认）：
T0 直播状态独立线程（60s）→ T1 主要账号信息（5min）→ T2 最新动态（15min）
→ T3a 全量账号慢周期（6h）；**手动任务优先**（定时档遇手动在跑即跳过本轮，
不再抢断用户操作）；启动链语义并入调度线程首轮（T1→T2 立即执行），
T0 首轮即启动时最快直播刷新。

## 分层决策（与用户确认）

| 决策点 | 定案 |
|---|---|
| T0 周期 | **60s ± 15s**（批量接口每 100 uid 1 请求，成本可忽略） |
| T1 主账号化后非主账号 | **T3a 每 6h 全量慢周期**补足 |
| T2 周期 | **15min ± 2min**（限 2 帖/账号，复用 limit_latest） |
| 手动 vs 定时 | **手动优先**；仅 T0 独立线程与一切任务并行——用户明确要求 |
| T0 形态 | **独立守护线程**：不占 `_fetch_lock`、不进状态通道、不写 last_result |

## 实现要点

- `live_sweep_core(db, client)`：T0 核（自建/复用 client，批量回写 live 字段 +
  live 跳变统计快照 + push account-progress）——从启动链阶段 1 抽出、
  **去掉锁/状态/结果汇总**；`start_live_poller()` 守护线程首轮
  `STARTUP_CHAIN_DELAY` 后立即执行，然后循环；
- `run_main_account_sweep()`（原 startup_main_account_sweep）：去掉
  `_set_account_last_result`（周期任务静默，完成胶囊只服务手动任务）；
- `run_latest_dynamics_sweep()`（原 startup_latest_dynamics）：同样去掉
  结果汇总；
- `_tier_loop()`：`STARTUP_CHAIN_ENABLED` → 首轮 T1→T2；之后心跳
  `TIER_TICK_SECONDS=10s`：`is_fetch_running() or is_post_fetch_running()`
  → 本轮跳过（手动优先）；到期档位按 T1→T2→T3a 贪心串行（单线程无档间并发）；
  各档 `interval±jitter`，interval<=0 禁用；
- **移除**：`fetch_and_update_vtubers`（旧 5min 定时任务入口）及其
  `IntervalTrigger` 注册与 `IntervalTrigger` import——APScheduler 仅保留
  外部数据 cron；原「定时优先让位协议」无置位方（机制保留以备复用）；
- `_fetch_scope` 保留（'full'/'single'/'main'，T0 不参与）；
- SQLite `busy_timeout` 10s→**30s**：T0 毫秒级事务与任何抓取任务并发写同表
  排队兜底，无需参与锁协议；
- 说明：`_yield_request` 让位机制从此不再被周期任务置位（手动优先），
  但保留在代码中（外部/未来用途；测试不依赖）。

## 验证

- 新增测试：`live_sweep_core` 批量回写 + 跳变快照（直接调核，不依赖锁）；
  T1/T2 锁被占 → 跳过（手动优先）；`limit_latest` 用例保留；
- 移除旧「定时任务优先协议」两测（fetch_and_update_vtubers 已不存在）；
- `python -m pytest tests -q -p no:cacheprovider` → **152 passed**。
