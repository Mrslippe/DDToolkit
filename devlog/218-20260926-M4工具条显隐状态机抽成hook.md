# 218-20260926-M4工具条显隐状态机抽成hook

批次 12 = 计划 §M4「拆 PostsPage 行为」。本批**只落了第一台**：
`useToolbarVisibility`（+ 8 条 hook 用例）。剩下的三台 hook 与 typed event 记进

## 一、为什么先挑它

计划对 M4 的硬要求是"**抽 hook 同时带出 hook 测试**，否则不做"。这台机器：
- **自洽**：状态与副作用全在"工具条显隐"这一件事里，不跨组件共享；
- **有真实事故史**（三条硬约束都是踩出来的），而原来的机器判据只有 `ui_probe.py --toolbar`
  （真浏览器 + 虚拟时间）—— 它钉的是**机制**（`data-shown` / opacity），量不到
  "140ms 的 dwell 到底有没有挡住路过"这种边沿行为；
- 抽出来之后 `PostsPage` 少 118 行。

## 二、搬了什么（**逐字保留**三条硬约束）

`hooks/useToolbarVisibility.ts`：`barShown` + `showBar/hideBarSoon/onScrollDown/onPanelMouseMove`
+ 闪现 effect + 清理 effect + `data-scroll-dir` 的 `MutationObserver`。

| 约束 | 为什么不能"顺手改成更好看的写法" |
|---|---|
| **`flashedThisSession` 必须模块级**（不能变 ref/state） | `PostsPage` 按路由挂载，切 V 会重挂；用组件内状态就每次切 V 闪一下 = 噪音 |
| **"要不要闪"必须在渲染期决定一次**（不能挪进 effect 判断） | StrictMode 下 effect 走 setup→cleanup→setup，cleanup 会清掉闪现定时器；判断若也在 effect 里，第二次 setup 会因"本会话已闪过"早退 ⇒ 定时器没人装 ⇒ **永久停在 `shown=1`**（`--toolbar` 探针实测抓到 `rest: shown=1 opacity=1`） |
| **`MutationObserver` 必须 `subtree: true`** | 视图是之后才挂载的（切 V / 切视图整体重挂）；预先 `querySelectorAll` 抓快照 ⇒ 一个都没 observe 上 ⇒ 功能静默失效（探针实测：`data-scroll-dir` 已是 `down`，工具条纹丝不动） |

另外**整个模块不新增 effect、不改依赖数组字面量** —— 抽 hook 的纪律是"搬位置，不改行为"。

## 三、判据（`hooks/useToolbarVisibility.test.tsx`，8 条，jsdom 假定时器）

冷启动闪现一次（1200ms 后收回）· **同会话重挂不再闪** · StrictMode 下**不许永久停住**
且指针路径照常 · dwell 140ms 才呼出（不到不呼出）· 离开热区 900ms 收回 ·
指针原地不动不误弹 · **`data-scroll-dir=down` 立即让位且指针还在热区时不许弹回**（R45-G 的坑）·
属性挂到"之后才挂载"的子树节点上也认（约束 3）。

⚠️ 两个测试写法坑（都实测踩到，写在注释里）：
1. **`MutationObserver` 的回调是微任务** ⇒ 必须 `await act(async () => { … await Promise.resolve() })`，
   同步 `act` 下断言会看到"属性改了、状态没动"（一次踩三条）；
2. **模块级 `flashedThisSession` 会跨用例串台** ⇒ 每个用例 `vi.resetModules()` + 动态 `import`
   拿新模块。

StrictMode 那条**刻意不断言"挂载那一刻一定闪了"**：jsdom + 假定时器下观察不到稳定的中间态
（实测挂载后直接就是 false）。事故的形态是**永久停住**，所以判据钉"窗口过完必须收回 +
指针路径没坏"这两条 —— 把"闪现到底有没有发生"留给真机/探针。

## 四、门禁与顺带发现

- `ui_probe.py --toolbar`：**[ok] 工具条：rest 全隐 / 进热区呼出 / 移出收回 / 聚焦显形 / 不挤动内容**；
  默认三档 × 10 帧 **0 问题**；vitest **629**。
- ⚠️ **`--toolbar` 的滚动那一步偶发**：第一次跑读到 `下滚后=shown=1(dir='up')` 并判红，
  同样的代码再跑一次是 `dir='down'` ⇒ 判红。**`dir` 不是 `down` 时那条判据必然红**，
  与产品行为无关 —— 记下来，别下次被它骗一轮。
