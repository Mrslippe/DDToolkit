# 帖子抓取链路优化 (2026-08-06)

## 一、动态详情数据补全修复

### 问题
图文/纯文字动态的 `summary` 列存储的是 `[1p]` 而非实际正文，`body_json` 内容也不完整。

### 根因分析
链路：`fetch_bilibili_dynamics` (feed) → `_do_fetch_posts` → `fetch_dynamic_detail` (detail API) → merge → 写入 DB

三个问题：
1. **detail API 静默失败** — 返回非 0 code 时直接 `return None`，无日志，完全感知不到
2. **合并逻辑缺陷** — `d.update({k:v for k,v in detail.items() if v})` 中 `if v` 会跳过空字符串，且带了不需要覆盖的字段（如 `platform_uid`）
3. **提取函数共用** — feed 和 detail 共用 `_extract_dynamic_text`，若 detail API 未返回 OPUS 格式则结果与 feed 相同

### 修复
- `fetch_dynamic_detail` 增加 warning 日志（API 错误、空 item），debug 日志记录 `major.type`
- 合并逻辑改为精确覆盖 7 个内容字段，无条件覆盖
- detail 获取失败时打 warning

## 二、分页参数可配置 & 全量拉取

### 改动
`POST /vtuber/fetch-posts` 新增 `dynamics_pages` 参数：

| 参数 | 默认值 | `-1` 行为 |
|------|--------|-----------|
| `video_pages` | 3 | 翻页到接口返回空 |
| `dynamics_pages` | 5 | 翻页到 `has_more=false` |

全量拉取示例：
```
POST /vtuber/fetch-posts?name=明前奶绿&video_pages=-1&dynamics_pages=-1
```

视频和动态循环均由 `for range()` 改为 `while True` + 条件 break。

## 五、帖子抓取逻辑迁入 scheduler

### 动机
将 `_do_fetch_posts` 从 router 移入 `app/services/scheduler.py`，统一管理锁、db 生命周期和运行状态。

### 改动
- **scheduler.py** — 新增 `async_fetch_posts(mid, video_pages, dynamics_pages)`，带 `_post_fetch_lock` 防并发，独立管理 db session；新增 `PostFetchResult` dataclass、`is_post_fetch_running()`
- **vtuber.py** — 删除 `_do_fetch_posts`、`_safe_json_parse`、`_dump_json`（~120 行），`fetch_posts_by_name` 委托给 `async_fetch_posts`

## 六、published_at 修复

### 问题
图文类型动态的 `published_at` 列为空。

### 根因
1. merge 列表不包含 `published_at`，detail API 返回的时间被忽略
2. `_parse_pub_time` 只接受 str，B站 detail API 可能返回 int 时间戳 → `s.isdigit()` 抛 AttributeError

### 修复
- `_parse_pub_time` 支持 `str | int | None`，int 类型自动识别秒/毫秒级时间戳
- 新增 `%Y年%m月%d日 %H:%M` 格式解析
- merge 列表加入 `published_at`，且只在 detail 值非 None 时覆盖

## 七、抓取频率控制

为防风控，调整动态抓取间隔：

| 位置 | 原来 | 现在 |
|------|------|------|
| 每条 detail API 调用 | `0.5s` 固定 | `random.uniform(0.5, 2.0)s` |
| 动态每页之间 | `1s` | `20s` |
