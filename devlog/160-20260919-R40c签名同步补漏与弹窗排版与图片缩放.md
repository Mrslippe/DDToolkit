## ① 签名同步：R33 修的是"渲染口径"，缺的是"通知通道"

**根因**：左栏 `VtuberSidebar` **自己** `listVtubers()` 取一次列表，之后只跟抓取快照合并；
而「档案设置」保存走的是 `PostsPage` 那份 `vtuber` 状态 ⇒ **右栏（卡片）立刻变、左栏一直是旧的**。
R33（devlog/135）修的是 `resolveSign` 那条**渲染链**（"该显示哪个签名"），
这次缺的是**保存后通知左栏**这条通道 —— 所以"之前修过又出现"。

**修法**：
- 新增 `utils/vtuberList.ts`：`VTUBER_UPDATED_EVENT` + `applyVtuberUpdate(list, updated)`（**纯函数**，
  **5 条单测**：按 id 命中 / 顺序不变 / 未带字段保持原值 / 没命中原样返回 / 脏输入不炸）；
- `PostsPage.onSaved` 保存后 `window.dispatchEvent(new CustomEvent(VTUBER_UPDATED_EVENT, {detail: v}))`
  （左栏不是本页子节点 ⇒ 用事件而不是 prop；本仓已有 `ddtoolkit:pill-message` 同款先例）；
- 左栏监听并**就地合并**那一行（不整表重拉 —— 那会让左栏闪一下并重排）。

**护栏（补上真正的缺口）**：原探针只覆盖"**启动前**种进库"的现场（左右两边都是新加载的），
**覆盖不到"应用内当场编辑"** ✗ —— 而用户报的正是后者。现在探针会：取一条真实 V → 改签名 →
派发更新事件 → 读左栏那一行 ✓（不跟着变就红）。
顺带把对照组判据改成**数据无关**的写法（"除目标 V 外没有别的行显示自定义签名"）——
原来拿"库里挑的那个对照 V"比，库里混进脏数据就会假红（实测就红在这条）。

## ② 弹窗排版（R40c）

- 「本场速览」的**标题与卡片底**去掉（`.lc-dlg-glance` 的 padding/background 归零）⇒ 左列矮一截；
- 四枚胶囊**四种底色**（粉/蓝/黄/绿 —— 取本仓既有的直播类型色系，值仍走 `--c-text-main` 保对比度）；
- `.lc-dlg-main` 从 `align-items: start` 改成 **`stretch`** ⇒ 右列（直播信息）撑满整行，
  **两列底边齐平、右下不再留白**。

**护栏**：探针新增三条 —— 速览标题必须为空、四枚胶囊底色必须 ≥4 种、两列底边差 ≤2px。

## ③ 图片查看器滚轮缩放

- 只动 **`transform: scale()`**（合成器属性，不重排；大图用 width/height 缩放会每帧重排）；
- **以指针为锚点**（`transform-origin` 跟着指针走）—— 放大后想看哪就看哪；
- 范围 `[1, 4]`：1 = 适应窗口（默认，不允许更小），切图/关闭由 `key` 重建自动复位；
- `nextZoom(cur, deltaY)` 是**导出的纯函数** + **5 条单测**（方向 / 下限 / 上限 / deltaY=0 / 往返不漂）；
- 容器下发 `data-viewer-scale`，供后续探针直接断言。

## ④ `--reservations` 那条既有红：**改名留下的陈旧选择器**

探针点的是 `clickView('档案')` —— 而 **R37-P1 把那一页改名成「数据视图」**之后，
`'档案'` 前缀只匹配得到**档案视图（卡片画布）** ⇒ 它点开了没有日历的那一页，
然后一直等 `.lc-cell` 超时 ✗（`clickView` 是**前缀匹配**，`数据视图（直播日历 / 粉丝趋势）`
不以「档案」开头，而 `档案视图（卡片画布）` 以它开头）。

修法：`clickView('数据视图')` ✓ + 加一条更诚实的判据：**日历视图没打开**（0 个格子）与
**预约没进日历**（格子有、徽章没有）分开报 —— 后者才是"接口没通"，前者是"点错了页"。
修完 `--reservations` exit 0 ✓。
