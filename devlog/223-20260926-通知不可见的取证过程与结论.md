# 223-20260926-「一条气泡都没看到」的取证过程与结论

> 用户：「一条气泡都没看到，帮我检查系统设置并修改」
>
> 结局：**应用自己的通知最后弹出来了**（用户确认「成功了，这次看到弹窗了」）。
> 但过程值得完整记下来 —— 这是一次典型的「代码侧全是成功、用户侧什么都没有」，
> 而且是在**我看不到用户屏幕**的约束下判的案。

---

## 一、先把事实摆清：代码侧的证据链

| 观察 | 手段 | 结论 |
|---|---|---|
| T0 轮询确实抓到了边沿 | 库里 20:24:45 / 20:27:52 / 20:33:02 / 20:40:52 各多一条 `live_status=1` 的 `account_stat_snapshots` | 状态边沿成立，`_notify_live_start_edge()` 必被调用（同一分支下一行） |
| 通知没有被关闭 | 用户/机器环境变量、数据目录 `.env`（只看键名）、注册表全局开关 `NOC_GLOBAL_SETTING_TOASTS_ENABLED`、无 `NoToastApplicationNotification` 策略、`WpnService`/`WpnUserService` 均 Running | `_dispatch` 的"关闭"分支排除 |
| 系统当时允许通知 | `SHQueryUserNotificationState()` = **5 (ACCEPTS_NOTIFICATIONS)**，勿扰（QUNT_TIME）未开 | 系统级静默抑制排除 |
| 应用的通知线程活着、队列空 | **py-spy dump --pid** → `_worker_loop (notifier.py:485)` 停在 `queue.get` | 线程没死、没卡；队列已被消费 ⇒ `_deliver()` 跑过 |
| 应用的通知窗口真的建了 | 在用户桌面枚举 PID 的顶层窗口 → `DDtoolkitNotify_0f5fe27e…`（可见性 0 = 隐藏窗口，正常） | `_make_balloon()` 成功；且它就在**用户的默认桌面**（`WinSta0\Default`，任务栏 `Shell_TrayWnd` 存在） |
| 失败路径没有触发 | `app.log` 里 20:26 之后零 WARNING/ERROR；而"无气泡后端"与"`Shell_NotifyIcon` 失败"都必然记日志 | ⇒ 只剩"`Shell_NotifyIcon` 返回成功"这一种可能 |

## 二、再看三个"排他"实验（都在用户桌面上跑）

我的命令跑在一个**独立桌面**（`WinSta0\CodexSandboxDesktop-…`），所以"我这里弹不出来"毫无参考价值。
把命令投进用户交互会话的办法：`Register-ScheduledTask -LogonType Interactive` + `Start-ScheduledTask`，
用 `wscript` 隐藏启动 `pythonw`（**不能留可见控制台**：上一轮测试就是被顺手关掉窗口、把进程一起结束的）。

投进去之后，逐条排除：

| 实验 | 变量 | 结果 | 排除了什么 |
|---|---|---|---|
| A vs B | WinRT 系统通知 vs 托盘气泡（英文文案） | 都看到 | "系统通知通路坏"与"气泡通路坏"都排除 |
| C | **队列 + 投递线程**（应用真正走的那条路），英文 | 看到（`last_delivery=ok=True`） | "只有 `show_now()` 能用、队列路径坏了"排除 |
| 中文测试 | 同 C，但文案换成应用原文（「明前奶绿 开播了｜…」） | 看到 | **文案编码**排除 |
| G/H/I | 设/清 `com.ddtoolkit.app` 这个**未注册的 AUMID** | 三条都看到 | **未注册 AUMID 会静默吞通知**这条假设排除 |
| 进程身份 | AUMID、桌面、任务栏、按应用通知条目（CloudStore 里全文搜 `ddtoolkit`） | 都没有异常 | 能想到的"进程级抑制"全排除 |

## 三、结论

**代码与系统都没有问题**。差别只剩"横幅只在**主显示器**右下角、只显示 **5 秒左右**"，
而我唯一能给出的判据是 `Shell_NotifyIcon` 的返回值 —— 它**只管"交给系统了"，不管"你看见没有"**。
这台机器还有第二块任务栏（`Shell_SecondaryTrayWnd` 存在 = **多显示器**），
用户当时很可能在看另一块屏（比如和我聊天的窗口）。

最后一次触发时我明确要求"盯主屏右下角，错过就按 Win+A 看操作中心"，用户就看到了 —— 收工。

## 四、这次沉淀下来的东西

1. **`Shell_NotifyIcon` 返回 TRUE ≠ 用户看见**。凡是"视觉副作用"，判据必须来自用户（或截图），
   日志只能证明"我们交了"，证明不了"它显示了"。
2. **诊断要带"确定判据"**：`notifier.last_delivery()`（本次为端到端脚本和排查都省了事）+
   **py-spy 抓线程栈**（一眼看出"线程活着、队列空"，直接把范围从"卡住/死掉"缩到"投递成功了"）。
3. **跨桌面投递**是这套环境下的通用手段：`Register-ScheduledTask -LogonType Interactive` +
   `wscript` 隐藏启动。踩到的两个坑一并记下：
   - 送进 `cmd.exe` 的脚本**必须 ASCII-only**（中文注释在 GBK 下会吃掉换行，把后面几行连成一体）；
   - **别留可见控制台窗口**（用户关掉它，测试进程一起结束，现场看起来像"崩溃"）。
4. **`scripts/notify_probe.py` 增加 `--queue`**：默认的 `show_now()` 是同步直弹，
   与应用真实走的"队列 + 投递线程"是**两条不同路径** —— 排查时踩过"直弹能显示、
   队列路径没人验"的坑，现在一条命令就能验后者（打印 `last_delivery()` 的判据与失败原因）。

## 五、用户侧要知道的两条

- 气泡出现在**主显示器**右下角，只显示几秒；错过可以按 **Win + A** 看操作中心的历史。
- 点击直达只在**气泡还在屏幕上**的那几秒有效（图标存活期 = `NOTIFY_BALLOON_LINGER_SECONDS`，默认 8s）。
