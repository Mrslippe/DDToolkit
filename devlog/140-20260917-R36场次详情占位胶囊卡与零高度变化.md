## 一、先量：用户说的"窗口长度变化"到底是多少

`.lc-dlg` 的高度是**内容驱动**的（只有 `max-height: min(680px, 100vh-64px)`，没有固定高），
所以内容一变高弹窗就变长。给 `--archive` 加了"连采两格"（点开格子后 120ms / 上游稳定后）后，
第一次就量到真数字：

| 采样 | 窗 | 两列区 | 右列卡片 |
|---|---|---|---|
| 上游未到位（打开后 120ms） | **533** | 207 | 207 |
| 上游到位 | **557** | 276 | 276 |

右列凭空多出 4 行 A 组指标（观看/点赞/打赏/互动）+ 一行「在线排名」的余量 ⇒ 两列区 +69px；
加上弹幕信息 / 直播动态两处从一行文案换成真内容 ⇒ 窗 +24px（在探针窗口里弹窗已顶到 `max-height`，
所以窗高只涨到上限就停了 —— 用户机器窗口更高，跳得更多）。

**左列空区域**：`.lc-dlg-main` 是 `264px | 1fr` 两列、`align-items: start`，左列只有封面
（264×198），右列却随指标长高 ⇒ 封面下方那块就是用户圈出来的空白。

## 二、三个口径（用户拍板）

| 口径 | 用户选择 | 理由 / 代价 |
|---|---|---|
| 胶囊卡里放哪几枚 | **只放四枚本地就有的值，分双行**（自定义） | 上游迟到的那组（观看/点赞/打赏/互动）不进卡 —— 它们在右列已有行式列表；卡片只负责"第一帧就把空区域填满" |
| 未到位处的形态 | **同尺寸骨架 + 只在超时/失败时出文字** | 骨架与到位内容同高是"高度零变化"的前提；而"没拿到"仍要说出来（devlog/063 的教训：缺席 ≠ 没有） |
| 弹窗高度 | **只在「未到位 → 到位」这段保证零变化** | 不做"弹窗恒定高"——那会让内容短的老场次凭空多一大块空白 |

## 三、落地

| 层 | 改动 |
|---|---|
| 左列 | `.lc-dlg-left`（封面 + 速览卡纵向排）→ `.lc-dlg-glance`「本场速览」**2×2 四枚胶囊**（时长 / 峰值在线 / 弹幕数 / 收益），第一帧就有值 |
| 口径 | `components/live/sessionGlance.ts::glanceCapsules()`（纯函数，**6 条单测**）：四枚**恒定**返回（少一枚就少半行 ⇒ 高度会跳）、顺序固定、缺值写 `—`；收益是唯一例外（`null` → `—`、`0` → `¥0`，与"缺席 ≠ 没有"一致） |
| 右列 | `.lc-dlg-metrics` **恒定四行**（骨架 → 真值）+ `min-height: 109px` 给第五行「在线排名」预留位；「上游响应较慢…」提示改挂**标题行**（`.lc-dlg-sec-note`，不占额外行高） |
| 弹幕信息 | 内容套 `.lc-dlg-slot--danmaku`（`min-height: 258px`）：未到位 = 两行骨架 + `.lc-skel--cloud`（**210px，与 `MosaicCloud` 的 `boxH` 一致**）；到位/没有/失败四种形态占同一块地方 |
| 直播动态 | 内容套 `.lc-dlg-slot--evts`（`min-height: 150px`）：未到位 = 三行骨架（点 + 时间条 + 文本条） |
| 骨架样式 | `.lc-skel`（扫光）/ `.lc-skel--cloud`（脉冲），尺寸与它替身的内容一致；`prefers-reduced-motion` 下只留静态灰块 |

**已知代价（写进 UI-MAP）**：`min-height` 是**故意留白** —— 数据比预留少时卡片底部空一点。
换来的是"打开后窗长不跳"。正常场次（有词云 + 几条动态）两者几乎相等，看不出留白。

## 四、护栏：`--archive` 连采两格（反向验证 3/3 红）

`?probe=archive` 现在在**点开格子后 120ms**采第一格（上游未到位），稳定后采第二格，量：
**滚动内容高**（`.lc-dlg-body .os-scroll` 的 `scrollHeight`）+ 窗高 + 两列区 + 右列卡 + 速览卡，
并断言速览卡的几何（紧贴封面下方 **12px**、同宽 **264**、四枚胶囊 **2×2**、不越界）与
**交叉对账**（胶囊的「峰值在线/弹幕数」必须等于右列同一字段 —— 不依赖"这场有没有值"，
两边都 `—` 也算一致，但读到值就得一模一样）。

**两个尺子坑（本批最有价值的部分）**：

1. **后端对上游有 10 分钟缓存** ⇒ 第一次实现直接采两格，结果"两格都采到了到位态"
   （探针跑第二遍时数据几十毫秒就回来了）—— 判据完全空转。改法：探针**自己把 `/upstream`
   压后 2.5s**（包装 `window.fetch`）来**造**未到位态，就像别的模式往副本库里种数据一样；
   采完立刻还原，后面等的是真实到达时间。
2. **窗高在内容顶到 `max-height` 之后恒等** ⇒ 只比窗高是**假绿**：反向验证时把预留高度
   改成 0，窗高照样相等（探针窗口矮，两格都顶在上限）。有牙口的是**滚动内容高**
   （1016 → 983px，−33px）—— 补上这条判据后反向验证才真的红。

**反向验证 3/3**（把实现逐条改回旧行为）：

```
左列不加速览卡（红圈区域还是空的）        → RED（间距 -298 / 宽 0≠264 / 胶囊 0 枚）
未到位态不打骨架标记（退回看不出在等的形态）→ RED（没有 data-pending + 内容高 -9px）
槽不留白（min-height 归零）              → RED（滚动内容高 1016 → 983，-33px）
```

另：**改造前的红**也留了档（第一次跑连采两格时判据尚未修）：

```
- 未到位态还是靠文案（实得 ['正在取上游弹幕…', '加载中…']），没有同尺寸骨架
- 左列没有速览卡（`.lc-dlg-glance` 没渲染）—— 封面下方那块空区域还是空的
- 弹窗高度从 533 变成 557（差 24px）—— 数据一到窗口长度就变了
- 两列区高度从 207 变成 276（差 69px）/ 右列卡片同理
```

**实跑输出（2026-09-12 那场，有真值）**：速览胶囊 = 时长 `6小时1分` · 峰值在线 `937` ·
弹幕数 `13,857` · 收益 `¥70,239.5`；几何 = 封面 `264×198 @(197,100)`、速览卡 `264×152 @(197,310)`
（间距 12px）、四枚胶囊 `114×46` 两行两列；**窗 557 / 两列区 362 / 右列 299 / 速览卡 152 /
滚动内容 1016，两格完全一致**。
