# 607-20261024-头像提速：连接池 + face 缓存 + 预热 + 缓存头

用户反馈"头像还是有点慢"。先量再改。

## 一、测量

| 场景 | 每头像耗时 |
|---|---|
| 缓存命中 | **5.4 ms** |
| 冷启动 | **466–726 ms** |

冷启动的三段开销：新建 `httpx.AsyncClient` 的 TLS 握手（150–300ms）+ card 接口（50–160ms）
+ 下载缩略图（45–70ms）。**每个头像两条上游请求，20 个头像就是 40 条。**

## 二、四项改动

| 改动 | 做法 | 省掉 |
|---|---|---|
| **连接池** | 全局 `AsyncClient`（16 连接、keepalive 8），并**绑定事件循环**（跨 loop 复用会报 `Event loop is closed`） | TLS 握手 |
| **face 缓存** | `avatars/_face.json` 持久化 uid→face URL，命中就不调 card | card 接口 |
| **后台预热** | `/ranked` 首页返回后，后台异步抓前 40 个头像（并发 6） | 用户的等待 |
| **Cache-Control** | `public, max-age=2592000, immutable` | 二次打开的重请求 |

（`PYTEST_CURRENT_TEST` 存在时不预热 —— 否则后台任务会在用例结束后继续发请求。）

## 三、实测（真实 uvicorn，不是 TestClient）

```
冷启动 16 个并发：总 718 ms · 成功 16/16 · 平均 45 ms/个
二次请求（缓存）：总 86 ms
Cache-Control: public, max-age=2592000, immutable
```

同 loop 连续取：首个 588ms，之后 93–172ms —— **连接复用确实生效**（TestClient 每次新 loop，
测不出来，所以必须起真服务测）。

## 四、验收

后端 fan **166 passed / 2 skipped**。前端无需改动。
