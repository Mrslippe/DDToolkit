## 三个想清楚的点

1. **为什么用 `transform` 而不是 `background-position`**：背景层是 `background-size: cover`，
   用 `background-position` 平移得先让图比容器大，而"大多少"取决于**图片宽高比**与容器宽高比 ——
   CSS 里拿不到（`cover` 没法乘倍数）。`transform` 不用知道这些，而且平移范围**天然被缩放卡住**：

   ```
   元素宽 W、缩放 s ⇒ 溢出 (s-1)·W、左右各半 ⇒ 平移上限 (s-1)/2·W
   x∈[0,1]（0.5 居中）⇒ translateX = (x-0.5)·(s-1)·100%   ← 恰好在边界上
   ```

   ⇒ **永远露不出边**（用户要的是"取景"，不是"把图挪开让底色露出来"）。判据里那条 ★ 就是钉它的：
   扫 `scale ∈ {1.4,2,3} × x ∈ {0,…,1}`，断言位移**不超过**半边溢出，**且边界上恰好顶到**。

2. ⚠️ **交叉淡出的旧层必须跟自己的图走**：`focus` 若被旧层实时读取，换 V 的那 250ms 里
   旧图会被按新 V 的取景变换一次 —— 看着像旧图跳了一下。所以 `Layer` 各带一份 `focus`，
   **当前层**才读实时值（顺带得到一个好处：在设置里调取景时右边背景当场跟着动）。

3. **取景只对自定义背景生效**：头像铺底那张是按 0.18 不透明度当纹理用的，给它加取景只会把脸
   挪出画面，而且用户也没地方调它。

## 实现与判据互相纠了一处

写判据时它把我实现里的**不一致**顶出来了：docstring 说"没有取景就不生成 transform"，而实现
对"居中 + 缩放 1"照样生成了一个**恒等变换**（`translate(0%,0%) scale(1)`）—— 白占一个 DOM 属性。
修法是让 `focusTransform` 在 `scale === 1` 时返回 `undefined`（那时本来就没有溢出，
`dx`/`dy` 恒为 0）。⚠️ 但"**居中 + 放大**"不能一起省 —— 那时 `translate` 是 0 而 `scale` 有效果。

同时改掉了 `parse` 里一处多余的设计：原本把"等价于居中"的值折成 `null`，
但 `x`/`y` 是**用户存下来的意图**（`scale=1` 时看不出效果，等他调大缩放就该还在那儿）——
折成 `null` 会把这个意图吃掉。"看不出效果就不生成 transform"是 `focusTransform` 的事。
