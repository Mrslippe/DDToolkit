# 280-20261002 小红书笔记：补全多图与正文，链接带上 xsec_token

> 用户报障（2026-10-02）：
> ① 「小红书抓到的笔记只有一张照片，文字内容也没有展示出来，是回包中没解析出来还是没抓取到」
> ② 「点击查看原文会跳转到当前笔记暂时无法浏览，可能是跳转 url 参数表不对」，并给了一个可用样例：
> `https://www.xiaohongshu.com/explore/69300e7f000000001b02641b?xsec_token=…&xsec_source=pc_search`

## 一、先按用户要求把回包结构挖清楚（结论：**是抓取能力不足，不是解析漏了**）

| 接口 | 真机形状（2026-10-02 实测） |
|---|---|
| 列表 `/user_posted`（一条） | `note_id` / `type` / `time` / `xsec_token` / `display_title` / `cover.info_list[]`（**只有 `WB_PRV` 预览图**）/ `interact_info.liked_count` —— **没有 `desc`、没有 `image_list`** |
| 详情 `POST /api/sns/web/v1/feed` | `note_card`：`title` / **`desc`（正文全文，实测 237 字）** / **`image_list`（该帖 6 张**，每张含 `url_default`/`url_pre`/`info_list`/`width`/`height`/`live_photo`）/ `tag_list` / `ip_location` / `interact_info` / `time` / `last_update_time` |

⇒ 列表能给的我们**已经全取了**（上一刀 devlog/278 修的就是"取错位置"）；"只有一张图 + 没有文字"
是因为**列表接口本身不带**这两样。`xsec_source` 用 `pc_user`（token 来自主页列表）实测 200，
`pc_search` 也是 200。

## 二、改法

1. **详情补全**：新增 `XiaohongshuPlatform.fetch_post_detail()`（签名 POST `/api/sns/web/v1/feed`，
   走同一套 `identity_limit` 额度）与纯函数 `parse_note_detail()`（正文/多图/标签/IP/统计/时间）。
   入库路径**不用改框架**：`_fetch_platform_posts` 对新帖本来就会调 `pf.enrich(d, client=…)`
   —— 实现这个钩子即可（`enrich()` 把详情合并进 item；**详情拉不到就不动 item**，
   列表能给的数据照旧入库，绝不让"补全失败"变成"帖子丢失"）。
2. **链接**：`_explore_url()` 统一生成
   `…/explore/{note_id}?xsec_token=…&xsec_source=pc_user`（token 百分号编码）。裸链在小红书侧
   就是"当前笔记暂时无法浏览"；token 每轮抓取都会刷新进库，所以列表越新越打得开。
3. **已入库的旧帖**：新增一次性脚本 `scripts/backfill_xhs_details.py`
   （`--limit` / `--dry-run` / `--gap`，每条之间 1.5s，分批提交；只补"正文缺或图 ≤1 张"的），
   已在本机开发库跑过一遍。

## 三、判据与实测

- `tests/test_platform_xiaohongshu.py` 新增 3 条：⑬ 详情多图+正文+标签（真机形状）、

  另修一处：`enrich()` 里**任何异常都不许冒泡**（假 client 没有 `post` 时曾把整条帖子顶掉，
  端到端那条用例当场抓住）。
