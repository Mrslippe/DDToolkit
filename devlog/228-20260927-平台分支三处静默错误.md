# 228-20260927-平台分支三处静默错误

第 4 阶段的 ③（`EXECUTION.md` §1.4「调研结论回来后顺序固定为」第 ③ 条）：
**三处把平台口径钉死的分支**。它们只有 B 站一个平台时看不出来，而"即将接入小红书/抖音"
之后每一条都会变成**静默错误** —— 不报错、不抛异常，只是"结果少了一块"。

## 一、三条 bug 与修法

| # | 位置 | 症状 | 修法 |
|---|---|---|---|
| **A** | `capabilities._logged_in`：`return bili if platform == "bilibili" else weibo` | **任何**非 bilibili 平台都读**微博**的登录态 ⇒ 新平台一进来就谎报"可用" | 改成 `_login_states(bili, weibo)` 映射 + `.get(platform, False)`：未知平台**不假装**就绪 |
| **B** | `routers/vtuber.py::_require_content_fetch()` 写死 B 站（`content_fetch_allowed()` 无参） | `POST /vtuber/fetch-posts?platform=weibo` 是拿 **B 站**登录态放行/拦截的：B 站登录着、微博没登录 ⇒ **越权放行**；反过来误挡 | `content_fetch_allowed(platform="bilibili")` 按平台分派 + 原因也按平台给；`_require_content_fetch(platform)` 一路传下去（那 4 个 B 站专属端点保持默认值） |
| **C1** | `scheduler.platform_accounts_of`（原 `async_fetch_vtuber_posts` 内联过滤）与 `routers/vtuber.py:989` 的 `.isdigit()` | B 站口径（uid 是数字）混进**通用选号** ⇒ 微博账号被静默跳过，返回"什么都没有" | 只要求"有非空 uid"；数字那件事归 **B 站批量接口**（`split_numeric_uids`） |
| **C2** | `scheduler.live_sweep_core`（T0）：非数字 uid 的账号 `continue` 掉 | **连 `result.failed` 都不计** ⇒ 界面显示"全部成功"，而那个账号永远不出现在任何计数里 | 分成 `(可用, 不可用)`，不可用的**计进 failed + details**（§1.4 边界②："不支持"不许静默丢弃） |

**共同形状**：三条都是"少了东西但不报错"。所以判据必须钉**具体行为**（谁能过闸门 / 谁被选进来 /
谁被计成 failed），而不是"函数不抛异常"。

## 二、判据（`tests/test_platform_branches.py`，7 条）

- **A**：① 门禁 —— `FEATURES` 里每个平台都必须在 `_login_states` 里表态（新增平台时**红**，
  逼人做决定）；② 两个平台都登录着时未知平台也必须返回 `False`。
- **B**：③ 单元级（可注入版本，四种组合）；④ **端点级** —— `_require_content_fetch("weibo")`
  在"只有微博登录"时必须放行、`"bilibili"` 必须 403、默认值仍是 B 站口径。
- **C**：⑤ `platform_accounts_of` 必须选中非数字 uid 的微博账号（空 uid 仍不算）；
  ⑥ `split_numeric_uids` 要**交出**不可用的那批；⑦ **跑真函数** `live_sweep_core`：
  一个数字 uid + 一个非数字 uid ⇒ `success == 1` 且 `failed == 1` 且 details 里有原因。
- 顺带把 `tests/test_capabilities.py:42` 那条写死的平台元组换成"必须在 `_login_states` 里表态"，
  并把 5 处 `content_fetch_allowed` 替身改成接受平台参数（签名变了，`lambda: (True, "")` 会 TypeError
  —— 这也是"改了签名要过一遍所有调用方"的一次实证）。

## 三、反向验证四刀

| 刀 | 改法 | 结果 |
|---|---|---|
| A | `_logged_in` 退回 `else weibo` | 未知平台那条红 |
| B | 闸门忽略 platform（退回写死 B 站） | **端点级**那条红 |
| C | 选号退回 `.isdigit()` | 非数字 uid 那条红 |
| D | T0 退回静默丢弃 | `failed == 1` 那条红（实测拿到 `failed=0 details=[]`） |

⚠️ **刀 B 我又预判错了**（第三次了，值得记）：我以为会打中单元级那条，实际打中的是**端点级**那条
—— 因为单元级直接调 `_content_fetch_allowed_with(platform, …)`，**绕过了包装器**，
把包装器写死它照样绿。这恰好说明"端到端那条不是多余的"：**判据要覆盖"调用方真的把参数传下去了"
这一层**，而不只是"函数本身按平台分派"。
