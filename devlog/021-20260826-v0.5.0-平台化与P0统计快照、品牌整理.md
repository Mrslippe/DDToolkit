## 平台扩展框架与微博登录（WIP 收尾）

- `app/services/platforms/`：平台抽象（base / bilibili / weibo + registry），
  `scheduler._fetch_one_account` 改为按 `acc.platform` 分发抓取；
- 微博扫码登录：`weibo_auth.py`（Session v2 轮询）+ `routers/auth.py`
  （`POST /auth/{platform}/qr/start`、`GET /auth/{platform}/qr/check`、`GET /auth/{platform}/status`）
  + `env_store.py`（登录态 Cookie 持久化到 `.env`，含临时文件清理）；
- 配套：`fetcher._detect_rate_limit` 覆盖微博风控（HTTP 418/429、`{"ok":0,"msg":"…频繁…"}`）；
  `img_proxy` 防盗链 Referer（sinaimg/wbcdn → weibo.com，hdslb → bilibili）——此前微博图床全 403；
  前端 `LoginDialog`（react-qr-code）+ fetchBusy 全局忙态。

## 候选池 / 批量任务 / 自定义背景（WIP 收尾）

## P0 账号统计快照历史

**问题**：`accounts.followers_count` 每次抓取原地覆盖，涨粉曲线一旦没记就永远没了。

**实现**：
- 迁移 `e001`：新表 `account_stat_snapshots`
  （`account_id` FK 索引 + `captured_at` 索引；`followers_count` / `live_status` / `live_title` 快照字段）；
- 模型 `AccountStatSnapshot` + `AccountStatSnapshotRepo`（追加 / 倒序读取）；
- 写入时机：账号信息抓取成功后追加一行——`async_fetch_and_update`（全量）与
  `async_fetch_vtuber`（单 V）共用 `_record_stat_snapshot` 挂点，随事务一起提交；
- **定案（TODO 二选一）**：简单优先，**全量记录**（每轮成功抓取即写一行，数值无变化不降噪）；
- 只读端点备用：`GET /account/{account_id}/stat-snapshots?limit=`（默认 100，上限 1000，时间倒序），
  captured_at 与 PostOut 同样补 UTC 时区；本期不做可视化。
