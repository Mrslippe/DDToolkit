# 277-20261002 小红书 406 的真因：签名器与字段映射**从来没接上线**

> 接 `devlog/276`：那篇把 406 归到"dev 壳跑在系统解释器、没有 `xhshow`"。
> 那**不是**本次 406 的原因（那是个真实的隐患，壳也照修了）—— 真因是下面这两条：
> **签名机制压根没接到生产的那个实例上**，加上**账号信息的字段映射对不上真实回包**。
> 用户口径（2026-10-02 晚）：「小红书抓取还是失败，但是现在有日志了，显示 406 Not Acceptable」。

## 一、签名器：测试全注入替身，生产那个单例攥着 `NullSigner`

`app/services/platforms/xiaohongshu.py` 的模块级单例，正是注册表用的那一个：

```python
fetcher = XiaohongshuPlatform()          # ← 没有 signer
...
self._signer: Signer = signer or NullSigner()   # ← 于是它拿的是"不签名"
```

`NullSigner.headers()` 返回 **`{}`** ⇒ 请求**一个签名头都没有**就发出去 ⇒ 小红书一律 **HTTP 406**。

**它为什么能一路绿着**：`app/` 里**没有任何地方构造 `XhsSigner`**（grep 只有 `signing.py` 自己），
而测试**全都显式注入替身**：

```python
pf = XiaohongshuPlatform(cookies="web_session=xyz", signer=FakeSigner())   # 测试里到处都是
```

连端到端那条的注释都写着「适配器是注册表里的单例（**没有 cookie/签名器**）⇒ 换成注入了替身的
实例再跑」—— **缺口被看见了，但没有任何判据钉住它**。
（我自己的第一次核查也踩了这个坑：直接 `XhsSigner()` 手搓一个请求 → 200，于是误判"签名没问题"。
**核查生产行为必须用生产的那条路径**：`registry.get_fetcher("xiaohongshu")`。）

## 二、账号信息：字段映射按"文档想象"写，而这条路径**没有一条成功用例**

同一个文件里 `fetch_user_info` 读的是顶层字段（`nickname` / `fans` / `image` / `desc`），
真回包（2026-10-02 实测）却把它们放在：

```json
{"basic_info": {"nickname": "普通小栗", "desc": "还没有简介",
                "imageb": ".../w/540/format/webp", "images": ".../w/360/...", "red_id": "4970845138"},
 "interactions": [{"type": "follows", "count": "85"},
                  {"type": "fans",    "count": "32445", "i18n_count": "32.4K"}, ...],
 "posted": 35, "liked": 82609}
```

⇒ 昵称 `None`、头像 `None`、粉丝数 `0`：**账号信息写进库等于空的**（用户报的"账号信息也没有抓取到"）。
之所以没被发现：`tests/test_platform_xiaohongshu.py` 里关于 `fetch_user_info` 只有**两条失败用例**
（没 cookie / 签名器不可用），成功路径**一条都没有** —— 解析写错了没人会红。

## 三、改了什么

| 处 | 改动 |
|---|---|
| `XiaohongshuPlatform.__init__` | 默认签名器改成 **`XhsSigner()`**（懒加载，不拖启动）；注释写明这次的缺口 |
| `_signed_headers` | **签名器产不出 `x-s` 就一个字节都不发**：`last_error=signer_unavailable` + warning + 抛 `SignerUnavailable`（以前 `NullSigner` 静默返回 `{}`，"没接线"伪装成"请求正常、上游 406"） |
| `parse_user_info(data, uid)` | 抽出**按真回包形状**解析：`basic_info.{nickname,desc,imageb,images}` + `interactions[type=fans].count`（字符串、"32.4K"那种 `i18n_count` 不能用）；`还没有简介` 当空签名；主页 URL 用请求的 uid（不是 `red_id`） |
| 测试 | ⑩ 判据打在**注册表实例**上（带真签名器 + 离线签出 `x-s`）；⑩′ `NullSigner` 被拒且不发请求；⑪ 账号信息按真机形状解析 |

## 五、两条要带走的纪律

1. **替身注入 ≠ 接线正确**：只在测试里被注入的协作对象（签名器、时钟、客户端），
   必须有一条判据打在**生产真正用的那个实例**上（这里是注册表单例）。
   否则"测试全绿 + 线上全 406"可以同时成立，而且能活很久。
2. **成败两条路径都要有判据**：这次两个错里，签名器是"只有失败路径被测"，字段映射是
   "只有失败路径被测" —— 同一个盲区的两种形态。**新接一个平台时，"成功一次"必须是一条用例**
   （回包形状要照真机抓下来的写，别照文档猜）。
