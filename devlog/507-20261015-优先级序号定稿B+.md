# 507-20261015 优先级序号定稿 B+（素数字 + 首行竖条）

## 用户口径

看完 6 版方案稿后：「那就 B+」。起因是上一版那个 **实心粉圆圈 + 白字** 的序号
（用户原话：「这个序号好丑」）。

方案稿：`_probe/mockups/vod-account-priority.html`（6 版同结构对照 + 完整小窗预览）。

## 落地的三处

| | 旧 | 新 |
|---|---|---|
| 序号 | 18×18 实心圆、`#f1f4f8` 底；第一行 `--c-primary` 底 + 白字 | **素数字**：`width:12px; text-align:right; font-size:11px; color:#aab4c0; tabular-nums`；第一行 `--c-primary-deep` + 700 |
| 主号标记 | （同上一格的底色） | 第一行 **3px 主色竖条**（`inset box-shadow`）+ 极浅粉底 `#fffafc` + 粉描边 |
| 读屏 | 序号带 `aria-hidden` | 不变 —— 顺序由 DOM 顺序与上面那句「越靠上优先级越高」表达，念一串数字只会更吵 |

## 为什么是 B+ 而不是别的（备查）

- 数字是**拖动时唯一会变的东西** ⇒ 拖一下看见 1/2/3 重排，比"位置变了"更好确认自己拖对了；
- 竖条只标记**主号**，不跟数字抢注意力（只做竖条的 A 版在拖动时没有任何反馈）；
- `tabular-nums` 让数字换位不抖；不引入新的形状语言 —— 圆圈恰恰是浅色行里最跳的元素；
- 其余几版的取舍写在方案稿页尾（C 斜切签更"标签"但更吵、D 头像角标最省宽但 9.5px 会糊、
  E 拖动态才显形最干净但要让用户自己撞见、F 文字标签最好懂但最占宽）。

## 验证

纯 CSS + 一处注释改动，行为零变化：

- `vitest VodAccountDialog` **19 条绿**（序号仍在 DOM 里，`textContent` 含 `1` 的那条判据照旧承重）
- `tsc --noEmit` / `eslint --max-warnings 0` 干净
- 方案稿里 B+ 那一版的 CSS 与 `posts.css` 逐条对齐（同一份行结构渲染，看到的即落地的）

⚠️ 老规矩：`posts.css` 那里留了**墓碑注释**（"原来是实心粉圆圈，别再改回去"）——
这一族改回去不会报错，只会再被用户嫌一次。

## 追记：同批两条小修（用户看完真机截图后）

1. **输入框的示例里不许出现具体 mid**（用户：「不要用我测试给的这个例子」）：
   `placeholder` 从「B 站 mid 或主页链接，例如 94009831」改成「B 站 mid 或主页链接」。
   判据：`placeholder` 里不许匹配到 5 位以上数字 —— 拿某个具体号当例子，
   下一个人就会以为那是"标准示例"（而它只是我手上正好有的那个）。
2. **说明文字左侧空了一块**：`.lc-ms-hint` 带 `padding-left: 54px`，那是给
   `ManualSessionDialog` 的四行表单**对齐输入框左缘**用的（44px 标签 + 10px 间距）；
   本窗没有标签，照搬就成了一块莫名其妙的空档 ⇒ 加 `.lvc-acct-hint { padding-left: 0 }`。
   ⚠️ jsdom 量不到布局，所以判据钉的是**类名契约**（`className` 必须带 `lvc-acct-hint`）——
   同 `dialogLayer.test.ts` 那条"名单式"判据的写法。
