# 315-20261004 日志为什么这么多：47% 是 httpx 的逐请求 INFO（附一条我自己的假警报）

> 用户真机第二轮之后问「重新试了，为什么 log 会这么多」。这一次我直接读了
> `E:\test\DDToolkit-data\logs\app.log`（3482 行 / 1.06MB），按 logger 分组统计 —— 结论是
> **绝大部分根本不是我们的诊断**。

## 一、谁在写日志（实测占比）

| 来源 | 行数 | 占比 | 该不该留 |
|---|---|---|---|
| `httpx`（每个出站请求一行 `HTTP Request: GET https://…?e=…&sign=…`） | **1621** | **47%** | **纯噪音**：我们自己那行 `[视频代理] … range= status= 首字节= 均速= 共=` 信息更全；而且它**把带签名的完整 URL 写进了日志** |
| `app.services.scheduler`（后台抓取逐账号点名） | 754 | 22% | 抓取链路的正常记录（与本批无关） |
| `app.routers.video_proxy`（我们的诊断行，devlog/306） | 443 | 13% | **要留**：排查"CDN 慢 / 代理慢 / 浏览器"就靠它 |
| 其余（apscheduler / auth / main / 前端诊断行 …） | ~660 | 19% | 正常 |

⇒ 修法：`app/core/logging_setup.py::quiet_noisy_loggers()` 把 `httpx` / `httpcore` 压到
**WARNING**（超时、连接失败照样报），并**放在 `basicConfig` 之前**（与根 handler 是否生效无关）。
判据打在**行为**上：`not httpx.isEnabledFor(INFO)` 且 `isEnabledFor(WARNING)`（只断言常量的话，
把这一句从 `setup_logging` 里删掉也不会红）。

## 二、为什么"按段取数"本身也让请求变多（这是设计，不是 bug）

MSE 每 5 秒取**一段**（视频 ~2.2MB / 音频 ~0.11MB）⇒ 播放时约 **24 请求/分钟**、每请求 2 行
（httpx + 我们的诊断行）。旧内核把取数交给浏览器（Range 由它自己合并），请求数少但**我们看不见**。
⇒ 压掉 httpx 之后，播放一分钟大约 24 行（只占十几 KB），要更静才该动"我们的诊断行"，
但那行是 `devlog/306` 特意留下的证据（首字节/吞吐），**先不动**。

## 三、顺带抓到我自己埋的一个假警报

日志里出现两次（04:27:37/38）：

```
[media] 泵无进展(audio) 目标=75.9s 可用=14.3s 该轨末=223.6s 段=- 共取=34次/33.4MB
```

`可用=14.3s`、`该轨末=223.6s` —— 缓冲明明是健康的。"无进展"的刻度（`devlog/314` 加的刹车）
取的是"这条轨**最后一段的末尾**"，而**回跳之后缓冲里还留着远处那段**（223.6s）：
在播放点前面补数据永远不会让那个数变 ⇒ 连记三次"无进展" ⇒ **白刹车 2 秒**（真机上那 2 秒前方会饿）。
修法：刻度改成"**从播放点起连续能播多久**"（`runwayEnd`），并且只在 **append 的回执**上记账
（`remove` 会让跑道变短，那是淘汰的正常后果）；换目标时把记账清零、解除刹车。

## 四、这份日志对两个症状说了什么（用数字，不靠猜）

- 多数 MSE seek **正常**：`起播=0.4–1.3s`、`末缓冲=7–22s`、`判定=正常`；
- 两例 `判定=数据受限 起播=未出画 饿住=6–7次 卡帧=9s 末缓冲=0.0s`（03:48–03:49）——
  那是**修之前**的构建（`devlog/313`/`314` 的 `endOfStream` 与淘汰 bug 都在）；
- 一例 `判定=呈现受限(合成节拍) 最长停顿=2.68s 停顿次数=6`（04:11:40）—— 取数健康、缓冲 7.7s，
  卡在**呈现**那一段（合成器/GPU），不是取数；
- 两例 `内核=渐进 判定=呈现受限(解码器停：seek 后在追赶) 最长停顿=4.03s`（03:51/04:07）——
  这是**旧内核**的经典形状（`devlog/310`），也是我们要换掉它的原因。

## 五、判据

后端 +1（`httpx` 逐请求 INFO 必须静音，行为断言）；前端 +1（回跳后在播放点前面补数据
**不许**被判成"无进展"）。A 档门禁九步全过。
