# 678-20261027-采集链路：gzip 压缩 + simhash 草图 + 破坏性行为画像（方案 A+C）

用户定案 A+C：保留 `mh`、raw 压缩、去 `pl`；同时加 64 位 simhash 草图，为将来的模糊匹配留路；
并在采集时预计算"破坏性弹幕行为"画像（带版本号）。

## 一、磁盘

| 变化 | 效果 |
|---|---|
| `raw` 改写 `.json.gz`（gzip level 6） | 实测 **1023 KB → 93 KB（9.1%）** |
| 去掉死字段 `pl`（每笔金额，无人读取） | 未压缩 -2.2%（压缩后影响很小） |

> 注意：**删除 `mh` 只省压缩后 10%**（1.34 → 1.20 MB），却会永久失去"事后重算"能力，
> 所以保留 `mh` —— 磁盘收益来自压缩，不来自删字段。

## 二、为"模糊复制"留的备份：`msh`（simhash）

`mh` 只能判"完全相等"；「自动融入」这类脚本常做变体（加 emoji / 空格 / 改写）。
新增 `msh` 数组（与 `mh`、`mt` 一一对齐），用**字符 3-gram + 加权位投票**生成 64 位 simhash：

- 用 `zlib.crc32`（C 实现、跨进程稳定）打散 3-gram；
- 汉明距离 ≈ 文本相似度，将来可在 `msh` 上做模糊查重；
- 每条 8 字节，压缩后代价约 +10%。

## 三、采集时预计算：`stats.bp`

`_behaviour_profile()` 在聚合后扫一遍记录（实测 16.7k 条的场次 **34 ms**）：

```jsonc
"bp": {
  "version": 1, "window_ms": 5000,
  "copy_msgs": 2, "copy_ratio": 0.667, "users": 2,
  "top": [{ "uid": "...", "copied": 1, "msgs": 2, "ratio": 0.5,
            "targets": 1, "lag_med": 1500, "interval_cv": 0.0 }]
}
```

- `copy_msgs/copy_ratio`：被判"跟着别人发"的条数与占比；
- `targets`：复制了多少个不同的人；
- `lag_med`：源消息 → 复制消息的延迟中位数（脚本通常很稳定）；
- `interval_cv`：发车间隔的变异系数（越小越"规律"）；
- **`version`**：判据一变就 +1，旧数据可据此判断是否过期。

## 四、兼容

- loader 读 raw：优先 `*.json.gz`，回落 `*.json`（老数据不迁移）；
- 同时修掉一处**先验检查**只认 `.json` 的遗漏（`raw 缺文件` 的假警告）；
- 采集的"跳过已采"判断也认 `.json.gz`。
