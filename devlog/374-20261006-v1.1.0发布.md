## 二、发布前修掉的两处（`build` 组 / token 回显）

### ① 打包前的一致性复核少问了一个组

`release.py` 的 preflight 查 `python -m PyInstaller --version`（PyInstaller 住在 **`build` 组**里），
而 `build_backend.py` 的"环境与锁文件一致吗"跑的是**不带 `--group`** 的
`uv sync --frozen --dry-run`（默认只有 `dev` 组）⇒ 发布机上装好 PyInstaller 之后，那一步会回
`Would uninstall …pyinstaller…` 并判"环境漂移"：**preflight 要它、打包又不许有它**，
两条判据互相打架，发布必停（`devlog/197` 加这道守卫时留下的，之后没发过版所以没暴露）。

- **修**：复核命令改成 `uv sync --frozen --dry-run --group build` ——
  复核的集合必须与"本脚本真正需要的组"一致；修复提示也写成 `uv sync --group build`；
- **判据**：`tests/test_release_script.py::test_build_env_check_asks_about_the_group_it_needs`
  读源文件，断言 `--dry-run` 那一次调用里同时出现 `--group` 与 `build`；
  **反向验证**：把 `"--group", "build"` 从内存里的源文本删掉再跑断言 ⇒ `AssertionError`（实测）；
- **另一条环境事实（不改代码，记在这）**：`npm run build:backend` 里的 `python` 走 **PATH**，
  发布时必须把 `.venv\Scripts` 放最前 —— 否则 `_assert_locked_environment()` 会因为
  `sys.prefix` 不是 `.venv` 直接停（本机 PATH 上是系统 Python 3.14.1）。

### ② token 会被发布脚本自己打印出来

`push_with_retry` 走 token 时把 `https://x-access-token:<token>@github.com/…` 拼进**命令行参数**，
而 `run()` 会把命令原样 `$ ` 回显 ⇒ **token 会进发布日志**（终端滚回、"把报错粘给我看"
这两条路同样带出去）；git 失败时的 stderr 也常把带凭据的 URL 原样回显。
`RELEASE.md` §6.4 的原话是"进过日志即视为泄露"，而脚本自己正是那个出口。

- **修**：新增 `redact_secrets()`（把 `GITHUB_TOKEN` / `DDTOOLKIT_GITHUB_TOKEN` 的值换成 `***`），
  `run()` 的回显与 `push_with_retry` 的 tail / 失败日志都过它 ——
  **token 只从环境变量进，绝不从任何输出里出去**；
- **判据**：`tests/test_release_script.py::test_token_never_leaks_into_printed_commands` ——
  真的跑一条"会把 secret 原样打印出来"的命令，`$ 回显` 里不许出现它（只测 `redact_secrets()`
  本身，会漏掉"忘了在回显上调用"这种错法）；
  **反向验证**：把 `redact_secrets` 换成恒等函数 ⇒ 同一条命令的 token **确实出现**在回显里
  （实测），说明这条断言不是假绿。
