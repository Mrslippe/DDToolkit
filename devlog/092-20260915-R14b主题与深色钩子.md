## 一、"留钩子"具体是什么（不写清楚就等于没做）

| 钩子 | 落地物 | 深色落地时要不要改 |
|---|---|---|
| 偏好**真的存** | `app_meta` 的 `prefs.theme`（`light \| system`，后端枚举白名单）+ `GET/PUT /settings/prefs` | 不用（多一个 `dark` 取值即可） |
| 解析逻辑 | `utils/theme.ts::resolveTheme(pref, systemDark)` | **只改它**：把 `DARK_IMPLEMENTED` 翻成 true |
| 根元素通路 | `applyTheme()` 写 `html[data-theme]`；`tokens.css` 末尾已有 `:root[data-theme='dark']` **空块** | 填那个空块里的令牌 |
| 真·跟随系统 | `watchSystemTheme()` 订阅 `prefers-color-scheme`，系统切换立刻重解析 | 不用 |
| 图表 | （本批不碰） | ECharts 按 `data-theme` 切双主题（`utils/chartTheme.ts`） |
| 逐屏走查 | （本批不做） | 按 UI-MAP 的对比度口径过一遍 |

## 二、深色为什么不能"顺手做掉"

三个 CSS 里**硬编码色值 243 处（146 种）**（`layout.css` / `posts.css` 为主），
外加 ECharts 图表主题与若干内联样式。只把 `:root` 的令牌换成深色，那些硬编码色
会在深底上刺眼甚至不可读 —— 用户看到的不是"深色主题"，是**半黑不黑**。
把 243 处收进令牌是纯机械但必须逐处确认的活（还要判断每一处该对应哪个语义令牌），
与"主题切换逻辑"混在一批里，两边都会做不干净。下一批的路径写在那个空块上方。

## 三、三处判据（都有单测/探针）

1. **`system` 在深色未实现时必须解析为浅色**（`DARK_IMPLEMENTED=false`）：
   挂上 `data-theme="dark"` 却没有任何规则认它 = 用户"切了没反应" —— 比明说没做更糟。
   单测钉住解析结果，探针钉住 `html[data-theme]` 实际值。
2. **该说的实话必须说**：系统是深色 + 偏好是跟随系统 + 深色未实现 ⇒ 界面显示
   「系统当前是深色，但深色主题尚未实现 —— 现在仍按浅色显示（偏好已记住）」。
   不说的话，用户会认为"跟随系统"坏了。
3. **跟随是真的跟随**：`watchSystemTheme` 订阅 `matchMedia` 变化并在卸载时解绑
   （只订不解会随窗口重挂叠加监听）。

## 四、一条跨语言契约（这一批特有的护栏）

「深色到底做没做」这件事同时存在于两个语言里：前端 `theme.ts::DARK_IMPLEMENTED`
（决定解析）与后端 `/settings/prefs` 下发的 `note`（决定界面上那句说明）。
两边不一致的两种坏法都很难看：
- 钩子还是 false 却不说"尚未实现" → 用户以为「跟随系统」坏了；
- 深色已经能做却仍写着"尚未实现" → 用户根本不会去试。

所以 `tests/test_runtime_settings.py::test_dark_theme_hook_flag_matches_what_the_ui_tells_users`
直接读 TS 文件里的那个布尔，与后端 `_theme_note()` 对账 —— **改一边不改另一边就红**。

## 六、顺带修掉 R12b 留下的一条**不稳定判据**

收尾跑全量探针时，`--status-island` 的 chevron 断言两次跑出不同结果：
一次 `matrix(-1, 0, 0, -1, 0, 0)`（翻转），一次 `matrix(1, 0, 0, 1, 0, 0)`（identity）。
查下去是**两件事叠在一起**：

1. 判据太松：只判 `!= none`，于是"过渡中途的 identity 矩阵"也算通过 ——
   它其实等于"箭头没指成可收起"，正是这条断言想拦的；
2. 量法不对：`transition: transform .2s` 在**虚拟时间**下会被冻在中途，
   直接读计算样式读到的是**过渡进度**，不是"规则有没有生效"。
   （`--settings` 那条探针早就踩过同一个坑，做法是"量之前先注入 `animation:none; transition:none`"。）

改成：先读过渡时长，再注入 `transition:none !important` → 强制重排 → 读终值 → 移除注入；
判据收紧到"必须是带 `-1` 的矩阵"。修完连跑三次结果一致（reduce 支也复验过：翻转保留、过渡 0ms）。
**教训**：量"有没有生效"要先把动画/过渡这条通路掐掉；量"动画对不对"才需要它开着 ——
两者混在一起，就会得到一条时绿时红的护栏。
