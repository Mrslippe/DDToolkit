# 447-20261008-词云词典空闲卸载（−50.6MB）

TODO §1 的「词云词典空闲卸载」，用户 2026-10-08 点名做。「−55MB 常驻」的记账从 R24a 起就挂在
`PERF.md` 的优化候选里（"只记账不删"），本条把它落地。

## 缺口是什么

R24/T2（`devlog/117`）只是**取消了启动预热** —— 解决了"没人用词云时不要占那 56MB"，
**没解决"用过一次之后永远占着"**：看一场直播的词云，那本前缀词典就一直在进程里。

## 改法：状态机 + 一次性定时器（都在 `danmaku_words.py` 里）

- `JiebaTokenizer` 记 `_last_used`（每次 `cut`/`add_words` 都刷），并在每次使用后**重新武装
  一个 `threading.Timer(TOKENIZER_IDLE_SEC)`**；到点仍没人用 ⇒ `release()`；
- `release()` 只动 jieba 的三样：`dt.FREQ = {}`（**那 56MB 就是它**）、`dt.total = 0`、
  `dt.initialized = False` —— 于是下次 `cut` 时 jieba 自己的 `check_initialized()` 会重建。
  **不动 `_impl` 与 `dictionary`**：模块很小、路径还要用。
- `TOKENIZER_IDLE_SEC` 默认 **600s**（连续看几场词云不该反复重建），
  `DDTOOLKIT_TOKENIZER_IDLE_SEC` 可覆盖（探针/真机验收要压到几秒才量得到），**设 0 = 关掉这个机制**。
- 为什么用一次性定时器而不是轮询线程/挂调度器：**自带驱动、不欠别人的账** ——
  词云端点在没有调度器的脚本里也能用；状态机本身可以注入假时钟做确定性判据。
- ⚠️ **释放不是降级**：下次仍然走 jieba（多等一次 ~0.6s 重建），**不会**退回正则分词。
- ⚠️ 释放会丢掉 `add_word` 灌进去的词 ⇒ 必须**重灌**（`_applied_words`），否则主播名又被切碎
  （`routers/vtuber.py` 里那条注释说的正是这个）。

## 判据（`tests/test_danmaku_words.py` 新增 8 条，22 → 30）

★超时真的释放（`FREQ` 空掉 + `initialized` 落下）＋**正对照"没超时不许动"**（少了它，
"释放了"与"永远释放"分不开）；★**释放不是降级**（重建后结果逐字一致）；★**自定义词不丢**；
★定时器真驱动到点释放且**再用一次会重新武装**；`TOKENIZER_IDLE_SEC=0` ⇒ 永不释放；
没加载时 `release()` 返回 False 且幂等；状态可观测（`tokenizer_state()`）；
★**切词途中绝不许释放**（见下）。

⇒ 正对照那条红；`_touch` 不武装定时器 ⇒ 定时器那条红；去掉"在途"保护 ⇒ 并发那条红。

## 写完才发现的一个真并发窗口（补了保护 + 用例）

第一版只有"空闲到点就释放"，没有"**此刻有没有人在切**"这一问。真实的坏时序是：

> 定时器在 T+600s 醒来 → 某个请求**刚好**开始切词（还没走到结尾那次刷新时间戳）⇒
> `release()` 把 `FREQ` 抽空，而这次 `lcut` 已经过了 `check_initialized()` ⇒
> **不抛错、但整句被切成单字** —— 用户看到的是"词云全是单字"，而日志里干干净净。

修法两条：① `cut()` **进函数就**标"在用"（`_in_flight += 1` + 刷时间戳），`finally` 里还回去；
② `release()` 在 `_in_flight > 0` 时直接拒绝（切完还会再武装定时器，所以不用担心它被永远推迟）。
用例用真线程把那次 `lcut` 卡在事件上，期间调 `release_if_idle(阈值给满)` 与 `release()` —— 都必须返回 False。
