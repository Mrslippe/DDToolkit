# 688-20261027-测试分三层：L1 合成夹具 + L2 快照 + L3 不变量

用户问"黄金值还有什么用"之后定下的结构调整。

## 三层分工

| 层 | 文件 | 钉什么 | 重采后要重录吗 |
|---|---|---|---|
| **L1 合成夹具** | `tests/test_fan_fixture_golden.py`（新） | 完全合成的 `Window`（20 用户 / 8 场）→ 池、类型分布、强度前 3 | **永不** |
| **L2 真实快照** | `test_fan_compose.py` / `test_fan_loader.py` | 真实数据的绝对值 | 每次重采 |
| **L3 不变量** | `tests/test_fan_invariants.py`（新） | 只钉**关系**，不钉数值 | **永不** |

## L1 覆盖与短板

夹具锁定：ACV 池裁剪（20 → 18）、核心度排序、类型判定（出勤/参与度/综合）。
**付费轴没有被独立成类**（夹具的付费结构还不够复杂），已在该文件注释里写明 —— 这块由 L2 兜。

## L3 的五条闸

1. 每场 **C1 内部恒等式**（raw 现算 vs stats 声称）；
2. **全局 Σ 一致性**：各用户聚合之和 == 各场求和（两条独立路径）；
3. **池占比**落在 `[0.5%, 20%]`（实测 2.7%–2.9%）；
4. 每场 **coverage ≥ 95%**（采集完整性的最后一道闸 —— 就是它能抓住"每场缺 5,000 条"那类问题）；
5. 类型分布**单一标签不超过 85%**（防分位/阈值写坏）。

> 初次运行把池占比下限写成了 5%，三条直接红 —— 实测 2.9%，是**边界写错**而不是数据错。
> 已按实测改成 0.5%–20%，并在注释里留下实测区间。

## 效果

- 改模型 → L1 立刻红（不用等重采）；
- 重采丢数据 → L3 的 coverage/Σ 一致性红（不会被"重录黄金值"掩盖）；
- 数据自然变化 → 只有 L2 需要重录，范围明确。
