# 574-20261020-采集写入 64 位文本哈希（mh）

用户要求：先做"采集时写入 64 位文本哈希"，好让**去重规则以后再定**也不耽误数据。

## 改动

`collector.aggregate` 的弹幕分支里，把归一化文本的 **blake2b/64 位哈希**追加到 `mh`，
与 `mt` **一一对齐**：

```
txt = _norm_text(message)      # 去首尾空白、空白压一格、全角空格视同空格
u["mh"].append(_hash_text(txt)) # 空文本写 0 占位，保证与 mt 等长
```

- **必须用 blake2b**，不能用内置 `hash()`：后者受 `PYTHONHASHSEED` 影响，**每个进程都不一样**，
  跨次采集无法比对；
- 只哈希**归一化后**的文本：空白差异被抹平，但大小写、标点、emoji 仍然区分；
- **原文不落盘**；`m`（原始条数）、`uniq`、`maxrep` 全部照旧，互不影响。

## 为什么值得现在做

现有 227 个 raw 文件里 **0 个**有 `uniq`，库里也没有弹幕文本表 ⇒ 旧数据**永远无法**重算去重。
现在开始写哈希，意味着：**无论将来把规则定成什么样（精确 / 归一化 / n-gram / 前缀），
都能在哈希序列上离线重算，不必重新采集。**

存储代价：每条 8 字节；一场几万条也就几百 KB，相对于已有的 `mt` 数组可忽略。
