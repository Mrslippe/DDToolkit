# 431-20261007-单推模式的沉浸视觉（分段收起 + hover 唤出 + 延时淡出）

用户口径（2026-10-07，四条）：

> 1. 左栏的收起展开是**常驻功能**，不管展开还是收起，提手都**自动隐藏**，hover 到那个区域才显示
> 2. 点单推 ⇒ **固定动画流程**：先左栏向左收起 → 然后左侧工具栏 → 最后顶栏，都带缓动曲线
> 3. 全收起之后**如果当时在 card 视图** ⇒ 一段时间之后降低页面元素透明度与白色遮罩透明度，让背景图完全显现
> 4. 单推模式下顶栏与左侧工具栏都能用**鼠标 hover 唤出**

## 改了什么

- **收起手法换成负外边距**（`width: 0` → `margin-left: calc(-1 * var(--sidebar-width))`）：
  只有位移能**动画**，而且被推出的那一栏**原样留在 DOM 里** —— "v 列表不变化"这条顺带更稳
  （原来靠 `display: none` 藏子元素，现在是整栏平移出去）。
- **拉手常驻 + 两种状态都常态隐藏**：不再只在单推里存在；`opacity: 0` 但**始终可命中**，
  `::after` 把命中区向外扩一圈；悬停/键盘聚焦才现身。展开态**取消了**原来的常驻半透明。
  偏好落在 `utils/railCollapsed.ts`（`ddtoolkit.rail.collapsed`）⇒ **单推不改这份偏好**，
  于是"退出回到进入前的状态"仍然成立（`collapsed = 单推强制 ∨ 用户手动`，`peek` 临时展开）。
- **分段收起**：`transition-delay` 递增（左栏 0 → 工具栏 1 段 → 顶栏 2 段），
  **退出倒着来**；每段 `--solo-step: 260ms` + `--solo-ease`。⚠️ **不写 JS 状态机** ——
  顺序本身就是"固定流程"，CSS 表达得住，也就没有"动画跑到一半组件卸载"的问题。
- **hover 唤出**：`.app-shell` 开头两条**贴边窄带**（顶 10px / 左 10px），
  靠 `~` 兄弟选择器把顶栏/工具栏的位移拨回 0；⚠️ 唤出必须把 `transition-delay` 归零，
  否则那几段延时会让唤出慢半拍。⚠️ 窄带必须排在被唤出的元素**之前**（`~` 只认后面的兄弟）。
- **延时淡出**：全收起后再等 `--solo-fade-delay: 2.4s` ⇒ 页面元素淡到 `--solo-dim: 0.12`、
  白纱罩撤到 0（背景图完全显现）。⚠️ **只在 cards 视图**（`PostsPage` 新挂 `data-view`）——
  别的视图没有 hero，内容淡掉就只剩一张背景。⚠️ 背景层本身被 `:not(.hero-backdrop)` 排除。
  唤出顶栏/工具栏时，四条兄弟选择器把两个变量拨回 1 且延时归零 ⇒ **立刻恢复可读**。

## 三个可调的数（都在 `layout.css` 的 `:root` 里）

`--solo-step: 260ms`（每段时长）· `--solo-fade-delay: 2.4s`（全收起后等多久才淡出）·
`--solo-dim: 0.12`（淡到多淡）。**视觉效果只能靠你自己的眼睛定**：判据钉的是"规则在、顺序对"，
节奏与深浅改这一行即可。
