# 360-20261006-浏览器扩展E4扩展本体

> E1/E2 见 `devlog/358`、E3 见 `devlog/359`。本篇是执行方案
> `docs/plans/browser-extension-cookie-sync-execution.md` 的 **E4**（收口批）。

## 一、交付了什么

`extension/`（仓库根，**第四个宿主**，零构建、零 npm 依赖）：

| 文件 | 作用 |
|---|---|
| `manifest.json` | MV3；权限只有 `cookies` + `storage`，`host_permissions` 只有四个平台 + `http://127.0.0.1/*`；**没有** content script / `tabs` / `scripting` |
| `src/logic.js` | **纯逻辑**（不许 import `chrome.*`）：cookie 拼接、缺键判定、请求体、回执文案、端口探测、状态码人话 |
| `src/popup.js` | 只碰 `chrome.*` 与 DOM：四行（键数/长度/缺哪个）+ 每行同步 + 顶部「同步全部四个平台」+ 设置（端口/token） |
| `popup.html` / `popup.css` | 320px 浮窗，与应用浅色浮片同族 |
| `README.md` | 装法 + **10 条手工验收清单** + 已知缺口 |
| `test/logic.test.mjs` | 14 条 `node --test` |

## 二、判据分三层（因为扩展本体没法在 CI 里驱动）

1. **纯逻辑**（`node --test extension/test/*.test.mjs`，**已进 A 档门禁**，~0.3s）：
   拼接保序/不去重（同名不同 path 是两条）、缺键（含抖音 `uifid`/`UIFID_TEMP` 两写法）、
   请求体（UA 只在抖音带）、回执文案、端口探测（认 `app` 标识、命中即停、非 JSON 换下一个）、
   POST 头正确。
2. **清单对账**（同文件最后一条，读**后端源码字面量**）：配对头名 · 应用标识 ·
   端口候选（与壳的 `PREFERRED_PORTS` 逐个相同）· 四个平台 key · B 站/微博必需键 ·
   小红书/抖音必需键在后端源码里存在 · 微博 URL 必须是 PC 域 · `logic.js` 代码里不许有 `chrome.*`。
   ⇒ **后端加了必需键而扩展没跟上**（症状是"同步成功但抓不到"）会被这条拦住。
3. **接线端到端**（`scripts/extension_smoke.py`，**已进 A 档门禁**，~10s）：
   临时数据目录起后端 → `/healthz` 认领 → `/auth/pairing`（没带应用 token 必须 401）→
   四平台导入（小红书/抖音走离线校验成功；B 站/微博判缺键 400，**不碰真上游**）→
   回执不泄值 → `.env` 落盘 → 错 token 401。
   ⚠️ 后端起在**随机端口**：`8765–8769` 上可能坐着**用户正在用的应用**，冒烟不去抢。

## 三、两条落地时的取舍（先在方案里改了，再实现）

- **`manifest.key`（稳定扩展 id）没写**：生成合法 SPKI 要工具链，而 P1 没有"自动化驱动 popup"
  的需求 ⇒ 搁置，缺口写进 `README.md` 与执行方案 §3.6；
- **没有图标**：不放假占位图，`manifest.json` 不写 `icons`（工具栏显示默认图标），上架前再补。

## 四、门禁变化：12 → **14 步**

新增 `extension logic`（通用步骤，三档都跑，实测 <1s）与 `extension smoke`（A 档，实测 **2s**）。
后者的理由与 `--app-settings`/`--notice-lab`/`--first-run` 那三条同源：
**没进门禁的检查会烂掉**；而扩展的接线（认领→配对→导入）恰好是"三处字面量必须对齐"的地方。

## 五、验不了的部分

- **真浏览器里 `chrome.cookies` 读 HttpOnly + 扩展页面 fetch 到回环不被拦**：只能真机判，
  写进了 `README.md` 的手工清单第 1 条（**这也是执行方案 §5 的第 1 条停止条件**）。
- 真上游验收（同步完立刻抓一次内容）：同样只能真机判（清单第 1/3/4 条）。
