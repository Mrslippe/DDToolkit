# 358-20261006-浏览器扩展E1配对令牌与凭据导入端点

> 用户 2026-10-06：「开工吧，按批次执行，有问题再问我」—— 执行方案
> `docs/plans/browser-extension-cookie-sync-execution.md` 的 **E1**（后端地基）。

## 一、这一批解决什么

| 平台 | 改动前 | 改动后 |
|---|---|---|
| B 站 | **只有扫码**（浏览器里已登录也得再扫一次）| `apply_cookie_checked()`：解析整条 cookie → 打一次 `nav` → 有效才落盘 |
| 微博 | `apply_cookie()` **不校验**（直接 `_valid = True` + 落盘）| 补探活：上游 `ok=-100` ⇒ 不落盘 + 内存还原 |
| 小红书 / 抖音 | 已有键校验（本次直接复用，一行没改）| 走同一个端点、同一张回执 |

新增三个端点（`routers/auth.py`）：`GET /auth/pairing`、`POST /auth/pairing/reset`、
`POST /auth/import`；两个新模块（`services/pairing.py` 配对凭证、`services/cookie_import.py`
导入链 + 回执）与一个小工具（`services/cookie_parse.py`，cookie 串解析）。

## 二、三条要留档的决定

1. **配对令牌必须是"另一把钥匙"**：`X-DDToolkit-Token` 是 Tauri 每次启动生成、只给自家前端的
   **整机 API 钥匙**。扩展只需要"写一次凭据"⇒ 另发一把（`app_meta` 的 `pairing.token`，
   `token_urlsafe(32)`，**持久**、可重置），走独立头 `X-DDToolkit-Pair`。
   由此 `POST /auth/import` 只能进 `PUBLIC_EXACT`（中间件放行、**凭证自带**），
   端点自己再加回环来源与失败节流（60s 内失败 ≥10 ⇒ 429）。
   ⚠️ 那条"公开白名单必须只有这几类"的用例就是为这种时刻写的 —— 它当场红了，逼着写清理由。
2. **"上游说未登录" ≠ "连不上上游"**：前者拒收（400）+ 内存与 `.env` 双还原；
   后者**照样保存**但 `verified=false` + note 如实说"没验成"。
   理由：今天的手抄路径**根本不校验**，网络抖一下就拒收是倒退；但也不许假装验过了。
3. **回执只给键名与数量，绝不回显值**（值进日志/界面 = 二次泄露）；成功与失败**同一形状**
   （失败是 400 而不是 500 —— "缺键/过期"是正常的业务结果，用户要看的是"缺哪个"）。

## 三、两个假绿通道（都当场抓到）

- **`TestClient` 的 `client.host` 是 `"testclient"`**，而第一道门就是回环判定 ⇒ 首跑 17 条里
  17 条 403。修法是夹具显式给 `client=("127.0.0.1", …)`，**不是**把 `is_loopback` 放宽成
  也认 `"testclient"`（那是拿产品代码迁就测试）。
- **conftest 会给每个 `TestClient` 默认塞上正确的应用 token** ⇒ "配对 token 不能当应用 token 用"
  那条断言不换客户端的话，证明的是"夹具给了 token"。第一版就是这么假绿的。

## 四、反向验证（拆掉守卫必须红）

- 拆掉 B 站的**内存还原** ⇒ `test_bilibili_expired_cookie_is_rejected_and_rolled_back` 红（实测）；
- 拆掉端点里的 `pairing.verify(...)` ⇒ **7 条**红（含 `test_api_auth.py` 里那条"公开但不设防"）；
- 拆掉 `.env` 不动那条判据的写法：`before/after` 比的是**字节**（不是"存在与否"）。

## 五、顺带修掉的跨用例串味（真因值得记）

`env_store.save_env_keys()` 除了写文件，还会 `load_dotenv(override=True)` +
**`setattr(settings, key, …)`** —— 而 `settings` 是**类属性** ⇒ 新用例真的走了落盘路径之后，
"用例编的假凭据"会留在类上，**下一个测试文件**就带着它跑。
实测：`test_auth_import.py` 排在 `test_platform_douyin.py` 前面时，后者两条红在
"应该是零请求却发了请求 / 失败分类不是预期那一种"。
⇒ conftest 新增 `_credential_settings_survive_env_writes`（每条用例后还原那 14 个凭据类属性）。
同类先例是 `devlog/353` 的"用例写坏了仓库根 `.env`"——**同一个根因的第二种表现**。
