# 728-20261028-一进工作台就"自己在分析"：两处自动触发（真根因）

## 用户报的现象

> 我还没点分析，只切换页签出现这个情况了

截图：结果区是空态骨架，标题行写着「分析结果 **正在分析… 已用 25 秒 / 预计 10 秒**」，
读数胶囊 `窗口场次 25 / 已有 24 / 待采 1`，细进度线在跑。

这条把上一篇（`devlog/727`）留下的疑点彻底钉死了：**不是渲染问题，是页面自己在发起计算。**

## 根因：两处自动调 `loadRanked`

| 触发点 | 时机 | 为什么是错的 |
|---|---|---|
| `tagFilter` 的 `useEffect`（`loadRanked(byOf(tab), …)`） | **组件挂载就跑一次**（`tagFilter.join('|')` 的初始值就是一次变化） | 一进工作台就发起完整计算（后端 `_compute` 冷启动 20–40 秒）。用户看到的就是"我没点分析，它在分析" |
| `onTab`（切页签） | 每次点页签 | 没分析过也会发起完整计算；而用户的心智是"切页签只是换看哪个轴" |

两处叠加的结果：**切个页签等于悄悄跑一次分析**，而且失败/慢的时候页面只剩空壳 + 一条"正在分析"。

## 修法

1. 新增 `analyzedRef`（用户是否**主动发起过**分析）：
   - `loadRanked` 真正发请求时置 `true`；
   - `onTab` 与标签 effect **只有 `analyzedRef.current` 为真时才跟着刷新** ——
     否则只切 UI（空态那张卡的标题本来就跟随页签，所以"切页签有反应"这件事仍然成立）；
   - 主动发起的入口保持三个：页面「分析」、浮窗「分析」、大窗口确认。
2. **忙态文案分三档**（原来把"取数中"也叫"正在分析"，误导）：
   | 状态 | 文案 |
   |---|---|
   | 采集任务在跑 | 正在采集弹幕… |
   | **分析任务在跑** | 正在分析… `12/25 场`（用任务进度，不用估算） |
   | 只是取数（`busy`） | 正在读取结果… 已用 `N` 秒 |
   | 都没有 | 尚未分析 |
3. 细进度线也跟着区分：分析任务有 `done/total` 就显示百分比，没有就流动。
4. **空态正文按状态给下一步动作**（原来永远写"请先进行采集"，而界面明明显示"已有 24 / 待采 1"，自相矛盾）：
   | 状态 | 提示 |
   |---|---|
   | 采集中 | 采集完成后点「分析」 |
   | 分析中 | 分析进行中，算完后这里会直接显示结果 |
   | 取数中 | 正在读取结果… |
   | 还有待采场次 | 当前窗口还有 N 场没采集 —— 先点「采集」 |
   | 都采完了 | 点「分析」生成名单与图表 |
