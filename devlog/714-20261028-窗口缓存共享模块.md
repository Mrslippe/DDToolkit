# 714-20261028-窗口缓存抽成共享模块（三个文件共用一份窗口）

## 1. 上一轮的估算错了，先纠正

`devlog/713` 只给 `test_fan_invariants.py` 单独加了缓存（879 s → 119 s），并估了一句
"同样手法搬到 checks / timeline / loader，能再压到 2 分钟出头"。**真去看调用点，这个估算不对**：

| 文件 | 真实调用形态 | 能不能靠"共享同一份窗口"省时间 |
|---|---|---|
| `test_fan_invariants.py` | 9 条 × 4 V = 36 次，**同一个窗口**反复要 | 能（已做，713） |
| `test_fan_checks.py` | 一条用例里 `for v in VTUBERS` 连加载 4 个；另一条要 `弥月`；还有一条要 `明前 n=400` | **部分能**（4 个窗口与 invariants 完全重合；`n=400` 是另一个窗口，不能共享） |
| `test_fan_loader.py` | 4 个 V 的**冻结窗口**（`until=FROZEN_UNTIL`）+ 一条 `弥月`（不冻结） | **几乎不能**：冻结窗口在键上与 invariants 的窗口不同，那 5 次加载省不掉 |
| `test_fan_timeline.py` | 走 `/fan/…/timeline` **端点**，内部自己 `load_window` + 路由器 `_CACHE` | **不能**：测试层拿不到端点内部那次加载 |

所以真实可省的是 **checks 的 5 次加载 + invariants 的 4 次**。另外发现一个更值的点（见 §3）。

## 2. 抽出 `tests/fan_window_cache.py`

```python
from tests.fan_window_cache import window as _window
w = _window("弥月")                                  # 最近 75 场
w = _window(v, 75, until="2026-10-26")               # 冻结窗口，键里带着 until
w = _window("明前奶绿", 400, require_entry=False, min_records=0)
```

三条设计纪律（都写进了模块 docstring）：

1. **键必须含窗口身份**：`(subdir, n, since, until, live_ids, require_entry, min_records)`。
   少一项就会串味 ——「最近 75 场」与「截至 2026-10-26 的最近 75 场」是两个窗口，
   而分位是**窗口内相对**的（`devlog/712` 的教训：绝对值不冻结就没有意义）。
   这条不是理论洁癖：`loader` 里那 4 个冻结窗口与 `invariants` 里的同 V 窗口**长得很像但不同**。
2. **`vtuber` 要归一成 `subdir`**：`_window("弥月")` 与 `_window(VTUBERS[0])` 否则会各存一份
   同一个窗口 —— 既不省时间，还把内存翻倍。（已实测两者产出同一键。）
3. **不收 `root=`**：键里没有任何路径信息，若允许传 `root=tmp_path`，临时目录的窗口会与真实
   数据的窗口撞进一个键。`test_fan_loader.py` 里几十处合成数据集**继续直接调**
   `load_window(..., root=…)`，不走这个缓存。

容量 **4 + LRU**（一个文件的完整工作集就是 4 个 V），峰值内存仍 ≈1.17 GiB 不变 ——
换了更多命中，但没有多占内存。逃生阀保留：`DDTOOLKIT_FAN_TEST_NO_CACHE=1`。

## 3. 顺带砍掉一次"为了 skip 而付 50 秒"

`test_real_data_tiny_session_dropped_when_not_prefiltered` 原来的顺序是：

```python
w = load_window("明前奶绿", 400, require_entry=False, min_records=0)   # ← 把该 V 四百场 raw 全解析
...
if not tiny: pytest.skip("当前数据集里没有 records<100 的场次")          # ← 才发现前提不成立
```

也就是说：**每次全量跑都要先付约 50 s，然后跳过**。现在把前置检查提到加载之前 ——
读 400 个小 `stats/*.json` 只要几十毫秒：

```python
if not _stats_have_tiny_records(get_vtuber("明前奶绿").subdir):
    pytest.skip("…（前置检查，未加载窗口）")
```

⚠️ 前置检查的门槛故意比断言宽（**150** vs 断言的 **100**）：宁可多跑一次昂贵加载，
也不要在字段口径差一点的时候**跳过一条本该跑的断言**。

## 4. 结果

三个文件（按全量里的实际顺序 checks → invariants → loader）：

| | 之前 | 现在 |
|---|---|---|
| `test_fan_checks.py` + `invariants` + `loader` | 约 350 s（18 次加载） | **200.59 s**（9 次加载 + 1 次跳过不再付加载费） |

`--durations` 的分布也说明缓存起作用了：唯一的 88.10 s 是
`test_real_data_c1_never_drops`（它一个用例里连加载 4 个窗口，是**第一**个碰数据的），
之后 `invariants` 的 36 条全部 <1 s，`loader` 剩下 4 次冻结加载 + 1 次 `弥月`。
