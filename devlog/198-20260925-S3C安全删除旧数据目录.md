# 198-20260925-S3C安全删除旧数据目录（junction 实验推翻了规格一处假设）

用户口径：「接着开」。本批只做一件事：**把"删旧数据目录"从"单击即删、四道判据全可绕"改成
"一次性票据 + 五道判据 + 二次确认"**。这是全应用**唯一一处不可逆操作**（没有回收站、没有撤销）。

## 一、开工先做实验，而实验推翻了规格的一处假设

规格（`ARCHITECTURE-IMPROVEMENT-PLAN.md` §S3-C）要求"拒绝 symlink/reparse point"，
而本仓自己的停止条件里写着「**无法可靠识别 reparse point**」—— 所以先写了一个一次性
`rustc` 探针（跑完即删）在本机实测三件事：

| 问题 | 实测结论 |
|---|---|
| `symlink_metadata` 认不认 junction | **认**：`is_symlink()=true`、`is_dir()=false`。而 `metadata()`（跟随）说 `is_dir()=true` |
| `canonicalize` 会不会解开 junction | **会**：junction 与它的目标 canonicalize 结果**完全相同** ⇒ 拿它当判据能识破"用 junction 冒充旧目录" |
| `remove_dir_all(junction)` 会怎样 | **不穿进目标**：junction 被删掉，目标目录与内容**完好无损** |

⚠️ **第三条推翻了规格的隐含恐惧**（"删链接会毁掉目标"）。真正的风险不是删链接，
而是**判据被绕过之后直接删到活目录**。另外 `mklink /D`（符号链接）**需要管理员特权**，
`mklink /J`（junction）**不需要** ⇒ 普通用户能造的只有 junction，**威胁模型以它为主**。

## 二、改造前的四道判据，逐条可绕

```rust
if path == cur { ... }                                   // ① 裸 PathBuf 相等
if !path.is_dir() { ... }                                // ② 跟随链接
if !path.join("vtuber.db").exists()
   && !path.join(".env").exists() { ... }                // ③ `||`：.env 命中就够
std::fs::remove_dir_all(&path)                           // ④ 无任何链接检查
```

①比不出 `..` / 大小写 / 8.3 短名 / 尾随 `.`（四种等价写法本机实测都能造出来）；
③意味着"任意含 `.env` 的目录"都能删。**合起来：传一个指向当前数据目录的 junction，
就能让正在被 SQLite 使用的活目录进入 `remove_dir_all`。**

## 三、改了什么

- Rust：`MigrateReport` + `migration_id`；迁移成功后把 `{canonical_path, id}` 记进
  **内存**（`MigrationRecord`）。`delete_old_data_dir(id)` 按 id 查表 →
  **重新 canonicalize** 并严格等于记录 → 拒当前目录 / 子孙 / 祖先 / reparse →
  **特征合取**（`vtuber.db` **且** `vtuber.db|vtubers.csv|logs|static` 里再命中 2 项）→
  删成功后**立刻清票据**（防重放）。
- 判据本体拆成纯函数 `prepare_old_dir_deletion`（只有它能被单测；命令壳只做状态读取）。
- 前端：`deleteOldDataDir(migrationId)`；`AppSettingsDialog` 存/传 id，
  **补二次确认框**（红底「删除」）—— 原先是一颗 `FloatPill` 单击即执行。
- 新增依赖 `getrandom`（只用 `fill` 生成 16 字节票据，不引 `rand`）。

## 五、未验证项（如实报告）

- **真机未验**：本批**没有**走一次真实的「迁移 → 删除旧目录」全流程（那要真迁一次数据目录）。
  `ui_probe` 也**覆盖不到**这条路径（它只在开发数据目录副本上跑，迁移是 OS 级 + 一次性动作）。
  ⇒ 建议下次真机验证时**顺带走一次**：迁移 → 确认新目录可用 → 点「删除旧目录」→ 看到确认框。
- **应用重启后票据失效**（有意）：重启后旧目录只能手动删。上一版其实也一样
  （`oldDir` 是组件 state），所以**不是回归**，但界面上现在不会显示那句提示了。
- **迁移失败的分类还没做**：schema 迁移失败时用户看到的仍是「后端启动失败」，
  而不知道"这是数据没坏、只是迁移没过，可以找回"。这是我原来规划在批次 16 的条目，
  **本批刻意不做**（范围已经够大）—— 已记进 `docs/TODO.md`。
