## 一、窗口右缘滚动条 + 宽度跳动 + 滚轮位移（问题 1、2）

**实测**（无头浏览器注入测量脚本，窗口 1076×501，四视图）：

| 视图 | 异常 |
|---|---|
| 展示页 | `DIV.hero-scroll nativeBarW=12` —— 它是**原生滚动容器**（`overflow-y:auto`），窗口右缘出现 12px 原生滚动条，出现/消失时内容宽度跳 12px |
| 档案页 | `.os-scroll client=534 scroll=722`；`.live-calendar [374 → 1244]` —— 卡片**定宽 870px** 在 534px 右栏里居中溢出，右侧被窗口切掉；且网格 `repeat(7, 115.714286px)` 固定列宽，卡片缩了也不跟着缩 |
| 列表页 | 工具栏 `.float-pill` 实测 `[1258 → 1344]`，按钮溢出窗口右缘 268px |

**修复**：
- `html, body { overflow: hidden }` —— 文档层永不滚动，从根上杜绝窗口级滚动条；
- `.hero-scroll` 改用 `OverlayScroll`（全站滚动条标准），消除原生 12px 条；
- `.live-calendar` / `.fan-chart`：`width: 870px` → `width: min(870px, 100%)`
  （**用户定案：上限 870、窄窗口自适应**）；`.lc-grid` / `.lc-weekdays` 列宽
  `repeat(7, 115.714286px)` → `repeat(7, minmax(0, 1fr))`（870 定宽下
  7×115.714+6×4=834 与原设计逐像素一致）；`.lc-cell-head` 的 `gap: 43px`
  改 `6px` + `space-between`（满宽视觉等价，窄格不再挤爆）；
- 列表页 `.type-chips-row` 允许换行（工具组掉第二行，不再被推出窗口）。

**验证**：新增 `scripts/ui_probe.py` + `frontend/src/dev/probe.ts`（`?probe=1`），
1100 / 1280 / 1440 三档宽度 × 四视图断言「文档无滚动条 / 无可见出窗元素 /
无容器横向溢出 / 无原生滚动条」，当前 **全绿**。

## 二、直播日历 / 粉丝趋势的「抓取入口不明确」（问题 3）

**用户口径**：历史场次与粉丝数来自第三方站点，应在**首次收录时同步获取**，不必做手动入口。

**核对代码后发现前提不成立**：`POST /vtuber/adopt` 只调度了 `async_fetch_vtuber`
（账号信息 + 帖子），第三方历史（zeroroku 粉丝历史 / danmakus 直播场次 / 礼物日）
**只在每日定时任务里全量跑**——新收录的 V 当天看不到历史，于是用户以为「入口藏起来了」。

**修复（让前提成真，而不是加按钮）**：
- `ExternalSource.run_job` / `run_external_interval` 增加可选 `account_ids` 白名单
  （zeroroku / danmakus 的 `_bili_accounts` 同步支持），避免为一条新记录全量扫第三方；
- `adopt` 追加后台任务 `_backfill_adopted_history(acc.id)`：收录即按账号回填历史；
- 两张卡标题行加 `.card-src-note`「数据自动同步」+ tooltip 说明来源与更新时机
  （直播日历：「收录时回填 · 每日同步，直播状态随账号抓取更新」；
  粉丝趋势：「账号抓取自动记录 + 收录时第三方回填」），把「没有入口」这件事讲清楚。

**验证**：`tests/test_externals.py::test_fan_history_account_scoped_backfill`
（白名单只写目标账号）。

## 三、顶栏胶囊按住不能拖窗（问题 4）

**根因**：`data-tauri-drag-region` 只标在 `<header>` 上，而 Tauri 按**命中元素**判定拖拽；
胶囊/标题/LOGO 区/空白占位都是子元素，按上去不触发拖动。

**修复**：给所有非交互子元素补 `data-tauri-drag-region`（按钮与登录入口保持不标、继续可点）。
注：真实拖动行为只能在打包/桌面态人工确认，代码层与既有 `present_window` 同一机制。
