# 476-20261013 日历弹窗「只有灰色遮罩、看不见小窗」：查到的与没查完的

> 用户报：「点击日期格之后有灰色遮罩但是没看见小窗」。这条**没修完**，
> 本文只记**已经证实的**和**已经排除的**，免得下一次重走。

## 一、已证实（探针量的，不是猜）

`ui_probe --archive` 现在会点两格并量几何：空日期格（未来 → 记录预约窗）、
过去空格（→ 记录场次窗）。现场：

| 量什么 | 值 |
|---|---|
| 弹窗盒 | `412×335 @(332,772)`，而**视口只有 621 高** ⇒ 整个在视口外 |
| `body.scrollTop` | **0**（这一轮）、`marks=[]`（**没有任何 scroll 事件**） |
| 遮罩容器 | 盒子高 **1080**（= 内容高，不是视口高）⇒ 它的 flex 居中落在 `y≈772` |

⇒ **根因不是"页面被滚"**（我用滚动解释过两轮，都是错的），而是**遮罩那个容器的盒子
比视口高 486px**，于是"居中"落在视口外。

## 二、走错的路（都真踩过）

| 试过 | 结果 |
|---|---|
| 把 `body.scrollTop` 钉回 0 | 反而把弹窗甩到 `y=761`（滚动被藏起来、布局仍按滚动算） |
| 给 body 上 `position: fixed` | 滚动照旧；且遮罩居中算在滚动盒上 ⇒ 一样在视口外 |
| 给 `.lc-ms` 上 `fixed + translate(-50%,-50%)`，遮罩留给它 flex 居中 | X 偏 210px（两套居中在打架） |
| 遮罩加 `height:100dvh` + grid 居中 | 单独不够 |

## 三、当前做法

**遮罩降级成纯调光层**（不再 flex/grid 居中），**弹窗自己** `fixed + translate(-50%,-50%)`：
`fixed` 的包含块是视口 ⇒ 与"body 滚没滚""遮罩多高"都无关。
去掉入场动画之后几何立刻正确：**盒 407×331 @(334,145) = 视口正中**。

⚠️ 入场动画（`lc-dlg-pop`）现在**注释掉了**：它在探针下量到 `opacity` 稳定停在 **0**、
位置停在 `from` 帧 ⇒ 即"动画没跑完"，而那正好就是用户看到的"看不见"。
不能拿"看不见"换 200ms 的顺手，所以先不加回来。

## 四、还没查完（下一个会话从这里接）

1. **`opacity` 为什么还是 0**：几何已经对了（`@(334,145)`），但 `.lc-ms` 的
   `getComputedStyle().opacity` 仍是 `0` —— 说明除了那条动画之外**还有第二个来源**。
   怀疑方向：Radix `DialogContent` 自带的 `data-[state=open]:animate-in fade-in-0`
   （Tailwind 那套 `tw-animate`）在 `.lc-ms` 上还有一条 `animation`，
   它没跑完 ⇒ 停在 `opacity: 0`。查法：在探针里把 `.lc-ms` 的 `animation-name` 打出来。
2. 判据已就位：`ui_probe --archive` 会同时断言
   ① 卡片上缘/scrollY 开合前后一致；② 弹窗盒在视口内且大致居中。
   ⚠️ 还**缺一条 opacity 判据**（这次就是靠临时打印才发现它是 0）—— 加进
   `_reservation_dialog_failures`：`opacity` 必须 ≥ 0.99。
3. C 档门禁现在**红在 `ui_probe` 这一步**（正是上面那条），修完即为绿。
