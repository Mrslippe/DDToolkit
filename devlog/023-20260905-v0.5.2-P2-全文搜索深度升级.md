# 023-20260905-v0.5.2-P2-全文搜索深度升级

## 概述

TODO「v0.5.x 后续小版本」的 P2 落地：关键词搜索从「标题/前 200 字摘要」
扩展到**正文全文**（`body_json` 提取的纯文本）。个人库量级按 TODO 定案
LIKE 即可（此刻真实库 4354 帖），FTS5 暂缓；无索引——LIKE `%q%` 本就
走不了 B-tree，加索引只增写放大。

## 实现

**数据层（迁移 `e003_post_body_text`，MIGRATION_HEAD → e003）**：
- `posts.body_text TEXT NULL`；存量回填走一次性脚本（不在迁移内搬数据，保持迁移轻）；
- 模型同步补列（create_all/旧库桥接路径依然可用）。

**提取服务 `app/services/post_text.py`**（新模块，纯函数，单一语义）：
- `extract_post_text(body_json: str | None) -> str | None`；
- 文本来源优先级（按实际 body_json 形态）：`text`（B站动态 full_text /
  OPUS delta_text / 微博正文）→ `content`（富文本 HTML：换行标签保底断行、
  剥残余标签、`&amp;` 等实体反转义）→ `description`（视频简介）；
- 转发帖叠加 `origin.text`（换行分隔，可搜到转发原文）；
- 归一化：连续空白压缩、段落边界双换行、空串/解析失败 → None
  （容错风格同 `_safe_json_parse`，不引入 DOM 解析依赖）。

**写入路径（三处，body_text 永远由后端派生）**：
- `scheduler._fetch_posts_core._flush_pending` 与
  `scheduler._fetch_platform_posts._flush_pending`：落库前从定稿的 body_json
  派生（enrichment 完成于 pending.append 之前，正文内容不遗漏）；
  `_safe_store_post` 兜底路径复用同一 `d`（已带 body_text）；
- 路由 `POST /posts`：`PostCreate` 不引入 body_text 入参，服务端计算。

**检索扩展 `PostRepo.paginated`**：`q` 的 OR 匹配增加 `Post.body_text.ilike(kw)`
（NULL 列天然不参与匹配，无空值陷阱）。

**回填脚本 `scripts/backfill_post_body_text.py`**：照抄 published_at 回填模式
（`--dry-run` / 直接执行 / 幂等——只处理 `body_text IS NULL`，与写入路径共用
`post_text.py` 提取函数）；真实开发库执行：**4163/4354 填充，191 纯图帖保持
NULL**（预期，无文本可提取）。

**前端**：搜索框 placeholder「搜索标题/摘要」→「搜索标题 / 摘要 / 正文」
+ title 提示（正文由后端检索，前端零 API 改动）。

## 已知限制（记录不掩盖）

- 正文提取是「入库时快照」：历史帖子的 body_text 不会随 posts 更新刷新
  （posts 本身也不原地更新正文；如未来支持正文修改再议）；
- 搜索词命中正文时卡片无高亮/命中位置提示——列表卡片本身渲染标题+摘要，
  命中上下文需点击详情查看（当前设计如此，P6 可再议）；
- 专栏富文本剥标签为粗粒度（段落边界以 `<p>`/`<br>` 保底），纯文本质量
  不影响检索命中，仅影响命中片段的可读性。
