> 用户口径（2026-09-16，B2b 开工前追问）：**"让壳尊重 `DDTOOLKIT_DATA_DIR`，真正区分便携版"**。
> 起因是 B2a 抓到的漂移：壳在 `spawn_backend()` 里**无条件**覆盖那个环境变量，于是
> README 里"便携版可改该变量自定义"是**假的**，而且"便携版"在代码里没有任何可判定的状态。

## 一、改了什么：启动优先级

```
环境变量 DDTOOLKIT_DATA_DIR  >  应用内迁移指针（B2a 的 %APPDATA%\DDToolkit\data-dir.txt）  >  默认目录
```

判定写成**纯函数** `datadir::resolve_startup(env_dir, pointer, default) -> Startup`，`lib.rs::setup()`
只负责取三样东西喂给它：

```rust
let mut default_dir = app.path().app_data_dir()?;      // dev 构建在这里加 -dev 后缀
let env_dir = std::env::var_os("DDTOOLKIT_DATA_DIR").map(PathBuf::from)
    .filter(|p| p.is_absolute());                     // 相对路径不认（会随 cwd 漂）
let startup = datadir::resolve_startup(env_dir, datadir::read_pointer(), default_dir);
```

三条实现细节值得记下来：

1. **`-dev` 后缀只加在默认目录上**。之前是"先算出目录再加后缀"，现在必须先把默认目录算好、
   加完后缀，再让优先级去挑 —— 否则用户显式指定的目录会被莫名加上 `-dev`
   （调试态与生产态的数据目录就串了）。
2. **环境变量优先于迁移记录**：它是"这次启动、这个快捷方式"的显式意图（U 盘、多套数据），
   比应用内留下的记录更"当下"。两者同时存在时用环境变量，并在日志里打出**来源**，
   免得用户以为迁移没生效。
3. **相对路径被过滤掉**：`filter(|p| p.is_absolute())` —— 相对路径会随工作目录漂，
   那是最难排查的一类"数据跑哪去了"。

## 二、便携版判定与它对迁移的影响

- **设了环境变量 = 便携/自定义安装**（`portable = true`）；
- 用户口径：**便携版不给迁移入口** —— 它本来就该"整个文件夹一起搬"，把数据分出去反而容易丢；
- 迁移过的安装版**仍然给入口**（可以再搬一次），来源标记为 `migrated`；
- 指针坏了 ⇒ 回退默认目录，`pointer_unusable` 带着原因进状态，**界面要提醒**（B2c 接）。

新增 `storage_info` 命令（`DataDirState` 状态）返回 `{ dir, source: env|migrated|default,
portable, pointer_unusable }` —— "我的数据到底在哪、为什么在那儿"必须能被回答。
