## 一、这一刀做出什么

| 文件 | 内容 |
|---|---|
| `app/services/platforms/signing.py`（新） | `Signer` 协议 + `NullSigner`（抖音非白名单路径/测试）+ **`XhsSigner`**（懒加载 `xhshow`）+ **`SignerUnavailable`** |
| `app/services/platforms/xiaohongshu.py`（新） | `XiaohongshuPlatform`：`fetch_user_info` / `fetch_post_page` / 笔记→统一 item / **失败分类** |
| `app/services/platforms/registry.py` | 注册 `xiaohongshu` ⇒ **调度器不改一行**就能抓它（`_fetch_platform_posts` 通用单流循环） |

| `tests/test_platform_xiaohongshu.py`（新） | 7 条判据（假签名器 + 假 httpx client，零网络） |

**三条坑照调研写死在实现里**（各有一条判据盯着）：
1. **query 里的逗号不能编码**（`image_formats=jpg,webp,avif` 编成 `%2C` ⇒ 签名校验失败）
   ⇒ 手拼 query，不用 httpx 的 `params`；
2. **`platform_post_id` 全程字符串**（长 id 转 Number 会静默丢精度）+ 三个 json 列
   必须序列化成 **JSON 串**（库里是 `Text`，塞 dict 会 `ProgrammingError`）；
3. **`xsec_token` 只进 `raw_json`**（不是凭证、会过期、不能当去重键）。

**失败要分门别类**（调研 §1.3 第 3 条）：`classify_http()` 把响应分成
`ok / cookie_invalid / signature_invalid / gateway_missing / risk_control / business_error`
（403 兜底按**风控**算 —— 宁可多冷却，也不要把"身份被风控"误判成"帖子被删"）。
⚠️ 这是**初版关键词规则**，真机拿到真实 `code` 后要校准（文件里写明了，别当已验证码表）。

**签名器不在 ⇒ 响亮地失败**：`SignerUnavailable` 被吞成 `None` + `last_error`，
**绝不静默发一个没签名的请求**（那会被风控记一笔且线上查不出来 —— 调研 §1.1 原话）。

## 二、判据（7 条）与反向验证

判据：① 签名头都在 + 逗号没被编码；② 长 id 仍是字符串 + 三个 json 列是串；
③ cursor 串页（第 1 页空游标 / 第 2 页用上一页的 / 回第 1 页要重来）；
④ 失败分类六档 + 403 落到 `cookie_invalid` 时清游标；⑤ 没 cookie 就**不发请求**；
⑥ 签名器不可用也**不发请求**；⑦ **端到端**：库里有小红书账号 ⇒ 经
`_fetch_posts_for_account` → 通用单流循环 → 落库（`platform=xiaohongshu`）。

**反向验证四刀**：query 逗号被编码（①红）· `platform_post_id` 转 int（②红）·
不回第 1 页重置游标（③红）· 403 兜底改成 `business_error`（④红）。
⚠️ 刀 A 的**判据**红了但我的 **needle** 没匹配上（我拿断言里的中文消息当标记，
而 `-q` 输出里只有用例名）—— 第四次"预判/标记错、判据没错"，照旧记下来。
