# 710-20261028-`binaries/backend` 缺失时给一句能照做的提示

## 事故

清理工作区时把 `frontend/src-tauri/binaries/backend/`（75 MB）当成"构建产物"删了，
随后 `npm run tauri:dev` 直接失败：

```
glob pattern binaries/backend/**/* path not found or didn't match any files.
error: failed to run custom build command for `ddtoolkit v1.4.1`
```

报错完全看不出"缺 sidecar"，也看不出该跑什么。

## 关键区别

| 目录 | 性质 | 能不能删 |
|---|---|---|
| `src-tauri/target/` | Rust 编译缓存（30 GB） | 能，下次重建 |
| `src-tauri/binaries/backend/` | **PyInstaller 产物 = 构建输入**（`bundle.resources` 的 glob） | **不能** |

## 修法

`build.rs` 里加与 `extension/` 同款的预检（2026-10-06 那次也是这么修的）：

```rust
if !std::path::Path::new("binaries").join("backend").is_dir() {
    println!("cargo:warning=binaries/backend/ 不存在 —— 先跑 `npm run build:backend`\
              （PyInstaller 生成 sidecar；它不是缓存，删了 dev/build 都起不来）");
}
```

## 验证

| 场景 | 结果 |
|---|---|
| 目录移走 → `cargo check` | 先打印我们的 `cargo:warning`，紧跟 tauri-build 的 glob 报错 |
| 目录恢复 → `cargo check` | 无 warning、退出码 0 |

## 恢复现场

`npm run build:backend` 重新生成 `binaries/backend`（75.2 MB），`tauri:dev` 恢复可用。
