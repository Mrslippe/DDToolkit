# 332-20261004 控件栏的上拉栏与按钮水平居中

> 用户口径（2026-10-04，接 `devlog/331`）：
> 「我希望上拉栏和下面的图标中央对齐」→ 补充：「**不只是清晰度按钮和上拉栏，控件栏中所有按钮
> 呼出的上拉栏都要对齐**」。

## 一、改了什么

旧口径是 `right: 0`（上拉栏的**右缘**贴按钮的**右缘**）：菜单比按钮宽时整体看着偏右，
不像"从这颗按钮长出来"。改成**以按钮中线为准**：

```css
.vp-menu   { position: absolute; left: 50%; transform: translateX(-50%); bottom: 32px; }
.vp-volpop { position: absolute; left: 50%; transform: translateX(-50%); bottom: 34px; }
```

- 锚点就是 `.vp-rate` / `.vp-volwrap`（`position: relative`，盒宽 = 按钮宽）⇒ `left: 50%`
  正好落在按钮中线上；`translateX(-50%)` 把菜单自身宽度的一半推回去 ⇒ **居中**；
- 覆盖面 = 控件栏里的**全部**上拉栏：分P、清晰度、倍速（共用 `.vp-menu`）+ 音量（`.vp-volpop`）。

## 二、居中之后要确认的一件事：别探出播放器

`.vp` 是 `overflow: hidden`（圆角裁剪）⇒ 上拉栏探出播放器会被**裁掉**。逐颗按钮算了一遍余量：
控件栏顺序是 `… [进度条] [分P] [清晰度] [倍速] [音量] [画中画] [全屏]`，
本栏**每颗按钮左右都有邻居**（全屏一定在最右），最宽的清晰度菜单居中后还要往右探约 32px，
而它右侧有 音量/画中画/全屏 三颗按钮（≈120px）兜着 ⇒ **仍在框内**。

## 三、判据（CSS 级，读 `posts.css` 文本）

- `.vp-menu`：必须有 `left: 50%` + `translateX(-50%)`，且**不许**出现 `right: 0`
  （旧口径是右对齐，正是"看着偏右"的原因）；
- `.vp-volpop`：同样两条（它是另一套规则，容易漏改 —— 这条判据就是防漏）。
