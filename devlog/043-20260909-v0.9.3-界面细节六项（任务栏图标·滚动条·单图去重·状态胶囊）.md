## 一、② 任务栏 LOGO 模糊：根因与修复

### 根因（两层叠加，都在 Tauri 构建链路里）

1. **Tauri 只取 ICO 目录的第一项当窗口图标。**
   `tauri-codegen/src/image.rs::CachedIcon::new_ico` 写死
   `let entry = &icon_dir.entries()[0];`，而 ico crate 的 `IconDir::read`
   按文件顺序入表（不排序），PIL 的 ICO 写入器又固定按尺寸**升序**写目录。
   旧 `icon.ico` 的目录顺序是 `16,24,32,48,64,128,256` —— 于是
   `default_window_icon` 实际是一张 **16×16** 位图；tao 的
   `set_window_icon` 把它设为 **`ICON_SMALL`**（`tao-0.35.3/.../window.rs:886`），
   而 Win11 任务栏按钮正是用 ICON_SMALL 缩放到 24/36px 绘制 —— 拿 16px 位图
   放大当图标，糊是必然的。
2. **线稿猫在 ≤32px 下描边不足 1px。**
   猫脸是 `stroke-width: 7.5`（viewBox 167.087×131.01）的线稿；按原比例
   （LOGO 视觉高占图标 60%）渲染到 24px 时描边只有 0.82px，抗锯齿直接抹成灰雾，
   16px 时 0.55px 几乎消失。实测旧 `icon.ico` 各层的白色像素分布：
   16px 层只剩几个孤立亮点（ASCII 自检可见）。

### 修复（`scripts/make_icons.py` 重写）

| 措施 | 说明 |
|---|---|
| **ICO 目录首项 = 48px 任务栏专用层** | 手写 ICO 目录（PIL 的写入器会升序重排，不能用），顺序 `48,256,128,96,64,40,32,28,24,20,16` |
| **首项用「简化加粗版」** | 只保留头部轮廓 + 两个圆点眼（去掉 X 眼细节与胡须），描边 ≈2.9px；Windows 缩到 24px 后仍有 1.45px，36px 有 2.2px |
| **≥64px 完全按设计稿** | stroke 7.5 全细节，描边由矢量反解（不再栅格缩放） |
| **≤48px 按尺寸补偿描边** | 目标 ≈5.8% 边长、下限 1px；视觉外接框恒占图标高 60%（与原图标一致） |
| 源改为矢量 | 直接栅格化 `docs/design/svg/LOGO.svg`（脚本自带 M/L/C 折线化 + 圆头圆角描边），不再依赖早期栅格导出 `NGNlogo无底.png` |

> 副作用（有意为之）：新图标描边 = 设计稿 7.5，比旧图标粗约两成。
> 旧图标是从 `NGNlogo无底.png` 等比拉伸来的，实测描边只占 LOGO 视觉高 4.4%，
> 而设计稿是 5.7% —— 现在应用图标与顶栏/启动幕里的 LOGO 同粗细。
> 实测 512 图标的白色外接框：旧 `392×307 @ (60,102)` → 新 `392×306 @ (60,103)`，
> 构图与比例未变。
>
> 站点图标（`frontend/index.html` 内联 data URI）同步把描边 7.5 → 13
> （32px 显示尺寸下约 1.7px），并重算 translate/scale 保持构图。

**生效条件**：ICO 与 PNG 由 Rust 侧 `include_bytes!` 内嵌，必须重新构建
（`npm run tauri build` / `cargo build`）才生效；Windows 还可能缓存旧图标。

### 实测：Windows 自己的图标选择器（GDI `LookupIconIdFromDirectoryEx`）

用 `System.Drawing.Icon(path, Size(n,n))` 走 Windows 原生层选择逻辑，统计渲染出的
白色像素数（猫是白描边，粉底不算）——旧图标在任务栏尺寸下**几乎全是空的**：

| 请求尺寸 | 旧 icon.ico | 新 icon.ico |
|---|---|---|
| 16px | **0** 个白像素 | 36 |
| 24px | **1** | 66 |
| 32px | **4** | 114 |
| 48px | **7** | 282 |

（旧图标各层是栅格拉伸产物，白色描边在 ≤32px 被抗锯齿抹成粉底同色；
新图标 ≤48px 走简化加粗版，48px 层被选为窗口图标后再由系统缩放到任务栏尺寸。）

## 二、① 顶栏标题字体

`--font-title` 从 `'Noto Sans SC Title'` 改为 `var(--font-family)`
（= 阿里妈妈方圆体 VF，全站正文同款）。随之删除 `NotoSansSC-Title.woff2`
（1.8KB，子集化只含 "DDtoolkit" 拉丁字形）及其 `@font-face` —— 全站只剩一款字体。
`.paper-title`（纯文字帖封面）也引用 `--font-title`，此前中文本来就回落到方圆体，
现在拉丁字形也统一，无视觉回退。

## 三、③ 滚动条：粉只属于「指针」

**问题**：原 `.os-root:hover .os-thumb { 变粉 + 加粗 }` —— 滚轮滚动时指针必然在
容器内，于是「一滚就粉」，与「滚动时浅灰」相悖。

**改法**（layout.css + OverlayScroll.tsx）：

- 变粉条件收窄为 `.os-thumb.os-show:hover`（指针压在拇指上）或
  `.os-thumb.os-show.os-drag`（拖拽中，组件在 `onThumbDown` 加类、`endDrag` 去类，
  保证指针滑出拇指也维持粉色）；
- 新增**指针进入右缘 18px 槽区即亮出拇指**（`reveal(1200)`）——否则滚完 700ms
  就淡出，指针还没移过去条就没了，「hover 变粉」根本够不着；
- 全局原生兜底 `::-webkit-scrollbar-thumb:hover` 本就是「指针压在滑块上」语义，未动。

## 七、追加（同日第二轮，用户复测后）

### 7.1 为什么 `tauri:dev` 里任务栏还是旧图标 —— 构建依赖没声明

用户确认 `icons-src/` 确实不用（已删），并反馈 `npm run tauri:dev` 下任务栏**依旧糊**。
实测定位（不是 CSS、也不是图标文件本身的问题）：

| 证据 | 数据 |
|---|---|
| dev 二进制 | `target/debug/ddtoolkit.exe` 构建于 **09-08 23:24:39**，早于新图标 **09-09 01:22** → 根本没重新构建 |
| 该 exe 内嵌图标 | 用 Windows GDI 提取出 32px 图标 → 与**旧** `icon.ico` 的 32px 层逐像素一致（散点白像素） |
| release 二进制 | 09-09 **01:36** 构建（晚于新图标），内嵌图标**同样是旧图** |
| Tauri 窗口图标缓存 | 构建脚本 OUT_DIR 里：旧缓存 `325a7850…` **1024 B = 16×16 RGBA**（旧 ICO 首项）；重建后 `4827e748…` **9216 B = 48×48 RGBA**（新 ICO 首项）—— 1024→9216 正是首项从 16px 变 48px 的直接证据 |

**根因**：图标是 tauri-build 构建脚本的输入（它生成 context 里的
`default_window_icon`，同时用 winres 把 ico 内嵌进 exe 资源），但 tauri-build 只对
`tauri.conf.json` / resources / capabilities / frontendDist 声明了
`cargo:rerun-if-changed`——**图标不在其中**。于是只改图标时 cargo 认为「无事发生」，
既不重跑构建脚本、也不重新链接，窗口图标与 exe 资源都停在旧值。proc-macro / 构建脚本
读取的文件本来就不在 cargo 的依赖图里（这是 cargo 的已知边界）。

**修复**：`src-tauri/build.rs` 显式声明四个图标文件依赖
（`icons/icon.ico|icon.png|32x32.png|128x128.png`）——构建脚本的 output 里现在能看到
`cargo:rerun-if-changed=icons/icon.ico` 等四行；重建后 `resource.lib`/`resource.rc` 与
窗口图标缓存同步刷新。

**重建后实测**（`cargo build`，28.9s）：
- exe 内嵌 32px 图标 = 清晰的猫脸（耳朵/眼睛/轮廓齐全），白像素 46 → **111**；
- 窗口图标缓存 1024 B(16×16) → **9216 B(48×48)**，ASCII 渲染可见完整猫脸。

> 仍需注意：Windows 会缓存 shell 图标；换图标后若资源管理器仍显示旧图，刷新图标缓存即可。
> 改图标后若构建脚本没重跑（例如在旧分支上），`cargo clean -p ddtoolkit` 兜底。

### 7.2 顶栏状态行改「浮片 + 阴影」设计语言

用户看后要求：**去掉玻璃质感与外发光，改成浮片和阴影设计语言**。于是把它并入
`.float-pill` 那套令牌：本体透明（无背景/无边框/无阴影/无 `backdrop-filter`），
斜切白卡画在 `::before`（`--pill-bg` + `--pill-radius` 3px + `skewX(var(--pill-skew))`
+ `--pill-shadow`），高 `--pill-h-sm`(25px)、字号 12px、字色 `--pill-fg`（白底 ≈8.6:1）。
本体因此**不能再设 `overflow:hidden`**（会裁掉斜切角），超长文案的省略号落到内层
`.pill-text-fade`。

CDP 实测：本体 `background: rgba(0,0,0,0)` / `box-shadow: none` / `backdrop-filter: none`
/ `overflow: visible`；`::before` = 白底 + r3px + `matrix(1,0,-0.176327,1,0,0)`（即
skewX(-10deg)）+ `rgba(15,23,42,.12) 0 2px 6px`；几何 `121×25 @ y=7.5` 双向居中；
字色 `rgb(61,74,92)`、12px；状态点绿 `rgb(82,196,26)`。

### 7.3 状态行再定调：浮片材质 + 全圆角胶囊

用户看到斜切版后要求「还是改成全圆角胶囊体」——**材质保留浮片那套、形状回到胶囊**：
白底 `--pill-bg` + `--pill-shadow` + `border-radius: 999px`，去掉 -10° 斜切。
没有斜切角之后 `::before` 不再需要（背景直接画在元素上），`overflow: hidden` 也随之
回来（裁切超长文案；省略号仍由内层 `.pill-text-fade` 提供）。

CDP 实测：`border-radius: 999px`、`background: rgb(255,255,255)`、
`box-shadow: rgba(15,23,42,0.12) 0 2px 6px`、`backdrop-filter: none`、`border: 0`、
`::before: none`、`overflow: hidden`、内层 `text-overflow: ellipsis`；
几何 `121×25 @ y=7.5` 双向居中。

### 7.4 小尺寸图标：给「自绘小稿」留好接口

用户复测后问「任务栏图标丢了细节，自绘一个 PNG 是不是更好」。结论：**是，但建议画成
SVG 而不是 PNG**——脚本要按 16/20/24/28/32/40/48 逐个尺寸栅格化，矢量稿才能给出
每个尺寸的干净像素；PNG 只能再重采样一次，等于把「任务栏糊」换个地方复发。
（几何事实：一根胡须在 24px 下长 2.2px、宽 1.1px，X 眼同理——**丢细节是尺寸的物理
限制，不是渲染方法问题**；各家平台图标规范都是「大图求细节、小图单独画」。）

`scripts/make_icons.py` 已留好接入点：存在 `docs/design/svg/LOGO-small.svg`（优先）
或 `docs/design/png/LOGO-small.png` 时，**≤48px 全部改用它**（≥64px 仍用主稿）。
SVG 版约定：只描边、`stroke-width` 原样使用（不再按尺寸补偿）、视觉外接框等比缩放到
图标高 60% 居中、建议画在 48×48 网格上只保留「头部轮廓 + 耳朵 + 两个圆点眼 +
每侧 1–2 根短胡须」。脚本头注释里有完整规格。

自检：临时放一份 `LOGO-small.svg` 跑一遍，≤48px 各层与 ICO 首项哈希均改变（接口生效）；
移除后重新生成，17 个图标文件的 SHA256 与改动前逐字节一致（重构未改变现有输出）。
