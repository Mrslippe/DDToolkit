## 一、② 任务栏 LOGO 模糊：根因与修复

### 根因（两层叠加，都在 Tauri 构建链路里）

1. **Tauri 只取 ICO 目录的第一项当窗口图标。**
   `tauri-codegen/src/image.rs::CachedIcon::new_ico` 写死
   `let entry = &icon_dir.entries()[0];`，而 ico crate 的 `IconDir::read`
   按文件顺序入表（不排序），PIL 的 ICO 写入器又固定按尺寸**升序**写目录。
   旧 `icon.ico` 的目录顺序是 `16,24,32,48,64,128,256` —— 于是
   `default_window_icon` 实际是一张 **16×16** 位图；tao 的
   `set_window_icon` 把它设为 **`ICON_SMALL`**（`tao-0.35.3/.../window.rs:886`），
   而 Win11 任务栏按钮正是用 ICON_SMALL 缩放到 24/36px 绘制 —— 拿 16px 位图
   放大当图标，糊是必然的。
2. **线稿猫在 ≤32px 下描边不足 1px。**
   猫脸是 `stroke-width: 7.5`（viewBox 167.087×131.01）的线稿；按原比例
   （LOGO 视觉高占图标 60%）渲染到 24px 时描边只有 0.82px，抗锯齿直接抹成灰雾，
   16px 时 0.55px 几乎消失。实测旧 `icon.ico` 各层的白色像素分布：
   16px 层只剩几个孤立亮点（ASCII 自检可见）。

### 修复（`scripts/make_icons.py` 重写）

| 措施 | 说明 |
|---|---|
| **ICO 目录首项 = 48px 任务栏专用层** | 手写 ICO 目录（PIL 的写入器会升序重排，不能用），顺序 `48,256,128,96,64,40,32,28,24,20,16` |
| **首项用「简化加粗版」** | 只保留头部轮廓 + 两个圆点眼（去掉 X 眼细节与胡须），描边 ≈2.9px；Windows 缩到 24px 后仍有 1.45px，36px 有 2.2px |
| **≥64px 完全按设计稿** | stroke 7.5 全细节，描边由矢量反解（不再栅格缩放） |
| **≤48px 按尺寸补偿描边** | 目标 ≈5.8% 边长、下限 1px；视觉外接框恒占图标高 60%（与原图标一致） |
| 源改为矢量 | 直接栅格化 `docs/design/svg/LOGO.svg`（脚本自带 M/L/C 折线化 + 圆头圆角描边），不再依赖早期栅格导出 `NGNlogo无底.png` |

> 副作用（有意为之）：新图标描边 = 设计稿 7.5，比旧图标粗约两成。
> 旧图标是从 `NGNlogo无底.png` 等比拉伸来的，实测描边只占 LOGO 视觉高 4.4%，
> 而设计稿是 5.7% —— 现在应用图标与顶栏/启动幕里的 LOGO 同粗细。
> 实测 512 图标的白色外接框：旧 `392×307 @ (60,102)` → 新 `392×306 @ (60,103)`，
> 构图与比例未变。
>
> 站点图标（`frontend/index.html` 内联 data URI）同步把描边 7.5 → 13
> （32px 显示尺寸下约 1.7px），并重算 translate/scale 保持构图。

**生效条件**：ICO 与 PNG 由 Rust 侧 `include_bytes!` 内嵌，必须重新构建
（`npm run tauri build` / `cargo build`）才生效；Windows 还可能缓存旧图标。

### 实测：Windows 自己的图标选择器（GDI `LookupIconIdFromDirectoryEx`）

用 `System.Drawing.Icon(path, Size(n,n))` 走 Windows 原生层选择逻辑，统计渲染出的
白色像素数（猫是白描边，粉底不算）——旧图标在任务栏尺寸下**几乎全是空的**：

| 请求尺寸 | 旧 icon.ico | 新 icon.ico |
|---|---|---|
| 16px | **0** 个白像素 | 36 |
| 24px | **1** | 66 |
| 32px | **4** | 114 |
| 48px | **7** | 282 |

（旧图标各层是栅格拉伸产物，白色描边在 ≤32px 被抗锯齿抹成粉底同色；
新图标 ≤48px 走简化加粗版，48px 层被选为窗口图标后再由系统缩放到任务栏尺寸。）

## 二、① 顶栏标题字体

`--font-title` 从 `'Noto Sans SC Title'` 改为 `var(--font-family)`
（= 阿里妈妈方圆体 VF，全站正文同款）。随之删除 `NotoSansSC-Title.woff2`
（1.8KB，子集化只含 "DDtoolkit" 拉丁字形）及其 `@font-face` —— 全站只剩一款字体。
`.paper-title`（纯文字帖封面）也引用 `--font-title`，此前中文本来就回落到方圆体，
现在拉丁字形也统一，无视觉回退。

## 三、③ 滚动条：粉只属于「指针」

**问题**：原 `.os-root:hover .os-thumb { 变粉 + 加粗 }` —— 滚轮滚动时指针必然在
容器内，于是「一滚就粉」，与「滚动时浅灰」相悖。

**改法**（layout.css + OverlayScroll.tsx）：

- 变粉条件收窄为 `.os-thumb.os-show:hover`（指针压在拇指上）或
  `.os-thumb.os-show.os-drag`（拖拽中，组件在 `onThumbDown` 加类、`endDrag` 去类，
  保证指针滑出拇指也维持粉色）；
- 新增**指针进入右缘 18px 槽区即亮出拇指**（`reveal(1200)`）——否则滚完 700ms
  就淡出，指针还没移过去条就没了，「hover 变粉」根本够不着；
- 全局原生兜底 `::-webkit-scrollbar-thumb:hover` 本就是「指针压在滑块上」语义，未动。
