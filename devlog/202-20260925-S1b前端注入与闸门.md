# 202-20260925-S1b前端注入与闸门（S1 收口：门真的关上了）

接 devlog/201。批次 1 只做了后端门禁 + 壳生成 token，**前端还不发 token** —— 那一批跑的是
"两个 token 都为空 ⇒ 放行"的过渡路径。本批把剩下三件事做完：前端注入、探针开发态通路、
以及把"没配就放行"改成**必须配**。

## 一、改了什么

- `api.ts`：唯一注入点（`request()` 与 `authFetch()` 都走 `Headers` **合并**，
  保住调用方自带的 `Content-Type`）；新增**启动闸门**。
- `main.tsx`：`tauriBootstrap` 里 `get_api_token` 与端口一起取；浏览器分支开闸。
- `widgetMain.tsx`：**小窗也是独立入口**，同样要注入 token —— 这次是按 `DEV-LOOP.md` §6.1
  的"顶层副作用清单"逐条过时**提前抓到的**（小窗到 S1 前只注入端口，diff 里能看到），
  不是事后发现。清单原文见 `DEV-LOOP.md` §6.1。
- 探针：`ui_probe.py` 给后端与 Vite 各注入同一个开发态 token（两个变量名不同：
  `DDTOOLKIT_DEV_API_TOKEN` / `VITE_DEV_API_TOKEN`）。
- `tests/conftest.py`：给测试里的 `TestClient` **统一带上 token**（见 §三）。
- 收口：`is_authorized` 的"没配 ⇒ 放行"改成"没配 ⇒ 拒绝"。

## 二、为什么需要"闸门"，以及它踩到的三个坑

`main.tsx` 的 `Root` 在 `state !== 'pending'` 时就挂载 `<Main/>`，而注入基地址与 token 都在
**异步**的 `tauriBootstrap` 里 —— 原先能工作靠的是"启动幕那 750ms 里没有业务请求自动发出"
这个**时序巧合**；加 token 之后多一次 `invoke`，只会更晚。所以要有闸门。

三个坑，每个都值得单记：

1. **闸门与"旗标"必须一起维护**：第一版把 `gateOpen` 初值写成 `true`，而 `gate` 是一个
   **永不 resolve** 的 pending promise ⇒ `request()` 里的 `await gate` **永远不返回**，
   **整个应用所有请求全部挂死**。表现是测试里第一条用例 5 秒超时。
   修法：一处 `newGate()` 构造，初值直接 `Promise.resolve()`。
2. **默认必须是放行的**：第二版把闸门做成"默认关、靠调用方去开" ⇒ 任何新调用方忘了开，
   请求就静静地挂着（没有报错、没有日志，比 401 难查得多）。
   改成"**默认放行；`holdApiUntilReady()` 才是那个显式声明**"。
3. **浏览器里关闸是错的**：探针是**模块加载就 `runUiProbe()`**（不等 React effect），
   于是它那几个 fetch 卡在闸门上永不返回 ⇒ "探针没量到 fetch-status"。
   修法：`holdApiUntilReady()` 自己判 `__TAURI_INTERNALS__`，浏览器里直接空操作 ——
   **需不需要等由环境决定，而不是靠调用方记得**。

## 三、收口的连带影响：86 条测试集体 401

把"没配就放行"改成"必须配"之后，所有 `TestClient(app)` 打真应用的用例**集体 401**
（`KeyError: 'id'`：拿不到响应体里的 id）—— 实测 **86 failed**。

修法放在 `tests/conftest.py`（**一处覆盖全部**，而不是每个测试文件各写一遍）：
进程内配一个已知 token，并包一层 `TestClient.__init__` 把默认头塞进去。
两件事缺一不可：**进程里要有可比的东西** + **每个客户端要带上它**。
否则"新写的测试忘了带头"就等于新测试直接红。

⚠️ 尾部必须把 `settings` 的两个属性**还原成读环境变量**：`settings` 是**类属性**，
`setattr` 写进类里不还原 ⇒ 下一个测试文件会继承"已配 token"的状态而看不到真实行为。

## 四、最费时的一段：三次"伪装成布局坏了"的排查

本批前端接线一共红过三轮，**每一轮的症状都是"页面数据全空 ⇒ 布局断言集体报红"**：

| 轮 | 真因 | 我加错的判据/写法 |
|---|---|---|
| 1 | `main.tsx` 的浏览器分支**无条件**调 `markNoTokenRequired()` —— 而它会把 `apiToken` **清空** | 把"开闸"与"清 token"写成了同一个动作 |
| 2 | `dev/probe.ts` 十余处**裸 `fetch`**（S1 之前写的）不带 token | 只改了 `request()`，漏了不走它的调用方 |
| 3 | `authFetch` 自己拼 `apiBase`，而探针传的是**完整 URL** ⇒ `http://127.0.0.1:59321http://...` | 没容忍绝对 URL |

**判据是同一个**：`git stash` / 单跑探针 / 直接量端点。第 3 轮是靠新加的诊断字段
一次定位的（`throw=TypeError: Failed to parse URL from http://127.0.0.1:59321http://...`）
—— 所以 I 留了一个 dev 钩子 `window.__ddtoolkitAuthDiag()` 与探针输出里的 `auth` 字段：
下次同类问题不用再猜"是没注入、还是注入了没带"。

## 六、未验证 / 风险

- ⚠️ **真机未验**：本批改了两个入口的启动链与 Rust 命令的调用，但**没有启动过一次 Tauri**
  （要 `cargo build` + 真机）。**这是本批最大的未验证项** —— 特别是
  `get_api_token` 的 label 校验（`main`/`widget`）与"取不到 token ⇒ 启动幕 failed"这条路。
  收尾时**补了一层静态对账**（不能替代真机，但把"接线接错了"这一半排掉）：
  `tauri.conf.json` 的主窗 label = `main`、lib.rs 建小窗用 `widget`、
  `CALLER_LABELS_ALLOWED = ["main", "widget"]`（有 Rust 用例钉着）、
  两条 `spawn_backend` 路径都 `.env("DDTOOLKIT_API_TOKEN", …)`、
  `config.py` 读的就是这个名字 ⇒ 静态链是通的，剩下的只有运行时的 invoke 通路与闸门时序。
- 纯 `npm run dev`（不起探针、不设 `VITE_DEV_API_TOKEN`）现在会**全 401**：
  走的是 `api.ts` 里那个默认值，而后端没有 `DDTOOLKIT_DEV_API_TOKEN`。
  取值口径记在 `docs/ARCHITECTURE.md` §6 第 26 条，`docs/DEV-LOOP.md` §一 的表里加了指针。
