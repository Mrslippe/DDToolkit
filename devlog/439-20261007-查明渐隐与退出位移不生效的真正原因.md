# 439-20261007-查明"渐隐/退出位移不生效"的真正原因

用户第三条反馈（原话）：「还是一样，进入没有渐显，退出没有渐隐和位移，**检查真正原因**」。

前两轮我改的是"我以为的原因"（`transform` 被抢、`!important` 压动画），都只对了一半。
这一轮改成**先查证再改**，两处真原因都在 `posts.css` 里、一眼可见：

## 真原因 1：`.view-body` 的入场动画是 `both` 填充 —— 它**永久占着** `opacity`/`transform`

```css
.view-body:not(.scene-exit) { animation: scene-in 0.22s … **both**; }
```

`both` = `backwards` + **`forwards`**。`forwards` 的含义是"动画结束后**继续应用末帧的值**" ⇒
对 `.view-body` 来说，**`opacity: 1` 与 `transform: none` 被永久钉住**。于是：

| 现象 | 解释 |
|---|---|
| 位移（`margin-top`）生效 | 动画不动 `margin`，躲过去了 |
| **渐隐永不生效** | `opacity` 被 `forwards` 钉住（`!important` 也压不过"动画仍在应用"） |
| **退出位移看不出** | 回来那条的 `opacity: 1 / margin-top: 0` 同样被钉 |
| 只有工具栏听话 | `.view-toolbar` 没有入场动画 |

**改法**：单推模式下把这些子元素的**填充方式**改成 `backwards`（入场照样播，播完不再占属性）：

```css
.app-shell[data-solo='1'] .posts-panel[data-view='cards'] > :not(.hero-backdrop) {
  animation-fill-mode: backwards !important;
}
```
⚠️ 不是 `animation: none` —— 那会把"切视图的入场"一起干掉。

## 真原因 2：纱罩有**两份真源**，我改的那份不是用户看的那份

`.hero-backdrop.custom::after` 单独还写着那套旧渐变（`rgba(255,251,251,.14/.24)` + 径向
`.28/.06`）。用户用的是**自定义背景** ⇒ 他看到的永远是**这一条**，而我把 12% 写在
基础 `.hero-backdrop::after` 上 ⇒ **他那边一个像素都没变**（"还是加上遮罩吧"改了等于没改）。

**改法**：**删掉 `.custom::after` 那一整条**，只留基础那条 `rgba(255,255,255,.12)`，两种状态共用 ✓。

## 判据（+2）

★★「真原因」：断言 `animation-fill-mode: backwards` 在、`animation: none` 不在，
并**配正对照**（那条 `scene-in … both` 确实还在，否则这条没有意义）·
★「纱罩只有一处真源」：断言 `.hero-backdrop.custom::after` **不存在**。

**反向验证**（两组）：去掉 `animation-fill-mode` ⇒ 那条红；把 `.custom::after` 加回来 ⇒ 那条红。

## 教训（比这两处 bug 更值钱）

**"我改的东西为什么没生效"，要先问三件事**：
① 我改的**是不是**用户看的那个元素/那份规则（真原因 2 —— 同名规则有两份，`P()` 之外还有 `.custom` 变体）；
② 有没有**别的东西也在写**这个属性（`animation` 的 `forwards` 填充是"一直在写"）；
③ 我**验证过**自己的改动真的落到了文件里吗（`devlog/422`/`425`/`427` 的旧账）。
前两轮我跳过了①，直接按②猜，所以改了两轮才回到起点。**先查那份 CSS 有没有第二处真源。**
