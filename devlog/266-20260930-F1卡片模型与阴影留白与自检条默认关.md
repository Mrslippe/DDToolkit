## 一、F1：卡片就是面板

### 改了什么

| | 旧（D1） | 新（F1） |
|---|---|---|
| 展开态卡片 | 胶囊（40）+ 间隙（6）+ 面板 | **面板本身** |
| 卡片高 | `40 + 6 + 面板高` | `面板高` |
| 胶囊 | 始终在场 | **展开时整行 `display:none`** |
| 面板落点 | 按胶囊 rect 推：`r.bottom + 6` / `r.top − 6 − h` | **恒为 `(pad, pad)`**（铺满卡片） |
| 方向（`data-dir`） | 决定面板落在上方还是下方 | **只剩"入场动画从哪一侧滑出"** |

### 连带删掉的东西（这才是这一步的收益）

F1 之后"卡片在窗口里靠哪一边"这个问题**不存在了**：卡片恒在 `(pad, pad)`。
于是 D1 那一整套偏移机制 —— `WidgetGeom.capOffsetX/capOffsetY`、
`--widget-capsule-x` / `--widget-capsule-offset`、`applyOffsets()`、
`StatusIsland.place()` 里读 `data-dir` 判上下、以及那个盯 `data-dir` 的 `MutationObserver`
—— **全部删掉**。位置只剩一个主人（`widgetExpandGeom` 算窗口矩形）。

> 这是本仓那条纪律的正面例子：**机制的前提消失时，连机制一起删**。
> 留着它们不会报错，只会让下一个人以为"这里还有两个真源要同步"。

### 判据放在哪儿（一个刻意的选择）

"展开时胶囊隐藏"由 **`StatusIsland` 写 `.widget-shell[data-open]`** 驱动（它知道 `open`），
而**不是**由窗口那边写。理由：窗口那条路在探针里**根本不跑**（没有真窗口）——
挂在窗口上就等于"这条判据只能真机验"。挂在组件上之后，探针里 hover 展开时
它也照样隐藏 ⇒ 判据 `capsuleDisplayWhenOpen == 'none'` **在探针里就有牙齿**。
（连带的好处：以前"展开时面板在不在视口内"那几条判据是在"胶囊还在场"的假设下量的，
现在那个假设与产品一致了。）

### 面板成了唯一的把手 ⇒ 补拖动

胶囊行没了之后，展开态**只剩那圈 32px 留白能拖**（面板是 portal 到 body 的，
指针事件不经过 `.widget-shell`）。所以补了一条**文档级**指针监听：
只接管落在 `.si-panel` 上的按下，**位移过 4px 才算拖**（与窗口壳同款阈值，
否则面板里的动作钮永远点不响）。与"用 `MutationObserver` 观察面板出现"是同一条取舍：
**不让组件知道窗口的存在**（§8）。

## 二、「阴影被截断」：根因是**窗口 == 卡片**

用户截图上那条灰边突然中止 —— 因为阴影要画在卡片**外面**，而窗口外面没有像素。
**透明窗口救不了**：窗口尺寸就是能画的全部范围。

修法：**窗口 = 卡片 + 一圈透明留白**，而留白**从阴影自己的伸出量算出来**：

```
一层 `0 dy blur` 的阴影向下伸出  dy + blur/2   （模糊半径的一半落在盒子外）
两侧伸出 blur/2、向上 blur/2 − dy
⇒ 留白 = 所有层里最大的 dy + blur/2，向上取整
```

`WIDGET_SHADOW_PAD` 因此是**算出来的常量**（不是拍的），有两组单测钉住它：
① 它 == 那个最大值；② **每一层都装得下**（`dy + blur/2 ≤ pad`）——
后一条就是"阴影被截断"的机器判据。探针侧还量**渲染出来的**阴影伸出量
（在浏览器里按括号深度切层、跳过 `inset`），要求 `reach ≤ --widget-shadow-pad`。

⚠️ 样例页那套阴影最远伸到 `36 + 88/2 = 80px` ⇒ 照抄要 80px 留白（窗口比卡片宽 160px）
⇒ **按留白缩了一档**（三层改成 `2/6`、`8/20`、`14/36`）：观感仍是"三层递进的柔和投影"，
最外圈的伸出量与 32px 留白对得上。

⚠️⚠️ **代价必须说清：那圈留白透明，但会挡住鼠标** —— 窗口是实心的可命中矩形，
单击落在留白上算点在小窗上，不会穿到桌面。32px 是"阴影可见"与"别挡太多"的取舍。
真要两者兼得，得在 Rust 侧按区域做 `WM_NCHITTEST → HTTRANSPARENT`（**没做**，
记在 `TODO.md` §1.5）。折叠态窗口因此从 200×40 变成 **264×104**（首帧尺寸同步改了）。

## 四、一次自伤：PowerShell 往 Python 源码里写了 BOM

改探针时我用 `Set-Content -Encoding UTF8` 落盘 —— 那个 `-Encoding UTF8` 在 Windows
PowerShell 上是**带 BOM** 的 UTF-8。Python 自己读源码能容忍 BOM，但
**`dev_check.py` 的 `ast.parse(open(...).read())` 不能**（`SyntaxError: invalid
non-printable character U+FEFF`）⇒ 门禁的"全仓语法扫描"那一步会红，而**报错行号指向文件第 1 行**，
看起来像"探针文件坏了"，其实是编码。
⇒ **别用 PowerShell 写 Python 源码**（用脚本/编辑器），落盘一律 `encoding="utf-8"`（无 BOM）。
本次由语法自检当场抓到（`[ok] 177 个文件语法通过` 之前先红了一次）。
