# 597-20261023-结果区：胶囊移到标题行右侧、两张图改为全池口径

用户看截图提了两条：

1. 红框里的胶囊（窗口场次 / 已有 / 待采）要放到**最右侧、与卡片标题同一行**；
2. 下面的「核心度分层」「核心度分布」要覆盖**全池**（过 10% 出席门槛的所有人），
   而不是现在截图里的"本次名单 300 人"。

## 一、胶囊右置

`wb-card-head` 本来就是 `display:flex; justify-content:space-between`，所以把胶囊块从
结果区的顶部挪进标题行即可。**未出结果时**（加载 / 采集中 / 空态）仍留在顶部 ——
那时没有标题行，挪进去会消失。

## 二、全池口径

原来的问题：两张图吃的是 `/ranked` 返回的 `items`，而前端把 `limit` 写死成 300，
于是 33,434 人的池子只画了 300 人，还标注"本次名单 300 人"。

改法：**聚合放后端**（前端拿不到 3 万人的明细）。

`GET /fan/{v}/ranked` 新增 `pool`：

```json
"pool": {
  "size": 33434,
  "tiers": {"核心": 6687, "次核心": 10030, "外层": 16717},
  "bins": {"lo": 0.209931, "hi": 0.999835, "counts": [ ... 20 桶 ... ]}
}
```

- 分层沿用原前端那套分位切法（前 20% / 20–50% / 其余），与 `cross_v.assign_tiers` 同一组阈值；
- 桶是 20 个，区间取全池 min–max；
- `ResultCharts` 优先用 `pool`，没有才退回 `items`（兼容旧响应）。

实测（星瞳 75 场）：`pool.size = 33,434`、三层之和 = 33,434、20 桶之和 = 33,434，
而 `items` 仍只回 limit 条 —— 图与名单口径彻底分开。
