## 一、规格补充：四条本批实测得出的结论（§7 原文没有）

**① 小窗不轮询，条目由主窗口推。**
六个信息源（任务进度 / 风控冷却 / 登录失效 / 完成报告 / 瞬时消息 / 磁盘）全在主窗口的
`TopBar` 里，小窗再来一份就是**双倍请求**。所以小窗是**纯显示**的：
主窗口推 `widget:notices`，小窗画；面板里的动作（"去登录"/"查看详情"）只有主窗口做得了，
小窗把点击**转回去**（`widget:action`）。

> **这是对 §8 `useStatusIsland()` 的有意偏离。** 查下来 `TopBar` 的 `status`/`auths`/`doneReport`
> 都是**组件内自持**的局部 state，抽那个 hook 等于重构 729 行组件 —— 而且抽完**两扇窗仍然各轮各的**。
> **推事件才是真的只轮一次**，也更小。

**② 拖动不能用 `data-tauri-drag-region`。**
那个属性在 **mousedown** 就调 `startDragging()`，于是"点一下打开面板"永远收不到点击。
主窗口那边能这么用是因为有 `.topbar-spacer` 那块**空白把手**；小窗 200×40 全是可交互面，没有。
改成**指针位移过 4px 才拖**：没动就是点击，动了才是拖窗口。

**③ 位置夹取是必需的，不是锦上添花。**
控件**置顶 + 无边框 + 不进任务栏** —— 整个跑出屏幕就**再也点不到它**
（连"从任务栏找回来"这条路都没有）。所以 `clampWidgetPos` 四个方向都留 24px 可见，
而且**"换到更小显示器"那条有单测**（1920 上存的坐标插到 1366×768 上必须被夹回来）。

**④ ⚠️ Rust 的 `CloseRequested` 拦截原来不分窗口 —— 这是个真 bug。**
那段逻辑是 R18 为"✕ = 隐藏到托盘"写的，**只有一个窗口时是对的**。加了第二扇窗之后，
小窗的 `close()` 会被拦下，并且顺手把**主窗口**藏进托盘（用户压根没点过主窗口）。
已加 `window.label() == "main"` 判断。

| 层 | 内容 |

## 三、判据

`ui_probe --status-widget` **第二段**（`?probe=status-widget-window&widget=1`）：
`.widget-shell` 在 / 胶囊 `data-density="widget"` / 200×40 / **居中误差 = 0** /
**顶栏与侧栏都不在**（分流生效）。

**反向验证过**（把 `?widget=1` 短路成 `false && …` ⇒ 六条同时报）：

```
- 小窗里没有 `.widget-shell`
- 小窗里的胶囊 density 是 'bar'，应为 'widget'
- 小窗里胶囊尺寸是 [128, 25]，应为 [200, 40]
- 胶囊在小窗里没居中（误差 Nonepx）
- 小窗里出现了顶栏 —— `main.tsx` 的 `?widget=1` 分流没生效（跑起了整个应用）
- 小窗里出现了侧栏 —— 同上
```

**过程中修掉自己两条判据错**：① 探针输出的 `<pre>` id 写成了 `probe-out`，
而 `_run_probe` 找的是 `ui-probe` ⇒ 报了"未拿到探针输出"；② 断言"胶囊偏移 = [0,0]"
—— 探针里视口是 **1100 宽**（不是 Tauri 那个 200×40），绝对偏移必然是几百像素；
改成判**居中误差**才对。
