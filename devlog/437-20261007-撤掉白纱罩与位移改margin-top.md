# 437-20261007-撤掉白纱罩 + 位移改 margin-top

用户两条：

> 1. 直接撤掉（问的是"背景遮罩能不能改高斯模糊"，看过禁区说明后选了"什么都不要"）
> 2. 界面元素位移似乎没完全生效：顶部工具栏可以看见生效了，但 hero 之类的元素又没有

## 第 1 条：撤掉白纱罩

`.hero-backdrop::after`（那层白的 `linear-gradient`）整体 `display: none` ✓，
`solo` 里那两条"让位时把纱罩渐隐"的规则一并删掉（成了死规则）。

⚠️ **留了一个副作用给真机看**：`utils/backdropTone.ts` 判"字色随底图明暗"时**假定背景上有一层
α=0.25 的白纱罩**。现在实际渲染没有它 ⇒ 深色底图上可能把字判成近黑而不够清楚。
真机若发现看不清，把那个假定值改成 0 就行（一处常量，已写在 CSS 注释里）。
原来的四个 alpha（0.28/0.36/0.45/0.18）也留在注释里，要恢复是一条 `display: none` 的事。

## 第 2 条：`transform` 被入场动画压掉了

**根因**：hero / 视图自带 `rise-in-page` 入场动画，而它**也是 `transform`** ——
CSS 里 **`animation` 的优先级高于普通声明**，所以我们写的那条
`transform: translateY(var(--solo-hide-shift))` 对它们**完全不生效**；
而 `.view-toolbar` 没有入场动画 ⇒ 它动了 ✓ 与用户看到的现象**逐字吻合**
（"工具栏动了、hero 没动"）。

**改法**：位移改用 **`margin-top`** —— 不与动画抢同一个属性。判据也改成断言 `margin-top`。

## 判据

`soloMode.css.test.ts` 7 条全部跟上（位移断言从 `transform: translateY(...)` 改成
`margin-top: var(--solo-hide-shift)`；纱罩改为断言"已 `display: none`"）。

## 教训

**"我写的声明为什么没生效"里，有一类答案是"它被 `animation` 压掉了"** ——
本仓的入场动画（`rise-in-page`）大量挂在页面级容器上，凡是给它加 `transform`/`opacity`
这类"动画也在动的属性"都要先想到这一条。换成**动画不用的属性**（这里是 `margin-top`）
比加 `!important` 干净。同类：`devlog/435` 的"负外边距让盒子仍横跨原位"也是"属性的隐含语义"坑。
