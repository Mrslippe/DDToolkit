# 379-20261006 B2 播放卡顿：只在全屏卡 ⇒ 先把全屏那笔合成账砍掉

> 用户口径（一句话把范围钉死）：「**B 站不卡** · **应用内不全屏不卡** · **独立小窗不卡** ·
> **全屏会卡**」，面板 240Hz，视频是 30fps（BV1PcAuzsEts，没大会员 ⇒ 各档都是 30fps）。
> 本篇只是**第一刀**（可以立刻真机验的那种），不是收口。

## 一、先说我排除了什么（别再往那些方向修）

诊断**不在浏览器控制台**：前端把关键行 `POST /settings/client-log`，落进
`<数据目录>/logs/app.log`（本次读的是用户那份 `E:\test\DDToolkit-data\logs\app.log`）。
20:23 那次（渐进式内核）的读数：

```
[video] seek→2.7s 内核=渐进 判定=正常 窗口=4.7s 饿住=1次 最低缓冲=136.3s
        解码=61.8fps 提交=57.0fps 前3秒=72.3 后段=30.0
        最长停顿=0.06s 停顿次数=0 卡帧=1s 丢帧=9/268 末缓冲=135.6s
```

- **缓冲 135s**（那几分钟代理吞吐掉到 0.49–2.36MB/s，但缓冲早就满了）⇒ **不是取数**；
- **停顿次数=0、最长停顿 0.06s、后段=30.0fps**（= 该源原生帧率）⇒ 页内视角看不出"卡"。

⇒ 我先前那个"一次 append 3–8MB 大块卡住解码管线"的假设**作废**（渐进式那条路根本没有 append，
用户实测渐进式也卡）。两条内核都卡 + 音频始终不卡 + **只在全屏** ⇒ 落在**合成**这一侧。

## 二、这一刀改了什么

`frontend/src/styles/posts.css`：

1. **`.vp:fullscreen` 复位圆角**：`.vp` 是 `border-radius: 8px; overflow: hidden`（卡片观感），
   全屏时**原样继承** ⇒ 视频层每帧都要过一次圆角遮罩，而且**阻止浏览器把视频提升到硬件覆盖层**
   （Chromium 的 overlay 路径不接受被裁剪/圆角的层）。全屏时置 `border-radius: 0`。
2. **全屏时把压在视频上的玻璃片去掉 `backdrop-filter`**（`.vp-bigplay` / `.vp-spin`）：
   它会让合成器**每帧重新采样背景**，全屏（大面积）正是这笔账最贵的时候；空闲态那颗播放键
   本来就看不见，缓冲转圈只在画面本来不动的几百毫秒里出现 ⇒ 去掉几乎无视觉损失。

`frontend/src/utils/playbackProbe.ts`：诊断行加一格 **`全屏=1/0`**（窗口开局记一次 +
报告那一拍再看一次当前状态）。为什么要它：只在全屏复现的卡顿，日志里没有这一格时
**同一段视频的全屏/非全屏两组数根本对不上账**。用例 `playbackProbe.test.ts` 三条断言钉住
（记过为 1 / 都没记过为 0 / **开局没记但报告时在全屏也算 1**）。

## 三、这一刀没做什么（留待真机回话再决定）

- 没动取数、预判、`WANT_AHEAD`、ABR —— 上面已经证明它们不是瓶颈；
- 没在全屏时隐藏面板背后的背景层（`.hero-backdrop`）：全屏元素自带不透明黑底，
  Chromium 的遮挡剔除本该把它们剔掉；若真机复测仍然卡，这是下一个要试的（需要页级
  `fullscreenchange` 状态 + 一个类）；
- 没加"主线程长任务"仪表（`PerformanceObserver('longtask')` + rAF 间隔直方图）：
  在 CSS 这一刀之后如果还卡，下一步就是它 —— 那时要区分的是"我们自己每 0.5–1s 的
  周期性活儿"与"窗口/驱动合成"。
