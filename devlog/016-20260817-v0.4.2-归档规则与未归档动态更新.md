# 016-20260817-v0.4.2-归档规则与未归档动态更新

## 规则定义（用户确认）

1. **归档**：`published_at` 早于 30 天前（默认，可配 `days`）的帖子 → `is_archived=1`；
   `published_at` 为空的帖子不参与（无法判定时间）；
2. **不再遍历**：抓取按时间倒序翻页，一旦某一整页的帖子**全部已归档**，更早的页必然也已归档 → 立即停止；
3. **新路由**：更新某个 V 或全部 V 的未归档动态贴文。

## 实现

### 后端

| 位置 | 改动 |
|------|------|
| `PostRepo.archive_before(cutoff)` | 归档规则核心（幂等 UPDATE，返回条数） |
| `scheduler._fetch_posts_core` | 新增 `include_videos` 参数（动态更新只抓动态）；预读 `archived_ids`；
  视频/动态两通道均加**归档边界停止**（整页全归档 → `archived_stop=True` → break）；`PostFetchResult` 新增 `archived_stop` |
| `scheduler.archive_old_posts(cutoff_days, db)` | 归档规则入口（可注入会话） |
| `scheduler.async_update_unarchived_posts(name)` | ① 先执行归档规则 → ② 定位账号（name 模糊匹配/省略=全部）→ ③ 逐个抓动态（`include_videos=False`，翻到归档边界即停），带锁与风控冷却 |
| 路由 `POST /posts/archive?days=30` | 手动执行归档规则（幂等），返回 {archived, cutoff, unarchived_total} |
| 路由 `POST /vtuber/update-posts?name=X` | 更新未归档动态（name 省略=全部 V），返回 {status, archived, total, details} |
| 脚本 `scripts/archive_old_posts.py` | 定时/手动执行归档（--dry-run / --days） |

### 行为说明

- 归档边界依赖**先归档后抓取**的顺序（update-posts 内部已保证）；单独跑 `fetch-posts`/`fetch-all-posts` 也会应用边界停止（`_fetch_posts_core` 统一逻辑）；
- 归档帖仍参与去重（existing_ids 含归档帖），不会重复入库。

## 存量数据执行

```
python scripts/archive_old_posts.py --dry-run   # 10,927 条待归档
python scripts/archive_old_posts.py             # 已归档 10,927，剩余未归档 126
```

## 端到端实测（临时后端 8001）

```
POST /posts/archive?days=30        → {"archived": 0, "unarchived_total": 126}   # 幂等 ✓
POST /vtuber/update-posts?name=明前奶绿
  → {"status":"done","archived":0,"total":{"dynamics":37,"stored":6,"skipped":31},
     "details":[{"archived_stop":true,"rate_limited":false}]}
```
- 遍历 37 条动态（约 2 页）即命中归档边界停止，未继续翻历史；新增 6 条入库 ✓
- 未归档分布：恬豆 55 / 星瞳 40 / 明前奶绿 29 / 七海 2
