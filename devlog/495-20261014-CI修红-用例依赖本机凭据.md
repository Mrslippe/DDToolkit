# 495-20261014 CI 修红：`test_content_gate` 依赖本机凭据

> 用户口径：「这是 token，不过**在建 release 之前先解决 CI 中的问题**」。
> CI 从 38141137142 那一批起就一直红（不只我这次推的），失败点固定：
> **后端单测（python 3.12 / 3.14 两条腿都是它）**，前端腿一直绿。

## 一、根因：登录态有**两半**，用例只造了前半句

CI 日志（`api.github.com/.../actions/jobs/<id>/logs`）：

```
FAILED tests/test_content_gate.py::test_lane_skip_reason_allows_bilibili_when_logged_in
FAILED tests/test_content_gate.py::test_gate_opens_when_logged_in
assert '抓投稿/动态需要登录 B 站：…' is None
assert (False, '抓投稿/…') == (True, '')
2 failed, 1490 passed, 2 skipped
```

闸门 `capabilities.content_fetch_allowed()` 读的是**两个**条件：

| 条件 | 怎么算 | fixture 造了吗 |
|---|---|---|
| `auth_manager.is_logged_in` | `@property`：动态读 `sessdata and bili_jct` | ✅ 造了（patch 两个属性） |
| `auth_manager.needs_login()` | 返回 `__init__` 里**算好并缓存**的 `_needs_login` | ❌ **漏了** |

`_needs_login` 在 `AuthManager.__init__` 里定一次（`not self.is_logged_in`）：

- **本机**：`.env` 里有真凭据 ⇒ 构造时算成 `False` ⇒ 闸门放行 ⇒ 用例**白捡绿灯**；
- **CI**：没有凭据 ⇒ 算成 `True` ⇒ 闸门不放行 ⇒ 用例红。

**同类坑这个仓早踩过一次** —— `tests/test_capabilities.py` 从一开始就 patch 了 `_needs_login`
（那里还留着一句注释吐槽本机环境），只有 `test_content_gate.py` 漏了这一半。

## 二、取证：先用**临时插件**把 CI 的状态复刻到本机

CI 的机器状态 = "构造 `auth_manager` 时没有凭据"。本机复刻它只需要在收集阶段把缓存字段拨到 `True`
（一次性插件，不进仓库）：

```python
# C:\...\Temp\ci_sim_plugin.py
def pytest_configure(config):
    from app.services.auth import auth_manager
    auth_manager._needs_login = True
```

| 跑法 | 结果 |
|---|---|
| 改前 + CI 状态（`-p ci_sim_plugin`） | **复现**：同样那 2 条 FAILED（与 CI 完全一致） |
| 改后 + CI 状态 | `test_content_gate.py` **5 passed**；相邻的 `test_capabilities` / `test_auth` 一起 **60 passed** |
| 改后 + **全量** pytest + CI 状态 | **1494 passed**（0 失败 ⇒ 推上去 CI 应当是绿的） |
| 改后 + 本机正常环境 | 20 passed（那三个文件） |

> ⚠️ 一开始想用"把 `BILI_SESSDATA` 置空"来模拟 CI —— **不管用**：pydantic 仍从 `.env` 读到真值，
> 用例照绿。**模拟环境要拨的是那个缓存字段，不是环境变量**（这也是这次踩空的同一个盲点）。

## 三、修法

`tests/test_content_gate.py` 的两个 fixture 各补一句 `monkeypatch.setattr(auth_manager,
"_needs_login", True/False, raising=False)`，并在 docstring 里写清"两半都得造、否则本机白捡绿灯"
（与 `test_capabilities.py` 的惯例对齐）。

**为什么不是改产品代码**：闸门的行为是对的（没凭据就不发请求，`devlog/086` 的原始动机是
"匿名调用会把 IP 弄脏"）—— 错的是**用例假设了跑它的机器已登录**。

## 三之二、Windows 腿还有**第二条**：定时器早醒后没人再武装（真问题，不是测试脆）

修完上面那条、推上去之后：**Linux 三腿全绿**，Windows 腿**仍然红**，但换了一条：

```
FAILED tests/test_danmaku_words.py::test_timer_drives_the_release_and_rearms_on_use
       AssertionError: 到点应当被定时器释放 / assert True is False
1 failed, 1491 passed
```

**根因（产品侧，不是用例）**：`_on_idle()` 只在定时器到点时看一眼 `release_if_idle()`，而它
"还没到点"就返回 False —— 此时**没有任何人再武装定时器**。而 `threading.Timer` **不保证不早醒**：
Windows 实测会提前几毫秒，于是那一次判断落进"还没到点"⇒ **词典从此永远不被释放**
（要等下一次用词云才重新武装）。Linux 的定时器不早醒 ⇒ 只有那条腿现形。

**两处都改**：

| 改哪 | 怎么改 |
|---|---|
| 产品 `_on_idle` | 释放没成功就**再武装一轮**（`if not self.release_if_idle(): self._arm_timer()`）。⚠️ 放在这里而不是 `release_if_idle()` 里 —— 后者是"看一眼"的判据，用例会用注入的 `now` 直接调它，不该有起定时器的副作用 |
| 用例 | 把"睡死 0.6s"改成**轮询到点**（上限 10s，失败时打印 `tk.state()`）：保留"真驱动"这个性质，同时不把"多久算够"写死 |

护栏：新增 `test_early_timer_fire_rearms_instead_of_giving_up`（把 `_last_used` 往后挪来造"还没到点"，
不赌调度）。**反向验证**：把 `_on_idle` 的重新武装去掉 ⇒ 它当场红（「早醒之后没人再武装定时器」）。

> ⚠️ **我在这条上自己踩了仓里的老坑**：做反向验证时用 `Set-Content -Encoding UTF8` 回写源文件，
> **PowerShell 给 `danmaku_words.py` 加了 BOM**（`ef bb bf`，diff 里第 1 行被改）。
> 是 `git diff` 里那行 `-"""弹幕分词…` / `+﻿"""弹幕分词…` 露的马脚 —— 按字节裁掉 BOM 才干净。
> **教训重申**：源文件只能用 `edit`/`write` 工具改；要做"改—验—还原"，用 `git stash` 或先备份到
> 临时目录再整文件拷回，别用 PowerShell 的 Set-Content。
