# 311-20261004 S1 spike：段表解析成立，MSE 双缓冲可播（seek 399ms 出画、稳定 30fps）

> 计划：`docs/plans/bili-mse-kernel-execution.md` §五 S1「后端段表接口 + 最小 MSE 页，
> 判据 = seek 后 1.5 秒内出画、稳定 ≥29fps、解码停=0」。这一篇是 spike 的实测结果。

## 一、段表（`app/services/bili_segments.py`，新增）

解析 `ftyp`/`moov`/`sidx`，从**真流**上量到的结果：

```
段数=54  段长=5.0s  总时长=265.33s  init=948B  首段=1628–1571488  覆盖全文件=True
```

（对照 `devlog/306` 那次手工探测：moov 912B / sidx 680B / 每条 mdat 1,567,961B —— 完全一致，
`覆盖全文件=True` 说明"逐段字节数之和 + 首段起点 = 文件总长"，没有漏段也没有重叠。）

### 踩到的两个坑（都写进判据了）

1. **`sidx` 的固定字段别漏 `timescale` 那 4 字节**：第一版算成
   `ver/flags + refID + EPT + first_offset + reserved`，把 count 读成 **0**，
   于是整条流被判成"没有段表"。正解：`fixed = 4+4+4+2*ept_size+2`（v0 ⇒ 22，条目从 24 起）。
2. **判据用"算术自洽"而不是"版本号"**：`8 + fixed + 2 + count*12 == 盒长` 这条**唯一确定**布局
   （真数据上版本字段与字段宽度并不总是一致）。测试里正反两面都钉了：
   盒长少一条 ⇒ 必须拒绝，而不是硬读出一张歪表。

## 二、MSE 最小内核（spike 页，跑在无头 Edge 里，同条件对比）

同一个视频、同一个本机代理，两个页面跑同样的动作（播 4 秒 → seek 到 75% → 量 10 秒）：

| | 现状 progressive（`src=` + 独立音轨） | **MSE（双 SourceBuffer）** |
|---|---|---|
| 起播（seek 后到出画） | 425ms | **399ms** |
| 段表 | — | 54 段 × 5.0s |
| 启动耗时 | — | **206ms** |
| seek 后帧率 | 30fps 稳定 | **30fps 稳定**（142 帧的追赶只占 1 秒） |
| 前方缓冲 | 6–14s（**浏览器自己决定**） | **20–24s（我们的泵维持）** |
| 事件 | `waiting=2` | `waiting=2`、**errors=[]** |

泵的形状（下一步要用在生产里）：串行队列 —— 淘汰（`remove`）与补段（`appendBuffer`）**同一个 sb 同时只能有一个操作**，
外加 500ms 定时踢一脚。spike 第一版把两者各自异步发起 ⇒ 撞出
`This SourceBuffer is still processing an 'appendBuffer' or 'remove' operation`，
而且泵一停缓冲就抽干（读数里从 5.5s 一路掉到 `None`、`readyState` 掉到 2）。

## 三、诚实记两笔

1. **无头环境不重放真机那个"2–4 秒冻帧"**：两条路径在这台机器上都是 30fps。
   所以 spike 证明的是"**MSE 这条路走得通、且各项指标不劣于现状**"，
   "能不能治真机那个冻帧"仍要**真机验证**（这正是 S1 的判据里"真机"那一半）。
2. **MSE 不能消掉全部预滚**：seek 落到段内时，解码器仍要从段首关键帧解到目标（样例里那 142 帧
   的爆发就是它）。但差别在于：**这段数据已经在手里**（整段 1.5MB 已 append），
   而 progressive 那次要**先猜字节位置再去取** —— 真机上 2–4 秒的空白就在那一步。

## 四、下一步（S2）与一个要你点头的取舍

S2 = 把这个内核接进 `VideoPlayer`（保留自绘控件/清晰度菜单/全局音量倍速），并按计划**保留老路径开关**。
我的建议是**先 opt-in**（设置项或 URL 参数开），你在真机上验一次——

- 真机上"拖到很后面"不再冻帧 ⇒ 再把默认切到 MSE；
- 万一 MSE 在你的机器上更差 ⇒ 开关切回来，零风险。

理由：headless 复现不了那个冻帧（见 §三.1），而**默认切换影响每一次播放** ——
这一刀该由真机数据来切，不该由我这边的推理来切。
