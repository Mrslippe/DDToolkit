## 一、先把"贵在哪"量出来：计算不是瓶颈

| 项 | 实测 | 结论 |
|---|---|---|
| 四道门禁（pytest + tsc + eslint + vitest） | **59.6 秒** | 便宜，可以每次改动都跑 |
| 单个 UI 探针模式（含起后端 + Vite + 浏览器） | **15.0 秒** | 便宜 —— **我原以为要 1~3 分钟** |
| `npm run release`（整包） | ~6 分钟 | 贵，但只在动 Rust 壳/安装包时才需要（RELEASE.md §3 早已写明） |

所以我原本打算推荐的"探针改成一次启动跑全部模式"**不成立**（五个模式合计只能省 30~40 秒，
却要引入耦合），拆小 pytest 同理。**真正的成本是：错结论换来的返工**，以及每次会话
重新通读文档（8 份活文档 ≈ 2900 行 / 约 6~7 万 token，外加 85 篇 devlog）。

## 三、落地的四项（用户选定）

### 3.1 `scripts/smoke_upstream.py`（常驻端到端冒烟）

数据目录副本 + 真后端 + 真上游，跑五条"只有真环境才暴露"的链路：

| 检查 | 断言 |
|---|---|
| `bili_search_name` | 真打 B 站名称模糊搜：有结果、`numPages` 正常；未登录 → **skip 并说明**（不算通过） |
| `bili_exact_uid` | 纯数字走 `acc/info` 精确通道（搜索接口搜不到 uid），返回 `exact=true` |
| `pool_search_labels` | 候选池检索每一行都带合法 `origin`（前端按它决定收录路径） |
| `pool_external_adopt` | 挑一条**索引来源**（不在 csv 池里）的条目：不带 `source` → 404、带 `source='bilibili'` → 201（服务端实查复核）、重复 → 409 |
| `live_upstream` | 场次第三方取数：`wc_status` 必须是设计的四态之一；`fetch_failed` → skip（上游此刻不行，不是链路坏） |

接进一把梭：`python scripts/dev_check.py --upstream`（真上游 + 冷进程各一次）。

索引条目 `'以太'(uid 88358)` 走通池外收录）。

## 四、冷进程模式当场抓出的两个错（都属于"我的结论"）

### 4.1 「空数据目录」并不等于「候选池为空」

冷进程断言"池外收录在未登录时应当 503"，实得 **201**。查下去：

- 日志写着 `收录 VTuber#1 「永雏塔菲」… 来源=pool` —— 走的是**池内**路径；
- `backend_main.py` 首启会把**随包分发的 `vtubers.csv` 引导复制进数据目录**；
- 于是我挑的那个"真实 uid"本来就在池里，测的根本不是池外通道。

修法：池外检查改为**先找一个不在池里的 uid**（`/vtuber/pool/search?kw=<uid>` 空结果即池外）。
**结论**：测试用例挑数据时，要挑"能证明结论"的那一份，而不是"看起来真实"的那一份
（和 §二 里"抽样前 200 行"是同一个错法）。

### 4.2 「B 站检索需要登录」的口径第三次澄清 —— 是**我们自己的**取键逻辑

冷进程跑出 `not_logged_in`，但同一次运行里 `acc/info`（uid 直查）**成功了** —— 自相矛盾。
直接用原始回包定论：

```
[裸 nav]      code=-101 message='账号未登录' 有 wbi_img=True
[auth 头 nav]  code=-101 message='账号未登录' 有 wbi_img=True
[get_wbi_keys] 抛异常 Exception: 获取WBI密钥失败: 账号未登录
[acc/info]     抛异常 Exception: 获取WBI密钥失败: 账号未登录
[relation/stat] -> {'follower': 2753673, 'following': 142}     ← 这条没签名，通
```

也就是说：**B 站并不要求登录**——匿名 `nav` 一样返回 `wbi_img`（WBI 密钥）；
是我们自己的 `wbi.get_wbi_keys()` 看到 `code != 0` 就 raise，于是"有密钥却用不了"。
我先后写过两个版本的结论（"不需要登录" → "两条路径都需要登录态"），**两个都不准确**：

- 事实 A：平台侧**不要求**登录（密钥随 `nav` 一起下发）；
- 事实 B：当前实现**要求**登录（因为 `get_wbi_keys` 在 `-101` 时不肯用现成的 `wbi_img`）；
- 事实 C：`relation/stat` 没走签名，任何情况下都能取（粉丝数）。

这条留作**待用户拍板的改进**（改 `wbi.get_wbi_keys` 会让共享的 WBI 路径在未登录时也能签名，
属产品决策），因此本批只把 `not_logged_in` 的 hint 保留、把它写进本 devlog 与
`docs/releases/v1.0.1.md` 的"需要登录态"表述之外**不再新增错误说法**。

## 六、给需求层（用户侧）的建议 —— 已写进 `docs/TODO.md` §0 用法

1. **报 bug 四行**：① 我在做什么（界面/按钮/输入）② 期望什么 ③ **实际什么（截图或原文报错）**
   ④ 每次都发生吗。本会话最有价值的一条报告就是那张截图（真实现场 + 最短复现，10 分钟定位根因）；
   反例是"微博登录过期"（其实没过期），我按错误前提白查一轮。
2. **功能需求补一句"怎么算做完"（验收标准）**。R11 若写了"我在 B 站搜一个池里没有的新 V，
   能加进来且名字正确"，那么"索引来源走哪条收录路径"在方案阶段就会被追问 ——
   用户实测到的那个 bug 大概率不会发生。
3. 明确**哪些决策归你**（R11 那四个口径是范式，我不用猜）。
4. 结论影响你判断时，要求我标"实测 / 推测"（你已经纠正过我两次，两次都避免了错误发布）。

## 七、不建议做（避免把力气花错地方）

- 探针"一次启动跑全部模式"：实测只省 30~40 秒，不值；
- 拆小 / 并行 pytest：全量 60 秒，拆了会让"全绿"失去意义（本仓已有三次"测试量错轴"的教训）；
- **为省 token 砍文档**：文档是这项目最大的质量资产；要省的是**重复通读**，不是文档本身；
- 自动化装机验证：装一次直装版 / 便携版必须人工，且正是历史上坏过的那一步。
