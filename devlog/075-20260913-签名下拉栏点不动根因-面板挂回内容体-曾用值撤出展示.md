# 075-20260913-签名下拉栏"点不动"根因 + 曾用值撤出展示（含一次自伤复盘）

> 用户实测两条反馈：
> ① **下拉栏里的项选不了，鼠标既不能 hover 也不能点击**；
> ② 「曾用签名」的语义不对 —— *"我指的是 V 在平台上的曾用签名"*，展示出来的却是
>    *"上次我修改入库的错误签名"*，而且这类内容**应该归到「账号信息历史快照」，先不展示**。
>
> 本批 = 一个真 bug 的根因修复 + 一次口径回退。**没有迁移**（f004 不动）。

## 一、"点不动"的根因：radix 给 `document.body` 打了 `pointer-events:none`

不是 CSS 层级、不是 z-index、不是命中区太小 —— 是**事件根本没送到面板**。

`@radix-ui/react-dismissable-layer` 在模态弹窗打开时会：

```js
ownerDocument.body.style.pointerEvents = "none";      // 关掉整页命中
// 只有弹窗内容体自己拿到内联的 pointer-events:auto
style: { pointerEvents: isBodyPointerEventsDisabled ? (isPointerEventsEnabled ? "auto" : "none") : undefined }
```

而上一版（devlog/073）把面板 **portal 到 `document.body`** —— 它继承了 body 的 `none`：
hover 样式不触发、click 不派发，**且控制台一声不响**（这是最坑的地方：几何全对）。

于是坐标、宽度、渐隐、再点收起全都测过且全绿，唯独"点不着"没人能发现 ——
**因为几何断言看不见 pointer-events**。

### 为什么不能只加一行 `pointer-events:auto`

试过两条岔路，都会被 radix 反噬：

| 方案 | 结果 |
|---|---|
| portal 到 body + `.vd-sign-panel{pointer-events:auto}` | 面板重新算作"弹窗之外"：radix 的 `deferPointerDownOutside` 会把行上的 pointerdown 记账、**在随后的 click 上关掉整个弹窗**（`onDismiss: () => onOpenChange(false)`） |
| portal 到**弹窗内容体**里 + 继续 `position:fixed` | 内容体带 `translate-x/y-[-50%]`（**是包含块**）→ `fixed` 退化成"相对内容体"，按视口算的坐标全错 |

### 最终结构（第三版）

**不做 portal**：把面板渲染成「**弹窗内容体的直接子元素**」，并且放在滚动体
`.vd-settings-scroll` **之外**，用 `position:absolute` + 相对内容体 padding box 的坐标：

- 与内容体共享 radix 给的那份 `pointer-events:auto` ⇒ hover/点击正常；
- 在内容体 DOM 子树内 ⇒ radix 不当它是"点了外面"，点行**不会**关掉弹窗；
- 不在滚动体的盒子里 ⇒ 不会被 `overflow:hidden` 裁掉，也不必跟 transform 包含块较劲。

### 顺带踩到并修掉的两个坑（都写进注释防复发）

1. **`.vd-settings{position:relative}` 把弹窗自己搞飞了**：本文件（`posts.css`）在 Tailwind
   之后加载，`.vd-settings` 与内容体上的 `.fixed` **同特异度**，后者被盖掉 → 弹窗从
   "视口居中浮层"变成"文档流里的相对定位"，实测飘到视口下方 620px
   （探针量到 `dialogRect.top=689 / 视口高 621`），于是面板既出视口、`elementFromPoint`
   也打不到。**面板的包含块根本不需要它**（内容体本身就是 `fixed`，已定位）。
2. **不给 `DialogContent` 传 `ref`**：`components/ui/dialog.tsx` 里它是普通函数组件，
   React 18 下 `ref` 被静默丢弃 → `placePanel` 提前 return → **面板压根不渲染**
   （探针量到 `rows=-1`）。改成 `signFieldRef.current.closest('.vd-settings')` 找包含块。

## 二、定位不再"只量一次"：transform 与"位置变了但尺寸没变"

两件之前没意识到的事：

- **`ResizeObserver` 不会被 transform 触发** —— 它看的是布局盒，缩放不改布局。所以
  弹窗入场动画（`zoom-in-95`）期间量到的"缩小态"宽度（438→424.9）**永远不会被 RO 纠正**；
- 弹窗内容会在开面板后继续长高（头像图加载、账号列表渲染）→ 输入条**位置**变了，
  但**尺寸**没变 → 任何"只看尺寸"的观察者都不会醒，面板就停在上一个位置。

改法：开面板后跑一段 rAF（90 帧 ≈ 1.5s，覆盖入场动画与首屏落位），**锚点矩形一变就重定位**；
之后交给 `ResizeObserver`（锚点 / 内容体 / `.os-scroll` 内容包裹层）+ `scroll`（捕获）+
`resize` + `animationend/transitionend` 兜底。收起时清掉位置，避免下次用旧坐标闪一帧。

## 三、曾用值：撤出展示 + 手改不再入账

用户口径（原话要点）：

- **语义**：曾用签名 = **V 在平台上曾经用过的签名**（"曾用名和曾用签名这些内容应该归类在
  账号信息历史快照中"）；
- **展示**：**先不用展示出来**；
- **事实纠正**：当时展示的是 *"上次我修改入库的错误签名而不是真的历史签名"*。

于是：

| 项 | 处置 |
|---|---|
| 档案设置里的「曾用签名」行、账号行下的「曾用名」行 | **删除**（含 `.vd-former` / `.vd-acc-former` 两条 CSS） |
| 前端 `api.getFormerValues` 包装与调用 | **删除**（连同 `VTuberFormerValues` 的引用；类型定义保留并注明"暂未接入"） |
| `PUT /account/{id}` 的记账 | **删除** —— 手改是本地动作，不是"平台上曾经用过的"；这正是用户看到脏数据的那条路径 |
| 抓取覆盖前的记账（`scheduler._fetch_one_account`） | **保留**（这才是平台侧的旧值），`GET /vtuber/{id}/former-values` 端点保留为那条线的读取口 |
| 数据表 `vtuber_field_history` | 保留（结构没变，f004 不动） |

> 记一笔：这条口径兜了一圈（074 引入展示 → 075 撤出）。**根因是我把"曾用值"的语义理解成
> "被覆盖掉的旧值"，而用户要的是"平台侧的历史值"** —— 两者在手改入库时就会分叉。
> 现在记录只在平台覆盖前发生，语义就唯一了。

顺带修掉弹窗引导文案里的 **markdown 星号**：`改动**点了就生效**（无需保存）` 会把 `**`
原样显示给用户（JSX 文本节点不解析 markdown），已去掉。

## 四、护栏：给"点不着"补上机器判据

几何断言对 pointer-events 完全无感，所以 `--settings` 探针这次补的是**可点性**：

| 新断言 | 判据 |
|---|---|
| `panelHit` / `rowHit` | `document.elementFromPoint(面板/首行中心)` 必须命中所属元素 —— pointer-events 被吃掉时立刻为 False |
| `panelParentIsDialog` / `panelOutsideScroller` | 面板是内容体直接子元素、且不在滚动体盒子里（结构判据） |
| `panelPosition == 'absolute'` | 别再改回 portal+fixed |
| `panelPlacedByRect` | 面板左缘与输入条对齐、上缘贴其下 6px（翻转时在上方） |
| `pickValueMatches` / `pickChanged` | 真点一行（`pointerdown→mousedown→mouseup→click`）后输入框变成那行的签名 |
| `pickKeepsDialog` | 点行**不把整个弹窗关掉**（radix 的"点了外面"那条路） |
| `pickClosedPanel` / `restoredSource` | 选完面板收起；探针把来源还原成打开时那一行（不留副作用） |

补充两条测量口径（都是被这次踩坑逼出来的）：

- **关掉动画与过渡再量**：探针跑在虚拟时间下，预算用完时入场动画会**冻在中途**
  （实测冻在 scale .97）→ 同宽/贴下方这类断言间歇性失败。停掉动画后连跑 3 次全绿。
- **同宽看 `offsetWidth`**（布局宽），不看视觉矩形 —— 缩放态下矩形会同比缩小。

**反向验证过护栏会红**：把 `.vd-sign-panel` 临时加上 `pointer-events:none`（= portal 那版的
失效形态）重跑 → `panelHit=False / rowHit=False` 并报出"面板命中测试失败"，去掉后恢复绿。

## 六、遗留

- 面板定位仍依赖"锚点矩形"这一套 JS 计算（没有用原生 `anchor()`）：多显示器/缩放切换、
  弹窗被拖动等场景没有覆盖；90 帧 rAF 之外的变化只靠 RO/scroll/resize 兜底。
- 探针**测不到**"入场动画进行中"的瞬时错位（虚拟时间下动画会被冻住，见 §四）：
  真机上那 200ms 由 rAF 重定位覆盖，但机器判据只保证**稳态**关系。
- 曾用值的展示入口待"账号信息历史快照"那条线落地后重新设计（数据一直在记）。
