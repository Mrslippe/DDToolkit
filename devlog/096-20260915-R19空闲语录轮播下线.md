# 096-20260915-R19 空闲语录轮播暂时下线

> 用户口径（2026-09-15）：「顶栏状态栏空置的时候轮播的语录集暂时下线，**等之后库中真有了
> 条目再上线**」。这是发 v1.0.2 之前的最后一个改动。

---

## 一、为什么下线

R12b 上线的那 7 句内置语录（"档案已就绪，随时可以翻"…）是**占位文案**，不是库里真有的东西。
顶栏空转着几句与数据无关的话，看起来像"这个控件在自娱自乐"；用户要的是——**等库中真有了条目
（弹幕热词 / 名场面 / 直播倒计时）再上线**，那时轮播说的才是"真东西"。

## 二、下线不是删掉（三样东西都留着）

| 留着的东西 | 为什么 |
|---|---|
| `idlePool()` 与 7 句内置语录 | 池子照建 —— 探针仍在量"池子还在不在、第 0 格是不是状态文案、池内有没有进度词" |
| 取模选格逻辑（`pickIdle`） | 单测用 `enabled: true` **覆盖着测**，逻辑不会烂；上线时不用重写 |
| `registerIdleProvider()` 扩展点 | 将来接真实条目（热词/名场面/倒计时）就走这个口子 |

新增一个开关 `IDLE_CAROUSEL_ENABLED = false`，`StatusIsland` 在它关着时**连定时器都不开**
（文案恒定，每 6s 重渲染纯属白干）。

## 三、护栏跟着"反向"（这条比改动本身更重要）

下线最容易变成"悄悄关掉、没人知道"。所以探针 `--status-island` 的判据**整体反过来写**，
并且把"开关状态"变成 DOM 上的单一事实来源：

```
空闲轮播：开关='off' 池=8 三格=['数据服务运行中', '数据服务运行中', '数据服务运行中'] 索引=[0, 0, 0]
```

- 空闲文案三次采样**必须完全一致**且等于「数据服务运行中」；索引恒为 0；
- `data-idle-carousel` 必须是 `'off'` —— 它由 `IDLE_CAROUSEL_ENABLED` 驱动，
  **改常量不改断言就会红**（反之亦然）：省得哪天悄悄开了/关了没人知道；
- 池子长度、第 0 格是状态文案、池内无进度词 `轮询`/`抓取中`/`同步` —— **照旧断言**：
  R12b 那条教训（语录是长期驻留文案，写成进度词就破坏了「自动节拍不占顶栏」）
  在将来接真实条目时同样成立。

单测这边：新增「语录集下线」三条（默认任何时刻都返回状态文案 / 实现没被删（`enabled: true`
仍能轮播）/ 下线不影响扩展点），并把"索引前进/回卷"那组用例显式传 `enabled: true` ——
**测的是机制，"当前关着"由另外那组钉住**，两者不混。

## 四、上线时要做什么（写在常量注释里，免得将来翻半天）

1. `utils/idleQuotes.ts`：`IDLE_CAROUSEL_ENABLED = true`；
2. `scripts/ui_probe.py` 的 `--status-island`：恢复"必须轮播 / 索引前进 / 文案不重复"那组断言
   （探针会先红 —— 故意的）；
3. 真要"库中真有条目"，接 `registerIdleProvider(() => [...])`（弹幕热词 / 名场面 / 倒计时）。
