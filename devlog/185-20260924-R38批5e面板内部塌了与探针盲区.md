## 二、根因一：`OverlayScroll` 的样式在小窗里根本没有

`OverlayScroll` 的 CSS（`.os-root` / `.os-scroll` / `.os-thumb`）在 **`layout.css`** 里。
而小窗的独立入口（`widgetMain.tsx`）**只引 `tokens.css` + `status-island.css`** ——
**不加载 `layout.css`**。

后果：小窗里
- `.os-root` 拿不到 `display:flex; flex-direction:column; overflow:hidden`
- `.os-scroll` 拿不到 `flex:1 1 auto; min-height:0; overflow-y:auto`

⇒ 头部 / 滚动体 / 页脚**不再各占各的位置**，条目直接压到页脚上。

**修法**：把整块搬进 `status-island.css`（`App.tsx` 两个文件都引，主窗口不受影响）。
搬家方向是**单向的**（`layout.css` → `status-island.css`），反过来不行 ——
小窗引 `layout.css` 正是独立入口要避免的那 153KB。

> ⚠️ **这正是我上一批（devlog/181）刚写进 `DEV-LOOP.md` §6.1 的坑**：
> 「拆入口时**顺带生效的全局样式**是最容易漏的一类依赖 —— 它不在 import 图里」。
> 上次漏的是 Tailwind preflight 的 `box-sizing`，这次漏的是另一个文件的**组件样式**。
> **同一条纪律，第二次犯。** 差别只在于上次是"框架给的"，这次是"我们自己另一个文件给的" ——
> 而**后者更容易漏**，因为它看起来"明明是我们自己的代码"。
>
> 已把判据补进 §6.1：**搬家/拆入口之后要按"用到它的入口有几个"审一遍共用组件**，
> 不是问"它看起来属于哪一块"。审计办法（本次现写的）：
> 从组件源码抓出所有 `className`，逐个查"是否只在另一个入口的 CSS 里定义"。

## 三、根因二：`calc(60vh - 74px)` 在真窗口里是**负数**

`.si-panel-scroll` 的 `max-height: calc(60vh - 74px)` —— 74px 约等于 head(34) + foot(40)。

探针里视口 621px ⇒ `60vh - 74 = 298px`，**夹不住**任何东西，看着完全正常。
真窗口只有 **40px 高** ⇒ `60vh = 24px` ⇒ **`24 - 74 = -50px`** ⇒
滚动体高度归零 ⇒ **条目一条都看不见**，只剩标题和页脚。

而 `.si-panel` 那条我在批 5d 已经改成 `--widget-panel-max-h` 了，
**却漏了 `.si-panel-scroll` 这条**（同一个死锁的第二处）。现在两处都用同一个变量：

```css
.si-panel        { max-height: var(--widget-panel-max-h, none); }
.si-panel-scroll { max-height: calc(var(--widget-panel-max-h, 60vh) - 74px); }
```

（主窗口里没有这个变量 ⇒ 退回原来的 `60vh`，行为不变。）

## 四、最该记的：**"只在真机上生效的修复"等于没法验证的修复**

上面那条 CSS 变量，我原本写在**"展开就 resize"那个 effect** 里。而那条 effect
**第一行就 `if (!('__TAURI_INTERNALS__' in window)) return`** ——
于是**探针里这个变量永远设不上**。

也就是说：批 5d 那句"已修"实际上**只在真机上成立**，探针里一直走的是 `60vh` 分支。
这正是"我修了、我验了、但验的不是我修的那条路"。

**修法**：把它挪成**独立的 effect**，任何环境都设
（`window.innerHeight` 在真窗口里是窗口高、在探针里是视口高，语义一致）。

**判据（可复用）**：一个修复如果依赖"某个只在真机存在的条件"，
那么**它的验证也必须在真机上** —— 否则就要像这样把变量准备挪到环境无关的地方。
**别把"修好了"和"在探针里绿了"当成同一件事。**

## 五、探针盲区补课（两处）

### 5.1 只验了外框，没验里面

批 5d 我加的三条判据全是**面板外面**的：在不在视口内 / 点不点得着 / 高不高。
**外框对 ≠ 里面没坏** —— 真机上外框完全正常，里面却是叠的。
新增四条内部判据：`osStylesOk`（共用组件样式加载了没）·
`panelNonOverlapping`（头/滚动/脚纵向不交叠）· `panelSumH ≈ panelH`（没被压扁）·
**`scroll` 高度 ≥ 24px**（滚动体没被压成 0）。

### 5.2 视口尺寸不对（**最难发现的那个**）

所有旧判据都跑在**浏览器视口**（约 1076×621）里，而真窗口是 **200×40**。
凡是按 `vh` 算的东西在 621px 下**全都显得正常** —— 这是个**系统性盲区**，
不是"某条断言写漏了"。

**修法**：新增一段**按真窗口尺寸**（200 宽 × 90 高）跑的判据。
⚠️ **只改宽度是不够的**：我第一版只把宽度改成 200、高度照旧用 `--height(=760)`，
结果**绿的，但什么都没验到**（`60vh` 在 621px 下永远够大）。
**盲区的形状是"尺寸"，不是"宽度"** —— 宽度和高度都得压到真机量级。
