# 422-20261007-V1b5取景框放大到整幅宽

需求 7 第六批。用户口径一句话：**「把这个取景框放大到宽度填充满」**。

## 改了什么

- `.vd-bg-preview`：`132×74` 缩略图 → **`width: 100%` + `aspect-ratio: 16/9`**（`max-height: 260px`
  只是超宽弹窗的兜底）。高度跟着宽度走，框里终于看得清裁切。
- 背景区由**横排改竖排**（`.vd-bg-row` → `.vd-bg-col`）：预览在上、按钮排在下面一行。
- 「重置取景」从按钮排**搬进框内右上角**（`.vd-focus-reset` 绝对定位）；缩放读数在右下角、
  一次性引导在左下角 —— 三个角各占一处，谁也不挤按钮。
  ⚠️ 框内那个钮必须在自己的 `pointerdown` 上 `stopPropagation`，否则按一下会顺手起一次拖拽（有用例钉着）。
- 没背景图时的"头像铺底"**沿用同一个框位**：上传前后那一块不会跳高度。

## 判据（+5）

组件侧（13 条）：1:1 跟手（460×613 的图、scale=2、右拖 30px ⇒ x 减 30/460）· `scale=1` 纵向跟手横向不动 ·
滚轮 `preventDefault` / 一格 ≈ +16% / 缩回正好 1× / 封顶 3× · **渲染里不许有 `input[type=range]`** ·
引导句只在没取景时出现 · ★**重置钮的 pointerdown 不许起拖拽** · 死区 · 松手才存 · 关窗兜底 · 坏 JSON · 方向键。

★ 新增 `BackgroundFocusEditor.css.test.ts`（4 条 **CSS 契约**）：**预览框必须 `width:100%` + 比例推高**、
且不许退回 `132px`/写死高度；取景三件套的**落点在内层**（`position:absolute` + `inset:0` + 外层
`overflow:hidden`/`position:relative`）；框内三个控件都是绝对定位 + 不挡指针；背景区是竖排。
**为什么非要用 CSS 判**：这几条**组件测试看不见** —— jsdom 里没有布局，把 `width:100%` 改回 `132px`
照样全绿，而真机上框会窄回去。

**反向验证**（三组突变，逐条对得上）：`width:100%` → `132px` ⇒ 第 1 条红；内层去掉 `position:absolute`
⇒ 第 2 条红；去掉 `touch-action:none` ⇒ 第 3 条红。

## 教训：突变本身也要证明"真的生效了"

第一次跑突变 2 时"全绿"，差点当成"判据不成立"——实际是我用 `\r\n` 去匹配一份 **LF** 的 CSS，
`String.Replace` 什么都没换，文件原样写回。**改判据/改代码的脚本不能只看结果，要当场打印
"替换是否发生"**（`$mut -ne $orig`）。这和 `devlog/419` 那次"事件派发成功 ≠ 处理器跑了"是同一类错：
**中间层静默失败**，两端都看不出来。
