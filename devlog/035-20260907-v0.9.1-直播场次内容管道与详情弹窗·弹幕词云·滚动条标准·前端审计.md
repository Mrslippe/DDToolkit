## 三、弹幕词云（danmakus v2 live 词云 → 加权 Voronoi 自绘）

**选型历程**（都是死路，最终自绘）：
- `react-word-cloud` **404**；`react-wordcloud@1.2.7` 可用（peer react16，`--legacy-peer-deps`，React18 OK）但形态是独立圆形气泡；
- `d3-circle-pack`/物理挤压方案不满足「面积 ∝ 词频」——**weighted-Lloyd 对均匀采样收敛到等面积**（node 原型验证，权重只影响初始站点）；
- `powerdiagram` npm **404**；d3-delaunay（普通 Voronoi）无权重；
- **结论：手写 Balzer 2005 加权 Voronoi（power diagram）**，零外部依赖。

**实现要点**（`LiveCalendar.tsx layoutPowerCloud`）：
- power 单元 `cell_i = ∩{x: |x−c_i|²−λ_i ≤ |x−c_j|²−λ_j}`，用**线性半平面 Sutherland–Hodgman 裁剪**直接求（无需 3D 凸包）；
- 每轮：① 站点弛豫（站点 → power 单元质心，power-Lloyd）② 权重修正 `λ += β(目标面积−当前面积)`，β=0.5；120 轮上限、maxRel<0.1 早停——node 原型验证：~51 轮收敛、面积偏差 ≤8%、**无空单元**（面积∝词频由数学保证）；
- 初始站点极坐标（hero=中心、大词靠内、黄金角 + 抖动），种子 `mulberry32(20260907)` → 同数据同布局不闪动；
- 视觉：10 色浅粉系填充（`--c-bg-card` 2px 描边分隔）、深色词字（hero 700，fs = max(8.5, min(hero?34:26, r*0.75, r*2.2/len))，`r>10.5 && len<=6` 才显示词字——放宽后中等格子长词不再被吞）；hover 当前格 1 + 文字 700，其余 0.4 + 文字 0.25；**hover 提示 = 黑玻璃胶囊「词 · N 次」**（clientX/Y 跟随）；
- 数据 = `detail.data.danmaku.top_words`（top40 带次数，后端 `LiveDanmakuInfo`）；高度 210px，宽度随容器（ResizeObserver）。

## 五、滚动条标准定案 + OverlayScroll（本批硬骨头）

**用户定案**：全应用统一；**不占布局宽度**；**不滚动/不 hover 时自动隐藏**；具体数值：贴右 4px、宽 4px、常态 `--c-border`、hover `--c-primary`、胶囊。

**演进**：
1. 全局 `::-webkit-scrollbar` 12px 槽 + 4px 内收（border transparent + background-clip: content-box）+ 灰常态/粉 hover——`scrollbar-width/color` 标准属性会令 webkit 规则全部失效，**禁用**；
2. 弹窗/浮层/list/archive 逐个排查——发现带 `scrollbar-width:thin` 的弹窗回退到系统默认带箭头滚动条，删除后统一；再发现**原生滚动条占布局宽度**（list/archive 内容被挤）→ 用户要求不占宽；
3. **overlay 思路定案** → `OverlayScroll` 组件：原生条隐藏（`display:none` + `scrollbar-width:none` 双保险）、拇指绝对定位悬浮、显隐纯调度。
4. 连踩的坑（都修了）：
   - **percent 高度失效**：`.os-scroll{height:100%}` 在 auto 高度根（弹窗 max-height）下解析为 auto → 弹窗滚不动 → 改 `.os-root{flex column}` + `.os-scroll{flex:1 1 auto;min-height:0}`（经典 modal 模式）；
   - **ResizeObserver 不触发**：内容长高改变的是子元素边框盒、scrollHeight 增长不触发自身 RO → 观察滚动体 + **首个子元素** + 400ms 轮询兜底；
   - **鼠标悬浮常亮不隐藏**：hover 清除定时器后未重排 → 改为 hover 亮出 1.2s 无动作自动淡出；
   - **拖拽状态机 = 唯一楔死路径**（pointer capture 丢失/拖拽中永远不隐藏）→ **移除拖拽**，拇指纯展示 `pointer-events:none`，隐藏定时器无条件执行；
   - **视图级容器漏网**：用户澄清「还是没有自动隐藏」指的是**视图本身**（`.archive-view`：profile 视图 + 日历/趋势外包）而非卡片内部 → 两处全部换 OverlayScroll。
5. **审计后补 hover 视觉**：`.os-root:hover .os-thumb` → 变粉 + 加粗 6px（right 同步 3px 保中心）——此前实现与注释承诺不符（thumb 无 hover 态）。

**落地清单**（F3）：list-scroll / archive-view×2 / archive-section-scroll×2 / lc-dlg / lc-pop / **侧栏 sidebar-list**（旧 5px 蓝灰可拖拽自绘条退役）；`.type-chips`/`.lc-stats`/`.lc-dlg-cat-pop` 横向或小面积滚动态一律**隐藏滚动条**（不占布局高度）。

## 后记（同日）：拇指拖拽恢复（robust 版）

用户问「拖拽功能为什么没有了」——答：删拖拽是为根治"滚动条不自动隐藏"（pointer capture 丢失 → 拖拽状态机抑制隐藏定时器 → 拇指常驻，即此前反复出现的问题）。用户选择恢复，改用四重兜底实现（`OverlayScroll.tsx`）：

- 按下 = `setPointerCapture` + 记录 `grabY`（指针相对拇指顶偏移）；移动 = **绝对反解** `scrollTop`（非增量累加，消除 clamp 累积误差）；
- 结束四重兜底：`pointerup` / `pointercancel` / `lostpointercapture` / **window `blur`**（拖出窗口、alt-tab、弹层拦截、捕获丢失全覆盖），结束**无条件** `reveal(700)`；
- 拖拽期间 `onScroll` 仅 `sync` 不 `reveal`（停顿不隐藏，收尾交给 `endDrag`）；
- 指针策略：基态 `pointer-events:none`（未显示零打扰），`.os-show` 后 `auto` + grab/grabbing 光标 + `touch-action:none`。

验证：`tsc` + `vite build` 通过；快速滚动→拖拽→按停、拖出窗口释放、任务切换（blur）等路径均不再出现常驻。UI-MAP F2 已同步。
