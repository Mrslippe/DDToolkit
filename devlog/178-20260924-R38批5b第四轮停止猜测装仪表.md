## 一、我前三轮错在哪（用户一句话点破）

用户第三轮复测后说：**「实则不然，实际三次修改都是一样的东西」**。

我当时一直在**追截图里的差异** —— 粉色变透明、阴影变小、边框变细 —— 并据此判断"修复生效了、
只是没修完"。但用户连着三次看到的是**同一个东西**。那些差异**不是我的修复造成的**，
而是同一块表面在**不同壁纸、不同时刻**下的样子。

**我把噪声当成了信号，连续三轮都在解读假差异。**

## 二、真正的事实（第四轮才拿到）

我请用户看小窗左上角那行 dev 自检条（`position:fixed` + **不透明白底黑字**）——
**用户答："没有"**。

⇒ **那行字不在**。而它只要 React 渲染过一次就绝不可能看不见。

**⇒ 小窗里的页面根本没有渲染出来。**

**⇒ 我前三轮改的东西 —— 启动幕、`html` 背景、`backdrop-filter`、DWM 外框 —— 一行都没机会执行。**

这解释了一切，包括"三次修改都是一样的东西"：窗口里始终是**同一个空页面**。

## 三、这一轮加了什么（只有仪表，没有猜测）

| # | 仪表 | 它回答什么 |
|---|---|---|
| 1 | **Rust 侧读 URL**（1.5s / 5s 各一次，`w.url()`）| 那个窗口**实际加载的地址**。不依赖页面，空白页也读得到 |
| 2 | **页面侧回传**（`widget_diag` 命令）| **页面到底有没有执行**。跑起来就打印 `[widget] 页面自检 css:… bg:… w/h:… q:…` |
| 3 | 探针结束语 | 若上面**没有** `[widget] 页面自检` 那行 ⇒ **页面没执行**，方向立刻转 Rust/WebView 侧 |

再加一条**看日志就能切开所有可能**的对照：

| 日志里看到 | 结论 |
|---|---|
| `小窗 @1500ms URL = http://localhost:5173/index.html?widget=1` + **有** `页面自检` | URL 与页面都正常 ⇒ 才是**绘制/合成**问题 |
| **URL 里没有 `?widget=1`**（或没有 `/index.html`）| Tauri 的 `devUrl.join(path)` 拼歪了 ⇒ 查 Rust 侧 |
| URL 正常但**没有** `页面自检` | 页面**没执行**（JS 报错 / 资源 404）⇒ 查前端与 WebView |
| URL 是 `tauri://localhost` 之类 | dev 下走了**资源协议** ⇒ 那里没有 `dist` 产物 |

## 四、为什么要走"回传"而不是 `eval`

第一版我写的是 `w.eval("document.readyState + …")` —— **Tauri 2 的 `eval` 不返回表达式值**，
编译就过不了（`()` 不实现 `Display`）。所以改成**页面主动调命令回传**：
`invoke('widget_diag', {info})`。这也更硬 —— **页面没跑就永远不会回传**，
"这条日志不出现"本身就是答案。
