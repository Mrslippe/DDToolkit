# 469-20261012-基础规则的四处修正：加 3D 类 / watch 扩边界 / _confident 的并列档

用户对基础分类规则给的修正（原话）：

> `watch`：一起看番/剧/电影/综艺/特摄**或者视频、投稿等主要以观看视频为主体**的直播内容
> `radio`：电台/谈心/深夜陪聊/**在电台区开播**/**没有 live2d 形象的松散直播形式**
> `fitness`：「回填的时候直接把健身类型去除，**不用直接用助眠替换**，助眠则是指一些主播
> 偶尔会进行的助眠回直播」
> 另：**加一个 `3D` 类型**，主要指 **3D 形式呈现**直播的场次

四处里有一处是**澄清**、一处是**扩词表**、一处是**新类**、还有一处**量不出料**。逐条记。

## 一、`fitness` 那处：已经在你要的状态上

你担心的是"回填时把健身直接替换成助眠"。T3（`devlog/468`）**就是按你说的做的**：
`TITLE_TERMS` 里健身那组词**整体删掉**、`AREA_RULES` 里健身那一行**整行删掉**，
新加的 `SLEEP` 只收助眠自己的词（助眠/哄睡/白噪音/asmr/音声/伴睡/耳骚/冥想）。
所以：**旧健身类不会被判成助眠**，那 58 条会按新规则重判（30 条 `chat`(area)、
27 条中性、1 条 `watch`）。`devlog/468` §四 有逐条去向。

⚠️ 顺带一个**真机实测**（本轮为了写这条又量了一次）：助眠词表在 8,523 条有标题的场次里
**命中 0 条**。也就是说「助眠」这个类今天是完全空的 —— 与"偶尔才会有的助眠回"这个
描述一致（你这批 V 还没播过，或者播了但标题里没写这些词）。

## 二、新类 `3d`：**有料，而且是这批里最大的一个类**

真机量测：标题含 `3d` 的场次 **702 条**（写法实测：`【3D】` 612 条、`家用3d…` 这类裸写法
93 条；`[3D]`/`“3D”` 各 0 条），另有 `3D虚拟主播` 分区 24 条。

换完之后的分布（合并视图 + 生效值）：

```
chat 2444 · live 1876 · game 1552 · 【3d 402】 · song 338 · radio 240 ·
special 176 · watch 135 · collab 45 · upload 29
```

**`3d` 402 场**（不是 702：其中 51 条被 `special` 正确抢走，其余落在分区/兜底之外的
靠标题判不出来 —— 见下面"权重 4.0"那段）。

### 三个设计决定（都可争议，逐条写了理由）

| 决定 | 取值 | 理由 |
|---|---|---|
| **权重** | `3d` = **4.0** | 真机 705 条里绝大多数**只有这一个信号**（`【3D】红豆来咯`、`家用3d的健身鹮`）。给 3.0 会被 `_confident`（要求领先 ≥1.0）判成不自信 ⇒ 全部落回分区/兜底，**等于白加**。4.0 ⇒ 单发即自信 |
| **优先级** | 特殊 > **3D** > 歌回 > … | 「3D 生日会」**首先是生日**（一年一次的事件，形式是次要信息）⇒ 3D 排在 `special` 之后；「家用3d歌回」「3d杂谈」按**形式**归档（你的诉求是"一眼看出哪些是 3D 场次"）⇒ 3D 排在 `song`/`chat` 之前 |
| **展位** | `TYPE_DISPLAY_ORDER` 里排**最后** | 它是"形式"不是"内容"。混在内容类目中间会让"杂谈→游戏→3D→观影"读起来没有线索 |

⚠️ **刻意没收的词**：`mmd` / 单独的 `模型`（太泛，会误伤"模型拼装"这类手工直播）。
**显式排除**：`晕3d` / `3d晕` / `3ds` / `3d眩晕` —— 真机有 `晕3d了谢会sc` 这种标题
（"游戏晕 3D"），裸 `3d` 会把它判成 3D 直播。判据
`test_category_3d_excludes_false_friends`。

## 三、`watch` 扩边界 + 撞出来的一个真 bug

按你的口径把"看别人的东西"那一族收进 `watch`（实测命中：看视频 19 · 一起看 106 ·
二创 23 · 看投稿 3 · 切片 3）。`watch` 从 122 → **135**。

⚠️ **`投稿回`/`看投稿` 与 `upload` 的 `投稿` 必然平分**（各 3.0）。这暴露了一个**老 bug**：

```
_argmax 用 TITLE_CATEGORY_PRIORITY 打破平分 —— 但 _confident 按「逐类相邻差 ≥1.0」判
⇒ {'watch': 3.0, 'upload': 3.0} 被判成"分歧太大" ⇒ 有优先级也白搭 ⇒ 落回中性兜底
```

实测受害者：`哇哈哈边看投稿边聊天`（watch 3.0 = upload 3.0，优先级明写 watch 在前）
修复前判成 `live`。**修复**：新增 `_ranked_groups()` —— 把得分按**档**聚类
（并列同分算一档，档内由优先级定代表），`_confident` 改成"**跨档**差距 < 1.0 才算分歧"。

这条修的不是 3D/watch 本身，是**打分器的语义**：既然宣言了优先级，就不该再把
"优先级能解决的分歧"当成分歧。判据 `test_confident_groups_ties_by_priority`
（含反向验证：真正的跨档分歧仍然不自信、弱词仍然不自信）。

## 四、`radio` 的"没有 live2d 形象"：**今天提取不到任何信号**

你给的两个新判据里，「在电台区开播」**已经在了**（`AREA_RULES` 的 `电台` → radio，
真机 130 条命中：`聊天电台/电台` 86 + `电台/聊天电台` 43 + 1），"深夜陪聊/谈心"也已在词表里。

但「**没有 live2d 形象的松散直播形式**」这条 **今天做不到**，原因是**没料**：

```
vtubers.setting 在真机 14 个 V 上全是空的（0 字）
分区里也没有"无模型/3D 人物"这类可用标签
```

也就是说"有没有 live2d 形象"这件事**在本地库里没有任何字段或文本可以推**。
三个可选做法（**都需要你拍**，我没动）：

1. **靠 `setting` 文本**：等用户填了设定集（里面有"形象/模型"字样）再说 —— 今天 0 命中；
2. **靠标题关键词**（`3d人物`/`mmd`/`无模型`）：真机 0 命中的可能性大（没人这么写标题）；
3. **靠 `3d` 类间接表达**：3D 直播天然就是"不是 live2d"，你要的"松散形式"可能已经被
   新加的 `3d` 类覆盖了 —— 但那是**另一个类**，不会进 `radio`。

我的建议：**先用 `3d` 类观察一段**，如果"没有 live2d 但也不是 3D"的场次确实多，
再决定要不要给 `radio` 加判据（那时应当先想清楚**用什么数据判**，而不是先写关键词）。
