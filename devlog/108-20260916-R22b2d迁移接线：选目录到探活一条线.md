## 一、一条可回滚的线（Rust，`lib.rs`）

```
选目录（tauri-plugin-dialog，系统文件夹选择框）
  → plan_migration（校验：绝对路径/不自我递归/空间 ≥ 待复制×1.15）
  → stop_backend（kill + 等端口真的让出来，最多 5s）
  → copy_tree → verify_copy（逐文件比对相对路径与字节数）
  → 写指针（原子）→ 用新目录 start_backend_and_wait（探活 /healthz，最多 30s）
  → 失败：回滚指针（有旧指针则写回、没有则清掉）+ 用旧目录重启 + 明确报错
```

**三条不变式**（写进代码注释，也就是这一批的验收口径）：

1. **旧目录全程不动** —— 复制只读源、只写目标；所以最坏情况是"新目录里有半份数据被丢"，
   用户的原始数据始终在原处。这也是"删旧目录"必须是**事后单独一步 + 用户确认**的原因。
2. **指针没写之前任何失败 = 什么都没发生**（复制/校验失败时只把后端用旧目录拉回来）。
3. **探活成功才叫成功** —— 写完指针后用新目录启动，`/healthz` 30 秒内不通就回滚。

几个实现要点：

- **端口复用**：重启时优先用原端口（刚被释放，且前端不必重新引导 —— 这是"只重启后端、
  窗口不闪"能成立的关键）；`stop_backend()` 会轮询 `/healthz` 直到旧进程真的让出端口，
  否则新进程 bind 会失败。
- **探活用的是已有的裸 `TcpStream` 手法**（与 `backend_manual_running` 同源）：
  为一个健康检查引 HTTP 客户端不划算，响应只看状态行。
- **便携/自定义安装不给迁移**：`migrate_data_dir` 里再兜一次底（`portable` 直接报错），
  因为"数据目录由环境变量指定"这件事本来就不该被应用内迁移覆盖。
- **删旧目录有护栏**：拒绝删"当前正在用的目录"，也拒绝删"不像数据目录的目录"
  （`vtuber.db` 与 `.env` 都不在就拒绝）—— 界面传错路径或用户手改都不至于误删。

## 二、界面（关于页「存储占用」面板）

- 新增一行**来源**：`默认位置（%APPDATA%）` / `已迁移到其他盘` / `由环境变量 DDTOOLKIT_DATA_DIR 指定`
  （来源字符串由 Rust 给，界面只做翻译，不自己判断）；
- **指针坏了** ⇒ 红色一行"迁移记录不可用，当前已回退默认目录：<原因>"（不静默）；
- 「**迁移到其他盘…**」浮片按钮：只在**桌面端**且**非便携**时出现；
- 迁移成功后：一行"旧目录仍保留：<路径> [删除旧目录]（确认新目录一切正常后再删）"。

`shellBridge` 三个新桥接（`storageInfo` / `migrateDataDir` / `deleteOldDataDir`）都带
**浏览器/探针退化**：`storageInfo()` 在非 Tauri 环境返回 `null` ⇒ 面板照常显示占用，
但**不出现迁移入口**（探针环境根本没有这回事）。另外 Rust 的 `Err(String)` 会被 `invoke`
原样抛出（不是 Error 对象），桥接层统一包成 `Error`，这样调用方 `.message` 就能直接显示。
