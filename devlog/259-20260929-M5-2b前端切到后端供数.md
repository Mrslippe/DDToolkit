## 二、口径：为什么是"服务端列表 + 本地覆盖"，不是纯轮询

三条都是硬约束（侦察 R2/R3/R5）：① 瞬时消息的服务端 TTL 是 **4s**，比空闲轮询 **10s** 短
⇒ 纯轮询**必然漏**；② "任务已受理"后端**不进环形缓冲**（`_note_manual_start` 只 publish）
⇒ 点完按钮那一瞬只有推送知道；③ 客户端自己的事实（磁盘快满 / 发现新版本）后端不知道。
合并规则三条：服务端报到同类 ⇒ 本地让位；按 id 去重（本地优先）；TTL 从**到达时刻**起算。

## 四、踩到的两个坑

1. **轮询链里读 state = 被闭包钉死在首帧**：`manual_running` 兜底最初写成 `useState`，
   poll 是 `[]` 依赖的 effect ⇒ 永远读到初值 `false`。改成 `useRef`（与 `isShellHidden` 那条
   教训同源，devlog/095）。eslint 的 `exhaustive-deps` 当场报出来 —— 这条警告值得留着。
2. **dev 注入会静默空转**：报告条目改由服务端出之后，`__ddtoolkitSeedReport` 只塞
   `doneReport` 已经画不出条目了 ⇒ `.si-count` / `.si-item-action` 那两条 WCAG 判据会
   **照旧全绿而面板里没有对象可量**。修法：注入走**本地覆盖**那一层（`extraLocal`），
   id 与后端同格式（`report-<seq>`），这样「查看详情」/「知道了」走的仍是同一条接线。
