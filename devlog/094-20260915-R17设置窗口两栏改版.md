# 094-20260915-R17 设置窗口改成左右两栏（参照参考图，细节走项目规范）

> 用户需求（2026-09-15，附一张参考图）：「设置窗口参照参考图的页面布局做成**左侧栏分类和
> 右侧主要内容**的形式，只粗糙参考布局即可，细节设计内容按照项目规范来，先给我设计方案」。
> 两个待定项由用户当场拍板：**右上动作行整个不做**；**导航 6 项、照后端分组**。

## 一、方案与取舍（先说清楚"借了什么、没借什么"）

| 参考图元素 | 决定 |
|---|---|
| 左右两栏（左分类 + 右内容） | **借** —— 本次核心 |
| 右上动作行（打开配置文件 / 导出诊断信息 / 打开终端 / 重启） | **不做**（用户口径）。其中"打开数据目录/日志"还要新增后端能力，"重启"我们没有通路 |
| 内容形态（外观三张卡 / 下拉 / 数字框） | **借形态、走项目令牌**：外观做成三张卡片；其余沿用 R14a 已有的 `.aps-*` 控件 |
| 深色 UI、DSH 专属分类（模型/插件/Agent 预设/权限/语言/字号/对话显示/繁忙发送行为） | **不借**：我们是浅色（深色是独立批次），那些功能在我们应用里不存在 |

## 二、导航是**数据驱动**的（这一批最值得保留的设计）

中间几项不写死清单，直接由后端 `GET /settings` 的 `specs[].group` 生成
（顺序也照后端声明序），**外观固定第一、关于固定最后**：

```
外观(1) · 抓取节奏(7) · 动态流与轮询(6) · 收录首屏(3) · 第三方数据(3) · 关于(10)
```

这条不是洁癖，是消掉一类漂移：以后在 `runtime_settings.py` 加一组参数（例如"弹幕采集"），
界面必须**自己**多出一项 —— 而不是等人想起来去改前端的导航数组（那种事一定会漏）。
探针拿导航标签与 API 的分组名逐项对账（`navMatchesApi`），钉的就是这件事。

## 三、布局与视觉规范

- 弹窗 **760 × min(600, 100vh−72)**，`max-width: calc(100vw − 48px)`，`padding: 0`
  （两栏自己撑满），头/脚驻留 —— 与既有最大弹窗 `.lc-dlg` 同构；最小窗口 960×600 放得下。
- 左栏 168：底色 `--c-bg-list`（近白）+ 右缘发丝线；右栏 `--c-bg-card`（纯白）
  —— **镜像应用外壳的「列表 / 卡片」层次**，不另造一套灰阶。
- 导航项：高 34 / 图标 15px / 右侧计数；**选中态沿用「左缘 3px 主色竖条 + 浅粉底」**
  （`.vtuber-item.active` 那套语言：`--sel-bar` / `--sel-bg`），不引入新的选中样式。
- 内容滚动一律 `OverlayScroll`；圆角/阴影走 `--radius-dialog` / `--shadow-dialog`。
- **字段控件一个都没改**：`.aps-row` / `.aps-input` / `.aps-switch` / `.aps-badge` 全部复用
  —— 这次只换外壳，把回归面压到最小。

## 四、四条状态口径（两栏布局必须写死的）

1. **切分类不丢草稿**：`draft` 仍是全局一份，切页只换渲染；左栏圆点（`data-nav-dirty`）
   标出哪一页动过 —— 两栏布局最容易踩的坑就是"切走即丢失未保存输入"。
2. **两种生效语义并存**：外观**立即生效**（`prefs.theme`），抓取参数**下一轮生效**；
   分类头的"生效时机"就是干这个的，不强行统一。
3. **报错要看得见**：跨字段冲突（上限 < 下限）涉及的两个字段在**同一页**，但用户可能翻到
   别的页去点保存 —— 所以前端补了**同源的跨字段预校验**（`settingsDraft.pairProblems`，
   与后端 `runtime_settings.PAIRS` 同一套），让"上限不能小于下限"直接落在出问题的那一行；
   真判定仍在后端（400 + detail 显示在底部错误条）。
4. **「恢复全部默认」要真的是全部**：顺带修掉 R14a 的遗留不一致 —— 那时按钮叫"全部"却只重置
   抓取参数、不动主题。现在前端打两个已有端点（`POST /settings/reset` + `PUT /settings/prefs`），
   后端零改动。另加分类级「恢复本类默认」（只填草稿，仍需点保存，与草稿模型一致）。

## 五、外观页：三张卡片，深色**只标不藏**

参考图里三张卡都能点，我们不能 —— 深色样式还没写（R14b 只铺了钩子）。按项目一贯口径
（受限功能只标不藏）：深色卡片**照样显示**，但 `disabled` + 卡片上写「尚未实现」。
`themeCards()` 里 `disabled: !DARK_IMPLEMENTED` —— 深色落地时这张卡自动解除禁用。
现有的"系统是深色但深色未实现"的说明（`themeCaveat`）保留在卡片下方。

## 七、两个"旧坑的新形态"（都写进了注释与 DEV-LOOP）

1. **分页渲染让 DOM 节点不再长寿**：探针原来抓住 `input` 就一直用它，切页后那是**游离节点**
   —— 写它不触发 React `onChange`，表现为"保存了但服务端没变"。改成**每次交互前重查节点**
   （`inputNow()`）。这与 devlog/071→080 那次"探针读了旧 DOM 节点"是同一类坑，这次由分页引入。
2. **探针的文案匹配别写死**：底部按钮从「全部恢复默认」改成「恢复全部默认」，
   探针的正则 `/恢复默认/` 就再也匹配不到了（报"底部没有这个按钮"）—— 判据本身把测试坑了。
   改成 `/恢复.*默认/` 并把按钮文案打进结果（`resetBtnLabel`），下次改名一眼能看出来。
