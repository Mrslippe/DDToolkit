# 377-20261006 CI 三连红的两个根因（Windows 专有路径 / 等圈数而非等条件）

> 用户把 CI 日志贴过来：v1.1.1 推上去之后 `vitest` 红 3 条（2 个文件）。**本地全绿、CI 全红**，
> 两条都不是产品坏了，而是**判据自己**的问题 —— 一类是平台写法，一类是等待方式。

---

## 一、`postTypes.test.ts`：`pathname.slice(1)` 是 Windows 专有写法（2 条）

```
ENOENT: '/home/runner/work/DDToolkit/DDToolkit/frontend/home/runner/work/DDToolkit/DDToolkit/frontend/src'
```

`new URL(import.meta.url).pathname.slice(1)` 在 Windows 上是对的（pathname 形如 `/C:/…`，
slice(1) 正好去掉那个多余的前导斜杠），在 Linux 上 pathname 就是 `/home/runner/work/…`
⇒ slice(1) 把它变成**相对路径**，`path.resolve` 再拿 cwd（`frontend/`）一拼就是上面那串。

- **修**：两处都改成 `path.dirname(fileURLToPath(import.meta.url))`；
- **判据**：`postTypes.test.ts` 新增一条**全仓扫描**（扫 `src/**/*.test.ts(x)` 里有没有
  `.pathname.slice(1)`，跳过注释行与本文件自己）；
  **反向验证**：临时放一个含该写法的 `__zz_guard_probe.test.ts` ⇒ 判据红并指出行号（实测，跑完删掉）。
- ⚠️ 这类"只在另一个平台红"的写法，**在 Windows 上靠人自查是抓不到的** —— 所以判据必须是机器判。

## 二、`mseKernel.test.ts` 的 ABR 判据：等的是"圈数"，不是"条件"（1 条）

判据本身没写错（"连续 3 段都喂不饱才报"），但等待方式是 `await flush(60)` ——
`flush(n)` 给的是 **n 轮宏任务**，每轮 `setTimeout(0)` 的真实耗时两端不同：
Windows/jsdom 上被钳到约 4ms（60 轮 ≈ 240ms，够取 3 段），CI 的 Node 上接近 1ms
（60 轮 ≈ 60ms，只取到 2 段）⇒ 本地永远绿、CI 永远红。

- **修**：新增 `waitUntil(cond, budgetMs = 5000)`（每轮给宏任务、到点收手），第一条判据等
  `onLinkSlow` 被调用；后两条"**不报**"的判据先等 `videoSegments() >= 4` 再断言
  —— 样本不足时的"没报"是**空转的绿**（这条也是同一课的另一半）。
- 顺带把失败信息补成现场：`已取 N 段：video 实测 X B/s vs 需要 Y B/s`。

## 五、第二波：另外两条腿也红着（同一批修掉）

查 CI 时发现**不止前端那三条**：`ci.yml` 的后端腿（3.12 与 3.14）与 `ci-windows.yml` 的
Rust 腿**也已经红了**（从 v1.1.0 那几个提交起）。两个根因都与我 2026-10-06 这批改动有关，
而且都属于"只在干净 clone 上才暴露"：

| 现象 | 根因 | 修 |
|---|---|---|
| 后端腿：`test_docs_gate.py::test_the_real_repo_is_clean` 红，`docs/ops/RELEASE.md` 第 205 行引用的路径不存在 | 我在 RELEASE.md 里写了 `frontend/src-tauri/extension/` —— 那是**构建期暂存 + gitignore** 的目录，本地刚构建过所以存在，CI 的干净 clone 上不存在 | 把那一行拆成表下的注记并打上 `<!-- 未建 -->`（`docs_gate` 的既有出口），顺带把"干净 clone 上会红在哪个 glob"写清楚 |
| Windows 腿：`cargo test` 的 build.rs 失败，`glob pattern extension/**/* path not found or didn't match any files.` | `bundle.resources` 新增的 `extension/**/*` 与既有的 `binaries/backend/**/*` 同一个坑（`devlog/199` 记过第一次）：**glob 匹配不到文件时 tauri-build 直接让 build.rs 失败**，而暂存目录被 gitignore | ① `ci-windows.yml` 第一步除了后端占位文件，**再给扩展造一个占位 manifest**（并把这个坑写进文件头）；② `build.rs` 在缺暂存时先打一句人话（`cargo:warning=extension/ 还没暂存 —— 先跑 npm run stage:extension`），紧跟着才是那条难以对号的 glob 报错 |

另外两处**判据本身的加固**（都属于"判据不严会放过坏产物"）：

- `release.py verify` 原先只数 `oname=extension\…` 的行数 > 0 —— 而 CI 那个**占位 manifest**
  也能凑出 1 行 ⇒ 改成**点名 `extension\manifest.json`**（便携 zip 那边本来就点名了）；
  真实 `installer.nsi` 的用例同步加这条断言；
- `cargo test` 里"暂存过来的扩展得是能加载的"那条用例，判据从"有 `manifest.json`"改成
  **"有 `icons/16.png`"** —— 否则 CI 的占位文件会让它红（那次占位不是"暂存过的扩展"）。

**验证方式（这次学到的一半）**：把 `frontend/src-tauri/extension/` 换成 CI 那个占位文件，
在**本机复现干净 clone 的状态**再跑一遍 —— `docs_gate` 无 FAIL、`cargo test` **67 passed**；
再把占位也删掉（真·干净 clone）⇒ `cargo test` 红，但**先看到那句人话提示**，才是 glob 报错。

### 复现差点骗了我一次（第三次才真绿）

第一次修完推上去，**Linux 腿照旧红在同一处**：`docs/ops/RELEASE.md：第 213 行引用
`frontend/src-tauri/extension``。两个错叠在一起：

1. **`<!-- 未建 -->` 必须与那条路径在**同一行**上** —— `docs_gate` 是按行判的
   （`if any(mark in line …): continue`）。我把它写在下一行，等于没写；
2. **我的"干净 clone 复现"不够干净**：我是"把暂存目录删掉、放上 CI 的占位 manifest"——
   目录还在，`docs_gate` 判"路径存在"就过了。而 Linux 那条腿**根本没有占位文件那一步**
   （占位只在 `ci-windows.yml` 里）⇒ 真正的 CI 状态是**目录整个不存在**。
   改成 `Rename-Item` 把整个目录挪走再跑，才复现出那条红。

> 教训与 §一/§二 是同一句：**复现要复现"CI 的那个状态"，而不是"我以为等价的状态"**。
> 一个占位文件就让两份判据（`docs_gate` 的路径存在性、`cargo` 的 glob 匹配）走向相反的结果。

### 还有第三处：补装 build 组排在了一致性复核之后（Windows 腿的下一步）

`cargo test` 修好之后，Windows 腿往前走到 `冻结后端（PyInstaller onedir）` 又红 —— 而这次是
**我 §二① 那个修复自己的顺序问题**：

- 复核问的是 **dev + build**（`--group build`，见 `devlog/374`），
- 而 `build_backend.py` 里"缺 PyInstaller ⇒ 按锁补装 build 组"那一段排在复核**之后** ⇒
  CI 的 Windows 腿**从没装过 build 组**（`uv sync --frozen` 只装 dev，那是**正常状态**），
  复核读到 `+ pyinstaller…` 就判"环境与 uv.lock 不一致"、在补装代码之前停下。

修：把补装整段挪到复核**之前**（并把"顺序也是判据的一部分"写进注释与用例）。
判据：`test_build_env_check_asks_about_the_group_it_needs` 加了第二半 ——
源码里 `import PyInstaller` 探测必须出现在 `--dry-run` 复核之前。
本机验证：`uv sync --frozen`（dev-only，复现 CI）⇒ 守卫先补装再复核、通过；再跑一次 ⇒ 静默通过。

### 结局

推 `4ff9bfe` 后两条腿**都绿了**（`CI`：后端 3.12/3.14 + 前端 tsc/eslint/vitest + 文档门禁；
`CI (Windows)`：Rust 单测 + 后端单测 + PyInstaller 冻结 + sidecar 冒烟）。
这一批共四处修复，**每一处都是"本机全绿、CI 红"**：
