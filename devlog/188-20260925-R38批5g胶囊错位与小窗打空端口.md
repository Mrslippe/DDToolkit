# 188-20260925-R38 批 5g：面板对了，但胶囊跑到窗口中间 + 小窗一直在打一个死端口

> **一句话**：用户的第三张截图里**面板内部完全正确**了（上一批的修复生效），
> 但暴露出两个新问题 —— ① 胶囊与面板**错位**（贴屏幕上沿时窗口被夹，CSS 的假设失效）；
> ② 小窗每 2 秒往 `127.0.0.1:8000` 发一个**必然失败**的请求（日志里那一片 `ECONNREFUSED`）。

---

## 一、胶囊错位：又一处"两个主人"

### 现象

截图：胶囊被压在屏幕顶端、与面板叠在一起；面板本身排得好好的。

### 根因

"胶囊在窗口里的位置"有**两个主人**：

- `widgetExpandGeom` 算**窗口矩形**；
- CSS 又自己认定"翻上去 ⇒ 胶囊贴窗口**底**边"（`.widget-shell[data-flip='up'] { justify-content: flex-end }`）。

**没被夹时两者一致**（窗口底边 = 胶囊底边），所以一直没露馅。但贴屏幕上沿时窗口**必须被夹**：

```
胶囊 y=10、高 40 ⇒ 向上翻要 y = 50 − 183 = −133 ⇒ 夹到 0
此时胶囊在窗口内的真实偏移 = 10 − 0 = 10
而 CSS 按"贴底边"画 ⇒ 给它 143（= 183 − 40）
⇒ 差 133px，胶囊跳到窗口中间、与面板叠住
```

### 修法

**位置由几何给，CSS 不许猜**：`widgetExpandGeom` 新增 `capsuleOffset`
（= 胶囊原顶边 − 窗口最终顶边），写进 `--widget-capsule-offset`，CSS 只用它。
折叠态恒为 0。

**这条判据可以推广**（已进 DEV-LOOP §6.9）：

> 当"一个东西的位置"能由**布局推算**也能由**几何计算**得到时，
> 只能有一个主人。两个主人**在大部分情况下会碰巧一致** —— 那正是它难发现的原因
> （只有夹取 / 边界条件才让它们分开）。

### 单测（5 条，含反向验证）

最要紧的一条不是"偏移等于某个数"，而是这个**不变量**：

```
胶囊在屏幕上的顶边 = 窗口 y + 窗口内偏移 = 原来那个 y   ← 展开前后必须不变
```

三个位置各验一遍（贴上沿 / 右下角 / 屏幕中部）。反向验证：
把 `capsuleOffset` 改回 `totalH - capH`（旧的"贴底边"写法）⇒ **1 条单测红**，恢复后绿。

## 二、小窗一直在打一个死端口

### 现象

用户终端里一片：

```
[vite] http proxy error: /settings/prefs
Error: connect ECONNREFUSED 127.0.0.1:8000   (×48)
```

### 根因

`api.ts` 的默认 base 是 **`/api`**（相对路径）。在主窗口里它由 **Vite 代理**转发到
`127.0.0.1:8000` —— 但**桌面端根本没跑 Vite 代理**，所以 `main.tsx` 会调
`get_backend_port` 拿到 sidecar 的**真实端口**，再 `setApiBase('http://127.0.0.1:<port>')`。

**小窗是独立入口，不经过 `main.tsx`** ⇒ 这条注入从来没跑过 ⇒ `apiBase` 一直是 `/api`
⇒ 穿透/全屏隐藏那两条轮询（**每 2 秒一次**）全部打到 `127.0.0.1:8000`
⇒ 那里没有服务在听 ⇒ `ECONNREFUSED`，攒了 48 次。

**修法**：`widgetMain.tsx` 自己 `injectBackendPort()`（拿端口 → `setApiBase`），
并在 `finally` 里才 `render()` —— 小窗一挂载就会读偏好，注入晚一步那两次请求照样打错地址。
与主窗口的区别：这里**不轮询 `/healthz`**（小窗是纯显示，不负责等后端就绪）。

### ⚠️ 这是同一条纪律的**第三次**现身

`DEV-LOOP.md` §6.1 写的是「拆入口时**顺带生效的东西**最容易漏」。三次实例：

| 次 | 漏掉的东西 | 表现 |
|---|---|---|
| 1（devlog/181） | Tailwind preflight 的 `box-sizing` | 胶囊宽 224 而不是 200 |
| 2（devlog/185） | `layout.css` 里的 `.os-*` 样式 | 面板里面塌了（条目压页脚） |
| **3（本批）** | **`main.tsx` 里的启动副作用**（`setApiBase`） | **每 2 秒一个必然失败的请求** |

**第三次比前两次更值得记**：前两次是**样式**（肉眼能看出不对），这次是**副作用** ——
它**失败得非常安静**：面板照样显示、胶囊照样亮，只是后台一直在打一个死端口。
**"界面看起来对"完全不能推出"它在正常工作"。**

**可复用的审计办法**（把 §6.1 那条从"样式"扩到"一切"）：
新建/拆分入口后，**逐条过一遍被跳过的那个入口模块的顶层副作用** ——
`setApiBase` / 埋点 / 定时器 / 全局监听 / 主题应用。判据还是那句：
**"这个东西是谁设置的？新入口里有人设置它吗？"**
