# 567-20261019-换区间不刷新、点当前界面不揭幕

用户两条，都先做了诊断再改（计划见对话）。

## 一、诊断结论（先查再改）

**"刷新"不是热力图的问题。** 核对后端：`days` / `detail` 是**全历史**查询（不带 `since/until`），
只有 `recent` 受区间约束。所以翻年时热力图的数据根本没变。

真凶是 `/activity` effect 一进来就执行的三行：

```ts
setRanked(null)   // 结果卡清空
setProgress(null)
setWin(null)      // ← 关键：窗口被清空
```

`win` 一清空 ⇒ 统计条**整行消失**（它只在 `win` 有值时渲染）⇒ 新 `recent` 到达后滑杆重新 emit
⇒ `win` 回来但日期是重算的 ⇒ `preview` 再请求一次。三段叠加 = 用户看到的"刷新"。

## 二、改法

| 项 | 改动 |
|---|---|
| A1 | **删掉 `setWin(null)`**：保留旧窗口值，等新 `recent` 到达由滑杆自然替换 |
| A2 | `setRanked(null)` 改成 **保留 + `rankedStale` 标记**：结果卡标题挂一个橙色小标「区间已改，以下结果基于旧区间」，点「分析」后清除 |
| A3 | 滑杆不强制归零（现有 `clamp` 保留，只在新数据不够时才收） |
| A4 | `/sessions` 预览加 **200ms 防抖**，请求期间保留旧值（不闪 `—`） |

## 三、点当前界面不揭幕

**诊断**：`IconRail` 两个入口无条件调 `requestViewChange`，`App` 的 driver 也没有判重 ——
点"当前界面"= 幕布合上 → 导航到原地 → 再打开，白白播 780ms。

**改法（两层）**：
1. `IconRail`：已在**同一界面**时**直接 `navigate`、不请求切换**。
   注意不是 `return`：`/vtubers/5 → /` 仍是有效导航（`IconRail.solo.test` 就是这条）；
2. `requestViewChange(next, key?)` 加界面键，driver 比对当前键，相同就只 `next()` 不播幕布。
   ⚠️ driver 读 `viewKeyRef` 而不是 `window.location` —— 后者在 MemoryRouter 测试里永远是 `/`。
