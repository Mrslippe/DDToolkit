# 442-20261007-外壳层级要压过面板里的浮层（左上角按钮被顶掉）

用户：「左上角的按钮被顶掉了」—— 单推模式下鼠标移到顶端/左缘唤出外壳后，
**唤出来的按钮自己看不见**。

## 真因：外壳和面板浮层在同一个层叠上下文里比大小，外壳输了

`441` 把 `.icon-rail` 的 `z-index` 提到基础规则、值还是 **2**（当时只为压过左栏的负外边距白盒）。
但单推时**左栏彻底收走** ⇒ 面板从 `0,0` 起 ⇒ 面板顶部那条工具条

```css
.view-toolbar { position: absolute; top: 0; left: 0; right: 0; height: 0; z-index: 3 }
```

正好落在**同一块坐标**（左上角）上，它是 **3** > 工具栏的 **2** ⇒ 盖住。顶栏同理
（顶栏此前**根本没给 z-index**，等于 `auto` ⇒ 连 3 都输）。

所以这不是"唤出没生效"，是**唤出来了但被压在下面** —— 用户看到的是"按钮没了"。

## 改法：外壳两层统一 10，且**不限定单推**

`.icon-rail` 的 `2 → 10`、`.topbar` 补 `position: relative; z-index: 10`。
值取 10 是**留余量**：面板里的浮层现在是 3，以后加新的浮层不至于又来一次。
作用域**不能限定** `[data-solo='1']` —— 这正是 `441` 的教训（负外边距的白盒在正常模式也盖）。

## 判据（净 +1）：关系式，不是字面值

★「唤出的工具栏/顶栏必须压过左栏与面板里的浮层」—— 断言的是
`maxZ('.icon-rail') > maxZ('.view-toolbar')` 且 `.topbar` 同理，
**并配正对照** `expect(overlay).toBe(3)`：证明我读到的确实是那条浮层的层级，
而不是正则又命中了一条无关规则。层级**留了多少余量**不写进判据（那是可调的）。

**反向验证**（两组，都杀死了）：去掉 `.topbar` 的 `z-index` ⇒ 那条红；
把 `.icon-rail` 的 `10` 改回 `2` ⇒ 那条红。

## 教训：注释里写了字面值 ⇒ 正则先命中注释（第 2 次了）

这次又假红了一轮：`maxZ('.topbar')` 死活返回 3，而文件里明明是 10 ——
因为**我给这条规则写的注释里就有 `z-index:3`**，被
`/z-index:\s*(\d+)/` 抢先命中（真值在后面）。上一回同型事故也在本批。
⇒ **读 CSS 值的正则一律行首锚定**（`/^\s*z-index:\s*(\d+)/m`）：

```js
const z = /^\s*z-index:\s*(\d+)/m.exec(body)   // ⚠️ 行首锚定：注释里也写着 z-index:3
```

注释里的值写成行内（`z-index:3` 不单独成行）就骗不到锚定正则了。
**给测试写注释时，顺手的字面值就是下一颗雷。**
