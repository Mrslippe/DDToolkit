## 这一批唯一需要想清楚的一段

**`VTuberRepo.reorder` 与 `AccountRepo.reorder` 语义不同 —— 而且绝不能互相"统一"掉。**

用户口径（2026-10-07）：**筛选下拖动只换可见那几条的相对位置，没显示的原地不动**。
账号那套是"未列出的**排在其后**"；拿它来做左栏，会把所有被筛掉的 V 一次性推到队尾。
所以这里做的是"**把传进来的 id 按新顺序，填回它们原本占的那些位置**"：

```python
slots = [i for i, v in enumerate(ordered) if v.id in set(want)]
for slot, vid in zip(slots, want):
    ordered[slot] = by_id[vid]
```

传**全部** id 也走同一条路（那时"位置"就是全体），所以调用方不必分两种情况。
重复 id / 不存在的 id ⇒ **400**（口径错误的提交当场说清，不猜语义静默乱序）；空数组合法。

⚠️ 这条口径写进了**三个地方**（`VTuberRepo.reorder` 的 docstring、`DATA-MODEL` 的列说明、
`GLOSSARY` 的词条），因为将来最可能犯的错是"看到两个 reorder 干同一件事就合并"——
而那个人读的是代码，不一定读文档。

## 判据

`tests/test_vtuber_api.py` 两条新用例（+3 个断言组）：

1. **`test_vtuber_order_endpoint_full_and_subset`** —— ① 全量重排；② **子集重排**（★ 关键格：
   只给三个 id，断言完整列表是"没传的那两个原地不动"）。
2. **`test_vtuber_order_rejects_bad_payload`** —— 重复 id / 不存在的 id ⇒ 400；空数组 ⇒ 200。

**反向验证过**：把 `reorder` 换成账号那套"未列出的排在其后" ⇒ **只有第 ② 段红**，
报错就是那句 `没传进来的必须原地不动 —— 这一条就是「筛选下拖动」的口径（推到队尾就错了）`。
