## 一、先取证，再动手（两处结果都改了原计划）

1. **UA 版本**：我们声称 **Edge 150**，而 2026-09 的真实稳定版是 **Edge/Chrome 153**
   （[Edge 153](https://forest.watch.impress.co.jp/docs/news/2140502.html) /
   [Chrome 153](https://forest.watch.impress.co.jp/docs/news/2141309.html)）。
   所以 150 是"几周前的旧版本"而不是"还不存在的未来版本" —— 问题比我原先担心的轻，
   但确实该刷新，而且**该有个刷新机制**。
2. **HTTP/2**：httpx 开 h2 需要 `h2` 包，实测**没装** ⇒ 开 HTTP/2 = 加依赖 + 重打后端产物，
   而我们的请求都是 API 调用（h1.1 vs h2 不是有意义的信号）⇒ **不做**。
3. **client hints**：`sec-ch-ua` 那套的 GREASE 串（`"Not_A Brand";v="24"` 之类）**只能靠猜**，
   版本组合猜错就是"没有任何真浏览器会发出的组合"—— 比不补更容易被识别。
   ⇒ **不做**（写进模块说明，免得日后有人当成遗漏又补上）。

## 二、盘点发现的真问题：全仓 **4 个不同的 Chrome 大版本**

| 位置 | 原来 | 现在 |
|---|---|---|
| `auth.py::BASE_HEADERS`（B 站主路径） | Chrome 150 + Edg 150 | `UA_EDGE` |
| `bili_search.py`（搜索页） | Chrome **131** | `UA_EDGE` |
| `img_proxy.py`（图片代理） | Chrome 150 + Edg 150 | `UA_EDGE` |
| `platforms/weibo.py::_PC_UA` | Chrome 150（无 Edg） | `UA_CHROME` |
| `platforms/weibo.py::_MOBILE_UA` / `weibo_auth.py` | iPhone Safari 13 | `UA_IPHONE` |
| `danmakus.py::BROWSER_HEADERS` | Chrome **126** | `UA_CHROME` |
| `runner.py::_USER_AGENT` | `DDtoolkit-archive/0.5.2` | `DDtoolkit-archive/{settings.VERSION}` |

**修法**：新建**零依赖**模块 `app/core/useragent.py`（`UA_MAJOR = "153"` + 三个 UA 常量），
所有消费方引用它 —— **发版时只刷新 `UA_MAJOR` 一处**。

> 为什么单独开模块而不是塞进 `core/http.py`：那边顶层 `import httpx` + certifi，
> 而 `routers/img_proxy.py` 刻意**延迟导入 httpx**（冷启动优化，见 devlog/046 那批）——
> UA 放那里会把 httpx 又拽回冷启动路径。

## 三、去掉 `Connection: keep-alive`

浏览器在 HTTP/1.1 下**不显式发**这个头（h2 更不会有），我们却一边声称 Edge 一边发它 ——
那比"少一个头"更扎眼。httpx 自己管理连接复用，删掉它不影响任何行为（用例实测连接池照常）。

## 四、护栏（5 条，`tests/test_user_agent.py`）

1. **结构化扫描**：`app/**/*.py` 里除 `core/useragent.py` 外**不许出现 UA 字面量**
   （`Chrome/\d` / `Edg/\d` / `AppleWebKit`）—— 防止再长出第 5 个版本号（与 R21 的
   "弹窗清单冻结"同一种思路）；
2. Chrome 与 Edge 的版本号自洽，且都等于 `UA_MAJOR`；
3. B 站头：UA 等于共享常量、**不含** `Connection`、`Referer`/`Origin`/`Accept`/`Accept-Language` 一个不少；
4. 六个消费方全部指向同一份常量；
5. `runner` 的自报家门 UA 含真实 `settings.VERSION`（钉住"版本不再漂"）。

## 五、顺带修掉一条不可靠的用例

`test_next_due_grows_with_account_count_over_rpm`（R28 那批写的）在跑全量时红了一次：
期望"间隔 ≥150s"实测 136.4s —— 因为轮间**抖动 ±15s** 被算进了差值。
修法：该用例把 `DYNAMICS_JITTER_SECONDS` 钉成 0（并在用例里写明原因）。
**教训与"测试量错了轴"同族**：断言里出现随机量时，要么把它钉住，要么把容差算进去。
