## 一、为什么自绘的角会"虚"（先量，再说方案）

用户给的 1:1 截图（1920×1080）逐像素：

```
左上角（粉顶栏）: 桌面 #6D8651 → #8A8B65 → #D29A96 → #FAA1B1 → 粉 #FFA2B4
中段边缘（同一张图）: 桌面 #4CB700 → rail #4B5A6F      ← 只有 1 个过渡像素
```

**中段是 1px 硬边 ⇒ 不是渲染糊、也不是 DPI 分数缩放**；"虚"只出在角上，因为
`--radius-window` 只有 4px：**弧越短，抗锯齿占的比例越大**，而我们是**透明窗口**，
那几个半透明像素直接和**桌面照片**混色 ⇒ 看着就是糊了一角。

## 二、原生方案：把圆角交给 DWM（实测三态）

`DwmSetWindowAttribute`：`DWMWA_WINDOW_CORNER_PREFERENCE=ROUND` + `DWMWA_BORDER_COLOR=NONE`，
**CSS 半径归零**，让 Windows 自己裁。脚本先在运行中的窗口上试（不重编译）：

| 状态 | 结果 | 证据 |
|---|---|---|
| 浮动 | 系统 ~8px 圆角，平滑、无混色 | 四角放大 8× 全是干净的系统弧 |
| **吸附**（真的按了 Win+←，窗口变成 `(0,30)-(960,1080)` 正好左半屏） | **四角全方、完全填满** | 精确角点像素：左上 `#FFA2B4`(粉)、左下 `#4B5A6F`(rail)、**右上 `#FFA2B4`**、**右下 `#FFFBFB`** —— 连**屏幕中间那两个角**也是方的 ⇒ 是"整窗状态"判定，不是逐边 |
| 最大化 | 方、填满 | `IsZoomed=True`，rect `(-8,22)-(1928,1088)` 覆盖整屏 |

⇒ **"什么时候圆、什么时候方"完全由 Windows 决定**，我们一行判定逻辑都不用写。
这也解释了 Clash Verge 为什么只在 Linux 上加 CSS 圆角
（[那个 commit 的标题就是 `Add border-radius for window on linux`](https://github.com/leungronwai/clash-verge-rev/commit/75d41b6fe527af876e212d9b4367613e19f4fa68)）：
**Windows 上交给系统**，连吸附都不用管。

## 三、落地（本批代码）

| 层 | 改动 |
|---|---|
| `lib.rs` | `apply_dwm_corners()`：raw FFI 调 `DwmSetWindowAttribute`（**零新依赖**，`#[link(name="dwmapi")]`）+ `SetWindowPos(SWP_FRAMECHANGED)` 让形状立即生效；结果存 `DWM_CORNERS` 静态量；新命令 `window_corners_mode()` |
| `main.tsx` + `utils/windowCorners.ts` | 启动时问壳一次 ⇒ `html.dwm-corners` 开/关；dev 钩子 `__ddtoolkitCorners` 供探针模拟 |
| `layout.css` | `html.dwm-corners { --radius-window: 0px }` |
| `tokens.css` | `--radius-window: 4px → 8px`（**只作 Win10/浏览器/探针的兜底**；8px 与系统窗口同量级，也不会像 4px 那样糊） |

### ⚠️ 落地时踩到的坑：属性要**在窗口显示之后**设

第一版把 `apply_dwm_corners` 放在 `setup()`（那时窗口还是 `visible: false`）——
重编译后跑起来**角还是方的**，日志却写着 `DWM 系统圆角 = true`：

```
setup() 里设 → 前端 present_window → show() → 角是方的（属性被显示流程冲掉）
```

改成挂在 **`present_window`（`show()` 之后）** 就正常了。为什么这个位置还更好：
**深休眠唤醒**是重建窗口 → 新窗口加载完页面同样会走 `present_window` ⇒ 一条路全覆盖，
不用像背景色那样在两个地方各写一次。

### Win10 回退（必须做）

Win10 没有这个属性，`DwmSetWindowAttribute(33)` 会返回失败 ⇒ **拿返回值当能力探测**：
成功（Win11）= CSS 半径归零、交给系统；失败（Win10）= 保留 CSS 8px 自绘，
**不会变成一扇裸方角窗口**。探测到的东西落一行 `shell.log`（`DWM 系统圆角 = true/false`），
打包版没有 stdout，排查时就靠它。

判据只认**圆角**那次 HRESULT：`DWMWA_BORDER_COLOR`（顺手去掉系统那 1px 描边）
在较早的 Win11 build 上可能不支持，**不该连累圆角** —— 这条写成了纯函数 + 单测。

## 四、护栏

| 护栏 | 钉住什么 |
|---|---|
| `cargo test` `dwm_corners_ok_*`（+1，**32 passed**） | 能力探测的判据（圆角 HRESULT 说话；描边失败不算失败） |
| 默认探针三档的 `shell` 断言（扩了两条） | ① 浏览器/探针没有 Tauri ⇒ CSS 兜底半径必须是 **8px**；② 用 dev 钩子模拟"壳说 DWM 可用"时 `.app-shell` 半径必须变 **0** —— 钉的是"谁画圆角"这条接线 |
| **反向验证** | 临时把 `html.dwm-corners` 的半径改成 4px ⇒ 探针立刻报 `半径是 '4px'，不是 0` 判红；改回即绿 |

### 没验到的部分（如实说）

- **吸附那条只验过一次**（实验阶段：运行中设属性 + 真按 Win+← + 逐像素量）。
  落地后想再跑一次，`Win+←` 被 DSH Desktop 自己的窗口抢了焦点、没送到应用 ——
  同一套属性、同一扇窗口，差别只在设置时机（时机已修正并验过浮动态），
  所以判据仍成立，但**这条留给用户在真机上按一下 Win+← 确认**。
- **不透明窗口 + 系统阴影**没做：`transparent: true` 是 Win10 回退路径（CSS 圆角）所必需的
  —— 不透明窗口的 CSS 圆角无法切掉窗口自己的角。所以保留透明，代价是没有系统阴影。
