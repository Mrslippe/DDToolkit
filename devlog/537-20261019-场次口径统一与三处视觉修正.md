# 537-20261019-场次口径统一与三处视觉修正

## 一、热力图多算 24% 的根因：数「行」不是数「场」
用户："2026-10-02 不是只有一场吗" —— **他是对的**。库里那一对有 2 行：
```
id=5867  live_id='729787580102344056'   来源 feed      session_key=NULL
id=5883  live_id='8c1b611b-…(uuid)'    来源 danmakus session_key='8c1b611b-…#729787580102344056'
```

同一场直播被两个来源各记一行。**项目的口径由日历端点给出**（实测 `GET /account/16/live-sessions`）：

| | 行数 |
|---|---|
| `live_sessions` 全部行 | 1,168 |
| 有 `session_key`（代表行） | **942** |
| 日历端点返回 | **942** ✓ |
⇒ **`session_key IS NOT NULL` 的行 = 一场直播。**
`/activity` 用的是 `count(*)`，所以 10-02 显示 2 场、年度场次虚高 24%。
`/profile` 的 `total_sessions` 同病。两处都加上代表行过滤。

**实测**：`activity` 场次合计 **1,168 → 942**，10-02 `n=1`，与日历完全一致。
（采集预估本来就用 `length(live_id) > 20`，恰好等价于代表行 —— 那部分数字一直是对的。）
