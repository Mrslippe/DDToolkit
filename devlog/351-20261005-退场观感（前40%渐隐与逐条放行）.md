# 351-20261005 退场观感：前 40% 渐隐 + 逐条（70ms）放行

> 用户 2026-10-05（350 之后，附截图）：
> ①「通知向左滑出的时候同步渐隐，因为现在下面顶上来的条目会和尚未滑出的条目重叠在一起」
> ②「全部已读的效果应该是从上到下一条一条逐个滑出，而不是现在这样一下全部滑出然后瞬间顶上去」
> —— 并按房规「有不明确的地方先问」，先问了三个问题再动手。

## 一、先问后做：三个选择（用户已定）

| 问题 | 用户选择 |
|---|---|
| 渐隐节奏 | **前 40%（≈90ms）就隐完**，之后只剩位移（滑出仍可读，重叠已看不见）|
| 逐条节奏 | **每 70ms 一条**依次开始，下面条目**跟着逐段上移**（5 条约 0.35s，"扫过去"）|
| 适用范围 | **凡是同时多条退场都按这个节奏**（不只「全部已读」：TTL 同批到点、服务端一次撤多条也一样）|

## 二、① 渐隐：只改不透明度的关键帧，位移照旧走满 220ms

```css
@keyframes si-item-out {
  0%   { opacity: 1; transform: translateX(0); }
  40%  { opacity: 0; }                         /* ← 只写 opacity */
  100% { opacity: 0; transform: translateX(-24px); }
}
```

⚠️ 40% 那一帧**故意不写 `transform`**：CSS 是**按属性各自插值**的，`transform` 只在 0%/100%
出现 ⇒ 位移仍按整段 220ms 走完；写了反而会把位移也压进前 40%。这条写进注释了 ——
否则下一个人"顺手补齐"就把滑出变成"闪一下"。

reduce-motion 那条路径（`si-item-out-fade`）不受影响：它本来就是原地淡出、没有横向位移。

## 三、② 逐条：把"不再活着"与"开始滑出"拆成两件事

原来的口径是"一过期/一已读就 `leaving`" ⇒ 一次 ack 多条就是**同拍全体浮起来**，
下面的分组于是"瞬间塌上去"（用户说的正是这个）。现在多了中间态：

```
活着 ──(被撤下 / 到点)──▶ queued（还在原位、照常渲染） ──(泵每 70ms 放一条)──▶ leaving ──220ms──▶ 移除
```

- 队列顺序 = **看得见的最上面那条先走**（组序 `GROUP_ORDER` + 组内 `compareInGroup`）；
- 队首**不计延迟**（没人在滑时当拍就走）—— 点单条已读必须跟手；
- 每条**自己的** 220ms 移除表（不是一条共享的）。

⚠️ 顺序必须与渲染**同一把尺子**：排队/滑出的条目已经不是 live、不再参与 `sectionNotices` 的排序，
不重排就会掉到组末尾（"点了全部已读，下面几条先跳个位置才开始滑"）。所以把组内比较器
抽成导出的 `compareInGroup`，`sectionNotices` 与 `drawnGroups` 同用。

### 踩到的三个坑（都留在注释里）

1. **条目会有一拍不在 DOM 里**：渲染先跑、effect 后跑 ⇒ "刚不再活着、还没被标记"的那一拍
   `drawnGroups` 里没有它。后果不只是闪一下：FLIP 每拍拍的布局快照也缺了它，
   于是放行时**量不到它的位置**（实测 `FREEZE msg-1 false ['report-1']` ⇒ 它只淡出、不滑出）。
   修法：渲染用更宽的 `exiting` 判据，而且**两条来源都要认** ——
   ① 被撤下（可能"还很新"，`isLive` 仍为真）；② 到点过期（**还在 `notices` 里**）。
   只认①会漏掉 TTL 那条缝，只认②会让「全部已读」那一拍 `drawnGroups` 直接空掉 ⇒ **面板当拍卸载**。
2. **面板会在逐条动画开始前就收起/卸载**：`primary` 与"没内容就收"两条判据都只看 live，
   清空最后几条时会当拍收面板。改成 `(primary || !showEmpty)` 与 `exiting.length === 0`。
3. **计时器被提交重排掉**（最隐蔽）：泵那条 effect 依赖 `rows`，而排队期间 `rows` 每几十毫秒
   变一次（`setCountPopped`、空闲轮播取时钟、上一条开始滑……）—— 常规写法"每次重跑都
   `clearTimeout` 再排"会让队首**永远轮不到**（实测日志 `PUMP wait 70 m2` → `PUMP cancel m2` → …）。
   修法：**已经排好就直接返回**，只在"队列空/刚放行一条"时重新起表；移除表同理改成**每条各一张**。

## 四、验证

- **实机**（`ui_probe --notice-lab --width 1440`，rc=0）：
  `逐条退场：批量 3 条，+120ms 已开始滑 2 条 [...]`（不是当拍全走 ✓）；
  `布局=空位 ['rel=6/h=51', …] ｜残留位移=[]`（350 那条判据仍然绿）；
  `全部已读：清=True 剩=[] ｜正在进行 6 → 6（未被动=True）`；`页面报错 0 条`。
- **单测 26 条**（StatusIsland）+ 32 条（`noticeBoard`）：新增
  「多条 ⇒ 从上到下逐条（70ms 一条，其余仍在原位不许消失）」「队列期间面板不许消失」
  「`compareInGroup` 与 `sectionNotices` 顺序逐字一致」。
- ⚠️ **探针那条"活着的条数必须少一"放宽成"不许变多"**：这一页有 TTL 到点、也有新推送同时进来，
  实测就撞上"点击那条确实进了滑出，同拍另有一条过期 + 一条新到 ⇒ 前后都是 10"。
  "点的那条走了"由 `ackOutIds`（按 id）判，那才是实体。
- ⚠️ 缓动/渐隐的**观感**探针验不了（无头环境不推进过渡，350 已把它做成自检项），仍需人眼。
