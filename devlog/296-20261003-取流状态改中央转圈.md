# 296-20261003 取流状态改「中央转圈」：删掉下黑边，失败改居中药丸

> 用户口径（2026-10-03 22:4x）：「这个『正在取流…』的下黑边也可以去掉，如果取流缓存需要时间
> 就在屏幕中央用旋转缓冲图标标识」。

## 一、为什么它又长成了一条黑边

`.bili-lazy-hint` 这个 class 在**全仓 CSS 里一条规则都没有** —— 一个裸 div 挂在 `.vp`
（黑底）里，加上封面 `max-height: 60vh` 撑不满容器时留出的空隙，就成了"封面下面一条黑边"。
和上一批删掉的标题带（`.bili-lazy-title`）**是同一个成因**：
**没有样式的裸元素在真机上会被盒子模型随手画成一条边**。

⇒ 记一条通用判据：**状态类元素必须显式有样式**（哪怕只是 `position: absolute`）。
本批顺手把两处状态都画出来了，并把 class 名写进判据（见 §四）。

## 二、取流中：中央旋转缓冲图标

```jsx
{busy ? (
  <div className="vp-spin" role="status" aria-label="正在取流">
    <Loader2 className="vp-spin-icon" aria-hidden="true" />
  </div>
) : (
  <button className="vp-bigplay" …><Play /></button>
)}
```

- 转圈与大播放键**互斥**（同一格位置，两个都画就叠在一起）——所以 `busy` 时不渲染播放键；
- `role="status"` + `aria-label="正在取流"`：读屏会念，不用靠"看得见在转"；
- `@keyframes vp-spin` 转 `.vp-spin-icon`；⚠️ **reduced-motion 下不是"取消动画"**，
  而是换成呼吸式明暗（`vp-pulse`）—— 转圈整个停掉看起来就是"卡死了"，比不尊重偏好更糟。

## 三、重新取流（换清晰度 / 补救）也在播放器里转圈

`VideoPlayer` 新增 `loading`：B站换清晰度、播不动后的同档重取或回落时，**播放器中央**转圈，
而不是把整块换掉 —— 那时候旧流还在元素上（可能还能拖着看），换掉整块会把画面和进度一起丢。
同一条规则"转圈时收起大播放键"。

## 四、失败：居中的玻璃药丸（不再是贴底黑条）

`bili-lazy-err` 从"底部裸 div"改成**播放键下方的居中药丸**（`top: calc(50% + 48px)`）：

- 播放键仍在正中 ⇒ **一点就重试**，两者不打架；
- `role="alert"`（读屏立刻念出"没有观看权限（充电专属 / 地区限制 / 需要登录）"这类**后端如实分级**的文案）；
- `max-width: min(86%, 420px)` + 可换行，长文案不撑破容器。

## 五、判据

| 用例 | 钉什么 |
|---|---|
| `BiliVideo.test.tsx` | 取流中 ⇒ `.vp-spin`（`role=status`）存在、**播放键不出现**、`.bili-lazy-hint` **查不到**；失败 ⇒ `.bili-lazy-err`（`role=alert`）+ 播放键回来；真 CSS 里 `.vp-spin` 必须 `position: absolute` 且 `translate(-50%, -50%)`、有 `@keyframes vp-spin`、reduced-motion 分支仍在 |
| `VideoPlayer.dash.test.tsx` | `loading` ⇒ 播放器里出现转圈且大播放键让位；不给 `loading` ⇒ 两者都不出现 |
