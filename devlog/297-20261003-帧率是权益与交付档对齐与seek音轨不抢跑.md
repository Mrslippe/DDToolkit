# 297-20261003 帧率是权益 / 交付档对齐 / seek 时音轨不许抢跑

> 用户两条真机反馈：① B站视频"帧数没有源视频流高"；② 点进度条跳转时**音轨先跳完、视频轨才跟上**，
> 卡一下才同步 ⇒ 声音与画面错位。
> ①查下来是权益（不是 bug，但顺手抓出一个**真** bug）；②是我们自己的实现问题，改了。

## 一、帧率：量出来是**大会员限制**，不是我们丢帧

真上游实测（同一条视频，改 `qn` 反复要）：

```
qn=120 → quality=80  fr=30.002  codecs=avc1.640032
qn=116 → quality=80  fr=30.002
qn=112 → quality=80  fr=30.002
qn= 80 → quality=80  fr=30.002
qn= 64 → quality=64  fr=30.002
```

⇒ 无论要哪一档，**流元数据里的 `frameRate` 就是 30**；`accept_quality` 里那个
`116 = 高清 1080P60` 永远拿不到（与 4K 一样是**大会员**档，菜单里已经用王冠图标如实标了）。
真 60fps 的片源也一样回来 30fps —— 所以"帧数比源低"是**平台按权益给的码流**，不是双元素内核丢帧，
也不是解码跟不上（解码跟不上会是掉帧/花屏，而不是稳定的 30）。

## 二、顺手抓到的**真** bug：选 720P 播的还是 1080P

上面那张表里藏着一行不对味的：

```
qn=64 → quality=64   …但 dash.video[0] 的 id 是 80
```

`dash.video` 列的是**所有可用档**（实测顺序恒为降序 `80,80,64,64,32,32,16,16`），
而**交付的是哪一档写在 `data.quality` 里**。前端一直取 `video[0]` ⇒
用户在第 4 步菜单里选 720P 时：**菜单显示 720P、画面其实还是 1080P**（后端回的 `quality=64`，
我们却播了列表第一条 80）。

**修**：新增 `prefer_quality(streams, quality)` —— 按 `quality` 对齐后**稳定排序**把交付档放到第一，
其余保持上游顺序；同一档里**AVC 优先**（`_codec_rank`：实测同档有 `avc1.640032` 与
`hvc1.1.6.L150.90` 两条，码率差一倍 —— HEVC/AV1 要看 WebView2 装没装解码器，AVC 到处能解）。
判据三条：交付档压过上游顺序、同档 AVC 优先且不丢镜像链、没有 `quality` 时保持原序。

## 三、seek 时音轨不许抢跑

用户描述的现象有明确的机理：**视频轨 seek 比音轨慢** —— 它要回到关键帧、重新缓冲，
音轨几乎瞬时。原来的实现是"两条都直接写 `currentTime`"：

```ts
el.currentTime = target
if (a) a.currentTime = el.currentTime      // ← 音轨立刻就到了新位置
```

于是那段时间里**听到的是新位置的声音、看到的是旧位置的画面**，要等 2s 一次的漂移纠正
才拉回来（用户看到的"卡一下才同步"）。

**改**：一次 seek 里**先把音轨 `pause`**（闭嘴），等视频轨 `seeked`（真的到位）再
`a.currentTime = el.currentTime` 并对齐复播（原来在播的才复播）。

- 拖拽：`pointerdown` 起音轨静默，`pointermove` 只动视频轨（每帧都去重设音轨只会更抖），
  `pointerup` 才对齐一次；
- **兜底定时器 1.5s**：`seeked` 万一不来（原地重跳、浏览器吞事件）也要把音轨放出来 ——
  否则症状会从"错位"变成"永远没声音"，那更难查；
- `settleAudio()` 幂等（`done` 标记），因为点击与拖拽两条路可能都触发收尾。

代价是 seek 后有一小段**静音**（视频轨在缓冲）。这比"声音和画面错位"正确得多：
静音是播放器的常规行为，错位是故障。

## 四、判据

| 用例 | 钉什么 |
|---|---|
| `test_bili_play.py` | 交付档（`quality=64`）必须排到第一（原来会是 1080P）；同档 AVC 优先且镜像链不丢；`quality` 缺失时保持上游顺序 |
| `VideoPlayer.dash.test.tsx` | seek 一开始音轨 `pause()`；视频轨没 `seeked` 前音轨**不许**被对齐到新位置；`seeked` 后才对齐 + 复播；拖拽期间音轨保持静默、抬手一次对齐；`seeked` 不来时兜底定时器也要放出声 |
