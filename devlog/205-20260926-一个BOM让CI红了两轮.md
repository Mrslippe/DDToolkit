# 205-20260926-一个BOM让CI红了两轮（本地门禁缺一条）

`f68030a` / `7005ffd` 推上去之后 **Linux 腿红**，而 Windows 腿绿、本地全绿。
两步排查（第一次还看错了日志，把上一条 Windows 的 ULP 红当成这次的）：

```
远端：CI(Linux) → 后端（python 3.12 / 3.14）→ 第 5 步「全仓 Python 语法扫描」= failure
      （第 6 步后端单测、第 7 步文档门禁因此 skipped —— 根本不是 pytest 的事）
本地：python scripts/dev_check.py --syntax-only
      [FAIL] tests\test_dynamics_backoff.py:1: invalid non-printable character U+FEFF
```

## 一、根因：我用 PowerShell 改文件，它给我写了个 BOM

修 ULP 那处时用了 `Set-Content -Encoding utf8`（**Windows PowerShell 5.1 的 `utf8` = 带 BOM**）
⇒ 文件第一个字节变成 `EF BB BF`。

**为什么 pytest / 本地门禁全绿**：BOM 是**合法 Python** —— `python file.py`、`import`、pytest
收集都自己吃掉 BOM。会红的只有**把文件当文本读出来再 `ast.parse`** 的那一处，也就是
`dev_check.py` 的语法扫描 —— 而它**只活在 CI 的 Linux 腿与"一把梭"里，不在 A 档门禁里**。

## 二、三处修（缺一条都还会再犯）

1. **去掉文件里的 BOM**（顺手对齐：全仓其它 `.py` 都没有）；
2. **让判据接受合法输入**：语法扫描改用 `read_text(encoding="utf-8-sig")` ——
   "能不能解析"这个判据不该被一个解释器自己都能吃掉的字节判死。
   （只做 ① 的话，下次换个编辑器/别的机器再来一次。）
3. ⚠️ **把语法扫描补进 `scripts/gate.py`（三档都跑，约 1s）**：这一次真正暴露的是
   **"只有 CI 会红的检查"** —— 本地跑完 A 档门禁 + 干净 clone 复现都绿，
   而 CI 的第 5 步第一个就红。判据很便宜，没有理由留在只有 CI 跑的位置。

## 三、教训

- **改文件的方式本身会引入缺陷**：PowerShell 的 `Set-Content -Encoding utf8`（5.1）= 带 BOM；
  用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))` 或让 Python 去写才不带。
  本仓已有同族记录（`Get-Content` 不带 `-Encoding` 会把 UTF-8 当 GBK 读），这次是写的那一半。
- **"本地不复现" 要先问清是哪一步不复现**：我第一轮把 Linux 的红归因到网络用例（全仓唯一真打上游那条），
  其实 Linux 腿**在 pytest 之前**就红了 —— 判据是**远端每步的 conclusion**
  （`GET /actions/runs/{id}/jobs` 里 `steps[].conclusion`，不需要任何权限），比翻日志快得多。
- 本地"干净 clone + `uv sync --frozen` + `uv run pytest`"复现不出来**不等于**CI 复现不出来：
  那次复现只跑了 pytest，而红的是第 5 步。
