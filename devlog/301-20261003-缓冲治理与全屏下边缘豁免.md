# 301-20261003 跳到很后面"一帧帧横跳"：缓冲治理 + 全屏下边缘豁免

> 用户两条（2026-10-03 收尾后）：
> ① 「跳到很后面时视频会**一帧帧播放并且每帧都暂停**，播放/暂停一直反复横跳……
> 可以在跳转后的加载阶段保证加载了一定内容之后才开始播放，具体策略可以搜索一下成熟播放器的缓冲区策略」；
> ② 「全屏状态下鼠标移到窗口最边缘会自动隐藏控件，这个功能可以，但**把下边缘豁免**——
> 用户想呼出控件栏而把鼠标移到最下面时反而被收起来了」。

## 一、先看成熟播放器怎么做（hls.js 的默认值）

hls.js 是这一层的公开参照（`docs/API.md` 的 Fine Tuning 一节），几个关键默认值：

| 参数 | 默认 | 含义 |
|---|---|---|
| `maxBufferLength` | **30s** | 想维持的**目标**缓冲长度（低于它就继续取） |
| `maxBufferHole` | 0.5s | 能容忍的缓冲空洞 |
| `highBufferWatchdogPeriod` | 3s | `currentTime` 3 秒不前进 ⇒ 跳洞或 nudge 播放头 |
| `nudgeOffset` / `nudgeMaxRetry` | 0.1s / 3 | 卡住时的微调步长与次数 |
| `maxStarvationDelay` / `maxLoadingDelay` | **4s** | 能**容忍**的饿住/起播等待上限 |

⇒ 两条可借的口径：**(a) 秒级的"能不能开播"门槛**（不是 30s 那种目标缓冲）；
**(b) 必须有看门狗**（不前进就介入），而不是干等。

## 二、我们的处境：progressive `<video src>`，缓冲节奏**不归我们管**

B站 DASH 是裸 fMP4，我们用 `src=` 直接喂（没有 MSE，见 `devlog/290`）⇒ 浏览器**只要缓冲里有
一帧就放一帧**，然后立刻又饿住。观感就是用户说的"一帧一帧 + 播放/暂停横跳"。
我们唯一能控的是**什么时候允许它继续跑**，于是按上面的口径做了一个小治理器：

| 常量 | 值 | 依据 |
|---|---|---|
| `HOLD_AT` | 0.5s | 前方不足半秒 ⇒ 认定在饿，**主动 `pause()`**（饿着跑只会抖）+ 转圈 + 音轨跟着停 |
| `RESUME_AT` | 2.0s | 缓冲到 2 秒才放（hls.js 的容忍值是 4s，这里是"开播门槛"，取更保守的一半） |
| `DEADLOCK_MS` | 1.2s | **兜底**：按住期间缓冲**完全不涨**这么久 ⇒ 立刻放开 |
| `HOLD_POLL_MS` | 200ms | 看门狗节拍 |

### 那条兜底不是想当然 —— 是量出来的

无头 Edge（与 WebView2 同族）经本机代理真播，跳转后**主动暂停**再看缓冲：

```
t=6.2s  hold-start   ahead=7.97   （暂停）
t=7.2s  held         ahead=7.97
…
t=14.2s held         ahead=7.97   ← **8 秒纹丝不动**
```

⇒ **暂停状态下浏览器不会继续把缓冲拉起来**。所以"等缓冲够了再播"如果没有兜底，
遇到"CDN 这会儿就是慢"的场景会变成**永远加载中** —— 比横跳更糟。
兜底放开之后最坏退化成"还是有点抖"，但**一定能继续播**。

### 谁按的暂停？（一个只有测试替身才会踩的坑）

按住期间要区分"我们自己按的暂停"和"用户按的暂停"（后者不能过一会儿又自动放起来）。
实现上用一个 `self` 标记，**在看门狗的每一拍清掉**：

- 真浏览器：我们的 `pause()` 会**异步派发** `pause` 事件（规范是 queue a task），
  事件到达时还没到下一拍 ⇒ `self` 仍为 true ⇒ 不会被误判成用户暂停；
- 测试替身：`HTMLMediaElement.pause()` 不派发事件（`src/test/setup.ts` 的取舍），
  于是那一拍清掉之后，**后到的** pause 事件就一定是用户按的 ⇒ 取消按住。
  用例里因此要**手动补一次**"我们自己那次 pause 事件"——这行注释比代码值钱。

## 三、全屏下边缘豁免

原来：指针离开播放器 ⇒ 立刻收起。全屏时把鼠标甩到屏幕最下面（想呼出控件栏）恰好触发它，
等于跟用户对着干。现在多一个**按坐标**判定的热区：

- `mousemove` 落在离下边缘 `BOTTOM_HOT_ZONE = 72px` 内 ⇒ 记为"钉住"，控件显示且**不参与自动隐藏**；
- 指针离开播放器时，若它还在那条热区里 ⇒ **不收起**；
- ⚠️ 量不到元素高度（`rect.height <= 0`）时**不豁免** —— 否则 jsdom/隐藏元素下每个坐标都会被
  判成"贴下边缘"，症状是"全屏时控件再也不隐藏"。这个坑是测试先炸出来的。

## 四、判据（新增 4 条）

| 用例 | 钉什么 |
|---|---|
| 饿住 ⇒ 按住、够了 ⇒ 放开 | `waiting` 且前方 0.2s ⇒ `pause()` + 转圈；缓冲涨到 3s ⇒ 自己 `play()`（不用用户再点） |
| 死锁兜底 | 缓冲 0.1s 永不涨 ⇒ 2 秒内必须放开（"永远加载中"是更糟的失败） |
| 用户暂停优先 | 用户按的暂停 ⇒ 之后缓冲够了**也不许**自动放起来 |
| 下边缘豁免 | 贴下边缘离开 ⇒ 不收起、且 5 秒后仍不收；从画面中间离开 ⇒ 照旧立刻收起 |
