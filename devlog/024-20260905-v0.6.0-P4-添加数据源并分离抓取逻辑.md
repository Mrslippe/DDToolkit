# 024-20260905-v0.6.0-P4-添加数据源并分离抓取逻辑

## 概述

P4 落地：接入第三方「已固定化数据」（粉丝历史、直播礼物、企划/公会索引进
一步到位），并把第三方采集与平台实时抓取在**架构层面分离**——新包
`app/services/externals/`（externals=只读拉取第三方固定化数据→落库，
platforms=直连平台实时爬取）。P3（JSONL 导出）按用户决定搁置，P4 先行。

## 数据源可行性（全部实测后定案）

| 源 | 端点 | 鉴权 | 实测 |
|---|---|---|---|
| zeroroku.com | `/api/bilibili/author/{mid}/history` | 公开 ✅ | 七海 2023-02→2026-09 完整粉丝历史 |
| zeroroku.com | `/api/bilibili/author/{mid}/live-paid-aggregations` | 公开 ✅ | 礼物/大航海/SC **日粒度**聚合（非单场起止） |
| danmakus.com | `/api/v2/vup-list` | 公开 ✅ | VTuber 全量索引 9141 条（**透传 laplace vup-slim.json**——laplace 无 API 但数据间接可用） |
| danmakus.com | `/api/v2/account/channel-lives` | **401 需登录** 🔒 | 直播场次列表留作 token 启用（弹幕 v3 同属鉴权列，backlog 暂缓） |
| laplace.live | — | 无 API | 空壳 `LaplaceSource`（enabled=False 占位） |

## 架构（分离抓取逻辑）

- `app/services/externals/base.py`：`ExternalSource`（`name`/`enabled`/`jobs`/
  `run_job`）契约 + `ExternalJob`（kind+周期） + `ExternalJobSummary`；
- `registry.py`：按名注册/发现（沿用 platforms registry 模式，import 即注册）；
- `zeroroku.py` / `danmakus.py` / `laplace.py`：各源适配器；
- `runner.py`：统筹执行（源级跳过 → 任务级错误隔离 → 汇总）；
  **账号级隔离**（zeroroku 内单账号网络异常不拖垮其它账号，实测发现的
  第一个健壮性缺口，已补）；
- 调度挂接在 `scheduler.start_scheduler`（`CronTrigger`）：**每日 3:00**
  （粉丝历史增量 + 礼物日聚合）、**每周一 3:30**（VTuber 索引整表刷新）；
  抓取任务进行中则本轮跳过（复用 `any_fetch_running` 判定，不碰让位状态机）；
- settings 开关：`EXTERNAL_ENABLED` / `EXTERNAL_ZEROROKU_ENABLED` /
  `EXTERNAL_DANMAKUS_ENABLED` / `EXTERNAL_RUN_HOUR`。

## 数据模型（迁移 `e004`，MIGRATION_HEAD → e004）

- `account_stat_snapshots.source`（默认 `self`）：**粉丝历史并入既有 P0 快照表**
  （用户定案）——zeroroku 行标 `zeroroku`，P5 可视化单表直接复用；
- `live_gift_days`：直播礼物日聚合（account_id+source+gift_date 唯一，
  金额以原始字符串保精度，room_id 快照）；「直播日程记录」单场起止留给
  P5 用自有 `live_status` 5min 快照推导；
- `thirdparty_vtubers`：VTuber 索引（source+platform_uid 唯一；
  name/type/room_id/group_name——企划·公会数据即此而来）。

## 验证

- 单测 6 例：时间解析（+00→naive UTC）、粉丝历史/礼物**幂等复跑不增行**、
  索引**整表刷新 + 源隔离**（他源行不受影响）、坏响应容错、注册表/空壳禁用；
- 全量 `pytest` **142 passed**（136 + 6）；迁移演练 e003→e004；
- **真实开发库首跑回填**：fan_history **7433 行**、gift_days **3010 行**、
  vtuber_index **9141 条**；复跑 stored=0（幂等验证）；
  抽查 七海Nana7mi → VirtuaReal 企划 ✓、明前奶绿 → 无企划 ✓；
- 读取端点：`GET /account/{id}/stat-snapshots?source=`（扩展）、
  `GET /account/{id}/gift-days`、`GET /externals/vtubers?kw=`（候选池增强）。

## 已知限制（记录不掩盖）

- zeroroku 礼物为日粒度：`live_gift_days` 是「日聚合」而非单场次记录；
- danmakus 鉴权端点（channel-lives/弹幕）等 token 配置后启用——弹出
  `DANMAKUS_TOKEN` 的配置位，启用前不生效；
- 第三方数据是「旁证」：粉丝图会呈现双源（self/zeroroku）两线，以直采为准、
  第三方补历史空洞，不互相覆盖；
- 第三方索引周级刷新（低频对站点友好），新收录 VTuber 的企划信息最多滞后 1 周。
