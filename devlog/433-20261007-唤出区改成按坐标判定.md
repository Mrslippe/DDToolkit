# 433-20261007-唤出区改成按坐标判定（第三版）

用户三条反馈（附截图）：

> 1. 左侧工具栏依旧唤不出来，显示白色
> 2. 唤出左侧工具栏和顶栏的时候都会伴随着界面元素的快速闪动以及唤出对应栏的卡顿
> 3. 界面元素的唤出区域应该就处在图中红框标出的中央部分，不要和其他 hover 区域重叠
>    （顶栏唤出、右栏顶部工具条唤出、左侧工具栏唤出等）

## 根因：判定依据错了，不是实现细节错了

前两版分别用 **CSS `:hover` 兄弟选择器**（`430`）与 **"指针落在哪个元素上"**（`432`）——
都建立在"指针下的元素"这个依据上，而**唤出会改变布局**（工具栏回来把内容推走 50px）、
唤出物又压在触发层上面 ⇒ 状态在"进/出"之间来回翻：**闪动 + 卡顿**（第 2 条），
而左栏那条因为层级/遮挡关系干脆进不去（第 1 条，"显示白色"= 那块还是内容）。

⇒ 第三版：**只看坐标**。`mousemove` 挂在 `window` 上，用 `clientX/clientY` 判定 ——
**与遮挡、层级、布局位移全都无关**（布局怎么动，指针的坐标没动）。

## 四个区（第 3 条：互不重叠）

```
┌──────────────────────────────┐  ← 顶栏区（贴上缘；唤出后长到顶栏那么高 = 46px）
├────┬─────────────────────────┤
│工  │                         │
│具  │      界面元素区（中央）   │  ← 只恢复内容，不碰两栏
│栏  │                         │
└────┴─────────────────────────┘
```

- `top` / `left`：贴边那 **8px** 薄条 ⇒ 调出顶栏 / 工具栏；
- ★**唤出之后那个区会"长大"到该栏自身的大小**（顶栏 46px / 工具栏 50px）——
  否则指针一移进去就掉出薄条、栏又从手底下消失（"唤出即消失"）。这一条同时满足了
  上一轮"触发宽度加宽到元素自身"的要求：**进得窄、留得宽**；
- 其余 ⇒ **中央区**：**只**恢复界面元素（两栏继续收着，避免三样一起蹦 = 用户说的"重叠"）；
- 优先级：上缘 > 左缘 > 中央（左上角那一小块归顶栏）。

## 顺手清掉的东西

- **窄带覆盖层整个撤掉**（`.solo-hover*`）：它既挡内容点击，又要靠 `pointer-events` 来回让位 ——
  坐标判定不需要它，App 里那两行 JSX 与 CSS 一并删除。
- **恢复改瞬时**（`transition: none`）：`data-peek` 是"鼠标扫过"级别的高频切换，
  带过渡的话每次都要重绘整块面板 —— 这是第 2 条"卡顿"的另一个来源。
  只保留"全收起后那一次淡出"的过渡（它有 2.4s 延时，不跟着鼠标抖）。

## 判据（净 +2：新文件 4 条，CSS 那条改写）

`utils/soloPeek.test.tsx`（4）：★三个区互不重叠 + 左上角归顶栏（顺序即优先级）·
★**唤出后长大**（顶栏 46 / 工具栏 50；超出就出去）· ★未启用时恒定 `center` 且**不挂全局监听** ·
★启用后跟着 `mousemove` 走、退出单推复位。
CSS 那条改写成"**不许再有窄带覆盖层**、也不许退回 `:hover` 兄弟选择器 + 唤出时位移与延时都归零"。

**反向验证**（两组，各自确认"改到了"）：去掉"长大" ⇒ 那条红；去掉左缘判定 ⇒ 两条红。

## 三次都栽在同一件事上（值得记）

`430` 的 `:hover` 兄弟选择器、`432` 的元素判定、以及这次的坐标判定 —— 前两版的共同点是
**把"指针在哪"当成稳定的输入**，而它恰恰是**被我们自己的动画改动的东西**（自反馈）。
⇒ 经验：**只要一个交互会改变布局，就不能用它自己改变后的布局去判定它**。
