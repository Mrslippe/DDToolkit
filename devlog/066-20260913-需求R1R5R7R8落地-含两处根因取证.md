## 一、先说取证：两条"看起来像 bug"的其实是数据问题

### R1(a) 头像：链路缺兜底，不是"选中了默认图"

档案设置里选的 `vtubers.avatar` 存的是**远端 URL**，而卡片视图的头像是裸
`<AvatarImage src>`：既没有 `normalizeImageUrl()`（http→https），也没有 `/img-proxy`
兜底，选项按钮里的 `<img>` 连 `referrerPolicy` 都没设。实测这些图床**不带 Referer 直连**：

```
i2.hdslb.com   → HTTP 206（可用）
i1.hdslb.com   → HTTP 206
i0.hdslb.com   → HTTP 403       ← 同一个 CDN 的不同分片
tvax1.sinaimg.cn（微博）→ HTTP 403
```

命中 403 就回落 `AvatarFallback`（名字首字）—— 看起来就是"选了头像却显示无头像默认图"。

### R1(b) 锁定"反了" = 没落库（附带一个播种陷阱）

只读 dev 库实测两处都**从未写入**：

```
accounts.locked_fields 非空：0 / 10   （全 NULL）
vtubers.avatar     非空：0 / 7
```

链路本身是通的（`AccountUpdate.locked_fields` → `AccountRepo.update` 直接 `setattr` → commit），
所以本批按"**让它们不可能丢**"来修：把头像选择与两个锁定开关改成**点击即写入**
（乐观更新 + 失败回滚 + 顶栏胶囊提示），不再依赖"记得点保存"。

顺带修掉一个真会让人以为"逻辑反了"的坑：锁定状态只在父级刷新后才会更新，
而锁完不刷新 → 关窗再打开按**旧的** `hero.locked_fields` 重新播种 ⇒ 刚锁上的又显示成未锁。
现在每次锁定写入后回灌 `onSaved(await api.getVtuber(id))`。

> ⚠️ 口径说明：以上是 **dev 数据目录**的取值。若你当时测的是安装版（另一份数据目录），
> 结论里的"没落库"需要在那份库上复核；但两处修复与是否落库无关，都该做。
