# 158-20260919-R40数据视图牌堆：一次一张卡

> 用户 2026-09-19：「抛弃原来的卡片固定布局，上下滚动来看不同卡片，取而代之的是**在页面中只展示一张卡片**，
> 滚轮上下滚动就在卡片集中轮流切换，并且动画效果要做的流畅 —— 向下滚动就是当前一张卡片**向下滑动出框**，
> 它背后的卡片**从透明渐显**（有点位移和缩放）；向上滚动则相反，当前一张卡片**向后渐隐**，
> 下一张卡片**从下面滑动入框**。根据这个想法给我技术和设计方案，并且分析动画的性能以及可行性」。

---

## 一、方案要点（拍板结果）

| 决策 | 取值 |
|---|---|
| 框高 | **卡片自适应填充**（`min(631, 可用)`；两张卡改流体高度） |
| 初始卡 | **按 V 记住上次那张**（`sessionStorage`） |
| 指示器 | **右缘竖排圆点**（可点直达） |
| 滚轮 | **两条通道 + 软锁 150ms + 动画可重定向 + 欠账 ≤2** |

## 二、方向语义（用户原话 → CSS 契约）

| 方向 | 出场卡 | 入场卡 |
|---|---|---|
| **向下滚**（前进） | `translateY(0 → 38%)` + `opacity 1→0`（滑出框） | 从**背后**来：`scale(0.955 → 1)` + `opacity 0→1` |
| **向上滚**（退回） | `scale(1 → 0.955)` + `opacity 1→0`（向后隐去） | 从**下方**入框：`translateY(38% → 0)` + `opacity 0→1` |

出场 300ms（`--ease-exit`，快出）/ 入场 380ms（`--ease-emphasized`，慢入）—— "快出慢入"是方向感的来源。
**索引是唯一真值、视觉跟着它走**：中途改向能自然接上，因为 CSS transition 在目标值变化时
**从当前计算值续跑**（不需要等上一段放完）—— 这也是"快拨不卡手"的机制。

## 三、性能分析（用户要求）

**每帧在跑的只有 2 个合成层的 `transform` + `opacity`：**

| 项 | 数字 |
|---|---|
| 每帧 JS / 布局 / 绘制 | **0 / 0 / 0**（CSS transition 驱动，只碰合成属性） |
| 图层显存 | 870×631 @DPR2 ≈ **8.8MB/层**，两层 ≈ 17.6MB |
| 切换时的 React 渲染 | **0**（两张卡始终挂载、props 不变 ⇒ 日历 42 格与 ECharts 都不重建） |
| 预算余量 | 合成 2 层亚毫秒级 ⇒ 16.7ms 预算下余量极大 |

**⚠️ 必须避开的反模式**：用 `width/height/top` 做动画会每帧 layout，并且 **ECharts 的
ResizeObserver 会每帧触发图表重建**（5–15ms/帧）⇒ 必卡。**只动 transform/opacity 时
ResizeObserver 不会触发**（它观察布局盒，不观察变换）—— 这是本方案流畅的根本原因。
`will-change` **只在动画期间挂**（`data-deck-phase ≠ idle`），静止时不留常驻合成层。

## 四、滚轮：两条通道（用户当场质疑出来的修正）

我第一版写的是"120ms 静默分界 + 一次手势一张"，用户立刻指出「快速滚动的时候岂不是会很卡手」——
**他抓对了**：鼠标滚轮是**离散大格**（一格一个事件，拨快时格间隔 30–50ms），会被静默规则合并成
一个手势。于是改成两条通道：

| 通道 | 判定 | 行为 |
|---|---|---|
| **离散格**（鼠标） | 单次 `\|Δ\| ≥ 40` | **每格一张**，锁一结束就吃下一格 |
| **连续流**（触控板/触屏） | 单次 `\|Δ\| < 40` | 累积 ≥ 60 切一张，**同一次手势内不再切**（惯性尾巴只算一次） |

**软锁 150ms**（不是动画全长 —— 那才是卡手的根源）+ 锁内**最多记 2 格欠账** + 动画可被重定向。

## 五、三处"探针测不了"与分工调整（本批最值钱的部分）

滚轮决策依赖**事件之间的时间差**，而探针跑在无头浏览器的**虚拟时间**下 —— 两次 `dispatchEvent`
之间时钟也会推进，150ms 手势分界**根本复现不了**（实测 8px 的连续流累积永远到不了阈值，
判定成"每个事件都是新手势"）。另外两处：定时器会立刻触发（相位活不过一个 timer）、
`transitionend` 不会来。

⇒ 按本仓既有分工**把纯逻辑抽出来做单测**：新增 `deckWheel.ts`（`wheelAction` / `releaseAction`）
+ **12 条单测**（噪声 / 离散格 / 欠账封顶 / 锁内反向记账 / 惯性尾巴只算一次 / 新手势分界 /
慢速长划…）。探针只守**集成面**：几何（卡在框内）、圆点与真值同源、方向契约（CSS 落点）、
过渡注册、键盘五键、首尾不越界、非前卡 `inert`+`aria-hidden`。

**方向语义的判法也跟着改**：不抓"动画中的那一帧"（虚拟时间下相位活不过一个 timer），
而是**杀掉过渡 + 手动摆出「出场卡/入场卡」再读落点** ⇒ 断言"向下滚出场卡 translateY=181px"
与"向上滚出场卡 scaleX=0.955" ✓ 这是纯 CSS 契约，稳定可判。

## 六、顺手修掉的一个真 bug

**键盘/圆点这类"明确导航"要取消待消化的滚轮欠账** —— 否则用户按 Home 之后，
上一轮滚轮攒下的欠账会在解锁时把卡片又推走一格（探针实测到：Home 之后索引被推回末张）。
现在 `cancelWheelDebt()` 在四个键盘键与圆点点击里都会清账。
