# 544-20261019-golden 用例为什么会红：窗口会跟着数据滑动

`test_matches_probe_golden_values[明前奶绿]` 报 **场次 72 vs 71**。

## 一、不是代码变了，是数据长了

```
stats 文件数：75 → 77
最近三个写入时间：2026-10-19 01:59   ← 就是用户在应用里点采集的时候
```

用例比的是"**最近 75 场**"的聚合，而窗口是**滑动的** —— 每采一批新场次，窗口就整体前移，
六项数字全变。**这条用例从设计上就会随使用而红**，不是回归。

## 二、改法：钉住截止日

```python
FROZEN_UNTIL = "2026-10-17"
s = summary(load_window(v, 75, until=FROZEN_UNTIL))
```

加了截止日之后，**之后新采的场次不会再移动窗口**。实测：弥月 / 星瞳 用该截止日精确复现原值。

## 三、但补采老场仍会落在冻结区间内部

明前奶绿**任何截断都是 72 场** —— 说明新采的那几场是**老场次**（补采），落在
`2026-10-17` 之前。这一半靠截止日救不了，只能重记：

```
(71, 168_619, 1_100_061, 2_155_930, 7_147, 533_777.60)
→ (72, 170_470, 1_118_922, 2_182_543, 7_069, 537_228.80)
```

并在文件头写清：**冻结区间内一旦补采，必须重新冻结本表**。
