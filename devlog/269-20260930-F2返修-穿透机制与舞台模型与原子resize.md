# 269-20260930 F2 真机两处失败的返修：换穿透机制 · 舞台模型 · 原子 resize

用户在真机上验出两条（第一版 F2 的问题，devlog/268 记的是落地，这篇记的是返修）：
① **留白依旧不能穿透**；② hover 时**胶囊先向左位移、然后左右闪**。
口径：先给分析与批次方案（0 证据 → 1 P1+P4 → 2 换穿透机制 → 3 舞台模型），批准后一次做完。

## 一、穿透：机制选错了（不是没装上）

第一版是 `WM_NCHITTEST → HTTRANSPARENT`。它的语义是"被**同一线程**的另一个窗口盖住时，
把消息继续传给下面的窗口"——**桌面与别的进程不在那条链上**，于是留白那一点既不属于小窗、
也没人接，用户看到的就是"点了没反应"。
⇒ 跨进程只有 `WS_EX_TRANSPARENT`（整窗位）：指针在**交互矩形**外就置上（交给下面）、
回到矩形内就清掉（卡片照常可点）。矩形由前端上报（`set_widget_hit_rect`：
折叠态 = 胶囊、展开态 = 卡片）——`pad` 一个数不够了，因为两者的位置尺寸都不同。
⚠️ 置上之后窗口**收不到任何鼠标消息** ⇒ 只能轮询回来：`WM_NCHITTEST` 发现"指针在留白"
**才**开表（25ms），回到矩形内**或离开窗口**就停表（离开时必须恢复交互位，否则自锁）。
`HTTRANSPARENT` 仍然返回：同线程那半有用（留白压在主窗口上时点得到主窗口）。

## 二、左右闪：三个时钟 + 一个自激环

**三个时钟**：`resize_widget_window` 原先调 Tauri 的 `set_size` + `set_position`
= **两次** `SetWindowPos`（中间隔着 IPC 往返），而浏览器的重排是第三个。
于是"窗口已经挪了、布局还没换"的中间帧真实存在——F1 之前那张卡片不是动画主体，
看不见；F2 之后它正好落在用户盯着看的地方。算术也对得上：`align='center'` 时
窗口要左移 `(400−胶囊宽)/2 ≈ 94–100px`，**那就是用户看到的位移量**。
**自激环**：形变那 310ms 里面板还 `visibility: hidden`（不可点），指针若在边缘擦一下，
200ms 的"离开宽限"会在形变跑完前到点 ⇒ 关 → 回位 → 指针又落在胶囊上 ⇒ 开……
一轮约 320ms（"闪个不停"）。

## 三、修法（三件，都对得上"一个位置只留一个主人"）

1. **Rust 一次 `SetWindowPos`**（位置 + 尺寸 + `SWP_NOZORDER|SWP_NOACTIVATE`，物理像素），
   消掉"尺寸变了位置还没变"那一帧。
2. **舞台模型**：窗口恒等于「展开态卡片 + 两圈留白」，**hover 期间一动不动**；
   卡片在舞台里恒在 `(留白, 留白)`；胶囊的落点由前端**算好写死**（`--wg-cap-*`，
   样例页 `.puck` 的机制）。删掉了 `margin:auto` 那套锚点——它依赖容器宽，
   而容器宽由另一个时钟改。
3. **hover 锁 400ms**（`StatusIsland`）：展开后先静默一段，切断那个 320ms 的自激环。

**顺带删掉的**（前提消失就删机制）：`widgetCollapseGeom` + `widgetCapsuleGeom`
（收起不再需要"精确还原窗口"，内容变宽也不再动窗口）、`WIDGET_RESIZE_DEADBAND`、
那三条锚点规则、`set_widget_card_inset`。

## 四、判据与已知取舍

- `cargo test` 64 条（换机制后重写了两条纯函数用例：矩形边界、"该停表了"）；
  `widgetWindow.test.ts` 73 条（+ `capsuleSpotInStage` 与"舞台不随胶囊宽变"）；
  `--status-widget` 三段（形变四条过渡 + 起终点几何 + "胶囊不许有 transform"）；
  A 档 9 步全绿。
- ⚠️ **一处一次性代价**：窗口从"胶囊 + 留白"变成"**卡片 + 留白**"（常驻舞台），
  而位置存的是**窗口左上角** ⇒ 升级后第一次出现时胶囊会**右移约 100px**（落点居中）。
  用户拖一次即可，没有做迁移（那要新 key + 跨语言改 `show_widget_window` 的语义）。
- ⚠️ **仍未机器化**：鼠标穿透与形变手感只能真机验（记在 `TODO.md` §1.3）。
