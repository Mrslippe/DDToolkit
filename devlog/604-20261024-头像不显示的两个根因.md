# 604-20261024-头像不显示：相对路径 + 原图过大

用户反馈头像仍然不显示，并提供了 danmakus 前端的头像地址：
`https://workers.vrp.moe/api/bilibili/avatar/<uid>?size=22`。

## 一、查了什么

1. **那个 CDN 我们这儿取不到**：`workers.vrp.moe` / `vrp.moe` 一律 **403**（Cloudflare），
   换 UA / Referer / Origin 都是 403；`api.vrp.moe` 直接连不上；`ukamnads.icu` 同路径是 404。
   ⇒ 只能当"浏览器侧可能能过"的候选，不能作为服务端唯一依赖。
2. **真正的 bug 是相对路径**：`/ranked` 返回的 `avatar_proxy` 是 `/fan/avatar/<uid>`，
   而 `<img src>` 会把它解析到**页面来源**（Tauri 是 `tauri://localhost`、开发态是 `:5173`），
   两者都不是后端。仓里早有同一条教训 —— `videoProxyUrl` 曾因相对路径"每段视频都 404"（devlog/294），
   并且已经有 `resolveAsset()` 负责拼 `apiBase`。
3. **顺带发现原图太大**：B 站 card 接口给的 `face` 是原图（实测 231 KB~1.28 MB），
   一页 20 个头像就是几十 MB。B 站图床支持 `@80w_80h.jpg` 后缀：**1.7 KB**。

## 二、修法

- 前端：`stage 1` 用 `resolveAsset(row.avatar_proxy)` 拼绝对地址；
- 后端：`/fan/avatar/<uid>` 取图时加 `@80w_80h.jpg` 缩略后缀，落盘缓存
  （首次 3.2 KB，之后直接命中缓存）；
- 头像三级兜底：danmakus CDN → 本地代理 → 昵称首字。

## 三、验证

- 真实中间件（不绕过鉴权）下 `GET /fan/avatar/390462074` → **200 image/jpeg 3,195 B**，二次命中缓存；
- 前端 16 passed、`tsc` 干净、`npm run build` 成功。

## 四、还需要什么

昵称与头像内容仍为空：`uName` 要等重采（镜像当前 504），头像则**已经可以显示**
（走本地代理，不依赖 danmakus CDN）。
