# 444-20261007-正常模式左栏的收起速度与单推解耦

用户：「正常模式下左栏收起的速度和 `--solo-step` 解耦」。

## 为什么它们本来粘在一起

基础那条 `transition` 把三个元素写在一起、共用**单推**那对旋钮：

```css
.sidebar-shell, .icon-rail, .topbar {
  transition: margin-left var(--solo-step) var(--solo-ease),
              margin-top  var(--solo-step) var(--solo-ease);
}
```

写这条时的意图是"给单推的三段收起配过渡"，但 `.sidebar-shell` 的**正常模式手动收起/展开**
（`.sidebar-shell[data-collapsed='1']` 的负外边距 ↔ 基础态）**读的也是它** ⇒
调单推的节奏会顺手改掉正常模式的手感，反之亦然。`--solo-step` 这个名字已经说明了它属于谁
—— 一条 transition 服务**两种语义**（"模式切换" vs "一段编排"）时就该拆。

## 改法（用户选了 A：单推三段保持原样）

```css
:root { --sidebar-toggle-ms: calc(180ms * var(--motion-scale)); }   /* 左栏自己的旋钮 */

.sidebar-shell { transition: margin-left var(--sidebar-toggle-ms) var(--ease-standard); }
.icon-rail,
.topbar       { transition: margin-left var(--solo-step) var(--solo-ease), …; }   /* 只在单推里动 */

.app-shell[data-solo='1'] .sidebar-shell {           /* 单推第①段钉回单推节奏 */
  margin-left: calc(-1 * var(--sidebar-width));
  transition-delay: 0ms;
  transition-duration: var(--solo-step);
  transition-timing-function: var(--solo-ease);
}
```

- **初始值 180ms**（用户口径；比原来那 260ms 利落一档，且解耦本身可独立调）。
- 走 `--motion-scale` 倍率，与 `--motion-*` 一族一致 —— 动效调测页要能看清这一段。
  （⚠️ `--solo-step` **没**跟倍率走，单推那段目前没法慢放看；这是现状，不是我引入的。）
- 曲线换成 `--ease-standard`（`tokens.css`）：原来借的是**单推**的曲线，同样是耦合。
- 钉回单推那三条是**简写 vs 长手**：`.app-shell[data-solo='1'] .sidebar-shell` 是 (0,3,0)，
  基础 `.sidebar-shell` 是 (0,1,0) ⇒ 长手赢，不需要 `!important`。

## 取舍（用户选项 A 的已知代价）

**单推第①段**钉住了 ⇒ **进场**节奏与改动前逐帧一致；
但**退出单推**那一下左栏跟 `--sidebar-toggle-ms` 走 —— 退出时 `data-solo` 已经摘掉，
CSS 读的是"变完之后"的样式，纯 CSS 钉不住（要钉就得在退出期间临时挂一个属性 = 一小段 JS 状态，
而这个文件开头明确写着"顺序靠 `transition-delay` 表达，不写 JS 状态机"）。
两个值只差 80ms 量级时看不出来；用户若以后把左栏旋钮调得很极端，记得这一处。

## 判据（净 +1，12 条）

★「正常模式左栏吃自己的旋钮，且**不含** `--solo-step`」＋**正对照**"单推第①段确实钉着
`--solo-step`"—— 正对照不是装饰：**万一基础规则被整条删掉**，左栏就是**完全不带动画**的硬切，
而"不含 `--solo-step`"照样成立（假绿）。另加"旋钮有定义且跟慢放倍率走"：
`var()` 取不到值时整条声明无效 ⇒ 时长回退 0s ＝ 硬切，**静默退化**。

**反向验证**（三组，都杀死了）：基础规则改回 `var(--solo-step)` ⇒ 红；
摘掉单推那条的 `transition-duration` ⇒ 红；删掉 `--sidebar-toggle-ms` 的定义 ⇒ 红。

（`devlog/433` 已撤）、`--solo-fade-delay:5s`（早已搬成 JS 的 `SOLO_IDLE_MS`）、
`--solo-dim:0.12`（实际 0）。这一行是「图标栏」的活文档，趁这次一并按代码重写
（旋钮只写名字、不写值 —— 值会变，名字与出处才是稳定的，见 `devlog/443` 的教训）。

## 教训

**旋钮的名字就是它的作用域。** `--solo-step` 出现在正常模式的手动收起上时，
"名字"和"谁在用"已经矛盾了 —— 那种矛盾早晚会被一次调参暴露成"我改 A 结果 B 也变了"。
拆的时候记住：**同名声明可能同时服务两种语义**，而**过渡读的是"变完之后"的样式** ——
所以"退出路径"永远钉不住。
