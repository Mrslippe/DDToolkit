# 225-20260927-迁移编排抽成可注入函数并补四条回滚判据

批次 16 的 ④（2026-09-26 明确没做）：**`migrate_data_dir` 的回滚编排补集成测试**。
计划要求四条失败路径各断言「指针未变 + 旧目录内容未动 + 后端仍在旧目录上跑」。

## 一、卡点与做法

卡点是那句编排长在 `#[tauri::command] migrate_data_dir` 里 —— 它要 `AppHandle`（真窗口、
真对话框、真后端进程），一条都测不到。做法照 `lib.rs::delete_old_dir` 的先例：

1. `migrate.rs` 新增 **`trait MigrateEnv`**（八个副作用：`log` / `stop_backend` / `copy_tree` /
   `verify_copy` / `read_pointer` / `write_pointer` / `clear_pointer` / `start_backend`）；
2. 五步编排搬进 **`migrate::orchestrate(env, current, plan) -> Result<Orchestrated, String>`**
   （`Orchestrated` 带 `port` / `report` / `old_dir_canonical`）；
3. `lib.rs` 里加 **`TauriMigrateEnv`**（把八个副作用接到真后端与指针文件上），命令体缩成
   "选目录 → 拒绝便携版 → `plan_migration` → `orchestrate` → 写壳状态/票据/报告"。

⇒ 产品行为不变（除了下面那条修掉的缺陷），但编排从此**可注入、可断言**。

## 二、⚠️ 顺带修掉一个真缺陷：**写指针失败会把应用留在"没有后端"的状态**

旧代码在写指针那步是 `datadir::write_pointer(&plan.data_dir)?` —— 直接早退。可那时
**后端已经停掉了**（第 ① 步），复制也做完了 ⇒ 用户看到"迁移失败"，而窗口里**没有任何数据服务**
（界面正常、点什么都空）。这恰恰是计划那句"各断言**后端仍在旧目录上跑**"逼出来的第一个真问题：
四条路径里只有三条做了回滚，第四条漏了。现在补上（写指针失败 ⇒ 用旧目录把后端拉回来）。

## 三、判据（`migrate::tests::orchestrate`，6 条，Rust 单测 56 → 62）

替身 `Fake` 记录**每一次副作用调用**（顺序断言用）+ 可注入的失败点；旧目录用真临时目录，
里面放一个**哨兵文件**（`哨兵.txt` = `old-data`）⇒「旧目录内容未动」是被真的断言了的。

| 用例 | 断言 |
|---|---|
| happy path | 调用顺序 = `stop → copy → verify → read_pointer → write_pointer(新) → start(新)`；指针 = 新目录 |
| 复制失败 | 错误含「数据目录没有改变」；**指针一个字节都没写**；`verify` 没跑；最后一条 `start` 在**旧目录** |
| 校验失败 | 同上（两条路径回滚必须一致） |
| **指针写失败** | 错误含「写指针失败」+「数据目录没有改变」；指针仍是旧值；`start` 在**旧目录** ← 这条以前必红 |
| 探活失败（有旧指针） | 指针先写新目录、失败后**写回原来那个**；最后 `start` 在旧目录 |
| 探活失败（从来没有指针） | 改调 `clear_pointer`（不许把新目录留在指针里） |

**反向验证四刀**（前三刀各自精确报红，第四刀是**计划点名的那条改法**）：

| 刀 | 改法 | 结果 |
|---|---|---|
| A | 写指针失败后**不再**把后端拉回来（= 旧行为） | 指针写失败那条红 |
| B | 探活失败**不还原指针** | 探活两条红 |
| C | 复制/校验失败后不再拉回后端 | 复制失败 + 校验失败两条红 |
| D | **把指针提前写**（复制之前就切） | 6 条里 5 条红 —— 与 `EXECUTION.md` 批次 16 反向验证表里那句「把指针提前写 ⇒ 必红」一致 |
