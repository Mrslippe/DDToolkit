# 298-20261003 开头的音轨抢跑 / 流畅度实测：0 掉帧，问题在启动与漂移

> 用户两条（2026-10-03 23:1x）：
> ① 「第一次点击播放的时候音轨会提前一点然后同步，导致开头一小段重复一点」；
> ② 「体感上明显 B站网页播放器更流畅一点，即使统计信息里帧率也是 30 —— 会不会是解码或内核问题」。
> ①是**真问题，已修**；②量了，**不是解码问题**，但量出了两个真东西（启动空档、音画漂移）。

## 一、为什么开头会"听两遍"：视频轨要缓冲，音轨不用

DASH 的两条流是**两个独立媒体管线**：音轨几乎瞬间就能出声，视频轨要先拿到并解出第一帧。
旧实现是"两条一起 `play()`"⇒ 声音先跑出去，等 2s 一次的漂移纠正把它拽回来 ——
那一小段就被听了两遍。

**实测这个空档有多大**（无头 Edge 经本机代理真播 20 秒，见 §三）：

```
waiting 事件 1 次，持续 1261.8ms      ← 视频轨第一帧要等 1.26 秒
```

**修**：`startPlayback()` 里视频轨先 `play()`，音轨**等视频轨的 `playing`（真的出画）**才对齐并启动：

```ts
void el.play()…
if (!el.paused && el.readyState >= 2) beginAudio()
else el.addEventListener('playing', beginAudio, { once: true })
```

已经出画的场景（暂停后复播、seek 后复播）直接起，不用等。视频轨被自动播放策略拒绝时
`playing` 不会来 ⇒ 音轨也不出声（正确：画面没起来，声音不该单独跑）。

## 二、顺带把漂移纠正分了级

同一次实测里还有一行：**19 秒后音轨超前 0.28s**（`v_time 18.74 / a_time 19.02`）。
原因是视频轨那条**没有音轨**（B站把音频分出去了）⇒ 它的时钟是"墙上时间"估的，
与跟声卡时钟走的音轨有约 **1.5%** 的速率差，越播越偏。

旧实现只有"超 0.3s 就直接对齐"一档 ⇒ 0.28s 这种"已经能感觉出来"的量级被放过去了，
而且每次修都是"跳一下"。现在按 `driftAction()` 分三档：

| 漂移 | 动作 |
|---|---|
| `> 0.6s` | 直接对齐（那么大的偏差本来就是故障态） |
| `0.05–0.6s` | 改 ±3% 速率**慢慢追**（1 秒追 30ms，听不出来；也不会"咔"一下） |
| `< 0.05s` | 不动，恢复用户设定的倍速 |

方向：音轨**超前**就让它慢一点（`rate*0.97`），落后就快一点（`rate*1.03`）—— 判据里专门钉了方向。

## 三、流畅度：量出来是**0 掉帧**，不是解码/内核问题

做法：本进程起一个**只挂真 `/video-proxy` 路由**的小服务（页面同源，避免 CORS 预检），
用**无头 Edge**（与 WebView2 同族 Chromium）播 20 秒，读 `getVideoPlaybackQuality()`：

```
elapsed_s: 20.01
video_frames_total: 566        video_frames_dropped: 0
decoded: 566                   dropped_webkit: 0
effective_fps: 28.3            ← 566 / 18.74s（真正播放的时长）= 30.2 fps，与流元数据一致
buffered_ahead_s: 16.7         ← 带宽绰绰有余（19 秒里下完了 35 秒的片子）
waiting: 1 次 / 1261.8ms       ← 只有开头那一次
readyState: 4
```

⇒ ① **解码与管线跟得上**（0 掉帧、有效 30.2fps、缓冲跑在前面），
所以"不够流畅"不是丢帧、也不是代理带宽；② 能改进的是**启动那 1.26 秒的空档**（§一已修）
与**音画漂移**（§二已修）—— 这两件事都会让人感觉"比我平时看的那个播放器差一点"。

⚠️ 反面提醒：WebView2 里还有 GPU 合成那条路本机量不到（无头 Edge 与真机窗口的呈现路径不同）。
如果修完仍觉得不流畅，下一步该量的是**真机里 `requestVideoFrameCallback` 的帧间隔直方图**
（不是再看掉帧数）—— 那能区分"帧来得不匀"与"帧不够"。

## 四、判据

| 用例 | 钉什么 |
|---|---|
| `VideoPlayer.dash.test.tsx` | 出画前音轨**不许** `play()`；`playing` 之后音轨起播且**对齐到视频轨当前时刻**（不是从 0）；音轨起不来的分支仍会把视频轨停住 |
| 同上（漂移） | `driftAction` 三档 + **方向**（超前变慢、落后变快）；每秒一次的纠正真的把 `playbackRate` 调偏、稳定后恢复 1.0 |
| `BiliVideo.test.tsx` | 点播放 ⇒ 视频轨立即起播、音轨等 `playing` |
