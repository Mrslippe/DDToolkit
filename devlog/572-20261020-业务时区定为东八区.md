# 572-20261020-业务时区定为东八区（选 A）

先把"非东八区客户端会怎样"查清楚，再让用户选口径。结论：**不会崩，但同一天会被算成不同天** ——
热力图按东八区分天，而场次列表/预约/`formatDate` 按**客户端本地时区**分天。东八区客户端上两者
恰好一致，所以这个矛盾一直没暴露。

用户选 **A：全站按业务时区（东八区）** —— 日期稳定，不随查看者时区漂移。

## 新增 `frontend/src/utils/cndate.ts`

`cnParts` / `cnDay` / `cnDateTime` / `cnTime` / `cnToday` / `cnDateKey`，
内部一律 `Intl.DateTimeFormat(..., { timeZone: 'Asia/Shanghai' })`。规则：

- **时间点**（带 `Z`/偏移）→ 换算到东八区再取年月日时分；
- **纯日期** `YYYY-MM-DD` → 原样返回，绝不当瞬时解析；
- **解析不了** → 返回空串，调用方据此丢弃（不拿半截串当日期）；
- **"今天"** → 东八区的今天。

## 改到的点

| 位置 | 变化 |
|---|---|
| `format.ts::localParts` | 本地 getter → `cnParts`（**对外函数名不变**，所有调用点自动跟随） |
| `dateRange.ts::today()` | 客户端今天 → `cnToday()`（默认区间的起点） |
| `reservationDays.ts` | 按 `cnDay(start_at)` 分组（与场次分组同一口径） |
| 后端 `/activity` 的 `today` | `date.today()`（服务器本地）→ `datetime.now(CN_TZ).date()` |

## 已知边界

- 身处东八区以外的用户，看到的是**北京时间**而不是当地时间 —— 这是选 A 的代价，也是数据产品的常规；
- `problemReport` / `LegalNotice` 里的时间戳仍按客户端本地格式化（那是"我这台机器什么时候报的"，
  语义上就该是本地），未改。
