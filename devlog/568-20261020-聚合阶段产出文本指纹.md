# 568-20261020-聚合阶段产出文本指纹（去独轮车的原料）

用户口径：去独轮车放在**聚合阶段**，但①保留原始条数 `m`；②判定算法要留**更改空间**。

## 改动

| 位置 | 变化 |
|---|---|
| `collector.aggregate` | 弹幕分支顺带做**文本归一化计数**（去首尾空白、内部空白压一格），收尾折算成 `uniq` / `maxrep`；原文**不落盘** |
| `stats` | 新增 `danmaku_total` / `uniq_total` / `dup_rate`（审计用，缺失记 `None` 而非 0） |
| `loader.UserFact` | 新增 `uniq` / `maxrep` / `text_tracked`；**老数据没有这两个键 ⇒ `text_tracked=False`，不写 0 冒充** |
| 新增 `fan/spam.py` | 版本化判定入口（`SPAM_ALGO_VERSION = 1`），**当前无调用方** |

`m` 全程未动 —— 它是"发言总量"口径的基础，去重字段是并列的第二个口径，不是替代。

## 为什么判定要单独一个模块

判定口径一定会改（阈值、是否结合入场模式、是否用相似度）。若写进 `aggregate`，改一次就要动采集链路，
而且报告里说不清"用的是哪一版判定"。现在：聚合只给原料，判定在 `spam.py`，带版本号。

`spam_score()` 在输入不足时返回 **None（未知）**，`is_spam()` 同理 —— 不把"未跟踪"说成"不刷屏"。

## 用例

`test_aggregate_records_text_fingerprint`：6 条弹幕（含 3 条重复 + 1 条带空白的同一句）
⇒ `m=6`（未被改动）、`uniq=3`、`maxrep=4`；全场 `dup_rate` 也对得上。

## 验收

后端 fan **28 passed / 1 skipped**；文档门禁 0 FAIL（404 / 900 行）。
⚠️ 老数据无法回补（raw 无文本），新旧数据 `uniq` 不可混算 —— 文档 §1.2 已注明。
