# 499-20261015 录播小窗的层叠补齐 + 详情页按钮回纯图标

## 用户报的两条（2026-10-15，带截图）

1. 「在没有录播的日期格详情窗口中，点击**添加录播**按钮打开的小窗**和前面提到的症状相同**，改掉」；
2. 「标题右侧的**编辑按钮不用浮片样式，就原本纯图标样式就行**」。

## 第 1 条：同一类漏加，第二次复发

`devlog/498` 把层叠改成命名层（`--z-dialog-6/-7` + `lc-dlg-layer`），但**只给当时在场的
三个窗加了**（`.lc-ms` 手动记录 / `.lvc-fill` 填充 / `VodAccountDialog`），**漏了 `VodDialog`**
（详情封面 `＋` 与下拉栏的「添加·更换录播」就是它）⇒ 它的遮罩与面板都落在二级窗**下面**，
症状与第一次一模一样。

补上 `lc-dlg-layer` 之后，同一类窗的名单是**四个**。这次不再靠"记得加"：

- **源码级判据** `frontend/src/components/live/dialogLayer.test.ts`：把"从详情窗里开出来的窗"
  列成名单，逐个断言 `DialogContent` 的 `className` 与 `overlayClassName` **都**带 `lc-dlg-layer`；
  再断言层号来自令牌（`--z-dialog-6/-7` + 两条 `data-slot` 兜底规则都在）。
  **反向验证过**：把 `VodDialog` / `VodFillDialog` 的类去掉 ⇒ 2 条当场红，且报错说清后果
  （"会掉到遮罩下面，点哪都关窗"）。
  ⚠️ 为什么必须是源码级：漏一个类**不会有任何行为报错** —— 编译过、用例过、渲染也对，
  只有真机上点不动（jsdom 没有布局与命中测试，量不到层号）。
- 真机层号仍由 `ui_probe --vod-fill` 守（"面板严格高于遮罩 + 中心点命中自己"）。

另外新增 `--shot-vod-fill`（与 `--shot-cell-pop` 同款）：把审查窗开着截一张，
"遮罩把面板盖住了"这类毛病只有看图才算验过。这一轮就是靠它确认视觉的。

## 第 2 条：按钮回纯图标

上一轮我把详情页那枚铅笔换成了 `NavMenu`，而 `NavMenu` 的触发钮**写死用 `FloatPill`**
⇒ 它带上了浮片族的斜切白卡 + 阴影（用户截图里能直接看到），而那正是他要去掉的。

⇒ `NavMenu` 加 `bare` 变体：触发钮改为**原生 `<button class="nav-menu-trigger">`**
（26×26 / r8 / 无底色 / hover 淡灰底，与关闭钮 `.lc-dlg-close` 同一套配方），
详情页那枚传 `bare`；日历工具栏那枚仍是浮片（与它左边几枚月份钮同族）。
判据 `NavMenu.test.tsx` ⑤：默认带 `float-pill`、`bare` **不带** `float-pill` 且带
`nav-menu-trigger`，并且仍然有 `aria-label`/`aria-haspopup`（换样式不能把可用性一起换掉）。
