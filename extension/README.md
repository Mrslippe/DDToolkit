# DDToolkit 凭据同步扩展（Edge / Chrome）

把浏览器里**已经登录**的 B 站 / 微博 / 小红书 / 抖音 Cookie 一键同步到本机的 DDToolkit，
省掉"打开 DevTools、抄整条 Cookie、粘进设置窗"那一步（抖音还要手抄 UA）。

- **只走本机**：请求只发往 `http://127.0.0.1:<端口>`，配对失败一律拒绝；
- **读得到 HttpOnly**：`SESSDATA` / `web_session` 这些 `document.cookie` 读不到，
  MV3 的 `chrome.cookies` 能读（这是官方能力，也是本方案只能是扩展的原因）；
- **不落明文**：cookie 只在内存里过一手就发走，`chrome.storage.local` 里只有端口与配对 token。

## 装（一次性）

1. 打开 `edge://extensions`（或 `chrome://extensions`）→ 打开「开发人员模式」；
2. 点「加载解压缩的扩展」→ 选**本仓库的 `extension/` 目录**（那个有 `manifest.json` 的目录）；
3. 打开应用 →「设置 → 登录 → 浏览器扩展」→ 点「复制」；
4. 点扩展图标 →「设置」→ 把 token 粘进「配对 token」→「保存」。
   （端口会**自动探测**：应用优先绑 `8765–8769`，扩展依次探并用 `/healthz` 的
   `app: "ddtoolkit"` 认领；探测不到时可以在同一栏手填端口。）

## 用

- 顶部「同步全部四个平台」：逐个平台推，**一个失败不影响其余三个**（逐条给回执）；
- 每行也能单独「同步」；行上写着读到了几个可用键、整条 cookie 多少个键；
- **只要那一行读到过 cookie，「同步」就能点**（缺键不禁用）：只有**应用**知道它自己有没有
  那个键，缺哪个由应用侧合并后说了算（见下一节）；
- 回执在应用侧也会留痕：「设置 → 登录 → 浏览器扩展」那一栏会显示**上次同步**（平台 + 时间 + 键名）。

## 某一行的「同步」是灰的 / 点了说缺键

**先看诊断行**：「设置 → 诊断：这次读到了哪些 cookie」每个平台第一行现在是
`读到 N 条（URL a · 域扫 b · 全量 c · 按名 d · 分区 e）` —— **五趟各读到几条**一目了然，
第二行 `按名取：a1=有@.xiaohongshu.com/` 是"逐个键到底能不能问到"的答案：

| 现象 | 说明 | 怎么办 |
|---|---|---|
| `全量` 只有个位数、而你在 DevTools 里看得见那个键 | 见下「权限那条真凶」：`https://` 权限读不到**非 Secure** 的 cookie | 确认扩展已**重新加载**（旧的 manifest 还在生效） |
| `按名取` 里那个键也**没出现** | 整个库 + 按名问都拿不到 ⇒ 这个键确实不在这个浏览器里 | 见下面那张表 |
| `全量`/`按名` 都是 0/个位数、四行都很少 | 扩展读的浏览器配置跟你登录的那个不是同一个 | 在**装了扩展的那个浏览器**里登录一次，点「重新读一次 cookie」 |
| 某一趟后面跟着 `⚠️ …` | 那一趟被浏览器拒了（老版本不认 `partitionKey` 等） | 把诊断整行发我 |
| 四行都 0 条 | 这个浏览器里没登录过这些站点（或从来没访问过） | 打开各站首页登录一次 |

### 权限那条真凶（2026-10-06 实测，走了三趟弯路才挖到）

cookies API 的可见性**由 host permission 的 scheme 决定**：只写 `https://*.<域>/*` 时
**读不到非 Secure 的 cookie**（MDN 的 cookies 权限表正读：`http://*.example.com/` 能读非
Secure 的、读不到 Secure 的；`*://*.example.com/` 两种都能读）。而平台那些**页面 JS 铸的
指纹键**（小红书 `a1`、抖音 `s_v_web_id`）多是非 Secure ⇒ **连 `getAll({})`（整库读）
都看不见它们**，症状就是"DevTools 里有、扩展读不到"。
`manifest.json` 因此改成 `*://*.{域}/*` + `*://{域}/*`（四个平台各两条），并有一趟
**按名取**（`get({url, name})`）兜底 + 把答案印进诊断。诊断里 `[非Secure]` 这个标志就是给这类排查用的。

**浏览器里那一类"指纹 cookie"也可能压根不存在**（同日实测的另一半）：`a1`、`s_v_web_id`
都是**页面 JS 铸的**（会被清、也可能没铸过），而登录凭证（`web_session` / `sessionid` /
`SESSDATA`）在。所以灰/缺键**不等于你没登录**。

现在按钮的策略是：**只要那一行读到过 cookie 就能点** —— 应用侧会把"浏览器这次读到的键"与
"**应用里已有那份**"合并（同名以浏览器为准、已有键**只增不删**），回执会如实写
「`a1` 来自应用里已有那份」。所以：

1. 直接点「同步」试一次 —— 应用里若已有那个指纹键，就成了；
2. 回执说"应用里现在没有这个平台的 cookie 可以补 / 已有那份也没能补上" ⇒ 才真的缺，
   去浏览器里**打开那个平台的网页并刷新一次**（让 JS 把指纹键铸出来），再点
   「重新读一次 cookie」；
3. 还是缺 ⇒ 打开「设置 → **诊断：这次读到了哪些 cookie**」，
   把那一份（**只有键名/域/路径/长度，没有值**）发我。

| 行 | 必需键 | 读不到的常见原因 |
|---|---|---|
| B 站 | `SESSDATA` `bili_jct` | 浏览器里没登录 B 站（或只在 App 里登录）|
| 微博 | `SUB` | 同上；⚠️ 要 **PC 域** weibo.com 的登录态 |
| 小红书 | `a1` `web_session` | `a1` 是页面 JS 铸的设备指纹（**不是**登录凭证）；扩展靠"全量读 + 按名取"兜住它，仍读不到就靠"应用已有那份"补（见上）|
| 抖音 | `s_v_web_id` `ttwid` + `uifid`（或 `UIFID_TEMP`）| `s_v_web_id` 要同时充当 `verifyFp`，同样是页面 JS 铸的 |

> 诊断里的 **`len=N` 很有用**：平台若把某个指纹 cookie 换了名字，靠长度能认出来
> （例如应用文档记着"`a1` 长度 52 字符"）。
> ⚠️ **2026-10-06 走了三趟弯路，记在这里免得再走**：
> ① 先量到"小红书只读到 4 条、`x-rednote-datactry` / `x-rednote-holderctry` 各 2 字符"，
>    据此判成"**不是**改名版 `a1` ⇒ 浏览器里就是没有" —— **后半句是错的**；
> ② 改成"整库读"（`getAll({})`）后再读，**还是 4 / 22 条**，于是又怀疑"扩展挂的浏览器配置
>    跟你登录的不是同一个" —— **也不对**：用户在同一个窗口跑 `document.cookie`，
>    `a1` / `s_v_web_id` 明明都在；
> ③ 真凶才露出来：**host permission 的 scheme**（见上一节）—— `https://` 权限读不到
>    非 Secure 的 cookie，而这两个指纹键正好是非 Secure（诊断里 `[非Secure]` 那个标志就是它）。
> 判据：诊断第一行的 `全量` 与第二行的 `按名取` —— **两个都拿不到**才叫"这个库真的没有"。
> ⚠️ 改完扩展代码到 `edge://extensions` 点**重新加载**；**改了 `manifest.json`（权限）必然要
>    重新加载**，否则旧权限继续生效、症状一模一样。

## 手工验收清单（**每一条都要真跑**，失败就记下来）

自动化能覆盖的部分在 `node --test extension/test/` 与 `scripts/extension_smoke.py`；
**下面这些只能真机判**（MV3 popup 没法在无头 CI 里驱动）：

| # | 步骤 | 期望 |
|---|---|---|
| 1 | 浏览器里已登录 B 站 → 点同步 | 回执「已同步 SESSDATA、bili_jct…（已验证登录态）」；应用顶栏不再报"未登录" |
| 2 | 已登录微博 → 点同步 | 回执同上；**同步后浏览器里微博仍登录着**（同一账号多网页端会不会互踢，实测过才知道） |
| 3 | 已登录小红书 → 点同步 | 回执带「未在线验证」（这个平台不做探活）；随后抓一次小红书内容**能拿到** |
| 4 | 已登录抖音 → 点同步 | 回执带「未在线验证」；随后抓一次抖音内容**能拿到**（UA 也跟着同步了） |
| 5 | 只登录其中一两个平台 → 点「同步全部」 | 没登录的那几行显示"还没登录，跳过"，其余照常成功 |
| 6 | 故意把 token 改错 → 点同步 | 行上写着「配对 token 不对 —— 到应用…复制当前那一条」（不是"失败了"三个字） |
| 7 | 应用没开 → 点同步 | 行上写着"没找到应用"与试过的端口 |
| 8 | **关掉应用再开**（同一台机器）→ 点同步 | 仍然成功（配对 token 持久化 ⇒ 不用重贴） |
| 9 | 应用里点「重置配对」→ 回扩展点同步 | 401 提示；重贴新 token 后恢复 |
| 10 | Chrome 与 Edge **各装一次** | 同一份代码两边都能用 |

⚠️ 第 1/2 条是"**端到端真的能用**"的判据；只看回执 200 **不算**（回执绿而抓取失败是本仓最怕的形态）。

## 已知缺口（诚实清单）

- **没有自动化判据**：popup 只能手工验。纯逻辑在 `extension/test/logic.test.mjs`（含
  "必需键/端口候选/应用标识与后端逐项对账"、**host permission 必须是 `*://` + 裸域**、
  多趟读的并集、全量读的按域过滤与泄漏闸、按名取的问法、大小写不敏感、以及"接线有没有真的
  读全量 / 按名取"的源码级判据），**接线**在 `scripts/extension_smoke.py`（Python 复刻扩展的
  请求序列）。要自动化得先解决"无头浏览器 + 稳定扩展 id"，那是一条独立的技术路线，
  没做之前不假装有。⚠️ 2026-10-06 实测：**这个 Edge 版本在 `--headless=new` 下根本不加载
  `--load-extension`**（窗口模式 + 独立 user-data-dir 也一样，profile 里一个扩展都没注册）
  ⇒ 想自动驱动 popup，先解决这一条。
- **读全量 = 一次性拿到整库**（只有"按域过滤"挡着）：`getAll({})` 不看 URL/path，是唯一
  能保证"DevTools 里有的就读得到"的读法，代价是**别的平台的 cookie 也短暂地经过内存**
  （过滤后立刻丢弃、绝不外发，有用例专门盯这条）。`cookies` 这个权限本来就能读全库 ——
  不读全量只是"我们没调那个重载"，不是"读不到"。嫌这个面大的话，关掉扩展即可。
- **图标**（2026-10-06）：`icons/{16,32,48,128}.png` 由 `scripts/make_icons.py` 从项目 LOGO
  （`docs/design/svg/LOGO.svg`）生成，**与桌面/任务栏图标是同一张图**（同一个 `make_icon`，
  32/128 两档在 `node --test` 里**逐字节比过**）。跑它需要 `uv pip install pillow`。
  ⚠️ 试过两版"加点元素"（小尺寸实心猫头 / 右下角白色 ⇄ 表示"同步"）都撤了 ——
  用户 2026-10-06 拍板：「浏览器拓展的 logo 还是直接用项目 LOGO 吧」：
  **品牌标识就是品牌标识**，别在上面叠私货。改图标 = 改那份 SVG 再重跑脚本，别手改 PNG。
- **没写 `manifest.key`**：所以扩展 id 由"载入路径"推出、换机器会变。
  只有自动化驱动 popup 时才需要稳定 id，那时再生成密钥对并钉在这里。
- **抖音只带 UA，不带 `sec-ch-ua`**：实测签名只吃 UA；平台若开始看 client hints，这里是缺口。
- **cookie 过期仍要用户点一下**：不做后台自动同步（那是另一套权限与风险模型）。
- **CORS/特权通道**：MV3 的扩展页面请求 `host_permissions` 里的主机是特权请求，
  但这条**只能在真浏览器里确认**（清单第 1 条就是它）—— 若被拦，脚本侧会显示 `发不出去：…`。
